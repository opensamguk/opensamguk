# 관리자 콘솔

> 상태: 관리자 역할·감사·제재 묶음 검증 중 · 필요 시점: M3 · 관련 AC: M3-04, M3-05, M3-10
> 참고: core2026 `admin-console.md`, `play-audit-operations.md`, `design/play-audit.md` (부정 플레이 조사 범위만)
> 이 문서가 답할 질문: 운영자가 어떤 화면에서 무엇을 할 수 있고 무엇이 기록되나?

## 1. 권한

T3-05 첫 묶음은 관리자 역할과 명령줄의 권한 부여·회수만 다룹니다. 기존 계정과 새 계정의 기본 역할은 USER이며 자동으로 관리자를 지정하지 않습니다. `admin.whoami`는 로그인·필수 이메일 인증 뒤 DB의 ACTIVE·ADMIN을 매번 확인하고 `{ admin: true }`만 돌려줍니다. 역할을 회수하면 기존 세션에서도 다음 요청부터 거부합니다. 요청의 사용자 ID나 역할 값은 권한 근거가 아닙니다.

관리자 지정·회수 API는 없습니다. 대상과 사유를 확정한 서버 운영자가 올바른 DB 환경을 확인한 뒤 `pnpm admin:grant` 또는 `pnpm admin:revoke`를 실행합니다. 이메일과 사유는 명령 인자에 넣지 않고 표준 입력 JSON으로 전달합니다. 입력 파일은 저장소 밖에 둡니다.

```json
{ "email": "operator@example.invalid", "reason": "운영자 권한 부여" }
```

```sh
pnpm admin:grant < /secure/admin-role-request.json
pnpm admin:revoke < /secure/admin-role-request.json
```

명령은 대상 사용자 행을 잠근 같은 트랜잭션에서 역할과 감사 행을 확정합니다. 같은 역할을 다시 요청해도 `admin.grant`·`admin.revoke`와 `payload.changed:false`로 감사하며 실패하면 역할도 되돌립니다. 출력은 사용자 UUID·역할·변경 여부·감사 ID만 담습니다. 이메일·비밀번호·세션·키는 출력하거나 감사 payload에 넣지 않습니다. 사유는1~200자이며 개인정보를 적지 않습니다.

유효한 계정 전체 또는 월드 제재가 남은 사용자는 ADMIN으로 올리지 못합니다. 먼저 관리자가 제재를 해제해야 합니다. 역할 부여와 제재가 경쟁해도 같은 사용자 행 잠금 아래에서 자격을 다시 확인합니다.

감사 기록은 DB 시각·CLI 행위·대상 UUID·사유·전후 역할을 남기고 UPDATE·DELETE·TRUNCATE를 DB trigger로 거부합니다. 사용자 UUID와 자유 입력 사유의 보존 정책 검토는 남아 있습니다. 이번 검증은 전용 시험 DB만 사용했으며 기존 개발 계정·실제 운영자의 권한은 변경하지 않았습니다. 전체 관리자 화면·월드 조작과 AC-M3-04 인수는 후속 묶음입니다.

## 3. 사용자 관리

제재 API 묶음은 실제 DB·HTTP 검증 중이며 관리자 화면은 아직 없습니다. `admin.sanction.create`는 대상 사용자 UUID, 월드 UUID(전체는null), 사유, 만료 ISO 시각(무기한은null)을 받습니다. 관리자는 본인이나 다른 ADMIN을 제재할 수 없습니다. 만료 시각은 서버 현재보다 뒤여야 합니다. `admin.sanction.lift`는 제재 UUID와 사유를 받으며 이미 해제한 요청도 성공하되 감사에서 변경 여부를 구분합니다. 제재 행과 대상 계정·월드 이력은 자동 삭제하지 않습니다.

계정 전체 제재는 세션을 모두 닫고 새 로그인과 세션 갱신을 거부합니다. 월드 제재는 해당 월드의20개 게임 변경 요청을 거부하며 조회·복구와 다른 월드의 예약은 유지합니다. 접수한 입력과 기존30칸 예약은 취소하지 않고 엔진이 계속 실행합니다. 만료·해제된 제재는 차단하지 않습니다. 본인 조회 `sanction.mine`은 현재 세션의 유효한 월드 제재·월드 이름·사유·만료만 반환하며 타인 사용자 ID를 받지 않습니다.

생성·해제는 같은 트랜잭션에서 `sanction.create`·`sanction.lift` 감사와 확정됩니다. 감사 payload에는 제재 UUID·범위·시각·변경 여부만 담고 이메일·IP·토큰·사유 원문을 중복 넣지 않습니다. 사용자 검색과 제재 표시 화면·로그인/IP/기기 자료는 후속입니다.

게임 화면 본문 위에는 본인에게 유효한 현재 월드 제재의 사유와 기한이 표시됩니다. 기한은 한국 시각과 ISO 원문으로 확인하며 무기한은 기한 없음으로 표시합니다. 변경 요청이 거부되면 상태를 다시 확인하고 수동 새로 확인도 할 수 있습니다. 조회 실패에는 재시도가 표시됩니다. 계정 확인 중과 계정이 바뀐 응답에는 이전 사용자의 안내를 숨깁니다. 안내가 사라져도 변경 권한은 서버가 최종 검사합니다.
