# 초기화 자원 DB 이전과 편집기, 도트 바탕 지도

> 상태: 제안 초안 (2026-10-23) · 결정: [D-028](../product/decisions.md#d-028-운영자-지도-편집기와-도트-바탕-지도를-만든다-2026-10-23)
> AC: AC-P2-26 (자원 DB 이전), AC-P2-27 (편집기), AC-P2-28 (바탕 지도) · 작업: T4-76~T4-87 ([Phase 2 명세 §6](./phase2-expansion.md#6-작업-분해)) · 작업마다 착수 전에 `T4-xx.md`를 따로 쓴다

## 1. 목표

- 월드 초기화 자원(지도, 시나리오, 병종, 기본 능력치 규칙, 초상 대응표)을 DB의 판으로 읽는다. 기존 JSON은 초기화 SQL로 바꾼 뒤 지운다 (2026-10-23 소유자 지시).
- 운영자가 게임 안 관리자 콘솔에서 지도를 편집한다. 지형(해안·강·산맥·호수), 도시 위치, 연결, 도시 추가와 삭제까지 고친다.
- 운영자가 나머지 초기화 자원도 편집한다. 시나리오(국가, 장수, 도시 소유, 시작 연월), 병종, 기본 능력치 규칙, 초상 대응표다 (2026-10-23 소유자 지시).
- 검증을 통과한 판만 게시한다. 게시한 판은 새 월드를 만들 때 고른다. 진행 중인 월드는 영향받지 않는다.
- 게시한 판의 지형 층을 밑그림으로 삼아 고전 게임 느낌의 도트 바탕 지도를 만들고 메인·공개 지도 아래에 깐다.

## 2. 지금 상태 (main `0115e6b`)

- 지도는 `resources/map/che.json` 하나다. core2026 `df6c926`의 `map_che.json`을 옮긴 것이고 MIT 고지가 있다. 좌표계는 700×500, 도시 94개다(`apps/web/src/main/WorldMap.tsx:5-7`).
- 월드를 만들면 도시가 월드별 `City` 행으로 복사된다(`packages/db/prisma/schema.prisma:115`). 월드는 `mapKey`를 저장한다.
- 월드 초기화 자원은 엔진의 `loadInitialWorld` 한 곳이 파일 5개를 읽는다(`apps/engine/src/world/resources.ts:11-21`): `map/<키>.json`, `scenario/<키>.json`, `unitset/<키>.json`, `scenario/default.json`(능력치 규칙), `portraits/rtk14-map.json`.
- 재생은 생성 기록의 `mapKey`로 지도 자원을 다시 읽고 `resourceHash`에 넣는다(`apps/engine/src/replay.ts:51-58`). 그래서 같은 키의 내용이 바뀌면 옛 월드의 재생이 깨진다.
- 시뮬레이터와 시험 고정물도 같은 함수를 DB 없이 부른다(`tools/sim/cli.ts:42`, `apps/engine/test/monthlyFixture.ts:4`).
- 지도 그리기에는 바탕 그림이 없다. 도시 점과 연결선만 그린다.
- 옛 독립 편집기 [opensamguk-map-editor](https://github.com/peppone-choi/opensamguk-map-editor)(`e15ce32`)는 1000×740 캔버스의 다른 형식이다. 기능 목록(배경 배치, 성 추가·이동·삭제, 연결 편집, JSON 가져오기·내보내기)만 참고한다.

## 3. 핵심 계약

### C-M1. 자원 카탈로그와 바뀌지 않는 판

- 새 모델 `GameResource`에 자원을 판 단위로 둔다. 열은 종류(`MAP`·`SCENARIO`·`UNIT_SET`·`STAT_RULES`·`PORTRAIT_MAP`), 이름, 판 번호, 상태(`DRAFT`·`PUBLISHED`), 내용(`jsonb`), 정규 해시, 출처, 만든 사람, 게시 시각이다.
- 키는 `<이름>@<판 번호>`다. 내장 자원의 지금 키(`che`, `1030`, `basic`)는 그 이름의 1판을 가리키는 별칭으로 영구히 남긴다. 그래서 기존 월드의 `mapKey`·`scenarioKey`와 재생 기록은 바꾸지 않는다.
- 게시한 판은 고칠 수 없다. 고치려면 새 판을 만든다. 재생은 판의 정규 해시를 대조한다.

### C-M1a. JSON을 없애고 초기화 SQL로 넣는다 (2026-10-23 소유자 지시)

- 내장 JSON 5종(`resources/map/che.json`, `scenario/1030.json`, `scenario/default.json`, `unitset/basic.json`, `portraits/rtk14-map.json`)을 한 번 변환해 초기화 SQL `packages/db/sql/resources-init.sql`을 만든다. 변환이 끝나면 JSON 파일과 파일 읽기 코드(`apps/engine/src/world/resources.ts`의 `readFile`)를 지운다.
- 초기화 SQL은 마이그레이션 뒤에 `pnpm db:init-resources`로 따로 돌린다. 내용은 `INSERT ... ON CONFLICT DO NOTHING` 뒤 정규 해시를 대조하는 검사다. 두 번 돌려도 결과가 같다. 같은 키에 다른 내용이 있으면 실패한다. `pnpm db:up`, `pnpm test:int`, E2E 준비, CI의 DB 작업이 이 명령을 마이그레이션 다음에 부른다.
- 자원 판이 없는 DB에서 월드를 만들면 어떤 자원이 없는지 알려 주고 실패한다. 빈 지도로 넘어가지 않는다.
- 출처: SQL 머리에 core2026 `df6c926` MIT 고지를 그대로 옮기고 각 행의 출처 열에도 적는다. `resources/NOTICE.md`는 SQL 파일을 가리키도록 고친다. 고지는 지우지 않는다.
- 초상 대응표 생성기(`tools/portrait-map/generate.ts`)는 JSON 대신 새 판을 넣는 SQL을 만든다.
- 정규화: `jsonb`는 키 순서와 숫자 표기를 바꾼다. 해시는 키를 정렬한 정규 JSON으로 계산한다. 변환 전 JSON과 DB에서 읽은 값으로 만든 `buildInitialWorld` 결과와 `resourceHash`가 같아야 한다. 이 대조는 변환 작업 안에서 한 번 하고 결과를 구현 기록에 남긴다.

### C-M1b. 읽는 곳

- `loadInitialWorld`는 DB에서 판을 읽는다. 엔진의 월드 생성·재생, 시뮬레이터(`pnpm sim`, `tools/season-throughput.ts`), E2E 준비(`e2e/rankingSeed.ts`)가 모두 이 길을 쓴다.
- 규칙 패키지는 지금처럼 DB를 모른다 (AGENTS §6). 읽은 값을 인자로 받는다.
- 지금 JSON을 읽는 단위 시험(`apps/engine/src/simulation.test.ts`, `apps/engine/src/world/resources.test.ts`, `tools/commands.test.ts`, `tools/world-bootstrap.test.ts`, `tools/t1-11.test.ts`)은 DB를 쓰는 통합 시험으로 옮긴다. 그래서 `pnpm check`에서 빠지고 `pnpm test:int`에 들어간다. 규칙 단위 시험은 작은 고정물로 돈다.
- 시뮬레이터가 DB를 쓰므로 `.github/workflows/simulation.yml`에 PostgreSQL 서비스를 더한다(`season-throughput.yml:18-28`과 같은 방식). AC-M1-18의 15분 측정도 DB를 띄운 상태에서 다시 잰다. 시뮬레이션 결과 해시가 이전 전과 같아야 한다.
- 화면: 전투 시뮬레이터가 번들에 넣던 병종 자료(`apps/web/src/battleSim/publicUnitSet.ts:4`)는 월드의 병종 판을 돌려주는 API로 받는다. E2E 기대값(`e2e/battleSim.spec.ts:17`)도 DB에서 읽는다.

### C-M2. 지도 형식 v2

`mapSchema`(`packages/rules/src/world/resources.ts:18`)에 지형 층을 더한다. 도시 필드는 지금 형식 그대로다.

```ts
type Terrain = {
  coast: Array<Array<[number, number]>>;     // 바다와 땅의 경계, 닫힌 다각형
  lakes: Array<Array<[number, number]>>;     // 닫힌 다각형
  rivers: Array<{ name?: string; points: Array<[number, number]> }>; // 열린 선
  mountains: Array<Array<[number, number]>>; // 산맥 영역, 닫힌 다각형
};
// v2 = 기존 MapResource + { version: 2, terrain?: Terrain }
```

- 좌표는 도시와 같은 좌표계다. 캔버스 크기는 지도마다 둔다(기본 700×500).
- 지형 층은 표시 전용이다. 이동·전투 규칙은 지금처럼 도시 연결만 본다. 지형이 규칙에 들어가는 것은 이 범위가 아니다 (AGENTS §3).

### C-M3. 검증기

게시 전에 아래를 모두 통과해야 한다. 같은 검사를 편집 화면과 서버가 함께 쓴다.

- 도시 ID와 이름이 겹치지 않는다. 좌표가 캔버스 안이다. 규모·지역 값이 범위 안이다.
- 연결이 양쪽에 있고 자기 자신을 가리키지 않는다. 모든 도시가 하나의 연결망에 이어진다.
- 이 지도와 함께 쓸 시나리오가 참조하는 도시(국가 수도, 장수 위치)가 모두 있다. 없으면 어느 시나리오의 어느 항목인지 알려 준다.
- 지형 다각형이 닫혀 있다.

### C-M3a. 지도 밖 자원의 검증

- 시나리오: 국가 ID·이름이 겹치지 않는다. 장수 ID가 겹치지 않고 소속 국가와 위치 도시가 있다. 국가 수도와 도시 소유가 함께 쓸 지도 판의 도시를 가리킨다. 시작 연월과 종료 조건이 범위 안이다. 시나리오 판은 함께 쓸 지도 판 하나를 기록한다.
- 병종: key가 겹치지 않고 수치가 규칙 스키마(`packages/rules/src/world/resources.ts:77`) 범위 안이다. 시나리오가 쓰는 병종이 모두 있다.
- 능력치 규칙: 스키마(`resources.ts:102`)를 지나고 합계·최솟값·최댓값이 서로 모순되지 않는다.
- 초상 대응표: 초상 ID가 10001~11000 안이다 (이미지 자산 §2).
- 검사는 종류마다 규칙 패키지의 순수 함수로 두고 편집 화면과 서버가 같은 함수를 쓴다.

### C-M4. 권한과 감사

- 편집·게시는 관리자 권한(T3-05) 가운데 자원 편집 권한이 있는 계정만 한다. 종류마다 권한을 나누지 않는다. 행위자는 세션에서 정한다.
- 초안 저장, 게시, 판 복제는 모두 감사 로그(T3-05)에 남는다.
- 초안 저장은 revision으로 동시 편집 충돌을 막는다. 두 운영자가 같은 초안을 고치면 늦은 저장이 거부된다.

## 4. 도트 바탕 지도

- 게시한 판마다 바탕 그림 하나를 둔다. 크기는 캔버스의 3배(기본 2100×1500)이고 형식은 WebP다.
- 만드는 순서: 편집기가 지형 층을 단색 도트 밑그림(바다·땅·강·산·호수 5색)으로 내보낸다. Codex가 이 밑그림만 입력으로 고전 게임 느낌의 도트 그림을 생성한다. 도시 점과 이름은 그림에 넣지 않는다.
- 보관: 이미지 저장소(D-016) `maps/<지도 키>/base.webp`. 판마다 경로가 달라 덮어쓰지 않는다.
- 화면: 그림이 있으면 지도 그리기가 도시 점·연결선 아래에 깐다. 없으면 지금처럼 바탕 없이 그린다.
- 출처 기록: 그림마다 밑그림 파일 해시, 생성 도구, 생성 일시를 이미지 저장소의 출처 표에 남긴다.

### 외부 그림을 참고할 때

와룡전 리메이크(`phixteam1/GRZ` v1.1)의 그림은 원작 그림을 확대한 것으로 보이며 이용 허락이 없다 (D-028).

- 해도 되는 것: 화풍, 색 구성, 어떤 지형을 표시할지 정할 때 보고 참고하기.
- 하면 안 되는 것: 따라 그리기, 이미지 생성의 입력 그림이나 참조 이미지로 넣기, 지형 배치를 그대로 옮기기, 저장소·이미지 서버에 올리기.

## 5. 작업 순서

```text
T4-76 형식 v2·검증기 ─▶ T4-77 자원 카탈로그 DB ─┬─▶ T4-78 지도 초안·게시 API ──┬─▶ T4-79 월드 생성 판 고르기
          │                                    │                            └─▶ T4-81 관리자 콘솔 연결 ◀── T4-80
          └─▶ T4-80 편집 캔버스 ─▶ T4-82 che 지형 층 초안 ─▶ T4-83 바탕 그림 생성 ─▶ T4-84 지도 화면에 깔기
T4-78 초안·게시 API (모든 종류) ─▶ T4-87 시나리오·병종·능력치·초상 대응표 편집 화면 ◀── T3-06
```

- T4-77은 편집기와 상관없이 혼자 가치가 있다. JSON을 초기화 SQL로 바꾸고 지운 뒤에도 기존 월드 재생 해시가 그대로임을 증명한다.
- T4-85(병종 조회 API)와 T4-86(전투 시뮬레이터가 API 값 쓰기)은 T4-77의 JSON 삭제와 같은 시점에 들어가야 화면 빌드가 깨지지 않는다. T4-77의 JSON 삭제 커밋은 T4-86 뒤에 병합한다.
- T4-80 편집 캔버스는 서버 없이 JSON 가져오기·내보내기로 돈다. 그래서 T4-78과 관리자 콘솔(T3-05·T3-06)을 기다리지 않고 T4-82·T4-83까지 먼저 갈 수 있다.
- T4-81 연결은 T3-05(관리자·감사)와 T3-06(관리자 콘솔)이 main에 들어온 뒤다.

## 6. 검증 요약

| 무엇 | 어떻게 |
| ---- | ------ |
| 초기화 SQL | PostgreSQL: 두 번 돌려도 같은 결과, 같은 키 다른 내용은 실패, 출처 열 보존, 자원 없는 DB의 월드 생성은 이유와 함께 실패 |
| 변환 대조 | 변환 작업 안에서 한 번: 변환 전 JSON과 DB 값의 `buildInitialWorld` 결과·`resourceHash`가 같다 |
| 시뮬레이터 | CI: DB로 `pnpm sim --seeds 10` 결과 해시가 이전 전 실행과 같다. 시간은 기록만 하고 AC-M1-18 판정은 따로 |
| 남은 파일 | 정적 검사: `resources/`에 JSON이 없고 `readFile`로 자원을 읽는 코드가 없다 |
| 기존 재생 | 통합: 이전 전 고정물(`apps/engine/test/fixtures/replay-v1-b8f5074.json`)과 이전 뒤 재생 해시가 같다 |
| 판 불변 | PostgreSQL: 게시 판 수정 요청 거부, 같은 키 재생 해시가 바뀌지 않음 |
| 진행 중 월드 | 통합: 새 판 게시 뒤 기존 월드의 `City`와 재생 결과가 그대로 |
| 검증기 | 단위: 위 C-M3 항목마다 통과 1건·실패 1건, `che` 통과 |
| 권한 | HTTP: 무인증·일반 계정·제재 계정의 편집·게시 거부, 감사 로그 기록 |
| 동시 편집 | HTTP: 늦은 초안 저장 거부 |
| 편집 화면 | Playwright: 도시 추가·이동·삭제, 연결, 지형 그리기, 검증 오류 표시, 내보내기·가져오기 왕복 |
| 자원 편집 | Playwright: 시나리오 장수 추가·국가 소유 변경, 병종 수치 변경, 능력치 규칙 변경을 초안 저장 → 검증 오류 → 고쳐서 게시. 새 판으로 월드 생성, 기존 월드 그대로 |
| 자원 검증 | 단위: C-M3a 항목마다 통과 1건·실패 1건, 내장 판 통과 |
| 바탕 그림 | Playwright: 그림 있는 판은 도시 점 아래에 그림, 없는 판은 바탕 없음. 출처 표에 해시가 있다 |

## 7. 하지 않는 것

- 지형을 이동·전투 규칙에 넣기
- 플레이어가 지도를 만들어 올리기
- 진행 중인 월드의 지도 바꾸기
- 변환 전에 JSON 내용 고치기 (내용은 그대로 옮긴다)
