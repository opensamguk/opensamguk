# 초기화 자원 DB 이전, 지도 편집기, 도트 바탕 지도

> 상태: 제안 초안 (2026-10-23) · 결정: [D-027](../product/decisions.md#d-027-운영자-지도-편집기와-도트-바탕-지도를-만든다-2026-10-23)
> AC: AC-P2-26 (자원 DB 이전), AC-P2-27 (편집기), AC-P2-28 (바탕 지도) · 작업: T4-76~T4-84 ([Phase 2 명세 §6](./phase2-expansion.md#6-작업-분해)) · 작업마다 착수 전에 `T4-xx.md`를 따로 쓴다

## 1. 목표

- 월드 초기화 자원(지도, 시나리오, 병종, 기본 능력치 규칙, 초상 대응표)을 JSON 파일이 아니라 DB의 판으로 읽는다. 파일은 내장 판을 들여오는 원본으로만 남는다 (2026-10-23 소유자 지시).
- 운영자가 게임 안 관리자 콘솔에서 지도를 편집한다. 지형(해안·강·산맥·호수), 도시 위치, 연결, 도시 추가와 삭제까지 고친다.
- 검증을 통과한 판만 게시한다. 게시한 판은 새 월드를 만들 때 고른다. 진행 중인 월드는 영향받지 않는다.
- 게시한 판의 지형 층을 밑그림으로 삼아 고전 게임 느낌의 도트 바탕 지도를 만들고 메인·공개 지도 아래에 깐다.

## 2. 지금 상태 (main `0115e6b`)

- 지도는 `resources/map/che.json` 하나다. core2026 `df6c926`의 `map_che.json`을 옮긴 것이고 MIT 고지가 있다. 좌표계는 700×500, 도시 94개다(`apps/web/src/main/WorldMap.tsx:5-7`).
- 월드를 만들면 도시가 월드별 `City` 행으로 복사된다(`packages/db/prisma/schema.prisma:115`). 월드는 `mapKey`를 저장한다.
- 월드 초기화 자원은 엔진의 `loadInitialWorld` 한 곳이 파일 5개를 읽는다(`apps/engine/src/world/resources.ts:11-21`): `map/<키>.json`, `scenario/<키>.json`, `unitset/<키>.json`, `scenario/default.json`(능력치 규칙), `portraits/rtk14-map.json`.
- 재생은 생성 기록의 `mapKey`로 지도 자원을 다시 읽고 `resourceHash`에 넣는다(`apps/engine/src/replay.ts:51-58`). 그래서 같은 키의 내용이 바뀌면 옛 월드의 재생이 깨진다.
- 시뮬레이터와 시험 고정물도 같은 함수를 DB 없이 부른다(`tools/sim/cli.ts:42`, `apps/engine/test/monthlyFixture.ts:4`).
- 지도 그리기에는 바탕 그림이 없다. 도시 점과 연결선만 그린다.
- 옛 독립 편집기 [opensamguk-map-editor](https://github.com/peppone-choi/opensamguk-map-editor)(`e15ce32`)는 1000×740 캔버스의 다른 형식이다. 기능 목록(배경 배치, 성 추가·이동·삭제, 연결 편집, JSON 가져오기·내보내기)만 참고한다.

## 3. 핵심 계약

### C-M1. 자원 카탈로그와 바뀌지 않는 판

- 새 모델 `GameResource`에 자원을 판 단위로 둔다. 열은 종류(`MAP`·`SCENARIO`·`UNIT_SET`·`STAT_RULES`·`PORTRAIT_MAP`), 이름, 판 번호, 상태(`DRAFT`·`PUBLISHED`), 내용(Json), 내용 해시, 출처, 만든 사람, 게시 시각이다.
- 키는 `<이름>@<판 번호>`다. 내장 자원의 지금 키(`che`, `1030`, `basic`)는 그 이름의 1판을 가리키는 별칭으로 영구히 남긴다. 그래서 기존 월드의 `mapKey`·`scenarioKey`와 재생 기록은 바꾸지 않는다.
- 게시한 판은 고칠 수 없다. 고치려면 새 판을 만든다. 재생은 판의 내용 해시를 대조한다.
- 내장 JSON 5종은 내용을 바꾸지 않고 그대로 DB로 옮긴다 (2026-10-23 소유자 지시). 운영의 월드 생성과 재생은 파일을 읽지 않는다.
- 들여오기: `pnpm resources:import`가 `resources/` 파일을 읽어 내장 판으로 넣는다. 두 번 돌려도 같다. 같은 키에 다른 내용이 이미 있으면 덮어쓰지 않고 실패한다. 파일 머리의 출처 주석(core2026 MIT)은 출처 열에 그대로 옮긴다.
- 읽기: `loadInitialWorld`는 자원 공급자 하나를 받는다. 엔진의 월드 생성·재생과 시뮬레이터(`pnpm sim`, `tools/season-throughput.ts`)는 DB 공급자를 쓴다 (2026-10-23 소유자 지시). 파일 공급자는 들여오기 검사와 DB 없는 단위 시험만 쓴다. 두 공급자는 같은 키에 같은 내용을 낸다는 시험으로 묶는다.
- 시뮬레이터가 DB를 쓰므로 `.github/workflows/simulation.yml`에 PostgreSQL 서비스를 더하고 들여오기를 먼저 돌린다(`season-throughput.yml:18-28`과 같은 방식). AC-M1-18의 15분 측정도 DB를 띄운 상태에서 다시 잰다. 시뮬레이션 결과 해시가 이전 전과 같아야 한다.
- 규칙 패키지는 지금처럼 DB와 파일을 모른다 (AGENTS §6). 공급자는 엔진에 둔다.
- `resources/` 파일은 지우지 않고 고치지 않는다. 빈 DB를 채우는 원본이다. 파일 공급자는 들여오기 검사와 DB 없는 단위 시험만 쓴다.

### C-M2. 지도 형식 v2

`mapSchema`(`packages/rules/src/world/resources.ts:18`)에 지형 층을 더한다. 도시 필드는 지금 형식 그대로다.

```ts
type Terrain = {
  coast: Array<Array<[number, number]>>;     // 바다와 땅의 경계, 닫힌 다각형
  lakes: Array<Array<[number, number]>>;     // 닫힌 다각형
  rivers: Array<{ name?: string; points: Array<[number, number]> }>; // 열린 선
  mountains: Array<Array<[number, number]>>; // 산맥 영역, 닫힌 다각형
};
// v2 = 기존 MapResource + { version: 2, terrain?: Terrain }
```

- 좌표는 도시와 같은 좌표계다. 캔버스 크기는 지도마다 둔다(기본 700×500).
- 지형 층은 표시 전용이다. 이동·전투 규칙은 지금처럼 도시 연결만 본다. 지형이 규칙에 들어가는 것은 이 범위가 아니다 (AGENTS §3).

### C-M3. 검증기

게시 전에 아래를 모두 통과해야 한다. 같은 검사를 편집 화면과 서버가 함께 쓴다.

- 도시 ID와 이름이 겹치지 않는다. 좌표가 캔버스 안이다. 규모·지역 값이 범위 안이다.
- 연결이 양쪽에 있고 자기 자신을 가리키지 않는다. 모든 도시가 하나의 연결망에 이어진다.
- 이 지도와 함께 쓸 시나리오가 참조하는 도시(국가 수도, 장수 위치)가 모두 있다. 없으면 어느 시나리오의 어느 항목인지 알려 준다.
- 지형 다각형이 닫혀 있다.

### C-M4. 권한과 감사

- 편집·게시는 관리자 권한(T3-05) 가운데 지도 권한이 있는 계정만 한다. 행위자는 세션에서 정한다.
- 초안 저장, 게시, 판 복제는 모두 감사 로그(T3-05)에 남는다.
- 초안 저장은 revision으로 동시 편집 충돌을 막는다. 두 운영자가 같은 초안을 고치면 늦은 저장이 거부된다.

## 4. 도트 바탕 지도

- 게시한 판마다 바탕 그림 하나를 둔다. 크기는 캔버스의 3배(기본 2100×1500)이고 형식은 WebP다.
- 만드는 순서: 편집기가 지형 층을 단색 도트 밑그림(바다·땅·강·산·호수 5색)으로 내보낸다. Codex가 이 밑그림만 입력으로 고전 게임 느낌의 도트 그림을 생성한다. 도시 점과 이름은 그림에 넣지 않는다.
- 보관: 이미지 저장소(D-016) `maps/<지도 키>/base.webp`. 판마다 경로가 달라 덮어쓰지 않는다.
- 화면: 그림이 있으면 지도 그리기가 도시 점·연결선 아래에 깐다. 없으면 지금처럼 바탕 없이 그린다.
- 출처 기록: 그림마다 밑그림 파일 해시, 생성 도구, 생성 일시를 이미지 저장소의 출처 표에 남긴다.

### 외부 그림을 참고할 때

와룡전 리메이크(`phixteam1/GRZ` v1.1)의 그림은 원작 그림을 확대한 것으로 보이며 이용 허락이 없다 (D-027).

- 해도 되는 것: 화풍, 색 구성, 어떤 지형을 표시할지 정할 때 보고 참고하기.
- 하면 안 되는 것: 따라 그리기, 이미지 생성의 입력 그림이나 참조 이미지로 넣기, 지형 배치를 그대로 옮기기, 저장소·이미지 서버에 올리기.

```text
T4-76 형식 v2·검증기 ─▶ T4-77 자원 카탈로그 DB ─┬─▶ T4-78 지도 초안·게시 API ──┬─▶ T4-79 월드 생성 판 고르기
          │                                    │                            └─▶ T4-81 관리자 콘솔 연결 ◀── T4-80
          └─▶ T4-80 편집 캔버스 ─▶ T4-82 che 지형 층 초안 ─▶ T4-83 바탕 그림 생성 ─▶ T4-84 지도 화면에 깔기
```

- T4-77은 편집기와 상관없이 혼자 가치가 있다. 지도·시나리오·병종을 DB 판으로 읽게 바꾸고 기존 월드 재생 해시가 그대로임을 증명한다.
- T4-80 편집 캔버스는 서버 없이 JSON 가져오기·내보내기로 돈다. 그래서 T4-78과 관리자 콘솔(T3-05·T3-06)을 기다리지 않고 T4-82·T4-83까지 먼저 갈 수 있다.
- T4-81 연결은 T3-05(관리자·감사)와 T3-06(관리자 콘솔)이 main에 들어온 뒤다.

## 6. 검증 요약

| 무엇 | 어떻게 |
| ---- | ------ |
| 들여오기 | PostgreSQL: 두 번 들여오기가 같은 결과, 같은 키 다른 내용은 실패, 출처 열 보존 |
| 시뮬레이터 | CI: DB 공급자로 `pnpm sim --seeds 10` 결과 해시가 이전 전 실행과 같다. 시간은 기록만 하고 AC-M1-18 판정은 따로 |
| 공급자 일치 | 단위: 파일 공급자와 DB 공급자가 같은 키에 같은 `buildInitialWorld` 결과와 `resourceHash` |
| 기존 재생 | 통합: 이전 전 고정물(`apps/engine/test/fixtures/replay-v1-b8f5074.json`)과 이전 뒤 재생 해시가 같다 |
| 판 불변 | PostgreSQL: 게시 판 수정 요청 거부, 같은 키 재생 해시가 바뀌지 않음 |
| 진행 중 월드 | 통합: 새 판 게시 뒤 기존 월드의 `City`와 재생 결과가 그대로 |
| 검증기 | 단위: 위 C-M3 항목마다 통과 1건·실패 1건, `che` 통과 |
| 권한 | HTTP: 무인증·일반 계정·제재 계정의 편집·게시 거부, 감사 로그 기록 |
| 동시 편집 | HTTP: 늦은 초안 저장 거부 |
| 편집 화면 | Playwright: 도시 추가·이동·삭제, 연결, 지형 그리기, 검증 오류 표시, 내보내기·가져오기 왕복 |
| 바탕 그림 | Playwright: 그림 있는 판은 도시 점 아래에 그림, 없는 판은 바탕 없음. 출처 표에 해시가 있다 |
