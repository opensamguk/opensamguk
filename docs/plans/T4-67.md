#### 4.3 계산

P0~P6 권장안을 넣은 모양이다. 결정이 다르면 이 절만 바뀐다.

- 실효 능력치: 통솔 `leadership`, 무력 `strength + round(intel/4)`, 지력 `intel + round(strength/4)`. 각각 0~255로 자르고 `Math.trunc`. 부상은 쓰지 않는다(P2).
- 기본 점수 `base = 셋의 합 × (1 + level(experience)/500)`. `level(e) = clamp(e < 1000 ? trunc(e/100) : trunc(√(e/10)), 0, 255)` (P3).
- 점수 `score = round(base × r1 × 결과 배율)`. 결과 배율은 보통 1, 실패 `0.2 + r3 × 0.2`, 성공 `2.2 + r3 × 0.8`.
- 국고 몫 `applied = isFront(현재 도시) ? score × FRONT_FACTOR : score`, 국고에는 `Math.trunc(applied)` (P4).
- 경험 `score × 0.7 / 3`, 공헌 `score / 3`. 실수 그대로 효과에 넣고 `applyEffects`가 누적 뒤 반올림한다.

`isFront`는 지금 `investment.ts` 안의 비공개 함수다. 같은 판정을 쓰려면 그 파일에서 내보내야 하는데 `commands/domestic/`은 기본 37개 파일이다. 구현은 (가) `investment.ts`에서 `isFront`를 export만 하거나 (나) `procure.ts`에 같은 식을 둔다. 기술 선택이며 쟁점 R1이다.

#### 4.4 RNG 소비 순서

원작과 난수열 일치는 목표가 아니다(D-001). 양 끝 포함 정수는 `rng.int`, 실수는 `rng.next()`다.

1. `rng.int(0, 1)` 자원. 0이면 `gold`, 1이면 `rice`.
2. `rng.next()` → r1 무작위 배율.
3. `rng.next()` → r2 결과 판정. r2 < 0.3 실패, r2 < 0.4 성공, 나머지 보통. 원작은 `roll − 0.3 ≤ 0`을 실패로 보지만 우리 `next()`는 [0, 1)이라 경계 차이는 확률 0이다.
4. 실패나 성공이면 `rng.next()` → r3.

능력 경험 선택 난수(원작 `:139-140`)는 P5에 따라 쓰지 않는다. 합계 3회 또는 4회다.

규칙 PR의 증거는 위 시험 결과와 커밋이다. 대응표의 engine 이후 단계(엔진 턴 실행, `pnpm test:int` 저장과 롤백, SIGKILL 재시작, 12개월 재생 해시, HTTP 저장·사전 검사, Chromium 목록 표시)는 T4-03·T4-04 병합 뒤 같은 T4-67로 더한다. 권한 단계는 T4-03의 `turns` 시험에 이 key의 무인증·다른 사용자·제재·잘못된 입력 사례와 재야·방랑 규칙 실패 사례를 더해 받는다.
