### 시나리오 형식 (변환기가 알아야 할 것)

- 국가 줄: `[이름, 색, 금, 쌀, 설명, 기술, 성향, 규모(0~7), [소속 도시 이름…]]`. 첫 도시가 수도다. 국가 번호는 배열 순서 + 1.
- 장수 줄: `[상성, 이름, 초상 경로, 국가 번호(0=재야), 도시 이름|null, 통, 무, 지, 관직, 생년, 몰년, 성격|null, 특기|null, (대사)]`
  - 관직: 0 재야, 1 장수, 5~10 수뇌, 11 참모, 12 군주. **이 숫자 체계를 그대로 `officerLevel`로 쓴다** (데이터 모델의 "정할 것" 해결).
  - 도시가 `null`이면 소속 국가 도시 중 하나, 재야면 전체 도시 중 하나를 **시드 RNG로** 고른다 (core2026 `packages/logic/src/world/bootstrap.ts` 520~530행과 같은 방식).
  - 초상 경로(`장수/조조.jpg`)는 무시하고 `portraitId = null`로 둔다. 이름 → 초상 ID 대응은 T1-17에서 한다.
  - 시작 연도에 15세 미만인 장수(`생년 + 15 > startYear`)도 만들되 `activeFromYear = 생년 + 15`를 저장한다. 행동 제외는 T1-07.
- 외교 줄: `[국가, 국가, 종류(0 전쟁·1 선포·7 불가침), 기간(개월)]` → `Diplomacy(state, untilTick)`. 같은 쌍이 두 번 나오면 마지막 줄을 쓴다.
- 도시 초기값: 지도 `initial`, 최대치: 지도 `max`, 민심: 지도 `defaults.trust`(50). 국가 소속 도시는 시나리오 국가 줄로 정한다.

### 시드 RNG와 해시 (`packages/shared`)

- `createRng(seed: string)`: 문자열 시드를 해시해 상태를 만드는 작은 PRNG(예: sfc32 또는 xoshiro128**). `next(): number`(0 이상 1 미만),
  `int(min, max)`, `pick(array)`만 둔다. **알고리즘을 고정하고 테스트로 처음 5개 값을 박아 둔다** (바뀌면 재생이 깨진다).
- `rngFor(worldSeed, ...scope)`: `rngFor(seed, 'bootstrap')`, 나중에 `rngFor(seed, 'turn', tick, generalId)`처럼 용도별로 독립된 흐름을 만든다.
- `hashState(value)`: 키를 정렬한 JSON의 SHA-256. 이 함수만 Node `crypto`를 쓰므로 `packages/shared/src/node/`처럼 경계를 분리하거나
  순수 JS 해시를 쓴다. rules는 node 내장을 import할 수 없다는 점에 주의.

### 접근

1. 리소스 파일 4개를 옮기고 병종을 4종으로 줄인다. `NOTICE.md`를 쓴다.
2. `packages/rules/src/world/resources.ts`: 지도·시나리오·병종·능력치 규칙의 zod schema. 튜플은 `z.tuple`로 검증한다.
3. `packages/rules/src/world/bootstrap.ts`: `buildInitialWorld({ map, scenario, unitSet, seed }) → WorldInit` (순수 함수).
   로드 시 검사: 연결이 양방향인지, 국가 도시·수도가 지도에 있는지, 같은 도시를 두 국가가 갖지 않는지. 실패하면 이유를 담은 오류.
4. Prisma 모델 5개와 첫 migration. 필드는 [데이터 모델](../product/data-model.md)을 따르되 이번에 쓰는 것만 넣는다.
   모든 게임 테이블에 `worldId`. `General.userId`는 nullable(NPC).
5. `apps/engine/src/cli/createWorld.ts`: `pnpm world:create --scenario 1030 --map che --seed <문자열> --turn-term <분> --name <이름>`.
   한 트랜잭션으로 저장하고 월드 ID와 상태 해시를 출력한다.
6. 테스트 (아래).

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 변환 결과 | 단위: 도시 94, 국가 21, 장수 491, 외교 줄 수, 조조의 수도가 진류 |

| DB 저장 | 통합(`pnpm test:int`): 월드 생성 → DB에서 다시 읽은 상태의 해시 = 메모리 해시 |

통합 테스트는 개발 DB와 다른 DB(예: `opensamguk_test`)를 쓰고 테스트 전에 비운다 ([테스트 정책](../testing-policy.md) §5를 이번에 채운다).

## 구현 기록 (Codex)

- 바꾼 것:
  - 지정 커밋 `df6c926`의 지도·시나리오·병종·기본 능력치 규칙을 `resources/`에 추가했다. 각 JSON에 출처를 표시하고 `resources/NOTICE.md`에 MIT 전문과 축소 내역을 남겼다. 병종은 4종, `general_ex`·사건·초상은 사용하지 않는다.
  - zod 튜플 검증과 순수 `buildInitialWorld()`를 구현했다. 도시 94·국가 21·장수 491·중복 정리 후 외교 7쌍, 수도·연결·소유·참조 검증, 시드 배치·15세 활성화 연도·원본 관직을 처리한다.
  - shared에 FNV-1a + Mulberry32 RNG와 용도별 스트림을 추가하고 첫 5개 값을 고정했다. 키 정렬 JSON SHA-256은 Node 전용 `@opensamguk/shared/node`로 분리했다.
  - Prisma 5개 모델과 첫 migration을 추가했다. 국가·장수 ID는 월드별 복합 PK이며 모든 외래키에 `worldId`를 포함한다. 수도의 순환 참조까지 한 트랜잭션으로 저장하고 재적재는 Repeatable Read로 읽는다.
  - `pnpm world:create`, `pnpm db:migrate`, `pnpm test:int`를 추가했다. 전용 `_test` DB 생성·migration·개발 DB 대상 거부와 테스트 전후 정리를 구현했다. 로컬 개발 DB에도 첫 migration을 적용했다.
- 계획과 달라진 점과 이유:
  - 외교 만료 tick 계산에 필요해 T1-04에서 정한 `TICKS_PER_MONTH = 10_000` 상수를 먼저 추가했다. 시계·상태 전환 기능은 추가하지 않았다.
  - 초기 상태 해시는 `WorldInit`만 대상으로 하며 DB 월드 ID·이름·생성 시각·턴 간격 등 운영 설정은 제외한다. 동일 시드로 이름이 다른 월드 두 개를 저장해도 메모리·재적재 해시가 일치한다.
  - 기존 Node 내장 모듈 차단 패턴이 정상적인 `clock/constants`까지 막아 import 시작점에 고정하고 회귀 검증을 추가했다. rules의 Node 전용 shared 진입점도 차단한다.
  - 기존 lint 테스트의 첫 플러그인 로딩이 5초를 넘어 한 번 실패했다. 준비 단계를 `beforeAll`로 분리한 뒤 전체 검사를 재실행해 통과했다.
- 검증 결과 (2026-10-20):
  - `pnpm check` 통과: Prisma 생성, lint, 6개 패키지 타입, 단위 테스트 41개.
  - `pnpm test:int` 통과: 실제 PostgreSQL 18의 `opensamguk_test`에서 5개. 저장·재적재·동일 시드의 두 월드 해시, 중간 실패 전체 롤백, 잘못된 생성 옵션, 다른 월드 참조 거부, CLI 실행을 확인했다.
  - `pnpm e2e` 통과: 로그인 화면 및 실제 서버·DB 정상 표시 1개.
  - 새 tools 코드도 별도 strict `tsc --noEmit`으로 검사했고, `git diff --check`가 통과했다.
  - 구현을 마쳐 대기열을 `리뷰`로 변경한다. Claude 리뷰 전이므로 AC-M1-03은 🟨다. 커밋·푸시는 하지 않았다.
