### 1.2 명령별

| 명령 | 능력치 | 성공 효과 | 부상 |
| ---- | ------ | --------- | ---- |
| 화계 `che_화계.ts` | 지력 | 농업 −P, 상업 −S, 도시 상태 32(불탐) | 있음 |
| 파괴 `che_파괴.ts` | 무력 | 수비 −P, 성벽 −S, 도시 상태 32 | 있음 |
| 선동 `che_선동.ts` | 통솔 | 치안 −P, 민심 −S(실수, 0~100으로 자름), 도시 상태 32 | 있음 |

탈취는 연도 계수 `sqrt(1 + max(0, 연도 − 시작 연도)/4)/2`를 쓴다. 금은 `P × 도시 규모 × 연도 계수 × (0.25 + 상업/상업 최대/4)`, 쌀은 S와 농업으로 같은 식이다. 대상 도시가 보급 상태(`supplyState === 1`)면 대상 국가의 금·쌀(0 미만은 0)로 상한을 두고 그만큼 뺀다. 보급이 끊긴 대상이면 대상 국가에서 빼지 않아 금·쌀이 새로 생긴다. 얻은 양의 `round(× 0.7)`은 자기 국가, 나머지는 장수가 갖고 장수 금·쌀은 더한 뒤 반올림한다.

### 1.3 제약

출발은 재야 아님, 자기 국가 도시, 보급 도시, 금·쌀이 비용 이상이다. 대상은 자기 국가 도시가 아님, 공백지가 아님, 불가침(외교 상태 7)이 아님이다. 선전포고 중이나 평시 국가도 대상이 된다. 원작 검사 순서는 재야, 자기 도시, 보급, 대상 자기 도시, 공백지, 금, 쌀, 불가침이다(`strategyCommand.ts:467~481`). §4.3은 불가침을 금·쌀 앞에 둔다.

### 4.4 계산

- 비용 `STRATAGEM.COST_GOLD = 100`, `COST_RICE = 100` (S1 (가)).
- 실효 능력치 `eff(g, stat)`: 통솔은 `g.leadership`. 무력은 `g.strength + Math.round(g.intel / 4)`, 지력은 `g.intel + Math.round(g.strength / 4)`. 0~255로 자르고 `Math.trunc`. 부상은 쓰지 않는다 (S2 (나)).
- 능력치: 화계 `intel`, 파괴 `strength`, 선동 `leadership`, 탈취 `strength`.
- 대상 장수 `defenders`: `cityKey === 대상 도시`이고 `nationId === 대상 도시 nationId`이며 `activeFromYear <= 현재 연도`인 장수를 `id` 오름차순으로. 마지막 조건은 출병 수비 장수(`attack.ts:58`)와 맞춘 우리 쪽 기술 선택이다. 현재 출병과 같은 기준이라 받아들일 만하다고 보며 확정은 Codex 계획 기술 검토가 한다.
- 공격항 `eff(actor) / 300`. 방어항 `max(0, ...defenders의 eff) / 300 + (log2(n + 1) − 1.25) × 0.04 + security / securityMax / 5 + (supplied ? 0.1 : 0)`. `sabotageDefence` 보정은 S6에 따라 없다.
- 거리 `d`: 출발 도시에서 `connections` 너비 우선 탐색, 5칸 안이면 그 거리, 아니면 99. 국경·소유와 상관없다.
- 확률 `p = min(0.5, max(0, (0.35 + 공격항 − 방어항) / d))`.
- 현재 연도는 `toGameDate(view.startYear, actor.tick ?? 0)`의 연도다.

### 4.5 RNG 소비 순서

검사를 통과한 실행 한 번이 아래 순서로만 소비한다. 순서는 원작 `strategyCommand.ts:245~343`과 같다. 양 끝 포함 정수 `nextInt(min, max + 1)`은 `rng.int(min, max)`, `nextFloat1()`은 `rng.next()`로 옮긴다.

확률 판정은 원작과 다르게 단순화한다. 원작 `RandUtil.nextBool(p)`는 p가 0 이하나 1 이상이면 난수를 쓰지 않고 정확히 0.5면 1비트를 쓴다(§1.1). 우리 `Rng`(`packages/shared/src/rng.ts`)에는 비트 추출이 없고 원작과 난수열 일치는 목표가 아니다(D-001). 그래서 판정은 언제나 `rng.next() < p` 한 번이다. 성공 확률 상한이 0.5이므로 원작과 소비가 달라지는 경우는 성공 확률이 0이거나 정확히 0.5일 때뿐이다. 부상 확률 0.3은 원작도 `nextFloat1() < 0.3`이라 같다.

1. `rng.next()` 한 번. `p`가 0이거나 정확히 0.5여도 같다. 값이 `p` 미만이면 성공.
2. 실패면 `rng.int(1, 100)` 경험, `rng.int(1, 70)` 공헌. 끝. 합계 3회.
3. 성공이고 화계·파괴·선동이면 `defenders`마다 `rng.next() < 0.3`. 맞은 장수만 이어서 `rng.int(1, 16)`. 기존 부상이 80 이상이어도 소비한다.
4. 피해량. 선동은 `rng.int(100, 800)` 다음 `rng.next()`. 나머지는 `rng.int(100, 800)` 두 번.
5. `rng.int(201, 300)` 경험, `rng.int(141, 210)` 공헌.

`Math.random()`과 현재 시각은 쓰지 않는다.
