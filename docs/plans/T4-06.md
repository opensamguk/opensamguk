### 원작 동작

공통은 세 명령 모두 같다. 실행 장수가 자기 국가 도시에 있어야 하고(보급은 보지 않는다) 관직이 4보다 커야 한다(수뇌 이상). 국가 전략 기한이 0이어야 한다. 비용은 없다. 실행하면 장수 경험·공헌이 각각 5(= 5 × (준비 턴 0 + 1)) 오르고 국가 전략 기한이 9가 된다. 명령별 다음 실행 연월은 실행 연월 + 대기(준비 턴 0)다. 대기 식의 장수 수는 max(국가 장수 수, 10)이다. 난수는 쓰지 않는다.

| 명령 | 인자 | 명령별 제약 (공통 뒤, 전략 기한 앞) | 효과 | 대기 (장수 10명 기준) |
| ---- | ---- | ----------------------------------- | ---- | --------------------- |
| 백성동원 | 도시 | 대상이 자기 국가 도시 | 수비 = max(수비, 수비 최대 × 0.8), 성벽 = max(성벽, 성벽 최대 × 0.8) | round(√(장수 × 4) × 10) = 63 |
| 이호경식 | 국가 | 대상 국가 있음, 대상과 전쟁 중이거나 선포 중 | 양방향 외교를 선포로. 기간은 전쟁이었으면 3, 선포였으면 기존 + 3 | round(√(장수 × 16) × 10) = 126 |
| 급습 | 국가 | 대상 국가 있음, 대상과 선포 중이고 남은 기간 12 이상 | 양방향 선포 기간 − 3, 하한 없음 | 126 |

원작 제약 순서는 백성동원이 자기 도시, 수뇌, 대상 자기 도시, 전략 기한이다. 이호경식·급습은 자기 도시, 수뇌, 대상 국가, 외교 상태, 전략 기한이다. 명령별 다음 실행 연월 검사는 엔진이 제약 뒤에 한다.

기록은 실행 장수의 행동 기록과 열전, 자기 국가 장수 전원과 대상 국가 장수 전원에게 보내는 알림, 자기 국가 기록과 대상 국가 기록(이호경식·급습)이다.

### 기술 계약 초안 (Codex 계획 기술 검토 전)

#### A. 재사용 대기 조각 `strategyCooldown`

```ts
// ext/strategy/cooldown.ts
export type NationCooldown = {
  strategicUntil?: number; // 이 게임 달부터 다시 전략 명령 가능
  commands: { [commandKey: string]: number }; // 명령 key → 이 게임 달부터 다시 그 명령 가능
};
export type StrategyCooldownState = { [nationId: string]: NationCooldown };
export const STRATEGY_COOLDOWN_KEY = 'strategyCooldown';
export const strategyCooldownSlice: ExtSlice<StrategyCooldownState>;
export function strategyMonth(tick: number): number; // Math.floor(tick / TICKS_PER_MONTH)
export function cooldownFailure(value: DeepReadonly<StrategyCooldownState>, nationId: number, key: string, month: number, opts: { strategic: boolean }): Failure | null;
export function setCooldown(value: StrategyCooldownState, nationId: number, key: string, month: number, waitMonths: number, opts: { strategic: boolean }): void;
```

- 조각 타입은 `interface`가 아니라 `type` 별칭으로 쓴다. `ExtSlice<T extends JsonValue>`(`packages/rules/src/commands/ext/state.ts:5`)의 `JsonValue` 객체 꼴은 문자열 인덱스 서명이고 `interface`는 인덱스 서명이 없어 TS2344로 거부된다. 2026-10-24 이 모양을 `interface`로 쓰면 TS2344가, `type` 별칭(선택 칸 포함, `exactOptionalPropertyTypes` 켬)으로 쓰면 통과하는 것을 `packages/rules` tsconfig로 임시 파일을 컴파일해 확인했다(파일은 지웠다).
- 게임 달 번호는 `Math.floor(tick / TICKS_PER_MONTH)`다. 원작 연월 번호(연 × 12 + 월 − 1)와 같은 간격이다.
- 원작 전략 기한은 달이 바뀔 때 1씩 줄고 0이면 허용한다. 이 값을 달 m에 9로 두면 m + 9번째 달에 0이 된다. 그래서 `strategicUntil = m + 9`로 두고 `month < strategicUntil`이면 거부한다. 월간 정산 처리가 필요 없다.
- 명령별 다음 실행 달은 `m + 대기 − 준비 턴`(RH:1754-1759)이다. 준비 턴 없는 세 명령은 `m + 대기`다. `month < commands[key]`이면 거부한다.
- `cooldownFailure` 순서: 전략 기한(`opts.strategic`일 때) → 명령별 다음 실행 달. 문구는 `전략 기한이 남았습니다.`, `{남은 달}달 더 기다려야 합니다.`이고 code는 둘 다 `BAD_STATE`다.
- `create`는 `{}`다. 조각에 국가 항목이 없으면 대기가 없다. `validate`는 key가 양의 정수 문자열, 값이 0 이상 안전 정수인지 보고 [T4-03](./T4-03.md) E7의 저장 가능 검사를 rules 안에서 같은 규칙으로 한다.
- 없어진 국가의 항목은 지우지 않는다. 국가 id는 다시 쓰지 않는다(`support.ts:61-66`).
- 이 조각과 함수는 T4-08이 그대로 쓴다. T4-08의 피장파장은 다른 국가의 `commands` 항목을 고친다.

#### B. `defineStrategy`

`defineCommand`는 국가 명령에 군주 검사를 강제한다(`support.ts:40`). 직책 범위(ST2)를 따로 정해야 하므로 `CommandDef`를 직접 만드는 공통 함수를 둔다.

```ts
// ext/strategy/base.ts
export function defineStrategy<A>(spec: {
  key: string;
  name: string;
  args: z.ZodType<A>;
  minOfficerLevel: number; // ST2. 5 또는 11
  preReqTurn: number; // T4-06은 0
  setsStrategicDelay?: boolean; // 기본 true. T4-08 피장파장만 false
  waitMonths(view: WorldView, nationId: number): number;
  check(view: WorldView, actor: Actor, args: A): Failure | null; // 명령별 제약
  change(state: WorldState, actor: Actor, args: A, rng: Rng): Omit<CommandResult, 'effects'>;
}): CommandDef<A>;
```

- `category`는 `nation`, `target`은 `nation`이다.
- `check` = `precheck` 순서: (1) 장수 없음 `NO_ACTOR` (2) 국가 없음 `NOT_NATION` (3) 현재 도시가 자기 국가 도시 아님 `NOT_OWN_CITY` `자기 국가 도시에서만 가능합니다.`(보급은 보지 않는다) (4) officerLevel < `minOfficerLevel`이면 `NOT_RULER`, 문구는 5면 `수뇌만 실행할 수 있습니다.`, 11이면 `군주나 참모만 실행할 수 있습니다.` (5) 명령별 `check` (6) `cooldownFailure(…, { strategic: true })`. 조각이 없으면 (6)은 대기 없음으로 본다.
- 새 실패 code를 만들지 않으려고 직책 실패에 기존 `NOT_RULER`를 쓴다. 문구가 이유를 밝힌다.
- `execute`: `check`를 다시 보고 실패면 예외(`support.ts:51-52`와 같다). `cloneWorld(view)`에 `change`를 적용하고 실행 장수 경험·공헌을 `5 × (preReqTurn + 1)`씩 더한 뒤 `setCooldown(…, waitMonths, { strategic: setsStrategicDelay })`를 한다. 명령별 다음 실행 달은 `waitMonths − preReqTurn`만큼 뒤다(RH:1754-1759). 결과는 `{ kind: 'world' }` 효과 하나다. 조각이 없으면 대기를 기록하지 않는다. 운영 등록 뒤에는 관계 행 때문에 늘 있다.
- 대기 길이는 실행 전 상태로 계산한다(원작은 `resolve` 전에 대기를 계산한다, RH:1480-1485).
- 국가 장수 수: `max(STRATEGY.MIN_GENERALS, n)`, n은 ST7에 따른 소속 장수 수다.

#### C. 명령별

| key | args | 명령별 `check` (순서대로) | `change` |
| --- | ---- | ------------------------- | -------- |
| `nation_mobilize` | `z.strictObject({ cityKey: positive })` | 도시 없음 `BAD_TARGET` `없는 도시입니다.` · 자기 국가 도시 아님 `BAD_TARGET` `자기 국가 도시에만 쓸 수 있습니다.` | 대상 도시 `defence = max(defence, round(defenceMax × 0.8))`, `wall`도 같은 식 |
| `nation_rivalry` | `z.strictObject({ nationId: positive })` | 국가 없음이거나 자기 국가 `BAD_TARGET` `다른 국가를 골라야 합니다.` · 외교 행이 `WAR`나 `DECLARED`가 아님 `NOT_WAR` `선포 중이거나 전쟁 중인 국가에만 쓸 수 있습니다.` | 외교 행을 `DECLARED`로. `untilTick`은 `WAR`였으면 지금 tick + ST3 기간, `DECLARED`였으면 기존 + ST3 기간 |
| `nation_raid` | 같음 | 국가 없음이거나 자기 국가 `BAD_TARGET` · ST4에 따른 선포 조건 아님 `NOT_WAR` `선포 기간이 충분한 국가에만 쓸 수 있습니다.` | ST4에 따라 `untilTick`을 줄인다 |

- 우리 외교 행은 국가 쌍마다 하나다(`bootstrap.ts:77-82`). 원작의 양방향 두 행을 한 행으로 옮긴다. 원작은 두 방향의 기간을 따로 계산하지만 우리는 한 값이다.
- 반올림: 백성동원은 원작이 반올림하지 않는다. 우리 효과 적용은 정수로 반올림하므로(`effects.ts:37`) 같은 결과를 계산 안에서 `Math.round`로 둔다.
- 숫자 상수는 `STRATEGY`에 둔다: `MIN_OFFICER_LEVEL`, `DIPLOMACY_OFFICER_LEVEL`, `MIN_GENERALS: 10`, `STRATEGIC_DELAY_MONTHS: 9`, `MOBILIZE_RATIO: 0.8`, `WAIT_FACTOR: { nation_mobilize: 4, nation_rivalry: 16, nation_raid: 16 }`, ST3·ST4 값. 공유 `BALANCE`에 넣지 않는다.
