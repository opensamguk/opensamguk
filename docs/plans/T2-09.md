# T2-09 메시지·공지·SSE

> 대기열: T2-09 · AC: AC-M2-04, AC-M2-07 · 구현: Codex · 리뷰: Claude
> 선행: M1 전체 · 관련: [실시간 갱신](../architecture/realtime.md), FR-MSG-01~04, FR-RT-01, FR-ADM-05

## 계획 (Claude)

### 목표

- 개인·국가·외교 메시지를 주고받고 읽음이 표시된다. 공개 범위 밖 메시지 조회는 거부된다 (AC-M2-04).
- 내 턴 결과와 새 메시지가 새로고침 없이 2초 안에 화면에 보인다 (AC-M2-07).

### 범위

- `Message`, `MessageRead`, `Notice`(로비·월드), `Nation.notice`+`noticeUpdatedAt`
- `apps/server/src/routers/message.ts`, `notice.ts`, `apps/server/src/realtime/` (SSE)
- engine·server의 커밋 뒤 `NOTIFY`

### 하지 않는 것

첨부 이미지, 게시판(글 목록·댓글), 기밀실 열람 기록(v1 아이디어, Phase 2), 웹 푸시(M3).

### 메시지 범위 결정

| scope | 보내는 사람 | 받는 사람 | 읽을 수 있는 사람 |
| ----- | ----------- | --------- | ----------------- |
| PRIVATE | 아무 장수 | 장수 1명 | 보낸 사람, 받은 사람 |
| NATION | 국가 소속 장수 | 그 국가 | 그 국가의 현재 소속 장수 |
| DIPLOMACY | 군주·참모 | 상대 국가 | 양국의 군주·참모 |
| WORLD | 운영자 | 월드 전체 | 모두 |

- 국가를 떠나면 그 국가 메시지를 더 읽을 수 없다 (현재 소속 기준).
- 본문 1,000자, 장수당 분당 10개 제한 (도배 방지).
- **국가 공지**(myosam 지령): 군주·참모가 쓴다. 바뀌면 소속 장수가 다음 접속 때 한 번 팝업으로 본다(`noticeSeenRevision`).

### 실시간 결정 (A11, Redis 없이)

```text
트랜잭션 commit 뒤 → NOTIFY world_<id>, {kind, target}   (target: generalId | nationId | 'world')
server LISTEN → 연결된 SSE 중 target에 해당하는 사용자에게 {kind, scope?}
web → 해당 query만 다시 조회 (알림 내용에 비밀 정보를 싣지 않는다)
```

- 종류: `turn.result`(내 턴 실행), `message.new`, `monthly.done`, `offer.new`, `treaty.new`, `notice.updated`.
- SSE 주소 `GET /sse?worldId=` (세션 쿠키로 인증). 30초마다 하트비트. 끊기면 브라우저가 다시 잇고 이어진 뒤 화면 전체를 한 번 다시 조회한다.
- NOTIFY 실패는 로그만 남기고 게임 진행에 영향을 주지 않는다.

### API 계약

```ts
message.list({ worldId, scope, cursor? }) → { items: [{ id, from, to, body, createdAt, read }], next }
message.send({ worldId, scope, to, body })
message.markRead({ worldId, ids })
message.unread({ worldId }) → { PRIVATE, NATION, DIPLOMACY, WORLD }
notice.nation.get/set({ worldId, body })
notice.nation.markSeen({ worldId, revision })            // 팝업에 띄운 그 revision까지만 읽음 (아래)
notice.world.list({ worldId })                           // 운영자 작성은 명령줄 (M3에 화면)
message.recipients({ worldId })                          // 쓰기 칸의 받는 사람·받는 국가 목록
```

로비 공지 읽기는 T2-03의 `lobby.notices`가 맡는다. T2-09는 로비 공지의 저장 모델과 운영자 명령줄 작성만 만들고 `notice.lobby.list`는 따로 두지 않는다.

### 화면(T2-10)이 기대하는 응답 모양

```ts
type MessageScope = 'PRIVATE' | 'NATION' | 'DIPLOMACY' | 'WORLD';
type GameDate = { year: number; month: number };
type NationTag = { id: number; name: string; color: string }; // NationBadge에 그대로 넘긴다
type Party = {
  generalId: number | null; // 국가 전체·운영자면 null
  name: string;             // 장수 이름. 국가 전체면 국가 이름, 운영자면 '운영자'
  nation: NationTag | null; // 재야·운영자면 null
};

type MessageItem = {
  id: string;
  scope: MessageScope;
  direction: 'sent' | 'received'; // WORLD는 운영자가 아니면 항상 'received'
  from: Party;
  to: Party | null;               // PRIVATE는 장수, NATION·DIPLOMACY는 국가(generalId null), WORLD는 null
  body: string;                   // 평문. HTML로 저장하거나 돌려주지 않는다
  sentAt: string;                 // ISO 시각
  gameDate: GameDate;             // 보낸 때의 게임 연월
  read: boolean;                  // 내가 보낸 것은 항상 true
};

// message.list: 최신순(sentAt 내림차순, 같으면 id 내림차순), 한 쪽 20개. 더 없으면 next = null
type MessageListResponse = { items: MessageItem[]; next: string | null };

// message.unread: 볼 권한이 없는 범위는 0이 아니라 null이다. 화면은 null인 탭을 숨긴다
// (재야는 NATION·DIPLOMACY가 null, 군주·참모가 아니면 DIPLOMACY가 null)
type UnreadResponse = Record<MessageScope, number | null>;

// message.send: 성공하면 보낸 행을 돌려준다. 화면은 이 행을 목록 맨 위에 넣고 다시 조회하지 않는다
type SendResponse = { item: MessageItem };
// 실패는 TRPCError이고, message는 입력칸 아래에 그대로 보여 줄 문장이다
//   TOO_MANY_REQUESTS 분당 10개 초과 ("N초 뒤에 다시 보낼 수 있습니다.")
//   BAD_REQUEST       빈 본문, 1,000자 초과, 받는 사람 없음
//   FORBIDDEN         범위 권한 없음 (군주·참모가 아닌 장수가 외교 메시지를 보냄 등)

// message.recipients: 공개 정보만 담는다
type RecipientsResponse = {
  generals: { id: number; name: string; nation: NationTag | null }[]; // 나 자신 제외, 이름순
  nations: NationTag[];                                               // 내 국가 제외, 이름순
};

// notice.nation.get: 재야면 null
type NationNoticeResponse = {
  revision: number;         // 국가 공지를 저장할 때마다 1씩 오른다. 한 번도 쓰지 않았으면 0
  body: string;             // 비어 있으면 ''
  updatedAt: string | null; // 한 번도 쓰지 않았으면 null. 표시용이고 읽음 판정에 쓰지 않는다
  updatedBy: string | null; // 쓴 장수 이름
  unseen: boolean;          // body가 비어 있지 않고 이 revision을 아직 읽음 처리하지 않았다. 화면은 true일 때만 팝업
  canEdit: boolean;         // 군주·참모만 true
} | null;
// notice.nation.set: 본문 1,000자, 군주·참모가 아니면 FORBIDDEN. 성공하면 같은 모양을 돌려준다
// notice.nation.markSeen: 성공하면 다시 읽은 NationNoticeResponse를 돌려준다. 그사이 새 공지가 오면 unseen이 true로 남는다

// notice.world.list: 고정 먼저, 그다음 최신순, 최대 20개
type WorldNoticeResponse = { items: { id: string; body: string; pinned: boolean; publishedAt: string }[] };
```

국가 공지 읽음은 시각이 아니라 revision으로 정한다 (검토 R63-3, 2026-10-21 추가). 공지 A(revision 3)를 보는 중에 B(revision 4)가 저장되면
A를 닫을 때 B까지 읽음이 되면 안 된다.

- 저장: `General.noticeSeen = { nationId, revision }`. 국가 공지 행은 `revision`을 가지고 `notice.nation.set`이 같은 트랜잭션에서 1 올린다.
- `markSeen({ revision })`은 화면이 팝업에 띄운 응답의 `revision`을 그대로 보낸다. 서버는 내 국가의 현재 공지 revision을 넘는 값이면 `BAD_REQUEST`,
  저장된 값 이하이면 아무것도 하지 않는다. 그 밖에는 `{ nationId: 내 국가, revision }`으로 올린다. 최신 revision으로 올려 주지 않는다.
- `unseen`은 `body !== '' && (noticeSeen.nationId !== 내 국가 || noticeSeen.revision < revision)`이다. 다른 국가로 옮기면 새 국가 공지를 한 번 본다.
- 같은 사람이 탭 두 개에서 다른 revision을 닫아도 큰 값만 남는다(작은 값은 무시). 행위 장수는 세션에서 정한다.

월드 공지 순서는 v1 공지 피드(`app/gateway-api/src/main/kotlin/opensamguk/gateway/service/NoticeService.kt:21`, 고정 우선·최신순·20건)를 따른다.

#### SSE 이벤트

`GET /sse?worldId=` 응답은 `text/event-stream`이다. 이벤트 이름이 `kind`이고 `data`는 아래 JSON이다. 본문·보낸 사람·수치는 싣지 않는다.

```ts
type WorldEvent =
  | { kind: 'ready' } // 연결(재연결 포함) 직후 한 번. 화면은 이때 전체를 다시 조회한다
  | { kind: 'turn.result' }
  | { kind: 'message.new'; scope: MessageScope }
  | { kind: 'monthly.done' }
  | { kind: 'offer.new' }
  | { kind: 'treaty.new' }
  | { kind: 'notice.updated'; scope: 'nation' | 'world' };
// 하트비트는 30초마다 주석 줄(": hb")로 보내므로 화면에는 이벤트로 오지 않는다
```

| kind | 받는 연결 |
| ---- | --------- |
| `turn.result` | 그 장수의 주인 한 명 |
| `message.new` PRIVATE | 받는 장수의 주인 (보낸 쪽은 `message.send` 응답으로 갱신) |
| `message.new` NATION | 그 국가의 현재 소속 장수 주인들 |
| `message.new` DIPLOMACY | 양국의 군주·참모 |
| `message.new` WORLD, `monthly.done`, `notice.updated` world | 그 월드의 모든 연결 |
| `offer.new` | 제안을 받는 쪽 (발령은 그 장수, 조약 제안은 상대국 군주·참모) |
| `treaty.new` | 양국의 소속 장수 |
| `notice.updated` nation | 그 국가의 소속 장수 |

`revision`은 싣지 않는다. 화면은 알림마다 해당 query를 무효화하고 끊겼다 이어지면 `ready`를 받은 뒤 전체를 다시 읽는다. 놓친 알림은 다시 보내지 않는다. v1도 같은 방식이었다. 첫 줄 `:connected`(`app/game-api/src/main/kotlin/opensamguk/gameapi/sse/RealtimeRelayController.kt:78`), 30초 하트비트(같은 파일 `:74`), 재연결 뒤 다시 읽기(`web/game/hooks/useSSE.ts:29-32`)가 근거다.

#### 화면 요소와 대조

| T2-10 화면 요소 | 쓰는 응답 |
| --------------- | --------- |
| 범위 탭, 탭별 안 읽음 수, 외교 탭 숨김 | `UnreadResponse` (null이면 탭 없음) |
| 위쪽 띠 안 읽음 배지 | `UnreadResponse`의 null이 아닌 값의 합 |
| 목록 행 (보냄·받음, 상대, 국가 이름표, 시각, 본문) | `MessageItem` |
| 이전 메시지 더 보기 | `next` |
| 받는 사람·받는 국가 고르기 | `RecipientsResponse` |
| 보내기 실패 이유 | `TRPCError.message` |
| 국가 공지 팝업, 공지 고치기 | `NationNoticeResponse`의 `unseen`, `canEdit` |
| 전체 탭 위 월드 공지 | `WorldNoticeResponse` |
| 연결 상태, 재연결 뒤 전체 재조회 | `ready`, EventSource 오류 |

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 범위 | API 권한 표: 4 범위 × (본인·같은 국가·다른 국가·전 소속·무인증) |
| 읽음 | API: 보내기 → 받는 쪽 안 읽음 1 → 읽음 처리 → 0 |
| 제한 | API: 분당 11번째 거부 |
| 실시간 | 통합: 엔진이 턴 실행 → 2초 안에 SSE `turn.result` 수신 (해당 사용자만) |
| 누설 없음 | 통합: 다른 국가 사용자는 그 국가 `message.new`를 받지 않음 |
| 재연결 | 통합: 연결을 끊었다 다시 이음 → `ready` 수신, 하트비트 재개 |
| 응답 모양 | API: 재야·일반 장수·군주로 `message.unread`를 불러 null 위치가 위 규칙과 같음, `notice.nation.get`의 `unseen`이 `markSeen` 뒤 false |
| 공지 읽음 경합 | API: revision 3을 받은 뒤 군주가 공지를 고쳐 revision 4 → `markSeen({ revision: 3 })` → `unseen` true, `markSeen({ revision: 4 })` 뒤 false. 현재보다 큰 revision은 `BAD_REQUEST`, 더 작은 값을 늦게 보내도 읽음이 되돌아가지 않음 |
