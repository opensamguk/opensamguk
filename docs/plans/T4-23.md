## 0. 이 문서의 위치

명세 §6 T4-23 행을 적는다. 장비매매는 예턴 명령이라 저장·사전 검사·실행·표시는 T4-03의 `turns` 경로를 그대로 탄다. 이 작업은 운영 등록, 장비 조회 API 둘, 실제 DB·HTTP·엔진 시험을 더한다. 즉시 행동이 없으므로 T4-49에 기대지 않는다.

착수 조건은 이 문서의 G-03 수용, T4-22의 사용자 결정과 구현 병합, T4-03 병합, AC-P2-12 (나)의 정식 반영이다.

## 계획 (Claude)

### 목표

- 장비매매를 켠 월드에서 장수가 `equipment_trade`를 예턴에 저장하고 사전 검사를 거쳐 엔진 턴에서 실행된다. 장착 상태는 턴과 같은 트랜잭션에 저장되고 재시작 뒤 복원되며 12개월 재생 해시가 같다.

## 2. 계약

### 2.1 저장

장착 상태는 T4-22의 `equipment` 조각 하나이며 T4-03의 `WorldExtSlice` 행(key `equipment`)에 저장한다. 턴 저장의 바뀐 조각만 쓰기(T4-03 E6) 덕분에 장비매매가 실행된 턴에만 이 행이 다시 쓰인다. 그래서 schema와 migration을 고치지 않는다. 명세 C8의 S4 자리는 쓰지 않는다(쟁점 T23-Q3).

### 2.2 운영 등록

- `extensionCommands`에 `equipment_trade`, `extSlices`에 `equipmentSlice`, `extCommandBindings`에 `{ commandKey: 'equipment_trade', target: 'general', sliceKeys: ['equipment'] }`.
- 등록 뒤 T4-02 확장 대조 시험이 `equipment_trade.test.ts`(T4-22)를 확인한다. 대응표 `equipment_trade` 행의 단계 증거는 이 작업의 시험 이름과 정확 SHA로 채운다.
- 효과 제공자 등록(`modifiers/providers.ts`)은 T4-22가 이미 했다. 이 작업은 등록 뒤 엔진 실행에서 효과가 들어가는지 시험한다.

### 2.3 API (`equipment` 라우터)

```ts
type EquipSlot = 'horse' | 'weapon' | 'book' | 'item';
type EquipmentEffectView = { stage: string; op: 'add' | 'mul'; value: number; commandKeys: string[] | null; stat: string | null };
type CatalogItem = {
  key: string; name: string; slot: EquipSlot;
  cost: number; requiredSecurity: number; buyable: boolean; charges: number | null;
  effects: EquipmentEffectView[]; // 화면이 고정 문구로 풀어 쓴다
};
type Allowed = { ok: true } | { ok: false; code: string; reason: string };
type MyEquipment = {
  generalId: number;
  cityKey: number;
  citySecurity: number | null; // 자기 국가 도시가 아니면 null
  gold: number;
  slots: Record<EquipSlot, { key: string; name: string; charges: number | null } | null>;
  canBuy: Record<string, Allowed>; // 매매 가능 장비 key마다. 지금 상태의 사전 검사 결과
  canSell: Record<EquipSlot, Allowed>;
};

// equipment.catalog({ worldId }) → { items: CatalogItem[] }   query
// equipment.mine({ worldId }) → MyEquipment | null           query (장수 없음이면 null)
```

| 단계 | 하는 일 |
| ---- | ------- |
| 입력 | `z.strictObject({ worldId })`. 장수 번호를 받지 않는다. 남는 칸은 `BAD_REQUEST` |
| 인증·월드 | `protectedProcedure`, 월드 없음 `NOT_FOUND` |
| 켜짐 | `requireRuleFeature(world, 'ext')` 뒤 그 월드 resolver에 `equipment_trade`가 없으면 같은 `PRECONDITION_FAILED` `이 월드에서 켜지 않은 기능입니다.` (T4-20 T20-Q2와 같은 규칙) |
| 목록 | 카탈로그 순서 그대로. 비매품도 이름·효과는 보인다(얻는 경로가 생기면 화면이 설명한다) |
| 내 장비 | 세션 장수의 조각 값. `canBuy`·`canSell`은 T4-03의 `resolver.precheck(view, actor, 'equipment_trade', args)`를 장비마다 부른 결과다. 화면 안내용이며 최종 판정은 엔진 실행이다 |
| 스냅샷 | 두 조회 모두 RepeatableRead 트랜잭션 하나에서 읽는다(지금 `general.mine`과 같다, `general.ts:97-119`) |

사전 검사를 장비마다 돌리는 비용은 매매 가능 장비 수(원고 18, 많아야 24)만큼의 순수 함수 호출이며 DB 왕복은 한 번이다.

### 2.4 엔진

엔진 코드는 고치지 않는다. T4-03의 턴 실행이 resolver로 `equipment_trade`를 돌리고 `ext`를 같은 트랜잭션에 쓴다. 효과는 T4-22 제공자가 `collectModifiers`를 지나 들어간다. 이 작업은 그것을 실제 PostgreSQL에서 확인한다.

## 3. 시험과 증거

### 3.0 rules 단위 (운영 등록 뒤)

T4-22는 운영 등록 전이라 `cloneWorld`를 지나는 경로를 시험하지 못했다(T4-22 2.3 끝, 4절). 이 작업이 등록과 같은 PR에서 더한다.

| ID | 내용 |
| -- | ---- |
| R1 | `equipment_trade.test.ts`에 `equipment_trade.execute`, resolver `run`, `runGeneralTurn`의 성공 1건·대표 실패 1건 |
| R2 | 장비 없는 장수만 있는 켠 월드에서 출병 골든 14건. 출병 결과의 `effects[0].state`와 적용 상태 모두에 [T4-22 §4.0 CMP](./T4-22.md#40-켠끈-월드-비교-규칙-cmp)의 CMP-B 정규화를 하고 `attack.test.ts`의 결과 SHA·난수 소비와 같다. 지운 `ext`는 실행 전 값과 같다 |
| R4 | 등록 뒤 투자 8종 × T4-18 V1 사례를 장비 없는 켠 상태(P0 + `ext.equipment: { generals: {} }`)에서 `execute`와 `applyEffects`로 돌린다. 기대: `{ result, applied }`를 [T4-22 §4.0 CMP](./T4-22.md#40-켠끈-월드-비교-규칙-cmp)의 CMP-B로 정규화한 SHA가 T4-18 V1 골든과 같다. 지운 `ext`는 실행 전과 같다 |
| R3 | 결정된 전투 효과 장비를 단 장수의 출병 명령 전체 경로 결과가 T4-22 S5의 `simulateBattle` 기대값과 같다 |

### 3.1 PostgreSQL 통합 (`apps/engine/src/equipment.integration.test.ts`)

준비는 T4-03 켠 월드 생성으로 `equipment_trade`를 켠 월드를 만든다. 장수 1은 치안이 충분한 자기 국가 도시에 있다.

| ID | 시험 | 기대 |
| -- | ---- | ---- |
| P1 | 장비매매 구매를 예턴 0칸에 넣고 엔진 턴 실행 | 장수 금 감소, `WorldExtSlice('equipment')` 값, `GeneralLog` 성공 한 줄 |
| P2 | 이어서 효과가 있는 명령(EQ-2 결정에 맞는 내정 또는 출병) 실행 | 결과가 같은 상태를 순수 함수로 돌린 값과 같다. 장비 없는 대조 실행과 다르다 |
| P3 | 금 부족 구매 | 실패 로그 `NO_GOLD`, 조각 행 그대로 |
| P4 | commit 직전 실패 | 조각 행·금·예턴 그대로 |
| P5 | SIGKILL 뒤 재시작 | 복원 상태 해시가 끊지 않은 실행과 같다 |
| P6 | 12개월 결정적 입력 시나리오(구매·판매·효과 명령) | 엔진 저장 해시와 순수 재생 해시가 달마다 같다 |
| P7 | 같은 시나리오를 장비매매를 켜지 않은 월드에서(장비매매 없이) | [T4-22 §4.0 CMP](./T4-22.md#40-켠끈-월드-비교-규칙-cmp)의 CMP-C. `replayFormat: 1` 월드는 이 작업 착수 직전 main의 고정 파일과 CMP-D로도 같다 |
| P8 | 장비 없는 장수만 있는 켠 월드(`ruleFeatures: ['ext']`)의 12개월 | 같은 시나리오를 규칙 기능 없이 만든 형식 3 월드와 달마다 엔진 상태 해시가 [T4-22 §4.0 CMP](./T4-22.md#40-켠끈-월드-비교-규칙-cmp)의 CMP-B로 같다. 지운 값은 켠 쪽 `ext: { equipment: { generals: {} } }`·`ruleFeatures: ['ext']`, 끈 쪽 없음 |
