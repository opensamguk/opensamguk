## 0. 이 문서의 위치

명세는 선양·해산(T4-15)과 모반(T4-52)을 나눴다(§6.1 끝). 모반은 군주가 오래 활동하지 않을 때 수뇌가 군주 자리를 가져가는 명령이다. 원작은 장수의 미활동 턴 수로 판정한다. 우리에게는 그 값이 없고 T2-13이 계획한 `lastActiveTick`이 가장 가까운 자료다. 그래서 이 계획은 판정 자료를 T2-13에 묶고 기준 값은 U-05로 남긴다.

#### R3 미활동 판정

```ts
// packages/rules/src/commands/ext/rebellion/threshold.ts
export function rulerInactive(view: WorldView, ruler: GeneralState, tick: number): boolean;
```

- 자료는 T2-13의 `lastActiveTick`이다. T2-13이 정한 대로 기록된 tick만 쓰고 현실 시각을 읽지 않는다. 그래서 엔진과 재생이 같은 답을 낸다.
- 기준 값과 단위는 U-05다. 후보 둘을 함수 하나로 받는다.
  - 후보 (가) T2-13 방식: `isInactive(lastActiveTick, tick, turnTermMinutes)`에 모반용 기준 일수를 넘긴다. 기준 일수는 월드가 돌아간 날 수다.
  - 후보 (나) 원작 방식: 군주의 마지막 활동 뒤 군주 턴이 실제로 N번 이상 실행됐다. 원작 값은 N = 1이다(1절 killturn의 뜻). 경과 tick을 턴 간격으로 나눈 값은 쓰지 않는다. 장수마다 턴 오프셋이 달라서(`world/bootstrap.ts:245`, `general/create.ts:97-99`) 마지막 활동이 tick 9,000이고 군주 턴이 10,000에 한 번 실행돼도 경과가 한 달에 못 미치기 때문이다.
  - 실행 횟수는 tick이 아니라 처리 순서로 센다. 예정 tick을 `lastActiveTick`과 비교하면 틀린다. T2-26 C2는 같은 달 안에서 활동 입력을 밀린 턴보다 먼저 처리하므로(T2-26 head `d7c571a` 처리 순서 절) 활동을 tick 9,000에 처리한 뒤 예정 tick 8,000인 밀린 군주 턴이 실행될 수 있다. 이때 활동 뒤 실제 실행은 1회지만 예정 tick 비교는 0회로 센다.
  - 그래서 활동을 기록할 때 그 장수의 그때 `nextTurnTick`을 함께 남긴다(`lastActiveTurnMark`). 장수 턴은 실행될 때마다(성공·실패 모두) `nextTurnTick`이 정확히 `TICKS_PER_MONTH`만큼 오르므로(`apps/engine/src/turnLoop.ts:186`, 순수 재생 `packages/rules/src/replay.ts:74`) 활동 뒤 실행 횟수는 `(nextTurnTick − lastActiveTurnMark) / TICKS_PER_MONTH`다. 활동 입력과 턴 실행이 같은 월드 행 잠금 아래 sequence 순서로 처리되므로 같은 달 지연과 같은 tick 경합에서도 처리 순서가 그대로 남는다. 즉시 입력인 예턴 저장(`turns.set`)은 API 트랜잭션에서 읽은 장수 행의 값을, 대기 입력(로그인 활동, 방침 변경)은 엔진이 처리할 때의 값을 쓴다. 재생은 같은 sequence 위치의 재생 상태 값을 쓰므로 같은 수가 나온다.
  - 이 값은 T2-13 활동 기록의 칸 하나다(상대 영역 T2-13). 나눗셈이 정수가 아니거나 음수면 활동 기록과 턴 실행 사이에 다른 경로가 `nextTurnTick`을 바꾼 것이므로 판정하지 않고 거부한다. 미등장 장수의 월간 조정(`monthly/index.ts:145-151`)이 그런 경로이며 군주는 등장한 장수라 닿지 않는다. 다른 경로가 생기면 쟁점 X5대로 실행 횟수 칸을 따로 둔다.
  - 시험: 단위 시험은 활동 9,000·실행 10,000(1회), 활동 9,000 처리 뒤 예정 8,000 밀린 턴 실행(1회), 같은 tick에서 활동이 턴보다 먼저 처리된 경우(1회)와 나중에 처리된 경우(0회), 오프셋이 다른 장수 여럿을 넣는다. 엔진 통합 시험은 계산 값이 마지막 활동 입력 처리 뒤 `TurnLoop.advanceTo`가 돌려준 실행 목록의 그 군주 항목 수와 같은지 본다(R-E1).
- 기준 값은 U-05 답 뒤 프리셋 규칙(`presetRules`)에 둘지 상수로 둘지 정한다. 프리셋에 두면 T2-02 프리셋 형식에 칸이 생기므로 T2-02 담당과 맞춘다(쟁점 X3).
- `lastActiveTick`이 상태에 없는 월드(T2-13 기능을 켜지 않은 월드)에서는 판정할 자료가 없다. 이때 모반은 늘 거부한다(쟁점 X1).

#### R4 실행 효과

1. 실행 장수의 관직을 12로 한다.
2. 옛 군주의 관직을 1로 한다. 원작은 경험도 `Math.round(experience × 0.7)`로 줄인다(70%만 남기는 30% 감소). 이 벌은 U-19 확인 대상이라 승인 전에는 구현하지 않고 경험을 바꾸지 않는 시험도 두지 않는다. 승인되면 1단계에서 넣는다.
3. 직책 칸: 인사 기능을 켠 월드는 T2-05의 `syncOffices(before, after, offices)`를 부른다. 군주 칸과 실행 장수의 옛 직책 칸이 비워지고 revision·tenure가 오른다. 인사 기능이 없는 월드의 국가 30칸을 어떻게 할지는 U-05b다. 답 전에는 기본 동작을 정하지 않는다. 그 갈래는 정책을 인자로 받는 내부 변형(`*WithPolicy`)과 그 단위 시험까지만 두고 운영 정의에는 넣지 않는다. 그래서 U-05b 답 전에는 인사 기능 없는 월드의 모반이 운영에 등록되지 않는다(단계 표 2단계 조건).
4. 전체·국가·장수 기록: 국가 역사 한 줄, 실행 장수 성공 로그, 옛 군주 로그. 문구는 구현 PR이 글쓰기 규칙으로 쓴다. 원작 표식(`【모반】`)은 옮기지 않는다.
5. 난수를 쓰지 않는다. 같은 상태면 같은 결과다.
