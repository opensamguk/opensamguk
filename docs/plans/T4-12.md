## 계획 (Claude)

### 목표

AC-P2-07의 저장·조회·권한 몫이다. 명세 문장은 이렇다. 첩보하면 대상 도시의 그 시점 정보가 자기 국가에만 보이는 기록으로 남고 기록 시각이 함께 보인다. 다른 국가와 무인증의 조회는 거부된다.

이 작업이 끝나면 아래가 실제 PostgreSQL과 HTTP로 성립한다.

- 엔진이 실행한 `spy`의 기록이 턴과 같은 트랜잭션에 저장되고 재시작 뒤에도 남는다(저장 경로는 T4-03 E6).

- 다른 국가 장수, 재야, 무인증, 제재 계정은 그 기록을 받지 못한다.
- 승인된 정책은 `intelPolicy.ts` 한 곳에 있고 T4-38의 `city.get`이 같은 객체를 import한다.

## 1. 열람 조건 (정본)

첩보 기록이 누구에게 무엇을 여는지를 여기 한 곳에서 정한다. T4-11은 IC-1·IC-3·IC-4·IC-8의 상태 몫을, 이 작업은 IC-2·IC-5·IC-6·IC-7·IC-10과 정책 모듈을, T4-38은 IC-9의 안개 몫을 만든다. IC-6·IC-7·IC-9의 값은 2026-10-24 사용자 승인(착수 조건 6)이고 어느 작업도 그 값을 바꾸지 않는다. 세 작업은 이 표를 고치지 않고 따른다. 고칠 일이 생기면 이 표를 먼저 고치고 셋을 함께 다시 검토한다.

## 2. API 계약

### 2.1 입력

```ts
intel.records: protectedProcedure.input(worldInput).query(...)
// worldInput = z.object({ worldId: z.uuid() }).strict() (queries.ts:6)
```

`nationId`, `generalId`, `cityKey`, `cursor` 같은 칸은 받지 않는다. strict라서 남는 칸은 `BAD_REQUEST`다.

### 2.2 출력

```ts
type IntelRecordsOutput = {
  enabled: boolean; // 이 월드에서 spy가 켜졌는가 (worldResolver(world).get('spy') !== undefined)
  items: IntelRecordView[]; // tick 내림차순, 같은 tick이면 cityKey 오름차순
};
type IntelRecordView = {
  cityKey: number;
  tick: number;
  year: number;
  month: number;
  ageMonths: number; // IC-5
  level: 1 | 2 | 3;
  owner: { id: number; name: string; color: string } | null; // 기록 당시 소유국, null은 공백지
  population: number;
  populationMax: number;
  trust: number;
  generals: number;
  crew: { min: number; max: number | null }; // IC-7
  domestic?: {
    agriculture: number;
    agricultureMax: number;
    commerce: number;
    commerceMax: number;
    security: number;
    securityMax: number;
    defence: number;
    defenceMax: number;
    wall: number;
    wallMax: number;
  }; // level <= 2
  crewTypes?: { crewType: number; name: string; generals: number }[]; // level 1
  tech?: 'overwhelming' | 'ahead' | 'even' | 'behind' | 'far_behind'; // level 1이고 owner가 있을 때
};
```

- 선택 칸은 기록에 없으면 키 자체가 없다(IC-4).
- 병종 이름은 `unitSetSchema.parse(world.unitSet)`에서 찾는다. 없는 병종 번호는 번호 문자열을 이름으로 쓴다(원작 `che_첩보.ts:131`과 같은 대체).
- 도시 이름은 넣지 않는다. 화면은 이미 받는 `world.map`의 공개 도시 이름을 쓴다.
- `tick`은 화면의 정렬과 시험을 위해 그대로 낸다. 비공개 값이 아니다.

### 2.3 처리 순서

`readWorld`(RepeatableRead) 한 트랜잭션 안에서 아래 순서로 한다.

1. 월드가 없으면 `NOT_FOUND`(`readWorld`).
2. `requireGeneral`로 세션 장수. 없으면 `NOT_FOUND`(IC-2).
3. 월드 행의 `preset`·`unitSet`을 읽어 `worldResolver`로 `enabled`를 정한다. 꺼졌으면 `{ enabled: false, items: [] }`(IC-10).
4. 장수가 재야면 `{ enabled: true, items: [] }`(IC-2).
5. `WorldExtSlice`의 `(worldId, 'intel')` 한 행을 읽는다. 켰는데 행이 없거나 `intelSlice.validate`를 지나지 못하면 `INTERNAL_SERVER_ERROR`다. 일부만 내지 않는다. 오류 문구는 `trpc.ts:10`대로 고정되고 값은 로그에 넣지 않는다.
6. `value[String(장수 국가)]`만 꺼낸다. 다른 국가 키는 읽지 않는다.
7. 기록마다 `intelRecordInfo(cityKey, record, { startYear, nowTick, unitSet }, INTEL_POLICY)`로 투영한다. `null`이면(기간 밖) 뺀다. 승인 정책에서는 늘 남는다. 남은 것을 정렬한다.

다른 조각은 읽지 않는다. 그래서 `restoreExtState`(T4-03 E5)의 전체 key 집합 검사는 하지 않고 `intel` 조각 하나만 검증한다. 전체 집합 검사는 엔진 적재가 맡는다.

### 2.4 `intelRecordInfo` (visibility.ts)

```ts
import type { IntelDisclosurePolicy } from './intelPolicy';
export function intelRecordInfo(
  cityKey: number,
  record: IntelRecord,
  context: { startYear: number; nowTick: number; unitSet: UnitSetResource },
  policy: IntelDisclosurePolicy,
): IntelRecordView | null; // policy.withinAge가 거짓이면 null
```

- 기록 칸을 허용 목록으로 하나씩 옮긴다. 펼치기(`...record`)로 넘기지 않는다.
- 병력은 `policy.crew(record.crew)` 결과만 낸다. 기록 값을 다른 칸으로 내지 않는다.
- `policy.withinAge(ageMonths)`가 거짓이면 `null`이다.
- `policy`는 선택 인자가 아니고 기본값도 없다. `visibility.ts`는 `intelPolicy.ts`의 타입만 import하고 `INTEL_POLICY` 값을 import하지 않는다. 운영 호출자 두 곳(`routers/intel.ts`, T4-38의 `routers/city.ts`)이 같은 `INTEL_POLICY`를 import해 넘긴다.

### 2.5 공개 정책 모듈 `intelPolicy.ts`

```ts
export interface IntelDisclosurePolicy {
  crew(crew: number): { min: number; max: number | null }; // IC-7
  withinAge(ageMonths: number): boolean; // IC-6
}
// 2026-10-24 사용자 승인 U-11. 각 구간의 하한이고 마지막 구간은 위가 열린다.
export const INTEL_CREW_BAND_FLOORS = [0, 1, 1_000, 5_000, 10_000, 20_000, 50_000] as const;
export function crewBand(crew: number): { min: number; max: number | null };
export const INTEL_POLICY: IntelDisclosurePolicy = Object.freeze({
  crew: crewBand,
  withinAge: () => true, // 승인: 기간 제한 없음
});
```

- `crewBand`: 하한표에서 `crew` 이하인 가장 큰 하한이 `min`, 다음 하한 − 1이 `max`, 마지막 구간이면 `max: null`. 0은 `{ min: 0, max: 0 }`. 음수나 정수가 아닌 값은 예외다(기록 검증을 지난 값이라 정상 경로에서는 없다).
- 파일 이름과 소유는 기술 판단이다. 안개(`fog.ts`, T4-38)보다 넓은 첩보 기록 공개 규칙이고 T4-12가 T4-38보다 먼저 병합되므로 T4-12가 만들고 소유한다. T4-38은 import만 하고 이 파일을 고치지 않으며 구간·기간 상수를 따로 두지 않는다. 정책을 바꾸는 일은 새 사용자 결정과 함께 이 파일 한 곳에서 한다.
- 게임 상태를 바꾸지 않고 재생 해시에 들어가지 않는 표시 규칙이라 `packages/rules`가 아니라 서버에 둔다(`visibility.ts` 옆).
- 순환이 없다. `intelPolicy.ts`는 다른 서버 모듈을 import하지 않는다. `visibility.ts`는 타입만, 두 라우터는 값을 import한다. T4-38은 T4-12 뒤라 선행 순환도 없다.
