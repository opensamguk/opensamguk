## 계획 (Claude)

### 목표

AC-P2-07의 저장·조회·권한 몫이다. 명세 문장은 이렇다. 첩보하면 대상 도시의 그 시점 정보가 자기 국가에만 보이는 기록으로 남고 기록 시각이 함께 보인다. 다른 국가와 무인증의 조회는 거부된다.

이 작업이 끝나면 아래가 실제 PostgreSQL과 HTTP로 성립한다.

- 엔진이 실행한 `spy`의 기록이 턴과 같은 트랜잭션에 저장되고 재시작 뒤에도 남는다(저장 경로는 T4-03 E6).
- 로그인한 장수는 `intel.records`로 자기 국가의 기록만 기록 연월·몇 개월 전과 함께 읽는다.
- 다른 국가 장수, 재야, 무인증, 제재 계정은 그 기록을 받지 못한다.

## 1. 열람 조건 (정본)

첩보 기록이 누구에게 무엇을 여는지를 여기 한 곳에서 정한다. T4-11은 IC-1·IC-3·IC-4·IC-8의 상태 몫을, 이 작업은 IC-2·IC-5·IC-10과 IC-6·IC-7의 응답 모양을, T4-38은 IC-6·IC-7의 값과 IC-9의 안개 몫을 만든다. 세 작업은 이 표를 고치지 않고 따른다. 고칠 일이 생기면 이 표를 먼저 고치고 셋을 함께 다시 검토한다.

| ID | 조건 | 만드는 작업 |
| -- | ---- | ----------- |
| IC-1 | 기록의 주인은 국가다. 실행한 장수의 실행 시점 소속 국가가 주인이고 장수 개인 몫은 없다. 재야는 첩보할 수 없다(T4-11 I4 (가) 전제. (나)로 정해지면 이 줄을 고친다) | T4-11 |
| IC-2 | 세션의 `(worldId, userId)` 장수의 지금 소속 국가가 주인과 같을 때만 연다. 요청에 국가·장수 ID를 받지 않는다. 장수가 없으면 `NOT_FOUND`, 재야면 빈 목록이다. 장수가 국가를 옮기면 옛 국가 기록은 닫히고 새 국가 기록이 열린다 | T4-12 |
| IC-3 | 기록 단위는 국가·도시마다 최신 하나다. 같은 국가가 같은 도시를 다시 첩보하면 단계와 상관없이 새 기록으로 바뀐다 | T4-11 |
| IC-4 | 단계가 정한 칸만 연다. 단계 3은 주민·주민 최대·민심·장수 수·병력, 단계 2는 여기에 농업·상업·치안·수비·성벽과 각 최대, 단계 1은 여기에 병종별 장수 수와 기술 비교(대상이 국가일 때)다. 응답은 기록에 없는 칸을 지어내거나 지금 값으로 채우지 않는다 | T4-11 (기록), T4-12 (투영) |
| IC-5 | 기록 시각은 게임 연월과 몇 개월 전이다. 연월은 `toGameDate(startYear, record.tick)`, 몇 개월 전은 `floor(nowTick / TICKS_PER_MONTH) − floor(record.tick / TICKS_PER_MONTH)`이고 0 미만이면 0이다. `nowTick`은 `world.summary`와 같은 서버 계산(`queries.ts:55~`)이다 | T4-12 |
| IC-6 | 표시 기간은 U-11이다. 결정 전에는 상한 없이 모두 연다. 상한이 정해지면 상한을 넘은 기록은 목록(`intel.records`)과 안개(`city.get`)에서 함께 닫힌다. 조각에서 지우지는 않는다 | T4-12 (모양), T4-38 (값) |
| IC-7 | 병력은 응답에서 늘 구간 `{ min, max }`다(`max === null`은 위가 열린 구간). U-11 전에는 `min = max = 기록 값`이다. 구간표가 정해지면 목록과 안개가 같은 함수로 바꾼다. 저장된 기록은 정확한 값 그대로다 | T4-12 (모양), T4-38 (값) |
| IC-8 | 주인 국가가 멸망하면 그 기록은 누구에게도 열리지 않는다. 지운 국가 ID는 다시 쓰이지 않는다(`removeNation`이 먼저 `commandMeta`를 고정, `commands/support.ts:61~71`). 조각에서 지우지는 않는다 | T4-11 |
| IC-9 | 도시 소유가 기록 뒤 바뀌어도 기록은 그대로이고 기록 당시 소유국 표시값(`owner`)을 함께 낸다. 지금 공개 범위가 상세를 주는 도시(`visibility.ts:14~15`: 자기 국가 도시, 내 장수가 있는 도시)의 안개 칸은 기록 대신 지금 값을 쓴다. 목록에는 그 기록도 그대로 남는다 | T4-38 |
| IC-10 | `spy`를 켜지 않은 월드에는 조각이 없다. `intel.records`는 `{ enabled: false, items: [] }`이고 `city.get`과 다른 기존 응답은 지금과 바이트 단위로 같다 | T4-12, T4-38 |

## 2. API 계약

### 2.1 입력

```ts
intel.records: protectedProcedure.input(worldInput).query(...)
// worldInput = z.object({ worldId: z.uuid() }).strict() (queries.ts:6)
```

`nationId`, `generalId`, `cityKey`, `cursor` 같은 칸은 받지 않는다. strict라서 남는 칸은 `BAD_REQUEST`다.

### 2.2 출력

```ts
type IntelRecordsOutput = {
  enabled: boolean; // 이 월드에서 spy가 켜졌는가 (worldResolver(world).get('spy') !== undefined)
  items: IntelRecordView[]; // tick 내림차순, 같은 tick이면 cityKey 오름차순
};
type IntelRecordView = {
  cityKey: number;
  tick: number;
  year: number;
  month: number;
  ageMonths: number; // IC-5
  level: 1 | 2 | 3;
  owner: { id: number; name: string; color: string } | null; // 기록 당시 소유국, null은 공백지
  population: number;
  populationMax: number;
  trust: number;
  generals: number;
  crew: { min: number; max: number | null }; // IC-7
  domestic?: {
    agriculture: number; agricultureMax: number;
    commerce: number; commerceMax: number;
    security: number; securityMax: number;
    defence: number; defenceMax: number;
    wall: number; wallMax: number;
  }; // level <= 2
  crewTypes?: { crewType: number; name: string; generals: number }[]; // level 1
  tech?: 'overwhelming' | 'ahead' | 'even' | 'behind' | 'far_behind'; // level 1이고 owner가 있을 때
};
```

- 선택 칸은 기록에 없으면 키 자체가 없다(IC-4).
- 병종 이름은 `unitSetSchema.parse(world.unitSet)`에서 찾는다. 없는 병종 번호는 번호 문자열을 이름으로 쓴다(원작 `che_첩보.ts:131`과 같은 대체).
- 도시 이름은 넣지 않는다. 화면은 이미 받는 `world.map`의 공개 도시 이름을 쓴다.
- `tick`은 화면의 정렬과 시험을 위해 그대로 낸다. 비공개 값이 아니다.

### 2.3 처리 순서

`readWorld`(RepeatableRead) 한 트랜잭션 안에서 아래 순서로 한다.

1. 월드가 없으면 `NOT_FOUND`(`readWorld`).
2. `requireGeneral`로 세션 장수. 없으면 `NOT_FOUND`(IC-2).
3. 월드 행의 `preset`·`unitSet`을 읽어 `worldResolver`로 `enabled`를 정한다. 꺼졌으면 `{ enabled: false, items: [] }`(IC-10).
4. 장수가 재야면 `{ enabled: true, items: [] }`(IC-2).
5. `WorldExtSlice`의 `(worldId, 'intel')` 한 행을 읽는다. 켰는데 행이 없거나 `intelSlice.validate`를 지나지 못하면 `INTERNAL_SERVER_ERROR`다. 일부만 내지 않는다. 오류 문구는 `trpc.ts:10`대로 고정되고 값은 로그에 넣지 않는다.
6. `value[String(장수 국가)]`만 꺼낸다. 다른 국가 키는 읽지 않는다.
7. 기록마다 `intelRecordInfo(cityKey, record, { startYear, nowTick, unitSet })`로 투영하고 정렬한다.

다른 조각은 읽지 않는다. 그래서 `restoreExtState`(T4-03 E5)의 전체 key 집합 검사는 하지 않고 `intel` 조각 하나만 검증한다. 전체 집합 검사는 엔진 적재가 맡는다.

### 2.4 `intelRecordInfo` (visibility.ts)

```ts
export function intelRecordInfo(
  cityKey: number,
  record: IntelRecord,
  context: { startYear: number; nowTick: number; unitSet: UnitSetResource },
): IntelRecordView;
```

- 기록 칸을 허용 목록으로 하나씩 옮긴다. 펼치기(`...record`)로 넘기지 않는다.
- 병력은 `{ min: record.crew, max: record.crew }`다(IC-7의 U-11 전 값). T4-38이 이 줄을 구간 함수 호출로 바꾼다.
- 나이 상한 거르기는 없다(IC-6의 U-11 전 값). T4-38이 라우터 6단계 뒤에 거르기를 더한다.

### 3.2 실제 PostgreSQL·TCP HTTP (`intel.integration.test.ts`)

준비: 고정 시드 월드 두 개(같은 시나리오, `spy`를 켠 프리셋 하나와 끈 프리셋 하나), 국가 A·B, 계정 넷(A 장수, A의 다른 장수, B 장수, 재야 장수)과 장수 없는 계정 하나, 제재 계정 하나. 켠 월드에서 A 장수의 `spy` 예턴을 넣고 엔진 `TurnLoop`로 실제 실행해 기록을 만든다. 경계 사례(나이·여러 도시·멸망 국가)는 같은 트랜잭션 규칙을 지키는 시험 도우미로 `WorldExtSlice` 행을 직접 쓴다.

| ID | 범주 | 내용 |
| -- | ---- | ---- |
| H1 | 성공 | A 장수가 실행한 기록을 A 장수와 A의 다른 장수가 같은 응답으로 받는다. `year`·`month`·`ageMonths`가 있고 값은 실행 tick의 도시·장수 값과 같다 |
| H2 | 저장 | H1의 턴을 실행한 엔진을 끄고 다시 띄운 뒤 같은 응답이 나온다. 턴 트랜잭션 commit 직전 실패를 넣으면 기록 행도 바뀌지 않는다(C5. 실패 주입 지점은 T4-03 E6 시험 도우미를 쓴다) |
| H3 | 다른 사용자 | B 장수는 A의 기록을 하나도 받지 않는다(B 자기 기록만). 입력에 `nationId: A`나 `generalId`를 더하면 `BAD_REQUEST`이고 DB는 그대로다 |
| H4 | 무인증 | 쿠키 없음, 위조 쿠키, 만료 세션은 `UNAUTHORIZED` |
| H5 | 제재 | 제재·탈퇴 계정의 기존 세션은 `UNAUTHORIZED`(H8 선례와 같은 준비) |
| H6 | 잘못된 입력 | `worldId` 누락, uuid 아님, 남는 칸, POST 호출은 거부된다 |
| H7 | 재야·장수 없음 | 재야는 `{ enabled: true, items: [] }`, 장수 없는 계정은 `NOT_FOUND`, 없는 월드는 `NOT_FOUND` |
| H8 | 국가 이동 | A 장수가 B로 옮긴 뒤 A 기록은 안 보이고 B 기록이 보인다(IC-2) |
| H9 | 멸망 | A가 멸망한 뒤 A였던 장수(재야)와 새로 생긴 국가 장수 누구도 A 기록을 받지 않는다(IC-8) |
| H10 | 다시 첩보 | 같은 도시를 다시 첩보하면 기록이 하나이고 새 tick이다(IC-3) |
| H11 | 끈 월드 | 끈 월드에서는 `{ enabled: false, items: [] }`. `WorldExtSlice` 행이 없다. 같은 월드의 `city.get`·`world.map` 응답이 이 PR 전 골든과 같다(IC-10) |
| H12 | 손상 | 켠 월드의 `intel` 행을 형식이 깨진 JSON으로 바꾸면 `INTERNAL_SERVER_ERROR`이고 응답 본문에 기록 값이 없다 |
| H13 | 응답 허용 목록 | 모든 성공 응답의 키 집합이 2.2와 같다. 다른 국가 키, `generalId`, 정확한 병력 이외의 숨은 값이 없다 |
| H14 | 상태 불변 | 조회 전후 월드·장수·조각 행이 같다 |

### 3.3 권한 대조

`tools/authz.integration.test.ts`의 `paths`에 `intel.records`를 더하고 `input()`에 `{ worldId }`를 준다. 다섯 범주 모두 실행 증거를 남기며 면제는 두지 않는다. `pnpm test:int` 결과에서 권한 대조 누락 0을 구현 기록에 붙인다.

### 3.4 인수 증거

T4-12의 증거는 위 단위·통합 시험 이름과 실행 명령(`pnpm check`, `pnpm test:int`), 권한 대조 출력, 커밋이다. AC-P2-07은 T4-11 규칙, T4-17 엔진, 이 작업, T4-13 화면이 모두 끝나고 반대쪽 리뷰가 끝나야 통과다.
