### 4.3 효과 (마지막 칸)

`change`가 복제 상태에서 차례로 한다. RNG는 쓰지 않는다.

1. `leadership`, `strength`, `intel`을 각각 `max(하한, round(× 0.85))`. 하한은 S3 (가)면 상수 10, (나)면 `actor.statRules.min`이다(4.5)
2. `age = 20`. S2 (나)면 `birthYear = 지금 연도 − 20`이고 `deathYear`에 같은 차이를 더한다. `activeFromYear`는 바꾸지 않는다
3. `injury = 0`
4. `experience = round(× 0.5)`, `dedication = round(× 0.5)`
5. MQ-1 (가)·(나)면 장수의 모든 계열 숙련을 `round(× 0.5)`(T4-60 `setProficiency`)
6. T4-25 특기 조각이 있으면 다음 특기 시점을 그 규칙의 초기값으로(S4 (가))

지금 연도는 `toGameDate(view.startYear, actor.tick ?? 0).year`다. 효과는 world 하나다.

### 4.5 능력치 규칙 전달 계약 (S3 (나)일 때)

지금 명령은 능력치 규칙을 읽을 수 없다. `WorldState`에는 칸이 없고(`model/world.ts:6-16`) `Actor`에는 병종 자료만 있다(`commands/types.ts:7-12`). 규칙 값은 `WorldInit.statRules`(`world/bootstrap.ts:94`)와 DB `World.statRules`(`packages/db/prisma/schema.prisma:34`)에 있다. 병종 자료가 `Actor.unitSet`으로 들어오는 길을 그대로 따른다.

| 자리 | 지금 `unitSet`을 넘기는 곳 | 더할 것 |
| ---- | -------------------------- | ------- |
| 타입 | `commands/types.ts:11` | `statRules?: DeepReadonly<StatRules> | undefined` 한 칸 |
| 엔진 턴 | `apps/engine/src/turnLoop.ts:178` | `World.statRules`를 `statRulesSchema`로 읽어 넘긴다 |
| 서버 사전 검사 | `apps/server/src/routers/turns.ts:115` | 같은 값 |
| 순수 재생 | `packages/rules/src/replay.ts:53`, `:67`(`runReplayAction` 인자) | 다섯째 선택 인자 `statRules` |
| 엔진 재생 | `apps/engine/src/replay.ts:295`, `:325` | `origin.initial.statRules` |
| 시뮬레이터 | `apps/engine/src/simulation.ts:44` | `initial.statRules` |

- 읽기는 `statRulesSchema.safeParse({ stat: 값 })`이다. 여러 통합 시험 고정물이 `statRules: {}`를 저장하므로(예: `apps/engine/src/lease.integration.test.ts:26`) 실패하면 칸을 넘기지 않는다. 그 월드의 기존 명령 결과는 그대로다.
- `actor.statRules`가 없으면 은퇴 검사는 `BAD_STATE`, `능력치 규칙을 확인하세요.`로 실패한다. 4.2 표의 3번이다.
- 세 호출 지점이 같은 월드 값을 넘기므로 사전 검사·엔진·재생이 같은 하한을 본다. 엔진 재생은 생성 기록의 값을 쓰므로 나중에 자원 판이 바뀌어도 재생이 바뀌지 않는다.
- 파일 소유: `commands/types.ts`와 `replay.ts`는 명세 §7의 T4-02 → T4-49 → T4-48 순서 파일이고 엔진·서버 호출 지점은 T4-03 연결 몫이다. 이 행은 그 순서에 끼지 않고 이 계약을 T4-03(또는 같은 순서의 소유 작업)이 수용해 넣어 주기를 요청한다(Q65-1). [T4-66](./T4-66.md) S4 (나)도 같은 길을 쓴다.
