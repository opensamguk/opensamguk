# 선택형 확장 월드 생성 연결

2026-11-07 T4-11·T4-12·T4-38의 새 선택 `san10-191-intel`은 `expanded-191-v8`을 사용한다. v7의 자원 다섯 판과 설정을 이어받고 `intel-v1`을 추가한다. 생성과 초기화에서 빈 첩보 원장을 시작하며 기존 판과 실행 중인 월드는 각자의 생성 설정을 따른다. 관리자 목록은 기존 선택 뒤에 새 항목을 보탠다. 운영 연결의 인수조건은 AC-P2-07·18이며 화면은 T4-13·T4-39에서 연결한다.

2026-11-06 D-075·076의 새 선택은 `expanded-191-v5`다. v4의 다섯 자원·여섯 설정과19기능에 `nation-lifecycle-v1`만 더한다. `creationOptions(expandedProfiles:true)`의 기존 다섯 항목 뒤에 `san10-191-lifecycle`을 추가하며 생략·false의 세 항목·revision은 유지한다. v5 파일만 누락·손상되면 여섯째 항목만 비가용이 된다. 선양·방랑·재정착·수동 및24개월 자동 해산을 연결하며 기존 v4와 진행 중 월드에는 소급하지 않는다. 실제 검증·독립 리뷰·정상 병합 전이다.

새 선택 `expanded-191-v4`는 형식3으로 SAN10 지도·`san10-191@2`·확장 병종·다섯 능력치·191 초상화의 게시 판을 고정한다. 기존 v1·v2·v3 파일과 시나리오 1판은 보존한다. D-048·072·073·074에 따라 도시 규모·폐허, 창극병·차병 모집 자원, 계략 패 여덟 종과 국가 전략 세 종을 포함한 19기능·여섯 설정을 연결한다. 현재 구현 중이며 전체 AC 완료가 아니다.

`creationOptions`는 `expandedProfiles: true`일 때 기존 네 항목 뒤에 `san10-191-expanded`를 추가한다. 생략·false는 기존 세 항목과 revision을 보존한다. 새 프로필은 자원 키 다섯 개를 모두 대조한다. 운영자는 `pnpm db:init-expanded`로 새 시나리오 2판을 게시한다. 게시된 기존 판의 내용·해시·출처가 다르면 덮어쓰지 않고 거부한다. 기존 자원 초기화 명령의 게시 목록은 바꾸지 않는다.

2026-11-06 INT-22의 새 선택은 `expanded-191-v3`다. 저장 형식2의 v2 설정·수치를 보존하고 `battle-affinity-v2`만 추가한 15기능·다섯 설정이다. 기존 v1·v2 파일과 원생성·초기화 계약은 유지한다.

## 범위와 계약

`expanded-191-v1` 설정 파일 하나에 통합판 자원과 기존 9기능에 물류·황실·가문·유산을 더한 13기능, 네 설정을 고정한다. 기본 수치는 rules 코드에 두지 않는다. 순수 스키마는 기존 네 기능 스키마를 재사용한다. 파일 읽기·해시는 서버와 엔진의 기존 자원 경계를 따른다. 새 의존성과 migration은 없다. 기존 프로필과 진행 중 월드는 보존한다.

관리자 `creationOptions`의 선택 입력 `expandedProfiles`가 true일 때만 네 번째 항목을 돌려준다. 생략·false는 기존 세 객체·순서·revision을 유지하고 새 파일을 읽지 않는다. true에서도 새 파일 오류는 확장 항목만 비가용으로 만든다. 반환 목록을 정한 뒤 revision을 계산하며 확장 항목에는 설정 내용 해시도 넣는다. 기존 화면과 열린 탭은 계속 세 항목을 받는다.

생성 입력과 version1 intent에는 선택 `featureProfileKey`만 더한다. 키가 없으면 기존 JSON·해시를 보존한다. 키가 있으면 입력 기능 자체가 파일과 정확히 같고 해결된 지도·시나리오도 일치해야 한다. 설정은 엔진의 기존 원생성 준비에 전달하고 resolution에 키·내용 해시를 고정한다. 누락·미지 키·손상·고정 뒤 변경은 `RESOURCE_INVALID`, 요청 조합 불일치는 `INPUT_INVALID`다. 실제 DB 오류의 PENDING 재시도는 유지한다.

초기화의 별도 strict resolution 스키마도 명세를 받는다. intent 키와 명세의 존재·키·해시, 저장된 원생성의 네 설정을 함께 확인한다. 자동 policy 자료와 프로필의 네 자료를 구분한다. 초기화는 현재 파일 대신 저장된 원생성 설정을 복사하며 기존 요청과 옛 성별 원장 선택을 보존한다.

## 검증과 후속

순수·단위 검증은 실제 491명 자료의 설정·기능·특산·이름 검사와 결정적 준비, 기존 요청 해시, 잘못된 키·조합·파일, 초기화 고정 명세를 포함한다. 실제 PG 검증은 관리자 HTTP 조회·접수에서 PENDING 요청을 만들고 실제 엔진 처리 뒤 13기능·네 상태·성별·원생성·재생을 확인한다. 같은 요청 재처리와 HTTP 초기화, 거부 전후 저장 보존도 확인한다. 직접 `saveInitialWorld`를 부르는 고정물로 생성 연결을 대신하지 않는다.
