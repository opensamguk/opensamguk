- 첩보 기록 저장·조회(T4-12), 국가 예턴 HTTP(T4-50), 화면(T4-04, T4-51).

### 접근

1. 선행 확인: T4-03 1단계와 각 기능 작업의 규칙 PR이 main에 있다. 아직 병합되지 않은 기능은 이번 등록에서 빼고 같은 ID로 다음 등록 PR을 연다(쟁점 Z3).
2. 대응표 도구가 정해진 factory를 읽게 한다(쟁점 Z1). 등록 전에 넣어야 `pnpm check`가 막히지 않는다.
3. 실제 시험 파일 대조를 넣는다(쟁점 Z2).
4. 명령·조각·관계를 등록한다. `ext/registry.test.ts`의 관계 대조가 통과해야 한다.
5. 기능 작업에서 조각 등록 전이라 미뤄진 실행 성공 단위 시험을 돌린다([T4-07](./T4-07.md) 쟁점 Z2).
6. 순수 재생 보존 시험과 엔진 통합 시험 X1~X14를 쓴다. T4-03 2단계 시험을 같은 PR에서 돌린다.
7. 끈 월드 골든과 기본 37개 대조를 확인하고 대응표 증거를 채운다.

- 권한: 기준 `commands/turn.ts:26-30`은 officerLevel 12인 장수의 턴에만 국가 칸을 실행한다. T2-05의 직책 분기도 5~12만 실행한다. 그래서 국가 명령의 수뇌 미만 직책 실패는 엔진에서 관찰할 수 없고 엔진 대표 실패로 세지 않는다. 그 검사는 기능 작업의 단위 시험([T4-06](./T4-06.md) N3, [T4-16](./T4-16.md) N4)과 T4-50의 국가 예턴 HTTP 권한 시험이 증거다.
- 순수 재생: `replay.test.ts`에 `strategyCooldown` 조각이 든 상태에서 장수 턴(계략)과 국가 턴(백성동원)이 섞인 12개월 재생을 두고 매달 `ext`가 사라지지 않으며 해시가 두 번 돌려도 같은지 본다(T4-02 2.4.5).
- 권한: 일반 명령은 기존 `turns.set`·`turns.edit`·`turns.precheck`·`commands.list`의 다섯 범주 시험에 확장 key 사례를 더한다(T4-03 2단계 A). 국가 명령의 저장 권한은 T4-50이다.
- 국가 명령은 엔진이 읽는 국가 칸을 시험이 직접 넣는다. T4-50이 먼저 병합되면 HTTP로 넣는 시험을 더한다.

### 등록 읽기 계약 (쟁점 Z1)

기준 `tools/command-coverage.mjs:143-166`, `:208-213`은 경로로 확인한 `defineCommand`의 객체 인자 하나만 읽는다. 이 계약은 그 성질(선언 경로와 import 심벌 추적)을 유지하면서 두 종류를 더한다.

| ID | 종류 | 허용 모양 | 읽는 값 |
| -- | ---- | --------- | ------- |
| F1 | 객체 spec factory | `defineCommand`(`commands/support.ts`), `makeStratagem`(`ext/stratagem/base.ts`), `defineStrategy`(`ext/strategy/base.ts`), `makeResearch`(`ext/research/makeResearch.ts`). 인자는 정확히 하나이고 호출 자리의 객체 리터럴이다(지금 `defineCommand` 규칙 `:210`과 같다) | `key`는 문자열 리터럴 속성. 대상은 객체의 `target` 문자열 리터럴이 있으면 그 값, 없으면 factory별 고정값(`defineCommand`·`makeStratagem`은 `general`, `defineStrategy`·`makeResearch`는 `nation`) |
| F2 | wrapper | `withPrepare`(`ext/prepare/withPrepare.ts`). 인자는 정확히 둘이다. 첫 인자는 아직 감싸지 않은 정의를 내는 F1 호출(`defineCommand`, `makeStratagem`, `defineStrategy`) 또는 그것으로 해석되는 `const`·import 별칭·재수출 참조다. `makeResearch`는 안에서 이미 `withPrepare`로 감싼 정의를 내므로([T4-09](./T4-09.md) 계약 D) 첫 인자가 될 수 없다. F2 호출을 다시 감싸는 것도 안 된다([T4-07](./T4-07.md) 계약 D의 두 번 감싸기 예외). 둘째 인자는 spec 객체이며 `key`·`target`·`name` 속성이 있으면 거부한다 | 첫 인자를 재귀로 읽은 `key`·대상을 그대로 쓴다. wrapper가 key와 대상을 바꾸지 않는다는 것은 [T4-07](./T4-07.md) 계약 D가 정한다 |
| F3 | 이름 확인 | factory·wrapper는 함수 이름만 비교하지 않는다. import 심벌을 따라가 위 파일의 그 export 선언에 닿아야 한다. 같은 이름의 다른 함수는 거부한다 | |
| F4 | 거부 | 목록 밖 factory, 계산된 key·대상, 동적 목록, 인자 수가 다른 호출, F1 인자에 spread가 있는 객체, F2 둘째 인자의 key·대상 덮어쓰기, `withPrepare(makeResearch({...}), spec)`와 `withPrepare(withPrepare(...), spec)` 같은 중복 감싸기, T4-02 리뷰가 찾은 참조되지 않는 선언의 부작용·구조 분해 선언 | 실패 |
| F5 | 대조 | 정적 결과의 key·대상·순서가 런타임 `extensionCommands`와 같다. 시험은 정상 등록 `withPrepare(defineStrategy({...}), spec)`과 `makeResearch({...})`, `const`·import 별칭, 재수출, 위 거부 사례를 모두 넣는다 | |

시험 파일 대조(쟁점 Z2)도 같은 원칙으로 주석·문자열 속 가짜 `describe`·`it`를 증거로 세지 않는다.
