## 2. 계약

### 2.1 휴전 설정

```ts
// packages/rules/src/clock/truce.ts
export interface Truce {
  utcOffsetMinutes: number; // −720 ~ 840 정수. 서머타임 없음
  startMinute: number; // 0 ~ 1439 정수. 그 지역 시각의 분
  endMinute: number; // 0 ~ 1439 정수, startMinute와 다름. start > end면 자정을 넘는다
}
export const truceSchema: z.ZodType<Truce>; // strict
```

- 구간은 날마다 반복되는 `[start, end)`다. 시작 포함, 끝 제외(C18).
- 프리셋 `presetSchema`에 `truce: truceSchema.nullable().optional()`을 더한다. 없거나 null이면 휴전이 없다. 지금 저장된 사본과 프리셋 파일 네 개는 그대로 통과한다.
- 상태(`presetRules`)에는 넣지 않는다.

### 2.2 순수 함수

```ts
export function truceMsBetween(from: number, to: number, truce: Truce): number; // [from, to)와 휴전의 겹침 ms. to ≤ from이면 0
export function effectiveElapsed(from: number, to: number, truce: Truce | null): number; // to ≤ from이면 0, 휴전 없으면 to − from
export function inTruce(at: number, truce: Truce): boolean;
export function truceWindow(at: number, truce: Truce): { active: boolean; endsAt: number | null; nextStartsAt: number };
export function timeAtTick(clock: Clock, targetTick: number): number; // C18 역변환
```

겹침 계산은 날짜를 돌지 않는 닫힌 식이다. 하루 `DAY = 86400000`, 휴전 길이 `L = ((end − start) mod 1440) × 60000`, 원점 `shift = (start − utcOffsetMinutes) × 60000`이다. 원점을 휴전 시작에 맞추면 날마다 휴전은 `[0, L)`이다.

```text
G(x) = floor((x − shift) / DAY) × L + min((x − shift) mod DAY, L)   // 원점부터 x까지의 휴전 ms
truceMsBetween(a, b) = G(b) − G(a)
H(x) = (x − shift) − G(x)                                             // 원점부터 x까지의 유효 ms
```

`mod`는 늘 0 이상인 나머지다. `H`는 휴전 안에서 평평하고 밖에서 기울기 1인 단조 함수다.

### 2.3 시계 함수의 변경

- `Clock`에 `truce?: Truce | null`을 더한다. 없거나 null이면 모든 함수가 지금 식과 같은 값을 낸다(2.6 골든).
- `nowTick`: RUNNING이고 실시간이면 `clockTick + floor(effectiveElapsed(anchor, now, truce) / msPerTick)`. 지금의 `Math.max(0, …)`는 `effectiveElapsed`가 음수를 내지 않아 같은 뜻이다.
- `timeAtTick(clock, target)`.
  - `need = (target − clockTick) × msPerTick`.
  - `need ≤ 0`(기준 tick 이하, 밀린 칸 포함)이거나 휴전이 없으면 `anchor + need`. 지금 `nextTurnAt`의 식과 같다. 밀린 칸의 시각은 이미 지난 시각이고 휴전을 되짚지 않는다(T40-Q1).
  - `need > 0`이고 휴전이 있으면 `H(x) = H(anchor) + need`가 되는 가장 이른 `x`. `W = DAY − L`, `v = H(anchor) + need`, `days = floor(v / W)`, `rem = v − days × W`일 때 `rem = 0`이면 `x = shift + days × DAY`(휴전 시작 순간에 딱 닿음), 아니면 `x = shift + days × DAY + L + rem`. C18의 휴전 시작 순간 규칙과 같다.
- `checkpointClock`: 새 tick은 지금처럼 `max(minimumTick, nowTick)`. 새 기준 시각은 `timeAtTick(clock, 새 tick)`. tick에 못 미친 잔여 유효 경과가 남는다. 휴전이 없으면 지금 식(`anchor + tick 차 × msPerTick`)과 같다.
- `pauseClock`: 지금처럼 `clockTick = nowTick(clock, now)`, 기준 시각 = `now`. tick에 못 미친 잔여는 지금처럼 버린다(T40-Q2). 휴전이 있어도 같은 규칙이다.
- `resumeClock`·`startClock`: 기준 시각 = `now`. 휴전 안에서 재개하면 휴전이 끝날 때까지 tick이 늘지 않는다.
- `endClock`: 지금처럼 `nowTick`으로 tick을 정한다.
- 가속 모드는 지금처럼 `nowTick`이 `clockTick`을 돌려주고 휴전을 보지 않는다.

### 2.4 정수와 반올림

`msPerTick = 6 × turnTermMinutes`는 정수이고 휴전 경계·원점은 분 단위다. 그래서 `G`, `H`, `timeAtTick`, 새 기준 시각은 모두 정수 ms이고 반올림이 없다. `World.clockAnchorAt`(PostgreSQL `timestamp(3)`)에 그대로 들어간다. 실행 중 시계의 기준 시각이 안전 정수여야 한다는 지금 검사(`clock.ts:21-23`)도 그대로 성립한다.

### 2.5 엔진과 서버 연결

- 엔진 `apps/engine/src/world/truce.ts`: `worldClock(world): Clock`가 월드 행에서 시계를 만든다. `world.preset`이 있으면 `parsePreset(world.preset).truce ?? null`을 넣는다. `controlClock`(`world/clock.ts:12-18`)과 턴 루프(`turnLoop.ts:127`)가 이 함수를 쓴다. 턴 루프의 기준 시각 저장(`:259`)은 `checkpoint.clockAnchorAt`을 그대로 쓰므로 고칠 것이 없다.
- `controlClock` 응답에 `truce: TruceStatus | null`을 더한다(2.5.1).
- 서버 `queries.ts`: `worldSelect`에 `preset: true`를 더한다. `worldClock(world)`를 서버에도 하나 두고(엔진 것과 같은 식, 규칙 함수만 부름) `worldSummary`·`nextTurnAt`·새 `turnSchedule`이 쓴다. `message.ts`와 `notice-publish.ts`도 이 함수로 시계를 만든다. 시계 객체를 직접 펼쳐 만드는 곳이 남지 않았는지 정적 시험으로 막는다(5절 V9).

## 4. 쟁점 (부모·Codex가 정할 기술 문제)
