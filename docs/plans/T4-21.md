## 0. 이 문서의 위치

명세 §6 T4-21 행을 화면 하나의 동작·파일·시험으로 적는다. 부대 만들기·가입·탈퇴·추방은 즉시 행동이라 결과가 엔진 처리 뒤 정해진다. 화면은 [UI 지침](../frontend-ui-guidelines.md) §2 외교실의 즉시 행동 규칙(요청마다 `requestId`, 처리 중 표시, 같은 요청 다시 보내기, 결과로만 확정)을 그대로 따른다. 집합은 예턴 명령이라 기존 30칸 편집기에서 넣고 이 화면은 부대원 위치와 안내만 보인다.

## 계획 (Claude)

### 목표

확장을 켠 월드에서 장수가 부대 화면을 열어 자기 국가의 부대를 본다. 부대를 만들거나 다른 부대에 가입하고 나갈 수 있으며 부대장이면 부대원을 내보낸다. 누른 행동은 엔진 처리 결과가 오기 전까지 처리 중으로 보이고 새로 고침이나 다시 로그인 뒤에도 같은 요청의 결과를 되찾는다. 부대원이 어느 도시에 있는지 보여 주어 부대장이 집합을 넣을지 정할 수 있다. 끈 월드에는 메뉴가 없다.

## 2. 화면 계약

### 2.1 진입

- 주소 `/w/:worldId/troops`. 직접 열기와 새로 고침이 된다. 로그인 가드는 기존 월드 경로 가드를 그대로 탄다.
- 메뉴 `부대`는 `commands.list` 결과에 `troop_gather`가 있을 때만 보인다. 결과를 받기 전에는 그리지 않아 메뉴가 깜빡이지 않는다.
- 끈 월드 판단은 메뉴와 같은 `commands.list` 신호로 한다. 주소로 직접 와도 `troop_gather`가 없으면 `troop.*`를 부르지 않고 `이 월드에서는 부대를 쓰지 않습니다.` 빈 상태와 메인으로 가는 링크를 보인다. 서버 문구로 판단하지 않는다(서버는 T2-26 `requireRuleFeature`의 `PRECONDITION_FAILED`를 주며 같은 코드가 다른 거부에도 쓰인다).

### 2.2 배치

```text
┌ 내 부대 ─────────────────────────────────────────────┐
│ 청주병 · 부대장 조조 · 부대원 3명                      │
│ 이름   위치   부대장 도시와 같음                        │
│ 조조   진류   부대장                                    │
│ 하후돈 복양   아니오 (집합하면 진류로 옴)    [내보내기]   │
│ [부대 해산] 또는 [부대 나가기]   집합은 예턴에서 넣습니다 → │
├ 국가 부대 ───────────────────────────────────────────┤
│ 부대 이름 · 부대장 · 인원 · [가입]                       │
├ 부대 만들기 ─────────────────────────────────────────┤
│ 이름 [          ] 폭 8/18  [만들기]                     │
└──────────────────────────────────────────────────────┘
```

- 내 부대 칸은 소속이 있을 때만 있다. 부대장 행에는 `Tag`로 `부대장` 글자를 붙인다. 위치가 부대장 도시와 다른 부대원은 노랑 글자 `떨어짐`과 도시 이름을 함께 쓴다. 색만으로 가르지 않는다(NFR-08).
- 부대장에게는 `부대 해산`, 부대원에게는 `부대 나가기`가 보인다. 둘 다 같은 `troop.leave`다. 해산은 부대원 모두가 빠진다는 확인을 한 번 거친다.
- `집합은 예턴에서 넣습니다` 링크는 `/w/:worldId/turns`로 간다. 부대장이 아니면 링크 대신 `집합은 부대장만 넣을 수 있습니다.`를 쓴다.
- 국가 부대 표는 `DataTable`이다. 머리글 정렬은 이름과 인원. 인원은 고정폭 숫자, 오른쪽 정렬.
- 가입 버튼은 `canJoin`이 `ok: false`면 숨기지 않고 점선 테두리로 두고 누르면 서버 이유를 보인다(`DisabledReason`). 이미 소속이 있으면 이유는 서버 문구 그대로다.
- 만들기 칸의 폭 표시는 안내다. 전각 2·반각 1로 세는 `nameWidth.ts`는 T4-19 2.3과 같은 규칙이지만 최종 판정은 엔진이다. 18을 넘으면 만들기 버튼을 점선으로 두고 이유를 보인다.
- 장수가 없으면 칸마다 장수 만들기 안내(지금 메인과 같은 문구)를 둔다. 재야면 `canCreate` 이유를 만들기 칸에 보인다.

### 2.3 즉시 행동 흐름

UI 지침 §2 외교실의 즉시 행동 규칙을 공통 꼴(`apps/web/src/inputs/`)로 옮겨 쓴다.

| 상황 | 화면 |
| ---- | ---- |
| 버튼 누름 | `requestId`(UUID)를 만들어 보내기 전에 sessionStorage에 둔다. 키에 계정과 월드를 넣는다 |
| `applied` | 성공 문구 한 줄(`aria-live="polite"`), 그 요청 지움, `troop.list` 다시 받기 |
| `pending` | 그 버튼이 있는 줄에 `처리 중`을 두고 같은 kind의 다른 버튼을 잠근다. `troop.request`를 1초마다 묻는다 |
| 오류 응답(`UNAUTHORIZED` 밖) | 코드만으로 확정하지 않는다. 접수가 커밋된 뒤 대기나 응답 처리에서 `INTERNAL_SERVER_ERROR`가 나도 입력은 `PENDING`이거나 이미 `APPLIED`일 수 있기 때문이다(T4-20 2.3 기록 → 대기 순서, `apps/server/src/trpc.ts:5-12`). 요청을 지우지 않고 `checking`으로 두어 `troop.request`를 한 번 묻는다. 아래 줄로 갈린다 |
| `troop.request`가 `applied`·`rejected`·`pending` | 그 상태를 그대로 따른다. `rejected`일 때만 기록된 이유를 빨간 글로 보이고 요청을 지운다 |
| `troop.request`가 `NOT_FOUND`이고 원래 오류가 접수 전 거부(`BAD_REQUEST`, `PRECONDITION_FAILED`, `CONFLICT`, `NOT_FOUND`) | 입력이 기록되지 않은 확정 거부다. 서버 이유를 보이고 요청을 지운다 |
| `troop.request`가 `NOT_FOUND`이고 원래 오류가 `TOO_MANY_REQUESTS` | 기록되지 않았으나 다시 보낼 요청이다. 요청을 남기고 `Retry-After` 뒤 같은 `requestId`와 같은 내용으로 다시 보낸다(C15) |
| 그 밖(`INTERNAL_SERVER_ERROR`, `TIMEOUT`, `troop.request`도 실패, 응답 없음) | `unknown`. 요청을 남긴다. `같은 요청 다시 보내기`가 같은 `requestId`와 같은 내용으로 다시 보낸다. 서버는 같은 키를 입력 하나로 본다 |
| `UNAUTHORIZED` | `다시 로그인` 링크. `requestId`는 남긴다. 다시 로그인하면 `troop.request`로 결과를 묻는다 |
| 새로 고침 | 저장해 둔 요청을 `checking`으로 살려 `troop.request`로 묻는다. `troop.list`의 `pending`과도 맞춘다 |
| `CONFLICT` 처리 중 | 서버 문구를 보이고 저장한 요청의 결과를 기다린다 |

목록에서 부대가 사라진 것으로 결과를 추측하지 않는다. 결과는 `requestId`의 상태로만 정한다. 요청을 지우는 경우는 `applied`, 기록된 `rejected`, 기록되지 않은 확정 거부 셋뿐이다.

외교의 지금 규칙(`apps/web/src/diplomacy/requests.ts`의 `applySendError`)은 `UNAUTHORIZED` 밖의 코드 있는 오류를 거절로 확정한다. 공통 꼴로 옮길 때 그 분기를 그대로 가져오지 않고 위 표의 분기로 바꾼다. 외교 파일 자체는 이 작업에서 고치지 않는다(외교 담당의 다음 작업에 알린다).

### 2.4 갱신

- `troop.list`는 화면을 열 때와 즉시 행동이 끝났을 때 받는다. 지금 메인의 0초 재조회(`GameLayout.tsx:52`, `:71`)에 이 쿼리를 넣지 않는다. 대신 화면에 있는 동안 턴 결과로 위치가 바뀌는 것을 보이려고 15초마다 다시 받는다. 탭이 숨겨지면 멈춘다(TanStack Query 기본 동작).
- 실시간 연결(T2-10)의 알림 종류에 부대가 없으므로 이 작업은 SSE를 잇지 않는다.

### 2.5 접근성

- 표는 `<th scope>`를 쓴다. 버튼 이름에 대상 이름을 넣는다(`하후돈 내보내기`).
- 처리 중·결과 문구는 `role="status"`, 거절 이유는 `role="alert"`.
- 해산 확인은 `<dialog>`이며 열면 초점이 확인 버튼으로, 닫으면 해산 버튼으로 돌아온다.
- 키보드만으로 만들기·가입·나가기·내보내기가 된다.

계약이 가짜 응답이므로 단위 시험은 API 증거가 아니다.

### 3.2 Chromium E2E (`e2e/troop.spec.ts`, `pnpm e2e`)

실제 `pnpm dev`(web·server·engine)와 `_test` PostgreSQL을 쓴다. `page.route`로 게임 응답을 짓지 않는다. 지연이 필요한 시험만 실제 요청을 잡았다가 그대로 흘려보낸다. 예외는 응답 유실을 만드는 E8·E8b뿐이며 요청은 실제로 서버에 닿게 하고 브라우저가 받는 응답만 끊거나 500으로 바꾼다.

준비(`troopSeed.ts create`): T4-03의 켠 월드 생성으로 `troop_gather`를 켠 PREOPEN 월드 K와 끈 월드 F를 만든다. K에 국가 1 사람 장수 A·B, 국가 2 사람 장수 C를 둔다. B는 A와 다른 도시다. 엔진 처리가 필요한 시험은 `rankingSeed.ts`처럼 `TurnLoop`를 직접 돌려 입력과 턴을 처리한다. 끝나면 `troopSeed.ts remove`가 모두 지운다.

| ID | 시험 | 기대 |
| -- | ---- | ---- |
| E1 | 진입 | K에서 메뉴 `부대`가 보이고 주소가 `/w/K/troops`. 새로 고침 뒤 같은 화면. F에서는 메뉴가 없고 주소로 열면 빈 상태 문구 |
| E2 | 만들기 | A가 `청주병`을 만든다. 엔진 처리 전 `처리 중`, 처리 뒤 내 부대 칸. DB의 InputEvent 1건 `APPLIED` |
| E3 | 가입과 다른 국가 | B가 가입하면 내 부대 칸에 둘. C의 국가 부대 표에 `청주병`이 없다 |
| E4 | 집합 | A가 예턴 화면에서 집합을 넣어 저장한다. 엔진이 A의 턴을 실행한 뒤 부대 화면에서 B의 위치가 A의 도시이고 `떨어짐`이 사라진다 |
| E5 | 나가기·해산 | B 나가기 뒤 A만 남는다. A가 해산을 확인하면 내 부대 칸이 없어진다 |
| E6 | 내보내기 | A가 B를 내보내면 B 화면에 소속이 없다 |
| E7 | 새로 고침 복구 | 엔진을 멈춘 채 A가 만들기를 누르고 새로 고친다. 다시 `처리 중`이고 엔진 처리 뒤 결과가 보인다 |
| E8 | 다시 보내기 | 첫 만들기 요청의 응답을 브라우저에서 끊는다. `같은 요청 다시 보내기` 뒤 DB의 해당 키 InputEvent가 1건 |
| E8b | 접수 뒤 서버 오류 | 엔진을 멈춘 채 만들기를 누른다. 실제 요청은 서버까지 보내고(`route.fetch`) 브라우저에는 그 응답 대신 500을 돌려준다(`route.fulfill`). 서버가 실제로 기록한 입력을 화면이 잃는 상황을 만드는 것이며 게임 응답을 짓지 않는다. 화면은 요청을 지우지 않고 `troop.request`로 `pending`을 확인한다. 새로 고친 뒤 엔진을 돌리면 같은 결과가 보이고 DB의 해당 키 InputEvent가 1건이다 |
| E9 | 로그아웃 뒤 회수 | 처리 중에 로그아웃하고 다시 로그인하면 같은 결과를 본다 |
| E10 | 무인증 | 쿠키 없는 문맥으로 주소를 열면 `/login?next=` |
| E11 | 키보드 | Tab과 Enter만으로 만들기·가입·나가기 |

## 4. 반례와 처리

| 반례 | 처리 |
| ---- | ---- |
| 처리 중에 다른 탭에서 같은 계정이 가입 | 서버 `CONFLICT`. 문구를 보이고 처리 중 요청의 결과를 기다린다 |
| 처리 뒤 결과가 거절(다른 국가 부대, 이미 소속) | 엔진 이유 문구. 버튼 상태는 새 목록으로 |
| 부대장이 하야해 부대가 사라짐 | 다음 목록에서 내 부대 칸이 없다. 화면이 따로 알리지 않는다 |
| 끈 월드에 남은 sessionStorage 요청 | 끈 월드면 화면이 요청을 다시 묻지 않고 그 월드 키의 요청을 지운다 |
| 이름에 꺾쇠·따옴표 | 글자 그대로 보인다(React가 글자로 그린다) |
