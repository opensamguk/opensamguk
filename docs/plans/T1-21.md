# T1-21 프리티어 설정·스크립트

> 대기열: T1-21 · AC: AC-M1-01 (저장소 검사) · 구현: Claude · 리뷰: Codex
> 선행: T1-01 · 다음: T1-22 (전체 포맷) · 2026-10-20 사용자 요청

## 계획 (Claude)

### 목표

코드 포맷터를 프리티어 하나로 정한다. 이 작업은 설정과 명령만 넣고 **파일은 하나도 포맷하지 않는다.**
전체 포맷은 Codex의 T1-06(작업 중 파일이 많음)이 커밋된 뒤 T1-22에서 커밋 하나로 따로 한다.

### 범위

- 루트 `devDependencies`에 `prettier` **3.9.9 정확히 고정** (버전이 바뀌면 포맷 결과가 바뀐다).
- `.prettierrc.json`: 지금 코드 모양에 맞춘다. `singleQuote`, `printWidth: 120`, 나머지는 기본값.
- `.prettierignore`: 생성물·데이터·잠금 파일·문서.
- 스크립트: `pnpm format`(고치기), `pnpm format:check`(검사만).

### 포맷하지 않는 것과 이유

| 대상 | 이유 |
| ---- | ---- |
| `*.md` | 문서 표와 줄바꿈이 크게 바뀐다. 코드 포맷터로만 쓴다 |
| `resources/` | 데이터. 생성 스크립트 출력과 바이트 단위로 같아야 한다 (T1-19) |
| `packages/db/prisma/migrations/` | 기존 migration은 고치지 않는다 (작업 지침 §9) |
| `pnpm-lock.yaml`, `dist/`, `coverage/`, `test-results/`, `playwright-report/`, 생성된 Prisma 클라이언트 | 생성물 |

### 하지 않는 것

- 파일 포맷, `pnpm check`에 검사 추가: T1-22.
- ESLint와 묶기(`eslint-config-prettier`): 지금 ESLint 설정에 모양 규칙이 없어 충돌하지 않는다.
- 편집기 설정, 커밋 훅.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 설치 | `pnpm prettier --version` → `3.9.9` |
| 무시 목록 | `pnpm prettier --check` 대상 목록에 위 표의 파일이 없다 (`--list-different`로 확인) |
| 아무것도 안 바꿈 | 작업 뒤 `git status`에 설정·스크립트·문서 외 변경 없음 |

### 채울 문서

구현하면서 함께 채운다. 리뷰어는 문서도 확인한다.

- `AGENTS.md §8 (검증 명령에 format·format:check)`

## 구현 기록 (Claude)

- 바꾼 것 (2026-10-20):
  - 루트 `package.json`: `devDependencies.prettier` = `3.9.9`(정확히 고정), 스크립트 `format`·`format:check`. `pnpm-lock.yaml` 갱신.
  - `.prettierrc.json`(`singleQuote`, `printWidth: 120`), `.prettierignore`(`*.md`, `resources/`, migration, 잠금 파일. 생성물은 `.gitignore`로 이미 빠짐).
  - `AGENTS.md §8`: 두 명령 추가.
- 계획과 달라진 점과 이유:
  - 3.9.10이 최신이지만 배포된 지 2주가 안 돼(2026-10-10) 3.9.9(2026-09-23)로 고정했다.
  - 생성물은 `.prettierignore`에 다시 적지 않았다. 프리티어 3이 `.gitignore`도 읽기 때문이다.
- 검증 결과:
  - `pnpm exec prettier --version` → `3.9.9`.
  - `pnpm exec prettier --list-different .` → 대상 **54개**(코드·설정만). `*.md`·`resources/`·migration·`pnpm-lock.yaml`·`generated/`·`dist/`는 0개.
  - 아무 파일도 포맷하지 않았다: `apps/server`, `packages/shared`, `tools/next-task.mjs` 등 대상 파일의 `git status`가 비어 있다.
  - `pnpm test` 103개 통과, `tools`·`apps/web`·`e2e` lint 통과.
  - 참고: 루트 `package.json`의 `engine:run` 스크립트 한 줄은 Codex의 T1-06 작업이며 이 작업이 아니다.

## 리뷰 (Codex)

- 결과: **통과** (2026-10-20). 설정·스크립트 범위의 T1-21을 `완료`로 바꾼다. AC-M1-01은 ✅ 유지, 증거를 보완한다. 전체 포맷·check 연결은 T1-22에 남긴다.
- 확인한 것:
  - `package.json`과 `pnpm-lock.yaml` 모두 prettier `3.9.9` 정확히 고정. `pnpm exec prettier --version`도 `3.9.9`다. `pnpm install --frozen-lockfile --ignore-scripts`가 lockfile 변경 없이 통과했다.
  - `.prettierrc.json`은 `singleQuote: true`, `printWidth: 120`, 다른 옵션은 기본값이다. `format`은 `prettier --write .`, `format:check`는 `prettier --check .`이며 `check`에는 아직 넣지 않았다.
  - `AGENTS.md §8`의 두 명령과 T1-22 이후 검사 연결 안내가 채워져 있다.
  - `.gitignore`·`.prettierignore`를 사용한 Prettier `getFileInfo`로 Markdown·리소스·migration·lockfile·Prisma 생성물·dist·coverage·Playwright 산출물이 모두 ignored=true임을 확인했다. 일반 `AuthForm.tsx`는 ignored=false다. 이미 포맷된 파일이 목록에서 빠지는 `--list-different`의 한계도 보완했다.
  - `pnpm exec prettier --list-different .` 및 `pnpm format:check`는 **54개 파일의 포맷 차이로 exit 1**이다. 설정만 추가하고 포맷하지 않는 계획에 맞는 결과이며 통과를 막지 않는다. 리뷰 중 `pnpm format`은 실행하지 않았다.
  - 설정 외 대량 포맷 변경은 없다. 기존 서버·shared·`tools/next-task.mjs`에 변경이 없고, 같은 작업 트리의 엔진·웹 변경은 각각 T1-06·T1-14 범위다.
  - `pnpm check`: Prisma 생성·전체 lint·전체 타입 검사·단위 **14개 파일/103개 통과**. `git diff --check` 통과.
- 고칠 것: 없음. T1-22는 계획대로 T1-06 수정·리뷰 및 커밋 이후 별도 작업으로 진행한다.
