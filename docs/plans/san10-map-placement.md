# SAN10 지도 거점 레벨 배치

> 관련 AC: AC-INT-03·AC-INT-10 · 사용자 결정 D-041·D-044 · 상태: 159표식 배치 채택, 1400×1000 확장

## 목표와 범위

제공된 SAN10MAP.png에서 확인한 119거점·153연결을 교체용 데이터로 보관하고 현재 지도의 레벨을 대응시킨다. 완료 조건은 원본 좌표·거점 종류·레벨 근거·연결 판단이 모두 저장되고 각 거점의 배치를 확인할 수 있는 것이다. 운영 지도 교체와 AC 완료 판정은 이번 배치 범위에 넣지 않는다.

## 현재 체계

현재 자원 `resources/map/integration.json`은 도시 53·관문 8·항구 시설 6·전장 표식 13곳이다. 도시는 레벨 1~8을 허용하며 실제 배치는 8레벨 7곳, 7레벨 7곳, 6레벨 14곳, 5레벨 19곳, 2레벨 6곳이다. 1·3·4레벨 도시는 없다. 관문은 별도 종류로 방어·성벽만 가지며 엔진 앵커 변환 때 내부 레벨 0을 쓴다. 항구·전장 표식에는 레벨이 없고 이동의 목표도 아니다.

이전 자원 `resources/map/che.json`은 1~8레벨 94거점을 한 종류로 다뤘다. 대도시가 8, 주요 도시가 7·6·5, 이민족 거점이 4, 관문이 3, 길목이 주로 2, 적벽·파양·탐라·유구가 1이었다. 이 구분은 배치에서 읽은 분포이며 레벨만으로 경제·방어 수치가 자동 계산된다는 뜻은 아니다. 도시별 초기값과 최대값은 별도 필드다.

## 첫 배치

데이터는 `resources/map-drafts/san10/placement.json`과 `sites.csv`, `connections.csv`에 둔다. 실행용 v3 자원으로 등록하지 않은 초안 형식이다. 원본 이미지와 재배포용 바탕 그림은 포함하지 않는다.

출처와 기존 자원 라이선스의 연결은 같은 폴더의 `NOTICE.md`에 둔다.

성 50곳은 현재 통합판의 같은 도시와 모두 대응된다. 기존 레벨과 대응 ID를 유지한다. 관문 8곳도 같은 관문과 대응되며 내부 레벨 0을 유지한다. 호로관·함곡관·면죽관·백랑산의 표기 차이는 명시적 대응표로 기록했다.

사용자가 공터 61곳도 점령·이동 가능한 거점으로 선택했다. 초안 역할은 OUTPOST이며 화면의 원본 종류 OPEN과 구분한다. 현재 실행 형식에 OUTPOST 종류가 있다는 뜻은 아니다. 첫 레벨 제안은 적벽 1, 나머지 60곳 2다. 이전 che의 1~2레벨 거점과 일치하면 그 레벨을 가져오고 새 공터는 2로 둔다. 초는 현재 도시 레벨 5에서 공터 레벨 2로 낮추는 제안이며 광릉은 2를 유지한다. 경제·방어 값을 레벨로 추정해 채우지 않는다.

## 연결과 판단 기록

그림 판독 151구간과 사용자 확정 2구간을 활성 연결로 보관한다. 119거점 모두 같은 연결 성분에 속한다. 153구간은 방향을 확정한 이동표가 아니므로 무방향 관계로 저장한다. LAND·BRIDGE·FERRY·WATER는 조사 분류이며 실행 형식으로 바꿀 때 도하·수로의 규칙을 대조해야 한다. WATER만으로 자유 항행·항구 시설·추가 직항을 만들지 않는다.

사용자가 오장원–한중과 하동–함곡관을 연결로 확정했다. 상용–영안과 경구–부춘은 직접 연결 제외 기록으로 별도 보관한다. 보류 구간은 없다. 나루 W01~W21은 연결의 근거 ID이며 전략 거점으로 추가하지 않는다.

## 실제 교체에 필요한 변경

현재 v3 형식은 연결 양끝을 도시·관문으로만 허용한다. 공터 전략 거점의 종류와 명령·내정·점령·건국·보급·통일 판정 적용을 먼저 정리해야 한다. 기존 FIELD를 그대로 넣으면 사용자가 선택한 61곳이 이동 목표에서 사라진다.

현재 지도 화면은 Natural Earth의 해시·범위·투영을 고정 검사한다. 원본 그림의 좌표를 기존 GIS 좌표로 가장해서 넣을 수 없다. 새 바탕 지도와 좌표 계약을 함께 바꿔야 한다.

초·광릉은 도시에서 공터 거점으로 바뀌고 홍농은 새 지도에 없다. 기존 191년 시나리오는 홍농을 참조하므로 국가 영토·장수 시작 위치를 명시적으로 대응시켜야 한다. 기존 파양 표식과 6항구 시설도 원본의 이름 있는 거점으로 가져오지 않는다. 배치 파일의 현 지도 대응 ID는 자료 연결용이며 새 운영 ID를 확정한 것이 아니다.

## 검증과 리뷰

데이터 검증은 119개의 유일한 ID·원본 좌표 범위·도시 50곳의 기존 레벨 일치·관문 8곳의 대응·공터 61곳의 1~2레벨·중복/자기 연결 없음·153활성 연결과 2제외 관계·전체 연결성을 대조한다. 검증 결과는 배치 데이터의 일관성 근거이며 게임 실행 검증이 아니다.

2026-10-29 위 데이터 검증과 CSV 행 수·기준 자원 해시·표시 데이터 일치 검사를 통과했다. 미리보기에서 적벽 1레벨과 오장원 2레벨 선택, 오장원–한중 연결 표시를 확인했다.

최종 `pnpm check`가 통과했다. Prisma 생성·lint·문구·포맷·6패키지 타입 검사와 290파일의 단위 시험 5296개가 모두 통과했다. 처음 실행에서 새 고지를 공통 NOTICE에 추가해 SQL 원문 대조 시험이 실패했다. 새 폴더의 NOTICE로 옮기고 공통 고지를 복원한 뒤 관련 59개와 전체 검사를 다시 통과했다.

운영 형식·엔진·DB·화면을 수정하지 않았다. 실제 교체의 통합·E2E 시험과 구현하지 않은 담당의 리뷰는 후속이며 기존 AC 상태는 유지한다.

## 지역 대표 거점 추가 (D-042)

2026-10-29 사용자 요청으로 강·오환·남만·산월·선비·흉노·저의 7곳을 더해 전체 배치가 126거점이 된다. 역할 TRIBAL은 지역 대표 거점이라는 초안 표기다. 기존 119곳의 위치와 153연결, 제외한 2구간은 그대로 보관한다.

기존 che의 강63·오환68·남만66·산월67·흉노65·저64는 레벨 4다. 선비는 같은 등급으로 제안하며 기존 대응 ID가 없다. 거점별 초기 경제·방어·소유 국가는 추가하지 않는다. 남만·산월 같은 광역 명칭을 단일한 역사 국가로 해석하지 않는다.

## 한반도·왜 참고 자료

사용자가 추가한 두 역사 지도는 나라·집단 분포와 성읍 위치를 읽는 자료이며 도로 연결의 증거가 아니다. 첫 게임 지도는 도로 모양을 참고한다. 앞선 대화의 양평–서안평–북부 성곽–낙랑 한 줄 제안은 고구려 중심지를 필수 경유지로 만들 수 있다. 이후 연결 초안에서는 서안평에서 낙랑 방면과 졸본·국내성 방면의 분기를 비교한다. 두 갈래 모두 실제 고대 도로가 확인됐다는 뜻은 아니다.

부여·읍루·마한·진한·변한은 지역·집단 이름과 성읍을 구분한다. 졸본·국내성·부조·화려·불이·백제국·목지국·건마국·사로국·구야국을 위치 후보로 검토한다. 현재 191년 시나리오에 넣을 소유권과 수도를 지도 경계선만 보고 정하지 않는다. 대방군은 건안 연간에 설치된 행정 단위이므로 191년부터 같은 군 체제를 적용하지 않는다([우리역사넷](https://contents.history.go.kr/front/tg/view.do?ganada=&levelId=tg_001_0660&pageUnit=10&treeId=0209)).

왜의 이름 후보와 현대 위치 대응, 연구 출처는 `resources/map-drafts/san10/east-asia-reference.json`에 보관한다. 처음에는 위치설을 채택하지 않고 후보를 모았다. 이후 사용자 요청에 따라 아래 D-043의 선정안을 저장했다. 왜인전의 주된 기록 시기와 191년 시작 시점은 구분한다.

혼슈 서부의 지역 대표 거점은 이즈모·기비를 선정했다. 각각 시마네권·오카야마권의 야요이 유적 연구 자료를 참고한다. 시코쿠는 사용자의 마지막 선택에 따라 이요·사누키 두 곳으로 나눈다. 현재 지도 좌표 배치는 아래 추가 배치 파일에 별도로 저장한다. 그림의 이름 없는 점과 일대일 대응하지 않는다.

추가 뒤 검증에서 126곳의 ID·좌표·레벨, 원본 153연결의 보존, 14개 제안의 중복·자기 연결 없음, 제안 포함 전체 연결성, CSV 126행·169관계, 참고 자료 출처 ID와 표시 데이터 일치를 확인했다. 미리보기에서 선비 4레벨과 구원·오환의 제안 연결을 확인했다. `pnpm check` 재실행도 290파일·5296시험이 모두 통과했다. 이 결과는 운영 반영이나 독립 인수 완료를 뜻하지 않는다.

## 전부 합친 지도 배치

사용자가 현재 지도에 모두 합친 구성을 요청했다. `merged-placement.json`과 `merged-sites.csv`, `merged-connections.csv`에 합친 결과를 저장한다. 재생성 명령은 `python tools/map-data/build-san10-merged.py`다. 기존 자료의 좌표·연결과 출처 파일은 유지한다.

SAN10 119곳, 주변 집단 7곳, 한반도·왜 추가 25곳을 합치면 151곳이다. 낙랑은 두 번 넣지 않는다. 현재 지도와 겹치는 72곳도 한 번만 남기며 도시·관문·전장 ID의 대응표를 보존한다. 현재 지도에만 있는 홍농·파양과 항구 6곳을 더해 전체 159표식이 된다. 전략 거점은 152곳이고 시설·표식은 7곳이다. 현재 80표식의 좌표는 모두 그대로 쓴다.

현재 좌표가 없던 중국 공터 46곳은 대표 권역에 게임 배치점을 제안했다. 자동으로 원본 그림을 늘이거나 옛 지도 좌표를 위경도로 가장하지 않는다. 사룡은 웨이산권, 화용은 첸장 남서부·룽완권, 남안은 남안군·웨이수이 상류권, 한가는 루산권을 택했다. 신규 위치는 고대 성터의 측량값이 아니며 정밀한 지형 검토가 남는다. 화용의 권역은 [첸장시 연혁](https://www.hbqj.gov.cn/zjqj/qjgk/lsyg/), 남안은 [톈수이시 지방사 자료](https://www.tianshui.gov.cn/dsb/info/1883/18872.htm), 한가는 [루산 역사문화 보호계획](https://www.sc.gov.cn/10462/c108551/2022/2/15/2e9dd7f9fb0c40d590d1e1c407cc59c9/files/ca99c291f664426590309452e32e0c12.pdf)을 참고했다.

연결은 판독·사용자 확정 153관계와 기존 홍농의 두 인접 관계를 합친 155관계를 보존한다. 주변 집단 14관계와 한반도·왜 31관계는 별도의 제안 45관계다. 이 제안까지 포함하면 전략 거점 152곳이 하나의 연결 성분이 된다. 제안은 실행 연결로 확정하지 않는다. 항구의 소속 관계 6개와 파양의 수로 경유 관계 2개는 전략 이동 연결과 구분한다.

기존 도시 직통로를 모두 더하면 새 공터를 건너뛰는 지름길이 생긴다. 기존 경로 원문은 `legacyRouteReference`에 보존하되 홍농 두 관계 외에는 새 확정 연결로 중복 활성화하지 않는다. 양평–낙랑의 원본 연결은 유지하며 서안평 분기는 제안으로 함께 표시한다. 기존 제외 판단인 상용–영안과 경구–부춘은 유지한다. 선은 관계를 표시하며 실제 도로·해안 항로의 모양이 아니다.

도시 51곳·관문 8곳·공터 61곳·집단 7곳과 새 한반도·왜 25곳이 전략 거점이다. 새 25곳의 레벨·경제·소유권은 아직 정하지 않는다. 운영 자원·DB·AC 완료 증거와 화면의 고정 계약은 바꾸지 않은 전체 배치 초안이다. 실제 교체 전에 전략 거점 종류·시나리오 대응·확장 범위·규칙과 새 인수 근거를 별도로 반영해야 한다.

2026-10-29 재생성 도구와 별도 데이터 대조에서 159개의 유일한 ID·이름, 기존 80좌표 및 앞선 33좌표의 보존, 원본 153연결과 126곳의 레벨 보존, 제외 관계 부재, 제안 포함 전략 거점 152곳의 연결성, CSV 159행·200관계와 입력 해시를 확인했다. 중국 공터 46곳의 반올림 좌표는 파생 육지의 해안 허용 오차 0.03도 안에 놓인다. 표시 데이터가 저장 데이터와 일치한다. 736px·375px에서 전체 배치와 거점 선택·확대를 확인했고 오장원–한중의 확정 연결, 서안평의 양평·낙랑·졸본 제안을 구분해 읽었다. `pnpm check`는 290파일·5296시험이 모두 통과했다. 운영 지도 교체의 독립 인수는 후속이다.

## 배치 채택과 지도 확대 (D-044)

사용자가 위 통합안을 채택하고 지도 확대를 요청했다. 첫 1200×800 판은 일본 동부와 만주 북부의 육지가 잘렸다. 일본과 만주까지 보이도록 한 추가 요청에 따라 1400×1000으로 넓힌다. 완료 조건은 채택한 정본을 저장하고 159곳이 모두 새 범위 안에 놓이며 지리적 위치·상대 거리·연결을 보존하는 것이다. 동쪽은 일본 열도 너머, 북쪽은 만주 북부까지 여유를 둔다.

정본은 `adopted-placement.json`과 `adopted-sites.csv`, `adopted-basemap.geojson`이다. 상태 ADOPTED_LAYOUT_PENDING_RUNTIME은 사용자가 채택한 배치와 실행 반영을 구분한다. 이전 `merged-placement.json`은 비교 자료로 보존한다. 재생성은 `python tools/map-data/build-san10-expanded.py --land-source <Natural Earth v5.1.2 육지 원본 경로>`로 한다. 원본 경로를 생략하면 고정 URL에서 로컬 캐시에 내려받고 해시를 검사한다.

동경 94도와 기존 축척을 유지하고 북쪽으로 260좌표 단위를 더한다. 모든 점에 x+0·y+260만 적용하므로 상대 거리는 변하지 않는다. 기존 운영 좌표 자체를 바꾸는 작업은 아니다. 새 범위는 동경 94~148도·북위 15.457~54.029도이며 159곳 모두 범위 안에 든다. 예를 들어 낙양은 478, 503이고 이요는 1005, 523, 사누키는 1038, 510, 야마타이는 1085, 505이다.

155개의 기존·판독 관계와 45개의 게임 연결 제안, 8개의 시설 소속·경유 관계를 보존한다. 신규 지명이나 연결을 더하지 않는다. 한반도·왜 새 25곳의 미정 수치를 확대 요청만으로 채우지 않는다. 기존 AC 완료 상태도 갱신하지 않는다.

현재 실행 형식은 `packages/rules/src/world/map/operational.ts`, 공개 지리는 `packages/shared/src/publicGeography.ts`, 운영 지도 화면은 `apps/web/src/main/OperationalWorldMap.tsx`에서 1000×700을 고정한다. 채택 배치의 운영 전환 때 세 계약과 GIS 해시·지형, 전략 거점 종류·초기값·시나리오 대응을 함께 반영해야 한다. 이번에는 채택 배치와 확장 미리보기를 저장하며 기존 월드나 운영 DB를 변환하지 않는다.

2026-10-29 검증에서 159곳의 ID·레벨, 전체 쌍의 상대 좌표, 위경도 환산값과 모든 관계가 이전 통합안과 일치했다. 새 범위 밖 거점은 0곳이며 CSV 159행과 입력·지형 해시, 미리보기의 저장 데이터 일치를 확인했다. 1024px·375px 화면에서 전체 지도와 거점 선택·확대를 확인했다. `pnpm check`는 문구·형식·타입 검사와 290파일·5296시험을 모두 통과했다. 배치 검증 결과이며 운영 전환의 독립 리뷰와 인수는 남아 있다.

일본·만주 추가 확대에서는 북위 54.029도·동경 148도까지 육지 원본을 다시 잘랐다. 홋카이도·혼슈 동부·만주 북부의 육지 포함, 159곳의 위경도·전체 쌍 상대 좌표·레벨·관계 보존과 입력·파생 해시를 확인했다. 320·375·736·1024·1280px의 전체 맞춤 계산에서 모든 표식이 범위 안에 든다. 화면에서도 홋카이도와 혼슈 동부, 읍루 북쪽의 육지 및 확대 후 전체 맞춤 복원을 확인했다. 거점 선택은 전체 배율을 유지한다. 확대 후 `pnpm check`도 문구·형식·타입 검사와 290파일·5296시험을 모두 통과했다.
