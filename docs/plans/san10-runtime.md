# SAN10 지도와 두 시나리오 적용

> 관련 AC: AC-INT-02·03·04·10·12, AC-M2-03 · 사용자 결정 D-045 · 상태: 원 지도 구현·검증 기록 보존, 도시 자원 결합 검증 전

2026-10-30 사용자가 제안 연결 전부를 도로로 합치고 역사·공백지 시나리오에 같은 지도를 적용하도록 요청했다. 159표식 중 152곳을 전략 거점으로, 항구 6곳과 파양을 시설·표식으로 유지한다. 기존 155관계와 제안 45관계를 합친 200개의 양방향 도로를 활성화한다. 바다를 건너는 제안도 게임상 도로이며 역사 도로의 실재를 주장하지 않는다. 제외한 두 직접 연결은 복구하지 않는다.

실행 지도는 새 불변 자원 `san10` 1판으로 만든다. 기존 `integration` 1판과 진행 중인 월드의 사본은 보존한다. 역사 시나리오는 현재 정식 191년 21국·491장수 편성을 새 지도에 대응한 `san10-191`이며 공백지는 같은 인물·능력치의 소속과 국가·외교를 비운 180년 `san10-empty`다. 다른 연도의 원작 시나리오 83종 변환은 이 두 모드 적용에 포함하지 않는다.

공터·집단과 신규 지역 거점은 기존 CITY 전략 앵커를 사용한다. 도시 레벨과 관문 0, 공터의 1~2레벨, 집단의 4레벨은 채택 배치를 따른다. 미정이던 한반도·왜 25곳은 새 게임 편성의 낮은 등급인 2레벨과 공터와 같은 경제 초깃값을 사용한다. 기존 도시·관문의 수치와 안정 ID를 유지하며 신규 앵커 ID는 조사 ID에 따른 별도 숫자 범위로 정한다.

실행 형식과 공개 지리는 지도별 캔버스를 검증한다. 화면은 등록한 GIS 해시와 범위만 받고 새 지도에서도 모든 표식을 포함한 초기 범위를 계산한다. 기존 지도의 GIS·밑그림과 재생 고정물은 보존한다. 기본 프리셋은 새 역사판을 사용하고 공백지 프리셋을 추가한다. 파일 로더와 DB 게시 자원 로더에서 두 시나리오를 모두 선택할 수 있게 한다.

완료 조건은 200도로의 활성화와 152전략 거점의 연결성, 두 모드의 같은 좌표·도로망, 역사 소속 보존·공백지 소속 없음, 동일 시드 결정성, 실제 PostgreSQL 생성·저장·재적재와 화면의 전체 범위 표시다. `pnpm check`, 변경에 맞는 통합·브라우저 검증을 기록한다. 기존 AC 완료 증거를 새 판의 독립 인수로 바꾸지 않으며 독립 리뷰 전에는 새 판의 AC 완료를 주장하지 않는다.

## 생성과 적용

`python tools/map-data/build-san10-basemap.py`와 해당 JSON의 Prettier 정리 후 `pnpm exec tsx tools/map-data/build-san10-resources.ts`로 지도·두 시나리오·게시 명세와 GIS 해시 상수를 재생성한다. 자료 출처는 [SAN10 고지](../../resources/map-drafts/san10/NOTICE.md)를 따른다.

기본 초기화 뒤 `pnpm db:init-san10`으로 새 불변 판을 게시한다. 이미 같은 내용이 있으면 재사용하고 같은 키의 다른 내용은 거부한다. 게시 자원으로 역사판을 만들 때는 `pnpm world:create --published --preset regular --seed <시드> --end-year 300 --name <이름>`을 쓰고 공백지판은 `--preset empty`를 쓴다. 도시 금·쌀·수비병이 있는 정식 판을 CLI로 만들 때는 `--rule-features campaign-assignment-v2,campaign-v1,city-resources-v1,five-stats,operational-map,personnel,policy,stratagem-basic,treaty`를 함께 고정한다. 기존 판이나 명시한 다른 규칙 선택을 새 지도의 기본값으로 바꾸지 않는다. 파일 합성을 쓰려면 `--published`를 생략한다. SAN10의 기본 능력치 규칙과 초상 대응은 5능력치·191년 대응표로 선택되며 명시한 옵션은 그대로 우선한다.

현재 게시 판의 월드 생성 로더는 1판을 고정하므로 새 이름의 1판을 사용한다. 기존 `integration/1`, 원작 `1030/1`과 이미 생성된 월드의 지도 사본은 바꾸지 않는다. 운영 DB 재초기화와 진행 중 월드 변환은 실행하지 않는다. 원 지도 작업의 미커밋 소스는 별도로 보존하고 통합 브랜치의 소스 보관 커밋과 실제 보호 병합을 구분한다.

집중 브라우저 검증은 공개 빌드 뒤 `pnpm e2e:san10` 또는 같은 전용 설정을 부르는 `pnpm test:san10`이다. 기존 테스트 DB 주소를 기반으로 자기 PostgreSQL DB와 API·공개 dist 출처를 만들고 끝나면 자기 DB와 프로세스만 정리한다. 두 모드를 DB 게시 로더에서 합성해 저장·재적재하고 실제 장수 생성 입력을 엔진에서 실행한 뒤 HTTP·화면·375px에서 표식·도로·초기 범위를 검증한다.

## 원 지도 작업의 로컬 검증 기록

`pnpm check`가 종료 코드 0으로 통과했다. 생성·ESLint·엄격 문구 검사·Prettier·전체 타입 검사와 Vitest 291파일 5,299건이 성공했다. 마지막 문서 변경 뒤에도 해당 문서의 Prettier와 엄격 문구 검사를 다시 통과했다.

2026-10-30 별도 PostgreSQL 18.6과 실제 API·엔진·Chromium에서 역사·공백지 2건이 통과했다. 두 모드 모두 152전략 거점·159표식·200도로를 저장하고 재적재했으며 같은 시드의 초기 해시가 일치했다. 장수 생성 입력 실행, 공개 응답의 내부 수치 제외, 375px 전체 범위와 야마타이국 선택, 기존 월드 해시 보존과 게시 재실행도 확인했다. 자기 테스트 DB·API·Vite 정리 기록을 확인한 뒤 별도 PostgreSQL을 종료했다.

결과 화면은 `test-results/san10-191-map-375.png`와 `test-results/san10-empty-map-375.png`다. 접속 가능한 운영 DB 설정이 없으므로 운영 DB 게시·기존 월드 변경은 실행하지 않았다. 새 판의 독립 리뷰와 보호 병합 전이며 AC 완료 상태는 올리지 않는다.

## 도시 자원·공개 후보 결합

도시 자원 결정 D-040과 지도 작업의 번호가 겹쳐 원 지도 D-039~043을 D-041~045로 옮겼다. 본문과 사용자 선택은 보존했다. 새 공개 생성 후보는 역사와 공백지 모두 기존 아홉 기능에 city-resources-v1을 포함해 원생성에 고정한다. 도시 원장은 새 지도의 152전략 거점과 정확히 대응하며 금·쌀은0, 수비병은 빈 배열로 시작한다. 기존 개인·국고·도시 잔액을 복사하지 않는다.

전용 Chromium 두 사례는 기존 191년 판을 비교 대상으로 보존하고 새 게시 자원의 역사·공백지 생성과 저장·재적재를 검사한다. 각 모드에서 사람 생성 입력과30칸을 실제 엔진으로 처리하고491명 NPC를 줄이지 않은 한 달 정산과 저장 입력 재생을 대조한다. 공개 응답·159표식·200도로·375px 전체 범위와 새152도시 원장의 대응도 확인한다. 기존120초 사례 한도·worker1·retry0을 유지하고 기본 E2E에서 같은 파일을 중복 선택하지 않는다. 공개 빌드 뒤 CI의 전용 단계 한 곳에서 두 사례를 실행한다. 자기 DB·연결·프로세스의 최종 정리는 기존 legalFixture의 실패 보존과 OID 경계를 따른다.

이 절의 결합 검사는 아직 실행하지 않았다. 위 5,299건과 PostgreSQL·Chromium2건은 원본 d82becb 기반 지도 작업의 기록이며 현재 결합 후보의 독립 통과 증거가 아니다. 기존53도시·61거점의 재생과132개월 기수 자료도 새 지도 인수를 대신하지 않는다. 새 지도 기본 공개 후보의 정식 한 기수·두 월드 격리·중복·중단·백업 복원·동일 시드 재생과 독립 리뷰·보호 병합은 별도 최종 인수로 남는다.
