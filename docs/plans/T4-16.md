## 계획 (Claude)

### 목표

### 기술 계약 초안 (Codex 계획 기술 검토 전)

#### A. 조각 `nationIdentity`

```ts
// ext/nationIdentity/slice.ts
export type IdentityRight = 'rename' | 'flag';
export type NationIdentityState = Record<string, { rename?: true; flag?: true }>; // 국가 id 문자열 → 남은 변경권
export const NATION_IDENTITY_KEY = 'nationIdentity';
export const nationIdentitySlice: ExtSlice<NationIdentityState>;
export function hasRight(value: DeepReadonly<NationIdentityState> | undefined, nationId: number, right: IdentityRight): boolean;
```

- 값이 `true`인 칸만 둔다. 변경권을 쓰면 칸을 지우고 국가 항목이 비면 국가 key도 지운다. 원작의 1과 0을 칸 있음과 없음으로 옮긴다.
- `create`는 이 작업에서 `{}`다. 어떤 국가에도 변경권이 없다. T4-55가 U-04대로 초기 변경권을 주려면 이 `create`를 그 작업에서 바꾼다(같은 폴더, T4-55 계획).
- `validate`는 key가 양의 정수 문자열, 값 객체가 `rename`·`flag` 칸만 `true`로 갖는지 본다.

#### B. 이름 검사 `name.ts`

```ts
export const nationNameSchema: z.ZodType<string>; // 건국 name과 같은 규칙: trim, 1~30자
export function nationNameTaken(view: WorldView, name: string): boolean; // 모든 국가 이름과 비교, 자기 국가 포함
```

- 건국의 이름 규칙은 `personnel.ts:12` 안에 있고 내보내지 않는다. 건국 파일을 고치지 않으려고 같은 규칙을 이 파일에 둔다. 두 규칙이 어긋나지 않게 `name.test.ts`가 이름 표(빈 값, 공백만, 앞뒤 공백, 30자, 31자, 한자, 결합 문자)를 `commandRegistry.get('found')!.args`와 `nationNameSchema`에 함께 넣어 통과 여부가 같은지 본다.
- 중복은 다듬은 이름으로 모든 국가와 비교한다. 자기 국가의 지금 이름과 같으면 실패다. 원작 국호 변경도 자기 국가를 포함한다.

#### C. 명령

`defineCommand`는 국가 명령에 `ruler`를 강제하는데 T2-05가 그 함수를 권한 표 검사로 바꾼다(`support.ts:40`). 권한 표에 확장 key가 없으므로 `CommandDef`를 직접 만든다(`domestic/investment.ts`와 T4-05 계략과 같은 꼴). 실행은 `cloneWorld(view)` 뒤 바꾼 상태 하나의 `{ kind: 'world' }` 효과다.

| key | args |
| --- | ---- |
| `nation_rename` | `z.strictObject({ name: nationNameSchema })` |
| `nation_flag` | `z.strictObject({ color: z.string().regex(/^#[0-9a-fA-F]{6}$/) })` (NI2 (가)) |

`category`는 `nation`, `target`은 `nation`이다. `check` = `precheck` 순서:

| 순서 | 조건 | code | 문구 |
| ---- | ---- | ---- | ---- |
| 1 | 장수 없음 | `NO_ACTOR` | 장수가 없습니다. |
| 2 | 국가 없음 | `NOT_NATION` | 국가에 소속되어야 합니다. |
| 3 | 현재 도시가 자기 국가 도시 아님 | `NOT_OWN_CITY` | 자기 국가 도시에서만 가능합니다. |
| 4 | NI1 (가): officerLevel ≠ 12 | `NOT_RULER` | 군주만 실행할 수 있습니다. |
| 5 | 현재 도시 보급 끊김 | `NO_SUPPLY` | 보급이 끊긴 도시입니다. |
| 6 | 변경권 없음 | `BAD_STATE` | 더 바꿀 수 있는 국호가 없습니다. / 더 바꿀 수 있는 국기가 없습니다. |
| 7 | 국호: 같은 이름 국가 있음 | `BAD_STATE` | 같은 이름의 국가가 있습니다. |
| 7 | 국기: NI3 (나), 지금과 같은 색 | `BAD_STATE` | 지금과 같은 색입니다. |

- 1~3, 5의 문구는 `ownCity`(`support.ts:11-19`)와 같다. 원작 순서(자기 도시 → 수뇌 → 보급 → 변경권)를 따라 3과 5 사이에 직책을 둔다.
- 6은 조각이 없으면 변경권 없음이다. 그래서 확장을 켰더라도 T4-55 전에는 늘 6에서 실패한다.
- 원작은 같은 이름을 실행 때만 보지만 우리는 사전 검사에서도 본다. 실행 결과는 같고 예약 때 이유를 미리 보인다.
- 색 비교는 대소문자를 무시한다(`#ff0000`과 `#FF0000`은 같은 색).

효과(실행):

| 순서 | 바뀌는 것 |
| ---- | --------- |
| 1 | 국가 `name` = 다듬은 새 이름, 또는 `color` = 새 색(받은 그대로) |
| 2 | 조각에서 그 국가의 그 변경권 칸 삭제 |
| 3 | 실행 장수 경험 +5, 공헌 +5 (NI4) |

- 난수 없음.
- 기록: 국호는 로그와 국가 기록 `국호 변경: {옛 이름} → {새 이름}`, 국기는 로그와 국가 기록 `국기 변경: {옛 색} → {새 색}`. 문구는 새로 썼다.
