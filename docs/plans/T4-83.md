## 계획 (Claude)

### 목표

T4-82가 내보낸 che 5색 밑그림 하나만 입력으로 고전 게임 느낌의 도트 바탕 그림을 만든다. 크기는 2100×1500, 형식은 WebP다. 그림에는 도시 점, 도시 이름, 연결선, 글자가 없다. 그림은 이미지 저장소 `maps/<정규 키>/base.webp`에 두고 출처 표에 한 줄을 남긴다. 출처 줄에는 밑그림 해시, 생성 도구, 생성 일시가 있고 외부 그림을 넣지 않았다는 입력 목록이 있다.

AC-P2-28의 그림·출처 몫이다. 메인·공개 지도에 까는 것은 T4-84다. 이 작업이 끝나도 AC-P2-28을 완료로 세지 않는다.

### 범위

| 위치 | 파일 | 내용 |
| ---- | ---- | ---- |
| 본 저장소 | `tools/map-base/generate.ts` | 밑그림 확인 → 생성 → 도트 격자 맞추기 → 정렬 검사 → WebP 부호화 → 출처 줄 쓰기 |
| 본 저장소 | `tools/map-base/raster.ts` | 밑그림 PNG 풀기, 래스터 해시(T4-82 정의), 격자 줄이기·키우기, 정렬 검사 |
| 본 저장소 | `tools/map-base/*.test.ts` | 단위 시험. 네트워크와 생성 서비스를 부르지 않는다 |
| 본 저장소 | 루트 `package.json` | `pnpm map-base:generate` 스크립트 한 줄 |
| 이미지 저장소 | `maps/<정규 키>/base.webp` | 바탕 그림. 정규 키는 조율 결정 R4를 따른다(1판은 이름만 `che`, 2판부터 `che@2`). 지형이 든 che는 `maps/che@2/base.webp`다 |
| 이미지 저장소 | `maps/provenance.tsv` | 출처 표. 판마다 한 줄 |
| 이미지 저장소 | `README.md` | `maps/` 절 몇 줄 |
| 본 저장소 | `docs/image-assets.md` | 지도 바탕 그림 절 (아래 채울 문서) |

`tools/`는 공통 설정이라 필요한 쪽(이 작업은 Codex)이 고치고 반대쪽이 리뷰한다. 밑그림 PNG 자체는 어느 저장소에도 커밋하지 않는다. T4-82의 `tools/map-terrain/che.v2.json`에서 편집기로 늘 같은 래스터가 다시 나오고 출처 표에 해시가 있어서다. D-016에 따라 이미지 저장소에는 게임이 실제로 쓰는 파일과 그 표만 둔다.

### 하지 않는 것

- 외부 그림을 입력이나 참조로 쓰기. 아래 외부 그림 절.
- 도시 점·이름·연결선·글자를 그림에 넣기. 이것들은 화면이 그 위에 그린다(T4-84).
- 화면 코드 (T4-84). 이미지 기본 주소 고정값을 옮기는 일도 T4-84다.
- 관리자 콘솔에서 게시할 때 그림을 자동으로 만드는 흐름. 이 작업은 운영자가 한 번 돌리는 도구다.
- che 말고 다른 지도의 그림.
- 생성 결과를 사람이 손으로 덧칠하기. 덧칠하면 입력과 과정이 출처 표와 맞지 않는다. 고치려면 다시 생성한다.

### 외부 그림 (D-028, map-editor.md §4)

와룡전 리메이크(`phixteam1/GRZ` v1.1)의 그림은 이용 허락이 없고 원작 그림을 확대한 것으로 보인다. 사용자가 제작자에게 서면 허락을 요청 중이다. 허락이 와도 결정 기록을 고치기 전에는 아래 규칙이 그대로다.

- 해도 되는 것: 화풍과 색 구성을 정할 때 사람이 보고 참고하기.
- 하면 안 되는 것: 따라 그리기, 생성 서비스의 입력 그림·참조 이미지·스타일 이미지로 넣기, 프롬프트에 그 그림을 묘사하거나 작품 이름을 넣기, 지형 배치 옮기기, 이 저장소와 이미지 저장소·이미지 서버에 올리기.
- 생성 호출에 넘기는 그림은 T4-82 밑그림 하나뿐이다(방식 A). 방식 B·C는 그림을 넘기지 않는다. 스크립트가 호출 직전에 넘기는 파일 목록을 출처 줄의 `inputs` 칸에 그대로 쓴다. 목록에 밑그림 말고 다른 파일이 있으면 호출하지 않고 멈춘다.
- 프롬프트는 우리가 쓴 글만 쓴다. 특정 게임·작가·작품 이름을 넣지 않는다. 고전 게임 느낌은 화소 크기, 색 수, 외곽선 같은 기법으로 적는다.

### 생성 방식 (사용자 결정 1)

세 방식 가운데 하나를 사용자가 고른다. 도구와 비용도 그 결정에 딸린다. 어느 쪽이든 도트 격자, 정렬 검사, 출처 표는 같다.

| 방식 | 하는 일 | 정렬 | 비용 | 위험 |
| ---- | ------- | ---- | ---- | ---- |
| A. 밑그림으로 그림 바꾸기 | 이미지 생성 서비스의 그림 편집 기능에 밑그림 하나와 글 프롬프트를 넣어 지도 전체를 그린다 | 서비스가 해안·강을 옮길 수 있다. 정렬 검사에 떨어지면 다시 생성한다 | 새 유료 호출. 시도 횟수만큼 든다 | 서비스가 지원하는 크기가 7:5가 아니면 여백을 붙이거나 잘라야 한다. 글자나 도시 같은 무늬가 생길 수 있다 |
| B. 층별 무늬 생성 후 밑그림으로 합성 | 다섯 층(바다·땅·강·산·호수)마다 이어 붙일 수 있는 작은 도트 무늬를 글 프롬프트만으로 생성하고 스크립트가 밑그림 칸마다 그 층의 무늬를 깐다. 해안선과 강가의 외곽선은 규칙으로 칠한다 | 밑그림과 칸 단위로 같다 | 새 유료 호출이 있으나 무늬 5~10장이라 A보다 적다 | 무늬가 반복되어 단조로울 수 있다. 외곽선 규칙의 품질이 결과를 좌우한다 |
| C. 생성 서비스 없이 규칙으로 | B의 합성을 그대로 쓰고 무늬도 스크립트가 시드 난수로 만든다 | 밑그림과 칸 단위로 같다 | 새 비용 없음 | D-028 소유자 답의 이미지 생성으로 만든다와 맞는지 사용자가 판단해야 한다 |

계획은 B를 권한다. 도시가 바다에 빠지지 않는 것이 이 그림의 첫 조건인데 B는 정렬을 구조로 보장한다. 타일을 깔아 그린 고전 게임 지도와 만드는 방식이 같아 화풍과도 맞는다. 다만 도구·비용을 정하는 것은 사용자다. 생성 서비스를 쓰는 A·B는 착수 전에 그 서비스의 이용 약관에서 생성물을 공개 서비스에 쓸 수 있는지 확인한다([이미지 자산](../image-assets.md) §3). 확인한 날과 약관 주소를 출처 줄에 적는다.

### 도트 격자

- 그림은 논리 화소 격자에서 만들고 마지막에 최근접 확대로 2100×1500을 만든다. 출발값은 논리 화소 하나가 이미지 6×6 화소, 지도 좌표 2×2다(격자 350×250). 구현 때 시험 출력을 보고 4·6·10 가운데 정하고 출처 줄의 `pixel` 칸에 적는다.
- 밑그림(2100×1500)을 격자로 줄일 때는 6×6 칸 안에서 가장 많은 층 번호를 그 칸의 층으로 본다. 동점이면 강 > 호수 > 산 > 땅 > 바다 순서로 고른다. 가는 강이 끊기지 않게 하려는 순서다.
- 색 수는 그림 전체 32색 이하를 출발값으로 둔다. 방식 A는 생성 결과를 이 색 수로 줄인다. 부호화는 무손실 WebP다. 손실 WebP는 도트 경계를 번지게 한다.
- 크기 목표는 1MB 이하다. 넘으면 그 크기를 구현 기록에 적고 T4-84와 로그인 화면 부담을 함께 본다. 크기를 맞추려고 격자나 색 수를 몰래 바꾸지 않는다.

### 정렬 검사

생성한 그림이 밑그림과 같은 지형인지 기계로 본다. 방식 B·C도 같은 검사를 지난다(외곽선 규칙의 실수를 잡는다).

1. 그림을 다시 격자로 줄인 뒤 화소 색을 다섯 층으로 되돌린다. A는 색 군집을 밑그림 층과 가장 많이 겹치는 층에 붙인다. B·C는 합성할 때 쓴 층 번호를 그대로 쓴다.
2. 논리 칸 일치율이 97% 이상이어야 한다. 층별 일치율도 같이 적는다.
3. che 모든 도시 중심의 논리 칸과 그 둘레 한 칸(3×3)이 땅이나 산이어야 한다. 하나라도 바다·호수면 실패다. 강은 도시 둘레를 지날 수 있어 실패로 치지 않는다.
4. 실패하면 그 그림은 버리고 이유를 남긴다. A는 다시 생성하고 시도 횟수를 센다. 다섯 번 넘게 실패하면 멈추고 사용자에게 알린다.

97%와 다섯 번은 출발값이다. B·C는 구조상 100%에 가까워야 하므로 97% 근처면 외곽선 규칙을 의심한다.

### 출처 표

이미지 저장소 `maps/provenance.tsv`에 그림 하나마다 한 줄을 둔다. 칸은 아래와 같다. 비밀 키, 요청 머리, 계정 정보는 적지 않는다.

| 칸 | 내용 |
| -- | ---- |
| `mapKey` | 정규 키(R4). 1판은 이름만(`che`), 2판부터 `<이름>@<판 번호>`(`che@2`). `che@1` 꼴은 쓰지 않는다 |
| `path` | `maps/<정규 키>/base.webp` |
| `sha256`, `bytes`, `width`, `height` | 결과 파일 |
| `sketchRasterSha256`, `sketchPngSha256` | T4-82 `tools/map-terrain/che.sources.json`의 두 해시. 생성 전에 다시 계산해 같았던 값 |
| `terrainCommit` | T4-82 `che.v2.json`이 들어간 본 저장소 커밋 SHA |
| `method` | A, B, C |
| `generator` | 서비스와 모델 이름·판, 또는 C의 스크립트 커밋 SHA |
| `prompts` | 프롬프트 전문. 길면 같은 폴더 `maps/<정규 키>/prompts.txt`를 가리킨다 |
| `params` | 크기, 시드(있으면), 품질 설정, `pixel`, 색 수 |
| `inputs` | 생성 호출에 넘긴 파일 목록과 각 해시. B·C는 `none` |
| `attempts` | 시도 횟수와 고른 시도 번호 |
| `alignment` | 전체 일치율과 층별 일치율, 도시 검사 결과 |
| `postprocess` | 격자 맞추기, 색 줄이기, WebP 부호화기 이름·판, 무손실 여부 |
| `generatedAt` | 생성 일시, UTC ISO 8601 |
| `operator` | 돌린 사람 또는 세션 |
| `tos` | 약관 확인 날짜와 주소. C는 `none` |

버린 시도의 그림은 커밋하지 않는다. 시도 횟수와 실패 이유만 구현 기록에 남긴다.

### 접근

1. 사용자 결정 1·2와 T4-78의 판 번호(R17)가 정해졌는지 본다. 풀리지 않았으면 생성 서비스를 부르지 않고 `raster.ts`와 시험만 먼저 만든다.
2. `raster.ts`: PNG 풀기(색 형식 3, 팔레트 5칸만 받음), T4-82 래스터 해시, 격자 줄이기(최다 층과 동점 순서), 최근접 확대, 정렬 검사. 모두 순수 함수로 두고 단위 시험한다.
3. `generate.ts`: 인자는 밑그림 PNG 경로, `che.sources.json` 경로, 정규 키, 방식, 이미지 저장소 작업 사본 경로다. 비밀 키는 환경변수로만 받고 명령줄 인자와 로그에 남기지 않는다(AGENTS §7). 밑그림 래스터 해시가 출처 표 값과 다르면 바로 멈춘다.
4. 생성하고 정렬 검사를 지나면 WebP를 쓰고 출처 줄을 더한다. 같은 `mapKey` 줄이 이미 있으면 덮어쓰지 않고 멈춘다. 판마다 경로가 달라 덮어쓰지 않는다는 설계(map-editor.md §4)를 도구에서도 지킨다.
5. 결과 그림을 사용자에게 보인다. 도시 점을 얹은 미리보기는 T4-84 전이므로 편집기 `/dev/map-editor`에 그림을 깔 수 없다. 대신 스크립트가 미리보기 PNG(그림 위에 che 도시 점만 검은 점으로 찍은 것)를 작업 폴더에 만든다. 미리보기는 커밋하지 않는다.
6. 사용자가 그림을 받아들이면 이미지 저장소에 커밋한다. push는 사용자 허락 뒤에 한다. 이미지 저장소 커밋 SHA를 구현 기록과 T4-84에 넘긴다.

가짜 생성 호출을 쓴 단위 시험은 도구 동작의 증거다. 그림이 있다는 증거는 실제 생성 한 번과 이미지 저장소 커밋, 고정 주소의 해시 대조다.

### 상대 영역에 필요한 것

- Claude T4-82: 래스터 해시 정의와 `che.sources.json`의 `sketch` 칸. `che.v2.json`이 들어간 커밋 SHA. 래스터 해시 정의는 조율 세션이 map-editor.md §4에 더한다.
- Claude T4-84: 이미지 저장소 커밋 SHA. T4-84가 화면의 이미지 기본 주소 고정 커밋을 이 SHA로 옮긴다. 옮긴 커밋에서 기존 초상 3종 주소가 그대로 200인지도 T4-84가 확인한다.
- Codex T4-78: che 지형 판의 판 번호(R17). 정규 키와 경로가 여기서 정해진다.
- Codex T4-89 (조율 결정 R16): 서버가 판마다 바탕 그림이 있는지 아는 DB 자리와 `world.map`·`world.publicMaps`의 바탕 그림 칸. 출처 표는 이미지 저장소에 있어 서버가 읽지 못한다. 이 작업은 그 자리에 넣을 값(정규 키, 경로, sha256, 너비, 높이)을 구현 기록에 남긴다.

3. 이미지 저장소 커밋 push 허락. 그림을 보고 받아들인 뒤 따로 묻는다.
