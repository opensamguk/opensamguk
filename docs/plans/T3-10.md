# T3-10 반응형 375px

## 2026-10-28 실행 범위 갱신

사용자가 공개 준비의 프론트 구현을 Codex에 인계하고 페이지 구조를 v1에 대조하도록 지시했다. 이전의 Claude 담당·M2 전체 대기·하단 탭 제외 조건은 이번 공통 탐색 묶음의 착수를 막지 않는다. D-020의 메인 한 화면·게임 규칙·API와 동결 범위는 유지한다.

아래는 이전 계획의 근거와 미완료 조건이다. 현재 파일·주소·실측을 우선하며 과거 경로 부재나 담당 이름 때문에 구현을 중단하지 않는다.

### 첫 묶음 구현과 검증

공통 메뉴를 머리줄에서 분리해 데스크톱 왼쪽과 모바일 하단에 뒀다. 기존 읽기용 메인·오류 화면의 탐색은 유지하고 장수 생성 주소에서만 메뉴를 숨긴다. 독립 리뷰에서 메뉴가 본문 뒤의 Tab 순서로 밀린 P2를 찾아 본문 앞 DOM으로 고쳤고 재리뷰를 통과했다. 메인 안 휘하·부곡 앵커는 선택 도시와 저장 전 초안을 보존한다.

2026-10-28 새 전용 PostgreSQL·실제 API/engine·Chromium에서 로그인/세션·메인·정식491명 휘하/부곡을 포함한29건을5.2분에 통과했다. 375·767·768·1440px의 메뉴44px·실제 Tab·Escape 초점·지도 이동, 구형 월드와 장수 생성 입장을 검사했다. 별도 정식132개월 종료 월드의 네 폭 캡처에서도 넘침·앵커·머리줄 크기를 확인했다. 최종 공개 빌드는102파일·승인 이미지6개·외부 초상0개이며 공개 Chromium4건도 통과했다.

첫 실행27/29에서 장수 없는 메인의 탐색을 없앤 회귀를 찾아 제품 동작을 복원했다. 두 번째28/29는 같은 checkout의 공개 Chromium 실행이 공용 로그인 상태 파일을 정리한 실행 충돌이었다. 로그를 보존하고 공개 검사와 분리한 최종 실행에서29/29와 자기 API·웹·엔진 정상 종료를 확인했다. 검사 조건·제한시간·skip은 바꾸지 않았다. 출처 고지는 기존 NOTICE 원문 뒤에만 덧붙이며 생성 SQL의 고지도 함께 맞췄다.

공통 탐색 묶음은 PR #265의 필수 검사와 병합 대기열8개 검사를 통과해 main `79f0851`에 병합됐다. 핵심 표/입력의 전체44px·v1 독립 페이지 추가 대조가 남아 있으며 AC-M3-08은 미완료다.

### 모바일 조작 묶음

보호된 main의 정식132개월 종료 월드를375px로 실측했다. 로비에는44px 미만 조작이 없었지만 메인134개·지도77개·도시1개·국가1개·기록5개·순위2개가 기준보다 작았다. 종료 월드의 관측이므로 활성 월드와 전체 인수를 대신하지 않는다.

남은 일을 일반 조작, 표·정렬, GIS 도시 선택, 전체 화면 인수로 나눴다. 각각0.5~1일이며 이번에는 일반 조작을 고친다. CSS9개에서767px 이하의 예턴 버튼·명령 라벨·입력·행, 방침, 지도 확대 버튼, 정보 링크, 기록·순위 탭을44px로 맞췄다. 입력 글자는16px이고 PC 정보량과 바뀜 태그의 한 줄 표시를 유지한다. 쓸 수 없는 버튼도 눌러 이유를 읽는 조작이므로 같은 크기다.

실제 검사에서 기록 화면 복귀가 선택 도시를 잃는 결함도 찾았다. 기록 주소의 선택 도시를 기존 메인과 같은 정수 범위로 검사하고 기록4탭·메뉴·메인 복귀에 전달한다. 잘못된 값은 복귀 주소와 탭 링크에서 제외한다. 초안 저장 경로와 서버 상태는 바꾸지 않는다. 이 추가 범위도 구현하지 않은 담당의 계획 리뷰를 통과했다.

새 Chromium 검사는 정식191년21국491명을 전용 PostgreSQL에 읽고 실제 장수 생성 화면·엔진 처리·30칸을 쓴다.375·390px에서 조작과 행 크기, 입력 글자 크기를 재고768·1440px도 가로 넘침을 검사한다. 명령 라벨 가장자리를 눌러 실제 선택을 확인하고30번 칸까지 스크롤해 농지 개간을 저장한 뒤 DB30칸과491명 보존을 확인한다. 새로고침·기록4탭·메인 복귀에서도 선택 도시와 미저장 초안을 확인한다. 표 정렬과 SVG 도시의 남은 크기는 별도 측정 파일에 기록한다.

첫 실행은 사용 불가 버튼4개의 크기를 찾아 실패했고 해당 편집기·방침 안의 이유 버튼까지 고쳤다. 다음 실행은 시험 라벨 선택자를 고쳤고 이후 기록 복귀와 잘못된 도시 검색값 보존을 고쳤다. 검사 조건·기존 제한시간·skip은 바꾸지 않았다. 최종 집중 검사1건은11초에 통과했다. 같은 수정판에서 기존 INT-11·#112·메인·직접 주소와 새 검사를 포함한33건도 실제 PostgreSQL·Chromium으로5.8분에 통과했다. 자기 API·웹·엔진은 모두0으로 종료했고 정리 오류와 점유 포트가 없었다.

전체 `pnpm check`는286파일5274건을277.38초에 통과했다. 공개 빌드는102파일·승인 이미지6개·외부 초상0개이며 공개 Chromium4건도4.5초에 통과했다. 구현하지 않은 담당이 CSS·기록 연결·시험·문구·375px 캡처를 검토해 열린 P1/P2 없이 승인했다. 필수 CI·보호 병합은 이어서 확인한다. 이 묶음만으로 AC-M3-08을 완료하지 않는다.

## 계획 (Claude)

### 목표

375px 폭에서 로비와 핵심 화면 6개를 가로 스크롤 없이 쓴다. 누르는 대상은 44px 이상이다 (AC-M3-08, NFR-07).

데스크톱 화면의 정보량과 조작은 그대로 둔다 (D-007, D-020). 좁은 화면에서도 같은 데이터, 같은 컨트롤, 같은 키보드 조작을 쓴다.

### 착수 조건과 승인

이 계획은 사용자가 검토한다. 검토가 끝나도 착수는 M2 관문이 모두 `완료`된 뒤다. M2 화면이 위쪽 띠·메인·표를 계속 바꾸므로 그 전에 고친 CSS는 다시 깨진다.

계획 검토, M2 선행, AC 판정, 공개 승인은 서로 다른 관문이다. 계획 PR이 합쳐져도 AC-M3-08은 미착수 상태 그대로다. 통과 표시는 구현 뒤 Codex 리뷰가 통과할 때만 붙는다. 공개 오픈 승인(T3-15)은 이 작업과 상관없이 사용자가 따로 한다.

아래 세 가지는 사용자 결정을 받아야 한다.

### 알려진 결함 #112

GitHub #112는 메인 오른쪽 좁은 명령 칸에서 바뀜 태그가 바/뀜 두 줄로 갈라지던 결함이다. PR #131이 `.changedTag`에 `white-space: nowrap`을 넣어 고쳤고(`TurnEditor.module.css:182-183`) 이슈는 닫혔다. 이 수정과 시험(`e2e/issue112.spec.ts:52`)은 Desktop Chrome 1280×720 한 폭만 본다. #112의 수용 기록도 375px과 AC-M3-08은 통과시키지 않는다고 적었다.

375px에서 명령 칸은 한 열로 접혀 폭이 늘지만 표가 4열로 343px에 들어가야 한다. 태그가 줄바꿈 금지이므로 명령·인자 글자가 줄바꿈하지 못하면 표가 상자보다 넓어진다. 그 넘침은 위 예턴 표 항목대로 상자 안 가로 스크롤이 된다. 반대로 표를 맞추려고 태그의 줄바꿈 금지를 풀면 #112가 되살아난다. 이 작업은 두 조건을 함께 지킨다. 태그는 한 줄, 명령·인자 글자는 줄바꿈, 표는 상자 안에 들어간다.

검사는 `issue112.spec.ts`의 측정을 그대로 375×667과 390×844에서 다시 한다. 긴 실제 인자(모병 수량 1000000, 병종 번호 1100)와 이름이 가장 긴 대상 도시를 쓰고 태그의 요소·글자 줄 상자 수가 1인지, 명령·인자와 겹치지 않는지, 칸 밖으로 나가지 않는지, 표 상자와 페이지에 가로 넘침이 없는지 본다. 측정 함수는 `e2e/responsive-check.ts`로 옮겨 두 spec이 함께 쓴다. `issue112.spec.ts`의 1280×720 시험과 단언은 바꾸지 않는다.

### 결정

지금 main에는 화면 배치 경계가 둘 있다. 메인 1100px(`MainPage.module.css:78`)과 예턴 단독 화면 900px(`TurnsPage.module.css:12`)이다. 둘은 칸을 한 열로 접는 경계이며 그대로 둔다. 이 작업은 누르는 크기와 글자 크기를 바꾸는 좁은 화면 기준 `max-width: 640px` 하나를 더한다. CSS 변수는 미디어 조건에 못 쓰므로 640을 상수로 쓰고 세 경계를 UI 지침 §5에 함께 적는다.

공통 규칙은 이렇다.

- `tokens.css`에 `--tap-target: 44px`를 둔다. 좁은 화면에서 `button`, 메뉴 링크, 표 안 링크, `select`, `input`, `summary`, `[role=button]`, `[role=row][tabindex]`는 `min-height`와 `min-width`를 이 값으로 맞춘다. 체크 상자와 라디오는 감싼 `label`을 44px로 키운다.
- 좁은 화면의 `input`, `select`, `textarea` 글자는 16px(`--text-lg`)이다. iOS Safari는 16px보다 작은 입력 칸에 초점이 가면 화면을 확대해 가로 스크롤을 만든다.
- 격자·flex 자식에는 `min-width: 0`을 둔다. 글자 칸은 줄바꿈을 허용한다. 숫자 칸과 #112의 바뀜 태그만 줄바꿈 금지를 유지한다.
- `html`, `body`, 화면 바깥 틀에 `overflow-x: hidden`을 쓰지 않는다. 넘치는 내용을 잘라 숨길 뿐 고치지 못한다. 검사도 이를 실패로 잡는다.
- 화면 안 가로 스크롤도 허용하지 않는다. 표를 옆으로 밀어 봐야 한다면 AC 문장(가로 스크롤 없이 쓴다)에 맞지 않는다. `DataTable`과 순위 표의 `overflow-x: auto` 상자는 데스크톱 안전망으로 남겨도 되지만 375px에서 실제로 넘치면 실패다.
- 말줄임(`text-overflow: ellipsis`)으로 값이 잘리면 정보를 숨긴 것으로 본다. 좁은 화면에서 정보 칸 값은 줄바꿈한다.
- 좁은 화면에서 DOM 순서와 보이는 순서를 같게 둔다. `order`, `*-reverse`, DOM과 다른 `grid-template-areas`를 쓰지 않는다. 키보드 이동 순서와 화면 낭독 순서가 눈에 보이는 순서와 어긋나지 않게 한다.
- 고정 머리글이 있는 표(`TurnEditor.module.css:118`, `DataTable.module.css:15`)는 행에 `scroll-margin-top`을 두어 초점 간 행이 머리글 밑에 가려지지 않게 한다.
- 641px 이상은 크기를 바꾸지 않는다. 표 행 28px, 위쪽 띠 44px, 1101px 이상 메인 10열 격자를 유지한다. 641~1100px에서 넘치는 곳은 이 크기를 건드리지 않고 줄바꿈과 `min-width: 0`으로만 고친다.

위쪽 띠는 좁은 화면에서 두 줄로 나뉜다. 첫 줄에 월드·연월·다음 턴, 둘째 줄에 메뉴 4개와 로그아웃이 오고 둘째 줄은 넘치면 다음 줄로 접힌다. 메뉴는 숨기지 않는다. 행 높이 고정(`GameLayout.module.css:3`)을 좁은 화면에서 `auto`로 풀고 위쪽 띠는 지금처럼 고정하지 않는다. M2 작업이 더하는 메뉴와 표시도 같은 규칙을 따른다.

### 측정 방법 (`e2e/responsive-check.ts`)

가로 스크롤은 세 가지를 본다.

- `document.documentElement.scrollWidth`가 `window.innerWidth`를 넘지 않는다.
- 보이는 요소 가운데 오른쪽 끝이 `innerWidth`를 0.5px 넘거나 왼쪽 끝이 -0.5px보다 작은 것이 없다. 실패하면 요소 경로와 폭을 목록으로 낸다.
- 계산된 `overflow-x`가 `auto`·`scroll`이면서 `scrollWidth > clientWidth`인 요소가 없다. `overflow-y`만 `auto`로 둔 상자도 계산값이 `auto`가 되므로 함께 걸린다. `html`, `body`의 `overflow-x`가 `hidden`·`clip`이면 실패다.

말줄임은 계산된 `text-overflow`가 `ellipsis`이면서 `scrollWidth > clientWidth`인 요소를 실패로 낸다.

44px은 보이는 `a[href]`, `button`, `input`, `select`, `textarea`, `summary`, `[role=button]`, `[role=tab]`, `[role=link]`, `[tabindex]:not([tabindex="-1"])`의 `getBoundingClientRect()` 폭과 높이가 둘 다 44 이상인지 본다. 예턴 표의 행처럼 로빙 tabindex로 `-1`이 된 같은 종류의 행도 함께 잰다. 체크 상자·라디오는 감싼 `label`을 잰다. 예외는 `data-tap-exempt` 속성으로만 표시하고 허용 값은 사용자 결정을 받은 것(`map-marker`, `inline`)뿐이다. 허용 목록 밖의 값이면 실패다. 예외 개수는 결과에 따로 적는다.

정보 보존은 같은 데이터로 1280px과 375px을 비교한다. 375px 쪽이 1280px의 보이는 글자(`body`의 `innerText`를 공백으로 나눈 낱말, 개수 포함)와 초점 대상(역할과 접근 가능한 이름, `ariaSnapshot()`에서 뽑음)을 모두 가져야 한다. 표 열을 옮기면서 붙인 열 이름처럼 375px에만 더 있는 것은 허용한다. 두 폭 사이에 다음 턴이 와서 데이터가 바뀌지 않게 `waitTurnWindow`(`e2e/game.ts:285`)로 여유를 확인한 뒤 잰다. 좁은 화면에서 숨긴 내용이나 빠진 컨트롤이 있으면 여기서 걸린다. 예외 결정의 거절안이 적용되면 그 차이(지도 도시 표시의 버튼 역할, 문장 속 링크)만 비교에서 빼고 뺀 항목을 결과에 적는다.

키보드·초점은 375px에서 본다. Tab으로 화면의 초점 대상을 끝까지 돈다. 초점이 간 요소는 뷰포트 안에 있어야 한다. 그 가운데 점의 `elementFromPoint`가 그 요소나 자손이면 가려지지 않은 것이다. 계산된 `outline-style`은 `none`이 아니어야 한다. 끝에서 다시 Tab하면 첫 대상으로 돌아와 갇히지 않아야 한다. 예턴 편집은 T1-15의 키보드 시험(`e2e/turns.spec.ts:292`, 마우스 없이 3칸 넣고 저장)을 375px의 단독 화면과 메인 명령 칸에서 한 번씩 더 돌린다.

`viewport` 메타는 `width=device-width, initial-scale=1.0`이고 확대 막기가 없는지 본다.

검사기가 실제로 잡는지 음성 시험을 둔다. 같은 페이지에 아래를 끼워 넣었을 때 각각 실패를 돌려줘야 한다.

## 2026-10-28 모바일 GIS 거점 터치 묶음

AC-M3-08의 다음0.5~1일 묶음은 모바일767px 이하 운영 지도다. 실제 GIS·좌표·도트·53도시/8관문/6항구 시설/13전장 표시와 기존 select·확대·PC·키보드 경로를 유지한다. 실제 SVG 크기와 현재 배율로46px 투명 선택 영역을 환산하며 지도 안에 둔다. 화면 밖 거점은 선택 영역과 Tab 순서에서 빼고 좌표 자체는 옮기지 않는다. 겹친 영역을 터치하면 이름·종류가 있는 후보에서 고르며 선택 전 도시·초안은 바뀌지 않는다. 취소와 Escape 뒤 원래 지도 거점으로 초점을 돌린다. 읽기 전용 지도에는 거점 선택 영역·후보·선택 입력을 만들지 않는다.

최초 실제 Chromium 검증에서 끌기 뒤 다음 터치의 pointerup은 오지만 click이 오지 않는 경로가 재현됐다. 모바일 탭을 같은 주 포인터의 pointerup에서 처리하도록 고쳤다. 후속 검사에서 후보 목록의 즉시 닫힘과 초점 유실도 발견했다. 후보를 지도 뒤로 옮기고 같은 완료 포인터의 파생 click만 프레임에서 막으며 초점을 복원했다. 다음 pointerdown에서 식별자를 지우므로 새 버튼 조작은 막지 않는다. 취소·다른 포인터와 끌기는 선택하지 않으며 기존 PC와 키보드는 그대로다. 최초 실패 로그와 수정 검증을 보존하고 전체44px·표·휘하·6화면 인수는 미완료로 둔다.
