# INT-02 운영 지도 v3·불변 자원·월드 계약

> AC-INT-02 · 구현 Codex · 리뷰 Claude · 선행 INT-01, INT-14 · 견적 3일
> 사용자 지시로 동결한 [통합판 v0.1](./integration-release.md)과 [5능력치](../product/five-stats.md)를 따른다.

## 계획

목표는 도시 경제와 관문 상태, 항구 시설과 전장 표시를 분리한다. 안정 ID·자원 판·기존 cityKey 앵커를 정의하고 생성·저장·조회·해시·재생을 연결한다. 간선 중간 위치나 행군 상태는 만들지 않는다.

수정 범위는 packages/rules/src/world/, packages/db/prisma/, apps/engine/src/world/, apps/server/src/resourceAdmin/다. 새 기능을 더하지 않는다. 기존 main·v1 기준 SHA와 자원 출처는 통합 기준 문서를 따른다. 세부 코드 경계·API 인증·엔진 단독 상태 변경·시드 RNG·턴 트랜잭션을 지킨다.

검증은 잘못된 참조·중복·잘못된 판·권한 없는 게시 거부, 옛 월드/자원 해시 보존, 새 판 생성·로드·재시작·재생

선행 인수 뒤 착수하고 검증 결과와 구현하지 않은 담당의 리뷰를 같은 문서에 남긴다. 구현자가 스스로 완료로 바꾸지 않는다.

## 구현 기록

2026-10-27 운영 계약의 순수 검증부터 착수한다. 자원 v3와 안정 ID/참조 검증, 생성·저장·조회 연결, 구형 판·권한·재생 검증의 세 묶음이며 각각 하루 이내다. AC-INT-02에 연결한다. 운영 거점은 도시와 관문만 cityKey 앵커를 갖는다. 항구는 도시 시설이고 전장은 지명 표시이며 연결의 전략 목표나 추가 이동 턴이 되지 않는다. 경로의 시각적 경유점은 게임 이동 비용을 만들지 않는다.

기존 General.cityKey와 FK를 보존하면서 거점 종류를 명시한다. 관문의 경제/인구 값은0이며 도시 경제·수도·성장 처리에 참여하지 않는다. 소유·방어·연결·주둔은 기존 상태 변경 경로를 쓴다. 새 판에만 종류와 운영 지도 원장을 추가하고 구형 판의 nullable 열은 상태·해시에서 계속 뺀다. 실제 좌표와 게임 조정 좌표는 같은 position 모델과 화면을 쓴다. 거점 수와 정식 연결 확정은 INT-03,191년 대응은 INT-04다.

## 리뷰

구현하지 않은 Codex 담당이 운영 지도 계약과 저장·조회·해시·재생 어댑터를 독립 검토했다. 관문을 조약 비용·도시 수에 포함하던 경로, 같은 이름의 항구/전장 표식에 영향을 받던 수도 검사, 연결된 시나리오를 게시할 때 수도 종류 검사 누락, 후속 migration의 nullable 열을 반영하지 못한 기존 검사 네 건을 지적했다. 모두 수정한 코드를 다시 검토해 추가 결함이 없다고 판정했다.

실제 PostgreSQL에서 새 판 저장·로드·API 공개 필드·사람 생성·월 정산·재시작·동일 시드 재생·구형191년 월드 보존·DB 제약·원장 변조 거부·관문 제외 조약 비용/수락의4건이 통과했다. 관련 migration5파일37건도 실제 DB에서 통과했으며 구형 행의 새 열NULL과 기존 값 보존을 각각 검사했다. 운영 지도 계약/실행 반례2파일24건이 통과했다. 전체 검사·필수 CI·병합 전이므로 AC 완료로 기록하지 않는다. 이 검사는 저장 계약을 위한 작은 가상 지도이며 정식 GIS·191년 시나리오와 한 기수 인수 증거는 INT-03/04/12에서 별도로 모은다.

외교 화면의 후속 독립 리뷰에서 교역 후보 API의 거점 종류 projection 누락을 발견했다. 출발 관문을 거부하고 목표 종류를 순수 규칙에 전달했다. 실제 PG 반례로 도시 후보는 유지하고 타국 관문 목표와 관문 출발을 제외했다. 최종 PG5건과 관련 조회·장수 자료 단위48건이 통과했고 수정본 독립 리뷰를 통과했다. 첫 전체 검사에서는 오래된 조회 시험 자료3건과 worktree의 새 의존성 연결 누락1파일이 실패했다. 실제 DB의 빈 기능 배열·NULL 지도 열을 시험 자료에 넣고 잠금 파일대로 오프라인 설치해 원인을 고쳤다. 검사를 줄이지 않고 전체를 다시 실행한다.

전체 정적 검사와 단위 검사를 다시 실행해256파일5005건이 통과했다. 기존 DB 전체 검사에서는1159건 통과와8건 실패를 확인했다. 그중 기존 시나리오 준비/감독 종료 결함은 PR244의 정상 병합으로 반영했다. 새 열을 무조건 반환하던 월드 생성은 필요한id만 받도록 고쳤다. 구형 공개 지도 시험의 nullable JSON 복제와 도시 수 조회 assertions도 실제 계약에 맞췄다. 자원 초기화20건·외교 조회17건·공개 지도8건이 실제 PG에서 통과했고 수정본 독립 리뷰를 통과했다. 전체 PG 재검증과 필수 CI·병합 증거는 아직 남아 있다.

## 병합 뒤 인수 근거

수정본은 전체 check5,013건과 실제 PostgreSQL1,169건을 통과했다. 새 판의 지도 계약·관문 제외·권한·원장 변조 거부와 구형NULL·기존 해시 보존을 포함하며 권한 대조의 누락은0이었다. 구현하지 않은 담당이 최종 코드와 실제 증거를 독립 검토했다.
