## 계획 (Claude)

### 목표

AC-M1-14의 이 명령 몫이다. 원작 `nation:che_감축`에 대응하는 확장 국가 명령 `nation_shrink`가 켠 월드에서 연속 예약으로 실행되어 증축했던 수도의 규모를 1 내리고 인구·내정·수비·성벽의 현재값과 최대를 줄이며 국고에 일부를 돌려준다. 지도 원래 규모보다 작게는 줄이지 못한다. 성공 1건과 대표 실패 1건 단위 시험이 있고 같은 입력이면 결과가 같다. HTTP 이후 단계 증거는 T4-50·T4-51 뒤 같은 ID 아래에서 받는다.

### 3. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 3.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `nation_shrink` | 감축 | `nation` | `nation` | `noArgs` |

증축과 같이 `defineCommand`로 `{ kind: 'world' }` 효과를 낸다. key와 target은 이 파일에 글자 그대로 적는다([T4-73 §2.5](./T4-73.md#25-등록-모양)).

#### 3.2 검사 순서

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | `defineCommand` 국가 명령 검사 | `NO_ACTOR`, `BAD_ARGS`, `NOT_NATION`, `NOT_RULER` | T2-05 뒤에는 권한 표 |
| 2 | [T4-73 §2.1](./T4-73.md#21-공통-검사-capitalscalecheckview-actor) 공통 검사 | `NOT_OWN_CITY`, `NO_SUPPLY`, `BAD_STATE` | 같은 문구 |
| 3 | 수도 규모 4 이하 | `BAD_STATE` | 더 감축할 수 없습니다. |
| 4 | 수도 규모가 `capital_scale.origin[수도]` 이하 | `BAD_STATE` | 원래 규모보다 작게 줄일 수 없습니다. |

4번에서 `origin`에 수도 키가 없으면 조각이 깨진 것이다. `ExtSlice.validate`는 월드 문맥을 받지 않아(`commands/ext/state.ts:8-13`) 키 형식과 값만 보고 모든 도시 키가 있는지는 보지 못한다. 모든 키가 있다는 보장은 `create`가 `context.cities` 전부로 `origin`을 만든다는 것 하나다. 그래서 키가 없는 상태(`origin = {}` 포함)는 4번 검사가 예외로 거부한다. 검사는 `view`를 읽기만 하는 단계이고 `change` 전이므로 예외가 나도 상태는 바뀌지 않는다. 엔진 턴에서는 그 턴의 트랜잭션이 롤백된다(C5). 복원 때 키 집합을 맞추는 일은 T4-03의 복원 검사 몫이다(쟁점 R1).

#### 3.3 실행

`change(state, actor)`가 아래를 바꾼다. RNG는 쓰지 않는다.

1. 수도 `level -= 1`.
2. 최대값: `populationMax −= POP_STEP`, 내정 셋 `−= DEVEL_STEP`, 수비·성벽 `−= WALL_STEP`.
3. 현재값: `population = min(새 populationMax, max(population − POP_STEP, SHRINK_POP_FLOOR))`, `agriculture`·`commerce`·`security = min(새 최대, max(값 − DEVEL_STEP, 0))`, `defence`·`wall = min(새 최대, max(값 − WALL_STEP, 0))`.
4. 국가 `gold += 환급`, `rice += 환급`.
5. `capital_scale.changes[국가] = (changes[국가] ?? 0) + 1`. 키가 없는 국가는 0으로 읽는다([T4-73 §2.2](./T4-73.md#22-조각-capital_scale) 읽기 행).
6. T4-73 C5 (가)면 행위자 `experience += 30`, `dedication += 30`.

3의 바깥 `min(새 최대, ·)`은 원작에 없는 기술 계약이다. 원작 식은 지도 규모가 인구 최대를 받쳐 준다는 가정에 기대지만 우리 지도 스키마는 그 관계를 강제하지 않는다. 그래서 인구 하한(D2)이 감축 뒤 인구 최대보다 크면 인구는 하한이 아니라 새 최대에서 멈춘다. 하한은 최대를 넘지 않는 범위에서만 지킨다. D2를 어떤 값으로 정해도 같은 규칙이다. 이렇게 해서 현재값 ≤ 최대라는 도시 불변식(효과 적용도 같은 불변식을 지킨다, `commands/effects.ts:33-37`)을 지도와 상관없이 유지한다. 감축이 허용된 수도는 `level > origin`이라 월드 생성 뒤 증축이 감축보다 적어도 한 번 많았다. 그래서 새 최대는 지도 원래 최대 이상이고 음수가 되지 않는다. 현재값이 최대보다 2,000 넘게 낮았던 칸은 같은 양을 빼므로 최대와의 차이가 그대로다. 원작과 같다.

#### 3.4 준비 턴

증축과 같다([T4-73 §4.4](./T4-73.md#44-준비-턴)). 원작에서는 증축과 감축이 같은 `capset` 번호를 쓰므로 증축 직후 감축을 이어 예약해도 번호가 바뀌어 처음부터 센다. T4-07이 이 뜻을 받는지는 T4-73 쟁점 R2와 같다.
