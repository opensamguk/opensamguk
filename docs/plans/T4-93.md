# T4-93 철·목재·말·창고·수송망

> 대기열: T4-93 · AC: AC-P2-30 · 구현: Codex(PG·rules) · 리뷰: Claude · CF 어댑터: Cloudflare 채팅

## 계획 (Claude)

### 목표
AC-P2-30 문장 그대로다. 새 판에서 철·목재·말의 생산/소비, 창고 용량, 거점 간 수송의 출발 차감·도착 가산·명시적 손실을 보존한다. 금·쌀과 병력은 이중으로 계산하지 않는다. 기존 월드 해시는 바꾸지 않는다.

### 코드에서 확인한 사실
- `city-resources-v1`(`cityResourcesFeature.ts`)은 `checkOrigin`에서 `data === undefined`를 강제한다. `cityResourceSchema`는 `strictObject{gold,rice,garrison}`이고 `version: z.literal(1)`이다. 이 스키마를 바꾸면 v1 월드의 파싱·기록 검증(`validateCityResourceRecord`)이 같이 바뀐다.
- `ext` 조각은 활성 *명령* 묶음(`extSliceKeysWithRegistry`)으로만 선택된다. `resolverForRuleFeatures`는 `sliceKeys`가 있으면 오류를 낸다. 그래서 규칙 기능 상태에는 `ext`를 다시 쓸 수 없다.
- 해시는 `hashState(replay)` 전체다. 선택 칸이 없으면 기존 해시는 그대로다. `cloneWorld`·`WorldState`는 칸을 하나씩 나열한다.
- 월 순서는 `runMonthly`(안에서 `applyCityResourceIncome`) → `settleMonthlyFeatures`(`monthlyOrder`) → 엔진 `persistMonthly` 훅이다.
- 장비는 아직 없다. T4-22 `equipment_trade`는 계획만 있고 U-06을 기다린다.
- T4-92가 `apps/web/src/turns/*`를 수정 중이다.

### 선택한 설계
1. 새 불변 규칙 기능 `logistics-v1`을 둔다. `requires: ['city-resources-v1']`이다. 진행 중 월드에는 켜지 않고 원생성에서만 켠다.
2. 정본 상태는 `WorldState.logistics?: LogisticsState`다. 새 열 `World.logisticsState Json?`에 저장한다(새 migration `2026111x_logistics_state`). 금·쌀은 계속 `cityResources`에만 있다. 이 상태는 세 재화, 창고 등급, 수송대만 가진다.
3. 초기 설정은 `featureData['logistics-v1']`에 고정한다. `checkOrigin`이 `logisticsConfigSchema`로 검사하고 특산 거점이 `initial.cities`에 있는지 대조한다.
4. 라우터는 새 `logistics` 라우터 하나로 한다(`cityResources` 확장이 아니다). 기존 `city.resources` 입력 종류와 기록 검증, v1 재생을 건드리지 않기 위해서다.
5. 새 규칙은 난수를 쓰지 않는다. 손실은 정해진 비율의 버림으로 계산한다. 그래서 기존 시드 RNG 흐름의 순서가 그대로다.
6. 새 범용 틀은 만들지 않는다. 기존 패턴을 그대로 복제·확장한다: `readCityResourcesState`, `persistCityResourcesState`, `processCityResourceInput`, `cityResourcesApi`, `createCityResourceCommandResolver` 래퍼, `CityResourcesPanel`.

| 항목 | 모양 |

행 하나는 보유처(도시 또는 수송대) 하나만 가리킨다. 순수 함수 `assertLogisticsConserved(before, after, movements)`는 재화마다 보유처별 증감과 행 합계가 같은지 확인한다. 외부 유입·유출은 `PRODUCE·CONSUME·LOSS_*·TRADE·UPGRADE`뿐이다.

### 규칙
- **생산**: 매월 `settleLogisticsMonthly`에서 한다. 대상은 `nationId≠null`, `supplied`, `kind≠PASS`인 특산 거점이다. 생산량은 `floor(perMonth × population / populationMax)`다. 고정 순서는 ① 도착 판정, ② 생산, ③ 용량 초과분을 `LOSS_OVERFLOW`로 기록한다. `monthlyOrder` 맨 끝에 `'logistics-v1'`을 둔다. 세수 배분이 끝난 뒤라 금·쌀과 섞이지 않는다.
- **수송**: 경로는 출발 때 자기 국가 거점만 지나는 BFS로 고른다. 이웃은 `cityKey` 오름차순, 최대 `maxHops`다. 출발지 재고를 빼서 수송대에 넣는다(`DEPART`). 도착은 `arriveTick` = 출발 뒤 `ceil(hops/hopsPerMonth)`번째 월간 정산이다. 중간 위치는 없다. 군대 행군 상태를 되살리지 않는다.
- **도착 판정**(보존식):
  - 경로 전 구간과 도착지가 아직 같은 국가면 운송분에서 `floor(운송분×lossBp×hops/10000)`를 `LOSS_TRANSIT`로 빼고 나머지를 도착지에 넣는다(`ARRIVE`).
  - 경로가 끊겼거나 도착지를 잃었는데 출발지가 같은 국가면 출발지로 돌려보낸다(`RETURN`).
  - 도착지가 전쟁 중인 국가 소유면 도착지가 가진다(`CAPTURE`).
  - 그 밖에는 전량 `LOSS_TRANSIT`다.
  - 넣는 곳마다 용량 초과분은 `LOSS_OVERFLOW`다.
- **취소**: 출발지가 같은 국가일 때만 받는다. 즉시 출발지에 돌려주고 초과분은 손실로 기록한다. 이미 정산된 수송대 id는 거부한다.
- **점령**: 도시 재고는 도시에 남는다. D-040에서 금·쌀이 도시에 남는 것과 같다. 수송대는 도착 판정 때만 처리하므로 공격 명령 경로는 고치지 않는다.
- **창고**: 용량 = `base + level×perLevel`이다. `upgrade`는 그 도시의 `cityResources.gold`와 목재를 같은 상태 전이에서 뺀다.
- **소비**:
  - 모병·징병: 병종 `armType`별 `recruitPer100`을 `ceil`로 계산해 그 도시 재고에서 뺀다.
  - `wall`·`defence`: 장수가 있는 도시의 재고에서 뺀다.
  - 방식: `createLogisticsCommandResolver`가 기존 resolver를 감싼다. `check/precheck`에서 부족하면 `NO_GOODS`(Failure 코드 하나 추가)로 막고 `execute` 뒤 같은 `world` 효과에 차감을 반영한다. 기존 금·인구 비용은 그대로다.
- **NPC**: `cityNpcPreparation`의 모병 수를 재고 한도로 줄인다. NPC 수송(L4)은 특산 재고가 용량 50%를 넘으면 수도로 보낸다.

### 권한·접수·재검사·멱등
- 행위자: 서버 세션의 활성 계정, 자기 장수, 제재 없음, 등장 연도 지남. 국가 직책은 `nation_city_allocate`와 같은 `officerLevel 5~12`이고 대상 거점은 자기 국가 소유여야 한다.
- 접수: `submit`이 `cityResourcesApi.submitCityResourceRequest`와 같은 순서로 처리한다. 세션 → `ready()` 기능·origin 대조 → 제재 → 멱등키 `logistics:<uuid>`(같은 키에 다른 payload면 CONFLICT) → `RUNNING` → `applyLogisticsInput(readView)`로 미리 판정한다. 접수 단계는 `PENDING` 행과 `general.active`만 쓰고 상태는 바꾸지 않는다.
- 엔진: `processLogisticsInput`이 같은 리스·World 잠금 안에서 사용자 `FOR SHARE`, 장수 `FOR UPDATE`를 잡고 다시 판정한다. 그다음 상태·원장 행을 한 트랜잭션에 쓴다. 판정이 바뀌었으면 `REJECTED`다.

### 호환
- `world.ts`·`clone.ts`에 `logistics` 선택 칸을 더한다. 꺼진 월드에는 칸이 없다.
- `readStoredLogistics`: 기능이 꺼진 월드에 값이 있으면 오류다.
- `assertStoredLogistics`: `capsGate.ts`·`replay.ts`에서 호출한다.
- `worldLoader`·`commandPersistence`·`monthly`에 `persistLogisticsState`를 연결한다. 조건부 UPDATE(이전 JSON 일치)로 쓴다.
- `world/persistence.ts`: 생성 때 `initialLogisticsState`를 쓴다.
- `initReplayState`: 중복 초기화를 거부한다.
- `checkArchive`: 기록 모양·수량을 검사한다.
- 리셋은 기존 `featureData` 사본 경로를 쓰고 상태를 다시 초기화한다.

### 조회·화면
- 자기 국가: 소유 거점별 재고·용량·등급, 자기 수송대, 최근 원장 행.
- 다른 국가: 특산 표시만 보인다(`visibility(actor).city`). 재고와 수송대는 숨긴다.
- 화면: `apps/web/src/main/LogisticsPanel.tsx`를 새로 만들어 `CityInfo.tsx`에서 `CityResourcesPanel` 아래에 붙인다. 요청 처리는 `logisticsRequest.ts`가 `cityResourceRequest.ts`와 같은 방식으로 한다. 패널 내용은 재고 막대, 보내기 폼(도착지·수량·예상 도착월·손실), 수송대 목록과 취소, 증축, 비용표다.
- `turns/*`는 T4-92 병합 뒤 모병 미리보기 한 줄만 따로 고친다.

  - 세 갈래 도착 판정과 초과 손실.
  - 보존식은 무작위 입력열 property 시험으로 확인한다.
- **골든**: 기능을 끈 월드(구판 1·3, `city-resources-v1`만 켠 판)의 결과·RNG 소비·해시가 기존 fixture와 같다. 등록표를 추가해도 바뀌지 않는다.
- **engine int (PG)**:
  - 접수와 엔진 재판정 경합.
  - 같은 `requestId` 재전송.
  - 롤백(원장 행과 상태가 함께 없음).
  - 엔진 재시작 뒤 이어서 처리.
  - `exportReplay` → 재생 해시와 원장 합계 일치.
  - 두 월드 격리.

- **server**: `queries.logistics.test.ts`에서 권한(직책 4, 다른 국가, 제재, 계정 바뀜), 다른 국가에 숨김, 꺼진 월드는 `PRECONDITION_FAILED`.
