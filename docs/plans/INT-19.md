# INT-19 장수 지시·수신·실행

> AC-INT-19A~C · 구현 Codex · 구현하지 않은 담당의 독립 리뷰 · 2026-10-30 사용자 추가 범위

## 목표와 경계

사용자는 휘하 인물의 미구현 명령을 오늘 구현하도록 요청했다. 플레이어도 군주·다른 플레이어·NPC에게 지시를 받을 수 있다. 장수의 직속 상급자는 한 명이며 여러 휘하를 거느릴 수 있다. 부곡은 장수 개인의 사병이고 한 장수가 여러 부곡을 소유한다. 기존 INT-05·06·11의 완료 기록과 이 추가 범위는 따로 집계한다.

개인 지시 권한은 현재 직속 관계를 따른다. 군주의 현재 동국 장수에 대한 국가 지시 권한은 직속 상급자를 추가하거나 바꾸지 않는다. 타국·다른 월드·무관한 인물의 사칭을 거부한다. 사람의 수락·거절은 본인이 하며 동의 없이 예약·소속·재산·부곡 소유권을 바꾸지 않는다. NPC 지시 요청은 현재 직속 상급자가 NPC일 때 허용한다. 직속 상급자가 없으면 현재 동국 NPC 군주에게 국가 지시를 요청한다.

## 입력과 실행

API는 세션·인증·제재·월드·현재 관계·기존 명령 형식·요청 번호를 검사하고 `campaign.order` 입력을 접수한다. 같은 번호와 내용은 기존 결과를 반환하고 다른 내용은 거부한다. 실제 원장·게임 상태는 엔진의 기존 월드 잠금·펜싱·단일 트랜잭션에서 바꾼다.

사람에게 보낸 지시는 응답을 기다린다. 수신자가 다음 예약 한 칸을 해당 지시로 실행하는 데 명시적으로 동의하면 현재 첫 칸과 예약 변경 번호를 고정한다. 거절은 무료다. NPC 상급자 지시는 엔진이 발신자를 정하고 기존 시드 NPC 판단으로 수신자에게 가능한 명령을 고른 뒤 본인 수락을 기다린다. 입력에서 NPC 발신자나 수락을 위조할 수 없다.

접수·수락은 기존 30개 예약 행을 덮어쓰지 않는다. 실제 차례에 권한·첫 칸·변경 번호를 다시 검사한다. 예약 편집·관계 해제·군주 변경 등으로 조건이 달라지면 지시를 취소하고 원래 예약을 실행한다. 유효한 지시는 기존 명령 실행기를 한 번 거쳐 성공·실패를 기록한다. 기존 다음 칸 이동도 한 번만 한다. 명시 지시가 없는 턴의 사람 기본 방침·NPC 판단·RNG는 보존한다.

휘하 NPC의 개별 내정·이동·귀환과 자기 소유 부곡 명령은 저장된 실행 대기 지시의 발신자·수신자·내용·현재 권한을 검증한 내부 실행 문맥에서 허용한다. 평소 NPC 자동 판단에는 이 예외를 적용하지 않는다. 상관 사병의 대리 출병·소유권 이전은 허용하지 않는다. 실제 지휘관과 소유자가 떨어지면 기존 집결 조건을 지킨다. 병력·군량·도시 자원을 중복 저장하거나 차감하지 않는다. 2026-10-30 사용자 결정에 따라 NPC가 받는 지시는 직속·군주 권한 모두 내정·군사(이동·귀환·자기 부곡)·개인 명령으로 한정하고 소속 변경·등용·계략은 거부한다.

## 저장과 호환

기존 `campaign-v1`에 입력을 등록하고 선택 필드 `campaign.orders`에 형식·다음 번호·지시 목록을 저장한다. 기본값을 넣지 않으며 신규 입력이 없는 월드의 JSON·해시·9개 기능·생성 기록을 보존한다. 새 컬럼·migration 없이 기존 상태 저장 경로를 쓴다. 입력 재생과 월턴 재생은 같은 순수 함수를 사용하며 저장된 성공 결과를 재계산해 대조한다.

## 현재 상태

2026-10-30 Codex 구현을 Claude가 이어받아 [PR #321](https://github.com/opensamguk/opensamguk/pull/321)로 main에 올린다. 지시 원장·권한·수락/거절·실제 차례 실행과 취소·재생, API·엔진 재검사, 메인의 `장수 지시` 화면을 구현했다. 순수 검사와 실제 PG 통합 검사(`tools/int19-orders.integration.test.ts`), 개발 서버 Chromium 검사(`e2e/int19-retinue-orders.spec.ts`)를 필수 CI에서 실행한다. Claude·Codex 독립 리뷰를 거쳤다. 실시간 진행에서 밀린 차례의 tick이 입력보다 이른 경우의 저장 오류는 리뷰에서 찾아 고쳤다.
