## 계획 (Claude)

2026-10-20에 처음 쓰고 2026-10-23 main `3e5b52a`의 코드에 맞춰 다시 썼다. 다시 쓰면서 세트를 두는 곳과 교체 방법, 빠진 이미지와 잘못된 ID 처리, 사용자가 정할 것 목록을 보탰다.

### 목표

공개할 이미지 세트(와 장수 데이터 출처)가 결정 기록에 남아 있고 공개 빌드가 승인되지 않은 이미지 경로를 참조하지 않는다 (AC-M3-06, 결정 기록 + 자동 검사).

### 사용자 결정 대기 (T3-12)

이 작업은 T3-12가 끝나야 착수한다. 이 계획은 아래 어느 항목도 대신 고르거나 승인하지 않는다. 결정은 사용자가 [결정 기록](../product/decisions.md)에 새 D 번호로 남긴다. T3-12는 계획 문서 없이 그 결정 기록으로 끝난다.

| 번호 | 정할 것 | 이 작업에 들어가는 곳 |
| ---- | ------- | --------------------- |
| U1 | 공개 빌드의 초상: [이미지 자산 §3](../image-assets.md#3-라이선스-구분-공개-전-관문)의 세 선택지(위험한 초상을 빼고 다른 세트·기본 이미지로 교체, 위험을 알고 운영자 책임으로 그대로 사용, 권리 확인 등 다른 방법) 중 하나 | `public-assets.json` 전체 |

특정 생성 서비스나 유료 권리를 이 계획에서 승인하지 않는다. 승인 세트를 만드는 일(그림 생성, 이미지 저장소에 커밋 만들기)도 이 작업 밖이다.

### 외부 그림 제약

와룡전 리메이크(`phixteam1/GRZ` v1.1)의 그림은 이용 허락이 없고 표본이 원작 그림을 확대한 것으로 보인다 (D-028). 얼굴은 쓰지 않는다. 지도와 그 밖의 그림은 화풍·색 구성을 볼 때만 참고한다. 이 작업은 그 그림을 따라 그리거나 이미지 생성 입력으로 넣거나 저장소·이미지 서버에 올리지 않으며 승인 목록 후보로도 다루지 않는다. 사용자가 제작자에게 서면 허락을 요청하고 있다. 2026-10-23 기준 답은 없다.

### 하지 않는 것

- 라이선스 판단, 이미지 생성, 이미지 저장소 정리와 새 커밋 만들기.
- 초상 ID 체계 변경. ID는 10001~11000이고 게임 데이터는 숫자만 저장한다 (D-004, FR-IMG-01). 세트가 이 범위 밖 ID를 요구하면 `packages/rules/src/general/create.ts:47`의 검증부터 바꿔야 하므로 별도 AC로 올린다.
- 서버의 초상 ID 검증 변경. API는 지금처럼 10001~11000만 받는다. 승인 세트에 없는 ID가 저장돼도 화면이 기본 이미지로 보이므로 서버를 고치지 않는다.
- 이미지 서버 배포 (T2-15). 운영 배포가 `build:public`을 부르고 서버의 이미지 커밋을 승인 목록과 맞추는 연결은 Codex 영역이다. `tools/deploy.sh`는 T2-15 계획에 있고(`docs/plans/T2-15.md:18`, `:30`) main에는 아직 없다.
- 운영 CSP. `deploy/security.caddy:5`의 `img-src`는 `https://cdn.jsdelivr.net`을 허용한다. T3-04 구현 기록은 이 허용을 자산 공개 권리 승인으로 보지 않는다. `img-src`를 `imageBaseUrls`와 맞추는 일은 Codex 영역이다.
- 글꼴(Pretendard)과 스크립트의 라이선스. AC-M3-06은 이미지만 본다. 외부 주소 검사는 글꼴·스크립트 주소도 막지만 묶은 글꼴 파일의 권리는 판단하지 않는다.
- 사용자 승인을 기다리는 핵심 규칙 변경과 관계없다. 도입하지 않는다.

### 세트를 두는 곳과 바꿔 끼우는 방법

결정과 상관없이 정해 두는 구조다.

- 그림은 이 저장소에 넣지 않는다. 초상 세트는 이미지 저장소 [opensamguk-images](https://github.com/peppone-choi/opensamguk-images)의 고정 커밋 하나다. 경로 규칙은 지금과 같은 `portraits/<변형>/<id>.<확장자>`다 ([이미지 자산 §2](../image-assets.md#2-초상-id와-경로)).
- 이 저장소에 묶이는 그림은 기본 이미지 `apps/web/src/portrait/fallback.svg`(코드로 그린 실루엣, 571바이트)뿐이다. 새 그림을 묶으려면 승인 목록에 출처와 함께 올려야 한다.
- 어느 세트를 쓰는지는 저장소 루트의 `public-assets.json` 하나에 적는다.
- 세트를 바꿀 때는 `public-assets.json`의 커밋·base URL·ID 범위를 고치고 `VITE_IMAGE_BASE_URL`을 맞춘 뒤 `pnpm build:public`으로 다시 빌드한다. base URL만 바꿔도 모든 주소가 바뀌는 성질은 T1-17이 이미 시험했다 (AC-M1-20).
- 개발 빌드(`pnpm dev`, 일반 `vite build`)는 지금처럼 jsDelivr 기본값과 10001~11000 전체를 쓴다. M1·M2 비공개 시험은 기존 초상을 쓴다 (D-004).

```json
{
  "decision": "D-0xx",
  "imageRepo": "peppone-choi/opensamguk-images",
  "imageRepoCommit": "<40자리 커밋>",
  "imageBaseUrls": ["https://img.<도메인>"],
  "portraitVariants": ["portrait", "icon", "thumb"],
  "portraitIds": [[10001, 11000]],
  "bundledAssets": [{ "file": "fallback.svg", "source": "apps/web/src/portrait/fallback.svg, T1-17 자작" }],
  "externalOrigins": [],
  "nonLoadingOrigins": [{ "origin": "http://www.w3.org", "reason": "SVG 이름공간" }]
}
```

- `portraitIds`는 닫힌 범위의 목록이다. 초상을 공개하지 않으면 `imageBaseUrls`와 `portraitIds`가 모두 빈 목록이고 `imageRepoCommit`은 `null`이다.
- `nonLoadingOrigins`는 번들에 문자열로만 남고 화면이 불러오지 않는 주소다(이름공간, 라이브러리의 오류 안내 주소, 입력칸 예시). 항목마다 이유를 적는다.
- 값은 위 예시가 아니라 T3-12 결정을 그대로 옮긴다.

### 빠진 이미지와 잘못된 ID

지금 동작(T1-17)과 이 작업에서 더할 동작을 한 표에 둔다.

| 경우 | 지금 (`3e5b52a`) | 공개 빌드 (이 작업 뒤) |
| ---- | ---------------- | ---------------------- |
| ID가 null, 정수 아님, 10001~11000 밖 | 요청 없이 기본 이미지 (`portraitUrl.ts:26-37`) | 같다 |
| 범위 안이지만 승인 세트 밖 | (해당 없음) | 요청 없이 기본 이미지. `portraitUrl`이 `null`을 돌려준다 |
| 승인 세트 안인데 파일이 없거나 불러오기 실패 | `onError`로 기본 이미지, 주소가 바뀌면 다시 시도 (`Portrait.tsx:16-18`, `:42`) | 같다 |
| 공개 base URL이 비었음 (초상 공개 안 함) | jsDelivr 기본값으로 떨어짐 (`portraitUrl.ts:18-21`) | 기본값으로 떨어지지 않고 모든 초상이 요청 없이 기본 이미지 |
| 장수 생성 화면의 초상 고르기 | 10001~10006 여섯 개 고정 (`createForm.ts:16`) | 승인 세트에 있는 것만 보인다. 하나도 없으면 기본 이미지만 고른다 |
| API로 범위 안 ID를 직접 보냄 | 서버가 받는다 (`create.ts:47`) | 서버는 그대로 받고 화면은 세트 밖이면 기본 이미지 |

승인 세트 밖 ID를 요청하지 않게 하는 이유가 둘 있다. 초상 대응표는 D-028에서 운영자가 편집하는 DB 자료가 되므로(T4-77·T4-87) 빌드 때 검사로 모든 ID를 잡을 수 없다. 그리고 세트가 일부 ID만 채우면 나머지 요청이 모두 404가 된다.

구현은 이렇게 한다.

- 공개 빌드는 `vite build --mode public`이다. `vite.config.ts`가 이 모드에서만 `public-assets.json`을 읽고 `portraitIds`와 공개 빌드 여부를 빌드 상수로 넣는다. `VITE_IMAGE_BASE_URL`이 `imageBaseUrls`에 없으면 빌드를 멈춘다.
- `portraitUrl`은 공개 빌드에서 base가 비면 `null`을 돌려주고 ID가 `portraitIds` 밖이면 `null`을 돌려준다. 분기는 빌드 상수로 해서 jsDelivr 기본값 문자열이 공개 번들에서 빠지게 한다.
- 공개 빌드는 이미지 인라인 한도를 0으로 둔다. 지금 `fallback.svg`는 Vite 기본 한도(4KiB) 아래라 `data:` 주소로 번들에 들어간다(`e2e/portrait.spec.ts:100`). 한도를 0으로 하면 파일로 나와 묶은 파일 검사가 이름으로 본다.
- 개발 빌드 동작, `portrait.test.tsx`의 기본값 시험, `e2e/portrait.spec.ts`는 그대로 둔다. 공개 분기 시험은 따로 더한다.

### 자동 검사

`pnpm build:public` = 공개 환경변수로 `apps/web`을 `--mode public` 빌드 → `pnpm assets:check`. 검사는 빌드 결과(`apps/web/dist`)와 저장소의 ID 자료를 본다. 실제로 배포될 파일이 기준이다. 실패하면 파일 이름과 걸린 값을 출력하고 0이 아닌 값으로 끝난다. 네트워크는 쓰지 않는다.

| 검사 | 막는 것 |
| ---- | ------- |
| 결정 기록 | `decision` 번호가 `docs/product/decisions.md`의 제목에 없음 |
| 세트 고정 | `imageRepoCommit`이 40자리 커밋이 아님(브랜치·태그 이름 금지). 세트 없음이면 `null`이 아님 |
| base URL | 번들에 박힌 base가 `imageBaseUrls`에 없음. 목록이 비었는데 번들에 base가 있음 |
| 외부 주소 | HTML·JS·CSS 안의 `http(s)://` 주소의 출처가 `imageBaseUrls`, `externalOrigins`, `nonLoadingOrigins` 어디에도 없음. jsDelivr 기본값도 여기서 걸린다 |
| 묶은 파일 | `dist/` 안의 이미지 파일(png·jpg·jpeg·webp·gif·svg·avif·ico)이 `bundledAssets`에 없음(Vite 해시를 뗀 이름으로 비교). `source`가 빈 항목. JS·CSS 안의 `data:image/` 주소 |
| 초상 변형 | `portraitVariants`가 `PORTRAIT_VARIANTS`(`portraitUrl.ts:9-13`)와 다름 |
| 고르기 ID | 장수 생성 화면에 보일 초상 ID가 `portraitIds` 밖 (화면 필터가 빠졌는지 확인) |
| 대응표 ID | `resources/portraits/rtk14-map.json`의 값이 정수가 아니거나 10001~11000 밖. 승인 세트 밖 ID는 실패가 아니라 개수와 목록을 출력한다 (화면이 기본 이미지로 처리) |

검사가 막지 못하는 것도 적어 둔다. 묶은 그림이 어디서 왔는지는 `source` 글로만 안다. 외부 그림을 본떠 만든 그림인지는 기계가 가리지 못하므로 리뷰어가 `bundledAssets` 항목과 결정 기록을 대조한다. T4-77이 먼저 들어와 대응표가 DB로 옮겨지면 대응표 ID 검사는 초기화 SQL의 같은 값을 읽도록 바꾸고 구현 기록에 적는다.

| ---- | ------ |

| 실제 빌드 | `pnpm build:public` 통과 로그. 같은 빌드를 승인되지 않은 base URL로 다시 하면 실패하는 로그. 일반 `vite build` 결과를 검사하면 jsDelivr 주소로 실패하는 로그 |

| 결정 기록 | 리뷰어가 `decisions.md`의 T3-12 결정과 `public-assets.json`이 같은지 직접 본다 |
| 기존 동작 | `pnpm check`와 `e2e/portrait.spec.ts`가 그대로 통과 (개발 빌드 동작 유지) |

### 상대 영역에 필요한 것 (Codex)
