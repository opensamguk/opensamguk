# T3-13 공개 이미지 세트 반영과 자동 검사

> 대기열: T3-13 · AC: AC-M3-06 · 구현: Claude · 리뷰: Codex
> 선행: **T3-12 (사용자: 공개 이미지 라이선스 결정, A8)** · 관련: FR-IMG-04, NFR-13, D-004, D-016, [이미지 자산 §3](../image-assets.md), [T1-17](./T1-17.md)

## 계획 (Claude)

### 목표

공개할 이미지 세트(와 장수 데이터 출처)가 결정 기록에 남아 있고 공개 빌드가 승인되지 않은 이미지 경로를 참조하지 않는다 (AC-M3-06, 결정 기록 + 자동 검사).

### 담당과 수정 범위

| 담당 | 에이전트 | 고치는 곳 |
| ---- | -------- | --------- |
| 구현 | opensamguk-frontend-implement (Claude) | `tools/public-assets/`(새로: 검사 스크립트와 단위 시험), `public-assets.json`(새로, 저장소 루트의 승인 목록), 루트 `package.json`의 `build:public`·`assets:check`, `apps/web/src/portrait/portraitUrl.ts`와 `apps/web/vite.config.ts`의 공개 빌드 분기(아래 지금 코드와 맞출 점) |
| 리뷰 | opensamguk-frontend-review (Codex) | 검사 규칙, 결정 기록과 목록의 일치, 채울 문서 |

`tools/`와 루트 `package.json`은 공통 설정이다. 같은 시기에 다른 작업이 루트 스크립트를 고치면 총괄이 반영 순서를 정한다.

### 사용자 결정 대기 (T3-12)

이 작업은 T3-12가 끝나야 착수한다. T3-12에서 사용자가 정할 것은 아래 두 가지이며 이 계획은 어느 쪽도 대신 고르거나 승인하지 않는다.

1. 공개 빌드의 초상: [이미지 자산 §3](../image-assets.md)의 세 선택지(위험한 초상을 빼고 생성 초상·기본 이미지로 교체, 위험을 알고 운영자 책임으로 사용, 권리 확인 등 다른 방법) 중 하나.
2. 장수 데이터(이름·능력치) 출처와 고지 방법 (A8).

생성 이미지를 쓰기로 하면 그 생성 서비스의 이용 약관 확인도 T3-12 결정에 들어간다. 특정 생성 서비스나 유료 권리를 이 계획에서 승인하지 않는다. 결정은 사용자가 [결정 기록](../product/decisions.md)에 새 D 번호로 남긴다.

### 하지 않는 것

- 라이선스 판단, 이미지 생성, 이미지 저장소 정리.
- 이미지 서버 배포 (T2-15). 운영 배포 스크립트가 `build:public`을 부르게 하는 연결은 Codex 영역이다. 스크립트 `tools/deploy.sh`는 T2-15 계획에 있고(`docs/plans/T2-15.md:18`, `:30`) main에는 아직 없다. 총괄이 Codex 작업으로 붙인다.
- 운영 CSP의 이미지 출처. 지금 검토용 `deploy/security.caddy:5`의 `img-src`는 `https://cdn.jsdelivr.net`을 허용한다. T3-04 구현 기록은 이 허용을 자산 공개 권리 승인으로 보지 않는다고 적었다. T3-12 결정 뒤 `img-src`를 `public-assets.json`의 `imageBaseUrls`와 맞추는 일은 Codex 영역이며 총괄이 같은 시기에 붙인다.
- 사용자 승인을 기다리는 핵심 규칙 변경 10건과 관계없다. 도입하지 않는다.

### 승인 목록

저장소 루트의 `public-assets.json` 하나로 둔다.

```json
{
  "decision": "D-0xx",
  "imageBaseUrls": ["https://img.<도메인>"],
  "portraitVariants": ["portrait", "icon", "thumb"],
  "bundledAssets": ["fallback.svg"],
  "externalOrigins": []
}
```

- `decision`은 T3-12 결정 번호다. 결정 기록에 그 번호가 없으면 검사가 실패한다.
- 위험한 초상을 쓰지 않기로 정하면 `imageBaseUrls`는 생성 초상 세트 주소만 갖거나 빈 목록이 된다. 빈 목록이면 화면은 기본 이미지만 쓴다.
- 개발 기본값인 jsDelivr 주소(`opensamguk-images@48163bd`)는 결정이 그 세트를 승인한 경우에만 목록에 들어간다.

### 자동 검사

`pnpm build:public` = 공개 환경변수로 `apps/web` 운영 빌드 → `pnpm assets:check`. 검사는 빌드 결과(`apps/web/dist`)를 본다. 소스가 아니라 실제로 배포될 파일이 기준이다.

| 검사 | 실패 조건 |
| ---- | --------- |
| base URL | 빌드에 박힌 `VITE_IMAGE_BASE_URL`이 `imageBaseUrls`에 없음 (비어 있으면 기본 이미지만 쓰는지 확인) |
| 외부 주소 | HTML·JS·CSS 안의 `http(s)://` 주소 중 이미지·폰트·스크립트를 가리키는 것이 `imageBaseUrls`·`externalOrigins`에 없음 |
| 묶은 파일 | `dist/` 안의 이미지 파일(png·jpg·jpeg·webp·gif·svg·avif)이 `bundledAssets`에 없음 |
| 초상 경로 | 초상 경로 틀이 `portraitVariants` 밖의 변형을 씀 |
| 결정 기록 | `decision` 번호가 `docs/product/decisions.md`에 없음 |

- 실패하면 파일 이름과 걸린 주소를 출력하고 0이 아닌 값으로 끝난다.
- 개발 빌드(`pnpm dev`, 일반 `vite build`)는 검사하지 않는다. M1·M2 비공개 시험은 기존 초상을 쓴다 (D-004).

### 지금 코드와 맞출 점

2026-10-22 main `76d56d0`의 화면 코드를 읽고 적었다.

- `VITE_IMAGE_BASE_URL`이 비면 jsDelivr 기본값으로 떨어진다(`apps/web/src/portrait/portraitUrl.ts:4`, `:18-21`). 그래서 지금 코드로는 `imageBaseUrls`가 빈 목록인 공개 빌드를 만들 수 없다. 기본값 문자열도 번들에 남아 외부 주소 검사에 걸린다. 공개 빌드에서는 빈 값이 기본값으로 떨어지지 않고 `portraitUrl`이 `null`을 돌려 기본 이미지를 쓰게 분기한다. 분기는 빌드 때 정해지는 값으로 해서 기본값 문자열이 공개 번들에서 빠지게 한다. 개발 빌드 동작과 `portrait.test.tsx`의 기본값 시험은 그대로 둔다.
- 기본 이미지 `apps/web/src/portrait/fallback.svg`는 561바이트다. Vite는 4KiB 미만 자산을 `data:` 주소로 번들에 넣으므로 지금 빌드의 `dist`에는 이 파일이 따로 없다. 공개 빌드는 `apps/web/vite.config.ts`에서 인라인 한도를 0으로 둬 모든 이미지를 파일로 내보낸다. 묶은 파일 검사는 Vite가 붙인 해시를 뗀 이름으로 `bundledAssets`와 비교한다. JS·CSS 안의 `data:image/` 주소는 실패로 센다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 규칙 | 단위: 승인 안 된 base URL, 목록 밖 외부 이미지, 목록 밖 묶은 파일, 없는 결정 번호를 넣은 가짜 `dist`에서 각각 실패. 승인된 것만 있는 가짜 `dist`에서 통과 |
| 실제 빌드 | `pnpm build:public` 통과 로그. 같은 빌드를 승인되지 않은 base URL로 다시 하면 실패하는 로그 |
| 화면 | Playwright: 공개 빌드를 띄운 화면에서 초상 요청이 모두 승인된 주소로만 나감 (네트워크 요청 목록 대조) |
| 결정 기록 | 리뷰어가 `decisions.md`의 T3-12 결정과 `public-assets.json`이 같은지 직접 본다 |
