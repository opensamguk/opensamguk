# T1-09 NPC AI와 헤드리스 시뮬레이터

> 대기열: T1-09 · AC: AC-M1-17, AC-M1-18 · 구현: Codex · 리뷰: Claude
> 선행: T1-08 · 관련: [테스트 정책](../testing-policy.md) §4

## 계획 (Claude)

### 목표

- 사람 없이 NPC만으로 10개 시드를 돌리면 10개 모두 오류 없이 천하통일 또는 종료 연도에 이른다 (AC-M1-17).
- 1판이 개발 PC에서 15분 안에 끝난다 (AC-M1-18). 참고: core2026은 장수 880명·94도시 무보정이 747개월, 약 470초.

### 범위

- `packages/rules/src/npc/`: `chooseGeneralTurn(view, general, rng)`, `chooseNationTurn(view, ruler, rng)` (순수 함수)
- `apps/engine`: 예턴이 빈 NPC 장수의 턴에서 AI가 고른 명령을 실행
- `tools/sim/`: DB 없이 메모리에서 한 판을 끝까지 돌리는 명령 `pnpm sim --seeds 10 [--scenario 1030] [--max-year 300]`

### 하지 않는 것

NPC 성격·성향 다양화(M2 FR-NPC-04), 사람 장수 대신 두기(D12 기본 방침, M2), 군사 조언 화면(D3, M3).
단, **판단 함수는 D3 군사 조언이 그대로 다시 쓸 수 있게** "후보 목록 + 점수 + 이유 문자열"을 돌려준다.

### 결정한 판단 구조

```text
후보 = 지금 실행 가능한 명령들 (check 통과)
점수 = 규칙 기반 가중치 (예: 전선 도시면 군사, 후방이면 내정, 병력 부족이면 모병)
선택 = 점수 상위 중 RNG로 하나 (rngFor(seed, 'npc', tick, generalId))
반환 = { chosen, candidates: [{ key, args, score, reason }] }
```

- 장수 판단 우선순위: 재야면 임관 → 소속 도시가 최대치 미만이면 내정 → 전선이고 병력 부족이면 모병·훈련·사기 → 준비되면 출병 → 아니면 이동(전선으로).
- 군주 판단: 교전국이 없고 접경국이 있으면 선포, 수도가 고립되면 천도, 금이 많으면 포상.
- 수렴 보조: 일정 연도가 지나도 통일이 안 되면 강국 쪽 출병 가중치를 올린다. **보조를 켠 실행과 끈 실행을 결과에 표시한다.**

### 결정한 시뮬레이터 출력

시드마다 한 줄: `seed, 결과(통일|종료연도), 종료 연월, 승자, 남은 국가 수, 장수 턴 수, 소요 초, 최종 상태 해시`.
같은 시드를 두 번 돌리면 해시가 같아야 한다 (결정성 검사도 겸함).

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 판단 | 단위: 재야 → 임관, 적 접경 + 병력 0 → 모병, 준비 완료 → 출병 |
| 완주 | `pnpm sim --seeds 10`: 10개 모두 통일 또는 종료 연도, 예외 0 |
| 시간 | 같은 명령의 소요 초 ≤ 900 |
| 결정성 | 시드 1개 두 번 → 해시 같음 |

결과 표를 인수조건 증거 칸에 붙인다.

## 구현 기록 (Codex)

- 담당은 Codex다. `packages/rules/src/npc/`, 공통 턴 함수, `apps/engine`의 턴 연결·메모리 실행기,
  `tools/sim/`, 관련 시험과 지정 문서를 수정했다. 하위 구현 담당은 두지 않았다.
- 바꾼 것: 장수·군주 판단이 실행 가능한 후보, 점수, 이유와 선택을 반환한다. 국가 명령을 먼저 실행한 뒤
  장수 판단을 다시 한다. 사람 장수와 사람 군주는 대행하지 않는다. 기존 빈 슬롯 표현인 `rest`와
  `nation_rest`만 자동 선택 대상으로 삼고 NPC의 비휴식 지정 명령과 잘못된 인자는 그대로 실행·거부한다.
  `runGeneralTurn`을 DB 엔진·입력 재생·메모리 시뮬레이터가 함께 쓴다. 시뮬레이터는 실제 1030 리소스의
  491명·94도시를 쓰며 모든 명령 효과와 월간 정산을 실행한다. 중립 도시가 남으면 통일로 세지 않는다.
- 계획과 달라진 점과 이유: 판단에 tick·병종 리소스·수렴 보조 설정을 문맥 인자로 받는다.
  전체 상태의 반복 직렬화 비용을 줄이려고 가변 필드를 모두 분리하는 `cloneWorld`를 추가하고
  첫 효과가 월드 교체이면 버릴 사본은 만들지 않는다. 복제 값·중첩 필드 분리 시험과 기존 재생 회귀를 유지했다.
  94도시·491명 상태의 복제 진단 100회는 `structuredClone` 671.497ms, `cloneWorld` 10.335ms였고
  복제 값은 같았다. 이 진단을 완주 시간 증거로 세지 않는다.
  전투식·성벽 방어 단위·비용·RNG 소비·월간 규칙은 바꾸지 않았다.
- 검증 결과: 소스 `33f67afe317e93d505bb8bebae099d994d89f5e8`의
  [PR CI 39542327712](https://github.com/peppone-choi/opensamguk/actions/runs/39542327712)와
  [push CI 39542324664](https://github.com/peppone-choi/opensamguk/actions/runs/39542324664)에서
  `pnpm check`(단위 303), 실제 PostgreSQL 통합 94, Chromium E2E 26, 웹 빌드가 통과했다. skip은 없다.
  네 job의 `EXPECTED_SHA`가 모두 같은 소스다. NPC 저장·사람 휴식·12개월 재생·commit 오류·펜싱 롤백을 포함한다.

  휴식 회귀 두 시험은 실제 User 소유 장수로 구분했고 국가 실패 기록 시험에는 명시한 농지 개간 예턴을 뒀다.
