## 계획 (Claude)

### 1. 목표

AC-P2-23 제안 문장(U-16 1차 범위에 맞춤): 계략 패 기능을 켠 월드에서 국가마다 패를 3장까지 든다. 패는 계략 4종(화계·파괴·선동·탈취)과 준비 턴 없는 전략 3종(백성동원·이호경식·급습), 엎어 두는 함정 1종이다. 패가 있는 국가의 장수와 군주만 그 명령을 실행하고 실행하면 패 한 장이 사라진다. 함정은 자기 국가 도시에 엎어 두며 적 장수가 그 도시로 출병하면 전투 전에 발동한다. 월간 정산마다 3장 미만인 국가가 시드 RNG로 한 장을 받는다. 다른 명령과 예턴 체계는 그대로다. 같은 시드와 같은 입력이면 결과가 같다. 기능을 끈 월드의 상태 해시, 일곱 명령의 동작, 출병 결과는 지금과 같다.

U-16의 사용자 결정은 아래와 같다.

- 국가당 패 3장.
- 계략 4종(T4-05)과 전략 3종(T4-06)을 패로 쓴다.
- 엎어 두는 함정 1종만 둔다. 적 출병 대상 도시에서 전투 전에 발동한다. 반격 패는 없다.
- 월간 정산마다 시드 RNG로 1장 보충한다.
- 패 그림은 나중이고 글자 패로 시작한다.

| (나) | 명령 가드 자리 연결, 출병 전 함정 자리, 함정 입력 kind 등록, 패 조회·함정 API | Codex → Claude |
| (다) | 국가 패 칸(글자 패), 함정 놓기, 플레이어 가이드 | Claude → Codex |

차별화 원칙(`docs/product/differentiation.md:9-11`, `:177-181`)대로 계략만 패로 묶는다. 명령 37개와 다른 확장 명령은 패와 상관없다. 일곱 명령의 정의 파일(T4-05·T4-06)도 고치지 않는다. 패는 명령 위에 붙는 가드와 소비 단계다.

### 3. 범위와 계약 초안

#### 3.1 패 조각 (가)

```ts
type CardKind =
  | 'fire_attack' | 'sabotage' | 'incite' | 'plunder'
  | 'nation_mobilize' | 'nation_rivalry' | 'nation_raid'
  | 'trap';
// 모두 type alias다. interface는 문자열 인덱스 시그니처가 없어 JsonValue의 객체 갈래에 들어가지 않는다.
type NationCards = {
  hand: CardKind[]; // 받은 순서
  traps: { cityKey: number; setTick: number }[]; // cityKey 오름차순, 도시마다 하나
};
type StratagemCardsSlice = {
  deck: { kind: CardKind; weight: number }[]; // 생성 때 복사, 바뀌지 않는다
  capacity: number; // 3 (U-16)
  trapsCountInCapacity: boolean; // 값은 RQ45-3 결정 뒤 생성 때 복사
  nations: { [nationId: string]: NationCards };
};
export const stratagemCardsSlice: ExtSlice<StratagemCardsSlice> = { key: 'stratagemCards', create, clone, validate };
```

- 조각 key는 `stratagemCards`이고 기능 key `stratagem-cards`로 생긴다(DX-3). 끈 월드에는 key가 없다.
- 조각 값은 JSON 값으로 닫는다. 모든 타입은 type alias이고 선택 칸(`?`)이 없다. 그래서 `StratagemCardsSlice`가 기존 `ExtSlice<T extends JsonValue>`(`packages/rules/src/commands/ext/state.ts:5`)의 `T`에 그대로 들어간다. `JsonValue`의 객체 갈래는 `{ [key: string]: JsonValue }`(`packages/rules/src/model/world.ts:4`)라 인덱스 시그니처 없는 interface는 맞지 않는다. `nations`처럼 key가 열린 칸만 인덱스 시그니처를 쓴다.
- `validate(value: unknown): value is StratagemCardsSlice`는 지금 저장 계약대로 `unknown`을 받아 판정한다. 조각 정의와 사용처에 `any`나 강제 캐스팅을 쓰지 않는다. `nations[id]`는 `noUncheckedIndexedAccess`(`tsconfig.base.json:8`)로 `NationCards | undefined`가 되므로 없는 국가를 빈 패로 다루는 분기를 둔다.
- 상한은 `capacity`(3)이고 함정을 셀지는 `trapsCountInCapacity`(RQ45-3)가 정한다. 운영 값은 결정 뒤에 넣는다.
- 덱은 이 월드에서 켜진 명령 key(T2-02 프리셋 `commands`)에 해당하는 패와 `trap`이고 가중치는 RQ45-2다. 일곱 명령이 하나도 켜지지 않은 월드에서는 `checkOrigin`이 기능 켜기를 거부한다. 덱, 상한, 함정 셈은 생성 때 조각에 사본으로 넣는다(T4-42 DX-2). 조각은 `initial.ext`로 origin에 저장되고 재생은 `initialReplayState`가 같은 사본을 싣는다. 보충과 가드는 조각의 사본만 읽고 내장 덱 정의를 읽지 않는다.
- `validate`: 국가 key는 양의 정수 문자열, 모르는 패 종류, 상한 초과, 도시 중복, 음수 tick을 거부한다.

#### 3.2 보충 (가)

`afterMonthly(state, { tick, date, rng })`(DX-4). RNG는 `rngFor(seed, 'feature', 'stratagem-cards', year, month)`이다.

1. 조각에서 지금 없는 국가의 항목을 지운다. 도시 주인이 바뀐 함정(도시의 `nationId`가 그 국가가 아님)을 지운다. RNG를 쓰지 않는다.
2. 국가를 id 오름차순으로 돈다. 상한에 못 미친 국가만 RNG 한 번으로 조각의 `deck`에서 가중치대로 한 장을 골라 `hand` 끝에 넣는다. 뽑기는 가중치 합 W에 대해 `rng.int(0, W − 1)` 한 번이다. 상한에 찬 국가는 RNG를 쓰지 않는다.
3. 국가 기록은 남기지 않는다. 패 종류가 다른 국가 기록으로 새지 않게 하기 위해서다.

새로 세운 국가(건국·거병)는 빈 패로 시작해 다음 월간 정산부터 받는다. 시나리오 시작 국가의 시작 패는 RQ45-7이다.

#### 3.3 명령 가드와 소비 (가)·(나)

일곱 명령의 정의를 고치지 않고 기능 정의에 두 자리를 둔다. 이 두 자리를 resolver와 `turn.ts`가 부르도록 T4-02·T2-26에 요청한다(DX-9 요청, §8 Z45-1).

```ts
interface RuleFeatureCommandHooks {
  // 켠 기능마다 key 오름차순으로 부른다. precheck·check·execute 앞에서 같은 결과를 낸다.
  commandGuard?(view: WorldView, actor: Actor, commandKey: string): Failure | null;
  // 명령이 성공으로 끝나 효과가 적용된 직후. 실패(Failure)면 부르지 않는다.
  afterCommand?(state: WorldState, actor: Actor, commandKey: string): WorldState;
}
```

- 가드: `commandKey`가 일곱 명령이고 행위 장수 국가의 `hand`에 그 종류가 없으면 `{ code: 'BAD_STATE', message: '이 계략 패가 없습니다.' }`. 다른 key는 `null`.
- 소비: 같은 일곱 명령이 성공으로 끝나면 `hand`에서 그 종류의 첫 장을 지운다. 계략의 확률 실패(T4-05 §4.3 끝)는 비용을 쓴 정상 결과이므로 패도 쓴다. 검사 실패는 패를 쓰지 않는다.
- 같은 국가 장수 둘이 한 장뿐인 화계를 같은 달에 예약하면 먼저 실행된 쪽만 성공하고 뒤쪽은 가드에서 실패한다. 턴 순서는 지금 엔진 순서 그대로다.
- 전략 3종의 재사용 대기(T4-06)와 직책 검사는 그대로다. 가드가 먼저 실패하면 대기 검사는 보지 않는다.
- T4-07 `trackTurn`도 같은 `afterCommand` 자리로 합치자고 제안한다. 둘 다 `applyEffects` 뒤 같은 위치다.

#### 3.4 함정 놓기 (가)·(나)

함정은 턴을 쓰지 않는 즉시 입력으로 놓는다(RQ45-4 권장). kind `stratagem-cards.set_trap`, payload `z.strictObject({ cityKey: positive })`(DX-5).

| 순서 | 조건 | code |
| ---- | ---- | ---- |
| 1 | 기능이 꺼짐 | `FEATURE_DISABLED` (T2-26 공통) |
| 2 | 행위 장수가 없거나 국가가 없음 | `NO_GENERAL` (T4-49 공통) |
| 3 | 행위 장수가 군주가 아님 (RQ45-5) | `NOT_RULER` |
| 4 | `hand`에 `trap`이 없음 | `NO_TRAP_CARD` |
| 5 | 도시가 없거나 자기 국가 도시가 아님 | `BAD_CITY` |
| 6 | 그 도시에 이미 함정이 있음 | `TRAP_EXISTS` |

통과하면 `hand`에서 `trap` 한 장을 지우고 `traps`에 `{ cityKey, setTick: tick }`을 넣는다. 함정 수는 패 상한 안에서 센다. `whilePaused`는 `hold`다.

#### 3.5 함정 발동 (가)·(나)

- 자리: `attack.ts`의 `change`에서 수비 장수를 고르기 전(`attack.ts:57` 근처)에 `hasRuleFeature(state, 'stratagem-cards')`일 때만 `springTrap(state, attackerId, cityKey)`를 부른다.
- 조건: 대상 도시의 주인 국가 항목에 그 도시 함정이 있고 출병 장수가 그 국가 소속이 아니다.
- 효과: 출병 장수의 병력 `crew`를 `round(crew × (1 − c))`로, 사기 `atmos`를 `max(0, atmos − a)`로 바꾼다. c·a는 RQ45-1이다. 함정 계산 자체는 RNG를 쓰지 않는다.
- 출병 전체의 RNG 소비 횟수는 함정이 발동하면 달라질 수 있다. `simulateBattle`의 페이즈 반복은 양쪽 병력과 사기가 0보다 클 때만 돈다(`packages/rules/src/battle/simulate.ts:63-66`). 병력·사기가 줄면 페이즈 수와 교전 수가 바뀌어 뒤 RNG 소비도 바뀐다(T4-18 §2.4와 같은 성질). 그래서 보장은 넷으로 한정한다. 함정 계산은 RNG를 쓰지 않는다. 끈 월드의 출병은 지금과 RNG 소비·결과가 같다. 켠 월드라도 함정이 없는 도시의 출병은 지금과 같다. 함정이 발동한 출병은 같은 시드·입력에서 결과가 같다.
- 함정은 그 자리에서 지워진다. 함정 뒤 출병 장수의 병력이나 사기가 0이면 지금 출병 코드는 아래처럼 흐른다(main `53dd348`, `packages/rules/src/commands/attack.ts:61-167`). 출병 검사(`attack.ts:42`)는 함정 전에 끝났으므로 다시 막지 않는다.

| 경우 | 지금 코드의 흐름 |
| ---- | ---------------- |
| 적격 수비 장수가 있음 (병력 0 또는 사기 0) | 첫 수비 장수에서 반복에 들어간다. `feed(g)`, `feed(defender)`가 돈다(`:78-79`). 출병 장수는 병력이 0이면 군량이 줄지 않는다. 사기만 0이면 병력만큼 군량이 준다. 군량이 0이면 굶주림 사기 감소가 걸린다(`:12-15`). 수비 장수는 병력만큼 군량이 줄고 0이 되면 사기가 준다. `simulateBattle`은 페이즈 0회로 입력을 그대로 돌려준다(`battle/simulate.ts:63-66`). 수비 장수가 살아 있으면 수비 장수에게 승리 1(`:103-104`), 교전 문구와 수비 장수 보고가 남고(`:105-107`) 반복이 끝난다(`:108-111`). 성벽 교전·점령은 없고 양쪽 국가 기록에 점령 실패가 남는다(`:163-166`) |
| 적격 수비 장수가 없음 (병력 0 또는 사기 0) | 반복을 건너뛰고 `cleared`는 `true`로 남는다. 성벽 교전은 `g.crew > 0 && g.atmos > 0` 조건에서 막히고(`:113`) `feed`도 돌지 않는다. 성벽이 0이어도 점령은 같은 조건에서 막힌다(`:136`). 승리·포로 기록 없이 점령 실패 기록만 남는다 |

  그래서 교전 없이 끝난다는 말은 페이즈와 성벽 교전이 없다는 뜻이다. 수비 장수가 있으면 수비 측 군량 소비와 승리 1이 생긴다. 이 경계를 그대로 둘지는 §7 Z45-3이다. 효과 수치(RQ45-1)는 정하지 않는다.
- 기록: 출병 장수 로그 `{도시}: 함정에 걸려 병력 N, 사기 M을 잃었습니다.`, 수비 국가 기록 `{도시}: 함정 발동`.
- 끈 월드와 함정 없는 도시는 지금 출병과 바이트가 같다(T4-33 골든).

다른 국가의 패 종류, 패 수, 함정 위치는 응답에 넣지 않는다(RQ45-6). 함정은 엎어 두는 패라 상대가 미리 알면 뜻이 없다. 예턴 화면의 명령 목록은 고치지 않는다. 패가 없으면 지금 사전 검사 경로가 가드의 실패 문구를 그대로 보인다.

글자 패의 문구는 명령 이름과 한 줄 설명이다. 그림은 만들지 않는다(C12, 승인 항목 A-09).

### 4. 하지 않는 것

- 반격 패, 함정 2종 이상, 패 교환·버리기.
- 명령 전체를 패로 바꾸기. 일곱 명령 밖의 명령은 패와 상관없다.
- 준비 턴 있는 전략 5종(T4-08)과 특수 병종 연구를 패로 쓰기.
- 패 그림과 카드 장식.
- NPC가 패를 쓰거나 함정을 놓는 판단(C11).
- 일곱 명령 정의 파일과 `ext/registry.ts` 등록 줄 수정.
