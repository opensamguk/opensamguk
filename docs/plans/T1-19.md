# T1-19 시나리오 장수 초상 ID 대응

> 대기열: T1-19 · AC: AC-M1-20 (데이터) · 구현: Codex · 리뷰: Claude
> 선행: T1-03 · 관련: [이미지 자산](../image-assets.md) §2 · T1-17 계획 중 생긴 작업

## 계획 (Claude)

### 목표

시나리오 장수(한글 이름)에 초상 ID(10001~11000)를 붙여, 화면에 실제 초상이 나오게 한다.

### 배경

- 시나리오 장수 이름은 한글(`조조`), 이미지 저장소의 `portraits/rtk14/officer-id-registry.tsv`는 한자 이름(`曹操`)·가타카나 읽기·ID다.
- 한글과 한자를 잇는 표가 없으므로 만든다.

### 범위

- `tools/portrait-map/`: 대응표 생성 스크립트 (한 번 돌리고 결과를 커밋)
- `resources/portraits/rtk14-map.json`: `{ "조조": 10006, … }` (+ 동명이인 처리 정보)
- `packages/rules/src/world/bootstrap.ts`: 월드 생성 때 이름으로 `portraitId`를 채움

### 결정

1. 한자 이름을 한글 독음으로 바꾼다 (한자→한글 독음 표. 두음법칙 예외는 수동 표로).
2. 독음이 시나리오 이름과 정확히 같으면 대응. 동명이인(같은 독음 여러 ID)은 생몰년으로 가린다 (registry에 없으면 수동).
3. 대응 못 한 이름은 목록으로 출력하고 `portraitId = null`.
4. 결과 통계(대응 수 / 491)를 이 문서의 구현 기록에 남긴다. 목표 80% 이상 ⚠️.

### 하지 않는 것

새 초상 제작, 라이선스 결정(M3 T3-12).

### 검증

- 단위: `曹操 → 조조`, `劉備 → 유비`, 두음법칙 예(`李 → 이`)
- 단위: 동명이인 규칙
- 통합: 월드 생성 뒤 `portraitId`가 채워진 장수 수 ≥ 목표

### 채울 문서

구현하면서 함께 채운다. 리뷰어는 문서도 확인한다.

- `docs/image-assets.md §2 (대응표 위치·적중률)`

## 구현 기록 (Codex)

- 바꾼 것: 고정된 registry 1000명과 한자 독음 805자의 출처·라이선스를 보존하고, 오프라인 대응표 생성 명령 `pnpm portraits:map`을 추가했다. 두음법칙과 성씨 예외를 적용하고 새 월드에 portraitId를 저장한다. 생성물은 `resources/portraits/rtk14-map.json`, 수동 수정 원본은 `tools/portrait-map/manual.json`이다.
- 계획과 달라진 점과 이유: **491명 중 429명(87.37%)**을 대응했다. 생몰년 없는 registry만으로 동명이인 12명을 추측하지 않았고, 미대응 50명과 함께 null로 두었다. 두 집단은 2026-10-20 사용자 요청에 따라 후속 추가·수정 대상으로 남긴다. 후보·미대응 목록을 생성물에 보존하며, 확인한 registry ID·근거를 수동 표에 넣으면 재생성 후에도 유지된다. 기존 월드는 변경하지 않는다. 계획의 조조 ID 예시는 실제 registry ID 10405로 바로잡았다.
- 검증 결과: 이름 독음·두음·전통자 예외, 동명이인 후보·수동 근거, 생성물 일치·범위·중복 검사 단위 4개 통과. `pnpm test:int` 12개 통과, 실제 DB에 저장된 429/491명 및 조조 10405·모호한 고승 null·재적재 해시 일치 확인. `pnpm check` 전체 단위 83개·lint·타입 통과, `pnpm e2e` 13개 통과. AC-M1-20의 화면 URL·기본 이미지 부분은 T1-17과 반대쪽 리뷰 뒤 완료 판정한다.

## 리뷰 (Claude)

- 결과: **통과** (2026-10-20). 대기열 T1-19를 `완료`로 바꾼다. AC-M1-20은 화면 쪽(T1-17)이 끝나야 ✅가 된다.
- 리뷰 대상: 커밋 `0b7ec38`에 T1-19 파일만 얹은 스냅샷 (`portraits:map` 스크립트 한 줄 포함).
- 확인한 것:
  - `pnpm check` 61개, `pnpm test:int` 8개 통과 (별도 DB, 끝나고 삭제). 대응표를 다시 생성하면 바이트 단위로 같은 파일이 나온다 (네트워크 없이).
  - 출처: registry와 독음표 모두 고정 커밋 링크로 남겼고, 독음표는 WTFPL(제한 없음). registry는 메타데이터만 복사, 그림 없음.
  - 정확도 표본: 유명 장수 30명 중 대응된 25명이 모두 맞다 (조조 10405 曹操, 관우 10853 関羽, 제갈량 10748 諸葛亮, 사마의 10129 司馬懿 …).
  - 새 월드에만 적용하고 기존 월드는 건드리지 않는다. 채울 문서([이미지 자산](../image-assets.md) §2) 채워짐.
- 고칠 것: 없음. 미대응·동명이인은 사용자 요청대로 후속으로 남긴다.
- 후속 작업 근거 ([백로그](../product/backlog.md)에 등록):
  - **이름 끝 숫자**: 시나리오는 같은 이름을 `노숙1`, `순욱1`, `유표1`·`유표2`처럼 숫자로 구분한다. 이런 이름 31개가 숫자 때문에 전부 빠졌다.
    미대응·동명이인 62건의 절반이며 순욱·노숙·유표·우금·전위·조홍·장소 같은 주요 인물이 포함된다. 숫자를 떼고 같은 규칙으로 맞추면 최대 +31명(약 94%).
  - **독음이 하나뿐**: 寧은 `령`만, 闞은 `함`만, 禕는 `의`만 있어 `감녕`·`감택`·`비위`를 놓친다. 글자마다 여러 독음을 허용하면 더 늘어난다.
