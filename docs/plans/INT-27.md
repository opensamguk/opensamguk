## D-096 적용 경계

`siteClassification: 'd096'`가 있는 새 지도에만 분류를 적용한다. CITY의 0~3은 소유하지 않는 작은 지점이며 4는 이민족 본거, 5~9는 도시 크기다. 기존 PASS는 소유 가능한 관문이다. 3판은 `capturableFields: true`를 명시하고 FIELD 38곳에도 앵커·지역을 둔다. 원본의 `city:` ID와 앵커는 분류가 FIELD로 바뀌어도 보존한다.

내부 지도 CITY의 `anchorKey`는 원본 대응 키로 보존하지만 작은 지점은 전략 그래프·월드 도시·공개 소유 앵커에 넣지 않는다. 공개 고정 지리는 `siteLevel`과 최대 600자의 `description`을 더한다. 작은 지점과 구판 FIELD의 `anchorKey`는 생략하며 3판 FIELD는 앵커를 보낸다. `level` 대신 `siteLevel`을 써서 구판 원시 지도에 있던 경제 규모 값이 새 공개 분류로 해석되지 않게 한다.

작은 지점과 구판 FIELD를 거치는 길은 다음 전략 거점까지 잇는다. 전략 거점에서 탐색을 멈추므로 관문이나 3판 FIELD 너머를 직접 잇지 않는다. 단방향·비활성 길을 지키고 LAND·FORD·BRIDGE·RIVER·SEA를 보존한다. 같은 쌍의 육로와 물길은 별도 간선이다. D-096 물길은 항구 시설을 강제로 추가하지 않고 지점 사이를 직접 잇는다. 구판의 RIVER 항구 검증은 유지한다.

시나리오 소유 목록에서 비소유 표식을 빼고 개명한 지명을 반영한다. 남는 도시가 없으면 국가와 장수 소속을 보존한 무도시 국가로 시작한다. 수도가 표식이면 남은 소유 CITY 가운데 원본 순서상 첫 도시를 쓴다. 장수의 표식 위치는 미지정으로 바꾸고 기존 엔진의 시드 배치를 쓴다. 표식 소유를 이웃 도시 소유로 옮기지는 않는다.

## 검증과 인계

지도 시험은 전체 연결·표식 경유·방향·관문에서 탐색 중지·동일 쌍 복수 길·공개 필드·원생성·직렬화 재적재·해시·구판 그래프와 잘못된 입력을 확인한다. 재수입한 91개 시나리오는 각각 자원 검사와 원생성을 거친다. 실제 DB 저장·재적재와 E2E는 별도 인수이며 이 작업에서 통과로 보고하지 않는다.

FIELD 점령은 `capturable-field-v1`과 지도 원장의 표시가 일치해야 한다. 출병과 전투 점령은 관문과 같은 순서를 쓰며 기본 소유는 null이다. 경제 수치와 최대치는 0이고 영지·세수·인구 증가·내정·모병·수도·건국·창고 효과는 없다. 마지막 경제 도시를 잃으면 남은 FIELD가 국가 멸망을 막지 않는다. 기존 수도 연결 보급 표시는 관문과 같이 거친다. R3 이동 예산·재충전은 구현하지 않는다.

공개 지도와 인증 지도는 새 기능 월드에서 `siteOwnership: Array<{anchorKey: number; nationId: number | null}>`를 보낸다. 지연 사본도 같은 배열을 보존한다. `home.get`과 `general.mine`의 내 장수는 `courtTitle: string | null`을 보내고 관직 기능이 꺼져 있으면 null이다.

`lobby.headlines`는 공개 국가 원장만 읽는다. 공개 지도 사본과 같은 시간 지연을 적용하고 사본을 찍을 때 저장한 마지막 사건 ID로 상한을 정한다. 같은 턴의 나중 사건과 밀린 턴 처리도 이 경계를 넘을 수 없다. 구사본에 경계가 없으면 빈 목록을 반환한다. 사건 당시 국가 이름·색은 새 JSON 열에 보존하며 구기록은 빈 배열로 남긴다.

로비는 정원·등록 마감·NPC 수·살아 있는 국가 수·설정 요약·현재 PREOPEN 정보·가능한 참가 방식을 더한다. 저장되지 않은 다음 리셋·확정 시작 일시는 null이다. 오픈 요청은 사용자 동의 원장과 관리자 승인 뒤 기존 생성 요청에 멱등 접수하는 설계만 남긴다.

## 2026-11-15 R3·D-098 후속 구현 상태

요청서10·12·13절과 D-097·D-098이 앞의 구판 보존·빈 부곡 편성 설명보다 우선한다. AC-INT-28의 행군 SP와 AC-INT-19A의 부곡 생성 계약을 구현·검증 중이며 AC를 완료로 바꾸지 않는다. 12절의 월드별 규칙 기능 제거와 모든 기능 기준 골든 전환은 미완료다.

새 확장 지도는 INT-28의 45도 회전 8단위 영지 격자를 생성 원장과 공개 지도의 `operationalMap.territory`에 저장한다. 경로 선분이 거치는 칸을 순서대로 기록한다. 영지 칸은 부모 도시를 따르고 관문·전장·부속 현은 거점 칸에서만 그 거점의 현재 소유국을 적용한다. 육상에서 고도 1,500m 이상인 칸은 산으로, 가장 가까운 거점에서 연결된 땅길로 12칸을 넘는 육상 칸은 오지로 계산한다. 수로와 해로에는 산·오지 배율을 적용하지 않는다. 출발 칸과 경계의 중복 칸은 차감하지 않는다. 미리보기와 전술 지도에서 같은 `cellId`를 쓴다. 8단위 영지 정보가 없는 기존 원장의 16단위 격자는 재생용으로 유지한다.

turns.precheck의 supply는 승인한 SP·소모·고갈 칸·경로/소유/외교 판 계약을 반환한다. campaign.get.units[].supply는 feature·unit·loaded·remaining만 공개한다. 실제 차감·고갈·복귀는 엔진 명령이 적용하는 순수 상태 변경 안에서 처리한다. 새 위치 미지정은 cityKey0이고 home.get.city는 null이다. General의 생성 열 cityAnchorKey가0 외 위치의 기존 도시 외래키를 유지하며 규칙 상태와 재생 해시에서는 이 DB 열을 제거한다.

모병·징병은 unitId:'new'로 자기 소유·지휘 부곡을 만들고 unitId:number로 기존 자기 부곡에 보충한다. 도시 자원 판의 비용·인구·물자는 기존 도시 모집 규칙을 쓴다. 도시 병력 배속은 unitId:'new', recipientId:number를 받아 수령 장수의 부곡을 만든다. 기존 unitId:number에는 recipientId를 받지 않는다. city.resources 결과는 요청 대상과 처리 revision·tick을 재생 검증한다. 도시 조회의 newUnitRecipients가 새 부곡 수령 후보와 지휘 상한을 알린다.

검증 결과와 정확한 계약 인계는 커밋하지 않는 private/int27/claude-server-map-3.txt에 남긴다. 실제 DB 적용·독립 검토의 미해결·병합 상태를 구분한다.

## 2026-11-15 국가 명령 상신

REQUEST-PROPOSALS.md의 후속 승인을 AC-M1-14에 연결한다. 제안자가 직접 실행할 수 없는 국가 명령을 같은 국가 권한자에게 올린다. 기존 국가 예턴 저장 함수로 승인자의 직책 칸을 편집하고 제안 원장을 함께 닫는다. 공헌과 개인·국가 기록은 proposal.record 엔진 입력으로 처리하며 공헌은 재생에서도 검증한다.

기본값은 12턴 만료, 제안자당 열린 제안 3건, 승인 공헌 10이다. 인자는 해당 명령 스키마로 검사하고 같은 명령·같은 인자의 중복을 막는다. 희망 칸은 0~11이며 승인자가 바꿀 수 있다. 직위·소속·제거 전환은 엔진 저장 때 원장을 닫는다. 기한 만료와 승인자 부재도 조회·응답 시 종료로 판정한다. 받은 목록은 현재 명령 권한자만 읽고 보낸 목록도 현재 자기 국가 안으로 제한한다.

proposals.commands는 상신 가능한 명령과 인자 스키마를 반환한다. proposals.history는 현재 자기 국가의 최근 상신 기록 30개를 읽는다. proposals.create·list·respond·cancel과 메뉴의 useInboxCount를 연결한다. 제안 작성·답변 화면은 Claude 담당이다. 개인 기록 kind는 proposal이고 국가 기록은 NationHistory.data.proposals에 같은 kind와 본문을 저장한다. API가 제안 원장과 예턴 편집을 저장하고 엔진이 기록과 승인 공헌을 적용하므로 공헌·기록은 입력 처리 후 보인다.

새 migration 20261220000000_command_proposals가 필요하다. 실제 DB 연결·E2E·독립 Claude 리뷰 전에는 AC를 완료로 바꾸지 않는다. API 형식과 실행 증거는 커밋하지 않는 private/int27/claude-proposals.txt에 남긴다.
## 2026-11-15 도시 상태·부속 현·목적지 이동

REQUEST-CITY-STATE.md의 D-101·102·103 후속 승인을 AC-INT-27·28, 세수는 AC-INT-18A, 명령은 AC-M1-14에 연결한다. 이 후속 요청은 앞 절의 CITY0~3 비소유 설명 중 수1·현2를 대체한다. 확장 지도는 전략 거점323곳이며 부속 현105곳의 parentCityKey를 자료에 고정한다. 기존 작은 지점 경유 지름길 대신 현과 수에서 전략 그래프 탐색을 멈춘다.

도시 상태와 기간은 City, 이동 진행은 General.movePath에 저장한다. 새 migration 20261221000000_city_state_counties가 필요하다. 월 정산과 재생은 city-disaster 시드 스트림을 쓴다. 도시 키 순으로 대상 확률을 먼저 굴리고 사건 하나를 고른 뒤 수의 물 재해 여부를 거른다. 관·진은 대상 확률 난수를 쓰지 않는다. 남은 도시·장수 키 순으로 부상 확률과 부상량을 굴린다. 시작3년 유예에는 난수를 쓰지 않고 이전 재해 표시만 지운다.

commands.moveTargets와 commands.attackTargets는 요청서 형식의 배열을 반환한다. path는 출발 거점을 포함한다. 이동 속도는 길 구간 두 개당 한 턴(올림)이며 남은 경로가 있으면 다음 장수 예턴을 계속 이동에 쓴다. 경로 소유가 바뀌면 앞 거점에서 중단한다. 지도 응답은 state·stateTerm·parentCityKey·detached와 emperorCityKey를 더한다. 안개가 켜지면 공개 사본에서 상태를 빼고 인증 지도에서는 자기 국가나 현재 위치의 상태만 보인다.

전술 전투 묶음 잠금 기능은 현재 작업 트리에 없다. 진행 중43 유지와 부속 현의 전술 묶음 편입은 해당 구현과 연결하기 전까지 미완료다. 화면의 영지 칠하기는 Claude에게 parentCityKey·detached를 인계한다. SP 칸 원장은 현의 넓은 영지를 부모에 합치고 현의 거점 칸 소유만 따로 남긴다. 실제 검증 결과와 독립 리뷰는 커밋하지 않는 private/int27/claude-city-state.txt에 기록한다. 독립 인수·실제 DB·병합 전이므로 AC 상태는 진행 중으로 둔다.
