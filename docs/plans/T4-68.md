## 계획 (Claude)

### 목표

AC-M1-14의 이 명령 몫이다. 원작 `general:che_장수대상임관`에 대응하는 확장 명령 `join_general`이 켠 월드에서 재야 장수를 고른 장수의 국가에 임관시키고 그 장수가 있는 도시로 옮긴다. 성공 1건과 대표 실패 1건 단위 시험이 있고 같은 입력이면 결과가 같다. 저장 이후 단계 증거는 T4-03·T4-04 뒤 같은 ID 아래에서 받는다.

### 하지 않는 것

- 기존 `join`·`join_random`(`commands/personnel.ts:53-79`)의 동작 변경. 같은 검사를 쓰고 싶으면 그 파일을 고치지 않고 이 명령 파일에 둔다.
- 국가 정원 정책을 새로 정하는 일. T2-02 P6는 사용자가 이미 승인했다. 기수 내내 사람 장수만 국가 정원으로 센다. 넘친 인원은 내보내지 않는다. 예턴 저장은 자리 예약이 아니며 실행 때 다시 검사한다. 공식 네 프리셋은 무제한(`null`)이다. 이 명령은 그 규칙을 바꾸지 않고 기존 임관과 같은 검사를 반드시 거친다(§4.2 7번). 지금 스키마가 `null`만 받는 것(`world/preset.ts:10-11`)은 T2-02 구현 순서의 기술 경계이며 P6가 미결이라는 뜻이 아니다.
- 임관 금지 국가 설정, 국가 이름 접두어 제한, 재야 뒤 대기 턴. 우리에게 세 상태가 모두 없다(§2.2). MQ-2 (가)가 넣기로 하면 상태를 만드는 작업이 따로 필요하다.
- 아이템 추첨(U-06), 화면(T4-04가 대상 장수 선택 행을 만든다), NPC 판단(C11).

### 4. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 4.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `join_general` | 장수대상임관 | `strategy` | `general` | `z.strictObject({ generalId: positive })` |

인자 이름은 우리 `invite`의 `generalId`(`personnel.ts:106`)에 맞춘다. 원작 `destGeneralID`는 옮기지 않는다. 범주는 기존 `join`(`personnel.ts:57`)과 같은 `strategy`다. 국가·도시·관직을 바꾸므로 `Effect`에 맞는 필드가 없다(`commands/effects.ts:7-11`). 기존 `join`처럼 `defineCommand`를 쓰고 `{ kind: 'world' }` 효과를 낸다. 이 명령의 RNG는 없다.

#### 4.2 검사 순서와 실패

MQ-2 권장안을 넣은 모양이다.

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | 장수 없음 | `NO_ACTOR` | 장수가 없습니다. (`defineCommand`가 한다, `support.ts:37`) |
| 2 | 인자 형식 | `BAD_ARGS` | 명령 인자가 잘못되었습니다. (`support.ts:38-39`) |
| 3 | 행위자가 재야가 아님 | `BAD_STATE` | 재야 장수만 임관할 수 있습니다. (`personnel.ts:61`과 같은 문구) |
| 4 | 대상 장수가 없거나 행위자 본인 | `BAD_TARGET` | 따라갈 장수를 골라야 합니다. |
| 5 | 대상 장수가 재야 | `BAD_TARGET` | 국가에 소속된 장수만 따라갈 수 있습니다. |
| 6 | 대상 국가가 수도를 갖지 않음 (J3 (가)) | `BAD_TARGET` | 임관할 국가가 없습니다. (`personnel.ts:65`와 같은 문구) |
| 7 | P6 사람 정원. 프리셋 `protection.maxGeneralsPerNation`이 수인 월드에서 사람 행위자(`userId !== null`)가 사람 장수 수가 그 수 이상인 국가로 들어감 | T2-02 정원 검사 함수의 code | T2-02 정원 검사 함수의 문구 |

행위자는 재야이므로 4의 본인 검사는 5에 앞서 걸리게 따로 둔다. MQ-2 (가2)를 고르면 7 뒤에 원작 초반 제한 검사가 붙는다.

7번은 선택이 아니다. 승인된 P6대로 아래를 지킨다.

- 검사 함수는 T2-02가 기존 `join`·`join_random`·`accept_invite`에 쓰는 순수 함수 하나다([T2-02 계획](./T2-02.md) `maxGeneralsPerNation` 행). 이 명령은 같은 함수를 부르고 조건을 따로 복제하지 않는다. 그래서 code와 문구도 그 함수를 따른다.
- 세는 대상은 대상 국가의 사람 장수(`userId !== null`)뿐이다. NPC 장수는 세지 않는다. NPC 행위자는 정원 검사를 받지 않는다.
- 값이 `null`(공식 네 프리셋)이면 검사를 건너뛴다.
- 예턴 저장 때 통과해도 자리를 잡아 두지 않는다. resolver는 실행 때 `check`를 다시 부르므로(`commands/resolve.ts:61-65`) 저장 뒤 다른 장수가 임관해 정원이 차면 실행이 실패한다.
- 정원을 넘은 기존 소속 장수는 내보내지 않는다. 이 명령은 새로 들어오는 행위자만 막는다.

#### 4.3 실행

`change(state, actor, args)`가 아래를 바꾼다.

- `general.nationId = 대상 국가`, `general.officerLevel = 1`.
- `general.cityKey = 대상 장수 도시`. 그 도시의 `nationId`가 대상 국가가 아니면 대상 국가 수도(J4 (나)).
- `state.commandMeta`가 있으면 `offers[general.id]`를 지운다. 기존 `join`과 같다(`personnel.ts:76`).
- MQ-2 (나)에서 경험을 주기로 하면 `general.experience += 값`. 기준 인원은 `activeFromYear <= 현재 연도`인 대상 국가 장수 수다. 출병 수비 장수의 기준(`commands/attack.ts:70`)과 같은 거르기이며 기술 검토 쟁점 R3이다.

T2-05의 `syncOffices`(직책 5~12 변화 감시)는 관직 1 임관과 닿지 않는다. T2-05가 먼저 병합되면 그 함수가 이 명령 뒤에도 변화 없음을 내는지 시험 한 건을 더한다.

| ---- | ---- |
| `logs` | `{국가} 임관: {대상 장수}를 따라감` |

### 6. 상대 영역에 필요한 것

- T4-04(Claude): 인자 입력 행 하나. 대상은 같은 월드의 국가 소속 장수이며 목록은 기존 장수 조회 API로 받는다. 다른 국가 장수의 비공개 값은 보이지 않는다(C9). 장수 도움말에 한 줄.
- T2-02(Codex): 승인된 P6 사람 정원 검사를 순수 함수 하나로 내보낸다. 입력은 상태, 대상 국가, 행위자이고 결과는 실패 또는 통과다. `join`·`join_random`·`accept_invite`와 이 명령이 같은 함수를 부른다. 이 연결이 이 명령의 구현 선행이다(§8).
- T2-05(Codex): 관직 1 임관이 직책 칸에 닿지 않는다는 시험을 함께 본다.
