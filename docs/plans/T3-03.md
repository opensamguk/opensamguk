# T3-03 가입·재설정·약관·탈퇴 화면

## 2026-10-29 현재 문서와 가입·재동의 연결 (AC-M3-02 일부)

사용자의 프론트 인계에 따라 Codex가2작업일 범위로 가입 체크·공개 본문·재동의와 게임 진입을 연결한다. 선행은 T3-02의 발행 본문 불변성과 기대 계정 조건이다. 선행 PR290이 필수CI8개·정상 대기열8개와 독립 리뷰를 통과해 main875d38b에 병합됐고 그 main을 화면 브랜치에 정상 통합했다. 결합판 검증·독립 리뷰·필수CI·보호 병합을 마쳐야 이 묶음의 완료다. 실제 정책 승인·탈퇴·보존안과 전체AC는 남긴다.

가입 화면은 `legal.current`가 답한 두 문서의 판·시행일·본문을 체크와 묶는다. 요청 직전 다시 조회해 달라지면 입력을 보존하고 새 동의를 요구한다. 조회 전·오류·본문 없는 현재 판·운영 승인 대기에는 가입을 보내지 않는다. 서버가 비필수라고 답한 개발 대기 상태만 기존 개발 가입을 유지한다. 현재 본문은 `/legal/terms`·`/legal/privacy`에서 텍스트로 읽고 판과 한국 시각의 시행일을 확인한다.

루트·게임·알림 가드와 가입 성공 이동은 이메일 인증을 먼저 확인한 뒤 필요한 동의를 `/legal/agree`로 보낸다. 실제 변경의403과 `CONSENT_REQUIRED`도 같은 경로를 쓴다. 재동의 화면은 서버가 요구한 문서만 직렬로 보내고 모든 요청에 서버가 확인한 기대 계정 ID를 붙인다. 부분 성공은 보존하고 실패 뒤 자동으로 쓰기를 반복하지 않는다. 새 조회와 focus·blur·offline·숨김은 이전 표시와 체크를 소거한다. 마지막 동의 뒤 실제 신원·현재 판·계정 상태를 다시 확인해 안전한 원래 목적지로 간다. 예약과 초안은 지우지 않는다.

`pnpm build:public` 뒤 `pnpm e2e:legal`은 기존 개발 서버를 공유하지 않고 실제 공개 dist·API·전용PostgreSQL을 기동한다. 기본 개발 검사와 분리한 이 검사는 CI shard1의 필수 단계다. 준비·본문 부재·조회 실패의 가입0, 두 체크·현재 판 변경·실제 동의 기록·이메일 우선·부분 실패·중복 클릭·마지막 신원 조회 뒤 계정 전환을 확인한다. 정식191년 두 월드·491NPC·21국·사람 장수·30예약과 실제403 뒤 같은 월드 초안 복구도 포함한다. 자기 서비스 종료·환경 복원·같은DB OID·연결0을 확인하며 실패한 자기 DB는 보존한다. 승인 정책은 null이며 시험 본문을 운영에 쓰지 않는다.

## 2026-10-29 정식 시나리오 인수 정리 경합 (AC-M3-01 일부)

main cccda103의 push CI40722241243에서 정식191년 인증 인수 본문 뒤 월드 삭제가 교착되고 후속 계정 삭제가 General 외래키로 실패했다. 시험은 실행권을 먼저 놓아 감독의 Lease→World 잠금과 World 삭제의 cascade가 엇갈렸다. 이 실패는 앞선 보호 병합 성공과 별도로 보존한다.

자기 페이지를 닫고 갱신 작업을 정착한 뒤 `heldWorldCleanup.ts`가 유효한 자기 실행권을 Lease→World 순으로 잠근다. World 잠금 뒤 삭제 직전에도 소유자·fencing token·DB 시각 만료를 확인하고 자기 시험 UUID 월드만 삭제한다. 만료·소유 변경·실패면 월드와 연결 계정을 보존한다. 본문·페이지 종료·월드 정리·DB 종료 오류를 함께 남긴다. 제품 엔진 잠금 순서·게임 규칙과 사용자 점검 환경은 바꾸지 않는다.

실제 PG 반례는 차단 PID와 Lease 보유자의 World 잠금 성공, 자기 월드 삭제·다른 정식 월드 보존, 소유 변경·이미 만료·World 대기 중 만료의 거부를 검사한다. 필수 인증 Chromium5건·전체check·공개검사·최종 독립 리뷰·필수CI·보호 병합은 아직 진행 중이다. 이 정리 보완을 전체 계정·동의·탈퇴 완료로 세지 않는다.

실제 PG4건은11.89초에 통과했다. Lease를 잡은 외부 연결 때문에 기다리는 정확한 PID를 확인했고 그 연결의 World 잠금이 성공한 뒤 자기 월드만 삭제됐다. 다른 정식 월드의 저장값은 같았다. 소유 변경·만료·World 대기 중 만료는 실제 LeaseLostError로 거부하고491NPC·14,730예약을 보존했다. 자기 DB 연결0과 동일OID를 확인해 자기 DB만 삭제했다. 생성자에 가짜 DB나 시간을 주입하지 않았다.

최종 코드의 실제 필수 인증 Chromium5건은26.9초에 통과했다. 정식191년 장수 생성·사람30칸 저장·실제403 뒤 같은 월드 초안 복구를 확인했고 자기 API·web·engine은 모두0으로 종료했다. 공개105자산·승인 이미지6·외부 초상0, 실제 공개 Chromium4건(4.4초), 자기 DB 연결0·같은OID·자기 DB 정리도 통과했다. 전체 `pnpm check`는 단위293파일5336건을 포함해 통과했으며 단위 실행은269.61초였다. 검사 중 소스 해시는 바뀌지 않았다. 최종 독립 증거 검토·새 필수CI·정상 보호 병합과 전체 계정 인수는 남아 있다.

## 2026-10-28 인증 가드 첫 묶음

사용자의 프론트 인계에 따라 Codex가0.5~1일의 인증 화면 연결을 구현한다. T3-02 첫 묶음의 `account.get.emailVerificationRequired`·`emailVerified`를 읽어 루트·게임 하위·알림 설정을 가드한다. `auth.me`와 기존 계정·예약·초안은 보존하고 로비·계정·인증/재설정은 복구 경로로 연다. 개발 기본값은 그대로이며 프론트 공개 토글로 운영 요구를 끄지 않는다. 약관 판·동의·탈퇴·외부 수신과 AC 전체 인수는 남긴다.

이동 때 세션과 계정을 새로 확인한다. 미인증·필수 상태는 안전한 로컬 목적지를 담아 인증 화면으로 보내고 조회 실패는 재시도 화면에서 막는다. 조회 사이 세션이 끝나면 로그인으로 보낸다. 가입·로그인이 이미 성공한 뒤 계정 조회가 실패해도 가입 입력을 다시 보내지 않는다. 실제 변경의403·`EMAIL_NOT_VERIFIED`를 함께 확인하는 루트 MutationCache 구독은 기존 초안을 지우지 않고 인증 화면으로 보낸다. 다른 오류와 복구 API는 기존 처리를 유지한다.

인증 성공 뒤 계속하기는 같은 사이트의 목적지로만 이동한다. 토큰 hash와 인증/로그인 순환 목적지는 받지 않는다. 메일 링크로 연 새 탭에 목적지가 없으면 로비로 가며 원래 탭은 재조회 후 원래 월드·검색·초안으로 돌아간다. 공통 게임 머리줄에 기존 계정 경로를 연결한다. v1 공통 프레임과 현재 메인 한 화면 구조를 유지한다.

수정은 `account/access`·인증 화면, 라우터·가입/로그인 성공 이동·머리줄, 필수 모드 E2E 구성·CI·문서다. `pnpm e2e:account`는 인증을1로 켠 실제 API·web·engine·전용 PostgreSQL의 Chromium 검사를 실행한다. 기본 개발 호환 검사와 별도로 CI shard1에 필수 실행해 새 시험이 빠지거나 skip으로 끝나지 않게 한다. 실제 가입/메일 인증·토큰 소거·직접 접근/새로고침·익명/세션 변경·네트워크 실패 재시도와 가입 중복 방지·375px/44px/키보드·정식191년491명 생성/30예약·실제403 뒤 재인증과 초안 복구를 검증한다. 시험 본문과 동시 실행의 정착을 모두 기다린 뒤 자기 데이터만 정리한다.

계획은 비구현 담당의 독립 리뷰에서 열린 P1/P2 없이 승인했다. 단위·타입·전체 check·실제 필수 모드/기존 모드 PostgreSQL·Chromium·공개 자산·코드 독립 리뷰·최신 CI·정상 보호 병합이 이 묶음의 완료 근거다. 새 API·migration·현재 약관 판은 만들지 않는다.

### 사용자가 정할 것

화면 몫에 걸린 사용자 결정은 둘이다. 메일 발송 서비스(T3-01)는 이 작업의 E2E가 capture 메일함을 쓰므로 걸리지 않는다. 결정 목록 전체는 [T3-02 사용자가 정할 것](./T3-02.md#사용자가-정할-것)에 있다.

- 약관·개인정보처리방침 본문 승인. 초안의 운영자 이름, 문의 연락처, 첫 판 번호, 시행일은 사용자가 정하기 전까지 빈칸 표시로 두고 지어내지 않는다. 화면은 초안임을 표시한다.
- 탈퇴 뒤 남기는 자료. 탈퇴 확인 화면과 개인정보처리방침 초안은 T3-02 탈퇴 절의 표를 그대로 옮긴다. 사용자 승인이 그 표를 바꾸면 T3-02 계획이 먼저 바뀌고 이 화면은 그 뒤에 따른다.

### 토큰 화면 연결 (Codex)

2026-10-28 사용자의 프론트 담당 인계를 따라 AC-M3-01의 인증·재설정 화면부터 연결한다. 후보 서버 `5cf239e`의 계정5API를 사용하며 요청/새 비밀번호 화면1일, 인증·본인 계정 화면과 실제 Chromium 검증1일로 나눈다. 로그인 화면의 재설정 링크와 로비의 본인 계정 링크를 더하고 기존 공개 지도와 게임 이동을 보존한다.

토큰은 라우트 진입 때 URL 조각에서 읽고 주소에서 지운다. query·localStorage·sessionStorage·로그에 복제하지 않으며 React StrictMode에서도 인증을 두 번 보내지 않게 한다. 토큰 화면의 referrer를 막고 같은 링크 재사용의 실제 `TOKEN_INVALID`와 `Retry-After`를 화면으로 확인한다. 새 화면은375px 가로 넘침과44px 조작 높이를 확인한다. 가입 동의·미인증 게임 가드·약관·탈퇴·운영 수신은 이 묶음의 완료로 세지 않는다.

실제 Chromium의 첫 실행은5건 중3건 통과·2건 실패였다. 같은 화면에서 같은 인증 링크를 다시 열면 이전 성공 표시가 남았다. 진입마다 페이지 상태를 새로 만들되 한 진입 안에서는 StrictMode의 중복 전송을 막도록 고쳤다. 수정 뒤375px·1280px의5건이8.3초에 통과했다. 인증의 실제 DB 시각·한 번 요청·링크 재사용 거부, 재설정의 비밀번호 불일치·즉시 같은 링크 재진입 거부·이전 비밀번호 거부·새 비밀번호 로그인, 토큰 제거와 referrer 차단을 확인했다. 다시 보내기 후 새로 고쳐도 서버가 실제429를 보내며 양의 정수 `Retry-After`와 화면의 남은 시간·버튼 제한이 일치한다.

URL 처리·공개 오류의31단위, 웹 타입·관련 ESLint·서식·엄격 문구·diff 검사를 통과했다. 실제375px의 본인 계정·인증 완료·새 비밀번호 화면3장을 열어 가독성과 가로 넘침을 확인했다. 시험 계정은 전용 PostgreSQL에만 만들었으며 기존 계정·정식 통합판 DB를 바꾸지 않았다. 최신 로컬 전체 회귀·새 프론트 커밋의 CI·보호 병합과 AC 전체 인수는 남아 있다.

구현하지 않은 담당이 두 P2의 해소와 한정 UI 범위를 재리뷰했다. 이 검토는 가입 동의·미인증 차단·약관·탈퇴·실제 메일 수신이나 사용자 수락을 대신하지 않는다.

후속1건은 실제 로그인 실패5번의401 뒤 올바른 비밀번호도429로 제한되는 경로를 Chromium에서 확인했다. 양의 정수 `Retry-After`와 화면의 남은 시간이 같고 로그인 화면을 유지한다. 새 집중 실행은1건 통과·2.3초이며 앞의5건 실행과 구분한다. 서버 시계·한도·응답을 주입하거나 우회하지 않았다.

### 재발송 고정 창의 실제 분 경계

가입 API 후보 `b7dea26`의 Linux CI [40599168633](https://github.com/opensamguk/opensamguk/actions/runs/40599168633)는 check·엔진·권한·Chromium3분할을 통과했지만 첫 분할의 인증 재발송1건이 실패했고 집계 관문도 실패했다. 실제 실행이 UTC23시02분에서03분으로 넘어가 고정 창이 새로 열렸는데 시험은429를 기대했다. 이 후보를 CI 전체 통과로 세지 않는다.

실제 로컬 HTTP에서 분 경계 전후200→200→429와 이전 토큰 무효·활성 토큰1개·세션 보존을 재현했다. 서버 시계와 제한을 바꾸지 않았다. E2E는 재요청이200이면 실제 분이 바뀌었는지 확인하고 새 인증 링크를 읽는다. 이어지는 같은 창의 요청은 반드시429이며 실제 Retry-After·화면 대기·인증과 재사용 거부 단언을 유지한다. 수정 뒤 실제 Chromium7건은11.3초에 모두 통과했고 구현하지 않은 담당이 시험·문서2파일과 실제 경계 증거를 독립 승인했다. 새 CI·최신 전체 로컬 회귀·보호 병합은 남아 있다.

별도의 실제375px Chromium에서도 준비된 화면에서 실제 분 경계를 기다려200→200→429를 확인했다. 새 링크 인증·이전 링크 거부·URL 토큰 제거·화면 대기 안내와 가로 넘침 없음, 시험 소유 계정 삭제를 확인하고 오류 화면 PNG를 직접 검수했다. 원장 `public-resend-real-boundary-ui.json`과 HTTP 원장 `public-resend-real-boundary.json`은 같은 로컬 인수 자료에 보존한다. 시계·응답·한도 주입이나 제한 우회는 없다.
