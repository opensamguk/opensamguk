# T3-03 가입·재설정·약관·탈퇴 화면

> 대기열: T3-03 · AC: AC-M3-01, AC-M3-02 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T3-02 · 관련: [T3-02 계획](./T3-02.md), [T1-14 로그인·가입 화면](./T1-14.md), [UI 지침](../frontend-ui-guidelines.md)

## 계획 (Claude)

### 목표

- 가입한 사람이 메일함의 링크로 이메일을 인증하고 비밀번호를 잊으면 1회용 링크로 재설정한다 (AC-M3-01, E2E 테스트 메일함).
- 가입할 때 약관·개인정보처리방침의 판을 보고 동의하며 계정 화면에서 탈퇴한다 (AC-M3-02의 화면).

### 담당과 수정 범위

| 담당 | 에이전트 | 고치는 곳 |
| ---- | -------- | --------- |
| 구현 | opensamguk-frontend-implement (Claude) | `apps/web/src/auth/`(`credentials.ts`의 `describeFailure` 포함), `apps/web/src/account/`(새로), `apps/web/src/legal/`(새로), `apps/web/src/router.tsx`, `e2e/account.ts`(`createAccount`의 인증·동의 상태), `e2e/account.spec.ts`(새로), `e2e/mailbox.ts`(새로) |
| 리뷰 | opensamguk-frontend-review (Codex) | 화면 E2E, 문구, 채울 문서 |

### 하지 않는 것

- 서버 API와 메일 템플릿 (T3-02).
- 약관·개인정보처리방침 본문의 확정. 이 작업은 **초안**을 쓰고 화면에 초안임을 표시한다. 공개 전 사용자 승인은 T3-15 점검 항목이며 이 리뷰가 그 승인을 대신하지 않는다.
- 제재 사유 화면 (T3-06), 375px 전수 점검 (T3-10). 새 화면은 처음부터 375px에서 가로 스크롤이 없게 만든다.

### 경로와 화면

| 경로 | 화면 | 로그인 |
| ---- | ---- | ------ |
| `/signup` | 기존 가입 폼에 약관·개인정보처리방침 동의 체크 2개를 더한다. 각 문서 링크는 새 탭. 둘 다 체크해야 가입 버튼이 켜진다 | 불필요 |
| `/verify-email` | 미인증 안내. 주소 일부를 가린 채 보여 주고 다시 보내기 버튼(1분 대기 표시) | 필요 |
| `/verify-email#token=…` | 토큰을 읽자마자 `history.replaceState`로 주소에서 지우고 `account.verifyEmail` 호출. 성공·실패 상태를 보여 준다 | 불필요 |
| `/forgot-password` | 주소 입력. 결과는 항상 같은 문구 (계정 존재를 드러내지 않는다) | 불필요 |
| `/reset-password#token=…` | 토큰을 주소에서 지운 뒤 새 비밀번호 2번 입력. 성공하면 로그인 화면으로 | 불필요 |
| `/legal/terms`, `/legal/privacy` | 현재 판 번호·시행일과 본문 | 불필요 |
| `/legal/agree` | 판이 바뀐 사용자에게 다시 동의를 받는 화면 | 필요 |
| `/account` | 내 계정: 이메일·인증 상태·동의한 판, 탈퇴 (비밀번호 재입력 + 되돌릴 수 없다는 확인, 알림 설정도 함께 지워진다는 안내) | 필요 |

- 로그인 가드는 `me`를 보고 `emailVerified = false`면 게임 경로(`/w/…`)에서 `/verify-email`로, `consentRequired`가 있으면 `/legal/agree`로 보낸다. 로그인 화면에 `비밀번호를 잊었습니다` 링크를 단다.
- 지금은 `currentUser`(`apps/web/src/router.tsx:41-44`)가 이동마다 `auth.me`를 다시 묻는다. 첫 화면 `/`(`:55-70`)와 게임 경로 `w/$worldId`(`:89-97`)의 `beforeLoad`가 로그인만 본다. 새 판단은 이 두 `beforeLoad`에 더한다. D-020의 메인 한 화면과 보조 주소는 모두 `w/$worldId` 아래라 같은 가드를 지난다.
- 지금 실패 문구는 `describeFailure`(`apps/web/src/auth/credentials.ts:29-35`)가 `data.code`만 보고 정한다. 아래 표는 이 함수를 넓히는 방식으로 넣는다.
- 오류 문구는 서버 message가 아니라 `TRPCClientError<AppRouter>`의 `data.code`와 `data.reason` 두 값으로 정한다 ([T3-02 오류 계약](./T3-02.md#오류-계약)). 두 값의 타입은 `AppRouter`에서 추론한 것을 쓰고 사유 문자열 목록을 화면 쪽에 다시 적지 않는다. `cause`와 message는 읽지 않는다.
- 남은 시간은 `Retry-After` 헤더다. `error.meta?.response`가 `Response`이면 `headers.get('Retry-After')`를 정수 초로 읽는다. 없거나 정수가 아니면 남은 시간 없이 잠시 뒤 다시 하라는 문구를 쓴다. 로그인·가입 화면에도 같은 처리를 넣는다 (T3-04 요청 제한과 맞춤).

| `data.code` | `data.reason` | 화면 |
| ----------- | ------------- | ---- |
| `FORBIDDEN` | `EMAIL_NOT_VERIFIED` | `/verify-email`로 보낸다 |
| `FORBIDDEN` | `CONSENT_REQUIRED` | `/legal/agree`로 보낸다 |
| `BAD_REQUEST` | `TOKEN_INVALID` | 링크가 만료됐거나 이미 쓰였다는 문구와 다시 요청하는 길 |
| `BAD_REQUEST` | `null` | 지금처럼 입력을 확인하라는 문구 |
| `TOO_MANY_REQUESTS` | `null` | `Retry-After`로 남은 시간 |
| 그 밖 | `null` | 지금 `describeFailure`의 처리 그대로 |
- 토큰이 든 화면은 `<meta name="referrer" content="no-referrer">`를 둔다.
- 약관 본문은 `apps/web/src/legal/`의 판별 Markdown 파일로 두고 판 번호는 `legal.current()`와 맞는지 단위 시험으로 확인한다. 개인정보처리방침에는 실제로 모으는 항목(이메일, 로그인 시각·IP·기기 해시, 동의 기록, 디스코드 웹훅 주소)과 탈퇴 뒤 처리([T3-02 탈퇴 절](./T3-02.md#탈퇴-때-지우는-자료))를 그대로 적는다.

### 검증

| AC | 무엇 | 어떻게 |
| -- | ---- | ------ |
| M3-01 | 가입 → 인증 | E2E: 가입 → `/verify-email` → 테스트 메일함에서 링크 → 인증 완료 → 월드 화면 진입 |
| M3-01 | 미인증 가드 | E2E: 인증 전 `/w/<id>` 접근 → `/verify-email` |
| M3-01 | 재설정 | E2E: 재설정 요청 → 메일 링크 → 새 비밀번호 → 새 비밀번호로 로그인, 같은 링크 다시 열기 → 실패 문구 |
| M3-01 | 만료 | 30분 경계는 T3-02 통합 시험(주입한 시계)이 증거다. 화면은 만료·사용됨이 같은 `TOKEN_INVALID`이므로 위 재사용 E2E로 문구를 확인한다. E2E를 위해 서버에 시계 조작 API를 열지 않는다 |
| M3-01 | 토큰 노출 | E2E: 링크를 연 뒤 `location.href`에 토큰이 없음 |
| M3-01 | 오류 왕복: 토큰 | E2E: 위 재사용 링크는 실제 HTTP 응답이 `@trpc/client`를 거쳐 `BAD_REQUEST`·`TOKEN_INVALID`로 읽히는 경로다. 화면에 만료·사용됨 문구가 나오고 일반 입력 오류 문구가 아님 |
| M3-01 | 오류 왕복: 한도 | E2E: `/verify-email`에서 다시 보내기를 1분 안에 두 번 → 두 번째에 서버 `Retry-After`로 계산한 남은 시간이 보임. 로그인 실패를 한도까지 반복한 뒤 남은 시간이 보임 |
| M3-01 | 오류 왕복: 미인증 | E2E: 미인증 사용자가 가드를 거치지 않는 실제 화면 동작으로 막힌 변경 API를 부르면 `/verify-email`로 감. 그런 화면 동작이 없으면 이 행의 증거는 T3-02의 HTTP → 클라이언트 통합 시험이고 그 사실을 구현 기록에 적음 |
| 공통 | 오류 분기 | 단위: 위 표의 조합마다 문구·이동이 맞음. 타입 시험: 분기 함수가 받는 `data.reason` 타입이 `inferRouterError<AppRouter>`에서 온 것임 |
| M3-02 | 동의 | E2E: 체크 없이 가입 버튼 꺼짐 → 체크 후 가입 → 동의한 판이 `/account`에 보임. 판이 바뀐 경우의 가드는 단위 시험(`consentRequired`가 있으면 `/legal/agree`, `FORBIDDEN`·`CONSENT_REQUIRED`를 받아도 `/legal/agree`)으로 보고 서버 쪽 증거는 T3-02의 HTTP → 클라이언트 통합 시험이다 |
| M3-02 | 탈퇴 | E2E: `/account`에서 탈퇴 → 로그인 화면 같은 계정 로그인 실패 |
| 공통 | 문구 | `pnpm lint:text` 0건, 반대쪽 리뷰가 문구도 본다 |
| 공통 | 375px | 새 화면 전부 Playwright 375px 뷰포트에서 가로 스크롤 없음 |

테스트 메일함은 T3-02의 capture 폴더다. `e2e/mailbox.ts`가 받는 사람으로 가장 최근 메일을 기다려 읽는다. 실제 메일함 수신은 이 E2E의 증거가 아니며 T3-02 구현 기록에 따로 남긴다.

E2E 준비 계정은 지금 규칙을 따른다. 서버는 같은 IP의 가입을 1시간에 10번까지만 받으므로(T3-04) 화면 가입은 가입 흐름 자체를 보는 시험에서만 하고 나머지는 `createAccount`(`e2e/account.ts:49-67`)로 DB에 바로 만든다. T3-02가 들어오면 `createAccount`가 인증 시각과 현재 판 동의를 함께 넣어야 기존 게임 E2E가 막히지 않는다. 이 수정은 T3-02 가지 위에 따로 커밋해 T3-02와 함께 병합한다. `page.request`로 보내는 POST에는 `appOrigin()`(`e2e/account.ts:19-23`)을 `Origin`으로 붙인다.
