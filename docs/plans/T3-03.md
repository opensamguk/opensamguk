## 계획 (Claude)

### 목표

- 가입한 사람이 메일함의 링크로 이메일을 인증하고 비밀번호를 잊으면 1회용 링크로 재설정한다 (AC-M3-01, E2E 테스트 메일함).
- 가입할 때 약관·개인정보처리방침의 판을 보고 동의하며 계정 화면에서 탈퇴한다 (AC-M3-02의 화면).

### 하지 않는 것

- 서버 API와 메일 템플릿 (T3-02).
- 약관·개인정보처리방침 본문의 확정. 이 작업은 **초안**을 쓰고 화면에 초안임을 표시한다. 공개 전 사용자 승인은 T3-15 점검 항목이며 이 리뷰가 그 승인을 대신하지 않는다.
- 제재 사유 화면 (T3-06), 375px 전수 점검 (T3-10). 새 화면은 처음부터 375px에서 가로 스크롤이 없게 만든다.
- 알림 설정 화면 자체 (T2-21). `/account`에서 그 화면으로 가는 링크만 단다.

### 사용자가 정할 것

화면 몫에 걸린 사용자 결정은 둘이다. 메일 발송 서비스(T3-01)는 이 작업의 E2E가 capture 메일함을 쓰므로 걸리지 않는다. 결정 목록 전체는 [T3-02 사용자가 정할 것](./T3-02.md#사용자가-정할-것)에 있다.

- 약관·개인정보처리방침 본문 승인. 초안의 운영자 이름, 문의 연락처, 첫 판 번호, 시행일은 사용자가 정하기 전까지 빈칸 표시로 두고 지어내지 않는다. 화면은 초안임을 표시한다.
- 탈퇴 뒤 남기는 자료. 탈퇴 확인 화면과 개인정보처리방침 초안은 T3-02 탈퇴 절의 표를 그대로 옮긴다. 사용자 승인이 그 표를 바꾸면 T3-02 계획이 먼저 바뀌고 이 화면은 그 뒤에 따른다.

### 경로와 화면

| 경로 | 화면 | 로그인 |
| ---- | ---- | ------ |
| `/signup` | 기존 가입 폼에 약관·개인정보처리방침 동의 체크 2개를 더한다. 각 문서 링크는 새 탭. 둘 다 체크해야 가입 버튼이 켜진다 | 불필요 |
| `/verify-email` | 미인증 안내. 주소 일부를 가린 채 보여 주고 다시 보내기 버튼(1분 대기 표시) | 필요 |
| `/verify-email#token=…` | 토큰을 읽자마자 `history.replaceState`로 주소에서 지우고 `account.verifyEmail` 호출. 성공·실패 상태를 보여 준다 | 불필요 |
| `/forgot-password` | 주소 입력. 결과는 항상 같은 문구 (계정 존재를 드러내지 않는다) | 불필요 |
| `/reset-password#token=…` | 토큰을 주소에서 지운 뒤 새 비밀번호 2번 입력. 성공하면 로그인 화면으로 | 불필요 |
| `/legal/terms`, `/legal/privacy` | 현재 판 번호·시행일과 본문 | 불필요 |
| `/legal/agree` | 판이 바뀐 사용자에게 다시 동의를 받는 화면 | 필요 |
| `/account` | 내 계정: 이메일·인증 상태·동의한 판, 탈퇴 (비밀번호 재입력 + 되돌릴 수 없다는 확인, 알림 설정도 함께 지워진다는 안내) | 필요 |

- 로그인 가드는 `me`를 보고 `emailVerified = false`면 `/verify-email`로, `consentRequired`가 있으면 `/legal/agree`로 보낸다. 인증을 먼저 본다(T3-02와 같은 순서). 로그인 화면(`apps/web/src/pages/LoginPage.tsx`)의 폼 아래에 `비밀번호를 잊었습니다` 링크를 단다. 같은 화면의 공개 지도 탭(T2-25)은 건드리지 않는다.
- 지금은 `currentUser`(`apps/web/src/router.tsx:52-55`)가 이동마다 `auth.me`를 다시 묻는다. 로그인을 보는 `beforeLoad`는 첫 화면 `/`(`:66-75`), 알림 설정 `settings/notifications`(`:97-106`), 게임 경로 `w/$worldId`(`:108-117`) 셋이다. 새 판단은 이 셋에 더한다. D-020의 메인 한 화면과 보조 주소, 장수 만들기 `w/$worldId/create`는 모두 `w/$worldId` 아래라 같은 가드를 지난다. 로비 `/lobby`(`:78`)는 로그인 없이 여는 화면이라 가드를 두지 않는다. 참가 버튼이 `w/$worldId` 아래로 가므로 거기서 걸린다.
- 지금 실패 문구는 `describeFailure`(`apps/web/src/auth/credentials.ts:29-35`)가 `data.code`만 보고 정한다. 아래 표는 이 함수를 넓히는 방식으로 넣는다.
- 오류 문구는 서버 message가 아니라 `TRPCClientError<AppRouter>`의 `data.code`와 `data.reason` 두 값으로 정한다 ([T3-02 오류 계약](./T3-02.md#오류-계약)). 두 값의 타입은 `AppRouter`에서 추론한 것을 쓰고 사유 문자열 목록을 화면 쪽에 다시 적지 않는다. `cause`와 message는 읽지 않는다.
- 남은 시간은 `Retry-After` 헤더다. `error.meta?.response`가 `Response`이면 `headers.get('Retry-After')`를 정수 초로 읽는다. 없거나 정수가 아니면 남은 시간 없이 잠시 뒤 다시 하라는 문구를 쓴다. 로그인·가입 화면에도 같은 처리를 넣는다 (T3-04 요청 제한과 맞춤).

| `data.code` | `data.reason` | 화면 |
| ----------- | ------------- | ---- |
| `FORBIDDEN` | `EMAIL_NOT_VERIFIED` | `/verify-email`로 보낸다 |
| `FORBIDDEN` | `CONSENT_REQUIRED` | `/legal/agree`로 보낸다 |
| `BAD_REQUEST` | `TOKEN_INVALID` | 링크가 만료됐거나 이미 쓰였다는 문구와 다시 요청하는 길 |
| `BAD_REQUEST` | `null` | 지금처럼 입력을 확인하라는 문구 |
| `TOO_MANY_REQUESTS` | `null` | `Retry-After`로 남은 시간 |
| 그 밖 | `null` | 지금 `describeFailure`의 처리 그대로 |
- 토큰이 든 화면은 `<meta name="referrer" content="no-referrer">`를 둔다.
- 약관 본문은 `apps/web/src/legal/`의 판별 Markdown 파일로 두고 판 번호는 `legal.current()`와 맞는지 단위 시험으로 확인한다. 개인정보처리방침에는 실제로 모으는 항목(이메일, 로그인 시각과 IP 해시·기기 해시(T3-05 `LoginRecord`, 기기 쿠키 `did`), 요청 제한을 위해 서버 메모리에만 잠시 두는 IP, 동의 기록, 디스코드 웹훅 주소)과 탈퇴 뒤 처리([T3-02 탈퇴 절](./T3-02.md#탈퇴-때-지우는-자료))를 그대로 적는다.

테스트 메일함은 T3-02의 capture 폴더다. `e2e/mailbox.ts`가 받는 사람으로 가장 최근 메일을 기다려 읽는다. 실제 메일함 수신은 이 E2E의 증거가 아니며 T3-02 구현 기록에 따로 남긴다.

E2E 준비 계정은 지금 규칙을 따른다. 서버는 같은 IP의 가입을 1시간에 10번까지만 받으므로(T3-04) 화면 가입은 가입 흐름 자체를 보는 시험에서만 하고 나머지는 `createAccount`(`e2e/account.ts:49-67`)로 DB에 바로 만든다. T3-02가 들어오면 `createAccount`가 인증 시각과 현재 판 동의를 함께 넣어야 기존 게임 E2E가 막히지 않는다. 이 수정은 T3-02 가지 위에 따로 커밋해 T3-02와 함께 병합한다. `page.request`로 보내는 POST에는 `appOrigin()`(`e2e/account.ts:19-23`)을 `Origin`으로 붙인다.

화면으로 가입하는 기존 E2E는 `e2e/auth.spec.ts`에 있다. 첫 시험(`가입 → 메인 → 로그아웃 → 로그인 → 메인`)은 가입 뒤 바로 `/w/1`로 들어간다고 기대하므로 T3-02가 들어오면 깨진다. 같은 커밋에서 동의 체크를 더하고 가입 뒤 `/verify-email`을 거쳐 메일함 링크로 인증한 다음 `/w/1`로 가게 고친다. 이미 가입된 이메일·입력 형식 시험은 동의 체크만 더한다.

### 토큰 화면 연결 (Codex)

2026-10-28 사용자의 프론트 담당 인계를 따라 AC-M3-01의 인증·재설정 화면부터 연결한다. 후보 서버 `5cf239e`의 계정5API를 사용하며 요청/새 비밀번호 화면1일, 인증·본인 계정 화면과 실제 Chromium 검증1일로 나눈다. 로그인 화면의 재설정 링크와 로비의 본인 계정 링크를 더하고 기존 공개 지도와 게임 이동을 보존한다.

토큰은 라우트 진입 때 URL 조각에서 읽고 주소에서 지운다. query·localStorage·sessionStorage·로그에 복제하지 않으며 React StrictMode에서도 인증을 두 번 보내지 않게 한다. 토큰 화면의 referrer를 막고 같은 링크 재사용의 실제 `TOKEN_INVALID`와 `Retry-After`를 화면으로 확인한다. 새 화면은375px 가로 넘침과44px 조작 높이를 확인한다. 가입 동의·미인증 게임 가드·약관·탈퇴·운영 수신은 이 묶음의 완료로 세지 않는다.

실제 Chromium의 첫 실행은5건 중3건 통과·2건 실패였다. 같은 화면에서 같은 인증 링크를 다시 열면 이전 성공 표시가 남았다. 진입마다 페이지 상태를 새로 만들되 한 진입 안에서는 StrictMode의 중복 전송을 막도록 고쳤다. 수정 뒤375px·1280px의5건이8.3초에 통과했다. 인증의 실제 DB 시각·한 번 요청·링크 재사용 거부, 재설정의 비밀번호 불일치·즉시 같은 링크 재진입 거부·이전 비밀번호 거부·새 비밀번호 로그인, 토큰 제거와 referrer 차단을 확인했다. 다시 보내기 후 새로 고쳐도 서버가 실제429를 보내며 양의 정수 `Retry-After`와 화면의 남은 시간·버튼 제한이 일치한다.

URL 처리·공개 오류의31단위, 웹 타입·관련 ESLint·서식·엄격 문구·diff 검사를 통과했다. 실제375px의 본인 계정·인증 완료·새 비밀번호 화면3장을 열어 가독성과 가로 넘침을 확인했다. 시험 계정은 전용 PostgreSQL에만 만들었으며 기존 계정·정식 통합판 DB를 바꾸지 않았다. 최신 로컬 전체 회귀·새 프론트 커밋의 CI·보호 병합과 AC 전체 인수는 남아 있다.

구현하지 않은 담당이 두 P2의 해소와 한정 UI 범위를 재리뷰했다. 이 검토는 가입 동의·미인증 차단·약관·탈퇴·실제 메일 수신이나 사용자 수락을 대신하지 않는다.

후속1건은 실제 로그인 실패5번의401 뒤 올바른 비밀번호도429로 제한되는 경로를 Chromium에서 확인했다. 양의 정수 `Retry-After`와 화면의 남은 시간이 같고 로그인 화면을 유지한다. 새 집중 실행은1건 통과·2.3초이며 앞의5건 실행과 구분한다. 서버 시계·한도·응답을 주입하거나 우회하지 않았다.
