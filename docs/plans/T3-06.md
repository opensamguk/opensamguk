# T3-06 관리자 콘솔 화면

> 대기열: T3-06 · AC: AC-M3-04, AC-M3-05 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T3-05 · 관련: [T3-05 계획](./T3-05.md), [관리자 콘솔](../admin-console.md), [UI 지침](../frontend-ui-guidelines.md)

## 계획 (Claude)

### 목표

- 관리자 화면에서 월드 생성·일시정지·재개·종료·초기화, 공지, 사용자 조회·제재·해제를 하고 각 조치가 감사 로그 화면에 보인다 (AC-M3-04, E2E + 감사 로그 조회).
- 관리자가 월드를 골라 IP·기기를 공유하는 계정 묶음을 본다 (AC-M3-05의 화면).
- 월드 제재를 받은 사용자가 그 월드에서 사유와 기한을 본다 (FR-ACC-07, T3-03 계획에서 이 작업으로 넘긴 부분).

`router.tsx`는 T3-03 등 다른 화면 작업과 같이 고치는 파일이다. 경로 등록 줄만 더하고 다른 경로는 건드리지 않는다.

### main 기준 사실 (2026-10-22, `76d56d0`)

- 경로는 `apps/web/src/router.tsx`에 정적 import로 모여 있다(`:10-21`). 관리자 화면은 이 파일의 첫 지연 로드 경로가 된다. `/admin` 아래 컴포넌트만 동적 import로 등록해 일반 사용자 번들과 나눈다.
- 게임 경로는 `w/$worldId`(`router.tsx:89-97`)이고 메인 작업 화면은 그 index(`:104-109`, D-020)다. 제재 안내는 `apps/web/src/layout/GameLayout.tsx`에 끼운다. D-018에 따라 `router.tsx`와 `GameLayout.tsx`는 경로 등록과 안내 한 곳만 고친다.
- 서버는 같은 IP의 가입을 1시간에 10번만 받는다(`apps/server/src/routers/auth.ts:32-35`). 그래서 기존 E2E는 계정과 세션을 E2E 전용 DB에 바로 만든다(`e2e/account.ts:5-7`, `:49` `createAccount`). `e2e/adminSetup.ts`도 이 도우미를 쓰고 관리자 지정만 `pnpm admin:grant`로 한다. 시험용 한도 우회는 만들지 않는다.
- `e2e/game.ts:309`의 `setUserStatus`는 `User.status`를 DB에서 바꾸는 도우미다. 제재 E2E는 이 도우미를 쓰지 않고 관리자 화면으로 제재한다.
- 관리자 변경 요청도 `mutation.user` 한도(1분 120번, `apps/server/src/trpc.ts:18-25`)를 받는다. `TOO_MANY_REQUESTS`면 [T3-04](./T3-04.md#상대-영역에-필요한-것)대로 `Retry-After`의 남은 시간을 보여 준다. 2초 상태 확인은 조회라서 이 한도에 들지 않는다.
- main의 errorFormatter는 모든 오류의 `data.reason`을 `null`로 둔다(`trpc.ts:9`). 아래 제재 안내 판정은 이 값과 맞는다.

### 하지 않는 것

- 서버 API, 실행기, 감사 로그 기록 (T3-05).
- 관리자 지정 화면. 지정은 명령줄 `pnpm admin:grant`뿐이다 (T3-05).
- 계정 전체 제재의 사유를 로그인 화면에 보여 주는 일. 공개 오류 필드에 새 값이 필요하며 결정 대기다 (T3-05 결정 대기).
- 375px 대응. AC-M3-08은 로비와 핵심 화면 6개가 대상이다. 관리자 화면은 폭 1024px 이상을 기준으로 하고 768px에서 가로 스크롤이 생기지 않게만 한다. 제재 안내는 게임 화면 안에 나오므로 375px에서 가로 스크롤이 없어야 한다.
- 원문 IP나 해시 전체를 보여 주는 일. 서버가 주는 앞 8자 묶음 이름만 쓴다.

### 경로와 화면

| 경로 | 화면 |
| ---- | ---- |
| `/admin` | 월드 목록. 상태, 시나리오·프리셋, 턴 간격, 사람 장수 수, 엔진 하트비트(마지막 시각·지연·최근 오류). 월드 만들기 버튼 |
| `/admin/worlds/new` | 이름·시나리오·프리셋·시드(선택)·턴 간격(선택). 보내면 요청 상태를 2초마다 확인해 완료되면 목록으로 |
| `/admin/worlds/$worldId` | 월드 조치(시작·일시정지·재개·종료·초기화), 이 월드 공지, 공유 계정 조사로 가는 링크 |
| `/admin/notices` | 로비 공지 목록·작성·수정·숨김 |
| `/admin/users` | 이메일 앞부분·사용자 ID·월드와 장수 이름으로 찾기 |
| `/admin/users/$userId` | 계정 상태, 장수 목록, 제재 기록, 최근 로그인(성공 여부, IP·기기 묶음 이름). 제재 만들기·해제 |
| `/admin/worlds/$worldId/shared` | IP 묶음과 기기 묶음. 묶음마다 사용자와 장수 이름, 로그인 수, 마지막 시각. 사용자를 누르면 상세로 |
| `/admin/audit` | 감사 로그. 기간·종류·행위자·대상·월드 필터, 더 보기 |

- 가드: `/admin` 아래에 들어오면 `admin.whoami()`를 부른다. `UNAUTHORIZED`면 로그인 화면으로(`next` 유지), `FORBIDDEN`이면 404와 같은 화면을 보여 관리자 경로가 있다는 사실을 드러내지 않는다.
- 사용자 찾기·사용자 상세·공유 목록은 부를 때마다 서버가 감사 행을 남긴다 (T3-05). 찾기는 사용자가 찾기 버튼을 눌렀을 때만 부르고 입력 중 자동 검색을 하지 않는다. 세 조회는 창 포커스·재접속 때 자동으로 다시 부르지 않는다. 서버가 `INTERNAL_SERVER_ERROR`를 주면 결과 칸을 비우고 조회 실패 안내만 보인다.
- 관리자 화면 코드는 `/admin` 경로에서만 불러오는 별도 청크로 나눈다. 일반 사용자 번들에 관리자 화면 문구와 API 경로 목록이 들어가지 않는다.
- 월드 조치는 비동기다. 버튼을 누르면 `inputEventId`를 받고 2초마다 `admin.world.request`로 상태를 본다. PENDING 동안 같은 월드의 다른 조치 버튼을 끈다. REJECTED면 서버가 준 결과의 이유를 보여 준다.
- 요청마다 `idempotencyKey`를 화면에서 만든다(`crypto.randomUUID()`). 네트워크 실패로 다시 보낼 때는 같은 키를 쓴다.
- 확인 대화 상자: 종료와 초기화는 월드 이름을 그대로 다시 입력해야 버튼이 켜지고 사유가 필수다. 일시정지·재개·시작은 사유만 받는다. 제재 만들기는 범위(계정 전체·월드 하나), 기한(없음·날짜), 사유를 받고 사유 입력란 아래에 개인정보를 쓰지 말라는 안내를 둔다.
- 초기화 대화 상자는 결과를 미리 적는다: 기존 월드는 종료로 남고 같은 설정의 새 월드가 개설 전 상태로 만들어지며 사람 장수는 옮겨지지 않는다.
- 운영 월드 경고: 사람 장수가 1명 이상인 월드의 종료·초기화 대화 상자에는 소유자 승인이 필요하다는 문장을 굵게 한 줄 둔다 (admin-console.md의 승인 절차와 같은 문장).

### 제재 안내 (일반 사용자)

- 게임 경로(`/w/$worldId/…`)에 들어오면 `sanction.mine()`을 한 번 부르고 그 월드의 유효한 제재가 있으면 게임 레이아웃 위쪽에 고정 안내를 띄운다: 제재 사유, 기한(무기한이면 기한 없음).
- 변경 요청이 `FORBIDDEN`이고 `data.reason`이 `null`이면 `sanction.mine()`을 다시 불러 안내를 갱신한다. 문구는 서버 message가 아니라 이 결과로 정한다.

### 문구와 표시

- 상태 이름은 서버 값과 일대일로 맞춘다: PREOPEN 개설 전, RUNNING 진행 중, PAUSED 일시정지, ENDED 종료. 상태를 색만으로 구분하지 않고 글자를 함께 쓴다 (NFR-08).
- 시각은 Asia/Seoul로 보여 주고 `title`에 ISO 원문을 둔다.
- 버튼과 안내는 [글쓰기 규칙](../writing-style.md)을 따른다. 위험한 조치의 버튼 이름은 동작 그대로 쓴다 (예: 월드 종료, 월드 초기화).

### 검증

E2E는 격리된 시험 DB와 실제 server·감독 프로세스(T3-05의 실행기 포함)로 한다. `e2e/adminSetup.ts`가 `createAccount`로 일반 계정과 관리자 계정을 만들고 관리자 지정은 `pnpm admin:grant`를 표준 입력으로 실행한다. T3-02가 먼저 병합되어 있으면 이메일 인증은 T3-03의 `e2e/mailbox.ts`로 통과시킨다. 이 작업은 시험용 인증 우회 API를 만들지 않는다.

| AC | 무엇 | 어떻게 |
| -- | ---- | ------ |
| M3-04 | 월드 조치 | E2E: 월드 만들기 → 목록에 개설 전 → 시작 → 진행 중 → 일시정지 → 재개 → 일시정지 → 종료(이름 입력) → 종료 |
| M3-04 | 초기화 | E2E: 일시정지 월드 초기화(이름·사유) → 기존 월드 종료, 새 월드 개설 전이 목록에 보임. 이름이 틀리면 버튼 꺼짐 |
| M3-04 | 공지 | E2E: 로비 공지 작성 → 일반 계정 로비에 보임 → 숨김 → 사라짐 |
| M3-04 | 제재 | E2E: 월드 제재 → 그 사용자가 월드에서 사유·기한 안내를 보고 예턴 저장이 막힘 → 해제 → 저장 성공. 계정 전체 제재 → 그 사용자의 다른 탭이 다음 요청에서 로그인 화면으로 |
| M3-04 | 감사 로그 | E2E: 위 조치마다 `/admin/audit`에 해당 종류의 행이 있음. 같은 내용을 API(`admin.audit.list`)로도 확인 |
| M3-05 | 공유 목록 | E2E: 같은 브라우저 컨텍스트(같은 `did`)로 두 계정이 같은 월드에 장수를 만든 뒤 조사 화면에 기기 묶음 1개, 사용자 2명 |
| 공통 | 가드 | E2E: 일반 계정이 `/admin` → 404 화면, 무인증 → 로그인 화면. 일반 사용자 번들에 `admin.` 절차 이름이 없음(빌드 결과 grep) |
| 공통 | 반복 요청 | 단위: 네트워크 실패 뒤 재전송이 같은 `idempotencyKey`를 씀 |
| 공통 | 문구 | `pnpm check`에 들어 있는 `lint:text --strict`(루트 `package.json:18`) 0건, 반대쪽 리뷰가 문구도 본다 |

### 상대 영역에 필요한 것 (Codex, T3-05)

- `admin.*`와 `sanction.mine()` 계약, 상태 조회 API, 실행기가 함께 도는 실행 명령.
- 계정 전체 제재 사유 표시에 쓸 `data.reason` 값은 결정 전이다. 결정되면 T3-02 소유 errorFormatter가 바뀌고 이 화면은 그 값만 읽는다.
