## 1. 이 문서의 위치

## 3. 분류와 공통 경로

### 3.1 남은 것의 종류

모든 행을 한꺼번에 가능이나 불가로 적지 않는다. 행마다 남은 것을 셋으로 나눈다.

| 표시 | 뜻 | 누가 푸나 |
| ---- | -- | --------- |
| 계약 | 코드 계약만 정하면 되는 기술 문제 | 담당(Codex) 상세 계획과 반대쪽(Claude) 기술 검토 |
| 결정 | 제품 정책이나 수치. 명세 §9 U, §8 A, 또는 아래 MQ 질문 | 소유자. 총괄이 작은 묶음으로 묻는다 |
| 연결 | 지금 코드나 다른 계획에 길이 없어 누군가 이어야 하는 것 | 해당 파일의 소유 작업 |

MQ-1~MQ-5는 이 문서 안의 질문 번호다. 명세 §9의 U ID가 아니다. U로 올릴지는 총괄이 정하고 올리면 명세 §9에 등록하는 일은 명세 소유 경로에서 한다.

### 3.2 모든 행에 공통인 담당과 경로

- 규칙: Codex(`opensamguk-implement`)가 `packages/rules/src/commands/ext/<key>/`에 만들고 Claude(`opensamguk-review`)가 리뷰한다(명세 C1). 명령마다 `<key>.test.ts`에 성공 1건과 대표 실패 1건을 둔다.
- 등록: 명령 정의는 `ext/registry.ts`의 `extensionCommands`에, 명령과 상태 조각의 관계는 `ext/state.ts`의 `extCommandBindings`에 한 행씩 더한다. 상태가 필요 없는 명령도 `sliceKeys: []` 행을 둔다. 상태 조각이 있으면 `extSlices`에 더한다([T4-02](./T4-02.md) 2.4). 두 공유 파일에서 T4-57~T4-75의 반영 순서는 9절이다.
- 소비 API: 새 API가 없다. 장수 명령은 기존 `turns` 라우터에 T4-03이 잇는 resolver, 국가 명령은 T2-05 `nationTurns`에 T4-50이 잇는 resolver를 그대로 쓴다. Codex가 연결하고 Claude가 리뷰한다. 같은 기능에 새 프로시저나 새 명령 ID를 두지 않는다.
- 화면: 인자가 있는 명령은 장수 명령 T4-04, 국가 명령 T4-51의 확장 인자 입력에 행을 더한다. Claude(`opensamguk-frontend-implement`)가 만들고 Codex(`opensamguk-frontend-review`)가 리뷰한다. 인자가 없는 명령은 기존 30칸 편집기의 목록 표시만 쓴다.
- 끈 월드: 이 19개는 확장 명령이므로 월드 프리셋에서 켠 월드에만 나온다(명세 C2, [T4-02](./T4-02.md) 2.1). 기본 명령 37개와 끈 월드의 결과는 바뀌지 않는다.
- NPC: 명세 C11과 U-18에 따라 NPC는 이 19개를 고르지 않는다. 실행 증거는 사람 장수 몫의 결정적 입력 시나리오로 받는다(명세 C19).

## 9. 공유 파일 순서

`packages/rules/src/commands/ext/registry.ts`와 `ext/state.ts`의 반영 순서는 명세 §7이 T4-02 → T4-17 → T4-20 → T4-48 → T4-52 → T4-23 → T4-53 → T4-28 → T4-31로 정했다. 총괄 run908 결정으로 T4-57~T4-75는 T4-31 뒤에 ID 오름차순으로 잇는다. 이는 두 파일에서 등록 줄을 두는 최종 위치다. 각 명령의 실행 선행(4절)을 없애거나 제품 결정을 대신하지 않는다. 앞 ID가 결정 대기로 막혀 있다고 뒤 ID가 그 결정을 기다리는 새 구현 사슬도 아니다. 각 행은 병합 직전 최신 main에서 자기 줄을 ID 순서 자리에 더한다. 명세 §7 표에 이 순서를 적는 일은 아래 편입과 함께 한다.

대응표 정합은 계획 문서를 읽는 새 parser를 도구에 더하지 않는 방식으로 맞춘다. PR #67 정본 통합 뒤 원작성자의 좁은 후속이 명세 §6의 단일 작업표에 T4-57~T4-75의 19행을 넣고 각 행의 상세는 이 문서로 링크한다. 대응표 `docs/product/command-coverage.json`의 19개 행 `queueIds`도 그때 채운다. 지금 도구는 T4 ID의 상태를 phases.md나 명세 §6 표에서만 찾기 때문이다(T4-02 5절). 기존 T4-01~T4-56, 19개 일대일, 미해결 원본 3개, 분모 91은 그대로 둔다. 이 문서 PR은 명세, 대응표, 도구를 고치지 않는다. 도구가 확장 registry를 읽게 하는 일은 T4-02 도구 PR 2(Codex 구현, Claude 리뷰, PR #67 통합 뒤)다.
