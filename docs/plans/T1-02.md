# T1-02 로컬 실행

> 대기열: T1-02 · AC: AC-M1-02 · 구현: Claude · 리뷰: Codex
> D-012 이전에 진행돼 계획 절은 사후 기록입니다.

## 계획 (Claude)

- 목표: `docker compose up`으로 DB를 띄우고 `pnpm dev`로 web·server·engine을 켜면 로그인 화면이 나온다 (AC-M1-02).
- 범위: `docker-compose.yml`, `.env.example`, server의 `health` procedure, web의 자리표시 로그인 화면, Playwright 스모크
- 하지 않는 것: 실제 가입·로그인 (T1-10, T1-14)

## 구현 기록 (Claude)

- PostgreSQL 18 (`127.0.0.1:5433`), server `127.0.0.1:3001` (Fastify + tRPC, `/trpc`), web `127.0.0.1:5173` (Vite 프록시)
- `health`가 `SELECT 1`로 DB 연결을 확인하고 화면에 "서버 정상 · DB 정상"을 표시
- server·engine 개발 실행은 `tsx watch` (Node `--watch`는 macOS에서 파일 감시 한도 초과로 실패했음)
- 검증: 2026-10-20 `pnpm db:up` → `pnpm e2e` 통과 (`e2e/smoke.spec.ts` 1개)
- 주의: Claude 실행 환경의 sandbox에서는 Docker 소켓과 로컬 포트가 막혀 sandbox 밖에서 실행했다

## 리뷰 (Codex)

- 결과: 수정 필요 (2026-10-20). 담당별 `구현` 1건 제한 때문에 T1-01이 완료될 때까지 대기열은 `리뷰`에 두고, 이후 `구현`으로 전환한다.
- 확인한 것: 실제 PostgreSQL 18에 대해 `pnpm db:up` → `pnpm e2e` 통과 (`e2e/smoke.spec.ts` 1개). 로그인 화면·입력 필드·서버 및 DB 정상 표시를 확인했다.
- 고칠 것:
  - [P2] `apps/web/vite.config.ts:11`: API 프록시가 `127.0.0.1:3001`에 고정돼 문서에 있는 `SERVER_PORT` 설정을 따르지 않는다. 기존 dev 서버 없이 `SERVER_PORT=3002 pnpm e2e`를 실행하면 스모크가 실패하고 상태 문구가 `서버에 연결할 수 없습니다`가 된다. Vite가 루트 `.env` 및 프로세스 환경변수의 API 포트 설정을 서버와 동일하게 반영하도록 수정하고, 기본 포트와 변경한 포트 모두 검증해야 한다.
