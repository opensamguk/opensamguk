## 0. 이 문서의 위치

2026-10-23 사용자 원문은 "아, 결정 정정. 멸망한 국가도 저장해 놓을 것."이다. <!-- lint-text-ignore J-2 --> 앞서 승인한 U-20의 처리(멸망 국가는 ID와 공통 회색 먼저, 과거 이름·색은 후속)를 사용자가 스스로 철회했다. 이 문서는 그 결정의 저장 몫만 T4-56 (가)의 기술 계약으로 구체화한다. 저장 대상은 멸망한 모든 국가다. 월간 프레임에 나왔는지와 관계없다.

이 결정으로 저장하는 값은 국가가 살아 있을 때 이미 공개였던 ID·이름·색뿐이다(`apps/server/src/routers/world.ts:21-25`). 실제 사건 자막, 비공개 정보, 무인증 공유·GIF(U-10, T4-37), 열전 문구는 승인되지 않았고 A-11 승인 대기에 남는다. 다른 U·A 항목도 이 문서가 정하지 않는다.

착수 조건은 T4-35와 같다. 이 문서의 Codex 계획 기술 검토(명세 G-03)를 통과하고 부모가 6절의 정본 hunk를 직렬로 반영한 뒤 그 SHA를 이 문서 머리에 핀해야 구현한다.

## 3. 계약

### 3.1 저장 모델과 migration

```prisma
model RemovedNation {
  worldId         String
  nationId        Int
  name            String
  color           String
  removedSequence Int
  removedTick     Int
  world           World @relation(fields: [worldId], references: [id], onDelete: Cascade)

  @@id([worldId, nationId])
}

model YearbookNation {
  worldId  String
  tick     Int
  nationId Int
  name     String
  color    String
  snapshot YearbookSnapshot @relation(fields: [worldId, tick], references: [worldId, tick], onDelete: Cascade)

  @@id([worldId, tick, nationId])
}
```

- `World`에 `removedNations RemovedNation[]`, `YearbookSnapshot`에 `nations YearbookNation[]` 관계 필드만 더한다. 기존 표의 DB 칸은 늘지 않고 기존 `findMany`·`select` 결과도 같다.
- `RemovedNation` 키가 `(worldId, nationId)`인 것은 국가 ID를 다시 쓰지 않기 때문이다(1절). 같은 국가가 두 번 지워지는 일은 버그이고 키 충돌로 막힌다.
- `YearbookNation`의 외래 키가 프레임을 가리키므로 프레임 없는 행은 들어갈 수 없다.
- migration은 `prisma migrate dev --create-only`로 병합 직전 최신 main 위에서 새로 만든다. 표 생성과 키·외래 키만 있고 데이터 SQL은 없다. 기존 migration은 고치지 않는다. 앞서 병합된 schema 변경(PR #161 T2-24 `PublicMapSnapshot` 등)이 있으면 그보다 늦은 timestamp로 다시 만든다.

### 3.2 쓰는 곳

```ts
// apps/engine/src/nationArchive.ts
export type ActionAt = { sequence: number; tick: number };
export async function archiveRemovedNation(tx: Prisma.TransactionClient, worldId: string, nation: { id: number; name: string; color: string }, at: ActionAt) {
  await tx.removedNation.create({
    data: { worldId, nationId: nation.id, name: nation.name, color: nation.color, removedSequence: at.sequence, removedTick: at.tick },
  });
}
export async function persistYearbookNations(tx: Prisma.TransactionClient, worldId: string, tick: number, state: WorldState) {
  const data = Object.values(state.nations)
    .sort((a, b) => a.id - b.id)
    .map(({ id, name, color }) => ({ worldId, tick, nationId: id, name, color }));
  if (data.length) await tx.yearbookNation.createMany({ data });
}
```

- `persistCommandState(tx, worldId, state, at: ActionAt)`로 인자를 하나 늘린다. 선택 인자가 아니다. 앞으로 국가를 지울 수 있는 새 호출(T4-49 즉시 행동 등)도 typecheck에서 행동 번호와 tick을 넘기도록 강제하려는 것이다.
- 삭제 루프(`commandPersistence.ts:71-76`)에서 `capitalCityKey: null` 갱신 전에 `await archiveRemovedNation(tx, worldId, nation, at)`를 부른다. `nation`은 같은 트랜잭션의 `loadWorld`로 읽은 `before`의 값, 곧 지워질 DB 행의 값이다.
- `persistEffects(tx, worldId, state, effects, at)`도 인자를 받아 world 효과일 때 그대로 넘긴다. `turnLoop.ts:179`는 `{ sequence, tick: due.nextTurnTick }`을 넘긴다. `sequence`는 같은 트랜잭션 `:160`의 `nextActionSequence` 값이고 `due.nextTurnTick`은 그 턴의 GeneralLog·BattleLog tick과 같다.
- `persistMonthly`에서 `yearbookSnapshot.create`(`monthly.ts:55-64`) 바로 뒤에 `await persistYearbookNations(tx, worldId, tick, next);`를 넣는다.
- 두 표 모두 `skipDuplicates`를 쓰지 않는다. 키 충돌은 오류이고 그 트랜잭션 전체가 롤백된다.

### 3.3 경계 사례

| 사례 | 결과 |
| ---- | ---- |
| 프레임 결합 | 프레임 `(worldId, tick)`의 `YearbookNation` 집합은 그 정산의 `next.nations`와 같고 `result.yearbook.nations`의 ID 집합과도 같다. 같은 tick의 장수 턴은 정산 뒤에 돌아 그 턴의 건국·멸망은 다음 프레임에 반영된다 |
| 행동 결합 | `RemovedNation.removedSequence`는 국가를 지운 장수 턴의 행동 번호이고 `removedTick`은 그 턴의 tick이다. 프레임 sequence와 비교하면 그 국가가 마지막으로 나온 프레임 뒤에 지워졌음을 알 수 있다 |
| 첫 정산 전·같은 달 안의 건국 뒤 멸망 | 프레임 행은 없지만 `RemovedNation` 행은 있다 |
| 같은 이름의 새 국가 | 멸망한 국가 3 "촉"과 뒤에 건국한 국가 4 "촉"은 ID가 달라 `RemovedNation`(3)과 `Nation`(4), 프레임 행이 따로 남는다 |
| 이름·색 변경 (T4-16 이후) | 다음 정산부터 새 값이 프레임에 남는다. 앞 프레임의 행은 그대로다. 멸망하면 삭제 직전 값이 `RemovedNation`에 남는다. 정산 사이 변경의 중간 값은 남지 않는다 |
| 턴 롤백 (오류·리스 토큰·만료·예턴 경합 `turnLoop.ts:211`) | `RemovedNation` 행과 국가 삭제가 함께 롤백된다. 다시 돌면 한 번만 생긴다 |
| 정산 롤백 | 프레임과 `YearbookNation`이 함께 롤백된다 |
| SIGKILL (commit 전·후), 재시작 | commit 전이면 셋 다 없고 재시작 뒤 한 번 쓴다. commit 후면 있고 재시작은 같은 턴·같은 달을 다시 처리하지 않는다 |

### 3.4 기존 데이터 백필

PR 1 migration 전에 쌓인 프레임에는 `YearbookNation`이 없고 그 전에 멸망한 국가에는 `RemovedNation`이 없다. migration에는 데이터 SQL을 넣지 않는다. `pnpm --filter @opensamguk/engine yearbook:backfill`(새 CLI)이 프레임 행만 채운다. `RemovedNation`은 백필하지 않는다. 그 전에 지워진 국가의 행동 번호를 저장한 곳이 없어서다.

**불변식.** 이 CLI는 국가 이름·색을 바꾸는 경로가 없는 빌드에서만 정확하다. 그 빌드에서는 어떤 국가든 생애 동안 이름·색이 한 값이므로 아래 증거가 그 국가가 나온 모든 프레임의 값이다. Codex는 구현 SHA에서 `name`·`color` 쓰기 경로를 다시 찾아 구현 기록에 적는다. 이름·색 변경을 넣는 PR(T4-16)은 같은 PR에서 이 CLI와 script를 지운다. 그래서 변경 경로가 있는 빌드에는 백필이 없다.

**증거.** 프레임 tick T의 국가 N에 대해 아래 셋 가운데 있는 것을 모두 모은다.

| 증거 | 조건 |
| ---- | ---- |
| `Nation` 행 (worldId, N) | 지금 살아 있다 |
| `RemovedNation` 행 (worldId, N) | migration 뒤 지워졌다 |
| `replayOrigin.initial.nations`의 N | 초기 국가다. `replayOrigin`이 `null`이면 이 증거는 없다 |

모은 증거의 이름·색이 서로 다르면 불변식이 깨진 것이다. 증거가 하나도 없으면(migration 전에 건국하고 멸망한 국가) 근거 없음이다. 사건 문구를 파싱해 이름을 만들지 않고 색을 정하지 않는다.

**처리.** 월드마다 한 트랜잭션에서 `SELECT id FROM "World" WHERE id = $1 FOR UPDATE`(엔진과 같은 잠금, `turnLoop.ts:102`)를 먼저 잡는다. 대상은 각 프레임의 `data.nations[].nationId` 하나하나다.

1. 사전 검사. 이 월드에 이미 있는 `YearbookNation` 행 가운데 지금 `Nation` 행이나 `RemovedNation` 행이 있는 국가의 것을 그 증거와 비교한다. 하나라도 다르면 이름·색이 바뀐 적이 있다는 뜻이므로 그 월드는 한 줄도 쓰지 않고 오류로 보고한다.
2. (프레임, 국가) 쌍마다 판정한다. 행이 이미 있고 증거와 같으면 그대로 둔다. 행이 있고 증거가 다르면 그 월드를 롤백하고 충돌로 보고한다. 행이 있는데 증거가 없으면 엔진이 쓴 값이므로 그대로 둔다. 행이 없고 증거가 하나로 모이면 넣는다. 행이 없고 증거끼리 다르면 그 월드를 롤백하고 충돌로 보고한다. 행이 없고 증거도 없으면 넣지 않고 근거 없음으로 센다.
3. 이 판정은 프레임에 이미 행이 있는지와 관계없이 쌍마다 한다. 앞선 백필이 일부만 채운 프레임도 빠진 국가만 다시 본다.

**보고와 실행.** 기본은 쓰지 않고 보고만 한다. `--apply`일 때만 쓴다. 두 번 돌려도 결과가 같다. 출력은 월드 ID, 프레임 수, 넣은 행 수, 이미 같은 값이던 행 수, 근거 없는 (tick, 국가 ID) 목록과 그 때문에 부분으로 남은 프레임 수, 충돌이면 그 쌍과 증거 출처다. 증거 값 자체와 연결 문자열은 출력하지 않는다. 실행 순서는 `pnpm db:migrate` → 보고 확인 → `--apply`이며 T4-16 병합 전이다.

**복구 경계.** 근거 없는 국가를 되살리는 길은 보관 파일 결정적 재생뿐이다. 해시가 모두 맞는 월드에서 재생 상태의 국가를 꺼내는 방식이며 이 작업 범위가 아니다. 부분 프레임은 PR 2 응답에서 그 국가가 `nations`에 없을 뿐이고 다른 국가 값은 정상이다.

### 3.5 조회 (PR 2)

T4-35의 `timelapse.frames`에 프레임별 필드 하나를 더한다. 새 절차가 아니므로 `router.ts`, `authz/exemptions.ts`, `tools/authz.integration.test.ts`, `visibility.ts`는 고치지 않는다. 입력, 정렬, cursor, `currentNations`는 T4-35 계약 그대로다.

  year: number;
  month: number;
  cities: { cityKey: number; nationId: number | null }[];
  nations: { id: number; name: string; color: string }[]; // 새 필드. 이 프레임 cities가 가리키는 국가의 그때 값, id 오름차순

- 같은 `readWorld` 트랜잭션에서 `tx.yearbookNation.findMany({ where: { worldId, tick: { in: 이 페이지 tick }, nationId: { in: 가리키는 ID } }, orderBy: [{ tick: 'asc' }, { nationId: 'asc' }], select: { tick: true, nationId: true, name: true, color: true } })` 한 번으로 읽는다. 고르는 칸이 모두 공개값이라 이 select는 `timelapse.ts` 안에 둔다.
