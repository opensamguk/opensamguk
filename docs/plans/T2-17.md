# T2-17 플레이어 가이드 9개

## 계획 (Claude)

### 목표

지인 테스트 참가자가 혼자 읽고 첫 장수를 만들어 예턴을 넣을 수 있는 플레이어 가이드 9개를 쓴다 (AC-M2-11).

### 범위

`docs/user/` 9개 뼈대를 실제 규칙으로 채운다. 게임 화면의 도움말 링크와 그 링크가 여는 가이드 화면도 이 작업(Claude)이 만든다 (아래 도움말 도달 경로).

### 하지 않는 것

원작 게시판 근거 문서(sources.md, 제외), 전략 공략, 영상.

### 결정

- **읽는 순서는 myosam 방식**: 기초(index) → 초급(장수와 도시, 시간과 턴) → 중급(전쟁, 지도와 보급, 재정과 외교, 국가 운영) → 참고(용어 사전, 명령과 실행 시기). 각 문서 끝에 "다음은 …" 링크.
- **규칙 근거는 코드다.** 수치·조건은 `packages/rules`와 `balance.ts`, 명령은 생성 문서(T2-16)를 기준으로 쓰고 문서마다 근거 파일을 맨 아래 한 줄로 남긴다.
- 원작과 다른 점(조약서, 작전판, 기본 방침, 발령 응답, 교역)은 원작 경험자가 헷갈리지 않게 "원작과 다른 점" 상자로 따로 표시.
- 처음 온 사람의 말로 쓴다. 은어는 용어 사전으로 링크.
- 화면 캡처는 넣지 않는다 (M2에서는 화면이 계속 바뀜). 화면 이름과 메뉴 위치를 글로 적는다.

### 도움말 도달 경로 (검토 R63-13, 2026-10-21 추가)

지금 웹에는 도움말 주소도 메뉴 항목도 없다(경로 트리 `apps/web/src/router.tsx:169-184`, 게임 메뉴 `apps/web/src/layout/GameLayout.tsx:12-17`).

- 소유: 링크와 가이드 화면은 이 작업(Claude, `apps/web`)이 만든다. 새 서버 API는 만들지 않는다.
- 방식: 웹 빌드가 `docs/user/`의 9개 문서와 생성 목록(`command-catalog.generated.md`)을 함께 묶어 `/help/:doc` 주소에서 보여 준다. 게임 메뉴와 로비에 도움말 링크를 둔다.
  문서 안 링크(다른 가이드, 생성 목록의 분류 절)는 같은 화면 안 주소로 바뀐다.
- 운영 빌드(`pnpm --filter web build` 결과를 띄운 화면)에서 도움말 → 가이드 9개 → 생성 목록과 그 절 링크가 실제로 열리는지 시험한다.

### 사실 확정 시점 (검토 R63-13, 2026-10-21 추가)

- 가이드는 리뷰를 통과해 합쳐진 기능만 완료된 기능으로 쓴다. 기능마다 근거 커밋 SHA와 리뷰 상태를 구현 기록에 적는다.
  대상은 기본 방침(T2-13·14), 조약과 교역(T2-07·08), 직책과 발령(T2-05·06), 메시지와 공지(T2-09·10), 작전판(T2-11·12), 알림(T2-20·21), 순위(T2-22·23)다.
- 아직 합쳐지지 않았거나 사용자 결정이 남은 기능(예: T2-13의 U63-1~3, T2-20의 U63-4·U63-5)은 쓰지 않거나 준비 중이라고 적는다. 초안 값을 확정된 규칙처럼 쓰지 않는다.
- 사실 대조는 위 기능이 모두 합쳐지고 리뷰어(Codex)가 각 문서의 수치·조건을 근거 파일과 대조했을 때 끝난다.
- 기존 뼈대의 틀린 사실도 이때 고친다. 예를 들어 `docs/user/time-and-turns.md:11`의 국가 예턴 12칸은 실제 30칸(`docs/architecture/command-protocol.md:102-104`)으로 고친다.
- 메인 흐름은 지도와 30칸 예턴 편집기가 한 화면에 있는 구성으로 설명한다. 예턴 저장(접수), 턴 실행(엔진), 실패·거절이 각각 언제 어디에 보이는지를 나눠 쓴다.
