# T4-88 지도 편집 캔버스를 rules 정본으로

> 대기열: T4-88 · AC: AC-P2-27 (편집기 일부) · 구현: Claude · 리뷰: Codex
> 선행: [T4-80 지도 편집 캔버스](./T4-80.md), [T4-76 지도 형식 v2·자원 검증기](./T4-76.md), [T4-77 초기화 자원 DB 이전](./T4-77.md) · 기준: `fff69d08`

## 계획 (Claude, Codex G-03 통과)

### 목표

지도 편집기(`/dev/map-editor`)의 형식 읽기와 검증 판단을 공개 `@opensamguk/rules/resources`의 `validateMap`으로 바꾼다. 화면 안 임시 타입과 임시 검사를 지운다. 화면은 보고를 문구·심각도·선택 대상으로만 바꾼다. 원본 `resources/map/che.json`에 기대던 시험 입력을 지운다. 이 작업이 끝나도 AC-P2-27을 완료로 세지 않는다.

### 범위

| 파일 | 내용 |
| ---- | ---- |
| `apps/web/src/mapEditor/contract.ts` | 자체 타입·읽기 함수 삭제. rules 타입 별칭, `DEFAULT_CANVAS=MAP_DEFAULT_CANVAS`, `isClosedPolygon=isClosedRing`. `parseMapJson`은 JSON 실패 문구를 지키고 `validateMap`을 불러 형식 오류나 `map-canvas-range`면 그 문구로 거부, 아니면 `normalizeMapToV2` |
| `apps/web/src/mapEditor/validate.ts` | 검사 로직 삭제. `toEditorIssues(report, map)`·`editorIssues(map)` adapter |
| `apps/web/src/mapEditor/MapEditorPage.tsx`, `MapEditor.module.css` | `오류`/`경고` 태그, 규모·지역 라벨의 `(1~8)` 삭제, 대상이 없는 항목은 눌러도 고르지 않음 |
| `apps/web/src/mapEditor/*.test.ts` | `node:fs`와 che 입력 삭제. 최소 3도시 v1 고정물, rules 경계로 바꾼 코드별 표 |
| `e2e/mapEditor.spec.ts` | `withE2eDb`·`readPublishedResources`로 게시된 MAP che@1을 읽어 시험 임시 파일로 올림 |

rules·server·db·resources·CI·다른 화면은 바꾸지 않는다. 판단은 `@opensamguk/rules/resources`의 `validateMap` 하나이고 `world/validate`의 다른 코드 목록과 섞지 않는다.

### adapter 규칙

- 대상: rules의 `city`·`terrain`은 그대로, `path`가 `['cities', n, …]`이면 도시 n, `['terrain', 층, n, …]`이면 그 선, 그 밖은 없음(`null`).
- 문구: `city-id-duplicate`, `city-name-duplicate`, `city-name-empty`, `city-out-of-canvas`, `link-self`, `link-missing-city`, `link-one-way`, `terrain-open`, `terrain-out-of-canvas`는 기존 조사 문장을 지킨다. `network-split`은 `"낙양이 업의 연결망에 닿지 않습니다."`로 바꾼다(rules가 첫 도시만 준다). 나머지 코드는 rules 문구를 그대로 쓴다.
- 심각도: rules 값을 그대로 쓴다(`city-off-land`는 경고). 내려받기 옆 오류 건수는 오류만 센다.

### 위험

- 이름 `''`이나 음수 규모는 `shape-invalid`라서 그 판의 의미 검사가 빠진다. 정본 동작이며 adapter가 그 도시를 가리킨다.
- 기본 `pnpm e2e`의 이 파일 첫 시험은 E2E DB에 che@1이 게시돼 있어야 한다. 없으면 `readPublishedResources`의 이유로 실패하며 대체 경로는 없다.
- `cityRadius`는 규모를 1~8로 묶으므로 규모 0·9도 음수 반지름을 만들지 않는다. 렌더는 바꾸지 않는다.

## 구현 상태

- 구현됨. 단위·경계·정적 검사와 실제 DB·브라우저 시험 5건을 통과했다. Codex 독립 리뷰의 필수 지적은 없다. 최종 CI와 정상 병합은 PR에서 확인한다.
- 계획과 달라진 점: `editor.test.ts`의 해안 고정물을 시험 도시를 감싸도록 넓혔다(땅 밖 경고 없이 오류 0건 단언을 지키려고). 강 1점 단언은 rules가 함께 내는 `terrain-degenerate`까지 정확히 본다.
