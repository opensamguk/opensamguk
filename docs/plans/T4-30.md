## 2. 계약

### 2.1 타입과 함수

```ts
// packages/rules/src/tournament/bracket.ts
import type { Rng } from '@opensamguk/shared';

export const MIN_BRACKET_PARTICIPANTS = 2;
export const MAX_BRACKET_PARTICIPANTS = 1024;
export const MAX_PARTICIPANT_ID = 2_147_483_647;

export type BracketSlot =
  | { kind: 'participant'; participantId: number }
  | { kind: 'winnerOf'; round: number; index: number }
  | { kind: 'bye' };

export interface BracketMatch {
  round: number; // 1부터
  index: number; // 라운드 안에서 0부터
  home: BracketSlot;
  away: BracketSlot;
}

export interface Bracket {
  size: number; // 참가자 수 이상인 가장 작은 2의 거듭제곱
  byes: readonly number[]; // 부전승 참가자 ID, 추첨 순서
  rounds: readonly (readonly BracketMatch[])[]; // rounds[r - 1]이 r라운드
}

export function createBracket(participants: readonly number[], rng: Rng): Bracket;
```

- 참가자 ID는 숫자다. 지금 장수 ID(`General.id`, PostgreSQL `Int`)와 API의 `entityKey`(`apps/server/src/queries.ts:7`, 1 이상 2147483647 이하)와 같은 범위다. 무엇의 ID인지는 이 함수가 모른다.
- RNG는 인자로 받는다. 같은 시드를 보장하는 것은 호출자의 몫이다. 시험은 `createRng(seed)`로 만든다. T4-31이 월드 시드에서 어떤 `rngFor` 스트림을 쓸지는 T4-31 계획이 정한다.
- `MAX_BRACKET_PARTICIPANTS = 1024`는 순수 함수의 입력 크기 상한(기술 경계)이다. 토너먼트 참가 정원이 아니다. 실제 정원은 T4-31이 U-09 뒤에 정하며 이 값 이하여야 한다. 더 커야 하면 이 계약을 다시 검토한다(3절 T30-Q2).

### 2.2 처리 순서

1. 입력 검사(2.3). 하나라도 실패하면 RNG를 한 번도 부르지 않고 예외를 던진다.
2. 입력 배열을 복사해 숫자 오름차순으로 정렬한다. 입력 순서는 결과에 영향을 주지 않는다.
3. 정렬한 복사본을 Fisher–Yates로 섞는다. `n`이 참가자 수일 때 `i = n − 1`부터 `1`까지 내려가며 `j = rng.int(0, i)`를 부르고 `i`번째와 `j`번째를 맞바꾼다. 결과를 추첨 순서 `draw`라 한다.
4. `size`는 `n` 이상인 가장 작은 2의 거듭제곱, 부전승 수 `b = size − n`이다. `byes = draw.slice(0, b)`.
5. 1라운드는 `size / 2`경기다. 인덱스 `i < b`인 경기는 `home = draw[i]`, `away = bye`. `i ≥ b`인 경기는 `k = b + 2(i − b)`일 때 `home = draw[k]`, `away = draw[k + 1]`.
6. `r ≥ 2`라운드의 `i`번 경기는 `home = winnerOf(r − 1, 2i)`, `away = winnerOf(r − 1, 2i + 1)`이다. 라운드 수는 `log2(size)`이고 마지막 라운드는 결승 한 경기다.

부전승 경기의 뜻. `away`가 `bye`인 1라운드 경기는 치르지 않는 경기이고 승자는 `home`이다. 경기 규칙(T4-54)과 진행(T4-31)은 이 경기에서 RNG를 쓰지 않아야 한다. 이 문장은 두 작업이 지킬 소비 계약이며 T4-30은 이 경기를 표시만 한다.

부전승은 추첨 순서 앞쪽 `b`명에게 가고 1라운드 위쪽 경기에 모인다. `n > size / 2`이므로 `b < size / 2`이고 한 경기에 부전승이 둘 들어가는 일은 없다. 2라운드부터는 부전승 칸이 없다. 부전승을 받은 두 참가자가 2라운드에서 만날 수 있다. 추첨이 무작위라 누가 부전승을 받는지는 공정하며 이 배치는 단순하고 결정적인 규칙으로 고른 것이다.

### 2.3 입력 검사

아래는 모두 `Error` 예외다. 게임 `Failure`로 바꾸지 않는다. 호출자(T4-31)가 먼저 걸러야 할 프로그램 오류이기 때문이다. 문구는 [글쓰기 규칙](../writing-style.md)을 따르고 시험은 문구가 아니라 예외 여부와 RNG 미소비를 본다.

| 순서 | 검사 | 예 |
| ---- | ---- | -- |
| 1 | `Array.isArray(participants)` | `null`, 객체 |
| 2 | 길이가 2 이상 1024 이하 | `[]`, `[7]`, 1025명 |
| 3 | 모든 인덱스에 값이 있다(빈칸 없는 배열) | `[1, , 3]` |
| 4 | 각 값이 `number`이고 `Number.isSafeInteger`이며 1 이상 2147483647 이하 | `'1'`, `1.5`, `NaN`, `0`, `-1`, `2147483648` |
| 5 | 중복 없음 | `[3, 3]` |

### 2.4 RNG 계약

- 성공하면 `rng.int`를 정확히 `n − 1`번, 인자 `(0, n − 1)`, `(0, n − 2)`, …, `(0, 1)` 순서로 부른다. `rng.next`와 `rng.pick`은 직접 부르지 않는다. 그래서 호출 뒤 RNG 위치는 `n`만으로 정해진다.
- 실패하면 RNG를 부르지 않는다.
- RNG 스트림을 새로 만들거나 시드 문자열을 읽지 않는다.
