## 계획 (Claude)

### 목표

AC-P2-18의 화면 몫이다. 명세 문장은 이렇다. 다른 국가 도시의 상세값은 첩보 기록으로만 보이고 몇 개월 전 기록인지 표시된다. 적 병력은 U-11에서 정한 구간으로 보인다.

이 작업이 끝나면 `spy`를 켠 월드의 메인과 도시 화면에서 아래가 보인다.

- 지도에서 다른 나라 도시를 고르면 도시 정보 칸이 자기 나라의 첩보 기록을 기록 연월·몇 개월 전·정보 단계와 함께 보인다. 병력은 승인 구간이고 오래된 기록도 기간 제한 없이 보인다. 기록이 없으면 기록이 없다는 안내가 나온다.
- 내 장수가 직접 서 있는 다른 나라 도시는 지금 값이 보인다(재야도 같다). 다른 나라 도시는 지금 값이 보이든 아니든 주둔 장수 표 대신 안내 한 줄이 나온다.
- 지도에서 첩보 기록이 있는 다른 나라 도시에 모양과 글자로 된 표시가 붙는다.
- `spy`를 끈 월드의 화면은 지금과 같다.

## 1. 화면 계약

### 1.1 도시 정보 칸

`CityInfo`는 응답에 `fog` 키가 있을 때만 바뀐다. 없으면 지금 코드 그대로다.

| 경우 (`fog` 있음)           | 수치 표 자리                                                                                       | 주둔 장수 자리                                  |
| --------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 상세(`isDetailedCity`)      | 지금처럼 지금 값                                                                                   | `garrisonHidden`이면 안내 한 줄, 아니면 지금 표 |
| 상세 아님, `fog.intel` 있음 | 안개 칸(1.2)                                                                                       | 같음                                            |
| 상세 아님, `fog.intel` 없음 | 안내 `첩보 기록이 없습니다. 예턴에 첩보를 넣으면 그때의 수치가 기록됩니다.`와 지금처럼 —인 수치 표 | 같음                                            |

수치 표 자리(지금 값인지)와 주둔 장수 자리(`garrisonHidden`)는 따로 정한다. 내 장수가 서 있는 다른 나라 도시는 상세 줄이지만 `garrisonHidden`이 참이라 주둔 장수 표 대신 안내가 나온다.

- 칸의 `data-visibility`는 `detail`, `intel`, `public` 셋이다(지금은 `detail`·`public`). E2E가 이 값으로 가른다.
- 공개 범위 밖 안내 문장(`:84`)은 켠 월드에서 1.3의 승인 문구로 바뀐다. 끈 월드 문장은 그대로다.
- 주둔 장수 자리는 서버의 `garrisonHidden`만 보고 바꾼다. 어느 도시를 가릴지 화면이 판단하지 않는다(T4-38 §3.1. 다른 나라 도시는 내 장수가 서 있어도 가린다. 자기 나라 도시와 공백지는 지금 표).

### 1.2 안개 칸 (`Fog.tsx`)

```text
첩보 기록 · 191년 2월 · 3개월 전 · 정보 많이
기록 당시 주인 [위나라]   (지금 주인과 다르면 [지금은 다른 나라 도시])
주민    12,345 / 30,000  ▇▇▇▇▁▁
농업     4,000 /  8,000  ▇▇▇▁▁▁    (단계 3이면 —, 이유: 정보를 어느 정도 이상 얻었을 때만 기록됩니다)
...
민심    72.5
장수 3명 · 병력 5,000~9,999
병종 창병 2 · 궁병 1           (단계 1만)
기술 내 나라보다 우위           (단계 1이고 주인이 국가일 때만)
기록은 첩보한 때의 값이며 다시 첩보하기 전까지 바뀌지 않습니다.
```

- 첫 줄은 제목이며 연월은 `formatYearMonth`, 나이는 `ageLabel`, 단계는 `levelLabel`이다(T4-13 `view.ts`). 같은 달이면 `이번 달`이다.
- 수치는 `StatTable`에 기록 값과 기록의 최대치를 넣는다. 기록에 없는 칸은 `value: null`과 `hiddenReason`이다. 지금 값으로 채우지 않는다.
- 병력은 `crewText`다. 구간이면 `5,000~9,999`, 위가 열리면 `50,000 이상`, 같은 값이면 한 값이다.
- 기록 당시 주인은 기록의 `owner`(이름·색)로 그린다. `world.map`의 지금 국가로 바꾸지 않는다. 공백지면 `공백지` 이름표다.
- 오래된 기록을 색으로만 흐리게 하지 않는다. 나이는 늘 글자로 쓴다(NFR-08).
- 숫자는 `.num`이다.

### 1.4 지도 표시

- 데이터: 메인과 지도 크게 보기가 `intel.records`를 받는다(`enabled`가 거짓이면 표시 없음). T4-13과 같은 쿼리 키라 캐시를 나눈다.
- `mapMarks.ts`의 `intelMarks(records, cities, myNationId)`가 `Map<cityKey, ageMonths>`를 낸다. 지금 주인이 내 나라인 도시는 넣지 않는다(그 도시는 지금 값으로 본다, IC-9).
- `WorldMap`에 선택 prop `intelMarks?: ReadonlyMap<number, number>`를 더한다. 표시가 있는 도시는 점 오른쪽 위에 작은 속 빈 마름모를 그리고 `cityLabel` 끝에 `, 첩보 기록 N개월 전`(같은 달은 `, 첩보 기록 이번 달`)을 붙인다. `<title>`과 `aria-label`이 같은 글이다. prop이 없으면 지금 그림과 같다.
- `MapLegend`에 선택 prop `intelLegend?: boolean`을 더한다. 참이면 `◇ 첩보 기록`(마름모 견본과 글자) 항목 하나를 붙인다.
- 색은 `--color-info` 토큰 하나를 쓰고 모양과 글자를 함께 둔다. 국가색은 쓰지 않는다(UI 지침 §1 3번).
- 공개 지도(T2-25)는 `intelMarks`를 넘기지 않는다.

### 1.5 불러오기와 갱신

지금 코드는 턴이 끝나도 도시 칸을 다시 받지 않는다. SSE `turn.result`는 `home.get`, `turns.get`, `records.general`만 무효화하고(`apps/web/src/realtime/useWorldEvents.ts:23~28`) `monthly.done`은 `world.summary`, `home.get`, `world.map`만이다(`:31~36`). SSE가 끊겼을 때의 0초 재조회도 `home.get`, `world.summary`, `records`뿐이다(`apps/web/src/layout/GameLayout.tsx:48~53`). `city.pathKey()`를 무효화하는 곳은 월드 상태나 시계 모드가 바뀔 때의 `plan.board`(`GameLayout.tsx:72~74`) 하나다. 그래서 첩보 뒤 같은 도시를 보고 있으면 창 포커스나 도시 다시 고르기 전까지 안개 칸이 옛 응답으로 남는다. 또 `turn.result`의 대상은 실행한 장수 한 명이다(`apps/engine/src/turnLoop.ts:276`, `target: { generalId }`). 같은 나라 다른 장수가 한 첩보는 그 알림으로 알 수 없다.

이 작업은 갱신 경로를 아래처럼 정한다.

| 경로                                                                            | 고치는 곳                                                               | 무효화에 더하는 키                                                |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------- |
| SSE `turn.result` (내 장수의 턴, 내가 한 첩보)                                  | `realtime/useWorldEvents.ts`의 `invalidationTargets` `turn.result` 갈래 | `trpc.city.pathKey()`, `trpc.intel.records.queryKey({ worldId })` |
| SSE `monthly.done` (달마다 한 번, 같은 나라 다른 장수의 첩보와 몇 개월 전 증가) | 같은 함수의 `monthly.done` 갈래                                         | 같은 두 키                                                        |
| SSE가 끊긴 동안의 0초 재조회 (내 장수의 턴)                                     | `layout/GameLayout.tsx`의 `refresh`                                     | 같은 두 키                                                        |

- 같은 나라 다른 장수가 한 첩보는 다음 `monthly.done`, 내 다음 턴, 창 포커스, 도시 다시 고르기 가운데 먼저 오는 때에 보인다. 이것보다 빨라야 하면 같은 나라 전체에 보내는 새 SSE 알림이 필요하고 그것은 서버 몫(T2-09)이라 이 작업 범위 밖이다(§4 Q3).
- `turn.result`는 첩보가 아닌 턴에도 오므로 도시 칸 재조회가 늘어난다. 보고 있는 도시 하나의 쿼리만 다시 받으므로(`city.pathKey()` 아래 활성 쿼리) 부담은 턴마다 요청 하나다.
- 지도 표시용 `intel.records`도 위 세 경로에서 함께 다시 받는다. T4-13 기록 탭도 같은 쿼리라 함께 맞는다.
- 끈 월드도 같은 무효화를 받지만 `intel.records`는 `{ enabled: false }`이고 화면이 그리지 않으므로 보이는 것은 바뀌지 않는다.
