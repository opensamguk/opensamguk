# T3-09 D17 관직 주재 효과

> 대기열: T3-09 · AC: AC-M3-12 · 구현: Codex · 리뷰: Claude
> 선행: M2 전체 · 착수 전 사용자 결정: 아래 U1~U3 · 다음: [T3-16 화면](./T3-16.md) (Claude) · 관련: [차별화 D17](../product/differentiation.md#d17-관직-주재-효과), FR-DIF-17, [T1-07 월간 정산](./T1-07.md), [T2-05 직책·인사](./T2-05.md), [T2-02 프리셋](./T2-02.md)
> [D-029](../product/decisions.md#d-029-재생-형식은-기능-표시-하나로-두고-codex가-통합-입력-처리기를-먼저-만든다-2026-10-23)(U62-5 결정, 2026-10-23)로 재생 형식과 입력 처리는 T2-26 기반 위에 얹는다. 이 문서의 형식 번호·처리기 절은 T2-26 계획이 나온 뒤 다시 쓴다. 본문은 그때까지 결정 전 원고로 남긴다.

## 계획 (Claude)

### 목표

태수·군사가 담당 도시에 머물면 월간 정산에 정해진 보정이 붙고 떠나면 다음 정산부터 빠진다. 중앙 관직의 주재 효과는 설정 파일 하나에 표로 있다 (AC-M3-12, 골든 테스트).

### 담당과 수정 범위

| 담당 | 에이전트 | 고치는 곳 |
| ---- | -------- | --------- |
| 구현 | opensamguk-implement (Codex) | `resources/office-effects.json`(새로), `packages/rules/src/office/`(새로: 표 스키마, 주재 판정, 보정 계산), `packages/rules/src/monthly/`(보정 적용), `packages/rules/src/personnel/`(태수·군사 임명 규칙), `packages/db` 새 migration, `apps/engine`(임명 처리, 관직 해제), `apps/server/src/routers/personnel.ts`(입력 확장) |
| 리뷰 | opensamguk-review (Claude) | 코드, 골든 파일, 설정 표, 채울 문서 |

### 하지 않는 것

- 종사(`officerLevel` 2). AC는 태수·군사만 요구한다.
- core2026의 관직별 명령 점수 ×1.05와 통솔 보너스(`packages/logic/src/actionModules/officerLevel.ts`) 이식. 이 작업의 효과는 월간 정산에만 붙는다.
- 월간 정산에 새 단계(예: 치안 감소, 도적) 만들기. 정산 순서는 AC-M1-12 그대로이며 기존 단계 안의 계산에만 보정을 곱한다.
- NPC 군주가 태수·군사를 임명하는 판단. 백로그 후보로 남긴다.
- 화면. 인사 화면의 임명 칸과 도시 정보의 주재 표시는 Claude 영역이며 [T3-16](./T3-16.md)이 맡는다.
- T2-05 직책 표의 이름 체계 변경, 자원 5종·縣식 생산·능력치 5종 등 승인 대기 중인 핵심 규칙 변경 10건.

### 지방 관직

- 숫자는 원작을 따른다. `officerLevel` 4가 태수, 3이 군사다 (core2026 `df6c926` `app/game-engine/src/turn/cityOfficeRequests.ts`의 `{ 2: '종사', 3: '군사', 4: '태수' }`). T1-03이 보존한 0~12 체계에서 비어 있던 자리다.
- 담당 도시는 새 칸 `General.officerCityKey`(정수, 없을 수 있음)에 둔다. DB CHECK로 `officerLevel`이 3·4일 때만 값이 있게 한다. `(worldId, officerCityKey, officerLevel)` 부분 고유 색인으로 도시마다 태수 1명·군사 1명만 둔다.
- 자격은 같은 국가 소속의 일반 장수(`officerLevel` 0~1)다. 태수는 무력, 군사는 지력이 `stat.chiefMin`(지금 65) 이상이어야 한다 (core2026 `packages/logic/src/personnel/officeRequest.ts`의 같은 하한). 담당 도시는 자기 국가 도시여야 한다.
- 임명·해임은 T2-05의 즉시 행동을 넓힌다. `personnel.appoint({ worldId, generalId, officerLevel, cityKey? })`에서 3·4면 `cityKey`가 꼭 있어야 하고 그 밖의 직책에는 받지 않는다. 권한은 T2-05 표대로 군주만이다. 엔진이 `InputEvent(kind: 'personnel.appoint')`를 처리한다.
- 입력 처리와 재생은 따로 만들지 않는다. main `76d56d0`의 엔진은 `general.create`만 꺼내는 `processCreation`(`apps/engine/src/inputs.ts:11-80`)을 쓰고 재생은 `turns.set`·`general.create`만 받는다(`packages/rules/src/replay.ts:67-108`). `personnel.appoint`는 T2-05(PR #51)의 새 입력이고 모든 kind를 한 줄로 꺼내는 처리기와 재생 형식 2의 소유자는 PR #62 T2-07 계획의 U62-5에서 사용자와 Codex가 정한다. 이 작업은 그 처리기와 형식 위에 태수·군사 갈래만 더한다.
- `loadWorld`는 장수 행을 칸째로 읽으므로(`apps/engine/src/worldLoader.ts:27-35`) `General.officerCityKey`는 그대로 두면 `hashState`에 들어간다. 기존 형식 월드의 해시를 바꾸지 않도록 이 칸은 새 재생 형식에서만 상태에 넣는다. 같은 파일 28-33행이 순위 누계를 빼는 방식과 같다. `World.officeEffects`는 지금 `loadWorld`가 읽지 않으므로 재생에 쓰려면 생성 원본이나 상태에 실어야 하고 그 운반 경로도 새 형식을 따른다. 형식 번호는 이 작업이 정하지 않고 착수 때 main의 최신 형식 다음 번호를 쓴다. T3-07의 평판 형식과 같은 시기면 한 번호로 모을지 착수 때 정하고 구현 기록에 적는다.
- 자리에 이미 사람이 있으면 교체한다. 이전 관직자는 일반 장수(1)가 되고 두 장수의 로그에 한 줄씩 남는다.
- 관직이 풀리는 때: 담당 도시를 빼앗김, 소속을 떠남(하야·등용 수락), 나라 멸망, 해임, 수뇌로 임명됨. 엔진이 그 일을 처리하는 같은 트랜잭션에서 `officerLevel`을 1(멸망·하야는 0)로, `officerCityKey`를 비운다. 담당 도시를 떠나 이동하는 것만으로는 관직이 풀리지 않고 주재만 끊긴다.

### 주재 판정과 보정 시점

```text
월간 정산 시작 (달 경계 앞의 장수 턴을 모두 처리한 상태, T1-07)
  주재 표 만들기 (읽기만)
    지방 관직  General.cityKey == officerCityKey 이면 담당 도시에 그 관직의 효과
    중앙 관직  현재 도시가 자기 국가 도시이면 현재 도시에 그 관직의 효과
  1단계 세금·봉급   도시 수입 × (1 + 그 도시 tax 보정)
  2단계 인구·민심   population·trust 보정이 있으면 그 도시 증가분에 곱함
  3단계 보급        supplyLoss 보정이 있으면 끊긴 도시의 손해에 곱함
  4·5단계           보정 없음
```

- 판정은 정산 순간에 한 번 한다. 달 중간에 들렀다 떠난 관직자는 세지 않는다. 그래서 담당 도시를 떠나면 그다음 정산부터 보정이 빠지고 돌아오면 다시 붙는다.
- 반기 세입(1·7월 금, 4·10월 쌀, T1-07)은 그대로다. `tax` 보정은 세입이 있는 달의 그 도시 수입에만 붙는다.
- 정수화는 각 단계 끝에서 반올림하는 T1-07 규칙을 따른다. 보정은 단계 안에서 곱하고 같은 자리에서 반올림한다.
- 세입이 있는 달에 보정을 받은 관직자의 장수 로그에 한 줄을 남긴다 (예: `태수로 머문 진류의 세수가 120 늘었다`).
- 관직자가 없는 월드에서는 정산 결과가 지금과 같아야 한다. 시나리오 1030에는 관직 3·4가 없으므로 T1-07 골든은 바뀌지 않는다.

### 설정 파일

`resources/office-effects.json` 하나에 지방·중앙 관직의 효과를 표로 둔다. 데이터 모델의 `OfficeEffect`(리소스 파일)가 이것이다.

```json
{
  "$comment": "D17 관직 주재 효과. 새로 작성. 값의 근거는 docs/plans/T3-09.md와 결정 기록",
  "version": 1,
  "stacking": "U1 결정 값",
  "local": [
    { "officerLevel": 4, "name": "태수", "effects": [{ "target": "tax", "rate": 0.1 }] },
    { "officerLevel": 3, "name": "군사", "effects": [{ "target": "tax", "rate": 0.1 }] }
  ],
  "central": ["U3 결정 값"]
}
```

- `target`은 월간 정산에 실제 있는 계산만 받는다: `tax`(1단계 금·쌀 수입), `population`(2단계 인구 증가분), `trust`(2단계 민심 변화), `supplyLoss`(3단계 보급 끊김 손해). 다른 값은 zod 스키마가 로드 때 거부한다.
- `rate`는 더하는 비율이다 (0.1이면 +10%). 범위는 −0.5~0.5다.
- 월드를 만들 때 이 파일 내용을 `World.officeEffects`에 사본으로 저장한다 (T2-02 프리셋 사본과 같은 이유, 재생 결정성). 이 작업 전에 만든 월드는 null이며 효과가 없다.
- 지방 관직 두 줄의 +10%는 [차별화 D17](../product/differentiation.md#d17-관직-주재-효과)의 "세수 +10%"(myosam)가 근거다. 이 밖의 값은 아래 사용자 결정을 받아서만 채운다.

### 착수 전 사용자 결정

지금 제품 문서로 정할 수 없는 값이다. 계획은 추정하지 않는다. 결정은 Claude가 [결정 기록](../product/decisions.md)에 새 번호로 남기고 이 문서의 설정 파일 절을 고친다.

| ID | 결정할 것 | 지금 문서 근거 | 고를 수 있는 범위 |
| -- | --------- | -------------- | ----------------- |
| U1 | 태수와 군사가 같은 도시에 함께 머물 때 세수 보정을 겹칠지 | D17은 "태수·군사 … 세수 +10%"만 적고 겹침은 적지 않았다 | 겹치지 않음(+10%) 또는 더함(+20%) |
| U2 | myosam의 "치안 감소 절반" 처리 | 우리 월간 정산(T1-07)에는 치안이 줄어드는 단계가 없다 | 뺀다, 또는 위 `target` 넷 중 하나로 바꾼다. 치안 감소 단계를 새로 만드는 것은 정산 순서를 바꾸는 일이라 이 작업 범위 밖이다 |
| U3 | 중앙 관직 중 효과를 받을 관직과 대상·값 | D17은 "중앙 관직 몇 개 … (예: 세금, 병량, 도적 감소)"까지만 적었다. 우리 정산에는 도적 단계가 없다 | 관직은 T2-05의 11 참모, 5~10 수뇌. 대상은 `target` 넷 |

U1~U3가 정해지기 전에는 보정 겹침, 치안 감소의 대체, 중앙 관직의 대상·값과 그 제품 효과를 확정하지 않는다. M2가 완료되고 사용자가 이 계획을 검토한 뒤에는 다른 작업에 기대지 않는 순수 부분인 표 스키마, 주재 판정, 테스트 틀을 미리 만들 수 있다. 월드에 실제 기본값을 적용하는 일, 태수·군사 임명·해제, DB migration, 월간 정산에 실제 효과를 잇는 일, 리뷰 통과와 AC 통과 표시는 U1~U3가 결정 기록에 오르고 설정 파일에 반영된 뒤에만 한다. 지금 관문 M1에서는 이 준비도 시작하지 않는다.

### API와 화면에 줄 모양

```ts
personnel.appoint({ worldId, generalId, officerLevel, cityKey? })   // T2-05 계약 확장. 3·4면 cityKey 필수
personnel.officers({ worldId }) → [{ generalId, name, officerLevel, isHuman, cityKey,
                                      officerCityKey: number | null, resident: boolean }]
city.get({ worldId, cityKey }) → 기존 필드 + officers: [{ generalId, name, officerLevel, resident }]
```

- 관직 이름과 관직자 이름, 주재 여부는 모두 공개한다. 다른 국가 장수의 이름·소속·위치는 이미 T1-12 공개 범위 안이다. main `76d56d0`의 `city.get`(`apps/server/src/routers/city.ts:7-19`)은 그 도시에 있는 장수를 누구에게나 `{ id, name, nationId }`로 낸다(`apps/server/src/visibility.ts:65-69`).
- `city.get`에는 `officers` 키 하나만 더한다. 기존 키와 `generals` 항목 모양은 그대로이며 `apps/server/src/routers/reads.integration.test.ts:273-302`의 공개 범위 시험이 고치지 않고 통과해야 한다. `General`에 새 칸이 생겨도 장수 정보는 `ownGeneralInfo`(`visibility.ts:35-63`)가 나열한 필드만 내므로 `officerCityKey`를 내려면 그 목록에 명시해서 더한다.
- 장수 ID는 임명 대상으로만 받는다. 행위자(군주)는 세션에서 정한다.

### 권한 시험

| 절차 | 성공 | 무인증 | 다른 사용자 | 제재 | 잘못된 입력 |
| ---- | ---- | ------ | ----------- | ---- | ----------- |
| `personnel.appoint` (태수·군사) | 군주가 자기 도시에 태수 임명 | `UNAUTHORIZED` | 일반 장수·수뇌·다른 국가 군주 `FORBIDDEN`, DB 변경 없음 | `User.status = SANCTIONED` 세션 거부, InputEvent 없음 | `cityKey` 없음, 다른 국가 도시, 무력 64 태수, 지력 64 군사, 다른 국가 장수, 3·4 밖 직책에 `cityKey` |
| `personnel.officers` | 관직 목록 | `UNAUTHORIZED` | 다른 국가 목록은 T2-05 규칙대로 | 거부 | 없는 월드 |
| `city.get` (관직 칸) | 관직자와 주재 | `UNAUTHORIZED` | 공개 필드만 | 거부 | 없는 도시 |

T3-05가 월드별 제재를 더하면 제재 칸은 그 판정을 따른다. 각 사례는 T3-04의 `authzCase`(main `76d56d0` `apps/server/src/authz/case.ts:6`)로 적는다. `pnpm test:authz`가 `AppRouter`의 모든 절차를 다섯 종류와 대조하므로 새 절차나 넓힌 절차의 사례가 빠지면 실패한다. `personnel.appoint`는 mutation이라 변경 요청 제한(`apps/server/src/trpc.ts:16-25`)도 받는다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 주재 골든 | 고정 시드 1030 월드에서 한 도시에 태수를 임명하고 1월(금 세입)까지 진행 → 그 도시 수입이 보정 없는 대조 실행의 1.1배인 기대 스냅샷과 같음 |
| 떠남 골든 | 이어서 태수가 다른 도시로 이동한 뒤 7월(금 세입)까지 진행 → 그 도시 수입에 보정 없음. 돌아오면 다시 붙음 |
| 군사·겹침 | 골든: 군사만, 태수·군사 함께 (U1 결과대로) |
| 중앙 관직 | 단위: 표의 중앙 관직이 자기 국가 도시에 머물면 그 도시에 효과, 다른 국가 도시면 없음 (U3 결과대로) |
| 설정 표 | 단위: 스키마 통과, 없는 `target`·범위 밖 `rate` 거부. 월드 생성 뒤 파일을 바꿔도 그 월드 결과 그대로 |
| 관직 해제 | 통합: 담당 도시가 점령되면 같은 트랜잭션에서 관직이 풀림. 하야·멸망·해임도 같음 |
| 기존 골든 | T1-07 월간 정산 골든이 바뀌지 않음 |
| 재생 | 통합: 임명 InputEvent를 넣은 12개월 재생 해시가 같음 (U62-5가 정한 처리기·형식으로). 이 작업 전 형식의 월드는 그 형식대로 재생이 통과 |
| 권한 | 위 표 전부 |
| 전체 | `pnpm check`(문구 strict 검사 포함), `pnpm test:int`, `pnpm test:authz` |
