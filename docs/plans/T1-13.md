# T1-13 화면 기반: 라우팅, 레이아웃, 디자인 토큰, 레퍼런스

> 대기열: T1-13 · AC: AC-M1-19 (기반) · 구현: Claude · 리뷰: Codex
> 선행: T1-02 · 관련: [UI 지침](../frontend-ui-guidelines.md), D-007, D-013, 가정 A10

## 계획 (Claude)

### 목표

핵심 화면 6개를 얹을 바탕을 만든다. API가 없어도 끝낼 수 있는 일만 한다.

### 범위

`apps/web`, `docs/frontend-ui-guidelines.md`, `docs/design/references/`

### 하지 않는 것

실제 데이터 연결(T1-14~T1-16), 반응형 마감(M3 T3-10), 다크 모드 완성(토큰 자리만).

### 결정

| 항목 | 결정 | 이유 |
| ---- | ---- | ---- |
| 라우팅 | TanStack Router (코드 기반 route 정의) | 타입 안전한 경로·검색 인자, React Query와 잘 맞음 |
| 데이터 | TanStack Query + `@trpc/tanstack-react-query` | 캐시·재조회·로딩 상태를 표준으로 |
| 스타일 | CSS Modules + `:root` CSS 변수 토큰 | 의존성 최소. 표 위주 화면이라 유틸리티 CSS 이득이 작음 |
| 글꼴 | Pretendard (npm `pretendard`, 자체 호스팅), 숫자는 `tabular-nums` | 한글 가독성, 숫자 정렬 |
| 지도 | SVG (도시 좌표·연결선은 `world.map` 응답) | M1은 타일 이미지 없이. 와룡전 타일은 라이선스 위험 (image-assets.md) |

### 주소 체계

```text
/login, /signup
/w/:worldId               메인
/w/:worldId/map           지도
/w/:worldId/turns         예턴 편집
/w/:worldId/city/:key     도시 정보
/w/:worldId/nation/:id    국가 정보
/w/:worldId/records       기록 (탭: 장수·국가·월드)
/w/:worldId/create        장수 생성
```

로그인 안 됨 → `/login?next=…`. 장수 없음 → `/w/:worldId/create`. 새로고침·직접 주소 접근이 모두 동작해야 한다.

### 레이아웃

- 데스크톱: 위쪽 띠(월드 이름 · 게임 연월 · 다음 턴까지 남은 시간 · 메뉴), 왼쪽 내 장수 요약 고정, 가운데 본문.
- 원작 정보량: 메인 한 화면에 장수·도시·국가·예턴 앞 5칸·최근 로그가 다 보이게 격자 배치.
- 공통 부품: `StatTable`(오른쪽 정렬 숫자, 최대치 막대), `ValueDelta`(+/− 색·부호), `NationBadge`, `EmptyState`/`ErrorState` 구분,
  `DisabledReason`(못 쓰는 버튼은 점선 + 누르면 이유, v1 원칙).

### 디자인 토큰

- 색: 배경·표면·글자·구분선·강조, 상태(성공·실패·경고·정보). 국가색은 토큰이 아니라 데이터에서 온다.
- 크기: 글자 12·13·14·16·20·24, 간격 4의 배수, 표 행 높이 28px.
- 다크 모드: 같은 토큰 이름을 `prefers-color-scheme: dark`에서 바꾼다 (자리만, 다듬기는 M3).

### 외부 레퍼런스 (A10)

정보 밀도가 높은 전략·관리 화면 레퍼런스 3~5장을 `docs/design/references/`에 모으고 `sources.json`에 출처를 적는다.
방향 합의용이며 화면에 다시 쓰지 않는다. 고른 뒤 사용자에게 한 번 보여 주고 가정 A10을 확인받는다.

### 접근

1. 의존성 추가, 라우터·쿼리 클라이언트 설정, tRPC 클라이언트를 React Query 방식으로 교체.
2. 토큰·글꼴·공통 부품 + 각 부품의 상태별 모습을 보는 `/dev/ui` 페이지(개발 모드에서만).
3. 레이아웃과 빈 화면 6개(자리표시), 로그인 가드.
4. 레퍼런스 수집, UI 지침 §3·§4 채우기.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 주소 | Playwright: 각 주소 직접 접근·새로고침 → 해당 화면(자리표시)과 위쪽 띠 표시 |
| 가드 | Playwright: 세션 없이 `/w/1` → `/login?next=/w/1` (T1-14 전까지는 자리표시 로그인) |
| 부품 | Vitest + Testing Library: `ValueDelta` 부호·색, `StatTable` 숫자 정렬 클래스 |
| 경계 | `pnpm check` (web은 server 타입만 import) |
