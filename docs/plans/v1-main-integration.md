## 1. 기준과 이번 요청에서 정한 것

개발 기준은 `opensamguk/opensamguk`의 원격 main `e3cd34f8707526995e37c04090a8532c47e12b02`다. v1의 비교 기준은 비공개 `peppone-choi/opensamguk-v1` main `bc053629710711d4c5dfa50683bae78f4baeca95`다. 로컬의 오래된 main을 기준으로 합치지 않는다.

사용자는 v1의 행군·휘하를 살리고 1턴은 현 main처럼 1개월로 유지하며 기존 지형과 군현 구획·와룡전풍 그림을 새로 만들기로 했다. 그 뒤 군현을 게임 단위로 삼지 않겠다고 정했고 전체 삼국지 시리즈 도시 목록을 후보로 놓되 삼국지 10의 지도를 기준으로 섞는 안을 요청했다. 따라서 v1의 1,608개 프로빈스·1,428개 관할·기존 래스터는 가져올 범위에서 뺀다.

삼국지 10의 지형·50도시·8관문을 골격으로 삼고 현 main의 도시·길목·전장을 선별해 섞는다. 첫 판의 권장 규모는 초·홍농·광릉을 더한 53도시다. 94개 전부를 도시로 남기거나 v1의 상세 지도 데이터와 합치는 안이 아니다. 이 문서의 53도시·항구 배치는 상세 검토를 받을 설계 제안이며 사용자에게서 수치별 승인을 받았다고 기록하지 않는다.

## 3. 지도는 관리 단위와 이동 공간을 나눈다

도시는 인구·내정·징세·수도·국가 점령의 단위다. 도시 사이의 별도 거점는 위치와 이동을 위한 것이며 군현처럼 세금·태수·개별 소유권을 갖지 않는다. 산맥이나 강의 표시가 곧 통행 간선이라는 뜻도 아니다.

| 종류         | 하는 일                            | 소유와 경제                                | 연결 규칙                                       |
| ------------ | ---------------------------------- | ------------------------------------------ | ----------------------------------------------- |
| 도시 `CITY`  | 내정·징세·임명·모병·기수 승리 판정 | 독립된 인구·경제·국가 소유                 | 도로·관문·항구로 이어짐                         |
| 관문 `PASS`  | 진입 통제·수비·공격                | 별도 수비·통제권, 도시 세입 없음           | 적 관문을 우회하려면 실제 우회 경로가 있어야 함 |
| 항구 `PORT`  | 육로와 수로의 승하선·연결          | 연결 도시의 시설, 별도 세입·승리 거점 아님 | 수송 수단·이동 방식이 맞는 수로만 이용          |

추가 3곳은 모두 전체 시리즈의 후보에도 있는 지명이다. 초(기존 38)는 허창·여남·수춘 사이의 기존 도시 역할을 살리고 홍농(42)은 관중과 낙양 사이의 도시와 관문을 구분하며 광릉(83)은 강동 북쪽의 도시·도하 역할을 살린다. 광릉은 기존 요충지에서 도시로 승격한다. 따라서 53도시는 main의 48개 위치에 대응하고 5개 위치를 새로 만든다. 기존 인구·시설 수치를 기계적으로 합산하지 않고 53도시의 세입·방어·공백지 균형을 다시 검증한다.

나머지 추가 도시 후보는 첫 판에서 보류한다. 하북 도시 밀도를 보강할 거록·중산·감릉, 청주의 제남·성양, 서북의 금성, 남부의 합포 등은 후속 지도 판의 후보로 보존한다. 같은 장소의 대체 명칭은 중복 도시를 만들지 않는다.

서량→무위, 패→소패, 하변→무도는 새 판의 표시명 대응이다. 역사상 모든 시기에 같은 행정구역이었다는 뜻이 아니며 원래 이름은 출처 대응에 남긴다. main의 75번 양평은 한중 옆 관문이므로 요동 양평 도시와 매칭하지 않는다. 60번 안평이나 59번 대도 위치를 확인하지 않고 양평·대현으로 바꾸지 않는다.

### 항구와 전장

94개 원본에는 명시적 항구 기록이 0개다. 해안에 가깝거나 강과 연결됐다는 이유로 기존 거점을 항구로 판정하지 않는다. 삼국지 10의 두 참고 페이지도 항구 목록은 제공하지 않는다.

첫 수로 설계 후보는 강릉·강하·시상·여강·건업·오의 항구 시설 6곳이다. 우리 게임의 설계 제안이며 삼국지 10에 독립 항구 6개가 있었다는 주장이 아니다. 장강 수로의 방향·승하선·통과 권한이 검증된 연결만 활성화한다. 해상 원정·해전 전체는 미룬다.

기존 역경·계교·관도·정도·합비·적도·가정·기산·이릉·장판·백랑·적벽·파양 13곳은 전장·요충지 후보로 분리한다. 13곳 모두를 첫 지도에 반드시 넣지는 않는다. 실제 연결과 역할을 검토해 선택한다. 광릉은 53도시에 포함하므로 같은 지점을 별도 과세 전장으로 중복 생성하지 않는다. 동황은 정체와 위치 근거를 회수하기 전까지 활성화하지 않는다.

### 새 지형과 그림

삼국지 10의 도시·길목·산맥·수계의 상대 배치를 기준으로 새 경로 지도를 그린다. 화면상 가까워도 강·산맥 때문에 직접 연결하지 않을 수 있고 표시 좌표의 직선 거리로 이동 시간을 만들지 않는다. v1 래스터나 와룡전 타일을 재색칠해 새 지도라고 부르지 않는다.

D-035에 따라 실제 Natural Earth 지형·해안선·하천·호수를 렌더링한다. 생성 이미지로 지리 배경을 대체하지 않는다. 거점은 실제 좌표를 바탕으로 가독성·연결 관계에 맞춰 조정할 수 있지만 그 차이를 화면에 나누어 표시하지 않는다. 지리 데이터와 거점 좌표·연결은 별도 층으로 편집한다.

구현할 때 자연 지형 원천이 필요하면 [Natural Earth 이용 조건](https://www.naturalearthdata.com/about/terms-of-use/)과 [NOAA ETOPO 자료](https://www.ncei.noaa.gov/products/etopo-global-relief-model)의 선택한 배포본을 확인해 새 입력 manifest에 버전·해시·출처를 고정한다. 현대 수계를 후한 시기와 같다고 가정하지 않는다. 게임상 재구성한 길·경계는 재구성이라고 표시한다. v1 NOTICE가 별도 조건을 명시한 CHGIS 파생 좌표·군현 경계는 자동 반입하지 않는다.

## 4. 데이터와 저장 계약

### 지도 판과 위치

현재 `mapV2Schema`는 도시 목록에 표시용 지형을 붙이는 형식이고 편집기 한도는 300도시·700×500이다. 이번 규모를 담을 수 있다는 이유만으로 이동 규칙까지 v2에 몰래 추가하지 않는다. 도시 키를 유지하는 새 `mapV3` 계약을 정의하고 v1·v2의 의미와 해시는 보존한다.

새 판은 `cities`, `sites`, `routes`, `terrain`, `renderManifest`를 갖는다. `cities`만 기존 `City` 경제 행에 대응한다. `sites`의 키는 `city:1`, `pass:75`, `field:80`, `port:13`처럼 종류를 포함하며 지도 연결의 정본은 안정된 노드·간선 ID다. 타일 번호·그림 픽셀·배열 순번은 게임 ID가 아니다.

간선은 양 끝, 방향, 이동 방식, 연결 활성 상태을 명시한다. 경로·위치·그림의 판 해시가 다르면 새 판을 추정해 끼우지 않고 거부한다. 지도 판은 `GameResource`의 불변 판 체계를 확장해 보관한다. 실행에 필요한 그래프는 월드 생성 기록과 재생 자료에도 고정한다. 큰 그림은 런타임 그래프와 분리해 해시로 참조하고 매 API 응답에 넣지 않는다.

기존 월드의 `General.cityKey`는 현재 의미를 유지한다. 새 지도에서 별도 거점 체류가 필요하면 단일 거점 ID와 기존 도시 키의 호환 앵커만 설계한다. 간선 위 진행 위치는 만들지 않는다. 인접 거점·관문·항구가 기존 이동·출병 명령에 들어가는 조건은 INT-02·03에서 확정한다.

### 첫 시나리오의 대응

첫 역사 시나리오는 main 1030의 191년 군웅할거를 기준으로 별도 키 `integration-1030-v1`을 만든다. 원본은 21국·491장수이며 이름만 보고 v1의 190년 3190 시나리오와 섞지 않는다. 지도에 없는 옛 도시·관문·전장의 소유는 새 도시 소유·관문 통제·전장 영향으로 분리한다.

도겸의 옛 서주·하비는 새 하비 권역에 연결하고 공손도의 옛 안평은 출처를 대조한 대응표를 통해 새 요동 양평에 연결하는 안을 검토한다. 후자는 안평이라는 이름이 양평의 별칭이라는 주장이 아니다. 75번 양평관은 장로의 한중 방면 통제 거점으로 따로 남긴다. 유언의 면죽·자동과 이각의 홍농·함곡도 도시 세입과 관문 통제를 나누어 적는다.

새 도시의 초기 소유·군주의 위치·역사 인물의 위치는 대응표로 고정한다. 누락·충돌은 생성 전에 거부하고 아무 도시로 무작위 대체하지 않는다. 새 다섯 도시의 배치와 출처가 끝나기 전에는 이 시나리오를 게시하지 않는다.

### 휘하와 군단

추가 저장 후보는 `RetinueLink`, `RetainerState`, `Unit`, `Deployment`, `MarchOrder`, `GeneralPosition`이다. 이름은 상세 계획에서 확정하되 모두 worldId를 포함한다. 개인 관계·국가 직책·군단 지휘권은 별도 사실로 저장한다.

새 판의 병력 정본은 `Unit`이다. `General.crew`와 부곡에 같은 병력을 동시에 넣지 않는다. 기존 월드는 기존 `crew`를 그대로 쓰고 새 판에서는 모집·편성·해산·전투가 같은 병력 원장을 사용한다. 지휘관은 활성 군단 하나만 지휘하고 한 부곡은 활성 군단 하나에만 들어간다. DB 고유 제약과 엔진의 재검사를 함께 둔다.

## 5. 이동은 main 방식을 유지한다

D-034로 v1 행군 이식을 취소했다. 1턴 1개월·기존 예턴·이동·귀환·출병 규칙을 유지한다. 거리 비례 이동 기간, 속도, 간선 중간 위치, 경로별 월 이동 예산과 행군 중 명령 잠금은 넣지 않는다.

새 지도에는 거점 간 연결·방향·종류를 편집하되 연결 미리보기는 지도 확인에만 쓴다. 실제 게임 입력은 기존 명령의 비용·행동 횟수·실행 시점을 유지한다. 군량은 기존 main의 월간 정산·전투 소비와 맞추고 휴대 군량·3개월 적재·출정 보급망은 추가하지 않는다.

## 6. 휘하는 관계·권한·병력을 구분해 이식한다

직속 상관은 하나이고 자기 자신·하위 장수를 상관으로 삼을 수 없다. 관계는 중첩을 허용하되 같은 월드와 국가 안에서 검증한다. 출사 후 기존 하위 관계를 군주 직속으로 평탄화하지 않는다. 직속 휘하의 코스트만 소유 장수의 명망에 계산하고 조상에게 중복 청구하지 않는다.

새 장수의 명망 수용량은 v1 기준 30을 첫 제안으로 둔다. 인물 코스트는 `max(1, ceil((통솔+무력+지력+정치+매력)/50))`다. 정치·매력을 현재 3능력치에서 추정하거나 0으로 채우지 않는다. 역사 인물은 출처가 확인된 다섯 값과 대응표가 있어야 이 규칙에 들어간다. 부곡은 이 인물 코스트에 중복 산입하지 않고 병력·자원·지휘 한도를 쓴다. 옛 가신 5명·부곡 2개 상한을 새 명망 규칙에 무조건 겹쳐 적용하지 않는다.

사람 장수는 자기 예약과 개인 휘하를 직접 조작한다. 상관은 발령을 제안하고 수락·거절을 받으며 다른 사람의 예약을 덮지 못한다. NPC 부장은 소유자의 배치·방침을 따르도록 연결하고 독립 NPC AI가 같은 병력에 다시 명령하지 못하게 한다. 본인 지휘와 부장 지휘 모두 배치·소유권·현재 위치를 검증한다.

국가가 멸망해도 개인 휘하·병력·자원을 즉시 지우지 않는다. 군주 직책과 국가 권한은 소멸시키고 개인 관계는 무소속 상태로 보존한다. 사망·해제·탈퇴·재출사 때 군단·지휘관 참조를 같은 사건에서 정리한다. 새 국가 거병·독립 시의 사람 장수 동반은 개별 동의가 필요하며 은퇴·봉신·황실 체계 전체를 이번 작업에 같이 넣지 않는다.

## 7. 전투·재생·API와 기존 작업의 충돌

전투 계산은 현 main의 `simulateBattle`을 먼저 사용한다. 새 군단은 정한 순서의 부곡을 계산기 입력에 투영하고 피해를 원래 부곡에 돌려 쓰며 총병력을 복제해 적용하지 않는다. 조우 → 전투 → 패배·철수 또는 도착 → 도시·관문 점령을 분리한다. 도시를 모두 차지해야 통일이고 관문·항구·전장을 도시 분모에 넣지 않는다.

새 규칙은 origin 3·archive 3의 기능 등록과 생성 자료를 확장해 `campaign-v1`에 고정한다. 기존 origin 1과 기능 없는 월드의 해시·바이트는 유지한다. 기존 `personnel`과 `ext`의 충돌 선언을 지우기만 하지 않는다. 호환 가능한 순수 함수는 함께 쓰고 새 위치·부곡을 읽는 인사·명령 어댑터와 기능 조합 시험을 먼저 만든다. 지원하지 않는 조합은 생성 때 거부한다.

새 상태는 typed `CampaignState`로 만들고 clone·load·persist·snapshot·resourceHash·초기 해시·최종 해시·export·readArchive·replay 모두에 연결한다. 현재 비어 있는 `extSlices`에 임의 JSON을 넣는 것으로 끝내지 않는다. 위치·휘하·부곡·기존 군량 중 하나를 바꾸면 검증 해시도 달라져야 한다. 수치 합산은 안전 정수 범위를 검사하며 Kotlin Long의 넘침을 JavaScript 부동소수점 반올림으로 숨기지 않는다.

API 행위자는 계속 서버 세션에서 정한다. 제안 이름은 `campaign.map`, `retinue.list`, `retinue.offer`, `retinue.respond`, `unit.form`, `deployment.issue`다. 정확한 tRPC 이름과 입력은 해당 상세 계획에서 AppRouter로 확정한다. 사전 검사와 엔진 실행 검사를 같은 순수 규칙으로 묶고 idempotencyKey·revision·월드 격리·제재·외부 사용자 소유권을 대조한다. 정적 지형이 공개여도 적의 휘하·현재 군단까지 공개하지 않는다.

기존 명령은 기존 이동 방식을 유지한다. 새 거점·휘하·부곡의 소유권·대상·위치 검사를 필요한 명령에만 연결한다. 현재 명령 대응표의 미완료를 이 계획으로 완료 처리하지 않는다.

T4-76~80의 게시·판 관리·검증 결과 구조와 캔버스 조작은 재사용한다. v2 지도에 지형이 그려졌다는 이유로 게임 연동이 끝났다고 세지 않는다. T4-77은 자원 판 기반 몫을 살리고 새 판 생성·재생 경로가 연결되기 전에 기존 자원 삭제를 앞당기지 않는다. T4-82~84의 che 바탕 그림은 새 배경의 선행으로 강제하지 않고 새 지도 역할에 맞춰 계획을 고친다. T4-35·36·56의 연감은 도시 소유권에 더해 관문·군단의 필요한 기록만 확장한다.

첫 시연은 합성 최소 월드에서 경계와 장애를 빨리 검증한다. 최종 AC-INT-12는 합성 월드만으로 통과시키지 않고 선택한 전체 지도·정식 시나리오·실제 서버와 DB를 사용한다. 미완료 메일·관리자·보안·공개 리허설 AC는 별도 관문으로 남는다. 통합 시연 통과를 공개 오픈 완료로 부르지 않는다.

## 9. 저장소와 월드 전환

개발 저장소는 현 공개 저장소 하나로 통일한다. v1은 고정 SHA의 비공개 원본과 회귀 사례 출처로 보관하고 필요한 코드·시험·허용된 자료만 출처 고지와 함께 기능별 PR로 옮긴다. 두 저장소의 전체 이력이나 비공개 문서·이미지를 통째로 공개 main에 합치지 않는다. 서비스 실행에 v1 clone·서브모듈·Gradle이 필요하지 않아야 한다.

첫 통합 월드는 새 지도 키와 시나리오 키로 생성한다. 현 계정·세션과 기존 월드·재생은 보존하고 새 기수 참가를 받는다. v1 운영 DB나 현재 진행 월드를 새 지도로 강제 변환하는 작업은 포함하지 않는다. 변환이 필요해지면 별도 ID 대응·예턴·군단·계정 중복 처리 AC를 만든다.

T4-77 자원 초기화와 새 migration은 빈 DB·기존 DB 양쪽에서 시험한다. 게시한 판은 수정하지 않고 고친 지도는 새 판으로 만든다. 공개 배포 직전 백업→다른 DB로 복원→정확한 서버 이미지 재시작→기수 상태·경로·해시 비교를 수행한다. 새 판을 끄는 rollback은 새 입력 접수를 멈추고 호환 이미지로 복구하는 것이며 기존 migration을 거꾸로 덮지 않는다.

## 10. 끝났다는 증거

실행 증거는 정확한 SHA의 `pnpm check`, `pnpm test:int`, `pnpm e2e`, 권한 대조와 고정 시드 재생 결과다. 명령 이름은 현 루트 package.json을 사용하고 새 검사 CLI가 필요하면 INT-01·해당 작업에서 스크립트와 문서를 같이 만든다. 처리량 기준은 먼저 같은 PC·동일 시드·장수 수·월드 수로 기준을 재고 채택한다. 출처 없는 밀리초·FPS를 이미 달성한 수치처럼 적지 않는다.

필수 반례는 양평 도시/양평관 혼동, 다른 판의 경로, 바다를 육로로 통과, 막힌 관문의 우회 추정, 중복 서약·부곡 배치, 같은 월의 중복 정산, NPC와 소유자 명령의 중복, 리스 상실 뒤 쓰기, 저장 실패 뒤 부분 상태, 소유권 없는 API, 재생에서 휘하·군량 누락이다.

새 지도는 같은 입력과 도구 버전에서 같은 그래프·판 해시를 만들어야 한다. 원본 첨부 이미지나 와룡전 파일을 빼도 지도·게임 실행이 가능해야 한다. 문구와 화면은 글쓰기 규칙을 따르고 주요 거점·실패 이유·군량 부족을 작은 화면에서도 읽을 수 있어야 한다.
