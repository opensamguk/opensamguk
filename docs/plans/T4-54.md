### 목표

AC-P2-15 (나)의 경기 몫. 토너먼트 경기 한 판의 승자를 내는 순수 함수가 있다. 종목, 두 참가자의 능력치, 시드 RNG를 받아 승자와 합마다의 기력·피해를 낸다. 같은 입력과 같은 시드면 결과가 같다. 100합 안에 한쪽 기력이 0 이하가 되지 않으면 남은 기력으로 승자를 정하므로 무승부로 끝나지 않는다.

## 3. 계약

### 3.1 타입과 함수

```ts
// packages/rules/src/tournament/match.ts
import type { Rng } from '@opensamguk/shared';

export const TOURNAMENT_EVENTS = ['total', 'leadership', 'strength', 'intel'] as const;
export type TournamentEvent = (typeof TOURNAMENT_EVENTS)[number];
export const TOURNAMENT_MAX_PHASES = 100;

export interface TournamentFighter {
  participantId: number; // createBracket의 참가자 ID
  leadership: number; // 0~100 정수
  strength: number;
  intel: number;
  // 원작 level 칸은 없다. 사용자 결정으로 모든 참가자 등급 0이다(2.1)
}

export interface TournamentExchange {
  phase: number; // 1부터
  homeEnergy: number; // 이 합 뒤 남은 기력. 음수 가능
  awayEnergy: number;
  homeDamage: number; // 이 합에 홈이 받은 피해
  awayDamage: number;
  homeFury: boolean; // 홈의 분노의 일격
  awayFury: boolean;
}

export interface TournamentMatchResult {
  winnerId: number;
  loserId: number;
  decidedBy: 'knockout' | 'double-knockout' | 'phase-limit';
  initialEnergy: { home: number; away: number };
  exchanges: readonly TournamentExchange[];
}

export function resolveTournamentMatch(
  input: { event: TournamentEvent; home: TournamentFighter; away: TournamentFighter },
  rng: Rng,
): TournamentMatchResult;
```

| `decidedBy`         | 뜻                                                                                | 합 기록                                             |
| ------------------- | --------------------------------------------------------------------------------- | --------------------------------------------------- |
| `'knockout'`        | 한쪽 기력만 0 이하가 됐다. 다른 쪽이 이긴다                                       | 1~100개. 마지막 합에서 패자 기력 ≤ 0, 승자 기력 > 0 |
| `'double-knockout'` | 같은 합에 두 기력이 모두 0 이하가 됐다. 더 큰 쪽, 같으면 원정이 이긴다            | 1~100개. 마지막 합에서 두 기력 ≤ 0                  |
| `'phase-limit'`     | 100합이 끝나도 두 기력이 모두 0보다 크다. 남은 기력이 큰 쪽, 같으면 원정이 이긴다 | 정확히 100개. 마지막 합에서 두 기력 > 0             |

- 결과의 `winnerId`는 늘 `home.participantId`나 `away.participantId` 둘 중 하나다. 무승부가 없고 유효한 입력에서 예외를 던지지 않는다. 그래서 T4-31 마감 월간 정산이 경기 때문에 롤백되지 않는다.
- 입력 객체에 정의되지 않은 칸(예: `level`)이 있으면 무시하지 않고 3.2의 예외로 막는다. 등급 값을 넘기는 호출자 실수를 숨기지 않기 위해서다.
- 홈·원정은 원작의 공격·수비 자리와 같다. 대진의 `home`이 원작 `attacker`, `away`가 `defender`다.

### 3.3 처리 순서

원작 `battle.ts`의 순서를 그대로 옮긴다. 기호는 홈 능력치 `hs`, 원정 능력치 `as`, 홈이 받은 피해 `toH`, 원정이 받은 피해 `toA`, `R`은 `Math.round`다. RNG 호출 `int(a, b)`는 양끝 포함이다.

1. `hs`·`as`를 종목으로 고른다. 종합은 `(통솔 + 무력 + 지력) × 7 / 15`이고 정수로 자르지 않는다.
2. 시작 기력은 `R(hs × 10)`, `R(as × 10)`이다. 원작 식에서 등급 비율이 1인 경우다(2.1).
3. 합 `phase = 1..100`마다 아래를 이 순서로 한다. 괄호 안이 RNG 호출이다.
   1. `toH = R(as × (int(0, 21) + 90) / 130)`, 이어서 `toA = R(hs × (int(0, 21) + 90) / 130)`.
   2. `hs ≥ int(0, 100)`이면 `toA += R(hs × (int(0, 41) + 10) / 130)`. 조건이 거짓이면 두 번째 호출은 하지 않는다.
   3. `as ≥ int(0, 100)`이면 `toH += R(as × (int(0, 41) + 10) / 130)`.
   4. 홈 분노: `시작 홈 기력 / 5 > 지금 홈 기력`이고 `toH > toA`일 때만 `hs ≥ int(0, 300)`을 본다. 참이면 원정 피해 배수 `R((int(0, 301) + 200) / 100)`, `homeFury = true`. 앞 두 조건이 거짓이면 RNG를 부르지 않는다.
   5. 원정 분노: 같은 규칙을 반대로. 원정 분노는 4에서 바뀌기 전의 `toH`·`toA`로 판단한다.
   6. `toH = R(toH × 홈 배수)`, `toA = R(toA × 원정 배수)`. 배수 기본값은 1.
   7. 첫 합이면 `hs × 0.9 > as`일 때만 `hs ≥ int(0, 400)`을 보고 참이면 `toA += R(hs × (int(0, 31) + 70) / 100)`. 이어서 원정도 같은 규칙. 둘째 합부터는 `homeFury`가 아닐 때만 `hs ≥ int(0, 1000)`을 보고 참이면 `toA += R(hs × (int(0, 31) + 20) / 100)`. 이어서 원정도 같은 규칙.
   8. 기력에서 피해를 빼고 합 기록 하나를 더한다.
   9. 두 기력이 모두 0 이하면 더 큰 쪽이 이기고 같으면 원정이 이긴다(`double-knockout`). 원작 `battleType` 1의 규칙이다. 한쪽만 0 이하면 다른 쪽이 이긴다(`knockout`). 끝났으면 멈춘다.
4. 합은 최대 100개다. 100합째의 9단계가 끝나도 두 기력이 모두 0보다 크면 더 진행하지 않고 판정한다. 남은 기력이 큰 쪽이 이기고 같으면 원정이 이긴다(`phase-limit`). 이 판정은 RNG를 부르지 않고 합 기록을 더하지 않는다. 예외를 던지지 않는다.

1차 원고의 20합 보장 주장은 철회한다. 종합 종목에서 능력치 합이 1이면 종목 능력치가 7/15이고 모든 피해가 0으로 반올림되어 100합이 지나도 기력이 그대로다(3.7 X4, G-03 P1). 등급 상한 논증(G-03 P2)은 등급 칸을 없애 해당하지 않는다. 계약은 100합 상한과 위의 정의된 판정뿐이다.

### 3.4 RNG 계약

- RNG는 `rng.int`만 부르고 `next`·`pick`은 부르지 않는다. 호출 순서와 인자는 3.3이 정한 것뿐이며 조건이 거짓이면 그 뒤 호출을 건너뛴다. 원작과 같은 단락 평가다.
- 3.3의 4 판정은 RNG를 부르지 않는다. 그래서 `phase-limit` 경기의 RNG 소비는 원작이 무승부로 끝낸 경기와 같다.
- 실패 입력에서는 RNG를 부르지 않는다.
- RNG 스트림을 새로 만들지 않는다. 경기마다 다른 스트림을 쓰는 것은 호출자 몫이다(T4-31 3.5).
