## 2. 수치 분류 (명세 C10)

| 수치 | 원작 값 | 처리 |
| ---- | ------- | ---- |
| 종합 종목 능력치 | (통솔 + 무력 + 지력) × 7/15 | 원작 그대로. 우리 능력치도 0~100 세 종류라 단위가 같다 |
| 단일 종목 능력치 | 해당 능력치 | 원작 그대로 |
| 시작 기력 | round(능력치 × 등급 비율 × 10) | 식은 원작 그대로. 등급 비율의 입력은 U54-2 |
| 등급 비율 | 높은 쪽 1 + log10(1 + 차) / 10, 낮은 쪽 1 − log10(1 + 차) / 10 | 원작은 두 참가자 모두에 홈 기준 비율 하나를 곱한다(T54-Q2) |
| 기본 피해 | round(상대 능력치 × (0~21 + 90) / 130) | 원작 그대로 |
| 추가 피해 | 능력치 ≥ 0~100이면 round(능력치 × (0~41 + 10) / 130) | 원작 그대로 |
| 분노의 일격 | 시작 기력 / 5 > 지금 기력, 받은 피해가 더 크고 능력치 ≥ 0~300이면 상대에게 주는 피해 × round((0~301 + 200) / 100) | 원작 그대로 |
| 첫 합 선제 | 능력치 × 0.9 > 상대 능력치이고 능력치 ≥ 0~400이면 round(능력치 × (0~31 + 70) / 100) | 원작 그대로 |
| 이후 합 일격 | 이번 합에 분노의 일격이 없고 능력치 ≥ 0~1000이면 round(능력치 × (0~31 + 20) / 100) | 원작 그대로 |

## 3. 계약

### 3.1 타입과 함수

```ts
// packages/rules/src/tournament/match.ts
import type { Rng } from '@opensamguk/shared';

export const TOURNAMENT_EVENTS = ['total', 'leadership', 'strength', 'intel'] as const;
export type TournamentEvent = (typeof TOURNAMENT_EVENTS)[number];
export const TOURNAMENT_MAX_PHASES = 100;

export interface TournamentFighter {
  participantId: number; // createBracket의 참가자 ID
  leadership: number; // 0~100 정수
  strength: number;
  intel: number;
  level: number; // 0 이상 정수. 무엇에서 오는지는 호출자(T4-31)가 정한다(U54-2)
}

export interface TournamentExchange {
  phase: number; // 1부터
  homeEnergy: number; // 이 합 뒤 남은 기력. 음수 가능
  awayEnergy: number;
  homeDamage: number; // 이 합에 홈이 받은 피해
  awayDamage: number;
  homeFury: boolean; // 홈의 분노의 일격
  awayFury: boolean;
}

export interface TournamentMatchResult {
  winnerId: number;
  loserId: number;
  decidedBy: 'knockout' | 'double-knockout';
  initialEnergy: { home: number; away: number };
  exchanges: readonly TournamentExchange[];
}

export function resolveTournamentMatch(
  input: { event: TournamentEvent; home: TournamentFighter; away: TournamentFighter },
  rng: Rng,
): TournamentMatchResult;
```

- 결과의 `winnerId`는 늘 `home.participantId`나 `away.participantId` 둘 중 하나다. 무승부가 없다.
- 홈·원정은 원작의 공격·수비 자리와 같다. 대진의 `home`이 원작 `attacker`, `away`가 `defender`다.

### 3.2 입력 검사

아래는 모두 `Error` 예외이고 RNG를 한 번도 부르지 않는다. 호출자가 먼저 걸러야 할 프로그램 오류라 게임 `Failure`로 바꾸지 않는다.

| 순서 | 검사 |
| ---- | ---- |
| 1 | `event`가 `TOURNAMENT_EVENTS` 안에 있다 |
| 2 | 두 참가자의 `participantId`가 1 이상 2147483647 이하 안전 정수이고 서로 다르다 |
| 3 | 세 능력치가 0 이상 100 이하 안전 정수다 |
| 4 | `level`이 0 이상 안전 정수다. 상한은 U54-2 답에서 정한다. 그 전에는 1000 이하로 둔다 |

### 3.3 처리 순서

원작 `battle.ts`의 순서를 그대로 옮긴다. 기호는 홈 능력치 `hs`, 원정 능력치 `as`, 홈이 받은 피해 `toH`, 원정이 받은 피해 `toA`, `R`은 `Math.round`다. RNG 호출 `int(a, b)`는 양끝 포함이다.

1. `hs`·`as`를 종목으로 고른다. 종합은 `(통솔 + 무력 + 지력) × 7 / 15`이고 정수로 자르지 않는다.
2. `ratio = level 비율(home.level, away.level)`. 시작 기력은 `R(hs × ratio × 10)`, `R(as × ratio × 10)`이다(T54-Q2).
3. 합 `phase = 1..100`마다 아래를 이 순서로 한다. 괄호 안이 RNG 호출이다.
   1. `toH = R(as × (int(0, 21) + 90) / 130)`, 이어서 `toA = R(hs × (int(0, 21) + 90) / 130)`.
   2. `hs ≥ int(0, 100)`이면 `toA += R(hs × (int(0, 41) + 10) / 130)`. 조건이 거짓이면 두 번째 호출은 하지 않는다.
   3. `as ≥ int(0, 100)`이면 `toH += R(as × (int(0, 41) + 10) / 130)`.
   4. 홈 분노: `시작 홈 기력 / 5 > 지금 홈 기력`이고 `toH > toA`일 때만 `hs ≥ int(0, 300)`을 본다. 참이면 원정 피해 배수 `R((int(0, 301) + 200) / 100)`, `homeFury = true`. 앞 두 조건이 거짓이면 RNG를 부르지 않는다.
   5. 원정 분노: 같은 규칙을 반대로. 원정 분노는 4에서 바뀌기 전의 `toH`·`toA`로 판단한다.
   6. `toH = R(toH × 홈 배수)`, `toA = R(toA × 원정 배수)`. 배수 기본값은 1.
   7. 첫 합이면 `hs × 0.9 > as`일 때만 `hs ≥ int(0, 400)`을 보고 참이면 `toA += R(hs × (int(0, 31) + 70) / 100)`. 이어서 원정도 같은 규칙. 둘째 합부터는 `homeFury`가 아닐 때만 `hs ≥ int(0, 1000)`을 보고 참이면 `toA += R(hs × (int(0, 31) + 20) / 100)`. 이어서 원정도 같은 규칙.
   8. 기력에서 피해를 빼고 합 기록 하나를 더한다.
   9. 두 기력이 모두 0 이하면 더 큰 쪽이 이기고 같으면 원정이 이긴다(`double-knockout`). 원작 `battleType` 1의 규칙이다. 한쪽만 0 이하면 다른 쪽이 이긴다(`knockout`). 끝났으면 멈춘다.
4. 100합 안에 반드시 끝난다. 능력치가 1 이상이면 매 합 기본 피해가 `R(능력치 × 90 / 130) ≥ 1`이고 시작 기력은 `R(능력치 × 10 × 비율)`이라 비율이 1.31을 넘지 않는 한(3.2 등급 상한 1000에서 약 1.30) 20합 안에 끝난다. 한쪽 능력치가 0이면 그쪽 시작 기력이 0이라 첫 합에 끝난다. 그래도 100합을 넘기면 계약 위반이므로 `Error`를 던진다(T54-Q1).

### 3.4 RNG 계약

- RNG는 `rng.int`만 부르고 `next`·`pick`은 부르지 않는다. 호출 순서와 인자는 3.3이 정한 것뿐이며 조건이 거짓이면 그 뒤 호출을 건너뛴다. 원작과 같은 단락 평가다.
- 실패 입력에서는 RNG를 부르지 않는다.
- RNG 스트림을 새로 만들지 않는다. 경기마다 다른 스트림을 쓰는 것은 호출자 몫이다(T4-31 3.5).

## 4. 쟁점 (부모·Codex가 정할 기술 문제)

| ID | 쟁점 | 이 문서의 처리 |
| -- | ---- | -------------- |
| T54-Q1 | 원작 승패 경기는 100합 뒤 무승부가 될 수 있다. 우리 대진은 승자가 있어야 다음 라운드 `winnerOf`가 풀린다 | 유효한 입력에서는 100합에 닿지 않음을 3.3의 4에 적었다. 닿으면 예외로 막고 무승부 규칙을 새로 만들지 않는다. 등급 상한(U54-2)을 1000보다 크게 정하면 이 상한을 다시 계산한다 |
| T54-Q2 | 원작 시작 기력은 홈과 원정 모두에 홈 기준 비율 `getLogRatio(attacker.level, defender.level)` 하나를 곱한다. 원정 쪽 비율을 뒤집지 않아 등급 차가 두 기력을 같이 늘리거나 줄인다 | 원작 그대로 옮긴다. 등급이 둘 다 0이면 비율이 1이라 영향이 없다. 뒤집을지는 U54-2와 함께 묻는다 |
| T54-Q3 | 종합 능력치 × 7/15와 `Math.log10`은 부동소수다 | 결과를 `R`로 정수화하는 원작 위치를 그대로 지킨다. 등급이 0이면 `log10(1) = 0`이라 플랫폼 차이가 없다. 등급을 쓰기로 하면 `log10` 대신 고정 표를 쓸지 Codex가 정한다 |
| T54-Q4 | 경기 기록을 얼마나 남길지 | 합마다 여섯 값만 낸다. 저장할지, 화면에 몇 합을 보일지는 T4-31·T4-32가 정한다 |

## 7. 상대 영역에 필요한 것

- T4-31(Codex): 경기마다 `rngFor`로 따로 만든 `Rng`를 넘긴다. 참가자의 능력치는 대회를 닫는 순간의 값으로 고정해 넘긴다. `level` 값의 출처를 정한다(U54-2 전에는 0). 부전승 경기는 부르지 않는다.
- T4-32(Claude): 합 기록 여섯 값과 `decidedBy`로 경기 내용을 그린다. 문구(분노의 일격 등)는 화면이 만든다. 색만으로 승패를 나타내지 않는다.
