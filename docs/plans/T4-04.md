## 0. 이 문서의 위치

확장 명령의 서버 연결은 T4-03이 한다. T4-03이 끝나면 `commands.list`가 켠 월드의 확장 일반 명령을 `argsSchema`와 함께 내고 꺼진 명령의 저장과 사전 검사가 정해진 문구로 거부된다. 이 계획은 그 응답을 30칸 편집기에서 쓰는 화면 몫이다. 화면은 `AppRouter` 타입만 import하고 서버 계약을 바꾸지 않는다(C7).

지금 편집기는 이미 `argsSchema`(JSON Schema)에서 인자 칸을 만든다. 그래서 이 작업의 큰 몫은 새 위젯이 아니다. 확장 명령의 인자 key와 이름표를 한 표에 모으는 일, 대상 장수를 이름으로 고르게 하는 일, 켬·끔 월드의 Chromium 증거를 만드는 일이다.

### 화면 계약

#### F1 확장 인자 표

```ts
// apps/web/src/turns/extArgs.ts
export const EXT_ARG_LABELS: Readonly<Record<string, string>> = {}; // 인자 key → 이름표
export const EXT_ENUM_LABELS: Readonly<Record<string, string>> = {}; // 열거 값 → 이름
export const EXT_GENERAL_SCOPE: Readonly<Record<string, 'nation' | 'any'>> = {}; // 명령 key → 대상 장수 후보 범위
```

- `args.ts`의 이름표 조회가 기본 표 다음에 이 표를 본다. 기본 표에 있는 key(`cityKey`, `nationId`, `generalId`, `amount`, `crewType`, `buy`, `resource`, `name`, `color`)는 확장 표에 다시 적지 않는다. 같은 key가 두 표에 있으면 단위 시험이 실패한다.
- 규칙 작업에 주는 요청: 뜻이 같은 인자는 기본 key를 그대로 쓴다. 대상 도시는 `cityKey`, 대상 국가는 `nationId`, 대상 장수는 `generalId`, 금·쌀 고르기는 `resource`(`gold`·`rice`), 수량은 `amount`다. 그러면 화면 표에 행을 더하지 않아도 된다. 원작 이름(`destCityId`, `destGeneralID`, `isGold`)을 그대로 옮기지 않는다.
- 새 key가 생기면 그 명령의 화면 증거를 받는 PR이 이 표에 한 행을 더한다. 이름표는 [글쓰기 규칙](../writing-style.md)을 따른다.
- 표가 빈 배열에서 시작하는 것은 T4-02의 운영 목록과 같다. 지금 알려진 확장 일반 명령의 인자는 T4-05 계략 4종의 `cityKey` 하나이고 기본 표로 그려진다.

| 작업 | 명령 | 원작 인자 | 화면 처리 |
| ---- | ---- | --------- | --------- |
| T4-05 | 계략 4종 | 대상 도시 | 기본 `cityKey` 칸 |
| T4-11 | 첩보 | 대상 도시 | 기본 `cityKey` 칸 |
| T4-14 | 강행 | 대상 도시 | 기본 `cityKey` 칸. 거리 3 안 도시만 후보로 줄일지는 T4-14 계약 뒤 `cityChoicesFor`로 |
| T4-48 | 방랑 국가 정착 | 이름·색 | 기본 `name`·`color` 칸 |
| T4-59 | 증여 | 금·쌀, 수량, 대상 장수(같은 국가) | 기본 `resource`·`amount`·`generalId`, 범위 `nation` |

#### F2 꺼진 명령과 오류

- 끈 월드의 `commands.list`에는 확장 명령이 없으므로 목록에 나오지 않는다. 화면이 따로 거르지 않는다.
- 꺼진 key가 저장된 초안(예: 다른 탭에서 만든 sessionStorage 초안)을 저장하면 서버의 `BAD_REQUEST` `이 월드에서 꺼진 명령입니다.`가 저장 오류 안내로 보인다(`useTurnDraft.ts:221-225`). 초안은 지우지 않는다. 사용자가 그 칸을 바꾸거나 비운 뒤 다시 저장한다.
- 같은 칸의 사전 검사는 T4-03의 `{ ok: false, code: 'COMMAND_DISABLED', message }`라서 칸 옆에 그 문구가 보인다(`TurnEditor.tsx:193`). 화면은 코드 값으로 갈라 읽지 않는다.
- 목록에 없는 key의 칸 이름은 서버가 준 `name`(T4-03 `displaySlots`, 없으면 key)을 그대로 쓴다.

#### F3 대상 장수 고르기 (개인 칸)

- `personalSource`가 `generals`를 넘긴다. 후보는 세션 장수가 속한 국가의 장수 목록이며 `nation.get`(`apps/server/src/routers/nation.ts:7-21`)의 `generals`에서 id와 이름만 쓴다. 재야면 후보가 없다.
- `EXT_GENERAL_SCOPE`가 `any`인 명령은 후보 고르기 대신 지금처럼 번호 칸이다. 다른 국가 장수 목록을 주는 조회가 생기면 바꾼다(상대 영역 F4).
- 후보는 표시를 돕는 값이다. 대상이 맞는지는 서버의 저장·사전 검사가 다시 본다(`args.ts:1-2`의 원칙).
- `TurnSource.generals`는 지금 정적 배열이고(`source.ts:51-52`) 메인(`apps/web/src/pages/MainPage.tsx:108`)과 단독 편집기(`TurnsPage.tsx:20`)는 기본값 `personalSource`로 편집기를 만든다(`TurnEditor.tsx:54-58`). 조회 결과를 넘기려면 `TurnSource`에 선택 칸 `generalsQuery?: SourceQuery<Array<{ id: number; name: string }>>` 하나를 더하고 편집기가 `generals`가 없을 때만 그 조회를 쓴다. `generals` 칸과 국가 칸(T2-06)의 동작은 그대로다.

#### F4 접근성과 문구

- 새 이름표는 기존 칸과 같은 `<label>` 구조를 쓴다(`CommandPicker.tsx:337`). 키보드 흐름(검색 Enter → 첫 인자 칸)은 바꾸지 않는다.
- 확장 명령의 이름·분류는 서버가 준 값이다. 화면에서 확장 여부를 따로 표시하지 않는다. 원작 이름을 화면 장식으로 덧붙이지 않는다(C12).

#### F5 Chromium 증거

`e2e/extCommands.spec.ts`가 실제 서버·PostgreSQL·엔진(`pnpm dev`)으로 돈다.

- 켠 월드: T4-03 2단계와 같은 시험 전용 프리셋으로 만든 월드에서 장수를 만든다. 확장 일반 명령 하나(첫 운영 등록인 T4-05 계략의 한 명령)를 고르고 대상 도시를 넣어 2번 칸에 저장한다. 새로 고친 뒤 30칸에 명령 이름과 도시 이름이 그대로 보인다. 사전 검사 문구가 칸 옆에 보인다.
- 끈 월드: 같은 key가 목록과 검색 결과에 없다. 켠 월드에서 만든 그 key의 초안을 끈 월드의 sessionStorage 키에 직접 넣고 저장하면 `이 월드에서 꺼진 명령입니다.`가 보이고 30칸은 저장 전 그대로다.
- 대상 장수: `generalId` 인자를 받는 확장 명령이 운영에 등록되면 같은 국가 장수 이름이 후보에 보이고 고른 이름이 30칸 요약에 보인다. 등록 전에는 이 사례를 넣지 않는다. 운영에 없는 명령으로 통과시키지 않는다.
- 엔진이 칸을 실행한 뒤 최근 실행 결과에 그 명령의 성공 또는 대표 실패 기록이 보인다. 실행 증거 자체는 T4-03·T4-17이 받고 이 시험은 화면에 보이는지만 본다.
- 명령마다의 ui 단계 증거는 그 명령이 이 spec에 사례 한 줄을 더해 받는다. 공통 사례가 있다고 다른 명령의 단계를 채우지 않는다([누락 명령 문서](./mvp-command-gaps.md) 3.3).

### 접근

1. `extArgs.ts`와 `args.ts` 연결, 단위 시험(지금 할 수 있다).
2. 개인 칸 대상 장수 후보 연결(F3)과 단위 시험. 끈 월드에서 화면이 바뀌지 않는지 기존 시험으로 확인한다.
3. T4-03 1단계 병합 뒤 끈 월드 E2E(목록 보존, 확장처럼 보이는 key의 서버 문구).
4. F2 수용 뒤 `e2e/extWorld.ts` 켠 월드 도우미.
5. 첫 운영 등록(T4-17) 뒤 켠 월드 E2E와 증거 기록. 리뷰.

| W6 | 전체 | `pnpm lint:text --strict`, 프리티어(`--end-of-line auto`) | 명령 그대로 |

- skip된 E2E와 시험 전용 화면 분기는 증거가 아니다. 켠 월드 E2E는 운영 등록된 확장 명령으로만 한다.

### 상대 영역에 필요한 것

- F1(Codex, 규칙 작업 전부): 뜻이 같은 인자는 기본 key(`cityKey`, `nationId`, `generalId`, `resource`, `amount`, `name`, `color`)를 쓴다. 인자 zod 스키마가 `z.toJSONSchema(def.args, { io: 'input' })`(`routers/commands.ts:11`)로 범위(`minimum`·`maximum`·`exclusiveMinimum`)와 열거(`enum`)를 내도록 만든다.
- F2(Codex, T4-03): E2E가 켠 월드를 만들 방법. 후보는 둘이다. (가) `pnpm world:create`에 시험 전용 프리셋 파일 경로 인자를 더한다. (나) T4-03 E3이 고정하는 `saveInitialWorld` 호출 목록에 `e2e/extWorld.ts`를 더한다. 이 계획은 (가)를 권한다. 제품 프리셋 파일(`resources/preset/*.json`)은 고치지 않는다.
- F3(Codex, T4-03): 꺼진 명령 문구 `이 월드에서 꺼진 명령입니다.`와 사전 검사 모양 `{ ok: false, code: 'COMMAND_DISABLED', message }`는 T4-03 원고 그대로다. 바뀌면 이 계획의 F2와 W5를 함께 고친다.
- F4(Codex, 미정): 범위 `any` 명령(장수대상임관)을 이름으로 고르려면 다른 국가 장수의 공개 이름 목록 조회가 필요하다. 지금 이 작업은 번호 칸으로 두고 필요해지면 대기열에 Codex 작업 한 줄을 올린다.
