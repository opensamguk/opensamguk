## 2. 계약

### 2.1 절차

```ts
// apps/server/src/routers/timelapse.ts
timelapse.publicFrames: publicProcedure.input(recordsInput).query(...)
// 입력: { worldId: string (uuid); cursor?: string } strict. 모르는 칸은 BAD_REQUEST
// 출력:
type PublicFrames = {
  world: { name: string; endedYear: number; endedMonth: number };
  map: { cities: Array<{ cityKey: number; name: string; x: number; y: number; connections: number[] }> } | null;
  items: Array<{
    tick: number;
    year: number;
    month: number;
    cities: Array<{ cityKey: number; nationId: number | null }>;
    nations: Array<{ id: number; name: string; color: string }>;
  }>;
  nextCursor: string | null;
};
```

- 이름·모양은 T4-37 3.3 요청서 그대로다. `currentNations` 칸은 없다.
- `map`은 `cursor`가 없는 첫 페이지에만 싣고 다음 페이지는 `null`이다. 도시는 `cityKey` 오름차순이다.
- `items`는 `timelapse.frames`와 같은 줄이다. `tick` 오름차순 30개, 31번째 행이 있으면 `nextCursor`는 30번째 행의 `tick` 글자다. 같은 `worldId`·`cursor`면 `items`와 `nextCursor`가 `timelapse.frames`의 같은 칸과 같다.
- `items[].nations`는 그 달 `YearbookNation`에 저장된 ID·이름·색만이다. 그 달 도시를 가진 국가만 남기고 ID 오름차순이다. 저장 행이 없는 국가는 생략하며 지금 `Nation` 행이나 회색으로 채우지 않는다(T4-56 (가), H16과 같다). 그런 달을 그리지 않는 것은 화면 몫이다(T4-36 패널의 국가 기록 누락 처리, T4-37 3.2).
- `RemovedNation`은 읽지 않는다. 멸망한 국가는 그 달 저장 이름·색으로만 나온다.

### 2.2 상태 검사와 트랜잭션

`readWorld(ctx.db, input.worldId, async (tx, world) => …)` 하나 안에서 아래 순서로 한다. 월드 상태, 종료 결과, 지도, 프레임, 저장 국가를 한 RepeatableRead 스냅숏에서 읽는다. 그래서 상태 검사와 프레임 읽기 사이에 다른 트랜잭션이 월드를 바꿔도 응답은 한 시점의 값이다.

1. 월드가 없으면 `readWorld`가 `NOT_FOUND`(`월드를 찾을 수 없습니다.`)를 던진다.
2. `world.status !== 'ENDED'`면 `TRPCError({ code: 'FORBIDDEN', message: '종료된 월드만 로그인 없이 볼 수 있습니다.' })`. 개시 전(PREOPEN)·진행 중(RUNNING)·정지(PAUSED) 모두다. 세션이 있어도 같다. 이 검사 앞에서는 프레임·지도·국가 표를 읽지 않는다.
3. `world.status === 'ENDED'`인데 `world.result`가 `null`이면 저장 상태가 어긋난 것이다. 오류를 던져 `INTERNAL_SERVER_ERROR`(가린 문구 `요청을 처리하지 못했습니다.`)로 내고 프레임을 내지 않는다.
4. 첫 페이지면 지도를 읽는다(3.3).
5. 프레임과 저장 국가를 `frames`와 같은 단계별 함수 둘로 읽는다(3.1). 현재 `Nation`은 읽지 않는다.

로그인 사용자도 이 절차를 부를 수 있고 결과는 무인증과 같다. 세션 쿠키는 읽지 않는다. 진행 중 월드를 보려는 로그인 사용자는 지금처럼 `timelapse.frames`를 쓴다.

## 3. 접근

### 3.1 프레임 읽기 함수 꺼내기

지금 `frames`의 쿼리 순서는 `yearbookSnapshot`(`:8-16`) → 현재 `Nation`(`:30-37`) → `YearbookNation`(`:38-49`)이다. 함수 하나로 스냅숏과 저장 국가를 함께 읽어 돌려주면 `frames`가 현재 국가를 그 뒤에 읽게 되어 이 순서가 바뀐다. 그래서 읽기를 단계별 함수 둘로 나누고 `frames`가 지금 순서대로 부른다.

| 함수 (`timelapse.ts` 안)                            | 하는 일                                                                                                                               | 옮겨 오는 줄 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| `readFrameRows(tx, worldId, cursor)`                | `yearbookSnapshot` 31행 읽기, `page`, `timelapseFrameInfo`, 페이지의 소유 국가 ID 모음. `{ items, nationIds, nextCursor }`를 돌려준다 | `:8-29`      |
| `attachSavedNations(tx, worldId, items, nationIds)` | `YearbookNation` 읽기와 프레임별 소유 국가 거르기. 프레임마다 `nations`를 붙인 배열을 돌려준다                                        | `:38-59`     |

- `frames`는 `readFrameRows` → 지금 자리의 현재 `Nation` 읽기(`:30-37` 그대로) → `attachSavedNations` 순서로 부른다. 쿼리 수, 쿼리 순서, 각 쿼리의 `where`·`orderBy`·`select`, 빈 페이지에서 쿼리를 건너뛰는 조건, 31번째 행을 파싱하지 않는 성질(`:17`)이 지금과 같다. 응답 객체의 칸과 순서도 같다.
- `publicFrames`는 2.2의 상태 검사 → 첫 페이지면 지도 → `readFrameRows` → `attachSavedNations` 순서로 부른다. 현재 `Nation`은 읽지 않는다. 공개 응답에 현재 국가를 쓰지 않으므로 우회로라도 읽어 두지 않는다.
- 검증은 기존 H1~H17이 고치지 않고 통과하는 것이다. 순서 보존 자체는 리뷰가 diff에서 `frames`의 세 쿼리 순서를 확인한다.

### 3.2 절차 본문

2.2 순서대로 쓴다. 응답 객체는 2.1의 칸만 새로 만든다. 읽은 행을 펼쳐 넣지 않는다(`...row` 금지). `world`는 `{ name: world.name, endedYear: world.result.endedYear, endedMonth: world.result.endedMonth }`다.

### 3.3 공개 지도 투영

`visibility.ts`에 함수 하나를 둔다.

```ts
export const publicTimelapseCitySelect = {
  cityKey: true,
  name: true,
  x: true,
  y: true,
  connections: true,
} as const satisfies Prisma.CitySelect;
```

절차는 `tx.city.findMany({ where: { worldId }, orderBy: { cityKey: 'asc' }, select: publicTimelapseCitySelect })`로 읽고 그 다섯 칸만 새 객체로 옮긴다. 지금 소유(`nationId`), 규모(`level`), 보급(`supplied`), 인구·농업·상업·치안·수비·성벽·민심은 내지 않는다. 지금 소유가 섞이면 마지막 프레임 뒤의 상태가 새기 때문이다. `mapCity`는 고치지 않는다.

### 3.4 요청 한도

`world.publicMaps`와 같은 방식이다. `publicProcedure`를 그대로 쓰고 새 한도·IP 한도를 두지 않는다(`trpc.ts:15`). 한 요청은 한 트랜잭션에서 최대 31행 스냅숏, 그 페이지 tick의 저장 국가, 첫 페이지면 도시 행을 읽는다. `timelapse.frames`보다 쿼리가 하나 적거나 같다. 공개 조회 전반의 한도가 필요해지면 그것은 운영 정책 결정이라 이 작업이 정하지 않는다.
