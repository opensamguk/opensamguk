## 0. 이 문서의 위치

명세 C13은 일반 명령 예약을 기존 `turns` 라우터(T4-03)에, 국가 명령 예약을 T2-05의 `nationTurns` 라우터(T4-50)에 resolver로 잇는다고 나눴다. `nationTurns` 라우터 파일은 T2-05 소유이고 이 작업은 그 안의 검사 연결 한 곳만 고친다(§7). T4-03이 일반 명령에 정한 두 단계 검사(E2)를 국가 칸에도 같은 모양으로 적용하는 것이 이 계획의 대부분이다.

T4-03 원고는 엔진의 국가 명령 실행을 resolver에 잇는다고 적었다(T4-03 하지 않는 것). 이 계획은 서버 API 몫과 직책 권한 표의 확장 몫을 맡는다.

## 계획 (Claude)

### 목표

AC-P2-02 (나)의 국가 명령 몫: 확장 국가 명령은 월드 프리셋 허용 목록에 key가 있을 때만 `nationTurns` 경로로 국가 예턴에 저장되고 사전 검사를 지나 실행된다. 꺼진 월드에서는 저장·사전 검사·실행이 `COMMAND_DISABLED`로 거부되고 `nationCommands.list`에 없다. 꺼진 월드의 국가 명령 결과와 응답은 지금(T2-05 병합 시점)과 같다.

### 범위 (모두 Codex)

| 파일 | 바꾸는 것 | 소유 |
| ---- | --------- | ---- |
| T2-05의 국가 칸 해석 함수(계획상 `nationTurns.ts` 안 또는 그 도우미) | 두 단계 검사(N1) | 파일은 T2-05, 이 연결 한 곳만 T4-50 |
| T2-05의 `nationCommands.list`·`precheck` 본문 | `resolver.list('nation')`, `resolver.precheck`(N2·N3) | 같음 |
| T2-05의 `nationTurns.get` 칸 이름 | `resolver.get(key)?.name ?? key`(N4) | 같음 |
| 새 파일 `packages/rules/src/commands/ext/permissions.ts`와 시험 | 확장 국가 명령의 직책 권한 표(P1) | T4-50 |
| `packages/rules/src/personnel/permissions.ts`의 판정 함수 한 곳 | 확장 표를 함께 읽는 줄(P2) | 파일은 T2-05, 한 줄만 T4-50(쟁점 X2) |
| `apps/server/src/game/resolver.ts` | 바꾸지 않는다. T4-03이 만든 `worldResolver(world)`를 import한다 | T4-03 |

- 새 절차, migration, `router.ts`·`authz/exemptions.ts` 변경은 없다. 권한 증거는 T2-05가 등록한 절차에 확장 사례를 더한다.

### 하지 않는 것

- `nationTurns`·`nationCommands`·`personnel` 라우터의 나머지(T2-05).
- 엔진의 국가 칸 실행 연결(T4-03, 직책 칸 갈래는 쟁점 X3).
- 확장 국가 명령 자체와 그 권한 값. 명령마다 어느 직책이 실행하는지는 그 명령의 규칙 작업(T4-06, T4-08, T4-70~T4-75 등)이 P1 표에 한 행씩 적는다.
- 국가 명령 인자 화면(T4-51).
- 인사 기능이 없는 월드에서 사람이 국가 칸을 편집하는 경로. T2-05는 그런 월드의 `nationTurns.*`를 거부한다(쟁점 X1).

### 기술 계약

#### N1 칸 해석 두 단계 (`nationTurns.set`·`edit`)

T4-03 E2와 같은 순서다. 끈 월드의 오류가 T2-05 병합 시점과 바이트 단위로 같아야 한다.

1. 트랜잭션 밖: `null`은 `nation_rest`다. key가 기본 국가 명령 또는 운영 `extensionCommands`의 국가 명령에 있고 인자가 그 정의의 zod를 통과해야 한다. 확장 명령 인자는 T4-03 E7 저장 가능 검사(`assertStorableJson`)도 지난다. 실패는 T2-05 문구 `명령과 인자를 확인하세요.`다. 운영 확장 목록이 빈 동안 이 단계는 T2-05의 해석과 같다.
2. 트랜잭션 안, `requireWorld` 바로 뒤: 입력에서 온 칸(`set`의 12칸, `edit`의 `put` 값)마다 `resolver.get(key)`가 있어야 한다. 없으면 `BAD_REQUEST` `이 월드에서 꺼진 명령입니다.`이고 아무것도 쓰지 않는다. 이어 T2-05의 본 직책 확인과 직책 권한 검사가 그대로 이어진다. 확장 key의 권한은 P2로 본다.

- `edit`의 `shift`·`repeat`는 저장된 칸을 다시 검사하지 않는다(T4-03 E2와 같다). 저장된 칸에 꺼진 key가 있으면 엔진 실행이 `COMMAND_DISABLED` 실패 로그를 남긴다.
- 응답 모양(`{ ok: true, revision, slots }`, STALE)은 T2-05 그대로다.

#### N2 `nationCommands.list`

- `resolver.list('nation')`에서 세션 장수의 지금 직책이 실행할 수 있는 명령만 고른다(T2-05 기본 표 + P1). 모양은 T2-05 그대로 `{ key, name, argsSchema }`이고 `argsSchema`는 `z.toJSONSchema(def.args, { io: 'input' })`(지금 `routers/commands.ts:11`과 같은 방법)다.
- 순서는 resolver 순서(기본 국가 명령 다음 켠 확장 명령, `extensionCommands` 순서)다.
- 끈 월드의 결과는 T2-05 병합 시점의 응답과 깊은 비교로 같다.

#### N3 `nationCommands.precheck`

- N1의 1단계 뒤 트랜잭션 안에서 `resolver.precheck(view, { generalId, tick, target: 'nation', unitSet }, key, args)`를 부른다.
- 결과 모양은 T2-05의 `Allowed`다. 실패는 `{ ok: false, reason: failure.message }`이고 꺼진 key는 `{ ok: false, reason: '이 월드에서 꺼진 명령입니다.' }`다. 화면은 코드가 아니라 `reason` 문구만 본다(`apps/web/src/personnel/NationTurnsPage.tsx:73-80`).
- 직책 권한 실패는 resolver 앞에서 T2-05 문구로 낸다. 같은 칸에 권한과 꺼짐이 함께 걸리면 꺼짐을 먼저 낸다(N1 순서와 같다).

#### N4 칸 이름 표시

- `nationTurns.get`과 `set`·`edit` 응답, STALE 응답의 `name`은 `resolver.get(key)?.name ?? key`다. 일반 칸의 `displaySlots(turns, resolver)`(T4-03 E2)와 같은 규칙이다.

#### P1 확장 국가 명령의 직책 권한 표

```ts
// packages/rules/src/commands/ext/permissions.ts (순수 자료와 함수)
export interface ExtNationPermission {
  commandKey: string; // extensionCommands의 국가 명령 key
  officerLevels: readonly number[]; // 실행할 수 있는 관직. 5~12 안의 값만
}
export const extNationPermissions: readonly ExtNationPermission[] = []; // 운영 목록. 이 작업에서는 빈 배열
export function extNationAllowed(officerLevel: number, commandKey: string): boolean;
```

- 확장 국가 명령 하나에 행이 정확히 하나 있어야 한다. 단위 시험이 `extensionCommands`의 국가 명령 key 집합과 이 표의 key 집합을 대조한다(T4-02 I9 대조와 같은 방식). 행이 없는 명령은 등록 시험에서 실패하므로 아무도 실행하지 못한 채 운영에 들어가지 않는다.
- 값은 각 명령 작업이 원작 제약으로 정한다. 원작 국가 명령은 대부분 수뇌(`beChief`, 관직 5 이상) 또는 군주(`beLord`)를 요구한다([누락 명령 문서](./mvp-command-gaps.md) 2절). 원작과 다르게 두려면 그 작업이 결정으로 올린다.
- 규칙 실행 검사(`defineCommand`의 국가 명령 권한)와 서버 목록·사전 검사·저장이 이 표 하나를 쓴다. 지금 `ruler` 검사(`support.ts:40`)를 T2-05가 직책 표 검사로 바꾸는 줄에서 P2를 함께 부른다.

#### P2 판정 합치기

- T2-05 판정 함수(예: `canRunNationCommand(officerLevel, key)`)가 기본 key는 `NATION_COMMAND_PERMISSIONS`로, 확장 key는 `extNationAllowed`로 본다. 두 표에 같은 key가 있으면 등록 시험에서 실패한다.
- 인사 기능이 없는 월드는 군주(12)만 국가 칸을 실행하는 지금 규칙 그대로다. 그 월드에서 확장 국가 명령은 군주 칸에서만 실행되고 P1의 `officerLevels`에 12가 없으면 실행 검사에서 실패한다.

### 상대 영역에 필요한 것

- 화면(Claude, T4-51): 꺼진 명령 저장은 `BAD_REQUEST` `이 월드에서 꺼진 명령입니다.`, 사전 검사는 `{ ok: false, reason }`, 목록은 `nationCommands.list`의 `argsSchema`를 그대로 쓴다. `AppRouter` 타입 모양은 T2-05 그대로다.

### 열린 사용자 결정

- 확장 국가 명령마다 어느 직책이 실행하는지. 원작 제약과 다르게 둘 때만 그 명령 작업이 결정으로 올린다.

### 다른 계획과 맞출 쟁점

| ID | 쟁점 | 이 계획의 제안 | 맞출 곳 |
| -- | ---- | -------------- | ------- |
| X1 | 인사 기능 없이 확장 국가 명령을 켠 월드 | T2-05는 인사 기능이 없는 월드의 `nationTurns.*`를 거부한다. 그 월드에서 확장 국가 명령은 사람이 예약할 길이 없고 NPC는 확장 명령을 고르지 않는다(C11). 그래서 확장 국가 명령을 켜면 `personnel` 기능이 필요하다. T2-26의 기능 `requires`나 T4-03 `ext` 기능의 `checkOrigin`으로 생성 때 막는다 | T2-05 B3, T2-26, T4-03 |
| X2 | 권한 표 위치 | 확장 표는 `ext/permissions.ts`에 따로 두고 T2-05 판정 함수에 한 줄로 합친다. `CommandDef`에 권한 칸을 더하면 `commands/types.ts` 공유 순서(T4-02 → T4-49 → T4-48)를 타고 기본 37개 정의도 바뀐다 | T2-05, T4-02 |
