# T2-10 메시지·공지 화면, 실시간 갱신

> 대기열: T2-10 · AC: AC-M2-04, AC-M2-07 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-09 (API)

## 계획 (Claude)

### 목표

메시지를 범위별로 읽고 쓰며 내 턴 결과·새 메시지·월간 정산이 새로고침 없이 2초 안에 화면에 반영된다.

### 범위

- `apps/web/src/realtime/useWorldEvents.ts`: SSE 연결 → 알림 종류별로 TanStack Query 무효화
- 메시지 패널 (메인 오른쪽 접이식 + `/w/:id/messages` 전체 화면), 위쪽 띠 안 읽음 배지
- 국가 공지 팝업 (바뀐 뒤 첫 접속 1회), 국가 정보 화면의 공지 칸과 고치기, 전체 탭 위 월드 공지
- T1-16의 "남은 시간 0초에 다시 조회" 임시 방식을 SSE로 대체

### 하지 않는 것

알림 소리·브라우저 알림(M3 웹 푸시), 메시지 검색.

### 결정

| 알림 | 다시 조회할 것 |
| ---- | -------------- |
| `turn.result` | `home.get`, `turns.get`, `records.general` |
| `message.new` | `message.list`(해당 범위), `message.unread` |
| `monthly.done` | `world.summary`, `home.get`, `world.map` |
| `offer.new`, `treaty.new` | 발령 상자, 외교실 |
| `notice.updated` nation | `notice.nation.get` |
| `notice.updated` world | `notice.world.list` |
| `ready` | 지금 화면의 query 전부 |

- 연결 상태를 위쪽 띠에 작게 표시 (연결됨 · 다시 잇는 중). 끊긴 동안에도 화면은 쓸 수 있다.
- 재조회는 서버 데이터만 바꾼다 (검토 R63-4). `ready` 전체 재조회와 `turn.result`의 `turns.get` 갱신이 지도 선택, 메인 30칸의 미저장 초안,
  메시지 작성 칸, 공지 고치기 초안을 지우지 않는다. 초안은 query 캐시와 따로 둔다.
- 30칸 초안을 고치는 중에 서버 revision이 바뀌면 초안을 덮지 않고 서버 예턴이 바뀌었다고 알린다. 저장은 초안의 revision으로 보내고 어긋나면 T1-15의 STALE 흐름을 탄다.
- 목록은 메시지 id로 중복을 없앤다. `send` 응답으로 먼저 넣은 행, 다른 탭의 재조회, `ready` 재조회, 다음 쪽 불러오기가 겹쳐도 같은 id는 한 줄이고 순서와 안 읽음 수가 맞는다.
- 메시지 탭: 개인 · 국가 · 외교(권한 있을 때만) · 전체. 탭마다 안 읽음 수.
- 보내기 실패(도배 제한 등)는 입력칸 아래에 이유 표시, 입력 내용은 지우지 않는다.
- 연결이 3초 넘게 끊겨야 "다시 잇는 중"을 띄운다. 첫 재시도에서 바로 이어지는 짧은 끊김에는 표시가 깜빡이지 않는다.
- 탭을 열어 첫 쪽이 보이면 그 안의 받은 메시지를 `message.markRead`로 읽음 처리한다. 버튼을 따로 두지 않는다.
- 국가 공지는 팝업을 닫으면 그 팝업에 띄운 `revision`으로 `notice.nation.markSeen`을 부른다. 응답의 `unseen`이 아직 true면(그사이 새 공지) 새 본문으로 팝업을 한 번 더 띄운다. 고치기는 국가 정보 화면의 공지 칸에서 군주·참모만 한다(`canEdit`).
- 월드 공지는 메시지 패널 전체 탭 맨 위에 고정 공지부터 보여 준다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 실시간 | Playwright: 두 브라우저(사용자 A·B) → A가 보낸 개인 메시지가 B 화면에 2초 안에, 새로고침 없이 |
| 턴 결과 | Playwright: manual 시계로 턴 진행 → 메인 최근 기록이 2초 안에 갱신 |
| 범위 | Playwright: 외교 탭은 군주·참모에게만 |
| 공지 | Playwright: 공지 수정 → 소속 장수 다음 접속 시 팝업 1회 |
| 공지 경합 | Playwright: 팝업을 띄운 채 다른 군주 세션이 공지를 고침 → 팝업 닫기 → 새 공지 팝업이 한 번 더 뜸 |
| 재연결 | Playwright(실제 서버): 두 사용자 브라우저에서 연결을 끊었다 다시 이음 → `ready` 뒤 전체 재조회 1회. 지도 선택·30칸 미저장 초안·메시지 작성 칸·공지 고치기 초안 유지, 목록 중복 행 없음. 가짜 EventSource만으로는 인수하지 않는다 |
| 정상 경로 2초 | Playwright: 위 실시간·턴 결과 두 줄을 commit부터 화면 표시까지 잰다 (AC-M2-07은 여기서 판정) |
| 초안과 턴 결과 | Playwright: 30칸 초안을 고치는 중에 턴이 실행됨 → 초안 유지와 서버 예턴 변경 안내, 저장 → STALE 흐름 |
| 목록 병합 | Playwright: 보낸 행이 맨 위에 있는 상태에서 `ready` 재조회와 다음 쪽 불러오기 → 같은 id 한 줄, 안 읽음 수 일치 |
| 접근성 | Playwright: 메시지 패널을 키보드로 열고 닫으면 초점이 여는 단추로 돌아옴, 접힌 패널을 다시 펴도 작성 칸 유지. 보내기 네트워크 실패 뒤 입력 유지와 오류 안내를 스크린리더 이름으로 확인 |
