# T4-92 명령 카드 선택

> AC: AC-P2-29 · 회귀: AC-M1-07·08·09·19, AC-M3-08 · 결정: D-061 · UI 설계: Claude 아티팩트 · 구현: Claude Code · 리뷰: Codex

## 계획 (Claude)

2026-11-02 읽기 전용 Claude 세션의 계획을 채택했다. 원고가 지적한 INT-18 ID 충돌을 피해서 T4-92/AC-P2-29로 등록했다. 계획을 읽는 동안 작업 기준을 로컬 `d82becb2`에서 원격 main `f00ec07e`로 맞췄으며 그 기준의 도시 자원 입력 갈래를 보존한다.

목표는 서버가 준 모든 명령을 분류와 인자가 표시된 카드로 고르는 것이다. 기존 개인 30칸·국가 12칸, 입력·권한·비용·실패·revision 계약을 유지한다. 카드의 표시 방식만 바꾸며 소비형 계략 패는 T4-45에서 구현한다.

1. `commands`에서 실제 분류 목록을 만든다. 알려진 분류는 기존 순서, 나머지는 응답 순서로 잇는다. 분류 단추와 묶음이 같은 목록을 쓴다. 모르는 분류를 전체 목록에서도 누락하는 기존 결함을 고친다.
2. 기존 label과 native radio를 카드로 표현한다. 이름과 보조 설명을 `aria-labelledby`·`aria-describedby`로 연결해 접근 이름은 명령 이름 그대로 유지한다. 분류·입력 항목은 서버 schema와 기존 `argFields`·`requiredKeys`로 표시하고 비용/효과를 추정하지 않는다.
3. INT-18의 훈련/사기 입력은 `cityPreparationSchema`로 고른 갈래를 카드와 입력 양쪽에서 사용한다. 필수 항목과 대상 장수의 표기는 기존 입력과 맞춘다. 지원하지 않는 schema는 인자 없음으로 표시하지 않는다.
4. 카드 선택과 키보드 초점은 굵은 선·outline·native radio로 표시한다. 기존 토큰만 쓰며 모든 폭에서 누름 영역 44px, 긴 이름 줄바꿈, 375px 가로 넘침 없음을 검증한다.
5. 검색 Enter·첫 인자 초점·필수값 누락·저장 불가 이유·목록 갱신 때 삭제된 명령의 입력 차단을 보존한다. 서버 분류가 사라지면 전체 목록으로 표시한다.

## 범위

`CommandPicker.tsx`, `TurnEditor.module.css`, `cityResourceArgs.ts`, 새 `CommandPicker.test.tsx`, 사용자 가이드와 범위/AC/대기열 문서를 고친다. `TurnEditor`의 개인·국가 예약과 `RetinueOrdersPanel`의 장수 지시가 공통 선택기를 쓴다. 별도 카드 컴포넌트·명령 레지스트리·API·DB·rules·의존성을 추가하지 않는다.

사용자의 최신 담당 인계에 따라 Codex가 먼저 만든 초안은 Claude Code가 이어받는다. UI 설계는 Claude의 아티팩트로 만들고 기존 한지·밤 군막 토큰과 접근성을 보존한다. 생성 이미지를 쓰지 않는 선택기이며 아티팩트 설계를 바탕으로 Claude Code가 구현을 확정한다.

## 검증

- React 단위: 모르는 분류와 필터·검색, 한 카드 선택, 접근 이름/설명, 필수 인자, 막힌 클릭/Enter, 서버 목록 갱신, 도시 수비병/부곡 갈래를 본다. `source.test.ts`·기존 도시 자원·외교 시험을 함께 실행한다.
- 지시 선택기의 `RetinueOrdersPanel.test.tsx`와 실제 `int19-retinue-orders.spec.ts`를 회귀 실행한다. 카드 묶음은 `pnpm exec playwright test --config playwright.command-cards.config.ts`이며 `command-cards`·`mobile-controls`·`int19-retinue-orders`·`t4-97-game-ui`가 들어 있다. 도시 자원 갈래 회귀 `int18-city-resources`는 공개 빌드와 10분 예산이라는 고정물 계약이 달라 기존 `pnpm exec playwright test --config playwright.city-resources.config.ts`로 따로 실행한다. 두 실행 모두 필수다.
- `pnpm check`를 실행한다. 기준 환경 실패도 실제 결과로 기록하고 다른 작업의 코드를 임의 수정하지 않는다.
- 실제 Chromium에서 375·768·1440px·밝음/어두움·키보드·긴 카드의 가로 넘침/44px를 확인한다. UI 고정물 시험은 실제 API·PG 인수와 구분한다.
- 실제 PG·API·엔진으로 개인/국가 칸 저장·재접속·오래된 revision·타인 조작 거부를 기존 경로에서 검증한다. 독립 리뷰·CI·보호 병합 전에는 AC를 완료로 바꾸지 않는다.

## 다른 런타임 영향

API·명령 ID·schema·원본/replay 형식은 변경하지 않는다. CF는 upstream 웹 변경을 정상 merge로 받는다. Docker의 이미지/자원/HTTP 정책 파일을 건드리지 않는다. 타입 계약과 기존 Prettier·ESLint·문구 규칙을 따른다.

## 구현 기록 (Codex)

공통 선택기를 카드로 바꾸고 모르는 분류 누락을 수정했다. 카드 선택은 소비 없이 기존 인자/예약 경로를 쓴다. 첫 React/source/도시 자원/외교 검사 39건과 자기 PostgreSQL·실제 API·Chromium 2건(개인/국가 카드, 정식191 모바일)이 통과했다. 첫 검사에서 문구4건·테스트 타입 오류와 시험용 NPC 배치/쿠키 출처 오류를 고쳤다. 독립 리뷰의 목록 내부 넘침·키보드 초점·revision 충돌·장수 지시 회귀 보완을 반영해 다시 검증한다.

리뷰가 찾은 기존 훈련/사기 대상 변경 시 기본값 불일치도 기존 `choose` 경로로 고쳤다. 월드 규칙을 받기 전에는 union schema를 인자 없음으로 표시하거나 Enter로 빈 인자를 넣지 않는다. 새 검증과 최종 독립 리뷰·CI·보호 병합 전이다.

## 구현 기록 (Claude Code 인수)

2026-11-02 사용자 인계에 따라 Codex 초안을 보존하고 Claude Code가 이어받았다. 인수 검토에서 찾은 동작 결함 넷을 `CommandPicker.tsx`에서 고쳤다. 검색 Enter는 서버 응답 순서가 아닌 화면 분류 순서의 첫 카드를 고른다. 국가 칸의 대상 장수는 카드 설명·입력 칸·누락 안내가 모두 '대상 장수'를 쓴다. <!-- lint-text-ignore J-2 -->
훈련·사기 갈래는 고른 카드에만 적용한다. 고르지 않은 카드는 기존 부곡 갈래로 설명하고 다른 카드로 옮기면 기존 부곡으로 돌아간다. 서버 목록에서 고른 명령이 빠지면 선택과 입력값을 비워 같은 키가 다시 와도 옛 값을 쓰지 않는다.

분류·검색·넣기 단추는 모든 폭에서 44px이다. 카드 테두리는 키보드 초점(`:focus-visible`)에서만 2px로 보이고 마우스로 고른 카드는 굵은 왼쪽 선과 배경으로 구분한다. 빈 검색 결과 안내에 다음 행동을 붙였다. `CommandPicker.test.tsx`에 네 결함의 React 시험을 더했고 `command-cards.spec.ts`에 분류·넣기 단추 44px 측정을 넣었다. 실제 union 갈래는 `int18-city-resources.spec.ts`로 본다. 처음에는 카드 묶음 설정에 넣었으나 그 고정물은 공개 빌드(`public-build.json`)와 시험 예산 600000ms를 계약으로 검사해 30초 기본값의 카드 묶음에서 시작하지 못했다. 예산을 바꾸지 않고 기존 `playwright.city-resources.config.ts`로 되돌려 따로 실행한다.

실제 검증에서 나온 보완: 도시 수비병 갈래는 명령 키 목록 대신 서버 schema의 `target: 'city'` 갈래로 판단한다(`hasCityBranch`). 갈래를 가진 명령은 서버 명령 계약이 정하고 화면은 표시·입력만 한다. 고른 뒤 서버 목록에서 갈래가 사라지면 입력을 막고 부곡으로 되돌릴 선택 칸은 남긴다. 비용 안내 문구(`cityPreparationNote`)와 모집 가능 병종 거르기는 아직 화면에 있으며 서버 계약으로 옮기는 일은 Codex 후속이다.

이 세션은 명령을 실행할 수 없어 format·typecheck·vitest·E2E·`pnpm check`를 돌리지 않았다. 부모 Codex의 실제 실행 결과와 독립 리뷰 전이며 완료로 기록하지 않는다. Claude Code의 자기 검토는 독립 리뷰가 아니다.

### 런타임 동등성 (AC-P2-35, T4-98)

카드 선택기는 공통 `apps/web` 하나이며 런타임에 따라 기능·권한·저장 동작을 나누는 분기가 없다. 쓰는 계약은 기존 `commands.list`·`nationCommands.list`·`turns.*`·`nationTurns.*`뿐이다. 2026-11-02 부모 실행에서 카드 묶음의 `command-cards`·`mobile-controls`·`int19-retinue-orders`·`t4-97-game-ui`가 실제 PG·API·Chromium으로 통과했다. `int18-city-resources`도 공개 빌드와 원래 전용 설정으로 3건을 모두 통과했다. 이 PG 결과는 opensamguk판 증거다. Cloudflare판(Worker·DO·D1)은 아직 연결과 실제 검증 전이다. PG 고정물(`saveInitialWorld`·Prisma 조회)로 만든 브라우저 시험을 Cloudflare 완료 증거로 쓰지 않는다. AC-P2-29는 [런타임 기능 동등성](../architecture/runtime-parity.md)대로 같은 장면을 양쪽에서 실제로 실행하기 전에는 완료가 아니다.

## 인수본 리뷰 (Codex)

2026-11-02 Claude Code 인수본의 명령 선택·schema 갈래·입력 라벨·기본값·목록 갱신·초점·반응형과 기존 예약 계약을 검토했다. 새 계층·의존성·API·게임 규칙은 없다. 프론트 인수본은 통과다.

실제 검증: `pnpm check` 386파일·6483시험 통과, 공개 빌드 통과. 카드 전용 묶음의 실제 PG·API·Chromium 4건(개인/국가 카드, 장수 지시, 모바일, 새 HUD)과 기존 도시 자원 전용 구성의 3건(원생성/사람/임관, 실제 세수·모집·훈련·사기, 권한·멱등·재시작)이 통과했다. 도시 자원 시험은 공개 dist와 원래 실행 예산을 사용했다. 처음의 구성 오류를 통과로 세지 않는다.
