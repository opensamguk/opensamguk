## 계획 (Claude)

### 목표

로그인하지 않은 사람도 진행 중인 월드마다 일정 시간 전에 찍어 둔 지도(도시 소유 색과 국가 이름)를 받는다. 지연 시간 안의 변화는 응답에 들어가지 않는다.

### 범위

- 엔진: 월드마다 공개 지도 사본을 주기적으로 저장하고 오래된 사본을 지운다.
- 서버: 무인증 조회 `world.publicMaps` 하나.
- DB: 새 모델 `PublicMapSnapshot`과 새 migration. 기존 migration은 고치지 않는다.

### 왜 사본인가

지금 `world.map`(`apps/server/src/routers/world.ts:18-29`)은 로그인한 사람에게 지금 상태를 바로 준다. 공개 지도에 같은 조회를 쓰고 시각만 늦추면 과거 상태를 다시 만들 방법이 없다. 월간 연감(`YearbookSnapshot`, `packages/db/prisma/schema.prisma:336`)은 한 달 단위라 실제 시간 기준 지연(D-026)과 맞지 않는다. 그래서 실제 시각을 붙인 사본을 따로 둔다.

### 데이터

```prisma
model PublicMapSnapshot {
  worldId String
  takenAt DateTime
  tick    Int
  year    Int
  month   Int
  data    Json // { cities: PublicCity[], nations: PublicNation[] }
  world   World @relation(fields: [worldId], references: [id], onDelete: Cascade)

  @@id([worldId, takenAt])
}
```

`data`에 넣는 값은 아래 둘뿐이다. 장수, 병력, 보급, 국고, 진행 중 출병은 넣지 않는다 (D-026 공개 범위).

```ts
type PublicCity = { key: string; name: string; level: number; x: number; y: number; nationId: number | null; links: string[] };
type PublicNation = { id: number; name: string; color: string };
```

`PublicCity`는 `mapCity`(`apps/server/src/visibility.ts:22-33`)에서 `supplied`를 뺀 모양이다.

### 사본 저장 (엔진)

- 엔진이 월드 턴 처리와 같은 리스 아래에서 저장한다. 게임 상태를 바꾸지 않는 읽기 사본이지만 쓰는 쪽을 엔진 하나로 둔다 (AGENTS §6).
- 저장 간격은 `PUBLIC_MAP_INTERVAL_MINUTES`(기본 5분)다. 지연 시간보다 길게 잡지 않는다. 마지막 사본보다 간격 이상 지났을 때 다음 턴 처리 뒤에 하나 찍는다. 턴이 없으면 찍지 않는다.
- 사본의 `takenAt`은 엔진 시계의 현재 시각이다. 시험은 manual 시계로 시각을 정한다.
- 지연 시간보다 오래된 사본은 가장 최근 하나만 남기고 지운다. 저장과 삭제는 한 트랜잭션이다.
- ENDED 월드는 더 찍지 않는다. 마지막 사본은 남긴다.

### 조회 (서버)

```ts
// publicProcedure. 기존 요청 제한(apps/server/src/trpc.ts:18-26)은 그대로 받는다
world.publicMaps: () => {
  delayMinutes: number;
  worlds: Array<{
    id: string;
    name: string;
    status: 'RUNNING' | 'PAUSED';
    map: null | { takenAt: string; year: number; month: number; cities: PublicCity[]; nations: PublicNation[] };
  }>;
}
```

- 대상은 RUNNING과 PAUSED 월드다. ENDED와 아직 열리지 않은 월드는 빠진다. 순서는 `world.list`와 같다(`createdAt`, `id`).
- 월드마다 `takenAt <= now - delay`인 사본 가운데 가장 늦은 것 하나를 준다. 없으면 `map: null`이다.
- 지연 시간은 `PUBLIC_MAP_DELAY_MINUTES`이고 기본값은 10분이다 (D-026). 저장 간격 5분과 합치면 화면의 지도는 10분에서 15분 전 상태다.
- 서버는 시작할 때 저장 간격이 지연 시간보다 길면 설정 오류로 멈춘다.
- 응답은 사본의 `data`를 그대로 내보내지 않는다. 위 두 타입의 키만 골라 담아 사본에 다른 값이 섞여도 새지 않게 한다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 지연 | 통합(실제 PostgreSQL): manual 시계로 사본 A를 찍고 도시 소유를 바꾼 뒤 사본 B를 찍는다. 지연 시간이 B에 닿기 전에는 A의 소유가 보이고 닿은 뒤 B가 보인다 |
| 공개 범위 | 통합: 응답의 키 집합이 위 타입과 정확히 같다. 장수·병력·보급·국고 키 없음 |
| 무인증 | 통합: 세션 없이 조회 성공. 제재 계정 세션으로도 같은 응답 |
| 대상 월드 | 통합: RUNNING·PAUSED는 나오고 ENDED는 빠진다. 사본 없는 월드는 `map: null` |
| 저장 간격과 정리 | 엔진 통합: 간격보다 짧으면 안 찍는다. 오래된 사본은 하나만 남는다. 저장과 삭제가 한 트랜잭션 |
| 재생 | 엔진 재생 시험: 사본 저장이 `stateHash`와 재생 결과를 바꾸지 않는다 |
| 설정 | 단위: 기본값 10분·5분. 저장 간격이 지연 시간보다 길면 서버 시작이 설정 오류로 멈춘다 |
| 권한 대조 | `tools/authz.integration.test.ts`에 새 절차를 공개 절차로 더한다 |
