## 0. 이 문서의 위치

[Phase 2 확장 기술 명세](./phase2-expansion.md)(이하 명세) C20과 §6 T4-35 행을 API 하나의 입력·출력·권한·시험으로 구체화한다. C20이 남긴 세 선택지(`records.world` 그대로, 그 라우터에 범위 조회 추가, 새 `timelapse` 라우터) 가운데 새 라우터를 고른다(2.1). 기술 선택이며 제품 결정이 아니다.

착수 조건과 지금 상태다.

1. 이 문서의 Codex 계획 기술 검토(명세 G-03). 2026-10-23 수용. 끝 절에 적었다.
2. 공통 정본(인수조건·결정 기록·명세)에 AC-P2-17 1차의 API 몫만 한정 반영. 별도 Claude 정본 작업이 직렬로 반영하며 통합 커밋 전이다.
3. 위 둘의 결과를 이 문서 머리에 SHA로 핀. 아직 SHA가 없다.

부모는 사용자의 Phase 2 구현 지시 아래 로컬 구현을 시작했다. 병합과 완료 판정은 위 세 가지와 독립 리뷰, 정확 SHA 필수 CI 뒤다.

사용자의 Phase 2 실행 지시(2026-10-23)는 기존 범위의 진행을 허락했다. U-10(공유·내보내기), A-11(D4 범위 축소)과 다른 U·A·MQ 결정은 승인되지 않았다. U-20은 사용자가 현재 행 값만으로 멸망 국가 표시를 대신하는 안을 철회하고 저장을 직접 지시했다. 그 저장은 별도 T4-56 계획(Claude)이 맡는다. 이 문서의 `currentNations`는 지금 국가 행의 값일 뿐이며 U-20을 충족하지 않는다. 2026-10-23 사용자 결정 U-01은 이 작업에 영향이 없다. 이 문서는 어떤 제품 정책도 정하지 않는다.

## 2. 계약

### 2.1 새 라우터를 고른 이유와 기존 API와의 차이

`records.world`를 바꾸지 않는다. 기록 화면(`Records.tsx:31`)이 지금 응답과 최신순을 쓰고 있어 정렬이나 모양을 바꾸면 프론트 영역이 함께 바뀐다. 같은 라우터에 절차를 더하면 `records.ts`를 고쳐야 하는데 그 파일은 명세 §7의 공유 반영 목록 밖이다. 새 `timelapse` 라우터는 명세 §7의 `router.ts`·`visibility.ts` 순서에서 T4-35가 첫 번째라 병합 선행이 없다.

| 항목 | `records.world` (그대로) | `timelapse.frames` (새) |
| ---- | ------------------------ | ----------------------- |
| 용도 | 기록 화면의 월간 연감 목록 | 재생 화면의 달별 도시 소유 |
| 입력 | `recordsInput` | 같은 `recordsInput` |
| 정렬 | tick 내림차순 | tick 오름차순 |
| cursor 뜻 | `tick < cursor` | `tick > cursor` |
| 페이지 | 31행 읽고 30행, 31번째가 있으면 30번째 tick | 같음 |
| 국가 요약 | `nationId`·`cities`·`generals` | 없음 |
| 도시 소유 | 저장 순서 그대로 | `cityKey` 오름차순으로 정렬 |
| 국가 표시 | 없음 | 이 페이지의 프레임이 가리키는 국가 가운데 지금 행이 있는 국가의 `id`·`name`·`color` |
| 권한 | 로그인만, 장수 불필요, 월드 상태 무관 | 같음 |

### 2.2 입력

`recordsInput`(`queries.ts:8-16`)을 그대로 쓴다. `{ worldId: uuid, cursor?: string }`이고 strict다. 다른 key(`userId`, `generalId`, `nationId`, `limit`, `order`, `fromTick` 등)는 모두 `BAD_REQUEST`다. 행위자는 세션에서만 정하고 이 절차는 행위자 ID를 읽지 않는다. 범위 지정 입력, 정렬 선택, 페이지 크기 선택은 두지 않는다.

### 2.3 출력

```ts
type TimelapseFrames = {
  items: {
    tick: number;
    year: number;
    month: number;
    cities: { cityKey: number; nationId: number | null }[]; // cityKey 오름차순
  }[]; // tick 오름차순, 최대 30개
  currentNations: { id: number; name: string; color: string }[]; // id 오름차순
  nextCursor: string | null;
};
```

- `items`는 `YearbookSnapshot`의 `tick`, `year`, `month`와 `data.cities`의 투영만 담는다. `sequence`, `stateHash`, `data.nations`와 그 안의 `power`·`gold`·`rice`·`generals`·`cities`, 도시 항목의 다른 key는 내지 않는다.
- `currentNations`는 이 페이지 `items`의 `nationId` 가운데 `null`이 아닌 값의 집합으로 `Nation` 행을 찾아 `id`·`name`·`color`만 고른다. 같은 `readWorld` 트랜잭션 안에서 읽어 프레임과 같은 시점이다. 집합이 비면 DB를 읽지 않고 빈 배열이다.
- 이름 `currentNations`는 값이 지금 행의 것임을 드러내려고 붙였다. 지금 main에는 국가 이름·색을 바꾸는 명령이 없지만 T4-16이 들어오면 옛 프레임에도 바뀐 이름이 붙는다. 과거 이름·색 복원은 T4-56이다.
- 프레임이 가리키지만 행이 없는 국가(멸망)는 `currentNations`에 없다. 화면은 그 ID를 이름 없이 받는다. 어떻게 보일지는 U-20이다. 국가 ID는 다시 쓰이지 않으므로(1절) 다른 국가의 이름이 잘못 붙지 않는다.
- 출력 상한은 프레임 30개, 프레임마다 그 월드 도시 수(지금 시나리오는 94개), `currentNations`는 이 페이지가 가리키는 국가 수다.

### 2.4 페이지와 cursor

- `where: { worldId, tick: { gt: Number(cursor) } }`(cursor가 없으면 조건 없음), `orderBy: { tick: 'asc' }`, `take: 31`.
- 기존 `page`(`queries.ts:91-94`)를 원본 행에 먼저 적용하고 그 30행만 투영한다. 31번째 행은 다음 페이지가 있다는 표시로만 쓰고 파싱하지 않는다.
- `nextCursor`는 31행을 읽었을 때 30번째 tick의 문자열, 아니면 `null`이다. 다음 요청은 그 tick보다 큰 행부터다.
- cursor 뒤에 새 달이 저장되면 다음 페이지에 나온다. cursor 앞(이미 읽은 범위)에 행이 끼어도 다음 페이지는 바뀌지 않는다.
- 빈 월드(PREOPEN이나 첫 정산 전)는 `{ items: [], currentNations: [], nextCursor: null }`.

### 2.5 투영 (`visibility.ts`에 더함)

```ts
const timelapseYearbook = z.object({
  cities: z.array(z.object({ cityKey: z.number().int(), nationId: z.number().int().nullable() })),
});
export const timelapseFrameInfo = (data: Prisma.JsonValue) => ({
  cities: [...timelapseYearbook.parse(data).cities].sort((a, b) => a.cityKey - b.cityKey),
});
export const publicNationDisplaySelect = { id: true, name: true, color: true } as const satisfies Prisma.NationSelect;
```

- zod `object`는 모르는 key를 버린다. 허용 목록 밖의 값은 응답에 닿지 않는다(명세 C9).
- `cities`가 없거나 `cityKey`가 정수가 아니거나 `nationId`가 정수·`null`이 아니면 예외다. 라우터는 이를 잡지 않으므로 `INTERNAL_SERVER_ERROR`와 가린 문구가 나간다. `records.world`와 같다.
- 기존 `publicYearbook`, `worldRecordInfo`, `nationInfo`는 고치지 않는다. 비공개 필드를 늘리지 않으므로 [D-019](../product/decisions.md#d-019-다른-국가의-기술은-공개-국력에서도-역산되지-않게-한다-2026-10-21)의 국력 역산 문제도 생기지 않는다.

### 3.2 PostgreSQL·실제 HTTP (`routers/timelapse.integration.test.ts`, `pnpm test:int`)

준비는 `routers/reads.integration.test.ts:74-198`과 같은 방식으로 이 파일 안에서 한다. 공유 helper를 새로 만들지 않는다. `readFixture`의 국가 1·2, 사용자 넷(국가 1 장수, 국가 2 장수, 재야 장수, 이 월드에 장수 없음)을 쓴다. 월드 두 개(`primary`, `other`)를 만들고 `primary`에 tick `10000 × (k + 1)`(k = 0~34)인 스냅샷 35개를 넣는다. 첫 도시의 소유는 달마다 국가 1과 2를 번갈아 바꾸고 둘째 도시는 k ≥ 30에서 국가 3(행 없음)으로 둔다. `data.nations`에는 `gold`·`rice`·`power`를 넣고 도시 항목에는 `population` key를 섞는다. DB 시험 환경은 부모가 준비한 전용 PostgreSQL(`TEST_DATABASE_URL`이 `_test`로 끝남)이며 공유 DB에서 다른 시험과 동시에 돌리지 않는다.

| ID | 시험 | 기대 |
| -- | ---- | ---- |
| H1 | 첫 페이지와 이어 읽기 | 첫 페이지 tick 10000~300000 30개, `nextCursor` `'300000'`. 둘째 페이지 310000~350000 5개, `nextCursor` `null`. 겹침 없이 35개 |
| H2 | 경계 | cursor `'350000'`은 빈 페이지. 스냅샷을 정확히 30개만 둔 월드는 30개와 `null`. 스냅샷 없는 월드는 `{ items: [], currentNations: [], nextCursor: null }` |
| H3 | 프레임 내용 | 각 프레임의 `cities`가 넣은 소유와 같고 `cityKey` 오름차순. 첫 도시 소유가 달마다 바뀐 그대로 |
| H4 | 응답 key 허용 목록 | 최상위 key `currentNations`·`items`·`nextCursor`, 프레임 key `cities`·`month`·`tick`·`year`, 국가 key `color`·`id`·`name`. 응답 JSON에 `gold`, `rice`, `power`, `generals`, `population`, `stateHash`, `sequence`, `tech`, `capitalCityKey`, `description`, `philosophy`, `isNpc`가 없다 |
| H5 | 지금 국가 행 기준 | 첫 페이지(k = 0~29) `currentNations`는 국가 1·2. 둘째 페이지(k = 30~34)의 프레임에는 `nationId` 3이 남고 `currentNations`는 국가 1·2뿐이다. 국가 2의 `name`을 DB에서 바꾸면 두 페이지 모두 새 이름이 나온다. 바꾼 이름은 시험 끝에 되돌린다 |
| H6 | 다른 사용자 허용 (공개 범위) | 네 사용자가 같은 입력으로 받은 응답이 깊은 비교로 같다. 시험 이름에 공개 범위라서 허용한다는 이유를 적는다 |
| H7 | 무인증·위조·만료 세션 | 401 `UNAUTHORIZED`, 데이터 없음 |
| H8 | 제재·탈퇴 | 같은 사용자를 `SANCTIONED`, `WITHDRAWN`으로 바꾸면 기존 세션으로 401. 끝나면 `ACTIVE`로 되돌린다 |
| H9 | 잘못된 입력 | `userId`, `generalId`, `actorId`, `nationId`, `limit`, `order`, `fromTick`을 더하면 400. `null`, `[]`, `{}`, uuid 아닌 `worldId`, 숫자 `worldId`는 `BAD_REQUEST`. cursor `''`, `'-1'`, `'01'`, `'1.5'`, `'2147483648'`, `'1e3'`, `1`, `null`, `{}`, `'9'`×1000은 400. POST는 405 |

### 3.3 권한 대조 (`pnpm test:authz`)

`tools/run-authz.ts`의 출력이 `procedures=24`, `missing=0`이고 `EXEMPT timelapse.frames otherUser: …` 한 줄이 늘어난다. `timelapse.frames`의 성공·무인증·제재·잘못된 입력 네 범주는 실행 증거로 남는다.

### 3.4 증거로 인정되는 것

| 무엇 | 명령 | 인정 |
| ---- | ---- | ---- |
| 투영 | `pnpm check` | U1~U3 시험 이름과 정확한 SHA의 CI |
| DB·HTTP·권한 | `pnpm test:int` | H1~H13. skip 0 |
| 권한 대조 | `pnpm test:authz` | 3.3의 출력 줄 |
| 문구 | `pnpm lint:text --strict apps/server/src` | 0건 |

mock DB나 tRPC caller 직접 호출은 증거가 아니다. 실제 TCP 소켓으로 서버를 띄운다(`reads.integration.test.ts:197`과 같음). 이 작업의 증거는 AC-P2-17의 Chromium E2E를 대신하지 않는다. 그 증거는 T4-36이 받고 AC-P2-17 1차는 T4-35와 T4-36이 함께 끝나야 닫힌다. 이 AC만으로 D4 완료를 판정하지 않는다(A-11).
