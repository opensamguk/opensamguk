## 0. 이 문서의 위치

명세 §6 T4-25 행을 적는다. 장수의 특기 값을 효과로 바꾸는 규칙, 그 효과를 T4-18 합산 틀에 넣는 제공자, 화면이 특기 이름과 설명을 읽을 조회 필드다.

이 작업의 사정은 장비와 다르다. 특기 값은 이미 있다. 시나리오 1030의 장수 491명 가운데 119명이 `special` 값을 갖고 월드를 만들면 DB에 그대로 저장된다(§1.1). 그래서 제공자가 `special`을 무조건 읽으면 지금 진행 중인 월드의 내정·전투 결과가 바뀐다. AC-P2-13은 확장을 끈 월드의 결과가 지금과 같아야 한다고 적었다. 그래서 월드마다 특기 효과를 켜는 표식이 먼저 필요하다. 표식은 [T2-26](https://github.com/opensamguk/opensamguk/pull/220)(PR #220 `fa516aa`, 채택 전)의 규칙 기능 `traits`다(§2.2).

착수 조건은 이 문서의 G-03 수용, §3 TT-1~TT-6의 사용자 결정, T25-Q2의 총괄 확인, T2-26 병합, AC-P2-13 (나)의 정식 반영이다.

## 계획 (Claude)

### 목표

AC-P2-13 가운데 규칙·조회 몫을 만든다. 특기 효과를 켠 월드에서 장수의 특기가 승인된 범위(U-07)의 내정·전투 계산에 T4-18 합산 틀을 거쳐 들어간다. 특기가 없는 장수와 특기 효과를 켜지 않은 월드의 결과·난수 소비·상태 해시는 지금과 같다(골든). 자기 장수와 같은 국가 장수의 특기 이름·분류·설명을 조회 응답에서 읽는다.

AC-P2-13 전체는 T4-26(E2E)까지 끝나야 닫힌다.

- 다른 국가 장수의 특기 공개. 지금 공개 범위(`visibility.ts:65-69`)를 바꾸지 않는다.
- 화면(T4-26), 전투 시뮬레이터(T4-34)에 특기 넣기, NPC 판단(C11).

## 2. 계약

### 2.1 카탈로그

```ts
// traits/catalog.ts
export type TraitKind = 'domestic' | 'war';
export interface TraitDef {
  key: string; // 시나리오 값 그대로. 예: '경작'
  kind: TraitKind;
  name: string; // 화면 이름. 원고는 key와 같다
  description: string; // 우리에게 들어간 효과만 적은 한 줄. 빈 효과면 정해진 문구(TT-2)
  effects: readonly TraitEffect[];
}
export type TraitEffect = {
  stage: 'domestic.score' | 'battle.dealt' | 'battle.taken';
  op: 'add' | 'mul';
  value: number;
  commandKeys?: readonly string[];
  role?: 'attacker' | 'defender'; // T25-Q2 (가)일 때만
  opponent?: 'general' | 'wall'; // T25-Q2 (가)일 때만
};
export const traitCatalog: readonly TraitDef[];
export function traitOf(special: string | null): TraitDef | null;
```

- 원고는 §1.2·§1.3의 28종을 key와 분류로 모두 적고 `effects`는 §3 결정 결과를 그대로 넣는다. 결정 전에는 비운다.
- `traitOf`는 카탈로그에 없는 문자열(시나리오 오타, 이후 시나리오의 새 값)에 null을 낸다. 효과 없이 지나가며 예외를 내지 않는다. 시나리오 적재가 이미 문자열을 받았으므로 거부는 시나리오 검사 몫이다(쟁점 T25-Q4).
- `description`은 [글쓰기 규칙](../writing-style.md)을 따르고 원작의 HTML 태그를 옮기지 않는다.

### 2.2 켜짐 표식 (T2-26 규칙 기능 `traits`)

- T2-26의 기능 목록에 `traits`를 등록한다. 켠 월드의 `initial.ruleFeatures`와 `WorldState.ruleFeatures`에 `traits`가 들어가고 origin 3·archive 3에 그대로 남는다. 그래서 재생도 기록의 기능 목록으로 특기 규칙을 탄다. `ruleFeatures`에 `traits`가 없는 기록에서는 특기 규칙이 실행되지 않는다.
- 갈림은 `hasRuleFeature(view, 'traits')` 하나다. 프리셋 스키마와 `PresetRules`는 고치지 않는다.
- 기능 자료가 없어 `featureData.traits`를 만들지 않는다. 특기 카탈로그는 rules 코드 상수라 재생이 같은 실행본의 같은 값을 쓴다. 카탈로그 효과의 뜻이 바뀌면 같은 key를 고치지 않고 새 기능 key를 등록한다(T2-26 형식 규칙).
- 보존 범위를 형식별로 나눈다. 형식 1 월드(`replayFormat: 1`)는 특기 코드가 닿지 않아 origin 1·archive 2 바이트와 해시가 지금과 같다. 기능 없이 만든 형식 3 월드(T2-26 뒤 새 월드의 기본, T2-26 74줄·158줄)는 `ruleFeatures` 키가 없어 상태 해시·`initialStateHash`·`resourceHash`가 같은 입력의 형식 1 월드와 같다. 형식이 달라 기록 바이트는 비교 대상이 아니다. `traits` 없이 다른 기능만 켠 월드도 특기 규칙을 타지 않는다.
- 어느 월드에 켤지는 T2-26 열린 결정 U26-2(기능을 고르는 화면·프리셋·로비 규칙)와 이 문서의 TT-6이다. 시험과 개발에서는 T2-26의 `pnpm world:create --rule-features traits`로 만든다.

### 2.3 제공자

```ts
// traits/provider.ts
export const traitModifierProvider: ModifierProvider;
```

- `hasRuleFeature(view, 'traits')`가 거짓이면 빈 배열이다. 특기 없는 장수, 카탈로그에 없는 값도 빈 배열이다(T4-18 P3).
- 특기의 `effects` 가운데 `context.stage`, `commandKeys`, `role`, `opponent`가 맞는 것만 낸다. `source`는 `trait:<영문 id>`다. 정규식(`/^[a-z][a-z0-9_]*:[a-z0-9_-]{1,48}$/`)이 한글을 받지 않으므로 카탈로그에 영문 id(예: `farming`)를 함께 둔다.
- T4-18 P1~P4를 지킨다. 장비 제공자 뒤에 등록한다(§7). 합산 순서는 `source` 문자열 순이라 `equipment:` 뒤 `trait:`이다.

### 2.4 역할 문맥 (T25-Q2, TT-3 결정에 따라)

기병·보병·공성처럼 공격과 수비, 장수전과 성벽전에 다른 값을 쓰려면 제공자가 역할을 알아야 한다. 지금 문맥에는 없다.

- (가) `ModifierContext`에 선택 칸 `role?: 'attacker' | 'defender'`와 `opponent?: 'general' | 'wall'`을 더하고 `attack.ts`의 수집 호출 넷에 값을 넘긴다. 내정 호출은 넘기지 않는다. T4-18 2.2 합산 순서와 기존 단계는 바꾸지 않는다. 무수정자 골든(T4-18 V2 출병 14건)이 그대로여야 한다.
- (나) 역할을 쓰지 않는다. 공격·수비 구분이 있는 특기는 한쪽 값만 쓰거나 빼고 TT-3에서 정한다.

### 2.5 조회 필드

`ownGeneralInfo`(`visibility.ts:35-63`)에 칸 하나를 더한다.

```ts
trait: { key: string; kind: 'domestic' | 'war'; name: string; description: string; active: boolean } | null;
```

- `special`이 null이거나 카탈로그에 없으면 null.
- `active`는 그 월드의 `hasRuleFeature(view, 'traits')` 값이다. 서버 `readView`가 T2-26대로 `ruleFeatures`를 상태에 싣는다. 꺼진 월드에서도 이름은 보이고 `active: false`다. 화면이 효과가 꺼졌다고 밝힌다(T4-26).
- 공개 범위는 지금 그대로다. `ownGeneralInfo`가 나가는 곳(자기 장수, 같은 국가 장수)에만 나간다. 기존 `special` 원문 칸은 남긴다. 지우면 지금 화면 계약이 바뀌기 때문이다.
- `ownGeneralInfo`를 부르는 곳은 `home.get`(`routers/home.ts:31`), `city.get`·`nation.get`의 장수 표(`generalInfo`를 거쳐, `routers/city.ts:16`, `routers/nation.ts:19`)다. `active`를 내려면 세 곳이 월드 표식을 함께 넘겨야 하므로 `ownGeneralInfo`·`generalInfo`에 선택 인자 하나를 더한다. 세 응답에 같은 값이 나오는지 서버 시험으로 확인한다.
