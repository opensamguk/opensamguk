# T2-11 D2 국가 작전판: 데이터·API

> 대기열: T2-11 · AC: AC-M2-15 (API) · 구현: Codex · 리뷰: Claude
> 선행: T2-09, T2-13(예턴 칸 `explicit`과 활동 기록) · 관련: [차별화 D2](../product/differentiation.md#d2-국가-작전판), FR-DIF-02

## 계획 (Claude)

### 목표

수뇌가 작전(목표 도시, 목표 연월, 참여 장수)을 만들면 참여 장수들의 턴 시각과 예턴을 한 타임라인으로 계산해 주고
목표 전에 출병이 실행되지 않거나 준비가 모자란 장수를 표시한다. 작전 참여 시 제안 예턴을 만든다. 관직자는 국가원 전원의
예턴·훈련·사기 표(감찰)를 본다. 다른 국가는 볼 수 없다 (AC-M2-15).

### 범위

- `Operation`, `OperationMember` 테이블
- `packages/rules/src/operation/`: 타임라인 계산, 판정, 제안 예턴 생성 (순수 함수)
- `apps/server/src/routers/operation.ts`, `inspection.ts`(감찰)

### 하지 않는 것

작전대로 예턴을 강제로 바꾸기(제안만, 장수가 확인해야 반영), 상관 지시로 남의 예턴 덮어쓰기(Phase 2).

### 타임라인 계산 결정

```text
참여 장수마다:
  턴 시각 목록 = nextTurnTick부터 목표 tick까지 TICKS_PER_MONTH 간격
  예턴을 순서대로 대입해, 각 칸이 언제 실행되는지 계산
  판정:
    ✓ 준비됨   목표 tick 전에 목표 도시로 '출병'이 있고, 그 시점 예상 병력·훈련·사기가 기준 이상
    ⚠ 늦음     출병이 목표 tick 뒤에 있음
    ⚠ 미흡     출병은 제때지만 예상 병력·훈련·사기가 기준 미달
    ✗ 없음     목표 도시 출병이 없음
```

- "예상 병력·훈련·사기"는 예턴의 모병·훈련·사기진작을 규칙의 **기대값**으로 더해 추정한다 (난수 없이). 화면에는 "예상"이라고 표시.
- 기준(최소 병력·훈련·사기)은 작전을 만들 때 정한다.
- **제안 예턴**: 남은 칸 수 안에서 "모병 → 훈련 → 사기진작 → 출병(목표 시각 직전 칸)"을 맞춘 30칸 사본. 장수가 `turns.set`으로 확인 저장해야 반영.
- 공개 범위: 작전과 감찰은 같은 국가에게만. 작전 목록은 직책자 전체, 작전 상세는 참여 장수와 직책자.

### API 계약

```ts
operation.create({ worldId, targetCityKey, targetYear, targetMonth, minCrew, minTrain, minAtmos, memberIds })   // 수뇌 이상
operation.list({ worldId }) → [{ id, target, targetDate, status, members: n, ready: n }]
operation.get({ worldId, id }) → { ..., timeline: [{ generalId, name, slots: [{ tick, at, commandKey, args }], verdict, expected: { crew, train, atmos } }] }
operation.suggest({ worldId, id }) → { revision, slots: Slot[30] }        // 내 장수용 제안 사본
operation.close({ worldId, id })
inspection.members({ worldId }) → [{ generalId, name, cityKey, crew, train, atmos, turns: Slot[5], lastActiveAt }]   // 직책자만
```

### 화면이 기대하는 응답 모양 (T2-12, 2026-10-21 추가)

이름은 바꿔도 되지만 필드는 모두 필요하다. 위 계약에서 달라진 점은 넷이다. `operation.list`가 만들기 가능 여부를 함께 준다.
`operation.get`은 열 머리(월)와 장수별 출병 칸을 따로 준다. `operation.suggest`는 현재 예턴과 바뀌는 칸을 함께 준다.
`inspection.members`는 미접속 표시를 준다. 화면 요소와의 대조는 [T2-12 v1 근거](./T2-12.md#v1-근거)에 있다.

```ts
type GameDate = { year: number; month: number };
type NationRef = { id: number; name: string; color: string };
type Allowed = { ok: true } | { ok: false; reason: string }; // T2-07과 같은 모양
// T2-13의 SlotView를 그대로 쓴다. 30칸 모두 객체이고 null이 없다. 빈칸은 explicit: false인 휴식이다.
type SlotView = { commandKey: string; args: unknown; name: string; explicit: boolean };
type Verdict = 'READY' | 'LATE' | 'WEAK' | 'MISSING'; // 준비됨·늦음·미흡·없음
type Readiness = { crew: number; train: number; atmos: number };

type OperationRow = {
  id: string;
  target: { cityKey: string; cityName: string; nation: NationRef | null }; // 공백지면 null. 지도에 공개된 소유만 쓴다
  targetDate: GameDate;
  targetAt: string; // 목표 tick의 현실 시각(ISO). 서버가 바꿔 준다
  status: 'OPEN' | 'CLOSED';
  createdBy: { generalId: number; name: string };
  members: number;
  ready: number; // verdict가 READY인 참여 장수 수
  joined: boolean; // 내 장수가 참여 장수인지
};
type TimelineCell = {
  slot: number; // 예턴 칸 번호 0~29
  tick: number;
  at: string; // 실행 시각(ISO)
  date: GameDate; // 실행되는 게임 연월. 열 머리와 맞춘다
  turn: SlotView;
};
type MemberTimeline = {
  generalId: number;
  name: string;
  cityKey: string;
  cityName: string;
  isMe: boolean;
  verdict: Verdict;
  sortie: TimelineCell | null; // 목표 도시로 가는 첫 출병 칸. 없으면 null(MISSING). 목표 뒤면 LATE
  expected: Readiness; // sortie 시점의 예상값. sortie가 없으면 목표 시각 기준. 기대값이라 난수가 없다
  cells: TimelineCell[]; // 지금부터 남은 30칸 전부. 화면이 목표 전 6개월만 먼저 보여 준다
};
type OperationDetail = Omit<OperationRow, 'joined'> & {
  min: Readiness; // 만들 때 정한 기준
  months: GameDate[]; // 열 머리. 이번 달부터 targetDate 다음 달까지(늦은 출병을 한 칸 보여 줄 자리)
  timeline: MemberTimeline[]; // 다음 턴 시각 순, 같으면 장수 ID 순
  canSuggest: Allowed; // 참여 장수이고 OPEN일 때만 ok
  canClose: Allowed; // 만든 장수 또는 군주이고 OPEN일 때만 ok
};
type InspectionRow = {
  generalId: number;
  name: string;
  officerLevel: number;
  cityKey: string;
  cityName: string;
  isHuman: boolean;
  crew: number;
  train: number;
  atmos: number;
  turns: SlotView[]; // 앞 5칸
  nextTurnAt: string; // ISO
  lastActiveAt: string | null; // 화면 표시용 현실 시각. NPC나 활동 기록이 없으면 null
  idle: boolean; // T2-13의 미접속 판정 함수를 지금 tick으로 부른 값(lastActiveTick 기준). NPC는 false
};

// operation.list → { canCreate: Allowed; items: OperationRow[] }
//   OPEN 먼저, 그 안에서 targetDate 이른 순, 같으면 id 순.
// operation.get → OperationDetail
// operation.suggest → { revision: number; current: SlotView[]; slots: SlotView[]; changed: number[] }
//   current는 turns.get과 같은 30칸, slots는 제안 30칸이다. 작전이 채운 칸은 explicit: true, 그대로 둔 칸은 current의 값(explicit 포함)을 복사한다.
//   changed는 T2-13의 sameSlot으로 다르다고 나온 칸 번호 오름차순이다. 화면은 이 칸만 강조해 미리 보여 준다.
//   장수가 확인하면 turns.set({ revision, slots: slots.map(toSlotInput) })로 저장한다. 빈칸은 null로 돌아가 빈칸으로 남는다.
//   revision이 어긋나면 T1-11과 같이 STALE과 explicit을 담은 현재 30칸을 받는다. 화면은 저장하지 않고 suggest를 다시 부른다.
// inspection.members → { items: InspectionRow[] }
//   officerLevel 높은 순, 같으면 장수 ID 순.
```

공개 범위 (T1-12와 원작 기준):

- 직책자는 officerLevel 5 이상(수뇌·참모·군주, T2-05 표)이다. 작전 만들기와 감찰은 직책자만 한다.
- `operation.list`는 같은 국가에게만 준다. 직책자는 모든 작전을, 그 밖의 장수는 자기가 참여한 작전만 받는다.
  `operation.get`은 참여 장수와 직책자만 받는다. 다른 국가 장수가 작전 ID를 알아도 `FORBIDDEN`이다.
- 참여 장수는 같은 작전 참여자의 예턴·예상값을 본다. 원작은 남의 예턴을 수뇌부나 오래 소속한 장수에게만 보여 주므로,
  이 작전 밖 장수의 예턴은 일반 장수에게 주지 않는다.
- 목표 도시는 다른 국가 도시이므로 이름과 소유 국가만 준다. 병력·수비 같은 수치는 넣지 않는다.
- 감찰 표는 원작 암행부처럼 자기 국가 장수만 담는다. 금·쌀은 화면에 쓰지 않으므로 넣지 않는다.
- M1에는 접속 기록이 없다. `General.lastActiveAt`·`lastActiveTick`과 활동 기록은 T2-13 범위이고 T2-11은 그것을 읽기만 한다.

### 예턴 칸 왕복 (검토 R62-2, 2026-10-21 추가)

작전 제안에서 `turns.set` 저장까지 빈칸과 직접 넣은 휴식이 섞이지 않아야 한다. 칸 모양과 비교 함수는 T2-13의
[예턴 칸 모양](./T2-13.md#예턴-칸-모양-검토-r62-2r63-2-2026-10-21-추가) 하나를 쓰고 T2-11은 따로 정의하지 않는다.

- 공유 타입: 화면으로 나가는 칸은 `SlotView`, 화면에서 들어오는 칸은 `SlotInput`(`null`은 빈칸, 객체는 직접 넣은 칸)이다. 변환은 `toSlotInput` 하나다.
- `changed`: `sameSlot(a, b)`가 거짓인 칸이다. 빈칸끼리는 같다. 빈칸과 직접 넣은 휴식은 다르다. 직접 넣은 칸끼리는 `commandKey`와 `args`(키 순서 무시)를 비교한다.
- 제안 생성(`packages/rules/src/operation/`)은 `QueuedTurn[]`(explicit 포함)을 받아 `QueuedTurn[]`을 돌려준다. 작전 배치에 쓰지 않는 칸의 explicit을 바꾸지 않는다.
- 선행: `explicit`의 저장·재생·엔진 당김·편집은 T2-13(Codex)이 소유한다. 그래서 T2-11은 T2-13 뒤에 구현한다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 판정 | 단위: 4가지 판정 각각 |
| 시각 | 단위: 턴 오프셋이 다른 장수 3명 → 출병 실행 tick 계산 |
| 제안 | 단위: 남은 칸 8칸 → 모·훈·사·출 배치, 목표 직전 칸에 출병 |
| 칸 왕복 | 통합: 빈칸과 직접 넣은 휴식이 섞인 예턴 → `suggest` → `turns.set(toSlotInput)` → `turns.get`에서 작전 밖 칸의 explicit이 그대로. `changed`에 빈칸↔직접 휴식 차이가 잡힘 |
| 충돌 | API: `suggest` 뒤 `turns.edit`로 revision을 올리고 저장 → STALE과 explicit 포함 30칸, 저장 안 됨 |
| 권한 | API: 일반 장수 작전 생성 거부, 다른 국가 조회 거부, 감찰은 직책자만 |
| 공개 범위 | API: 참여하지 않은 일반 장수는 `operation.list`에 그 작전이 없고 `get`은 `FORBIDDEN`. 목표 도시는 이름·소유만 |
| 반영 | 통합: 제안 저장 → 실제 턴 진행 → 목표 전 출병 실행 |
