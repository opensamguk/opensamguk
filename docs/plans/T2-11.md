# T2-11 D2 국가 작전판: 데이터·API

## 계획 (Claude)

### 목표

수뇌가 작전(목표 도시, 목표 연월, 참여 장수)을 만들면 참여 장수들의 턴 시각과 예턴을 한 타임라인으로 계산해 주고,
목표 전에 출병이 실행되지 않거나 준비가 모자란 장수를 표시한다. 작전 참여 시 제안 예턴을 만든다. 관직자는 국가원 전원의
예턴·훈련·사기 표(감찰)를 본다. 다른 국가는 볼 수 없다 (AC-M2-15).

### 범위

- `Operation`, `OperationMember` 테이블
- `packages/rules/src/operation/`: 타임라인 계산, 판정, 제안 예턴 생성 (순수 함수)
- `apps/server/src/routers/operation.ts`, `inspection.ts`(감찰)

### 하지 않는 것

작전대로 예턴을 강제로 바꾸기(제안만, 장수가 확인해야 반영), 상관 지시로 남의 예턴 덮어쓰기(Phase 2).

### 결정: 타임라인 계산

```text
참여 장수마다:
  턴 시각 목록 = nextTurnTick부터 목표 tick까지 TICKS_PER_MONTH 간격
  예턴을 순서대로 대입해, 각 칸이 언제 실행되는지 계산
  판정:
    ✓ 준비됨   목표 tick 전에 목표 도시로 '출병'이 있고, 그 시점 예상 병력·훈련·사기가 기준 이상
    ⚠ 늦음     출병이 목표 tick 뒤에 있음
    ⚠ 미흡     출병은 제때지만 예상 병력·훈련·사기가 기준 미달
    ✗ 없음     목표 도시 출병이 없음
```

- "예상 병력·훈련·사기"는 예턴의 모병·훈련·사기진작을 규칙의 **기대값**으로 더해 추정한다 (난수 없이). 화면에는 "예상"이라고 표시.
- 기준(최소 병력·훈련·사기)은 작전을 만들 때 정한다.
- **제안 예턴**: 남은 칸 수 안에서 "모병 → 훈련 → 사기진작 → 출병(목표 시각 직전 칸)"을 맞춘 30칸 사본. 장수가 `turns.set`으로 확인 저장해야 반영.
- 공개 범위: 작전과 감찰은 같은 국가에게만. 작전 목록은 직책자 전체, 작전 상세는 참여 장수와 직책자.

### API 계약

```ts
operation.create({ worldId, targetCityKey, targetYear, targetMonth, minCrew, minTrain, minAtmos, memberIds })   // 수뇌 이상
operation.list({ worldId }) → [{ id, target, targetDate, status, members: n, ready: n }]
operation.get({ worldId, id }) → { ..., timeline: [{ generalId, name, slots: [{ tick, at, commandKey, args }], verdict, expected: { crew, train, atmos } }] }
operation.suggest({ worldId, id }) → { revision, slots: Slot[30] }        // 내 장수용 제안 사본
operation.close({ worldId, id })
inspection.members({ worldId }) → [{ generalId, name, cityKey, crew, train, atmos, turns: Slot[5], lastActiveAt }]   // 직책자만
```

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 판정 | 단위: 4가지 판정 각각 |
| 시각 | 단위: 턴 오프셋이 다른 장수 3명 → 출병 실행 tick 계산 |
| 제안 | 단위: 남은 칸 8칸 → 모·훈·사·출 배치, 목표 직전 칸에 출병 |
| 권한 | API: 일반 장수 작전 생성 거부, 다른 국가 조회 거부, 감찰은 직책자만 |
| 반영 | 통합: 제안 저장 → 실제 턴 진행 → 목표 전 출병 실행 |
