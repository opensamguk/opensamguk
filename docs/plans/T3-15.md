# T3-15 오픈 리허설과 공개

> 대기열: T3-15 · AC: AC-M3-11, AC-M3-16 · 구현: 사용자 (대기열 칸 유지) · 판정 리뷰: 리허설 참가자를 운영하지 않은 쪽
> 선행: 대기열 기준 · 결정: [D-021](../product/decisions.md#d-021-지인-참가-시험을-독립-에이전트-참가-시험으로-바꾸고-공개를-승인한다-2026-10-21) · 기록 형식: [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험) · 관련: [릴리스 운영](../release-operations.md)

## 계획 (Claude)

### 목표

- 공개 전 독립 에이전트 참가자 5명 이상으로 오픈 리허설을 한 번 한다. 가입부터 첫 턴 결과까지 막힌 참가자가 0명이다 (AC-M3-11).
- 도메인과 HTTPS로 누구나 가입해 참가할 수 있고 첫 공개 월드가 시작된다 (AC-M3-16).

### 승인과 결과를 나눠 적는다

| 항목 | 현재 상태 | 근거 |
| ---- | --------- | ---- |
| 공개에 대한 소유자 승인 | 받음. 다시 묻지 않는다 | D-021 |
| 오픈 리허설 결과 | 하지 않음 | 아래 구현 기록 |
| 제품 QA 통과 (M3 AC 전부) | 아님 | [인수조건](../product/acceptance-criteria.md#m3) |
| 공개 실행 (AC-M3-16) | 하지 않음 | 아래 구현 기록 |
| 운영 변경 권한 | 이 계획이 주지 않는다 | 그때 적용되는 운영 권한과 안전 절차 |

승인을 공개 완료나 QA 통과로 적지 않는다. 새 비용, GCP 기동, 운영·게임 초기화는 이 승인에 들어 있지 않다.

### 범위

리허설 방법, 공개 직전 확인 목록, 증거 형식만 정한다. 제품 코드, 시험 실행, 인수 판정, 배포는 이 문서가 하지 않는다. 참가 에이전트 배정과 일정은 총괄이 정한다.

### 하지 않는 것

NPC나 같은 에이전트의 요청 수로 참가자 채우기, 운영자가 대신 진행시킨 참가자를 통과로 세기, 메일 서비스(T3-01)나 공개 이미지 권리(T3-12) 결정 대신하기.

### 오픈 리허설 (AC-M3-11)

1. 공개할 환경과 같은 빌드에서 한다. 시작 전에 `sourceSHA`(필수 CI를 통과한 정확한 커밋), 도메인, 리허설 월드의 `worldId`, 참가자 목록을 적는다.
2. 참가자 5명 이상이 [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험)의 독립 기준을 지킨다. 계정·로그인 세션·에이전트 세션이 참가자마다 다르다.
3. 참가자마다 가입 → 이메일 인증(T3-01에서 정한 서비스의 시험용 메일함) → 약관 동의 → 로비에서 월드 선택 → 장수 생성 → 예턴 입력 → 첫 턴 결과 확인까지 한다.
4. 막힘은 참가자가 운영자 도움, 관리자 조치, DB 수정, 내부 API 없이는 다음 단계로 못 간 경우다. 막힌 참가자가 1명이라도 있으면 원인을 고친 뒤 리허설을 다시 한다. 두 번 모두 기록한다.
5. 참가자별 기록과 피드백, 결함 목록을 남긴다.

### 공개 (AC-M3-16)

공개 직전에 M2 AC 전부와 AC-M3-01~15가 통과했는지, 공개할 커밋의 필수 CI와 교차 리뷰, [릴리스 운영](../release-operations.md) 절차, 백업이 있는지 확인한다. 공개는 그때 적용되는 운영 권한과 안전 절차로 실행한다. 서버 밖 세션에서 공개 도메인에 HTTPS로 접속해 가입한다. 첫 공개 월드의 `worldId`와 시작 시각을 남긴다.

### 검증

- AC-M3-11: 리허설 회고. 참가자 표(§6 필드), 참가자별 막힘 여부, 피드백, 결함 목록, 원본 기록 SHA-256.
- AC-M3-16: 공개 URL 접속 기록. 접속 시각, 도메인, 인증서 확인, 가입 성공, 첫 공개 월드 시작.
- 리허설 참가자를 운영하지 않은 쪽이 원본 기록과 요약을 대조한 뒤에만 AC를 통과로 표시한다.
