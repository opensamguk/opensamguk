### 요청 제한 결정

서버 1대(A13)이므로 프로세스 안 고정 창 계수기로 한다. Redis는 쓰지 않는다 (A11). 재시작하면 계수가 비는 것은 받아들인다. 계수기의 계약과 한도 표는 아래 공유 절에 있다.

- IP는 Fastify `trustProxy`를 운영 Caddy 한 단계만 믿도록 설정해 얻는다. 개발에서는 소켓 주소를 쓴다. 설정 값은 `TRUST_PROXY`이며 기본은 꺼짐이다.
- 이 작업이 거는 한도는 `auth.login.ip`, `auth.login.failure`, `auth.signup.ip`, `mutation.user` 넷이다. 메일과 계정 토큰 namespace는 T3-02가 건다.

### 공유 요청 제한 계수기 결정

이 절은 [T3-02](./T3-02.md#공유-요청-제한-계수기-결정)와 같은 내용이다. 한쪽을 고치면 다른 쪽도 같은 커밋에서 고친다.

- 소유: `apps/server/src/security/rateLimit.ts`는 T3-04가 만들고 T3-04만 고친다. T3-02는 import만 하고 계수기를 복제하지 않는다.
- 선행: T3-02의 선행은 T3-01과 T3-04다. T3-04는 T3-02에 의존하지 않는다 (T3-04 선행은 M2).
- 인계: T3-04가 리뷰를 통과해 main에 병합된 커밋 SHA를 T3-02 구현 기록 첫 줄에 적고 그 위에서 착수한다. 계약을 바꿔야 하면 T3-02가 파일을 직접 고치지 않고 대기열에 T3-04 담당 작업을 더한다.
- 공개형:

  ```ts
  export interface LimitRule { namespace: string; key: string; limit: number; windowMs: number }
  export interface RateLimitDecision { allowed: boolean; retryAfterSeconds: number }
  export function createRateLimiter(options: { now: () => number }): {
    check(rules: readonly LimitRule[]): RateLimitDecision;
    consume(rules: readonly LimitRule[]): RateLimitDecision;
  };
  ```

- 시계: `now()`는 epoch ms다. `check`·`consume`은 호출마다 `now()`를 한 번만 읽고 그 값으로 모든 규칙을 판정한다. `buildServer`가 서버의 `options.now`(없으면 `Date.now`)로 프로세스당 하나를 만들어 Context의 `rateLimiter`로 넘긴다. 시험은 같은 주입 시계로 요청 시각과 계수기 시각을 함께 움직인다.
- 버킷: `namespace`·`key`·`windowMs` 셋이 버킷 하나다. `windowMs`가 다르면 같은 namespace·key라도 따로 센다.
- 창: 고정 창이다. 창 번호는 `floor(now / windowMs)`이고 구간은 `[n × windowMs, (n + 1) × windowMs)` 반개구간이다. 경계 시각이 되면 바로 새 창(계수 0)이다. 하루 창은 epoch 기준이라 UTC 자정에 바뀐다. 지난 창의 버킷은 다음 호출 때 지운다.
- `check`: 규칙마다 현재 창 계수가 `limit` 이상이면 차단이다. 계수를 바꾸지 않는다.
- `consume`: 모든 규칙을 먼저 판정한다. 모두 허용일 때만 모든 버킷을 1씩 올린다. 하나라도 차단이면 어느 버킷도 올리지 않는다. 동기 함수이고 안에 `await`가 없어 판정과 증가 사이에 다른 요청이 끼지 않는다.
- `retryAfterSeconds`: 허용이면 0이다. 차단이면 차단된 규칙들의 (창 끝 시각 − now) ms 중 가장 큰 값을 `ceil(ms / 1000)`초로 준다.
- 입력: 빈 규칙 배열은 허용·0이다. `limit`·`windowMs`가 양의 정수가 아닌 규칙을 받으면 계수를 바꾸지 않고 예외를 던진다.
- 차단 응답: 부르는 쪽이 `ctx.reply.header('Retry-After', String(retryAfterSeconds))`를 달고 `TRPCError({ code: 'TOO_MANY_REQUESTS' })`를 던진다. `data.reason`은 `null`이다. 헤더 값은 `retryAfterSeconds` 정수 그대로다.
- 비밀: 키에 이메일·IP가 들어간다. 계수기와 부르는 쪽 모두 키·이메일·IP·웹훅 주소를 로그, 파일, DB, 오류 message에 쓰지 않는다. 계수는 메모리에만 있고 재시작하면 빈다.

| namespace | key | 규칙 | 쓰는 곳 | 거는 작업 |
| --------- | --- | ---- | ------- | --------- |
| `auth.login.ip` | IP | 15분에 30번 | `auth.login` 전체 | T3-04 |
| `auth.login.failure` | 정규화한 이메일 + IP | 15분에 5번 | `auth.login` 실패 | T3-04 |
| `auth.signup.ip` | IP | 1시간에 10번 | `auth.signup` | T3-04 |
| `mutation.user` | userId | 1분에 120번 | 로그인이 필요한 변경 API 전체 | T3-04 (T3-02의 새 변경 API도 같은 미들웨어를 쓴다) |
| `mail.verify.resend` | userId | 1분에 1번, 하루에 5번 (한 번의 `consume`에 두 규칙) | `account.resendVerification` | T3-02 |
| `mail.password.reset` | 정규화한 이메일 | 1시간에 3번 | `account.requestPasswordReset` | T3-02 |
| `account.token.ip` | IP | 15분에30번 | 공개 `account.verifyEmail`·`account.resetPassword`의 합산 소비 시도 | T3-02 |

이메일 정규화는 T1-10 가입·로그인과 같은 방식을 쓴다.

- 로그인 순서: `auth.login.ip`를 `consume`한다. 차단이면 429. 다음에 `auth.login.failure`를 `check`한다. 차단이면 비밀번호를 검사하지 않고 429. 그다음 인증을 시도한다. 실패하면 `auth.login.failure`를 `consume`하고 `UNAUTHORIZED`를 준다. 이 `consume`이 차단이어도 응답은 `UNAUTHORIZED` 그대로다. 성공은 실패 버킷을 지우지 않는다.
- 다시 보내기: 이미 인증된 계정이면 계수 없이 `{ ok: true }`. 아니면 `mail.verify.resend` 두 규칙을 한 번에 `consume`하고 차단이면 429와 `Retry-After`.
- 재설정 요청: 계정 유무와 관계없이 `mail.password.reset`을 `consume`한다. 차단이어도 상태 코드·본문이 같은 성공 응답을 주고 `Retry-After`도 달지 않는다. 메일만 보내지 않는다.

### 쿠키와 CSRF 결정

| 항목 | 결정 |
| ---- | ---- |
| 쿠키 | 지금 값 유지: `sid`, `HttpOnly`, `SameSite=Lax`, `Path=/`, 운영 `Secure`. 이 작업은 운영 설정에서 `Secure`가 빠지면 서버가 시작을 거부하게 한다 |
| Origin 검사 | `/trpc`의 변경 요청(POST)과 SSE 연결은 `Origin`이 `PUBLIC_ORIGIN`과 같아야 한다. `Origin`이 없으면 `Sec-Fetch-Site`가 `same-origin`일 때만 받는다. 둘 다 없으면 거부한다 |
| 본문 형식 | 변경 요청은 `Content-Type: application/json`만 받는다. 다른 형식은 415. 단순 폼 전송으로는 변경 API에 닿지 않는다 |
| CORS | 열지 않는다. 화면과 API는 같은 출처다 (T2-15 Caddy) |
| 보안 헤더 | 서버 응답에 `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY`. CSP와 HSTS는 Caddy 설정(T2-15 파일)에 두고 그 값은 이 계획의 채울 문서에 적는다 |

### 권한 대조 결정 (자동)

- API 목록은 코드에서 뽑는다. `appRouter._def.procedures`를 돌아 모든 절차 경로와 종류(query·mutation·subscription)를 얻는다. 사람이 손으로 적는 목록을 두지 않는다.
- 시험 쪽 목록은 `authzCase(path, category, fn)` 도우미로 만든다. `category`는 `success`, `unauthenticated`, `otherUser`, `sanctioned`, `invalidInput` 다섯 가지다. 도우미는 실행된 사례를 `apps/server/.authz/cases.json`(Git 제외)에 기록한다.
- `pnpm test:authz`가 통합 시험을 돌린 뒤 두 목록을 대조한다. 절차마다 다섯 가지가 모두 있어야 한다. 빠지면 경로와 빠진 종류를 출력하고 실패한다. skip된 사례는 없는 것으로 센다.
- 해당하지 않는 종류는 `apps/server/src/authz/exemptions.ts`에 경로·종류·이유를 적어야만 빠질 수 있다. 예: `health`의 `otherUser`, 무인증 공개 API(`lobby.worlds`, `legal.current`)의 `unauthenticated`는 실패가 아니라 공개 응답을 확인하는 사례로 대신한다. 면제 목록은 리뷰어가 줄마다 본다.
- 판정 기준: `unauthenticated`는 `UNAUTHORIZED`이거나 공개 응답에 남의 정보가 없음, `otherUser`는 `FORBIDDEN`·`NOT_FOUND`이고 DB 변경 없음, `sanctioned`는 거부되고 DB 변경 없음, `invalidInput`은 `BAD_REQUEST`이고 DB 변경 없음. DB 변경 없음은 시험 전후 해당 테이블 행 수와 `turnRevision`을 비교해 확인한다.
- 행위자는 세션에서만 정한다. 입력에 `userId`·`generalId`를 받는 절차는 그 값이 세션 사용자의 것인지 확인하는 `otherUser` 사례가 꼭 있어야 한다 (AGENTS.md §7).

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 계수기 계약 | 단위(주입한 시계): 창 끝 1ms 전 차단·경계 시각 허용, `check`는 계수 그대로, 규칙 둘 중 하나가 차단이면 `consume`이 어느 버킷도 올리지 않음, `retryAfterSeconds`는 차단된 창들의 남은 ms 최대값의 올림, 허용이면 0, 빈 규칙은 허용·0, `windowMs`만 다른 두 규칙은 따로 셈, 양의 정수가 아닌 `limit`·`windowMs`는 예외이고 계수 그대로 |
| 로그인 제한 | 통합: 같은 이메일·IP 실패 5번 뒤 6번째는 맞는 비밀번호도 거부, 창이 지나면(주입한 시계) 성공. 다른 IP는 영향 없음. 성공 로그인이 실패 계수를 지우지 않음. 같은 IP 31번째 로그인 요청은 429 |
| 가입 제한 | 통합: 같은 IP 11번째 가입 거부, `Retry-After`가 `retryAfterSeconds` 정수와 같음, 응답 `data.code = TOO_MANY_REQUESTS` |
| 쿠키 | 통합: 운영 설정 응답의 `Set-Cookie`에 `HttpOnly`, `Secure`, `SameSite=Lax`. `Secure` 없는 운영 설정은 시작 실패 |
| CSRF | 통합: 다른 `Origin`의 POST 거부, `Origin`·`Sec-Fetch-Site` 없는 POST 거부, `text/plain`·폼 형식 POST 415, 같은 출처 POST 성공. 거부된 요청은 DB를 바꾸지 않음 |
| 권한 대조 | `pnpm test:authz`: 이 작업 시점 API 목록의 모든 절차 × 다섯 종류 통과, 면제는 이유와 함께 출력. 뒤에 오는 T3-02는 자기 새 API에 같은 `authzCase`를 더하고 다시 통과시킨다 |
| 대조 도구 자체 | 단위: 절차를 하나 더한 가짜 라우터에서 대조가 실패하고 빠진 경로를 출력 |
| 헤더 | 통합: 응답에 위 보안 헤더 3개 |

### 상대 영역에 필요한 것

- 화면(Claude): `TOO_MANY_REQUESTS`를 받으면 `Retry-After`를 읽어 남은 시간을 보여 준다. 로그인·가입 화면의 이 처리는 T3-03 범위에 넣어 같이 만든다. 헤더는 tRPC 클라이언트 오류의 `meta.response.headers`에서 읽는다 ([T3-03](./T3-03.md)).
- T3-02(Codex): 이 작업이 리뷰를 통과해 main에 병합된 커밋 SHA를 넘긴다. T3-02는 그 SHA 위에서 착수하고 계수기를 복제하지 않는다.
- T2-15 `Caddyfile`의 CSP·HSTS 값은 이 작업의 채울 문서에 적은 값을 따른다. 파일 반영은 Codex가 같은 작업 안에서 한다 (같은 영역).

APT 구성은 이렇게 확인된다. 941행과 1029행의 `Get:1 file:/etc/apt/apt-mirrors.txt Mirrorlist [144 B]`로 보아 Ubuntu 저장소는 `mirror+file:` 미러 목록을 거쳤다. 실제 내려받은 호스트는 `http://azure.archive.ubuntu.com/ubuntu`다. `noble`, `noble-updates`, `noble-backports`, `noble-security` 네 suite가 모두 이 호스트에서 왔다. 미러 목록의 실제 내용은 증거에 없고 크기 144 B만 있다. 타사 저장소는 `https://packages.microsoft.com/ubuntu/24.04/prod`가 보인다.

runner-images의 `configure-apt.sh`는 관측 이미지 태그 `ubuntu24/20261012.334` 원문과 2026-10-23T19:42Z에 읽은 main 원문의 sha256이 `0857e4ce…7f48807`로 같다(`official-source-pin.json`). 그러니 두 원문 사이에 차이는 없다. 다음 이미지도 같다고 가정하지는 않는다. 이 스크립트는 x64에 `zz-retries`로 `Acquire::Retries "1"`과 http·https `Timeout "15"`를 쓰고 `99bad_proxy`에 `Pipeline-Depth 0`, `No-Cache true`, `BrokenProxy true`를 더한다. `ubuntu.sources`와 `apt-mirrors.txt`는 만들지 않고 `cat`으로 출력만 한다. 이번 계획은 이 apt 설정 파일을 하나도 바꾸지 않는다.

### 선택한 안

Playwright 설치 직전에 단계 하나를 더한다. 이 단계는 APT 구성이 관측한 모양인지 읽기만 해서 확인한다. 맞으면 `/etc/apt/apt-mirrors.txt`에서 `azure.archive.ubuntu.com` 줄 하나만 뺀다. 남는 줄은 원래 목록에 이미 있던 Ubuntu 공식 호스트(`archive.ubuntu.com`, `security.ubuntu.com`)뿐이어야 한다. 모양이 다르면 아무것도 쓰지 않고 실패로 멈춘다.

`ubuntu.sources`는 읽기만 하므로 Types, Suites, Components, Architectures, Signed-By가 구조적으로 보존된다. 보안 suite `noble-security`도 같은 stanza에 그대로 있다. 서명 검증은 같은 `Signed-By` keyring으로 같은 Ubuntu 서명 메타데이터를 대상으로 한다. 남는 줄의 scheme은 원래 값 그대로이므로 TLS를 쓰던 줄은 TLS를 계속 쓴다. 관측된 azure 줄은 http였고 http 줄의 보호는 지금과 같이 APT의 서명·해시 검증이다. `packages.microsoft.com` 같은 타사 저장소 파일과 keyring은 바꾸지 않는다. sed 일괄 치환이나 sources 전체 재작성은 하지 않는다. 미러 목록에서 검증한 한 줄을 정확히 빼고 diff로 한 줄 삭제, 추가 0줄을 확인한다.

`ubuntu.sources`의 `URIs`를 직접 고치는 방법보다 이쪽이 좁다. 관측 구성에는 이미 미러 목록이라는 간접 계층이 있어 sources 파일의 필드를 다시 쓸 이유가 없다. 이 변경으로 빨라진다는 근거는 없다. 같은 azure 호스트에서 인덱스는 10.0 MB/s였고 패키지는 34.0 kB/s였던 것도 관측 사실일 뿐이다. 구현 뒤 한 번의 CI로 결과를 기록할 뿐이며 그 결과가 느리거나 실패해도 그대로 남긴다.

### 검토하고 쓰지 않은 안

| 안 | 쓰지 않은 이유 |
| -- | -------------- |
| `ubuntu.sources`의 `URIs` 직접 수정 | 관측 구성에서는 미러 목록만으로 경로를 바꿀 수 있다. sources 필드 재작성은 Suites·Signed-By 보존을 따로 증명해야 해서 범위가 넓다 |
| 공식 Playwright 이미지 | 아래 문단. PostgreSQL 연결 주소, 사용자, 실행 환경이 바뀐다 |
| apt 아카이브·브라우저 캐시 | 캐시 적중을 보장할 근거가 없다. 공식 CI 문서는 브라우저 캐시가 OS 의존성을 대신하지 못한다고 한다 |
| apt-fast, 병렬 내려받기, `Acquire::Retries`·`Timeout`·`Queue-Mode` 조정 | 새 도구를 네트워크에서 받거나 APT timeout·재시도를 바꾼다. runner main 스크립트의 재시도·timeout 조절은 참고 사실이며 도입하지 않는다 |
| 설치를 `test:authz`와 겹쳐 실행 | `test:authz` → `db:migrate` → 설치 → E2E 순서를 지키지 못한다 |
| `--with-deps` 생략이나 일부 패키지 제외 | 시스템 의존성과 폰트를 그대로 유지해야 한다 |

공식 이미지 `mcr.microsoft.com/playwright:v1.64.1-noble`을 고른다면 태그 대신 정확한 `@sha256:` digest를 고정하고 그 이미지 안의 Playwright가 1.64.1이며 브라우저가 `chromium-1248`(Chrome for Testing 156.0.8078.4)인지 먼저 확인해야 착수할 수 있다. 확인한 뒤에도 동등성 문제가 남는다. job을 컨테이너로 돌리면 서비스 PostgreSQL은 컨테이너 네트워크의 서비스 이름으로 닿고 `DATABASE_URL`·`TEST_DATABASE_URL`의 `127.0.0.1:5432`로는 닿지 않는다. 환경값을 바꿔야 하므로 경계를 넘는다. 이미지 기본 사용자는 root라서 Chromium sandbox 동작과 checkout·pnpm 저장소 파일 소유자가 지금의 `runner` 사용자와 달라진다. 폰트와 `libnss3`·`libglib2.0`·`xvfb`는 이미지를 만든 시점 버전이라 이번 실행이 noble-updates에서 올린 버전과 다를 수 있다. 공유 메모리 크기도 Docker 기본값이 되어 `--ipc=host` 같은 옵션을 따로 정해야 한다. 이미지 pull은 job마다 추가 내려받기다. 그 크기는 이 증거에 없으므로 digest manifest의 layer 크기로 따로 재야 한다. 설치 단계도 컨테이너 안에서 `apt-get update`를 다시 하므로 설치 명령을 그대로 두면 인덱스 내려받기가 남는다. 실행기는 같은 `ubuntu-24.04`여도 시험이 도는 사용자 공간이 이미지의 것으로 바뀐다. 그래서 이번 범위에서는 쓰지 않는다.

### 인수 조건

| 무엇 | 기준 |
| ---- | ---- |
| 경로 변경 | 새 단계가 관측 구성을 확인하고 미러 목록에서 azure 줄 하나만 뺀다. 같은 job 설치 로그의 Ubuntu 저장소 Get·Hit·Ign 줄에 `azure.archive.ubuntu.com`이 없다 |
| 보존 | `ubuntu.sources`, Ubuntu keyring, `/etc/apt` 아래 다른 모든 파일의 sha256이 단계 전후로 같다. apt 설정에 서명·TLS 검증을 끄는 값이 없다 |
| 서명 | 설치 로그에 `NO_PUBKEY`, `is not signed`, `couldn't be verified`, `Hash Sum mismatch`, `insecure`, `unauthenticated` 경고·오류가 없고 설치가 성공한다 |
| 시험 범위 | `test:authz` 42파일 699개 통과, skip 0, `AUTHZ procedures=44 executed=200 exemptions=20 missing=0`. E2E `Running 150 tests using 1 worker`, 최종 요약이 `150 passed`뿐이다 |
| 시간 | database-browser job이 그대로인 20분 한도 안에서 success, check job이 15분 한도 안에서 success |
| 경계 | timeout·worker·명령·순서·의존성·Playwright 버전 변경 0 |

AC-M3-03의 상태와 T3-04 단계는 이 후속 때문에 바꾸지 않는다.

### 수정 파일과 하지 않는 것

| 파일 | 변경 |
| ---- | ---- |
| `.github/workflows/ci.yml` | database-browser job의 `pnpm db:migrate`와 설치 단계 사이에 단계 하나 추가. 다른 줄은 그대로 |
| `tools/ci/ubuntu-archive-path.sh` | 새 파일. 아래 검사·변경 스크립트 |
| `docs/plans/T3-04.md` | 이 절과 구현 기록·리뷰 |

`runs-on: ubuntu-24.04`, Node 24.22.0, pnpm 10.33.0, `package.json`, `pnpm-lock.yaml`(Playwright 1.64.1), `playwright.config.ts`는 그대로다. job 20분·check 15분 한도, 웹 서버 60초 timeout, 시험 timeout, APT `Retries`·`Timeout`, `--workers=1`, `--reporter=line`도 그대로 두고 단계별 `timeout-minutes`를 새로 달지 않는다. `pnpm test:authz` → `pnpm db:migrate` → `pnpm exec playwright install --with-deps chromium` → `pnpm e2e --workers=1 --reporter=line`의 명령과 순서는 글자 하나 바꾸지 않는다. skip·재시도·분할·시험 선별·판정·권한·폰트·시스템 의존성은 손대지 않는다. 699개와 150개는 지금 baseline이며 줄이거나 숨겨 고르지 않는다. 유료 실행기, 캐시, 수동 rerun은 쓰지 않는다. 보호 대상 SQL 18개와 기존 migration, 기존 실패 원문, 통합 root는 건드리지 않는다. 이 계획 단계에서는 CI 수정·commit·push를 하지 않는다.

### 구현

CI 단계는 이렇게 더한다. 다른 줄은 바꾸지 않는다.

```yaml
      - run: pnpm db:migrate
      - name: Use official Ubuntu archive path
        run: sudo bash tools/ci/ubuntu-archive-path.sh /
      - run: pnpm exec playwright install --with-deps chromium
      - run: pnpm e2e --workers=1 --reporter=line
```

설치 직전에 두는 이유가 있다. 검사가 멈춰도 `test:authz` 699개와 migration 결과는 이미 남는다. 설치 앞에서 멈추므로 바뀐 경로 없이 설치하는 일도 없다. 스크립트는 네트워크를 쓰지 않고 `apt-get update`도 부르지 않는다. 인덱스와 패키지는 기존 설치 명령이 지금처럼 받는다.

```bash
#!/usr/bin/env bash
# T3-04 CI 설치 경로 후속. Ubuntu 공식 저장소 미러 목록에서 azure 미러 한 줄만 뺀다.
# 예상한 구성이 아니면 아무것도 쓰지 않고 종료 코드 1로 멈춘다. 첫 인수는 검사할 루트다(CI는 /).
set -euo pipefail

root=${1:?usage: ubuntu-archive-path.sh ROOT}
root=${root%/}
etc="$root/etc/apt"
src="$etc/sources.list.d/ubuntu.sources"
list="$etc/apt-mirrors.txt"
keyring=/usr/share/keyrings/ubuntu-archive-keyring.gpg
work=$(mktemp -d)
# 실제 실행기(루트 /)는 언제나 apt-config를 쓴다. 시험 자료 루트에서만 같은 출력을 내는 대역 경로를 받는다.
if [ -z "$root" ]; then
  apt_config=apt-config
else
  apt_config=${FIXTURE_APT_CONFIG:?fixture root needs FIXTURE_APT_CONFIG}
fi
# grep 상태는 셋으로 나눈다. 0은 일치, 1은 불일치, 2 이상은 읽기·검사 실패라서 쓰기 전에 멈춘다.
# 불일치가 통과인 검사는 파이프와 grep -q, || true로 상태를 섞지 않고 출력을 파일로 받은 뒤 상태를 직접 본다.
# azure 미러 줄은 아래 두 awk에서 같은 정규식 리터럴 /^http:\/\/azure\.archive\.ubuntu\.com\/ubuntu\/?$/로 찾는다.
# awk -v로 넘기면 역슬래시가 풀려 \.이 아무 문자에나 맞을 수 있어서 리터럴로 둔다.

stop() { echo "APT_PATH_STOP $*" >&2; exit 1; }
snapshot() {
  find "$etc" "$root/usr/share/keyrings" -type f ! -path "$list" -print0 | sort -z | xargs -0 -r sha256sum
}

# 운영체제와 파일
grep -qx 'VERSION_ID="24.04"' "$root/etc/os-release" || stop os-version
grep -qx 'VERSION_CODENAME=noble' "$root/etc/os-release" || stop os-codename
for f in "$src" "$list" "$root$keyring"; do
  [ -f "$f" ] && [ ! -L "$f" ] || stop "file $f"
done

# 한 줄 형식 sources와 다른 파일의 Ubuntu 저장소는 예상 밖이다
if [ -e "$etc/sources.list" ]; then
  status=0
  grep -E '^[[:space:]]*deb(-src)?[[:space:]]' "$etc/sources.list" > "$work/legacy" || status=$?
  case $status in
    0) cat "$work/legacy" >&2; stop legacy-sources.list ;;
    1) ;;
    *) stop "sources.list-read status=$status" ;;
  esac
fi
status=0
grep -rlE '(azure\.archive|archive|security|ports)\.ubuntu\.com|apt-mirrors\.txt' "$etc/sources.list.d" > "$work/ubuntu-files" || status=$?
case $status in
  0) ;;
  1) stop ubuntu.sources-not-matched ;;
  *) stop "sources.list.d-read status=$status" ;;
esac
status=0
grep -xF "$src" "$work/ubuntu-files" > /dev/null || status=$?
case $status in
  0) ;;
  1) stop ubuntu.sources-not-matched ;;
  *) stop "ubuntu-files-read status=$status" ;;
esac
status=0
grep -vxF "$src" "$work/ubuntu-files" > "$work/other-files" || status=$?
case $status in
  0) cat "$work/other-files" >&2; stop other-ubuntu-source ;;
  1) ;;
  *) stop "ubuntu-files-read status=$status" ;;
esac

# deb822 ubuntu.sources: 모든 stanza가 미러 목록과 Ubuntu keyring을 쓴다
sources=$(awk -v uri="mirror+file:/etc/apt/apt-mirrors.txt" -v keyring="$keyring" '
  function fail(r) { print "STOP " r; failed = 1; exit }
  function within(value, set,   n, a, i) {
    n = split(value, a, /[[:space:]]+/)
    for (i = 1; i <= n; i++) if (!(a[i] in set)) return 0
    return n > 0
  }
  BEGIN {
    RS = ""; FS = "\n"
    n = split("Types URIs Suites Components Signed-By Architectures Enabled", a, " "); for (i = 1; i <= n; i++) F[a[i]]
    n = split("deb deb-src", a, " "); for (i = 1; i <= n; i++) T[a[i]]
    n = split("noble noble-updates noble-backports noble-security", a, " "); for (i = 1; i <= n; i++) S[a[i]]
    n = split("main restricted universe multiverse", a, " "); for (i = 1; i <= n; i++) C[a[i]]
    n = split("amd64 i386", a, " "); for (i = 1; i <= n; i++) A[a[i]]
  }
  {
    split("", v); count = 0
    for (i = 1; i <= NF; i++) {
      line = $i
      if (line ~ /^#/) continue
      if (line ~ /^[[:space:]]/) fail("continuation-line")
      p = index(line, ":"); if (p < 2) fail("syntax")
      name = substr(line, 1, p - 1); value = substr(line, p + 1)
      gsub(/^[[:space:]]+|[[:space:]]+$/, "", value)
      if (!(name in F)) fail("field " name)
      if (name in v) fail("duplicate " name)
      v[name] = value; count++
    }
    if (count == 0) next
    stanzas++
    if (("Enabled" in v) && v["Enabled"] != "yes") fail("enabled " v["Enabled"])
    if (v["URIs"] != uri) fail("uris " v["URIs"])
    if (v["Signed-By"] != keyring) fail("signed-by " v["Signed-By"])
    if (!within(v["Types"], T)) fail("types " v["Types"])
    if (!within(v["Suites"], S)) fail("suites " v["Suites"])
    if (!within(v["Components"], C)) fail("components " v["Components"])
    if (("Architectures" in v) && !within(v["Architectures"], A)) fail("architectures " v["Architectures"])
    if (v["Types"] ~ /(^|[[:space:]])deb($|[[:space:]])/) {
      n = split(v["Suites"], a, /[[:space:]]+/); for (i = 1; i <= n; i++) seenS[a[i]]
      n = split(v["Components"], a, /[[:space:]]+/); for (i = 1; i <= n; i++) seenC[a[i]]
    }
    print "STANZA Types=" v["Types"] " Suites=" v["Suites"] " Components=" v["Components"] \
      " Architectures=" (("Architectures" in v) ? v["Architectures"] : "-") " Signed-By=" v["Signed-By"]
  }
  END {
    if (failed) exit
    if (!stanzas) { print "STOP no-stanza"; exit }
    for (s in S) if (!(s in seenS)) { print "STOP missing-suite " s; exit }
    n = split("main restricted universe", a, " ")
    for (i = 1; i <= n; i++) if (!(a[i] in seenC)) { print "STOP missing-component " a[i]; exit }
    print "SOURCES_OK"
  }
' "$src")
printf '%s\n' "$sources" | sed 's/^/APT_PATH_/'
[ "$(printf '%s\n' "$sources" | tail -n 1)" = SOURCES_OK ] || stop ubuntu.sources

# 미러 목록: azure http 한 줄과 Ubuntu 공식 호스트 한 줄 이상, 태그는 priority만
mirrors=$(awk '
  BEGIN { FS = "\t" }
  /^[[:space:]]*(#|$)/ { next }
  {
    for (i = 2; i <= NF; i++) if ($i !~ /^priority:[0-9]+$/) { print "STOP tag " $i; failed = 1; exit }
    if ($1 ~ /^http:\/\/azure\.archive\.ubuntu\.com\/ubuntu\/?$/) { found++; next }
    if ($1 !~ /^https?:\/\/(archive|security)\.ubuntu\.com\/ubuntu\/?$/) { print "STOP host " $1; failed = 1; exit }
    official++
  }
  END {
    if (failed) exit
    if (found != 1) { print "STOP azure-lines " found + 0; exit }
    if (official < 1) { print "STOP no-official-mirror"; exit }
    print "OK"
  }
' "$list")
[ "$mirrors" = OK ] || stop "apt-mirrors.txt $mirrors"

# 아키텍처는 실제 실행기에서만 본다
if [ -z "$root" ]; then
  [ "$(dpkg --print-architecture)" = amd64 ] || stop arch
fi

# 서명·TLS 검증을 끄는 apt 설정. 출력 명령의 성공과 비어 있지 않은 전체 출력을 먼저 요구한다
status=0
"$apt_config" dump > "$work/apt-config.dump" 2> "$work/apt-config.err" || status=$?
if [ "$status" -ne 0 ]; then
  cat "$work/apt-config.err" >&2
  stop "apt-config-dump status=$status"
fi
[ -s "$work/apt-config.dump" ] || stop apt-config-dump-empty
status=0
grep -Ei 'Verify-(Peer|Host) "(false|no|0|off)"|Allow(Insecure|Weak|DowngradeToInsecure)Repositories "(true|yes|1|on)"|AllowUnauthenticated "(true|yes|1|on)"|Trusted "(true|yes|1|on)"' \
  "$work/apt-config.dump" > "$work/apt-config.unsafe" || status=$?
case $status in
  0) cat "$work/apt-config.unsafe" >&2; stop insecure-apt-config ;;
  1) ;;
  *) stop "apt-config-check status=$status" ;;
esac
# Retries·Timeout은 바꾸지 않고 같은 출력에서 기록만 한다. 없으면 apt 기본값이다
status=0
grep -E '^Acquire::(Retries|https?::Timeout) ' "$work/apt-config.dump" > "$work/apt-config.acquire" || status=$?
case $status in
  0) sed 's/^/APT_PATH_ACQUIRE /' "$work/apt-config.acquire" ;;
  1) echo 'APT_PATH_ACQUIRE default' ;;
  *) stop "apt-config-acquire status=$status" ;;
esac

# 쓰기: azure 줄 하나만 뺀 목록을 같은 파일(소유자·권한 유지)에 쓴다
cp "$list" "$work/before"
awk 'BEGIN { FS = "\t" } !($1 ~ /^http:\/\/azure\.archive\.ubuntu\.com\/ubuntu\/?$/)' "$list" > "$work/after"
status=0
diff "$work/before" "$work/after" > "$work/mirrors.diff" || status=$?
[ "$status" -eq 1 ] || stop "diff status=$status"
removed=$(awk '/^< / { n++ } END { print n + 0 }' "$work/mirrors.diff")
added=$(awk '/^> / { n++ } END { print n + 0 }' "$work/mirrors.diff")
[ "$removed" = 1 ] && [ "$added" = 0 ] || stop "diff removed=$removed added=$added"
snapshot > "$work/snapshot.before"
tee "$list" < "$work/after" > /dev/null
cmp -s "$list" "$work/after" || stop write
snapshot > "$work/snapshot.after"
cmp -s "$work/snapshot.before" "$work/snapshot.after" || stop other-apt-files-changed

echo APT_PATH_SNAPSHOT; cat "$work/snapshot.after"
echo APT_PATH_MIRRORS_BEFORE; cat "$work/before"
echo APT_PATH_MIRRORS_AFTER; cat "$list"
echo APT_PATH_OK
```

새 단계의 출력은 `APT_PATH_STANZA`, `APT_PATH_SOURCES_OK`, `APT_PATH_ACQUIRE`, `APT_PATH_SNAPSHOT`, `APT_PATH_MIRRORS_BEFORE`·`AFTER`, `APT_PATH_OK` 순서다. 스크립트는 `bash -n`과 아래 시험 자료로 확인한 뒤 올린다. `prettier --check`와 `lint:text`의 대상 밖인 `.sh` 파일이라 check job 수치에 영향을 주지 않을 것으로 본다. 영향이 있으면 구현 기록에 원인을 적는다.

### 멈추는 조건

멈추면 표준 오류에 `APT_PATH_STOP <이유>`를 쓰고 종료 코드 1로 끝난다. 쓰기 전 검사에서 멈추면 어떤 파일도 바뀌지 않는다. 뒤 단계인 설치와 E2E는 실행되지 않는다.

| 구성 | 판별 | 처리 |
| ---- | ---- | ---- |
| deb822와 `mirror+file` (관측 구성) | `ubuntu.sources`의 모든 stanza `URIs`가 `mirror+file:/etc/apt/apt-mirrors.txt`, 목록에 azure http 한 줄과 공식 호스트 한 줄 이상 | 진행 |
| deb822와 직접 주소 | `URIs`가 `http://azure.archive.ubuntu.com/ubuntu/` 같은 주소 | `uris`로 멈춤 |
| 한 줄 형식 | `/etc/apt/sources.list`에 주석 아닌 `deb` 줄 | `legacy-sources.list`로 멈춤 |
| `sources.list` 읽기 실패 | 파일은 있는데 grep 상태가 2 이상 | `sources.list-read`로 멈춤 |
| 다른 파일의 Ubuntu 저장소 | `sources.list.d`의 다른 파일에 Ubuntu 호스트나 미러 목록 | `other-ubuntu-source`로 멈춤 |
| `sources.list.d` 검색 실패 | 재귀 grep 상태가 2 이상(일부 파일만 읽은 경우 포함), 또는 `ubuntu.sources`가 검색 결과에 없음 | `sources.list.d-read`·`ubuntu-files-read`·`ubuntu.sources-not-matched`로 멈춤 |
| 미러 목록 이상 | azure 줄이 0개·2개 이상, 공식 호스트 0개, 다른 호스트, priority 아닌 태그 | `apt-mirrors.txt`로 멈춤 |
| sources 이상 | 모르는 필드, 이어진 줄, 인라인 키, 다른 keyring, `Enabled` 값 이상, 범위 밖 suite·component·architecture, 네 suite나 main·restricted·universe 누락 | 해당 이유로 멈춤 |
| apt 검증 해제 | `apt-config dump` 전체 출력에서 `Trusted`, `Allow*Repositories`, `AllowUnauthenticated`, `Verify-Peer`·`Verify-Host` 끔이 일치(grep 상태 0) | `insecure-apt-config`로 멈춤 |
| apt 설정 읽기 실패 | `apt-config dump`의 종료 코드가 0이 아님, 출력이 빔, 출력 검사 grep 상태가 2 이상 | `apt-config-dump`·`apt-config-dump-empty`·`apt-config-check`·`apt-config-acquire`로 멈춤 |
| 기타 | 24.04·noble·amd64 아님, 파일 없음·심볼릭 링크, 미러 목록 diff 상태가 1이 아님, 쓰기 불일치, 다른 apt 파일 해시 변화 | 해당 이유로 멈춤 |

grep 상태 0은 일치, 1은 불일치로만 읽고 2 이상은 언제나 검사 실패로 멈춘다. 불일치가 통과인 검사(apt 위험 설정, 한 줄 형식, 다른 Ubuntu 저장소 파일)는 파이프, `grep -q`, `|| true`를 쓰지 않고 출력을 파일로 받는다. 위 읽기 실패는 모두 쓰기 전에 걸리므로 미러 목록은 바뀌지 않는다. `os-release`의 `grep -qx`처럼 일치해야만 통과인 검사는 파이프 없이 파일을 직접 읽고 0이 아닌 상태가 모두 멈춤이라 따로 나누지 않는다. 그 밖의 명령이 실패하면 `set -e`로 0이 아닌 코드로 끝난다. 이 검사들은 기존 `sudo bash` 한 번 외에 새 timeout·재시도, 추가 권한, 서명·TLS 완화를 더하지 않는다.

직접 주소나 한 줄 형식은 고쳐 쓰지 않고 멈춘다. 그 구성을 바꾸려면 sources 필드를 다시 써야 해서 이 계획 범위를 넘는다. 이미지가 바뀌어 멈추면 그 실행을 실패로 남기고 계획 담당에게 돌린다.

### 검증 시나리오

구현자는 올리기 전에 임시 디렉터리를 루트로 주고 시험 자료로 한 번씩 실행한다. 시험 자료의 미러 목록 세 줄(azure http, archive https, security https와 각 `priority` 태그)은 가정한 모양이다. 관측 증거는 크기 144 B뿐이므로 이 모양을 실제 구성으로 세지 않는다. 시험 자료 실행은 아키텍처 검사를 건너뛰고 `apt-config` 대신 `FIXTURE_APT_CONFIG`로 준 대역 스크립트를 쓴다. 대역은 정해 둔 dump 파일을 출력하거나 정해 둔 코드로 끝나기만 한다. 그래서 시험 자료 결과는 CI 증거가 아니다. CI는 루트 `/`라서 이 변수를 읽지 않는다. 읽기 실패 시나리오는 일반 사용자로 실행해 권한 0의 파일이나 디렉터리를 만들어 재현한다. 결과와 로그는 저장소 밖에 두고 커밋하지 않는다. 지금은 어떤 시나리오도 실행하지 않았다.

| 시나리오 | 기대 |
| -------- | ---- |
| 관측 모양 sources와 세 줄 목록, 안전한 dump(검증 해제 키 없음, `Acquire::Retries "1";`과 Timeout 줄 포함) | `APT_PATH_OK`, `APT_PATH_ACQUIRE` 세 줄이 dump 값 그대로, azure 줄만 빠지고 나머지 두 줄과 순서·태그 그대로, sources·keyring 해시 불변 |
| 안전한 dump에 Acquire 줄이 없음 | `APT_PATH_ACQUIRE default`, 진행 |
| 대역이 dump를 낸 뒤 종료 코드 100 | `apt-config-dump status=100`으로 멈춤, 목록 불변 |
| 대역이 코드 0으로 빈 출력 | `apt-config-dump-empty`로 멈춤, 목록 불변 |
| dump에 `Acquire::https::Verify-Peer "false";` | `insecure-apt-config`로 멈춤, 걸린 줄 출력, 목록 불변 |
| dump에 `Acquire::AllowInsecureRepositories "true";`, `APT::Get::AllowUnauthenticated "1";` | 각각 `insecure-apt-config`로 멈춤, 목록 불변 |
| dump에 `Acquire::https::Verify-Peer "true";`, `Acquire::AllowInsecureRepositories "false";`만 있음 | 일치 없음(상태 1)으로 진행 |
| `sources.list`를 권한 0 파일이나 디렉터리로 | `sources.list-read status=2`로 멈춤, 목록 불변 |
| 주석만 있는 `sources.list` | 불일치(상태 1)로 진행 |
| `sources.list.d` 안에 권한 0 파일 하나 추가 | `sources.list.d-read status=2`로 멈춤, 목록 불변 |
| `ubuntu.sources`에 Ubuntu 호스트·미러 목록 문자열이 없음 | `ubuntu.sources-not-matched`로 멈춤 |
| sources의 `URIs`를 azure 직접 주소로 | `uris`로 멈춤, 목록 불변 |
| 주석 아닌 `deb` 줄이 있는 `sources.list` | `legacy-sources.list`로 멈춤 |
| `Trusted: yes` 필드 추가 | `field Trusted`로 멈춤 |
| `Signed-By` 다른 경로나 인라인 키 | `signed-by`나 `continuation-line`으로 멈춤 |
| suite에 `noble-proposed` 추가, `noble-security` 삭제 | 각각 `suites`, `missing-suite`로 멈춤 |
| 목록에 다른 호스트, azure 두 줄, azure만 한 줄 | `host`, `azure-lines 2`, `no-official-mirror`로 멈춤 |
| `sources.list.d`에 다른 Ubuntu 저장소 파일 | `other-ubuntu-source`로 멈춤 |
| 타사 저장소 파일만 추가 | 진행, 그 파일 해시 불변 |

CI는 구현 허가 뒤 정상 push 한 번만 본다. 같은 commit으로 PR 실행이 함께 생기면 기록하되 push 실행을 대신하지 않는다.

### 한계

- 효과는 검증하지 않았다. 호스트를 바꿔도 빠르다는 근거는 없고 한 번의 실행은 표본 하나다. 빠르게 끝나도 안정적인 개선으로 세지 않는다.
- 미러 목록의 실제 내용을 모른다. 첫 실행에서 검사가 멈출 수 있고 그 경우 경로 변경 효과는 관측되지 않는다.
- azure 줄을 빼면 남은 공식 호스트만 후보가 된다. Retries 1·Timeout 15를 바꾸지 않으므로 그 호스트들이 응답하지 않으면 설치가 실패한다.
- `noble-security`도 남은 호스트에서 받는다. 호스트마다 게시 시점이 다를 수 있다. 서명 검증은 무결성을 지키지만 가장 최신인지는 보장하지 않는다.
- 호스트가 바뀌면 인덱스 내려받기 양이 관측한 12.5 MB와 다를 수 있다. `Fetched` 줄로 기록만 한다.
- E2E 150개 전체 소요는 관측되지 않았다. 관측 실행에서는 설치 앞까지 약 7분이 걸렸다. 설치가 줄어도 E2E가 남은 시간을 넘으면 20분 한도에서 실패하며 이 계획은 그것을 풀지 않는다.
- 같은 commit의 push 실행 40008855794도 database-browser가 취소됐지만 로그는 읽지 않았다. 그 실행의 원인은 이 계획에 쓰지 않는다.
- AC-M3-03, T3-04 단계, M1·M2·M3 관문은 바꾸지 않는다.

### CI 설치 경로 구현 기록 (Codex, 2026-10-24)

부모가 채택한 계획 `4d8f5afb64f2d1c0784397b27255b2fad95e6b7b83c92417adf9da15af05f9bd`를 별도 작업 트리의 기준 `3290630bee128c5f4e05378cba88a87d2ebaf004` 위에 구현한다. 수정 범위는 workflow의 설치 직전 한 단계, `tools/ci/ubuntu-archive-path.sh`, 이 문서뿐이다. 검사 결과는 아래에 적었고 반대쪽 리뷰를 기다린다. 실제 CI, APT 설치, E2E, PG는 실행하지 않았고 효과는 미검증이다. 기존 150개 E2E 미완료와 20분 제한 초과 기록을 유지한다.

계획의 삭제 1줄·추가 0줄 조건을 유지하면서 셸 도구의 출력과 필드 해석 세 곳을 다뤘다. AWK 단락 끝의 빈 필드는 건너뛰고 diff는 `-U 0`으로 형식을 명시했다. 추가 줄의 접두사는 `[+]`로 검사한다. 조건이나 허용 호스트는 넓히지 않았다.

- 최종 fixture: Windows Git Bash 21개 통과. Windows 권한 시험 2개는 실행하지 않았다. 기존 Alpine 이미지의 Linux BusyBox ash에서는 UID 1001로 23개 모두 통과했고 읽기 권한 오류 두 건도 실제 chmod 0으로 확인했다. 이 두 실행은 같은 사례가 겹치므로 44개 단위 시험으로 합산하지 않는다. 실제 Ubuntu Bash·APT·서명·다운로드·설치나 실제 CI를 검증한 증거가 아니다.
- 실패 보존: 첫 Linux 실행은 AWK의 마지막 빈 필드 때문에 7개 통과·16개 실패였다. 빈 필드 처리 뒤 14개 통과·9개 실패는 시험용 tmpfs의 noexec 때문에 대역을 실행하지 못한 결과였다. 시험 전용 tmpfs의 실행을 허용한 뒤 19개 통과·4개 실패는 BusyBox diff의 기본 출력 형식 차이였고 diff 형식을 고정한 뒤에도 19개 통과·4개 실패가 남았고 추가 접두사 정규식 해석 차이로 `added=3`이 기록됐다. 추가 접두사 정규식을 `[+]`로 명시한 최종 코드에서 23개를 통과했다. 앞선 원문을 덮어쓰지 않았다.
