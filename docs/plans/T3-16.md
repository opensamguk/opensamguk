# T3-16 태수·군사 임명과 도시 주재 화면

> 대기열: T3-16 · AC: AC-M3-12 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T3-09, T2-06, T1-16 · 관련: [T3-09 관직 주재 효과](./T3-09.md), [T2-05 직책·인사](./T2-05.md), [T2-06 인사 화면](./T2-06.md), [T1-16 핵심 화면](./T1-16.md), [T3-10 반응형](./T3-10.md), [UI 지침](../frontend-ui-guidelines.md), [차별화 D17](../product/differentiation.md#d17-관직-주재-효과)

## 계획 (Claude)

### 목표

- 군주가 인사부에서 자기 나라 장수를 자기 나라 도시의 태수나 군사로 임명한다. 권한이나 자격이 모자라면 그 이유를 본다.
- 도시 정보에서 그 도시의 태수·군사가 누구인지, 지금 그 도시에 머무는지 본다. 관직자가 다른 도시로 옮기면 주재 표시만 바뀌고 관직은 그대로다.

AC-M3-12의 판정 근거는 T3-09의 골든 테스트다. 이 작업은 같은 AC의 화면 몫을 E2E로 더한다. 인수조건 문서의 AC 상태는 T3-09와 이 작업의 리뷰가 모두 끝난 뒤에만 통과로 바꾼다.

### 착수 조건

M1·M2·M3는 모두 Phase 1이다. 이 작업은 M2 관문이 끝나고 선행 T3-09·T2-06·T1-16이 `완료`된 뒤에 시작한다. 계획 검토, 선행 완료, AC 판정은 서로 다른 관문이다. 이 계획이 PR로 합쳐져도 착수 허가나 AC 통과가 아니다.

T3-09는 D17 U1~U3가 결정 기록에 오른 뒤에만 완료되므로 이 작업도 그 뒤에 시작한다. 화면과 가이드에 적을 효과 값은 T3-09 구현 기록에 남은 실제 표만 쓴다. 이 계획은 U1~U3, T3-07의 사용자 검토 항목, 승인 대기 중인 핵심 규칙 변경 10건 어느 것도 정하지 않는다.

### 담당과 수정 범위

| 담당 | 에이전트 | 고치는 곳 |
| ---- | -------- | --------- |
| 구현 | opensamguk-frontend-implement (Claude) | `apps/web/src/office/`(새로: 직책·도시 고르기 칸, 거절 문구, 주재 표시), T2-06이 만든 인사부 화면 파일(`/w/:worldId/nation/personnel`)에 칸 하나, T1-16이 만든 도시 정보 화면 파일(`/w/:worldId/city/:cityKey`)에 칸 하나, `e2e/office.spec.ts`(새로), 채울 문서 |
| 리뷰 | opensamguk-frontend-review (Codex) | 화면 E2E와 API·DB 확인, 문구, 채울 문서 |

서버·규칙·엔진·Prisma schema·migration은 고치지 않는다. API 타입은 `apps/server`의 `AppRouter`에서 `inferRouterInputs`·`inferRouterOutputs`로만 가져온다.

### 하지 않는 것

- 새 API, 새 필드, 새 권한 판정. 화면에 필요한 값이 계약에 없으면 아래 화면 계약 절에 적은 대로 처리한다.
- 효과 수치 표시와 계산. 화면은 관직과 주재만 보여 준다. 정산에서 붙은 보정은 T3-09가 쓰는 장수 로그 한 줄로 보인다.
- 종사(`officerLevel` 2), 중앙 관직의 주재 표시, 지도 위 관직 표시.
- 로비, 기존 핵심 화면 6개, 국가 예턴의 구조 교체. 인사부 표와 도시 정보에 칸만 더한다.
- NPC 군주의 임명 (T3-09에서도 뺐다).
- 375px 전수 점검 (T3-10). 새로 만드는 부분은 처음부터 375px에서 가로 스크롤이 없고 누르는 대상이 44px 이상이게 만든다.

### 화면 계약

T3-09 계획의 `API와 화면에 줄 모양` 절을 그대로 쓴다.

```ts
personnel.appoint({ worldId, generalId, officerLevel, cityKey? })   // 3·4면 cityKey 필수, 그 밖에는 보내지 않음
personnel.officers({ worldId }) → [{ generalId, name, officerLevel, isHuman, cityKey,
                                      officerCityKey: number | null, resident: boolean }]
city.get({ worldId, cityKey }) → 기존 필드 + officers: [{ generalId, name, officerLevel, resident }]
```

- 행위자(군주)는 서버가 세션에서 정한다. 화면이 보내는 `generalId`는 임명 대상일 뿐이다.
- 임명 칸을 열지 잠글지는 T2-06이 쓰는 서버 권한 값(T2-05 최종 계약)으로 정한다. 태수·군사 고르기도 같은 값을 따른다.
- 자격은 화면이 다시 계산하지 않는다. 무력·지력 하한(`stat.chiefMin`), 같은 나라 장수, 자기 나라 도시 판정을 화면 코드에 옮겨 적지 않는다. T3-09 계획에는 제출 전에 자격을 알려 주는 필드가 없다. 그래서 착수할 때 최종 병합된 계약을 보고 둘 중 하나로 정한다.
  - 계약에 사전 검사 값이 있으면 그 값으로 칸을 잠그고 이유를 보여 준다.
  - 없으면 제출한 뒤 서버 거절의 코드로만 이유를 보여 준다. 제출 전 이유가 꼭 필요하다고 판단되면 화면에서 추측하지 않고 대기열에 Codex 작업 한 줄을 더한 뒤 사용자에게 알린다 (AGENTS.md §0).
- 임명은 엔진이 처리하는 즉시 행동이다 (`InputEvent(kind: 'personnel.appoint')`). 응답이 처리 결과인지 접수만인지, 거절이 tRPC 오류(`data.code`·`data.reason`)인지 결과 union인지는 T3-09 최종 병합 계약을 인계받은 뒤 고정한다. 착수 첫 단계에서 병합 SHA와 타입 위치를 구현 기록에 적는다. 어느 쪽이든 화면은 낙관적으로 바꾸지 않고 서버에서 다시 읽은 값만 그린다.

### 인사부의 태수·군사 임명

T2-06의 인사부 표에 담당 도시와 주재 칸을 더한다.

```text
인사부 · 조조군
┌ 이름   ┬ 직책 ┬ 담당 도시 ┬ 지금 도시     ┬ 공헌 ┬ 구분 ┐
│ 하후돈 │ 태수 │ 진류      │ 진류 · 주재   │ ...  │ 사람 │ [직책 바꾸기]
│ 순욱   │ 군사 │ 허창      │ 진류 · 부재   │ ...  │ NPC  │ [직책 바꾸기]
│ 조인   │ 장수 │           │ 복양          │ ...  │ NPC  │ [직책 바꾸기]
└────────┴──────┴───────────┴───────────────┴──────┴──────┘

조인의 직책  [태수 ▾]   담당 도시 [진류 ▾  지금 태수 하후돈]
진류 태수 하후돈은 일반 장수가 된다.
[임명] [취소]
```

- 직책 고르기에 T2-05 표의 직책과 함께 태수(4)·군사(3)를 더한다. 담당 도시 칸은 태수·군사를 고를 때만 나온다. 다른 직책으로 바꾸면 칸이 사라지고 `cityKey`를 보내지 않는다.
- 도시 목록은 기존 조회에서 얻는 자기 나라 도시다 (T1-16의 `nation.get` 소유 도시). 도시마다 그 자리의 지금 관직자 이름을 붙인다. 이름은 `personnel.officers`의 `officerCityKey`로 찾는다.
- 자리에 사람이 있으면 교체를 알리는 한 줄을 보여 준다. T3-09 규칙대로 이전 관직자는 일반 장수가 된다.
- 담당 도시를 고르기 전에는 `[임명]`이 잠긴다. 최종 판단은 서버다.
- 권한이 없는 장수(일반 장수·수뇌·참모)는 T2-06과 같은 `DisabledReason`을 본다 (`군주만 임명할 수 있습니다`). 점선 테두리로 두고 누르면 이유가 나온다 (UI 지침 §1).
- 거절 이유 문구 초안이다. 실제 코드 이름은 착수 때 T3-09 타입에서 가져오며 구현할 때 글쓰기 규칙으로 다시 본다.

  | 거절 | 화면 |
  | ---- | ---- |
  | 권한 없음 | `군주만 임명할 수 있습니다` |
  | 태수 무력 미달 | `무력이 모자라 태수가 될 수 없습니다` |
  | 군사 지력 미달 | `지력이 모자라 군사가 될 수 없습니다` |
  | 다른 나라 도시 | `우리 나라 도시가 아닙니다` |
  | 다른 나라 장수 | `우리 나라 장수가 아닙니다` |
  | 그 밖의 거절 | `임명하지 못했습니다`, 목록을 다시 불러온다 |

- 거절 코드를 문구로 바꾸는 함수는 계약에서 추론한 코드 타입을 받아 빠짐없이 분기한다. 서버에 코드가 늘면 타입 검사가 실패한다.
- 접수만 되고 처리 전인 경우가 계약에 있으면 `임명을 처리하는 중입니다`를 보여 주고 결과가 정해지면 지운다.
- T2-06의 해임으로 태수·군사를 풀 수도 있다. 해임 뒤 그 행은 장수로, 도시 정보의 자리는 빈칸으로 돌아간다.

### 도시 정보의 관직자

T1-16의 도시 정보에서 수치 아래, 주둔 장수 표 위에 관직 칸을 둔다.

```text
진류 · 조조군
관직
  태수   하후돈   주재
  군사   순욱     부재
```

- 자리가 비면 `태수 없음`, `군사 없음`이라고 쓴다.
- 주재와 부재는 글자로 쓰고 색은 보조로만 쓴다 (NFR-08).
- 관직 이름, 관직자 이름, 주재 여부는 T3-09가 공개로 정했다. 다른 나라 도시에서도 이 칸은 보인다. T1-16의 비공개 수치 `—` 처리는 그대로다.
- `city.get`의 관직자 항목에는 지금 위치가 없다. 부재일 때 어디 있는지는 적지 않는다.

### 갱신

- 임명·해임 결과가 정해지면 `personnel.officers`, 관련된 두 도시(새 담당 도시, 이전 담당 도시)의 `city.get`, 직책을 보여 주는 `home.get`을 무효화하고 다시 읽는다.
- 턴 실행으로 관직자가 움직였거나 점령으로 관직이 풀린 뒤에는 T2-10의 SSE 무효화 방식을 따른다. 맞는 알림이 없으면 화면에 다시 들어오거나 새로고침할 때 읽는다. 새 알림이나 시계 API를 만들지 않는다.

### 검증

E2E는 `e2e/office.spec.ts` 하나에 둔다. 고정 시드 월드와 이동·점령 준비는 기존 도우미(manual 시계 엔진 실행, 고정 시드 fixture)로 만든다. E2E를 위해 서버에 시계 조작 API를 열지 않는다. DB 확인은 E2E 쪽 읽기 전용 Prisma 조회로 한다. 그런 도우미가 착수 때 없으면 `e2e/` 안에 만든다. 임명 API의 권한 시험 전체는 T3-09의 통합 시험이 맡는다. 여기서는 같은 경우를 실제 브라우저 세션과 HTTP로 한 번 더 거친다.

| 무엇 | 어떻게 |
| ---- | ------ |
| 군주 임명 | E2E: 군주 계정 → 인사부 → 무력이 하한 이상인 장수에게 태수와 자기 나라 도시 → 임명 → 엔진 한 번 → 인사부 행에 태수·담당 도시·주재, 그 도시 정보의 관직 칸에 이름과 주재. DB: `officerLevel` 4, `officerCityKey` 그 도시, `personnel.appoint` InputEvent 한 행 |
| 군사와 교체 | E2E: 지력이 하한 이상인 장수를 군사로 임명. 이어서 같은 태수 자리에 다른 장수를 임명 → 교체 한 줄 → 이전 관직자는 장수, 도시 정보에 새 이름 |
| 일반 장수·수뇌 | E2E: 그 계정의 인사부에서 직책 칸이 잠기고 이유가 보임. 같은 세션의 `page.request`로 `personnel.appoint`를 직접 보냄 → `FORBIDDEN`, DB와 InputEvent 변화 없음 |
| 다른 나라 군주 | E2E: 다른 나라 군주 세션으로 우리 장수·우리 도시 임명을 직접 보냄 → `FORBIDDEN`, DB 변화 없음 |
| 무인증 | E2E: 쿠키 없는 요청 → `UNAUTHORIZED`. 인사부 주소로 가면 `/login?next=`로 감 (T1-14 가드) |
| 제재 | E2E: `User.status = SANCTIONED`인 계정의 세션 → 거부, InputEvent 없음, 화면은 로그인으로 감 |
| 잘못된 입력 | E2E: 화면에서 담당 도시 없이 `[임명]`을 누를 수 없음. 직접 보낸 요청(`cityKey` 없음, 다른 나라 도시, 무력 미달 태수, 지력 미달 군사, 다른 나라 장수, 3·4 밖 직책에 `cityKey`) → 각각 거절, DB 변화 없음. 화면으로 낼 수 있는 경우(무력·지력 미달)는 그 이유 문구가 보임 |
| 도시 이동 | E2E: 태수의 예턴에 다른 도시 이동 → 엔진 → 도시 정보와 인사부가 부재. DB의 `officerLevel` 4와 `officerCityKey`는 그대로. 다시 돌아오면 주재 |
| 점령 | E2E: 담당 도시가 점령되게 준비 → 엔진 → 인사부와 도시 정보에서 그 관직이 사라짐. DB `officerLevel` 1, `officerCityKey` null |
| 해임 | E2E: 태수 해임 → 인사부 행이 장수, 도시 정보에 `태수 없음` |
| 375px | Playwright 375px 뷰포트에서 새 칸(임명 칸, 관직 칸)에 가로 스크롤이 없고 누르는 대상이 44px 이상. T3-10의 `e2e/responsive-check.ts`가 main에 있으면 그것을 쓴다 |
| 스크린샷 | 인사부 임명 칸과 도시 정보 관직 칸을 데스크톱·375px로 저장하고 인수조건 증거 칸에 경로를 남긴다 |
| 기존 화면 보존 | T2-06·T1-16의 기존 E2E가 고치지 않고 통과. 기존 화면 문구는 이 작업에서 바꾸지 않는다 |
| 문구 | `pnpm lint:text` 0건. 반대쪽 리뷰가 문구도 본다 |
| 단위 | Vitest: 직책에 따른 도시 칸 보임과 `cityKey` 전송 여부, 교체 한 줄, 거절 코드별 문구, 주재·부재·빈 자리 표시 |
| 타입 | 타입 시험: 거절 문구 함수가 받는 코드 타입이 `AppRouter` 추론에서 옴 |
| 전체 | `pnpm check`, `pnpm e2e`. 무거운 시험은 GitHub의 기존 표준 실행기에서 돌린다 |
