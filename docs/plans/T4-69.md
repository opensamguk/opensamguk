### 3. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 3.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `return_border` | 접경귀환 | `military` | `general` | `noArgs` (`commands/support.ts:8`) |

범주는 기존 `return`(`military.ts:92`)과 같다. 장수 도시를 바꾸므로 `Effect`에 맞는 필드가 없다(`commands/effects.ts:7-11`). 기존 `return`처럼 `defineCommand`로 `{ kind: 'world' }` 효과를 낸다.

#### 3.2 탐색 함수

`nearestOwnCities(view, from, nationId, maxDistance = 3): number[]`

1. `visited = { from }`, `frontier = [from]`.
2. 거리 1부터 `maxDistance`까지 `frontier`의 각 도시에서 `connections`를 배열 순서대로 보고 처음 닿은 도시를 `next`에 더한다.
3. `next` 가운데 `nationId`가 같고 `supplied`인 도시를 고른다. 하나라도 있으면 `cityKey` 오름차순으로 정렬해 돌려준다.
4. 없으면 `frontier = next`로 다음 거리를 본다. 끝까지 없으면 빈 배열이다.

후보 정렬은 원작과 다르다. 원작은 지도 파일의 연결 배열 순서로 닿은 순서를 따른다. 우리 `connections`는 월드를 만들 때 이미 오름차순으로 정렬된다(`world/bootstrap.ts:173`). 그래도 후보 목록을 `cityKey`로 한 번 더 정렬해 탐색 순서와 상관없이 고르기 전 목록을 고정한다. 원작과 난수열 일치는 목표가 아니다(D-001).

#### 3.3 검사 순서와 실패

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | 장수 없음 | `NO_ACTOR` | 장수가 없습니다. (`defineCommand`) |
| 2 | 인자 형식 | `BAD_ARGS` | 명령 인자가 잘못되었습니다. (`defineCommand`) |
| 3 | 재야이거나 국가 없음 | `NOT_NATION` | 국가에 소속되어야 합니다. |
| 4 | 방랑 국가 (T4-48 표식) | `BAD_STATE` | 방랑 중인 국가는 접경귀환할 수 없습니다. |
| 5 | 현재 도시가 자기 국가 도시 | `BAD_STATE` | 이미 자기 국가 도시에 있습니다. |
| 6 | `nearestOwnCities`가 빈 배열 | `BAD_TARGET` | 3칸 안에 돌아갈 자기 국가 도시가 없습니다. |

6번은 원작에서 실행 단계 기록이다. 우리는 검사로 옮긴다. 탐색은 상태만 읽는 순수 계산이라 예약 화면의 사전 검사가 같은 이유를 미리 보일 수 있다. 결과의 차이는 실패가 실행 결과가 아니라 검사 실패로 남는 것 하나다. 이 선택은 쟁점 R1이다.

#### 3.4 실행과 RNG

- `rng.pick(후보)` 한 번. 후보가 하나여도 쓴다(`packages/shared/src/rng.ts:28-31`).
- `general.cityKey = 고른 도시`. 다른 값은 바꾸지 않는다.
- `logs`: `{도시} 접경귀환`.
