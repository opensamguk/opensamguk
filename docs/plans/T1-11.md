# T1-11 장수 생성·예턴 API

> 대기열: T1-11 · AC: AC-M1-06 ~ AC-M1-09 (API) · 구현: Codex · 리뷰: Claude
> 선행: T1-05, T1-10 · 다음: T1-15 장수 생성·예턴 편집 화면 (Claude)

## 계획 (Claude)

### 목표

- 이름·능력치·초상 ID로 장수를 만든다. 같은 월드에서 두 번째 생성과 능력치 규칙 위반은 거부된다 (AC-M1-06).
- 예턴 30칸 저장, 여러 칸 넣기·당기기·밀기, 빈칸은 휴식 (AC-M1-07).
- 오래된 revision의 저장은 거부되고 최신 목록을 돌려준다 (AC-M1-08).
- 넣을 때 사전 검사 경고, 실행 때 재검사 (AC-M1-09. 실행 쪽은 T1-06·T1-05에 이미 있음).

### 범위

- `apps/server/src/routers/general.ts`, `apps/server/src/routers/turns.ts`
- `packages/rules`의 `precheck`를 server에서 호출 (server → rules 의존은 허용)

### 하지 않는 것

기존 NPC 장수 맡기(D15 역할별 입장, M3), 국가 예턴 편집 화면(M2 직책), 실시간 갱신(M2).

### 결정

- **게임 상태(장수 생성)는 엔진이 만든다** (아키텍처: API는 게임 상태를 바꾸지 않음).
  `general.create`는 `InputEvent(kind: 'general.create', idempotencyKey)`를 기록하고, 엔진이 처리한 결과를 기다려 돌려준다
  (최대 5초 폴링, 넘으면 `pending` 상태 반환 → 화면이 `general.mine`으로 다시 조회).
- **예턴은 API가 직접 쓴다** (데이터 소유권 표). 저장 때 같은 트랜잭션으로 `InputEvent(kind: 'turns.set')`도 남긴다 (T1-07 재생용).
- 능력치 규칙: `resources/scenario/default.json`의 `stat` (합계 165, 각각 15~80).
- 생성 위치: 재야, 무작위 도시(엔진이 `rngFor(seed, 'create', userId)`로 선택).

### API 계약 (화면이 쓸 모양)

```ts
general.create({ worldId, name, leadership, strength, intel, portraitId | null })
  → { status: 'created', general } | { status: 'pending' }
general.mine({ worldId }) → { general | null }

turns.get({ worldId }) → { revision, slots: Slot[30] }            // Slot = { commandKey, args, name }
turns.set({ worldId, revision, slots: Slot[30] })
  → { ok: true, revision } | { ok: false, reason: 'STALE', revision, slots }
turns.edit({ worldId, revision, op })                             // op: { put: {from, to, commandKey, args} } | { shift: n } | { repeat: … }
  → turns.set과 같은 결과
turns.precheck({ worldId, commandKey, args }) → { ok: true } | { ok: false, code, message }
commands.list({ worldId }) → [{ key, name, category, argsSchema(JSON) }]
```

- 장수 ID는 세션 사용자와 월드로 서버가 찾는다. 요청에 장수 ID를 받지 않는다.
- revision은 저장마다 1 증가. 엔진이 턴을 실행해 예턴을 당길 때도 1 증가.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 생성 | API: 생성 → mine. 같은 월드 두 번째 → `CONFLICT`. 합계 166 → `BAD_REQUEST` |
| 예턴 | API: set → get 일치. put 범위 넣기, shift ±1, 빈칸 휴식 |
| 충돌 | API: revision 3으로 저장 성공 → 같은 3으로 다시 저장 → `STALE` + 최신 목록 |
| 엔진과 경합 | 통합: 엔진이 턴을 실행한 직후 이전 revision으로 저장 → `STALE` |
| 권한 | 무인증 `UNAUTHORIZED`, 다른 사람 월드 장수 접근 불가(애초에 ID를 안 받음), 잘못된 명령 key `BAD_REQUEST` |

### T1-10 리뷰에서 넘어온 것

- 세션 연장은 남은 기간이 기준(예: 15일) 이하일 때만 해서, 요청마다 DB 쓰기·Set-Cookie가 일어나지 않게 한다.
- 이 작업에서 처음 쓰는 `protectedProcedure`에 무인증 `UNAUTHORIZED` 테스트를 붙인다.

## 구현 기록 (Codex)

### 사전 준비 범위

이 기록은 AC-M1-06~09의 API·보안 시험 준비다. 구현 담당은 `opensamguk-fix`, 카드 `t_14598ef1`, 브랜치는 `wt/t_14598ef1`이다. 대조한 소스는 새 저장소 `peppone-choi/opensamguk`(repository ID `1426568182`)의 `e7dde33ff3b9b43b853824fac324dfef48591402`다. 이번 변경은 이 계획의 구현 기록에만 한정한다. API 구현, 실제 DB 시험, 화면 검증과 AC 통과는 아직 하지 않았다.

T1-07 카드 `t_65f25b0d`가 InputEvent schema·새 migration·월간 엔진을 맡는다. T1-07의 승인·병합 뒤 확정 DB 계약과 SHA를 대조하고 T1-11 구현을 시작한다. `phases.md`의 T1-11 단계와 AC 상태는 준비 문서만으로 올리지 않는다. `request-turn-persistence.md` §1·§2와 `code-map.md`도 실제 구현 때 채운다.

### AppRouter 공개 계약 대조

현재 `apps/server/src/router.ts`의 `appRouter`에는 `auth`와 `health`만 있다. `AppRouter = typeof appRouter`를 `@opensamguk/server/router`에서 내보내며 `apps/web/src/trpc.ts`는 이 타입만 import한다. 아래 T1-11 경로는 위 계획의 목표 계약이며 현재 호출할 수 있는 API가 아니다. 별도 프론트 DTO나 가짜 라우터를 만들지 않는다.

| 목표 경로 | 보존할 입력·반환 의미 | 구현 전 남은 확인 |
| ---- | ---- | ---- |
| `general.create` | `worldId`, 이름, 세 능력치, nullable `portraitId`를 받고 `created`와 general 또는 `pending`을 반환한다. API는 이벤트만 기록하고 엔진 결과를 최대 5초 기다린다. | general 반환 필드, 멱등 키의 전달·재사용 방법, 엔진 거절 결과의 API 변환을 확정 계약과 맞춘다. 계획의 입력 목록에는 멱등 키가 아직 없다. |
| `general.mine` | `worldId`로 세션 사용자의 장수를 찾아 `{ general }` 또는 `{ general: null }`을 반환한다. | general 반환 필드는 생성 결과와 맞춘다. 다른 사용자의 장수로 대체하지 않는다. |
| `turns.get` | `worldId`로 `{ revision, slots }`를 반환한다. slots는 30칸이며 표시용 `name`도 포함한다. | `name`은 rules 명령 정의에서 얻는다. 장수가 없을 때 오류 계약은 계획에 아직 없다. |
| `turns.set` | `worldId`, `revision`, 30칸을 받아 성공 시 새 revision, 충돌 시 `ok: false`, `reason: 'STALE'`, 최신 revision·slots를 반환한다. | 빈칸 표현과 정규화 위치를 정해야 한다. 클라이언트 `name`을 권한·명령 판단이나 재생의 근거로 쓰지 않는다. |
| `turns.edit` | `worldId`, `revision`, `op`를 받고 `turns.set`과 같은 결과를 반환한다. | 계획은 `put`, `shift`, `repeat`만 제시했다. 인덱스·범위 끝 포함 여부·repeat 구조·넘친 칸 처리 규칙은 계획 담당과 확정한 뒤 시험한다. |
| `turns.precheck` | `worldId`, `commandKey`, `args`로 `{ ok: true }` 또는 `{ ok: false, code, message }`를 반환한다. | registry 조회·args 파싱 뒤 소유 장수의 WorldView로 `precheck`를 호출한다. HTTP 입력 오류와 rules 경고를 구분한다. |
| `commands.list` | `worldId`로 `key`, `name`, `category`, JSON `argsSchema` 목록을 반환한다. | 현재 `CommandDef`에는 `category`가 없다. `target`을 임의로 category로 바꾸지 않는다. 노출 대상과 Zod → JSON 변환 방식도 확정해야 한다. |

T1-11 API는 인증을 거치며 장수는 `(worldId, ctx.user.id)`로 찾는다. 요청에 `generalId`나 `userId`를 추가하지 않는다. 구현 뒤에는 실제 AppRouter 타입으로 입력·반환을 대조하고 T1-15에 정확한 SHA를 넘긴다. `Slot`, general 반환 필드와 op 구조를 이 준비 작업에서 새로 정의하지 않는다.

### 후속 시험 목록

아래 항목은 실행 결과가 아닌 시험 명세다. HTTP 항목은 실제 AppRouter가 등록된 Fastify 어댑터와 전용 PostgreSQL로 실행한다. 응답 코드뿐 아니라 General·GeneralTurn·revision·입력 기록의 전후 상태도 대조한다. 아직 없는 API를 mock으로 통과시키지 않는다.

| 구분 | 입력·상황 | 기대 결과와 확인 대상 |
| ---- | ---- | ---- |
| 공통 인증 | 위 7개 경로 각각에 쿠키 없음, 잘못된 형식·위조·삭제·만료 세션으로 요청 | 유효한 입력을 사용해 보호 절차의 `UNAUTHORIZED`를 확인한다. 장수·예턴·입력 기록이 바뀌거나 타인 데이터가 응답에 섞이지 않는다. |
| 공통 제재 | 발급 당시 유효했던 쿠키로 User를 `SANCTIONED`, `WITHDRAWN`으로 바꾼 뒤 각각 요청 | `authenticate`가 null을 반환해 `UNAUTHORIZED`다. 이미 발급된 쿠키로 계속 쓰지 못한다. |
| 소유권 | 사용자 A·B가 같은 월드에 장수를 갖고 A로 조회·편집·사전 검사 | A의 장수만 읽고 바뀐다. 같은 ID의 다른 월드 장수와 B의 장수·예턴은 그대로다. A의 장수가 없고 B만 있어도 B로 대체하지 않는다. |
| 권한 필드 삽입 | 모든 경로의 입력에 `userId`, `generalId`를 덧붙임 | strict 입력 검증으로 `BAD_REQUEST`를 확인하고 타인 데이터·입력 기록은 그대로인지 조회한다. |
| 입력 형식 | 없는 월드, 잘못된 타입, 필수값 누락, 알 수 없는 속성, 음수·소수 revision | 잘못된 형식은 `BAD_REQUEST`다. 형식이 맞는 미존재 월드는 확정한 오류 계약으로 거부하고 DB를 바꾸지 않는다. |
| 세션 연장 | 주입 시각으로 연장 기준 전·경계·후 요청, 만료 시각과 같은 요청 | 기준 전에는 만료일 쓰기와 새 `Set-Cookie`가 없다. 기준에 도달하면 연장하고 쿠키를 갱신한다. 만료 경계는 인증되지 않는다. 기존 auth 회귀도 함께 실행한다. |
| 생성 성공 (AC-M1-06) | 유효한 이름·능력치, 초상 ID 또는 null로 생성 후 mine | API의 이벤트 기록과 엔진 처리 단계를 구분한다. 엔진 처리 뒤 장수 1명, 세션 사용자 소유, 재야·월드 내 도시, 입력한 능력치·초상이 일치한다. 도시 선택은 엔진의 시드 RNG를 쓴다. |
| 능력치 (AC-M1-06) | 합계 165와 166, 각각 15·80의 경계 및 14·81, 소수·문자열 | 월드 stat 규칙을 만족한 정수만 허용한다. 거부 시 장수와 유효 입력 기록이 늘지 않는다. 기본값과 다른 statRules를 가진 시험 월드도 대조한다. |
| 생성 입력 | 빈 이름·잘못된 타입, 잘못된 초상 타입 | 확정한 입력 schema에 따라 거부한다. 아직 정하지 않은 이름 길이·초상 ID 범위를 이 기록에서 만들지 않는다. |

### 확정 계약과 실제 구현

담당은 `opensamguk-implement`, 카드 `t_14d353f8`, 브랜치는 `wt/t_14d353f8`이다. 준비 병합 `850e2f8cb09e668f659d0bdece9c1a379e19adb6`과 T1-07 병합 `97aadc950b46bf1e26513604148e83241f6a596a`를 main에서 확인했다. InputEvent는 이 소스의 요청·턴·저장 §5를 그대로 쓴다. schema와 migration은 바꾸지 않는다. 위 사전 준비 절은 당시 기록으로 보존한다.

총괄 run659가 원계획 카드 `t_584e5736` comment783의 계약과 D1~D9를 수용했다. API7개는 모두 인증과 strict 입력을 쓰며 행위자는 세션에서만 정한다. 장수 생성 입력의 name은 허용하되 예턴 Slot의 name·userId·generalId는 거부한다. 이름은 NFC·trim 뒤 코드포인트 1~6글자, 한글 음절·Han·ASCII 영문·숫자다. 같은 월드 NPC도 정규화된 정확한 이름으로 중복 검사하며 영문 대소문자는 구분한다. 능력치는 World.statRules의 정수·범위·합계와 일치해야 한다. 초상은 null 또는 10001~11000이다.

생성 API는 World 잠금 아래 같은 actor의 PENDING payload를 재사용한다. 다른 payload는 CONFLICT이며 서버 UUID 키만 쓴다. 5초 이후 pending은 mine.creation으로 복구한다. mine은 rejected의 안전한 code/message도 반환한다. 접수 후 제재·탈퇴의 거절 코드는 ACTOR_INACTIVE, 공개 API 코드는 UNAUTHORIZED다. 생성·mine은 명시한 OwnGeneral projection만 반환하며 affinity·userId·내부 입력 식별자를 제외한다.

엔진은 새 `inputs.ts`에서 실제 생성과 완료 결과를 저장한다. `turnLoop.ts`에는 잠금 뒤 생성 분기와 beforeCommit·리스 검사를 연결했다. 게임 규칙은 rules에 두었다. RNG 순서는 cityKey 정렬 후보의 도시→affinity→offset이다. 장수 ID는 World 잠금 아래 기존 최댓값+1이며 nextTurnTick은 처리 tick보다 반드시 뒤가 될 때까지 월 간격을 더한다. 초기값은 확정 D8을 쓴다. 성공·거부마다 nextActionSequence는 한 번만 부른다.

예턴 set/edit는 World→키 재검사→General 잠금·revision 비교 뒤 최종30칸·revision·APPLIED turns.set 입력을 같은 트랜잭션에 저장한다. STALE은 최신 같은 스냅샷을 돌려주고 입력을 만들지 않는다. null은 휴식이며 args 생략은 빈 객체다. put은 0기반 양끝 포함, shift 양수는 뒤로 밀기, repeat는 편집 전 구간을 to+1부터 times번 복사하고 끝을 자른다. 성공 응답도 slots를 포함한다. 공유 유틸은 registry 의존 없는 일반 배열 편집 함수다.

category 정의와 기존9개 값은 이 작업 소유다. domestic 8개와 personal rest만 지정했으며 T1-08의 새28개는 만들지 않았다. 명령 목록은 general 대상만 registry 순서로 반환하고 기동 때 Zod 입력 JSON schema를 계산한다. 세션은 수명30일·잔여15일 이하 연장이며 경합 시 최신 상태를 다시 검사한다.
