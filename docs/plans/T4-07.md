## 계획 (Claude)

### 목표

AC-P2-05 가운데 공용 기제 몫이다. AC 문장은 "준비 턴이 있는 전략 명령 5종(필사즉생·수몰·의병모집·허보·피장파장)이 U-01에서 정한 방식대로 준비·실행된다"이고 U-01은 원작처럼 같은 명령을 연속 칸에 예약해야 실행되는 방식이다. <!-- lint-text-ignore J-2 --> 이 작업이 끝나면 준비 턴 N인 확장 명령은 같은 명령과 같은 인자를 N+1번 연속으로 실행해야 효과가 나고 그 앞 N번은 준비 중 기록만 남긴다. 준비 진행은 확장 상태 `ext`에 있어 턴·월간 저장, 재시작, 순수 재생을 그대로 지난다. 확장을 끈 월드와 준비 턴 명령을 켜지 않은 월드는 상태 해시와 RNG 소비가 지금과 같다.

이 기제는 T4-08(전략 명령 5종), T4-09·T4-10(특수 병종 연구 9종)과 [누락 명령 문서](./mvp-command-gaps.md)의 [준비] 8행(T4-57, T4-58, T4-62, T4-65, T4-71~T4-74)이 함께 쓴다.

### 접근

원작의 진행 기록을 확장 상태 조각 `prepare` 하나에 옮긴다. 기록을 바꾸는 곳은 둘이다. 준비 턴 명령은 감싸개가 기록을 올리거나 지운다. 다른 명령이 완료되면 `runGeneralTurn`의 추적 호출이 기록을 지운다. 그래서 P7(다른 명령 완료는 초기화)과 P8(실패는 유지)이 원작과 같다.

1. `slice.ts`: 조각 계약을 만든다(아래 계약 A).
2. `advance.ts`: 감싸개의 판단과 추적의 판단을 조각 값만 다루는 순수 함수로 만든다(계약 B, C).
3. `withPrepare.ts`: 명령 정의를 받아 같은 key·이름·인자를 가진 정의를 낸다. 준비 칸은 기록만 바꾸고 실행 칸은 원래 `execute`를 부른 뒤 기록을 지운다(계약 D).
4. `turn.ts`: 국가 명령 실행 직후와 장수 명령 실행 직후에 `trackTurn`을 한 번씩 부른다. 조각이 없는 상태에서는 아무것도 바꾸지 않는다(계약 C).
5. 시험: 순수 함수는 이 PR에서 전부 시험한다. 감싸개를 거친 전체 실행은 조각 등록 뒤에만 돌 수 있으므로 쟁점 Z2의 답에 따라 이 PR 또는 T4-53에서 돈다.

### 기술 계약 초안 (Codex 계획 기술 검토 전)

#### A. 조각 `prepare`

```ts
// ext/prepare/slice.ts
export interface PrepareRecord {
  commandKey: string;
  args: JsonValue; // resolver가 zod로 해석한 인자
  term: number; // 1 이상 정수. 지금까지 센 준비 칸 수
  seq?: number; // stackSequence를 쓰는 명령만. 기록할 때의 순번
}
export interface PrepareState {
  general: Record<string, PrepareRecord>; // key는 장수 id 문자열
  nation: Record<string, Record<string, PrepareRecord>>; // 국가 id → officerLevel → 기록
}
export const PREPARE_SLICE_KEY = 'prepare';
export const prepareSlice: ExtSlice<PrepareState>;
```

- `create`는 `{ general: {}, nation: {} }`를 낸다. 월드 상태를 읽지 않는다.
- `clone`은 깊은 복제다. `validate`는 모양, `term`이 1 이상 안전 정수인지, `commandKey`가 빈 문자열이 아닌지, `seq`가 있으면 안전 정수인지, key가 양의 정수 문자열인지 본다. [T4-03](./T4-03.md) E7의 저장 가능 검사(U+0000, 짝 없는 대리 코드, `-0` 거부)를 rules 안에서 같은 규칙으로 한다. rules는 `packages/db`를 import할 수 없으므로 같은 규칙을 이 파일에 둔다.
- 국가 기록의 둘째 key는 실행한 장수의 officerLevel이다. T2-05 전에는 군주 칸만 실행되므로 늘 `"12"`다. T2-05 뒤에는 직책 칸마다 따로 센다(P2).
- 기록은 실행이 끝나거나 다른 명령이 완료되면 지운다. 원작의 term 0 기록은 두지 않는다. 지운 상태와 term 0 상태는 다음 칸에서 같은 결과(1부터 셈)를 낸다.

#### B. `advancePrepare`

```ts
export function advancePrepare(
  record: PrepareRecord | undefined,
  commandKey: string,
  args: JsonValue,
  preReqTurn: number,
  seq?: number,
): { phase: 'prepare'; record: PrepareRecord } | { phase: 'execute' };
```

- `continuing = record?.commandKey === commandKey && sameArgs(record.args, args) && record.seq === seq`. `seq`를 쓰지 않는 명령은 양쪽이 `undefined`라 비교가 늘 참이다.
- `term = continuing ? record.term + 1 : 1`.
- `term <= preReqTurn`이면 `{ phase: 'prepare', record: { commandKey, args, term, ...(seq === undefined ? {} : { seq }) } }`, 아니면 `{ phase: 'execute' }`.
- `sameArgs`는 객체 key 순서와 상관없는 깊은 비교다. 배열 순서는 본다.
- `preReqTurn`이 1 이상 정수가 아니면 예외다. 준비 턴 0인 명령은 감싸지 않는다.

이 정의는 원작 P4·P5와 같은 결과를 낸다. 원작은 `!continuing || term < 준비 턴`일 때 준비하고 새 term을 쓴다. 이어지지 않으면 새 term은 1이고 준비 턴이 1 이상이므로 늘 준비다. 이어지면 새 term은 이전 term + 1이며 이전 term < 준비 턴, 곧 새 term ≤ 준비 턴일 때 준비다.

#### C. `trackTurn`

```ts
export function trackTurn(
  state: WorldState, // runGeneralTurn이 방금 applyEffects로 만든 새 상태
  actor: { kind: 'general'; generalId: number } | { kind: 'nation'; nationId: number; officerLevel: number },
  commandKey: string,
  result: CommandResult | Failure,
): WorldState;
```

- `state.ext?.prepare`가 없으면 `state`를 그대로 낸다. 끈 월드와 준비 턴 명령을 켜지 않은 월드는 여기서 끝나므로 상태와 해시가 지금과 같다.
- `result`가 실패면 그대로 낸다(P8).
- 행위자의 기록이 있고 `record.commandKey !== commandKey`이면 그 기록을 지운다(P7). 국가 기록이 비면 그 국가 key도 지운다.
- 같은 key면 건드리지 않는다. 같은 key의 완료는 감싸개 자신이 낸 결과이고 감싸개가 이미 기록을 올렸거나 지웠다.
- 난수를 쓰지 않는다. `state`는 `applyEffects`가 늘 새로 만든 객체(`effects.ts:39`)이므로 그 자리에서 고쳐 낸다. 입력 `view`는 바꾸지 않는다.
- `turn.ts`의 호출 자리는 국가 명령 `applyEffects` 직후(`:48` 다음)와 장수 명령 `applyEffects` 직후(`:79` 다음)다. 국가 행위자는 실행 직전 장수의 `nationId`와 `officerLevel`, 장수 행위자는 `actor.generalId`다. 장수 명령의 `commandKey`는 NPC 판단으로 바뀐 뒤의 `selected.commandKey`다.
- T2-05가 국가 칸 분기를 직책 칸으로 바꿔도 호출 자리는 `run` 결과 적용 직후 한 곳으로 유지한다. 그 병합 충돌은 나중에 병합하는 쪽이 맞춘다.

#### D. `withPrepare`

```ts
export interface PrepareSpec {
  preReqTurn: number; // 1 이상 정수
  stackSequence?(view: WorldView, actor: Actor): number; // 원작 getStackSequence. 쓰는 명령만
}
export function withPrepare<A>(def: CommandDef<A>, spec: PrepareSpec): CommandDef<A>;
```

- `key`, `name`, `category`, `target`, `args`, `precheck`, `check`는 `def`의 것을 그대로 쓴다. 준비 칸에도 resolver가 `check`를 먼저 부르므로 원작 P3(모든 칸 전체 제약)과 같다. 재사용 대기 검사도 명령의 `check` 안에 있으면 모든 칸에서 돈다.
- `execute(view, actor, args, rng)`:
  1. 행위자 key를 정한다. 장수 명령은 `general[actor.generalId]`, 국가 명령은 `nation[장수.nationId][장수.officerLevel]`이다.
  2. `view.ext?.prepare`가 없으면 예외다. 이 명령을 켠 월드에는 관계 행(`extCommandBindings`)의 `sliceKeys`에 `prepare`가 있어 조각이 반드시 있다. 없으면 설정 오류이므로 게임 실패로 바꾸지 않는다(T4-02 2.4.4와 같은 원칙).
  3. `advancePrepare(기록, def.key, args, spec.preReqTurn, spec.stackSequence?.(view, actor))`. 순번은 실행 전 `view`로 계산한다.
  4. `prepare`면 `cloneWorld(view)`에 새 기록을 넣고 `{ effects: [{ kind: 'world', state }], logs: [{ kind: 'success', text: `${def.name} 준비 중 (${term}/${preReqTurn + 1})` }] }`를 낸다. `rng`는 읽지 않는다(P12).
  5. `execute`면 `def.execute(view, actor, args, rng)`를 부른다. 그 결과의 `effects`를 `applyEffects(view, effects)`로 적용한 상태에서 행위자 기록을 지운다. 그다음 효과를 그 상태 하나의 `{ kind: 'world' }`로 바꾼 결과를 낸다. `logs`, `reports`, `history`, `battleAwards`는 그대로 둔다.
- 5단계의 효과 합치기는 `def.execute`가 낸 필드 효과와 world 효과를 같은 순서로 적용한 결과와 같아야 한다. 시험 D5가 고정한다.
- `withPrepare`를 두 번 감싸면 예외다.
- 감싸개는 `ext/prepare/withPrepare.ts`에만 있고 `slice.ts`는 이 파일을 import하지 않는다. `ext/state.ts`가 `slice.ts`만 import하면 순환이 생기지 않는다.

#### E. 문구

준비 칸의 장수 로그 문구는 `{명령 이름} 준비 중 ({term}/{준비 턴 + 1})`이다. 원작 문구를 옮기지 않고 새로 썼다. 국가 명령의 준비 칸은 지금 엔진 경로대로 국가 기록에 `{명령 이름}: {명령 이름} 준비 중 (n/m)`으로 남는다(`turnLoop.ts:197-205`). 이 중복 표기를 줄일지는 T4-53에서 실제 기록을 보고 정한다(쟁점 Z4).

A1~A3, T1, S1, S2, R1은 이 PR의 시험이다. D1~D8은 감싸개가 `cloneWorld`·`applyEffects`를 지나므로 `prepare` 조각이 운영 `extSlices`에 있어야 돈다. 쟁점 Z2가 조각만 먼저 등록하는 안을 받으면 이 PR에서 돈다. 받지 않으면 T4-53이 등록과 함께 돌린다. 어느 쪽이든 시험용으로 운영 목록을 바꾸거나 `vi.mock`을 쓰지 않는다.

명령은 `pnpm exec vitest run packages/rules/src/commands/ext/prepare packages/rules/src/replay.test.ts --maxWorkers=2`와 `pnpm check`다. 엔진 통합(연속 칸, 중단, 재시작, 재생)은 T4-53의 `apps/engine/src/extPrepared.integration.test.ts`가 낸다.

### 상대 영역에 필요한 것

- T4-03(Codex): `prepare` 조각은 E7 저장 가능 값만 담는다. 켠 월드의 턴 저장이 바뀐 조각 행만 쓰면 준비 칸마다 `prepare` 한 행이 갱신된다.
- T4-06(Codex): 재사용 대기 검사는 명령 `check` 안에 둔다. 그러면 준비 칸마다 검사된다(P3).
- T4-50(Codex): 국가 예턴 저장은 준비 진행을 검사하지 않는다(P9).
- T4-51(Claude): 화면은 준비 턴 수를 명령 설명으로만 보인다. 진행 상황 표시는 범위 밖이며 필요하면 별도 AC가 있어야 한다.
- T2-05(Codex): 직책 칸 분기를 바꿀 때 `trackTurn` 호출 자리를 유지한다. 직책 칸을 비울 때 그 직책의 준비 기록을 함께 지울지는 쟁점 Z5다.
