## 계획 (Claude)

### 목표

AC-P2-18의 조회 몫이다. 명세 문장은 이렇다. 다른 국가 도시의 상세값은 첩보 기록으로만 보이고 몇 개월 전 기록인지 표시된다. 적 병력은 U-11에서 정한 구간으로 보인다.

이 작업이 끝나면 `spy`를 켠 월드에서 아래가 HTTP로 성립한다.

- `city.get`이 공개 범위 밖 도시에 대해 자기 국가의 첩보 기록을 몇 개월 전과 함께 낸다. 기록이 없으면 상세값이 없다. 기록은 기간 제한 없이 보인다(승인).
- 기록의 병력은 승인 구간으로만 나간다. `intel.records`와 `city.get`이 같은 `intelRecordInfo`와 같은 `INTEL_POLICY` 객체를 쓴다.
- 다른 나라 도시의 주둔 장수 목록이 빠진다. 세션 장수가 직접 서 있어 지금 수치가 보이는 도시도 같다(승인 F3, 적용 범위는 §3.1).
- 세션 장수가 직접 있는 도시는 국가 소속이든 재야든 지금 값이 보인다(승인 F4).
- `spy`를 끈 월드의 모든 응답은 지금과 바이트 단위로 같다(IC-10).

AC-P2-18의 첩보 기록으로만 문장은 승인 F4 때문에 내 장수가 없는 다른 국가 도시로 좁혀야 한다. 정본 AC 문장 수정은 이 문서가 하지 않고 조율 세션(정본 단독 작성자)에 요청으로 남긴다(§6 Q3).

## 3. 기술 계약 초안 (Codex 계획 기술 검토 전)

### 3.1 `fog.ts`

```ts
import type { IntelRecordView } from './visibility';
export function fogLive(city: Pick<City, 'cityKey' | 'nationId'>, viewer: Viewer): boolean;
export function fogForeign(city: Pick<City, 'nationId'>, viewer: Viewer): boolean;
export function fogCityInfo(input: {
  live: boolean; // fogLive 결과. 지금 수치 공개 여부
  foreign: boolean; // fogForeign 결과. 주둔 명단 가림 여부. live와 따로 정한다
  record: IntelRecordView | null; // intelRecordInfo(..., INTEL_POLICY) 결과. 기록이 없거나 null이면 null
}): { intel: IntelRecordView | null; garrisonHidden: boolean };
```

사용자가 승인한 문장은 `다른 나라 도시의 주둔 장수 목록은 가리되, 내 장수가 직접 있는 도시는 현재 수치를 볼 수 있습니다. 재야도 자신이 있는 도시는 현재처럼 봅니다.`다. 명단 가림(F3)과 지금 수치 공개(F4)는 서로 다른 조건이다. 내 장수가 있으면 지금 수치가 보인다는 문장을 그 도시의 명단 공개로 넓히지 않는다. 그래서 `fogLive`는 수치만, `fogForeign`은 명단만 정한다.

- `fogLive`: `visibility(viewer).city(city)`(`visibility.ts:14~15`)와 같다. 자기 나라 도시이거나 세션 장수가 직접 있는 도시면 참이고 재야도 자기가 있는 도시는 참이다(F4 승인). 따로 함수를 두는 이유는 안개 판정을 한 이름으로 고정해 시험하기 위해서다.
- 수치 칸은 지금처럼 `cityInfo(city, viewer)`가 만든다. `cityInfo`는 안에서 같은 `visibility(viewer).city`를 보므로(`visibility.ts:73`) `fogLive`가 참이면 지금 값, 거짓이면 `mapCity` 칸만 나간다. 앞선 판의 `fogCityBase`는 F4 (나)에서 두 판정이 갈릴 때의 누출을 막는 장치였다. 승인 F4에서는 두 판정이 같은 함수라 갈리지 않으므로 그 장치를 뺀다. 같음은 F-U6 시험으로 고정한다.
- `fogForeign`: 도시 소유가 `null`(공백지)이면 거짓이다. viewer가 국가에 속하고 도시 소유가 그 국가면 거짓이다(자기 나라 도시). 그 밖은 모두 참이다. 그래서 재야와 장수 없는 계정에게는 국가가 가진 모든 도시가 다른 나라 도시다. 세션 장수가 그 도시에 서 있는지는 보지 않는다.
- `fogCityInfo`: `intel`은 `live`면 `null`, 아니면 받은 `record`다. `garrisonHidden`은 언제나 `foreign`이다. `live`가 참이어도 `garrisonHidden`을 거짓으로 바꾸지 않는다.
- F3 적용 범위: 다른 나라가 가진 도시 전부다. 세션 장수가 직접 서 있는 다른 나라 도시도 지금 수치는 보이고(F4) 주둔 명단은 가린다(F3). 재야가 자기가 서 있는 도시를 볼 때도 같다. 그 도시가 국가 소유면 지금 수치는 보이고 명단은 가린다. 자기 나라 도시와 공백지의 명단은 이번 승인 질문의 대상이 아니어서 지금 동작을 그대로 둔다.
- 공개 정책 값(구간·기간)은 이 파일에 없다. T4-12 `intelPolicy.ts`가 소유하고 `routers/city.ts`가 import한다.

### 3.3 `city.get` 출력

켠 월드에서만 키 하나를 더한다.

```ts
type CityGetOutput = ReturnType<typeof cityInfo> & {
  generals: GeneralInfo[];
  fog?: {
    intel: IntelRecordView | null; // T4-12 §2.2와 같은 모양
    garrisonHidden: boolean; // 다른 나라 도시면 live와 상관없이 true(F3). 이때 generals는 []
  };
};
```

처리 순서는 `readWorld` 한 트랜잭션 안에서 이렇다.

1. 지금처럼 viewer, 도시, 장수를 읽는다. 없는 도시는 `NOT_FOUND`.
2. 월드 행의 `preset`으로 `worldResolver`를 만들고 `spy`가 꺼졌으면 지금 응답을 그대로 낸다. 끝.
3. `live = fogLive(city, viewer)`.
4. `live`가 아니고 viewer가 국가에 속하면 `intel` 조각에서 `[viewer 국가][cityKey]` 하나를 읽어 `intelRecordInfo(cityKey, record, { startYear, nowTick, unitSet }, INTEL_POLICY)`로 투영한다. 기록이 없거나 결과가 `null`이면 `record`는 `null`이다. 읽기·검증 실패는 T4-12 2.3의 5단계와 같이 `INTERNAL_SERVER_ERROR`다. `nowTick`과 `unitSet`은 T4-12와 같은 방법으로 읽는다.
5. 수치 칸은 지금처럼 `cityInfo(city, viewer)`로 만든다.
6. `fogCityInfo({ live, foreign: fogForeign(city, viewer), record })`로 `fog`를 만들고 `garrisonHidden`이면 `generals`를 빈 배열로 낸다.

`cityInfo`·`generalInfo`·`visibility` 함수 자체는 바꾸지 않는다. 끈 월드는 지금 경로 그대로다. 주둔 장수의 상세(`generalInfo`)는 본인과 같은 국가 장수만 보이는 규칙이라 내 장수가 있다는 이유로 열리지 않는다. 세션 장수가 없는 계정은 지금처럼 공개 칸을 받고 `fog.intel`은 `null`이다.
