# T4-80 지도 편집 캔버스

> 대기열: T4-80 · AC: AC-P2-27 (편집기 일부) · 구현: Claude · 리뷰: Codex
> 설계: [지도 편집기 설계](./map-editor.md) C-M2·C-M3·§4 · 결정: [D-028](../product/decisions.md#d-028-운영자-지도-편집기와-도트-바탕-지도를-만든다-2026-10-23) · 기준: PR #166 head `38afaff`

## 계획 (Claude)

### 목표

운영자가 서버 없이 지도 JSON을 불러와 도시, 연결, 지형 층을 고치고 검증 결과를 보며 v2 JSON과 5색 도트 밑그림 PNG로 내보낸다. 내보낸 v2를 다시 불러오면 내보내기 전과 같은 지도가 된다. 밑그림 PNG는 바탕 그림 생성(T4-83)의 유일한 입력이다.

AC-P2-27 전체가 아니다. 초안 저장, 게시, 권한, 감사, 관리자 콘솔 연결은 T4-78·T4-81 몫이고 이 작업이 끝나도 AC-P2-27을 완료로 세지 않는다.

T4-76(`packages/rules`의 v2 형식·검증기)이 아직 없다. 그래서 형식과 검증을 화면 폴더에 임시로 둔다. `contract.ts`와 `validate.ts` 머리에 T4-76이 main에 들어오면 `@opensamguk/rules`의 타입과 검증기로 바꾼다고 적는다. 지금 `apps/web`은 rules를 import하지 못하므로(패키지 경계 E1만 예외) 바꿀 때 경계 예외 하나가 더 필요하다. 아래 상대 영역 요구에 적는다.

### 하지 않는 것

- 서버 API, DB 초안 저장, 게시, 권한 (T4-78·T4-81)
- 시나리오가 참조하는 도시 검사. 편집기에 시나리오가 없다. T4-76 검증기와 T4-81에서 한다
- 도시 수치(`max`·`initial`) 편집. 새 도시는 기존 도시 값을 복사한다 (아래 도시)
- che 지형 층 그리기 (T4-82), 바탕 그림 생성 (T4-83), 메인 지도에 깔기 (T4-84)
- 운영 빌드 노출. 개발 모드에서만 열린다

### 형식 (C-M2를 화면에 옮긴 모양)

```ts
type Point = [number, number];
type Terrain = {
  coast: Point[][];      // 닫힌 다각형
  lakes: Point[][];      // 닫힌 다각형
  rivers: Array<{ name?: string; points: Point[] }>; // 열린 선
  mountains: Point[][];  // 닫힌 다각형
};
type MapV2 = MapResource & { version: 2; canvas: { width: number; height: number }; terrain: Terrain };
```

- 도시 필드는 지금 `mapSchema`(`packages/rules/src/world/resources.ts:18`) 그대로다. `id`·`name`·`level`·`region`·`position`·`connections`·`max`·`initial`.
- `canvas`는 설계의 캔버스 크기는 지도마다 둔다를 위해 더한 칸이다. 없으면 700×500으로 읽는다. T4-76에 이름과 위치를 확정해 달라고 넘긴다.
- 닫힌 다각형은 점 4개 이상이고 마지막 점이 첫 점과 같다. 열린 선은 점 2개 이상이다. 그리기를 마치면 편집기가 첫 점을 끝에 붙여 닫는다.
- 지금 형식 읽기: `version`이 없으면 지금 형식으로 보고 빈 지형 층과 기본 캔버스를 붙인다. 도시의 `meta`(che의 `connectionNames`)는 연결을 고치면 맞지 않게 되므로 버린다. 맨 위 `$comment`(MIT 출처 고지)와 `defaults`의 나머지 키(`trade`, `frontState`)는 그대로 둔다.
- 쓰기는 키 순서를 고정한 JSON이다. 같은 지도는 늘 같은 글자열이 된다.

### 검증 (C-M3 지도 항목)

| 코드 | 실패 조건 | 누르면 |
| ---- | --------- | ------ |
| `city-id-duplicate` | 도시 ID가 겹침 | 그 도시 |
| `city-name-duplicate` | 도시 이름이 겹침, 빈 이름 | 그 도시 |
| `city-out-of-canvas` | 좌표가 0~너비, 0~높이 밖 | 그 도시 |
| `city-level-range`, `city-region-range` | 규모·지역이 정수 1~8 밖 | 그 도시 |
| `link-self` | 자기 자신을 가리킴 | 그 도시 |
| `link-missing-city` | 없는 도시를 가리킴 | 그 도시 |
| `link-one-way` | 한쪽에만 있는 연결 | 그 도시 |
| `network-split` | 첫 도시의 연결망에 닿지 않는 도시 | 닿지 않는 첫 도시 |
| `terrain-open` | 다각형이 닫히지 않음, 강의 점이 2개 미만 | 그 선 |
| `terrain-out-of-canvas` | 지형 점이 캔버스 밖 | 그 선 |

규모·지역 1~8은 che의 실제 값 범위이고 `cityRadius`(`WorldMap.tsx`)가 쓰는 규모 범위다. 정식 범위는 T4-76이 정한다. 검사는 매 편집 뒤 다시 돌린다. 오류가 있어도 내보내기는 막지 않는다. 게시를 막는 것은 T4-78 서버 검증이다. 다만 오류 수를 내보내기 버튼 옆에 보인다.

### 화면

```text
┌ 지도 편집기 (개발) · 파일 불러오기 · v2 내려받기 · 밑그림 PNG 내려받기 · 되돌리기 · 다시 하기 ┐
├ 도구: 선택 · 도시 추가 · 연결 · 해안 · 호수 · 산맥 · 강    확대 · 축소 · 맞춤 ─────────────┤
│ 캔버스 (700×500 SVG, 지형 → 연결선 → 도시)        │ 고른 것: 도시 칸 또는 선 칸          │
│                                                   │ 검증: 오류 목록 (누르면 고름)        │
└───────────────────────────────────────────────────┴──────────────────────────────────────┘
```

- 좌표계는 메인 지도와 같다. `MAP_WIDTH`·`MAP_HEIGHT`, `mapLinks`, `cityRadius`를 `WorldMap.tsx`에서 가져다 쓴다.
- 선택 도구: 도시나 선을 누르면 고른다. 도시를 끌면 옮긴다. 고른 선의 점을 끌면 그 점이 옮겨지고 점을 누르면 그 점을 고른다. 빈 곳을 끌면 화면이 움직인다.
- 도시 추가 도구: 빈 곳을 누르면 그 자리에 도시가 생긴다. ID는 가장 큰 ID + 1, 이름은 `새 도시 <ID>`, 규모 1, 지역 1이다. `max`·`initial`은 규모 1인 첫 도시에서 복사하고 없으면 첫 도시에서, 도시가 없으면 0이다.
- 연결 도구: 도시 하나를 누르고 다른 도시를 누르면 둘을 잇는다. 이미 이어져 있으면 끊는다. 늘 양쪽에 함께 넣고 함께 뺀다.
- 지형 도구: 누를 때마다 점을 찍는다. [그리기 마치기]나 Enter로 끝내고 Esc로 버린다. 다각형은 점 3개, 강은 점 2개 미만이면 마치기 버튼이 점선이고 누르면 이유를 보인다.
- 도시 칸: 이름·규모·지역 입력, 연결 목록과 [끊기], [도시 삭제]. 삭제하면 다른 도시의 연결에서도 빠진다.
- 선 칸: 층 이름, 점 수, [고른 점 지우기], [선 지우기]. 강은 이름 입력이 있다.
- 되돌리기·다시 하기는 버튼과 Ctrl+Z·Ctrl+Shift+Z다. 끌기 하나는 놓을 때 한 번으로 쌓인다. 불러오기는 기록을 비운다.
- 확대·축소는 버튼과 휠, 맞춤은 전체 보기다. 1배부터 8배까지다.
- 지형 색은 밑그림 5색을 옅게 깔아 쓴다. 화면 색 토큰이 아니라 형식의 일부라서 `contract.ts`에 둔다.
- 오류는 문구로 쓰고 색만으로 구분하지 않는다. 버튼 문구는 동사로 쓴다.

### 밑그림 PNG

- 크기는 캔버스의 3배(기본 2100×1500)다. 도시 점과 이름, 연결선은 넣지 않는다.
- 해안 다각형이 있으면 바탕은 바다이고 해안 다각형 안을 땅으로 채운다. 해안이 없으면 바탕이 땅이다. 그 위에 산맥, 호수, 강 순서로 칠한다. 강은 지도 좌표 2만큼의 굵기로 칠한다.
- 경계를 섞지 않도록 브라우저 캔버스를 쓰지 않고 직접 칠한다(짝홀 규칙 주사선 채우기, 굵은 선은 선분까지 거리). 그래서 모든 화소가 다섯 색 가운데 하나다.
- PNG는 색 형식 3(팔레트)에 팔레트 5칸이다. 압축은 브라우저의 `CompressionStream('deflate')`를 쓴다. 파일 형식상 다섯 색 밖의 화소가 있을 수 없다.

| 번호 | 층 | 색 |
| ---- | -- | -- |
| 0 | 바다 | `#2b5d8c` |
| 1 | 땅 | `#cbb98a` |
| 2 | 강 | `#4f8fd0` |
| 3 | 산 | `#7a6347` |
| 4 | 호수 | `#6aa6d8` |

### 진입과 운영 빌드

`router.tsx`의 `devUiRoute`는 `...(import.meta.env.DEV ? [devUiRoute] : [])`로 경로 목록에 들어간다. 운영 빌드(`vite build`)에서는 `import.meta.env.DEV`가 `false`라 경로가 없고 없는 주소 화면이 나온다. `/dev/map-editor`도 같은 식으로 따로 한 줄 넣는다. 부품은 `lazyRouteComponent`로 불러서 첫 화면 묶음에 넣지 않는다. 관리자 콘솔(T3-06)이 생기면 T4-81이 그쪽으로 옮긴다.

### 상대 영역에 필요한 것 (Codex T4-76)

- `@opensamguk/rules`에 v2 지도 타입과 `validateMap(map, { scenarios? })`. 결과는 코드, 사람이 읽는 문구, 대상(도시 ID 또는 층과 번호) 목록이면 이 화면이 그대로 쓴다.
- 캔버스 크기 칸의 이름과 위치. 이 화면은 `canvas: { width, height }`, 없으면 700×500으로 읽는다.
- 닫힌 다각형의 정의. 이 화면은 점 4개 이상이고 마지막 점이 첫 점과 같음으로 본다.
- 규모·지역 범위. 이 화면은 정수 1~8이다.
- 지형 점이 캔버스 안이어야 하는지. 이 화면은 0~너비, 0~높이(경계 포함)를 요구한다.
- 맨 위 `$comment`와 `defaults`의 추가 키를 버릴지 둘지. 지금 `mapSchema`는 zod 기본값이라 버린다. 출처 고지 때문에 이 화면은 둔다.
- 밑그림 5색 값. T4-83 입력이므로 형식 문서에 같은 표를 둔다.
- `apps/web`이 rules의 지도 타입·검증기를 import하도록 패키지 경계 예외 하나(E3, `apps/web/src/mapEditor/**`). `eslint.config.js`와 `docs/architecture/package-boundaries.md`를 함께 고친다.
- T4-77이 `resources/map/che.json`을 지우면 `e2e/mapEditor.spec.ts`와 `contract.test.ts`·`validate.test.ts`의 che 입력이 사라진다. 그때 T4-77이 DB에서 내보낸 che 파일이나 시험 고정물을 대신 둔다.

## 구현 기록 (Claude)

- 기준: PR #166 head `38afaff` 위에서 작업했다. T4-80 행과 설계 문서가 아직 main에 없어서다. 중단 시점 작업은 `b4a15be`로 보존해 PR #179로 main에 들어왔고 마무리는 main `3e5b52a` 위에서 했다.
- 바꾼 것: `apps/web/src/mapEditor/`에 형식(`contract.ts`), 검사(`validate.ts`), 편집 상태(`editor.ts`), 밑그림(`sketch.ts`), 받침 조사(`josa.ts`), 화면(`MapEditorPage.tsx`, `MapCanvas.tsx`, `MapEditor.module.css`), 단위 시험 5개와 시험 지도(`fixtures.ts`)를 두었다. `router.tsx`에 `/dev/map-editor`, `WorldMap.tsx`의 `mapLinks`는 인자 타입만 넓혔다. `e2e/mapEditor.spec.ts`를 더했다.
- 계획과 달라진 점과 이유:
  - 해안 다각형이 하나도 없으면 밑그림 바탕을 땅으로 둔다. 해안을 아직 그리지 않은 지도(지금 che)를 내보내면 온통 바다가 되어 밑그림 구실을 못 해서다. 화면 바탕도 같은 규칙을 따른다.
  - 도시 이름처럼 바뀌는 낱말 뒤 조사를 받침에 맞추려고 `josa.ts`를 더했다.
  - 경로 정의 자체를 `import.meta.env.DEV`일 때만 만든다. `devUiRoute`처럼 목록에만 조건을 걸면 운영 빌드에 편집기 묶음(`MapEditorPage-*.js`, 33 kB)이 남았다. 바꾼 뒤 `vite build` 결과에 `map-editor`·`지도 편집기` 글자가 없다.
  - 접근성 보완으로 도시 찾기 목록을 두었다. 캔버스를 누르지 않고도 도시를 고른다.
  - E2E는 창을 1600×1200으로 둔다. 기본 1280×720에서는 캔버스 아래쪽이 창 밖이라 좌표로 누를 수 없었다.
