## 0. 이 문서의 위치

명세 §6 T4-27 행을 적는다. 경매 상태 조각, 경매 열기·입찰·마감의 순수 판정, 매달 정산에서 부르는 마감 단계다. 입찰 기록(InputEvent), 저장, API, 화면은 T4-28·T4-29다.

원작 경매는 실제 시각으로 마감하고 입찰마다 분 단위로 마감을 늦춘다(§1.2). 우리 규칙은 현재 시각을 쓰지 못하고(AGENTS.md §6) 한 턴과 한 달의 상태 변경을 한 트랜잭션에 저장한다(C5). 그래서 이 계획의 안은 게임 tick, 그 가운데 월간 정산 경계로 마감하는 것이다. 이 선택은 U-08의 마감 기준 결정이며 이 문서가 정하지 않는다. 다만 실제 시각 마감을 고르면 재생과 트랜잭션 계약이 크게 달라지므로 그 비용을 §3에 함께 적는다.

착수 조건은 이 문서의 G-03 수용, §3 AU-1~AU-9의 사용자 결정, AC-P2-14의 정식 반영이다. AU-2에서 장비 경매(다)·(라)를 고르면 T4-22 병합에 더해 장비 경매의 생성 계약(§2.5)을 이 문서에 써서 추가 G-03 검토를 받아야 계약 준비로 올린다. 지금 원고의 계약은 자원 경매만 다룬다.

## 계획 (Claude)

### 목표

AC-P2-14 가운데 규칙 몫을 만든다. 경매를 열고 입찰하는 판정, 입찰금을 미리 빼고 이전 최고 입찰자에게 돌려주는 계산, 마감 때 최고 입찰자에게 낙찰하고 주최자에게 대금을 주는 계산, 입찰이 없을 때의 유찰이 순수 함수로 정해진다. 같은 입력이면 결과가 같고 난수를 쓰는 곳은 시드 스트림 하나뿐이다. 경매를 켜지 않은 월드의 상태와 해시는 지금과 같다.

AC-P2-14 전체는 T4-28(InputEvent·PostgreSQL 롤백·재생·HTTP 권한)과 T4-29(E2E)가 끝나야 닫힌다.

## 2. 계약

### 2.1 상태 조각 `auction`

```ts
// ext/auction/state.ts
export type AuctionKind = 'sell_rice' | 'buy_rice' | 'equipment'; // AU-2 결정 범위만 켠다
// interface는 JsonValue(model/world.ts:4)에 할당되지 않으므로 조각 값과 중첩 값을 모두 type alias로 쓴다.
export type AuctionRecord = {
  id: number;
  kind: AuctionKind;
  hostId: number | null; // null은 중립 경매(AU-2 (나))
  lot: { resource: 'gold' | 'rice'; amount: number } | { equipmentKey: string };
  pay: 'gold' | 'rice';
  startBid: number;
  finishBid: number | null;
  openedTick: number;
  closeTick: number; // 월간 정산 경계 tick (AU-1 (가))
  latestCloseTick: number; // 연장 상한
  highest: { generalId: number; amount: number } | null; // 맡긴 입찰금
};
export type AuctionResult = {
  id: number; kind: AuctionKind; hostId: number | null;
  lot: AuctionRecord['lot']; pay: 'gold' | 'rice';
  winnerId: number | null; price: number | null; closedTick: number;
};
export type AuctionSlice = {
  nextId: number;
  open: AuctionRecord[]; // id 오름차순
  closed: AuctionResult[]; // 최근 것부터 최대 30건 (T4-28 T28-Q2)
};
export const auctionSlice: ExtSlice<AuctionSlice>;
```

- 형식 제약: `ExtSlice<T extends JsonValue>`(`commands/ext/state.ts:5-10`)를 만족하도록 모든 칸이 JSON 값이고 선택 칸(`?:`)과 `undefined`가 없다. 구현 PR은 `as`나 `any` 없이 선언하고 `const check: JsonValue = {} as AuctionSlice;` 컴파일 시험 한 줄을 둔다. 런타임 `validate`는 그대로 엄격하다.

- `create`는 `{ nextId: 1, open: [], closed: [] }`.
- `validate`: 번호가 양의 정수이고 `nextId`보다 작다, `open`·`closed` 번호 중복 없음, 금액·수량이 양의 안전 정수, `closeTick ≤ latestCloseTick`, 둘 다 `TICKS_PER_MONTH`의 배수, `closed` 30건 이하.
- `clone`은 깊은 복제.

### 2.2 열기 `openAuction`

```ts
export function openAuction(view: WorldView, slice: DeepReadonly<AuctionSlice>, hostId: number,
  input: { kind: 'sell_rice' | 'buy_rice'; amount: number; startBid: number; finishBid: number; closeMonths: number },
  at: { tick: number }): AuctionOutcome;
export type AuctionOutcome =
  | { ok: true; slice: AuctionSlice; state: WorldState; auctionId: number }
  | { ok: false; code: AuctionCode; message: string };
```

AU-2에서 장수가 여는 경매를 고를 때만 쓴다. 검사 순서는 원작 처리기(`opener.ts:45-100`)를 따른다.

1. 장수 없음 `NO_ACTOR`.
2. 마감 개월 1~24 밖 `BAD_INPUT`. 거래량 100~10000 밖 `BAD_INPUT`. 시작가가 거래량의 50~200% 밖, 즉시 거래가가 110~200% 밖이거나 시작가의 110% 미만 `BAD_INPUT`. 값은 §3 AU-4.
3. 그 장수의 열린 자원 경매가 이미 있음 `ALREADY_HOSTING`.
4. 내놓을 자원 < 거래량 + 남길 기본값(쌀 500, 금 0) `NO_RESOURCE`.

성공하면 주최자 장수의 자원을 거래량만큼 빼고(`state`), `open`에 넣고 `nextId`를 올린다. `closeTick`은 `at.tick` 다음 월 경계부터 센 `closeMonths`번째 경계다. `latestCloseTick`은 AU-5다.

### 2.3 입찰 `placeBid`

```ts
export function placeBid(view: WorldView, slice: DeepReadonly<AuctionSlice>, bidderId: number,
  input: { auctionId: number; amount: number }, at: { tick: number }): AuctionOutcome;
```

검사 순서(원작 `bidder.ts:280-470`의 순서):

1. 번호 판정. `auctionId`가 `open`에 있으면 다음 검사로 간다. 없을 때 `auctionId < slice.nextId`이면 이미 열렸다가 닫힌 번호이므로 `CLOSED`다. `closed` 30건 밖으로 밀려난 번호도 같다. `auctionId ≥ slice.nextId`이면 연 적 없는 번호라 `NO_AUCTION`이다. 번호는 1부터 `nextId`를 하나씩 올려 쓰고 다시 쓰지 않으므로(§2.2) 이 구분이 성립한다. `open`에 있어도 `at.tick ≥ closeTick`이면 `CLOSED`다(마감 정산 전 같은 걸음의 입력).
2. 최고가가 있으면 그보다 높아야 하고 없으면 시작가 이상이어야 한다. 어기면 `BID_TOO_LOW`. 두 자원 경매 모두 같은 방향이다(§1.2의 `isReverse` 사실). 그래서 유효 입찰 구간은 첫 입찰이 [시작가, 즉시 거래가], 그다음은 (최고가, 즉시 거래가]이고 열기 검사가 즉시 거래가 ≥ 시작가 × 1.1을 요구하므로 구간은 늘 비지 않는다.
3. 즉시 거래가를 넘음 `BID_OVER_FINISH`.
4. 장비 경매면 최소 올림폭(AU-6) `BID_STEP`.
5. 장수 없음 `NO_ACTOR`. 자기가 연 경매 `OWN_AUCTION`.
6. 장비 경매면 그 칸에 이미 비매품이 있음 `HAS_UNIQUE`(T4-22 §2.3의 같은 규칙).
7. 낼 금액: 지금 최고 입찰자가 자기면 차액, 아니면 전액. 내고 난 뒤 1000(AU-7)을 남기지 못하면 `NO_RESOURCE`.

성공하면 한 상태에서 함께 바꾼다.

- 입찰자 자원 −낼 금액.
- 이전 최고 입찰자가 다른 장수면 그 장수에게 맡긴 금액을 돌려준다.
- `highest = { generalId: bidderId, amount }`.
- 마감 연장(AU-5): 남은 시간이 한 달 이하이면 `closeTick`을 한 달 늦추되 `latestCloseTick`을 넘지 않는다.
- 즉시 거래가와 같으면 `closeTick`을 다음 월 경계로 당긴다.

입찰자·이전 입찰자의 소속 국가는 보지 않는다. 경매는 국가와 무관한 시장이다(원작도 보지 않는다). 재야도 입찰한다. AU-8에서 다르게 정하면 검사 5 뒤에 넣는다.

### 2.4 마감 `settleAuctions`

```ts
export function settleAuctions(state: WorldState, tick: number, rng: Rng): { state: WorldState; closed: AuctionResult[] };
```

월간 정산 경계에서 부른다(쟁점 T27-Q1).

1. `state.ext?.auction`이 없으면 입력을 그대로 내고 아무것도 하지 않는다. 끈 월드의 월간 결과와 해시가 같다.
2. `closeTick ≤ tick`인 열린 경매를 번호 오름차순으로 닫는다.
   - 최고 입찰자가 있으면 낙찰. 최고 입찰자에게 `lot`(자원이면 그 장수 자원 +수량, 장비면 T4-22 장착 함수), 주최자가 있으면 주최자에게 맡긴 입찰금.
   - 없으면 유찰. 주최자에게 `lot` 자원을 돌려준다. 중립 경매면 아무도 받지 않는다.
   - 받을 장수가 월드에 없으면(지금 경로상 생기지 않음) 예외를 낸다. 조용히 버리지 않는다.
3. 닫은 경매를 `closed` 앞에 넣고 30건을 넘으면 뒤를 자른다.
4. AU-2 (나)이면 그 다음에 중립 경매를 연다. 난수는 `runMonthly`가 받은 월간 스트림이다. 엔진(`apps/engine/src/monthly.ts:33`), 순수 재생(`packages/rules/src/replay.ts:59`), 시뮬레이터(`apps/engine/src/simulation.ts:63`)가 모두 `rngFor(seed, 'monthly', 연, 월)`을 넘기므로 서명을 바꾸지 않아도 세 곳이 같은 값을 쓴다. 이 단계는 `runMonthly`의 맨 끝에서만 소비한다. 그래서 뒤에 재해·사건 단계를 그 앞에 붙여도 그 단계의 결과는 경매 유무와 무관하다. 경매 조각이 없는 월드는 이 스트림을 소비하지 않는다.

`runMonthly`의 반환값에 `auctions: AuctionResult[]` 칸을 더한다. 끈 월드에서는 칸 자체를 넣지 않는다. T4-28이 이 값으로 장수 기록을 쓴다.

### 2.5 장비 경매 (AU-2 (다)·(라)일 때만, 계약 미정)

`openAuction`(§2.2)과 중립 경매(§2.4 4)는 자원 경매만 연다. 장비 경매는 생성 주체·주기·대상 선정·시작가(AU-9)와 값(AU-3)이 정해진 뒤 이 절에 아래를 써서 다시 검토받는다. 그 전에는 `AuctionKind`의 `equipment`와 `lot.equipmentKey`를 운영 경로에서 만들지 않으며 `validate`도 거부한다.

- 생성 판정: 정원 계산(같은 비매품을 단 장수 수와 열린 같은 장비 경매), 주최자·같은 장비 경매 하나 제한, 그 칸 비매품 보유 거부.
- 낙찰: 최고 입찰자 칸에 T4-22 장착 함수로 장착(T27-Q3), 이전 매매 장비 처리는 T4-22 EQ-4를 따름. 대금은 주최자가 장수면 주최자, 시스템이면 아무에게도 가지 않음.
- 유찰: 장비가 아무에게도 가지 않고 맡긴 금액이 없다.
- 시험: 생성 성공·정원 초과·이미 비매품 보유 거부, 낙찰 장착, 유찰, 입찰 올림폭(AU-6) 경계값.
