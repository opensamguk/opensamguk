# 작업 계획

> 흐름: 계획 (Claude) → 구현 (담당) → 리뷰 (구현하지 않은 쪽) · 결정: D-012
> 다음 할 일: `pnpm next` · 대기열: [단계 계획](../product/phases.md)
> Phase 2 대기열 분리: [T4-01 상세 계획](./T4-01.md) (제안, 도구 수정 전)

대기열 작업 하나마다 계획 문서 하나를 씁니다. 파일 이름은 작업 ID입니다 (`T1-03.md`).
계획·구현 기록·리뷰가 한 문서에 쌓이므로, 나중에 "왜 이렇게 됐나"를 이 문서 하나로 봅니다.

계획 문서 목록은 [문서 지도의 plans/ 절](../index.md#plans-작업-계획-계획--구현--리뷰-기록)에 있습니다.
M3 계획은 [T3-02](./T3-02.md), [T3-03](./T3-03.md), [T3-04](./T3-04.md), [T3-13](./T3-13.md), [T3-15](./T3-15.md)가 있습니다.
사용자 작업 T3-01(메일 발송 서비스)과 T3-12(공개 이미지 라이선스)는 계획 문서 없이 결정 기록으로 끝냅니다.

Phase 2 전체의 범위·계약·작업 분해는 [Phase 2 확장 기술 명세](./phase2-expansion.md) 한 문서에 둡니다. 작업 ID는 T4-01부터,
인수조건 ID는 AC-P2-01부터 씁니다. 작업마다 착수 전에 이 틀로 `T4-xx.md`를 따로 씁니다. 상세 계획의 기술 검토와
AC-P2 정식 반영 전에는 구현에 들어가지 않습니다(명세 §6.1). 2026-10-24 [D-030](../product/decisions.md#d-030-phase-2를-2026-10-24에-끝내도록-계획-채택과-codex-작업자-운용을-바꾼다-2026-10-24)부터 Codex 기술 검토(G-03)를 통과한 상세 계획은 사용자 개별 리뷰 없이 채택하고 같은 때 AC-P2 정식 반영과 단계 변경(`계획` → `구현`)을 합니다. 사용자 결정이 필요한 U·A 항목은 열어 두고 그 몫은 결정 전까지 구현하지 않습니다. 목표일 뿐 완료 보장이나 AC 면제가 아닙니다.
화면 상세 계획 제안: [T4-36 월간 영토 재생 화면](./T4-36.md) (U-20 정정(D-027)대로 멸망 국가 보존값을 쓴다. 계획 기술 검토는 조건부 수용. 보존 저장 계약과 정식 AC 채택 전이라 서버와 무관한 화면 부품만 만든다).

## 단계별로 하는 일

| 단계 | 누가 | 이 문서에서 | 대기열에서 |
| ---- | ---- | ----------- | ---------- |
| 계획 | Claude | "계획" 절을 쓴다 | 단계를 `구현`으로 |
| 구현 | 담당 (Codex 또는 Claude) | "구현 기록"을 쓴다 | 착수 시 `진행중`, 검증 후 `리뷰`로 |
| 리뷰 | 구현하지 않은 쪽 | "리뷰"를 쓴다 | 통과면 `완료` + 인수조건 ✅, 아니면 `구현` | <!-- lint-text-ignore C-5 -->

전체 명령 MVP(D-022)의 분해 제안은 [T4-02 상세 계획](./T4-02.md)과 [누락 명령 19개·미해결 원본 3개](./mvp-command-gaps.md)에 둡니다. 원고 `391432c`의 기술계약 검토를 통과한 제안이며 사용자 승인·구현 허가는 별도입니다. 대기열에는 올라가지 않았습니다.
계획을 쓰고 단계를 `구현`으로 바꿔도 선행 작업이 끝나기 전에는 착수하지 않습니다. 예를 들어 [T3-10 반응형 375px](./T3-10.md)은 계획 검토와 별개로 M2 관문이 끝난 뒤 시작합니다.

```markdown

> 대기열: T?-?? · AC: AC-M?-?? · 구현: Codex|Claude · 리뷰: Claude|Codex

## 계획 (Claude)
- 목표: 이 작업이 끝나면 무엇이 되는가 (AC 문장 그대로)
- 범위: 고칠 파일·패키지
- 하지 않는 것:
- 접근: 3~7단계
- 검증: AC의 검증 방법을 어떤 명령·테스트로 실행하나
- 상대 영역에 필요한 것: (예: 화면이 쓸 API 모양)

## 구현 기록 (담당)
- 바꾼 것:
- 계획과 달라진 점과 이유:
- 검증 결과: 실행한 명령과 결과

## 리뷰 (반대쪽)
- 결과: 통과 | 수정 필요
- 확인한 것: (계획 대비, 경계 규칙, 테스트, 보안)
- 고칠 것:
```

## 다른 계획에서 이어진 작업

다른 계획의 후속 절에서 나온 작업도 대기열에 행을 만들고 같은 틀로 씁니다. 원래 계획의 머리에는 `다음:`으로 링크를 겁니다. 예를 들어 [T3-16 태수·군사 임명과 도시 주재 화면](./T3-16.md)은 [T3-09 관직 주재 효과](./T3-09.md)의 화면 몫입니다.
