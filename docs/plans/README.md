# 작업 계획

> 흐름: 계획 (Claude) → 구현 (담당) → 리뷰 (구현하지 않은 쪽) · 결정: D-012
> 다음 할 일: `pnpm next` · 대기열: [단계 계획](../product/phases.md)

대기열 작업 하나마다 계획 문서 하나를 씁니다. 파일 이름은 작업 ID입니다 (`T1-03.md`).
계획·구현 기록·리뷰가 한 문서에 쌓이므로, 나중에 "왜 이렇게 됐나"를 이 문서 하나로 봅니다.

## 단계별로 하는 일

| 단계 | 누가 | 이 문서에서 | 대기열에서 |
| ---- | ---- | ----------- | ---------- |
| 계획 | Claude | "계획" 절을 쓴다 | 단계를 `구현`으로 |
| 구현 | 담당 (Codex 또는 Claude) | "구현 기록"을 쓴다 | 착수 시 `진행중`, 검증 후 `리뷰`로 |
| 리뷰 | 구현하지 않은 쪽 | "리뷰"를 쓴다 | 통과면 `완료` + 인수조건 ✅, 아니면 `구현` | <!-- lint-text-ignore C-5 -->

전체 명령 MVP(D-022)의 분해 제안은 [T4-02 상세 계획](./T4-02.md)과 [누락 명령 19개·미해결 원본 3개](./mvp-command-gaps.md)에 둡니다. 둘 다 1차 기술 검토의 수정을 반영한 제안이며 재판정 전이고 대기열에 올라가지 않았습니다.
