## 2. 화면 계약

### 2.1 진입

- 주소 `/w/$worldId/tournament`. 검색 칸 `seq`가 있으면 그 회차, 없으면 지금 대회(없으면 마지막 대회)를 연다. 모르는 `seq`는 서버 `NOT_FOUND`를 받아 그 자리에 안내하고 지금 대회 링크를 둔다.
- 위쪽 메뉴에 `토너먼트`를 둔다. 끈 월드에서도 메뉴는 보이고 화면이 안내한다. 메뉴를 숨기려면 응답 없이 기능 유무를 알아야 하는데 지금 `world.summary`에 그 칸이 없다(T32-Q1).

### 2.2 지금 대회 칸 (`tournament.current`)

| 서버 값 | 화면 |
| ------- | ---- |
| `enabled = false` | `EmptyState` `이 월드에서는 토너먼트를 열지 않습니다.` 아래 칸은 모두 없음 |
| `open = null`, `nextOpenAt` 있음 | `지금 열린 대회가 없습니다. 다음 대회는 {연}년 {월}월 정산에서 열립니다.` |
| `open = null`, `nextOpenAt = null` | `지금 열린 대회가 없습니다.` |
| `open` 있음 | 제목 `제{seq}회 {종목} 대회`, 등록 마감 `{연}년 {월}월 정산` + 예정 시각(`closesAtTime`, 오늘이면 시:분, 아니면 월/일 시:분), 참가 `{n} / {정원}명`, 참가자 표 |

- 종목 이름: `total` 종합, `leadership` 통솔, `strength` 무력, `intel` 지력.
- 예정 시각은 서버 값을 그대로 쓰고 tick으로 다시 계산하지 않는다(UI 지침 §1). RUNNING이 아니면 `—`와 이유(`월드가 멈춘 동안은 시각을 정할 수 없습니다`).
- 참가자 표: 이름, 국가(`NationBadge`, 재야는 `재야` 글자), 신청 순. 30명을 넘으면 접고 `모두 보기`로 편다. 능력치 열은 없다.

### 2.3 참가 신청

| 상태 | 표시와 조작 |
| ---- | ----------- |
| `mine = null` (장수 없음) | 점선 버튼 `참가 신청`, 누르면 `장수를 만들어야 참가할 수 있습니다.`와 장수 만들기 링크 |
| `canJoin.ok = false` | 점선 버튼, 누르면 이유. `ALREADY_ENTERED` 이미 신청했습니다, `TOURNAMENT_FULL` 정원이 찼습니다, `GENERAL_INACTIVE` 아직 활동할 나이가 아닙니다, `WORLD_NOT_RUNNING` 월드가 진행 중일 때만 신청할 수 있습니다 |
| `canJoin.ok = true` | 버튼 `참가 신청` |
| 보낸 뒤 PENDING 또는 `mine.pending` | 버튼 대신 `신청을 받았습니다. 다음 턴 처리 때 확정됩니다.` (`role="status"`) |
| APPLIED 또는 `mine.entered` | `참가가 확정됐습니다.` |
| REJECTED (`JoinStatus.code`) | 거절 코드별 문구(위 표와 같고 `TOURNAMENT_CLOSED`는 등록이 이미 닫혔습니다, `FEATURE_DISABLED`는 이 월드에서는 토너먼트를 열지 않습니다, `WORLD_CLOSED`는 월드가 끝나 신청을 처리하지 못했습니다, `ACTOR_INACTIVE`는 계정 이용이 제한되어 신청이 거절됐습니다)와 다시 보기. 모르는 코드는 신청이 거절됐습니다로 보이고 코드를 숨기지 않는다 |
| 신청이 `PRECONDITION_FAILED` 오류 | 이 월드에서는 토너먼트를 열지 않습니다. 기록되지 않았으므로 상태 조회를 하지 않는다. 서버 오류 변환기가 오류 이유 칸을 null로 덮으므로(`apps/server/src/trpc.ts:4-12`) 코드로만 가른다 |

- 요청 식별자: 버튼을 누를 때 `crypto.randomUUID()`로 만들고 `sessionStorage`의 `tournament.join:{worldId}:{seq}`에 둔다. 같은 회차에서 다시 보낼 때(네트워크 실패, `TOO_MANY_REQUESTS`)는 이 값을 그대로 쓴다. `Retry-After` 초가 지나기 전에는 버튼을 막고 남은 초를 보인다. APPLIED·REJECTED를 받아도 지우지 않고 그 회차가 닫힐 때까지 둔다. 새로고침 뒤에도 같은 식별자로 결과를 다시 묻기 위해서다. 다른 회차의 키는 새 신청 때 지운다.
- 처리 결과 받기: `join` 응답이 PENDING이면 `tournament.joinStatus({ worldId, requestId })`를 10초마다 묻는다. APPLIED나 REJECTED가 오면 멈추고 그 결과를 보인 뒤 `tournament.current`를 한 번 다시 받는다(참가자 표). 페이지가 보이지 않으면 묻기를 쉬고 다시 보이면 바로 한 번 묻는다. 엔진이 정원 초과·마감으로 거절해도 열린 화면이 REJECTED와 이유를 받는다.
- 다시 열 때: 저장된 식별자가 있으면 `joinStatus`로 묻는다. 없거나(다른 기기, 저장소 삭제) `NOT_FOUND`면 `current.open.mine.lastJoin`으로 PENDING·APPLIED·REJECTED와 거절 코드를 되살리고 PENDING이면 그 `requestId`로 위 묻기를 잇는다. 두 값이 다르면 서버의 `lastJoin`을 따른다.
- 이중 클릭은 진행 중 버튼 잠금으로 막고 서버 멱등이 한 번 더 막는다.

### 2.4 대진표 칸 (`tournament.get`)

- 끝난 대회(`DONE`)와 마지막 대회를 고르면 보인다. 열린 대회는 대진이 아직 없으므로 칸 대신 `등록이 닫히는 정산에서 대진과 결과가 한 번에 정해집니다.`
- 라운드마다 열 하나. 열 머리는 남은 인원으로 `결승`, `준결승`, `8강`, `16강`, 그 앞은 `{2^k}강`. 대진 크기가 1024라도 같은 규칙이다.
- 경기 칸은 위아래 두 줄(홈·원정)이다. `general`은 이름, `bye`는 `부전승`, `winnerOf`는 `앞 경기 승자`. 승자 줄은 굵은 글자와 `승` 표시를 함께 쓴다. 색만으로 승패를 나타내지 않는다. 부전승 경기에는 합 수가 없고 다른 경기는 `{n}합`.
- 칸이 화면보다 넓으면 대진표 영역 안에서만 가로로 움직인다. 페이지 전체 가로 스크롤을 만들지 않는다(AC-M3-08 방향).
- 64명을 넘는 대진은 처음에 16강부터 결승까지 열고 앞 라운드는 `앞 라운드 펼치기`로 연다. 1024명 대진도 한 번에 1023칸을 그리지 않는다.
- 아래에 도달 단계 표: 단계, 이름, 받은 금, 받은 경험. 단계 이름은 `우승`, `준우승`, `4강`, `8강`, `16강`.
- `CANCELLED` 대회는 `참가자가 모자라 열리지 않았습니다.`와 신청자 수만.

### 2.5 지난 대회 (`tournament.history`)

- 대진표 칸 위에 회차 고르기(`select`). 30개씩 받고 `더 보기`로 잇는다. 고르면 `?seq=`만 바뀌고 화면 구조는 그대로다.

| 상황 | 화면 |

| `current` 실패 | `ErrorState`와 다시 시도. 없는 월드면 `QueryError`의 월드를 찾을 수 없습니다 |

### 2.7 접근성

- 대진표는 라운드마다 제목이 있는 목록(`section` + `h3` + `ol`)이다. 경기 항목의 이름은 `8강 2경기, 관우 승, 장비, 7합`처럼 읽힌다.
- 신청 결과 문구는 `role="status"`·`aria-live="polite"`. 10초 재조회로 값이 그대로면 다시 읽지 않는다.
- 점선 버튼은 `aria-disabled="true"`이고 초점을 받으며 누르면 이유가 열린다(UI 지침 §1).

## 4. 시험

### 4.1 단위 (`tournament.test.tsx`, jsdom, `pnpm check`)

- `bracketLayout`: 2·3·5·8·16·1024명 대진의 라운드 이름, 64명 초과 접기, 읽기 문구.
- `joinRequest`: 같은 회차 재시도는 같은 UUID, 다른 회차는 새 UUID, 결과를 받아도 그 회차가 닫힐 때까지 남음, 다른 회차 키 삭제, `sessionStorage` 예외(사생활 모드)에서도 메모리로 이어 간다, `Retry-After` 남은 초.
- `OpenTournament`: 2.2·2.3 표의 모든 행을 가짜 응답으로 그리고 문구·버튼 상태·`aria` 속성을 확인한다. 화면이 참가 가능 여부를 스스로 판정하지 않는지(서버 `canJoin`만 따르는지) 확인한다.
- 결과 묻기: PENDING이면 가짜 시계로 10초마다 `joinStatus`를 부르고 REJECTED·APPLIED에서 멈춘다. 숨은 페이지에서는 쉬고 다시 보이면 바로 묻는다. 저장된 식별자가 없을 때 `lastJoin`으로 상태를 되살린다. `PRECONDITION_FAILED` 오류면 상태를 묻지 않는다.
- `BracketView`: 부전승·앞 경기 승자·승자 표시가 글자로 구분되는지, 색 없이도 승자를 읽을 수 있는지.

### 4.2 Chromium E2E (`e2e/tournament.spec.ts`, `pnpm e2e`)

`e2e/tournamentSeed.ts`가 토너먼트를 켠 시험 월드를 만든다(T4-31의 생성 인자, 주기 1달·등록 1달·정원 8). 다른 사용자 장수 둘은 API로 만들고 신청도 API로 넣는다. 엔진은 `holdLease`·`startEngine`(`e2e/game.ts:141`, `:190`)으로 돌린다.
