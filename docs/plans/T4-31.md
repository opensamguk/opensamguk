## 2. 입력과 설정

### 2.1 기능과 설정

- T2-26의 기능 목록에 `tournament`를 등록한다. `requires`와 `conflicts`는 비운다. 확장 명령(`ext`)과 독립이다(T31-Q1).
- 월드 생성 때 설정을 `featureData.tournament`에 복사한다. 재생은 파일이나 프리셋을 다시 읽지 않고 이 사본만 쓴다(T2-26 origin 3).

```ts
// packages/rules/src/tournament/config.ts
export interface TournamentConfig {
  cycleMonths: number; // 몇 달마다 여는지. 1~12 정수 (U-09)
  openMonth: number; // 1~12. (연 × 12 + 월 − 1) % cycleMonths === (openMonth − 1) % cycleMonths 인 달의 정산에서 연다
  entryMonths: number; // 등록 기간(달). 1~3 정수
  events: readonly TournamentEvent[]; // 돌아가며 쓰는 종목. 비지 않음, T4-54 목록 안 (U54-1)
  maxEntrants: number; // 2~1024 (T4-30 상한 이하)
  rewards: readonly { reach: 'champion' | 'final' | 'semifinal' | 'quarterfinal' | 'round16'; gold: number; experience: number }[]; // 0 이상 정수 (U-09)
}
export const tournamentConfigSchema: z.ZodType<TournamentConfig>;
```

- `checkOrigin`이 `tournamentConfigSchema`로 사본을 검사하고 어기면 월드 생성을 거부한다.
- 설정을 어디서 받는지(생성 인자, 프리셋 칸, 기본 묶음)는 T2-26의 U26-2 답을 따른다. 프리셋 칸으로 정해지면 `presetSchema`에 선택 칸 `tournament`를 더하는 한 줄이 필요하다. 이 파일은 명세 §7 표에 없고 T4-40도 같은 파일에 `truce`를 더하려 한다(T31-Q4).

### 2.2 입력 종류

| kind | 경로 | payload (zod, rules) | 결과 | 기능 |
| ---- | ---- | -------------------- | ---- | ---- |
| `tournament.join` | queued | `{ seq: number }`. 신청한 대회 번호 | APPLIED `{ seq, entrantCount }`, REJECTED `{ code, message }` | `tournament` |

- 행위자는 서버가 세션에서 정한다. payload에 사용자·장수 ID가 없다. `InputEvent.userId`는 세션 사용자이고 `generalId`는 엔진이 처리할 때 그 사용자의 장수로 채운다.
- 멱등 키는 C15대로 `tournament.join:<requestId>`다. `requestId`는 화면이 만드는 UUID다. 같은 키·같은 payload 재시도는 기존 행을 돌려준다. 같은 키에 다른 payload는 충돌로 거부한다. 재접속 조회는 T4-49가 만드는 요청 식별자 조회를 쓴다(T31-Q3).
- 처리 시점 재검사와 거절 코드.

| 순서 | 검사 | REJECTED `code` |
| ---- | ---- | --------------- |
| 1 | 기능이 켜져 있다 (T2-26 처리기 4단계) | `FEATURE_DISABLED` |
| 2 | 지금 열린 대회가 있고 `seq`가 그 번호다 | `TOURNAMENT_CLOSED` |
| 3 | 세션 사용자의 장수가 이 월드에 있다 | `NO_GENERAL` |
| 4 | 장수가 활동 중이다(`activeFromYear ≤` 처리 tick의 연도) | `GENERAL_INACTIVE` |
| 5 | 같은 대회에 아직 없다 | `ALREADY_ENTERED` |
| 6 | 참가자가 `maxEntrants` 미만이다 | `TOURNAMENT_FULL` |

  제재 계정은 API에서 막고(기존 세션 규칙) 처리 시점에 제재 상태를 다시 보는 방법은 T4-49 계약을 따른다. 국가 소속은 묻지 않는다(재야도 참가, U31-2).
- 재생: `apply`는 APPLIED만 받아 열린 대회 참가자 목록 끝에 장수 ID를 더한다. 처리 tick은 archive 3의 `input.tick`이다.

## 3. 계약

### 3.1 규칙 상태

```ts
// packages/rules/src/tournament/season.ts
export interface TournamentRuleState {
  nextSeq: number; // 1부터
  open: null | {
    seq: number;
    event: TournamentEvent;
    openedTick: number; // 연 정산의 경계 tick
    closesAtTick: number; // openedTick + entryMonths × TICKS_PER_MONTH
    entrants: number[]; // 장수 ID, 처리 sequence 순
  };
}
```

- 켠 월드의 `WorldState`에만 `tournament` 키가 생긴다. 끈 월드에는 키가 없어 해시가 같다(명세 C3, T2-26 목록 정규형).
- 자리는 T2-26 방식(기능 key가 상태 키를 하나 갖고 `initReplayState`가 시작값을 둠)을 따른다. 명세 §7은 `ext/state.ts` 반영 순서에 T4-31을 넣어 확장 상태 조각을 예상했다. 둘 중 하나로 정한다(T31-Q1).

### 3.2 월간 마감 계산

```ts
export interface TournamentMonthReport {
  opened: { seq: number; event: TournamentEvent; closesAtTick: number } | null;
  closed:
    | null
    | { seq: number; status: 'cancelled'; entrants: readonly number[] }
    | {
        seq: number;
        status: 'done';
        event: TournamentEvent;
        bracket: Bracket; // T4-30
        matches: readonly { round: number; index: number; result: TournamentMatchResult | null }[]; // 부전승은 null
        placements: readonly { generalId: number; reach: TournamentReach }[];
        rewards: readonly { generalId: number; gold: number; experience: number }[];
      };
}

export function settleTournament(
  state: WorldView,
  context: { tick: number; seed: string; config: TournamentConfig },
): { state: WorldState; report: TournamentMonthReport };
```

`tick`은 월간 정산의 경계 tick이다. 처리 순서는 아래로 고정한다.

1. 닫기. 열린 대회가 있고 `closesAtTick ≤ tick`이면 닫는다.
   1. 참가자 가운데 지금 상태에 없는 장수를 뺀다. 순서는 그대로다.
   2. 남은 참가자가 2명 미만이면 `cancelled`. 보상은 없다.
   3. 아니면 `createBracket(참가자, rngFor(seed, 'tournament', seq, 'bracket'))`.
   4. 라운드 오름차순, 경기 번호 오름차순으로 부전승이 아닌 경기마다 `resolveTournamentMatch({ event, home, away }, rngFor(seed, 'tournament', seq, 'match', round, index))`. 능력치는 이 순간 상태의 값이고 `level`은 U54-2 답 전에는 0이다.
   5. 도달 단계를 매긴다. 결승 승자 `champion`, 결승 패자 `final`, 준결승 패자 `semifinal`, 8강 패자 `quarterfinal`, 16강 패자 `round16`. 그보다 앞 라운드에서 진 장수는 단계가 없다. 대진 크기가 작으면 없는 단계는 건너뛴다.
   6. 보상은 장수마다 자기 도달 단계의 표 한 줄만 받는다. 원작처럼 단계별 보상을 더하지 않는다(U31-5). 금과 경험은 2147483647에서 멈춘다. 상태의 장수 금·경험에 더한다.
2. 열기. 닫은 뒤 열린 대회가 없고 이번 달이 2.1의 여는 달이면 `seq = nextSeq`, `event = events[(seq − 1) % events.length]`로 연다. `nextSeq`를 1 올린다.
3. 같은 정산에서 닫고 바로 여는 것을 허용한다. 등록 기간이 주기보다 길면 열린 대회가 있는 동안 여는 달이 와도 건너뛴다.

`rngFor(seed, 'monthly', …)` 스트림은 쓰지 않는다. 그래서 켠 월드에서도 월간 정산 자체의 난수 소비는 끈 월드와 같다.

### 3.3 부르는 자리

`settleTournament`는 엔진 월간 정산과 순수 재생이 같은 순서로 불러야 한다. 지금 두 자리는 `apps/engine/src/monthly.ts:33`과 `packages/rules/src/replay.ts:59`이고 둘 다 `runMonthly` 바로 뒤다. T2-26의 `RuleFeatureDefinition`에는 월간 뒤 단계 자리가 없다. 기능 목록에 `afterMonthly?(state, { tick, seed, data })` 자리를 더해 달라고 T2-26에 요청한다. 받아들여지지 않으면 두 자리에 `hasRuleFeature(state, 'tournament')` 분기 한 줄씩을 더하며 그때는 명세 §7 `replay.ts` 행에 T4-31을 넣어야 한다(T31-Q2).

```prisma
  openedTick     Int
  closesAtTick   Int
  closedTick     Int?
  closedSequence Int?     // 닫은 월간 정산의 action sequence
  entrantCount   Int      @default(0)
  championId     Int?
  runnerUpId     Int?
  world          World    @relation(fields: [worldId], references: [id], onDelete: Cascade)
  entries        TournamentEntry[]
  matches        TournamentMatch[]
  @@id([worldId, seq])
}

model TournamentEntry {
  worldId      String
  seq          Int
  generalId    Int
  inputEventId BigInt   @unique
  sequence     Int      // 처리한 입력의 action sequence
  reach        String?  // 3.2의 단계, 닫기 전과 단계 없음은 null
  rewardGold   Int?     // 보상을 저장한 뒤에만 값이 있다
  rewardExperience Int?
  @@id([worldId, seq, generalId])
}

model TournamentMatch {
  worldId     String
  seq         Int
  round       Int
  index       Int
  homeId      Int?     // 부전승 경기도 home은 있다
  awayId      Int?     // 부전승이면 null
  winnerId    Int
  decidedBy   String?  // 부전승이면 null
  exchanges   Json?    // T4-54 합 기록. 공개 범위는 U31-4
  @@id([worldId, seq, round, index])
}
```

- 장수별 1회는 `TournamentEntry`의 기본키 `(worldId, seq, generalId)`로 막는다. 보상 칸은 그 행에 한 번만 쓴다. migration에 CHECK를 둔다. `rewardGold`와 `rewardExperience`는 함께 null이거나 함께 0 이상이다. `status = 'OPEN'`이면 `closedTick`·`closedSequence`·`championId`가 null이다.
- 외래키: `TournamentEntry (worldId, generalId)`와 `TournamentMatch`의 장수 칸은 `General (worldId, id)`를 가리킨다. 지금 장수 행은 지워지지 않지만 지워지는 경로가 생기면(해산·사망) 그 작업이 삭제 규칙을 정한다.
- migration은 명세 C8대로 병합 직전 최신 main에서 T4-28 뒤에 새로 만든다.


| ---- | ---- |
