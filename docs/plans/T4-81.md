# T4-81 편집 캔버스의 관리자 콘솔 연결

> 대기열: T4-81 · AC: AC-P2-27 (지도 편집의 콘솔·초안·게시 화면) · 구현: Claude · 리뷰: Codex

> 선행: [T4-80](./T4-80.md) 편집 캔버스, T4-78 초안·게시 API, [T3-06](./T3-06.md) 관리자 콘솔 · 이어지는 작업: [T4-87](./T4-87.md) · 기준: main `3e5b52a`

## 계획 (Claude)

### 목표

운영자가 관리자 콘솔에서 지도 판을 복제해 T4-80 캔버스로 고치고 초안으로 저장한 뒤 검증을 통과한 판만 게시한다. 다른 운영자가 먼저 저장했으면 늦은 저장이 거부되고 화면이 그 사실과 다음 할 일을 보여 준다. 권한 없는 계정은 편집 화면에 들어오지 못하고 API를 직접 불러도 거부된다.

AC-P2-27 전체가 아니다. 지도 밖 자원의 표 편집은 [T4-87](./T4-87.md), 서버 권한·감사·판 불변은 T4-78, 새 판으로 월드 만들기는 T4-79 몫이다. 이 작업이 끝나도 AC-P2-27을 완료로 세지 않는다.

- 바탕 그림 올리기와 미리 보기 (T4-83·T4-84)

### main 기준 사실 (`3e5b52a`)

- 편집기는 `MapEditorPage`(`apps/web/src/mapEditor/MapEditorPage.tsx:23`)가 파일 선택으로 지도를 받아 내부 `Editor`(`:102`)에 넘긴다. `Editor`는 `useReducer(editorReducer, initial, initialEditor)`(`:103`)로 상태를 쥐고 밖으로 내보내는 값이 없다. 서버 판을 넣고 바뀐 지도를 읽으려면 `Editor`에 알림 하나를 더해야 한다.
- 편집 상태는 `map`·`past`·`future`·`selection`이고(`apps/web/src/mapEditor/editor.ts:15-20`) 기록은 200개까지다(`:42`). 저장 기준을 따로 두지 않는다.
- 검증은 매 편집 뒤 `validateMap(map)`(`MapEditorPage.tsx:110`)을 다시 돌린다. 지금은 화면 안 임시 함수(`apps/web/src/mapEditor/validate.ts:35`)이고 시나리오 참조 검사가 없다. 오류가 있어도 내려받기는 막지 않고 안내만 한다(`MapEditorPage.tsx:213-216`).
- 읽기는 `parseMapJson`(`apps/web/src/mapEditor/contract.ts:149`), 쓰기는 키 순서를 고정한 `serializeMap`(`:188`)이다. 지금 형식을 읽으면 `meta`를 버리고 `$comment`를 둔다(T4-80 계획 형식 절).
- `/dev/map-editor`는 개발 모드에서만 경로 정의를 만든다(`apps/web/src/router.tsx:250-258`, `:287`).
- E2E는 `resources/map/che.json`을 파일 선택으로 넣는다(`e2e/mapEditor.spec.ts:7`, `:72-74`). T4-77이 이 파일을 지운다.
- 서버 오류 형식은 모든 오류의 `data.reason`을 `null`로 지운다(`apps/server/src/trpc.ts:9`). 오류에 검증 목록을 실어 보낼 수 없다.
- 변경 요청은 사용자당 1분 120번이고 넘으면 `TOO_MANY_REQUESTS`와 `Retry-After`다(`apps/server/src/trpc.ts:18-25`).
- 늦은 저장의 선례는 예턴 저장이다. 서버는 오류가 아니라 `{ ok: false, reason: 'STALE', revision, slots }`를 돌려주고(`apps/server/src/routers/turns.ts:48`) 화면은 저장하지 않은 편집을 탭 `sessionStorage`에 둔다(`apps/web/src/turns/useTurnDraft.ts:37`, `:113`).

### 접근

1. `Editor`를 내보낸다. 받는 값에 `onMapChange(map)`, `readOnly`, `toolbarStart`(위쪽 띠 자리)를 더한다. `readOnly`면 도구는 선택과 화면 배율만 남고 도시 칸·선 칸 입력이 꺼진다. `/dev/map-editor`는 세 값을 넘기지 않아 지금과 같다.
2. T4-76 검증기로 바꾼다. `validate.ts`의 `validateMap`을 `@opensamguk/rules`의 지도 검증기로 바꾸고 결과를 지금 `Issue` 모양으로 옮기는 얇은 함수만 남긴다. 패키지 경계 예외(T4-80 계획의 E3)가 T4-76에서 들어와 있어야 한다.
3. 공통부를 만든다. 목록 화면, 초안 상태(`draft.ts`의 순수 함수 + `useResourceDraft` 훅), 위쪽 띠, 게시 확인, 늦은 저장 안내. 순수 함수는 단위 시험으로 덮는다.
4. `MapDraftEditor`가 `admin.resource.get`으로 판을 받아 `parseMapJson`으로 읽고 `Editor`에 넣는다. 바뀐 지도는 `serializeMap`으로 바꿔 초안 공통부에 넘긴다. 저장할 내용은 이 글자열을 다시 읽은 JSON이다.
5. 경로와 가드를 T3-06 관리자 경로 아래에 단다. 화면 코드는 관리자 청크 안에서도 다시 나눠 편집 화면에 들어갈 때만 캔버스를 불러온다.
6. E2E를 쓴다. 관리자 계정 준비는 T3-06의 `e2e/adminSetup.ts`를 쓴다.

### 경로와 가드

| 경로 | 화면 |
| ---- | ---- |
| `/admin/resources?kind=map` | 자원 판 목록. `kind`가 없으면 `map` |
| `/admin/resources/map/$name/$version` | 지도 판 편집. 게시한 판이면 읽기 전용 |

- 키 `<이름>@<판 번호>`(설계 C-M1)는 주소에서 `$name`·`$version` 둘로 나눈다. `@`를 주소에 넣지 않으려는 것이다. 이름에 `/`가 들어갈 수 있는지는 T4-78에 묻는다(Q-81-4).
- `$kind` 칸은 `map`·`scenario`·`unit-set`·`stat-rules`·`portrait-map`이다. 서버 종류 이름 `MAP`·`SCENARIO`·`UNIT_SET`·`STAT_RULES`·`PORTRAIT_MAP`(C-M1)과 일대일이다. 모르는 값이면 없는 주소 화면이다.
- 가드는 T3-06의 `/admin` 가드를 그대로 탄다. 무인증이면 로그인 화면(`next` 유지), 관리자가 아니면 404와 같은 화면이다. 이 작업이 가드를 따로 만들지 않는다.
- 자원 편집 권한이 관리자 전체가 아니면(Q-81-2, 사용자 결정 U-81-1) 목록은 보이되 복제·저장·게시 버튼이 점선이 되고 누르면 자원 편집 권한이 없다는 이유를 보인다. 서버가 `FORBIDDEN`을 주면 같은 상태로 바꾼다.
- 콘솔 메뉴에 자원 한 줄을 더한다. 위치는 T3-06이 만든 관리자 메뉴의 끝이다.

### 자원 판 목록 (공통)

```text
┌ 자원 판 ─ 지도 · 시나리오 · 병종 · 능력치 규칙 · 초상 대응표 (탭) ───────────────────────┐
│ 이름 che                                                                                │
│  판  상태    해시      복제 원본  만든 사람  고친 시각         게시 시각         [동작]  │
│  1   게시    3fa9c2e1  (내장)     초기화     2026-10-23 10:00  2026-10-23 10:00  열기 복제 │
│  2   초안    -         che@1     관리자 a1b2  2026-10-24 14:02  -                 열기 복제 │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- 탭은 `role="tablist"`이고 고른 탭이 주소 `kind`에 남는다. 이름별로 묶고 판 번호 내림차순이다.
- 상태는 `Tag`로 글자와 색을 함께 쓴다. 초안, 게시 둘이다. 해시는 앞 8자를 보이고 `title`에 전체를 둔다. 초안에는 해시가 없다(게시 때 정해진다).
- 만든 사람은 서버가 주는 표시값만 쓴다. T3-05가 감사에 사용자 UUID만 남기므로 화면도 이메일을 보이지 않는다. 표시값이 없으면 사용자 ID 앞 8자다.
- [복제]는 대화 상자를 연다. 같은 이름의 다음 판(기본) 또는 새 이름의 1판을 고른다. 보내면 새 초안의 편집 화면으로 간다. 요청마다 `idempotencyKey`를 화면에서 만들고(`crypto.randomUUID()`) 응답을 못 받아 다시 보낼 때는 같은 키를 쓴다. T3-06과 같은 규칙이다.
- 시각은 Asia/Seoul로 보이고 `title`에 ISO 원문을 둔다(T3-06 문구와 표시).
- 빈 종류는 `EmptyState`, 목록을 못 받으면 `ErrorState`와 다시 시도다.

### 지도 편집 화면

```text
┌ 위쪽 띠: che@2 · 초안 · revision 5 · 마지막 저장 14:02 · 저장하지 않은 편집 3 · 검증 오류 1 ┐
│          [초안 저장] [게시] [이 판 복제] [v2 JSON 내려받기] [밑그림 PNG 내려받기] [지도 파일 불러오기] │
├ T4-80 편집기 (도구 · 캔버스 · 고른 것 · 검증) ─────────────────────────────────────────────┤
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- 판을 받으면 `parseMapJson`으로 읽는다. 읽지 못하면 편집기를 띄우지 않고 이유와 [JSON 내려받기]만 둔다. 서버가 검증한 판이라 생기면 안 되는 일이지만 T4-80 형식과 T4-76 형식이 어긋날 때를 대비한다.
- 저장하지 않은 편집 수는 저장 기준 지도와 지금 지도의 `serializeMap` 글자열이 다른지로 정한다. 같으면 0, 다르면 저장 뒤 쌓인 편집 기록 수다. 되돌리기로 저장 상태로 돌아오면 0이 된다.
- [지도 파일 불러오기]는 T4-80의 파일 불러오기를 이 초안 위에 얹는다. 불러온 지도는 편집 한 번으로 쌓이고 되돌릴 수 있다. 기록을 비우지 않는다는 점이 `/dev/map-editor`와 다르다. 늦은 저장 뒤 내 편집을 다시 얹을 때 쓴다(아래).
- 지도의 `id`·`name`은 판 이름과 별개다. 이 화면은 `id`를 판 이름으로 바꾸지 않는다. 둘의 관계는 T4-76·T4-78이 정한다(Q-81-6).
- 게시한 판은 읽기 전용이다. 위쪽 띠에 게시한 판은 고칠 수 없으니 복제해 새 초안을 만든다는 안내와 [이 판 복제]를 둔다. 내려받기 두 개는 그대로 쓴다. 밑그림 PNG는 게시한 판에서 내려받는 것이 T4-83의 입력이다.
- 검증은 T4-76 지도 검증기를 매 편집 뒤 돌린다. 시나리오 참조 검사에 넣을 시나리오는 T4-76·T4-78이 정한 범위다(Q-81-3). 정해지기 전에는 복제 원본 판을 쓰는 게시 시나리오를 `admin.resource.list`로 받아 넣고 목록 머리에 어느 시나리오 기준인지 적는다.

### 초안 저장

- [초안 저장]은 저장하지 않은 편집이 있을 때만 켜진다. 없으면 점선이고 누르면 저장할 편집이 없다는 이유를 보인다. 검증 오류가 있어도 저장한다. 초안은 고치는 중인 판이다.
- 보내는 값은 `{ key, revision: 기준 revision, content }`다. 성공하면 기준 revision과 저장 기준 지도를 바꾸고 편집 수를 0으로 한다. 되돌리기 기록은 남긴다. 저장 뒤 되돌리면 다시 저장할 편집이 생긴다.
- 저장 중에는 버튼이 저장 중으로 바뀌고 다시 누를 수 없다. 편집은 계속할 수 있다. 저장 중에 생긴 편집은 성공 뒤에도 저장하지 않은 편집으로 남는다.
- 저장하지 않은 편집은 탭 `sessionStorage`에 둔다. 키는 사용자 ID, 자원 키, 기준 revision이다. 새로 고치거나 다시 로그인해 같은 판을 열면 서버 판의 revision이 키와 같을 때만 이어서 편집할지 묻는다. 다르면 아래 늦은 저장 안내로 간다. 예턴 편집 초안(`useTurnDraft.ts:37`)과 같은 방식이다.
- 저장하지 않은 편집이 있으면 다른 콘솔 화면으로 갈 때 묻고(TanStack Router 이동 막기) 창을 닫을 때 브라우저 경고를 띄운다.
- 로그인이 풀리면 [다시 로그인] 링크를 보이고 탭 초안은 남긴다. `TOO_MANY_REQUESTS`면 `Retry-After`의 남은 시간을 보인다(T3-06과 같다). `FORBIDDEN`이면 권한 없음 상태로 바꾸고 탭 초안은 남긴다.

### 늦은 저장 거부

두 운영자가 같은 초안을 고치다 늦게 저장한 쪽이 거부된다(C-M4). 화면은 합치지 않는다.

```text
┌ 다른 곳에서 이 초안이 먼저 저장되었습니다. 내 편집 3건은 저장되지 않았습니다.          ┐
│ 서버 판: revision 6 · 14:05 저장 · 저장한 사람 관리자 c3d4                              │
│ [내 편집 JSON 내려받기] [최신 초안 불러오기] [닫기]                                       │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- 안내는 `role="alert"`로 위쪽 띠 바로 아래에 고정한다. 서버 판의 revision, 저장 시각, 저장한 사람 표시값(있으면)을 보인다.
- [내 편집 JSON 내려받기]는 지금 화면의 지도를 `serializeMap`으로 내려받는다. 파일 이름에 판 키와 기준 revision을 넣는다.
- [최신 초안 불러오기]는 내 편집을 버린다는 확인을 거친 뒤 서버 판으로 편집기를 다시 만든다. 되돌리기 기록과 탭 초안도 지운다.
- [닫기]는 안내만 접는다. 편집은 이어서 할 수 있지만 [초안 저장]은 점선이 되고 누르면 최신 초안을 먼저 불러와야 한다는 이유를 보인다. 같은 기준 revision으로 다시 보내지 않는다.
- 내 편집을 살리려면 JSON을 내려받고 최신 초안을 불러온 뒤 [지도 파일 불러오기]로 그 파일을 얹고 저장한다. 다른 운영자의 편집을 덮는다는 사실을 운영자가 알고 고르는 길이다. 덮어쓰기 버튼은 따로 두지 않는다.
- 같은 판이 그 사이 게시되었으면(다른 운영자가 저장 뒤 게시) 안내 문장을 이 초안은 이미 게시되어 고칠 수 없다로 바꾸고 [최신 초안 불러오기] 대신 [이 판 복제]를 둔다.
- 거부를 어떻게 받는지는 T4-78이 정한다. 예턴 저장처럼 결과 `{ ok: false, reason: 'STALE', ... }`로 오면 그 값을 쓰고 `CONFLICT` 오류로 오면 `admin.resource.get`을 다시 불러 서버 판의 revision과 시각을 얻는다. 화면은 둘 다 처리하되 시험은 T4-78이 고른 한 가지로 한다.

### 게시

- [게시]는 저장하지 않은 편집이 없고 화면 검증 오류가 0일 때만 켜진다. 아니면 점선이고 누르면 먼저 초안을 저장해야 한다, 또는 검증 오류 N건을 고쳐야 한다는 이유를 보인다.
- 누르면 확인 대화 상자를 연다. 판 키, revision, 검증 결과, 그리고 게시한 판은 고칠 수 없고 새 월드를 만들 때 고를 수 있으며 진행 중인 월드는 바뀌지 않는다는 문장을 적는다. 확인 버튼 이름은 게시다.
- 보내는 값은 `{ key, revision }`이다. 성공하면 읽기 전용으로 바꾸고 해시와 게시 시각을 보인다.
- 서버 검증이 실패하면 서버가 준 목록을 화면 검증 목록 자리에 보이고 목록 머리에 서버 검증 결과라고 적는다. 화면 검증과 서버 검증이 다르면 서버가 기준이다. 같은 목록 항목을 누르면 T4-80처럼 대상을 고른다.
- 게시 요청이 늦은 revision이면 늦은 저장 안내와 같은 흐름이다.
- 응답을 못 받아 다시 보낼 때는 같은 `{ key, revision }`을 보낸다. 이미 게시된 같은 revision이면 성공으로 받는다는 것을 T4-78에 요구한다(Q-81-5).

### 문구

- 버튼은 동사로 쓴다. 초안 저장, 게시, 이 판 복제, 최신 초안 불러오기.
- 상태는 서버 값과 일대일이다. DRAFT 초안, PUBLISHED 게시.
- 오류와 안내는 [글쓰기 규칙](../writing-style.md)을 따르고 색만으로 구분하지 않는다.

### 상대 영역에 필요한 것

#### T4-78 (Codex) 초안·게시 API

이름은 제안이다. T4-78이 정한 이름과 모양을 화면이 따른다. 판 키는 C-M1의 `<이름>@<판 번호>`다.

```ts
admin.resource.list({ kind? }) → [{
  key, kind, name, version, status: 'DRAFT' | 'PUBLISHED',
  revision, hash: string | null, baseKey: string | null, // 복제 원본, 내장 판은 null
  mapKey: string | null,                                  // 시나리오 판만, 함께 쓸 지도 판
  createdBy: { userId: string | null; label: string },     // 초기화 SQL이 넣은 판은 userId null
  updatedBy: { userId: string | null; label: string } | null,
  createdAt, updatedAt, publishedAt: string | null,
}]
admin.resource.get({ key }) → 위 한 행 + { content }        // content는 저장한 원문, 모르는 키도 그대로
admin.resource.clone({ key, name?, idempotencyKey }) → { key, revision }
  // name 없으면 같은 이름의 다음 판. 감사 resource.clone
admin.resource.saveDraft({ key, revision, content })
  → { ok: true, revision, updatedAt } | { ok: false, reason: 'STALE', revision, updatedAt, updatedBy }
  // 늦은 저장. 게시된 판이면 reason 'PUBLISHED'. 감사 resource.draft.save
admin.resource.publish({ key, revision })
  → { ok: true, key, hash, publishedAt }
  | { ok: false, reason: 'INVALID', issues: Array<{ code, message, target }> }
  | { ok: false, reason: 'STALE', revision }
  // 같은 revision이 이미 게시되었으면 ok true와 같은 hash. 감사 resource.publish
```

- 거부 결과를 오류가 아니라 결과 합집합으로 달라는 이유는 `trpc.ts:9`가 오류의 `data`를 지우기 때문이다. 검증 목록은 오류에 실을 수 없다. 늦은 저장은 예턴 저장(`turns.ts:48`)과 모양을 맞춘다.
- `issues`의 모양은 T4-76 검증기의 결과와 같아야 화면이 서버 목록과 화면 목록을 같은 부품으로 그린다.
- 권한: 무인증 `UNAUTHORIZED`, 관리자 아님 `FORBIDDEN`, 자원 편집 권한 없음 `FORBIDDEN`. 읽기(`list`·`get`)를 자원 편집 권한 없는 관리자에게 열지 정해 달라(Q-81-2).
- 화면이 자원 편집 권한을 미리 알 길. `admin.whoami()`에 `resourceEdit: boolean`을 더하는 안을 낸다. 권한을 나누지 않으면 필요 없다.
- `content` 크기. 시나리오 1030은 장수 491행이다. 저장 요청 한 번의 크기 한도를 정해 달라. 화면은 한도를 넘으면 보내기 전에 이유를 보인다.
- `createdBy`·`updatedBy`의 `label`. 감사에는 UUID만 남기는 T3-05 원칙에 맞춰 이메일이 아닌 값이어야 한다.

#### T4-76 (Codex) 형식·검증기

- 지도 검증기의 결과 모양 `{ code, message, target }`과 `target`의 종류. T4-80 화면은 도시 번호 또는 층과 선 번호를 쓴다(`validate.ts:21`).
- 지도 검증의 시나리오 참조 검사에 넣을 시나리오의 범위(Q-81-3).
- 패키지 경계 예외 E3를 `apps/web/src/mapEditor/**`와 함께 `apps/web/src/admin/resources/**`, `apps/web/src/admin/maps/**`에도 열어 달라. T4-87이 종류별 검증기를 쓴다.

#### T3-06 (Claude) 관리자 콘솔

- 관리자 경로를 어느 파일에 두는지와 메뉴 위치. 이 작업은 그 파일에 경로 두 줄과 메뉴 한 줄만 더한다.
- `e2e/adminSetup.ts`가 관리자 계정을 둘 이상 만들 수 있어야 한다.
