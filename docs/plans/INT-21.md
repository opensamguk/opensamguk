# INT-21 도시 규모와 폐허 복구

상태: 구현 중. AC-INT-21과 D-048에 연결한다. 계획은 Claude의 2026-11-06 보완안을 Codex가 검토했다. 실제 통합 검사와 독립 리뷰 전에는 완료로 세지 않는다.

## 범위

기존 월드와 게시 자원은 보존한다. 새 지도에서 무(0)와 경(9)을 받으며 시나리오가 생성 시 도시 규모와 폐허 상태를 지정한다. 관문의 내부 level 0은 무 도시와 구분한다. 원래 규모는 폐허가 되어도 바뀌지 않는다.

소·중·대·특 사이의 규모 변경은 같은 지도의 목표 규모 도시들의 최대치를 필드별로 평균 내고 정수로 반올림한다. 시작값은 상한을 넘는 항목만 낮춘다. 같은 규모를 지정하면 도시 고유 최대치를 유지한다. 다른 기존 규모도 같은 방식으로 계산하며 표본이 없으면 검증 오류로 돌린다.

무의 최대치는 주민 10,000과 나머지 다섯 항목 200이다. 시작값은 주민 1,000과 수비·성벽 100이며 나머지는 0이다. 경은 낙양·장안만 허용한다. 기존 특 도시를 경으로 바꾸면 그 도시의 최대치에 같은 지도의 대→특 평균 차이를 더한다. 지도에 이미 경으로 지정된 도시의 최대치는 유지한다.

SAN10에서 경의 주민 최대치는 낙양 987,925명과 장안 744,525명이다. 낙양의 특 주민 최대치 835,700명을 보존하여 계산한 값이다. integration 지도는 각각 986,214명과 742,814명이며 che는 987,314명과 743,914명이다. 같은 원판의 모든 대·특 도시를 평균에 포함한다.

평균 차이는 정수 합과 표본 수로 계산한 뒤 한 번 반올림한다. 각각의 평균을 실수로 만든 뒤 빼서 반 정수 경계가 달라지는 경우를 막는다. 폐허 내림으로 최대치가 0이 되면 새 기능을 켠 월드의 계략 계산은 해당 개발 비율을 0으로 읽는다. 기존 월드의 공식과 난수 소비는 유지한다.

## 구현

`world/map/cityScale.ts`의 순수 변환을 legacy 지도 도시와 운영 지도 앵커가 함께 쓴다. 시나리오의 선택 자료를 해석하여 규모·최대치·초기값을 계산하고 영향받은 도시의 규모와 100% 최대치를 `WorldInit.cityScale`에 고정한다. 새 필드가 없는 기존 생성 결과에는 새 키를 넣지 않는다. 운영 지도 검사는 변환된 앵커와 생성 상태를 계속 엄격히 비교한다.

선택 규칙 `city-scale-v1`은 별도 지도 기능에 의존하지 않는다. `WorldState.cityRuins`에 폐허의 도시 키·단계·100% 최대치를 둔다. 월간 기능의 마지막에서 소유 국가와 주민·농업·상업의 90% 조건을 검사한다. 최대치를 10% → 40% → 70% → 100%로 한 달에 한 단계 올리며 마지막에는 폐허 항목을 지운다. 현재값을 보상으로 올리지 않으며 난수를 쓰지 않는다.

`World.cityRuinsState`는 새 nullable JSON 칸으로 저장한다. 엔진의 생성·적재·복제·월 정산·재생 내보내기·상한 검사와 서버의 조회 상태를 연결한다. 기능이 꺼진 월드의 저장값은 NULL이고 실행 상태에는 새 키가 없다. 기능이 켜진 월드의 누락·잘못된 도시·최대치 불일치는 거부한다.

최초 저장은 `world/persistence.ts`, 일반 재적재는 `worldLoader.ts`, 내보내기와 상한 검사는 `replay.ts`·`capsGate.ts`까지 연결한다. MAP 검사뿐 아니라 `validate/scenario.ts`와 `resourceEditor/validate/scenario.ts`의 SCENARIO 게시 방향도 같은 계산을 거친다. 지도 문맥 부재와 잘못된 문맥의 기존 검사 상태는 유지한다.

도시·지도·공개 지도 응답에는 새 월드에서만 폐허의 복구 비율을 표시한다. 기존 권한과 공개 지도 지연을 지킨다. 실제 AppRouter 타입과 응답 예시를 Claude에게 넘기며 화면은 Claude가 구현한다. 새 출처 입력 필드를 필수로 추가하지 않는다.

## 순서와 검증

| 순서 | 변경과 완료 조건 |
| --- | --- |
| 1 | 공유 변환·시나리오·지도 schema와 두 검증기. 세 지도 경 최대치 전 항목, 목표 평균, 같은 규모 보존, 무 상수, 없는 표본, 중복·관문·잘못된 경 대상 거부를 검사한다. |
| 2 | 생성·운영 지도 엄격 검사·규칙 등록·폐허 정산·clone. 원생성 변조 거부, 정확한 90% 경계, 한 달 한 단계, 공백지 무복구, 해제와 복제 독립성을 검사한다. |
| 3 | DB migration·엔진 생성/적재/저장/재생·서버 조회. 실제 PG에서 생성 후 정산·재적재와 DB 없는 별도 재생의 해시를 비교한다. 기존 migration 고정본과 기존 월드 해시를 확인한다. |
| 4 | 새 191 확장 판에 낙양 경·폐허와 장안 경을 넣는다. 기존 도시를 임의로 무로 내리지 않는다. 무와 다른 규모 변경은 사용자 시나리오 생성 통합 시험으로 확인한다. |
| 5 | `pnpm check`, 변경에 맞는 실제 통합·브라우저 검사와 독립 리뷰를 통과한 뒤 정상 PR 병합한다. Claude의 표시 연결이 미검증이면 AC를 완료로 바꾸지 않는다. |

T4-79의 정확한 게시 판 선택을 사용한다. 기존 프로필·게시 1판을 덮어쓰지 않는다. 여러 확장 기능과 45병종을 한 월드로 묶는 최종 프로필은 별도 통합 검증도 거친다.

새 프로필은 기존 integration 기준 `expanded-191-v3`와 분리한다. `expanded-191-v4`라는 새 키의 지도·시나리오·병종·능력치·초상 다섯 ref를 명시하고 기존 featureData를 바탕으로 새 기능을 추가한다. `worldCreateOptions.ts`의 새 프로필 반환과 `admin/createRequests.ts`의 정확 선택 검사를 함께 연결한다. 실제 관리자 HTTP → 생성 큐 → 엔진 경로에서 다섯 ref와 감사·초기화 준비가 선택한 판에 고정됨을 확인한다. 기존 프로필의 정확 선택 검사는 느슨하게 바꾸지 않는다.
