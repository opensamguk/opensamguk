## 계획 (Claude)

### 목표

경매를 켠 월드에서 장수가 경매 화면을 열어 열린 경매의 물건, 치르는 자원, 현재 최고가와 입찰자, 마감 연월, 서버가 계산한 다음 입찰가를 본다. 입찰하면 처리 중으로 보이다가 엔진 결과가 오면 최고 입찰자가 되거나 거절 이유를 본다. 다른 장수가 더 높게 부르면 내 맡긴 금액이 돌아온 것을 목록에서 본다. 장수가 경매를 열 수 있는 월드(AU-2)면 열기 칸에서 연다. 마감된 경매는 지난 경매 표에 낙찰자와 값이 남는다. 끈 월드에는 메뉴가 없다.

## 2. 화면 계약

### 2.1 진입

- 주소 `/w/:worldId/auction`. 직접 열기·새로 고침이 된다.
- 메뉴 `경매`는 `world.summary`의 경매 켜짐 칸이 참일 때만 그린다. 끈 월드에서 주소로 오면 서버의 꺼진 기능 응답을 빈 상태 `이 월드에서는 경매를 하지 않습니다.`로 보인다.

### 2.2 배치

```text
┌ 열린 경매 ─────────────────────────────────────────────────────────────────┐
│ 번호 물건        치름  주최    최고가(입찰자)   즉시   마감       내 상태      │
│ 3    쌀 1,000    금    조조    1,200 (유비)     1,500  191년 4월  맡김 1,200  │
│      [입찰 금 1,212 이상] [     ] [부르기]  연장 가능                        │
├ 경매 열기 (AU-2) ───────────────────────────────────────────────────────────┤
│ 종류 [쌀 팔기▾] 거래량 [ ] 시작가 [ ] 즉시 거래가 [ ] 마감 [ ]개월 [열기]     │
│ 거래량 100~10,000 · 시작가 50~200% · 즉시 거래가 110~200% · 쌀 500은 남김     │
├ 지난 경매 (최근 30건) ───────────────────────────────────────────────────────┤
│ 번호 물건 치름 낙찰자 값 마감 연월 (유찰은 낙찰자 칸에 유찰)                   │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 열린 경매 표는 `DataTable`이다. 기본 정렬은 마감이 이른 순. 금액·수량은 고정폭 숫자와 천 단위 쉼표.
- 쌀 팔기는 금으로, 쌀 사기는 쌀로 부른다. 두 종류 모두 높게 부른 쪽이 이긴다([T4-27](./T4-27.md) §1.2). 치르는 자원 칸을 글자로 밝혀 둘을 헷갈리지 않게 한다.
- 내 상태: 내가 최고 입찰자면 `Tag` `최고 입찰`과 맡긴 금액, 주최자면 `내 경매`. 아니면 비운다.
- 입찰 칸의 기본값은 서버의 `nextBid`다. `canBid`가 거부면 부르기 버튼을 점선으로 두고 누르면 이유를 보인다(`DisabledReason`). `nextBid`가 null이면 입력 칸도 없이 이유만 둔다.
- 열기 칸은 `openRules`가 있을 때만 있다. 범위 안내는 `openRules`와 `me`의 금·쌀로 만든다. 화면 검사는 안내이고 최종 판정은 엔진이다. 범위를 벗어난 값은 칸 아래에 이유를 보이고 열기 버튼을 점선으로 둔다.
- 지난 경매 표는 `closed` 그대로다. 유찰은 낙찰자 칸에 `유찰`, 값 칸 —.
- 장수가 없으면 표는 보이고 입찰·열기 칸 대신 장수 만들기 안내를 둔다.

### 2.3 즉시 행동 흐름

T4-21 2.3과 같다. 다른 점만 적는다.

| 상황 | 화면 |
| ---- | ---- |
| `applied` 입찰 | `최고 입찰`로 바뀌고 금이 줄어든 목록을 다시 받는다 |
| 거절 `BID_TOO_LOW`(그 사이 다른 장수가 더 부름) | 이유를 보이고 새 `nextBid`로 입력 칸을 채운 목록을 다시 받는다 |
| 같은 경매 처리 중 | 그 행의 부르기 버튼을 잠근다. 다른 경매는 부를 수 있다 |
| 열기 처리 중 | 열기 칸을 잠근다 |

### 2.4 갱신

- `auction.list`는 화면을 열 때, 즉시 행동이 끝났을 때, 열려 있는 동안 10초마다 받는다. 탭이 숨겨지면 멈춘다. 다른 장수의 입찰과 월간 마감을 따라잡기 위해서다.
- 위쪽 띠의 0초 재조회 묶음(`GameLayout.tsx:52`, `:71`)에는 넣지 않는다.

### 2.5 접근성

- 표 머리글 `scope`, 버튼 이름에 경매 번호와 물건(`3번 쌀 1,000 부르기`).
- 처리 중·결과 `role="status"`, 거절 `role="alert"`.
- 금액 입력은 `inputmode="numeric"`이고 설명(`aria-describedby`)에 최소·최대 안내를 잇는다.
- 키보드만으로 부르기·열기.

### 3.2 Chromium E2E (`e2e/auction.spec.ts`, `pnpm e2e`)

실제 `pnpm dev`와 `_test` PostgreSQL. 준비(`auctionSeed.ts`)는 경매 표식을 켠 월드 K와 끈 월드 F를 만들고 K에 사람 장수 H(쌀 충분), A·B(금 충분)를 둔다. 입력·월간 처리는 `TurnLoop`를 직접 돌린다. AU-2가 장수 경매를 넣지 않으면 E2를 중립 경매 준비(엔진 월간 정산으로 연 경매)로 바꾼다.

| ID | 시험 | 기대 |
| -- | ---- | ---- |
| E1 | 진입 | K 메뉴 `경매`, F 메뉴 없음, F 주소 직접 열기는 빈 상태 |
| E2 | 열기 | H가 쌀 1,000 팔기를 연다. 처리 중 뒤 열린 경매 표에 행, H의 쌀이 줄었다 |
| E3 | 입찰과 밀려남 | A가 기본값으로 부른다 → `최고 입찰`. B가 더 높게 부른다 → A 화면 다음 갱신에서 `최고 입찰`이 사라지고 A의 금이 돌아왔다 |
| E4 | 거절 이유 | A가 그 사이 낮아진 값으로 부르면 엔진 거절 `BID_TOO_LOW` 이유와 새 기본값 |
| E5 | 마감 | 마감 달 월간 정산을 돌린 뒤 지난 경매 표에 B와 값, B 쌀 증가, H 금 증가 |
| E6 | 유찰 | 입찰 없는 경매가 마감되면 `유찰`, H 쌀 환급 |
| E7 | 새로 고침 복구 | 엔진을 멈춘 채 부르고 새로 고친다. 다시 처리 중, 처리 뒤 결과 |
| E8 | 다시 보내기 | 응답을 끊고 `같은 요청 다시 보내기`. DB의 해당 키 InputEvent 1건 |
| E9 | 무인증 | 쿠키 없이 주소를 열면 `/login?next=` |
| E10 | 키보드 | Tab·Enter만으로 부르기 |

## 4. 반례와 처리

| 반례 | 처리 |
| ---- | ---- |
| 보는 중 경매가 마감됨 | 다음 갱신에서 열린 표에서 빠지고 지난 표에 생긴다. 부르던 입력은 버린다 |
| 처리 중 입찰이 마감 뒤 처리됨 | 엔진 거절 `CLOSED` 이유 |
| 서버 `nextBid`와 사용자가 넣은 값이 다름 | 화면이 막지 않는다. 엔진이 판정한다 |
| 내 경매에 부르기 | 버튼을 그리지 않고 `내 경매` 표시. 서버도 거절한다 |
| 금액 칸에 쉼표·공백 | 숫자만 남겨 보낸다. 안전 정수 밖이면 화면이 막는다 |
