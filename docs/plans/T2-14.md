# T2-14 기본 방침 설정 화면

> 대기열: T2-14 · AC: AC-M2-17 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-13 (API)

## 계획 (Claude)

### 목표

장수가 기본 방침을 고르고 빈 칸이 실제로 무엇을 할지 예턴 편집에서 미리 본다. 화면은 T2-13의 실제 `AppRouter` 응답만 쓴다.

### 범위

`apps/web`: 메인의 지도와 T1-15의 재사용 30칸 편집기 `TurnEditor`(`apps/web/src/turns/TurnEditor.tsx`, 메인 배치는 합쳐진 T1-16의 `apps/web/src/pages/MainPage.tsx:80`, `:99`) 위쪽의 방침 선택, 편집기 안의 빈 칸 표시, 메인 장수 정보 칸의 방침 이름, 미접속 안내 한 줄.
별도 페이지나 앞 5칸만으로 기능을 끝내지 않는다 (검토 R63-8).

#### 실제 연결 범위 (2026-10-23 정정)

준비 병합 `96c06c5`에서 부모 기준 `be4c182`와 backend `fe7b4f9`의 원조상이 보존됐다. 화면 코드와 E2E는 이 범위대로 썼다(아래 구현 기록의 실제 기본 방침 화면).

- 고치는 파일은 `apps/web/src/policy/*`, 장수 정보 칸의 방침 한 줄(`apps/web/src/main/GeneralInfo.tsx`), 그 단위 시험, `e2e/policy.spec.ts`와 새 `e2e/policyFixture.ts`, 아래 채울 문서다. 개인 예턴 읽기·저장(`apps/web/src/turns/draft.ts`, `useTurnDraft.ts`)은 고치지 않는다(아래 정정 1). `turns/turns.test.ts`는 지울 임시 타입을 가져오던 줄만 바꾼다.
- `TurnEditor.tsx`는 부모가 검증한 homePoll과 칸 모양 제네릭 blob `cf7008756a177b2afe2efe984815ae8942e06cbc` 그대로 둔다. 빈 칸 표시는 `usePolicyQuery`의 타입이 바뀌는 것만으로 이어진다. 꼭 고쳐야 하면 구현 기록에 이유를 쓴다.
- 국가 임시 계약(`apps/web/src/personnel/contract.ts`)과 다른 화면, `apps/server`·`apps/engine`·`packages/*`의 router·schema·shared·게임 상태, `apps/web/src/game/types.ts`(AppRouter 추론이라 읽기만 한다), `playwright.config.ts`, `e2e/game.ts`·`account.ts`·`publicMapFixture.ts`와 다른 spec은 고치지 않는다. PR #203 원본 WIP는 동결한다.
- 부모 root에는 backend PR #193이 아직 없으므로 이 작업을 feature root 전체에 합치지 않는다. 옛 사람 장수의 T/0 기준값(P-1), 전환 표지, 배포 차단은 T2-13 그대로이고 이 화면이 승인하지 않는다.

타입은 아래처럼 바꾼다. 필수 `explicit`을 optional로 낮추거나 캐스트로 덮지 않고 false를 true로 바꾸지 않는다.

| 지금 | 바꿀 것 |
| ---- | ------- |
| `policy/contract.ts`가 손으로 쓴 `PolicyResponse`·`SetPolicyOutcome`·`SetPolicyInput`·`SlotView`·`GeneralPolicySummary` | `inferRouterOutputs<AppRouter>['general']['policy']`, `['general']['setPolicy']`, `inferRouterInputs<AppRouter>['general']['setPolicy']`에서 꺼낸다. `PolicyKey`는 응답 `current`의 타입, 칸은 기존 `PersonalSlot`(`turns/source.ts:19`), 장수 방침은 `Home['general']['policy']`다. 임시 파일은 지운다 |
| `policyProcedures`의 `as unknown as` (`contract.ts:44-45`) | `useTRPC().general.policy`·`general.setPolicy`를 그대로 쓴다 |
| `homePolicy`의 `Partial` 캐스트와 null 갈래 (`contract.ts:48-50`, `GeneralInfo.tsx:35`, `:72-76`) | 필수인 `home.general.policy`를 그대로 읽는다. 받지 못했다는 갈래는 지운다 |

정정 1 (Codex 검토, 2026-10-23): 위 표에 있던 `toTurn`의 explicit 없는 값을 true로 읽는 변경은 반려됐다. U63-3은 기존 DB의 휴식 칸을 직접 칸으로 남기는 서버 전환이고 그 값은 서버 migration과 실제 `AppRouter` 응답이 true로 준다. 지금 `turns.get`·`turns.set`·STALE은 필수 boolean `explicit`을 주므로 화면은 기존 칸 모양 제네릭으로 그 false·true를 조회·저장·캐시에 그대로 잇는다. 공용 `draft.ts`의 `toTurn` 대체 규칙과 `useTurnDraft.ts`의 옛 보관 초안 읽기는 국가 12칸에도 쓰인다. 바꾸면 응답에 없는 explicit을 지어낸다. 그래서 둘은 `toSaveSlots`·편집 규칙과 함께 그대로 둔다. 가짜 true를 넣거나 optional로 낮추거나 우회 캐스트를 쓰지 않는다.

저장 입력은 지금처럼 빈 칸 `null`, 직접 칸 `{ commandKey, args }`이고 다른 키를 싣지 않는다(서버 `slotInput`은 strict, `apps/server/src/game/slots.ts:12-13`).

화면이 읽는 실제 응답은 이것뿐이다 (`apps/server/src/game/policy.ts:6-37`, `routers/general.ts:51-116`, `routers/home.ts:28-35`, `routers/turns.ts:92-107`).

| 요청 | 화면이 쓰는 값 |
| ---- | -------------- |
| `general.policy` | `current`, `pending`(엔진이 아직 집행하지 않은 내 입력의 방침), `lastRejected`(`{ policy, reason }`, reason은 엔진 거절 코드), `options`(방침 이름, `emptyCommand`·`thenCommand`의 명령 이름), `inactiveAfterDays` |
| `general.setPolicy` | `{ status: 'applied', policy }`는 다시 읽은 `general.policy`이고 `{ status: 'pending' }`은 상태만 준다. 5초 안에 엔진이 거절하면 결과 대신 오류이고 메시지는 엔진 문장이다(ACTOR_INACTIVE는 UNAUTHORIZED, WORLD_CLOSED는 PRECONDITION_FAILED, NO_GENERAL은 FORBIDDEN, 나머지는 BAD_REQUEST). 접수 전에는 종료·전환 대기 월드가 PRECONDITION_FAILED(`policy.ts:64-68`), 다른 방침이 대기 중이면 CONFLICT다 |
| `turns.get`·`turns.set` | 칸마다 필수 `explicit`과 `name`. STALE도 같은 칸 모양 |
| `home.get` | `general.policy`의 `{ key, name }`. `turnsPreview`(앞 5칸)는 화면이 쓰지 않는다 |

내 마지막 활동 시각, 미접속 날 수, 지금 미접속인지, AI가 맡았는지는 이 응답들에 없다. 화면은 이것을 계산하거나 지어내지 않는다.

### 화면

- 예턴 편집 위: `기본 방침: [권농 ▾]  빈 칸은 '농지 개간'을 합니다. 실패하면 휴식합니다.`
- 빈 칸은 흐린 글씨로 "(권농) 농지 개간"이라고 보여 준다. 직접 넣은 휴식은 진한 "휴식"으로 구분.
- 방침 줄 아래에 미접속 안내를 한 줄로 둔다. 승인된 U63-1·U63-2대로 `정지한 시간을 빼고 월드 시간으로 14일 넘게 들어오지 않아도 직접 넣은 명령과 휴식은 그대로 하고 빈 칸만 기본 방침대로 합니다.`라고 쓰고 14는 응답의 `inactiveAfterDays`로 채운다. 미접속 여부는 실행을 바꾸지 않으므로(T2-13 U63-1) 내 활동 시각이나 남은 날 수는 보이지 않는다.
- 방침 바꾸기는 예턴 저장과 별개로 고르는 즉시 보낸다. 엔진이 처리하기 전에는 고른 방침 옆에 처리 중을 둔다. `applied`를 받거나 다시 읽은 `pending`이 null이 되면 확정으로 보여 준다(T2-13 방침 바꾸기 처리). `pending` 응답에는 방침이 없으므로 고른 값을 처리 중으로 두고 `general.policy`를 다시 읽는다. `lastRejected`가 있으면 이유를 보여 주고 고르기 칸을 `current`로 되돌린다.
- 정정 3 (Codex 검토): `pending` 응답 뒤 `general.policy` 다시 읽기로 `current`가 바뀌면 그 확정 시점에 `home.get`을 다시 읽어 장수 정보 칸의 방침 이름을 맞춘다. 보내기가 끝난 때(`onSettled`)에만 다시 읽으면 엔진이 나중에 적용한 방침이 15초 주기 동안 옛 이름으로 남는다. 바뀐 `current`를 따라 `home.get`만 다시 읽고 캐시의 이름이 이미 같으면 다시 읽지 않는다. 예턴 초안·turnRevision·예턴 조회는 무효화하거나 지우지 않고 다시 읽기 주기도 더하지 않는다.
- `lastRejected.reason`은 엔진 거절 코드다(`apps/engine/src/inputs.ts:72-84`의 WORLD_CLOSED·ACTOR_INACTIVE·NO_GENERAL·BAD_POLICY). 코드를 그대로 보이지 않는다. 기본안은 같은 줄의 엔진 문장을 `policy/` 한곳에 옮겨 보이고 모르는 코드는 `방침을 바꾸지 못했습니다.`만 두는 것이다. 응답에 문장을 싣는 쪽이 낫다면 backend 일이므로 Codex 검토에서 정한다.
- 메인 장수 정보 칸의 방침 이름은 `home.get`의 `general.policy.name`이다. D-020 뒤 메인에는 앞 5칸 미리보기가 없으므로(`turnsPreview`를 쓰는 화면이 없다) 따로 만들지 않는다. 메인 30칸 편집기와 `/w/:worldId/turns`가 같은 `TurnEditor`로 빈 칸을 보인다. 칸 모양은 `turns.get`의 칸(`PersonalSlot`)이다.
- 방침 이름, 빈 칸에서 할 명령 이름, 날 수는 모두 서버 응답 값이다. 화면에 방침 표나 날 수를 따로 적지 않는다.

### 검증

기존 `e2e/policy.spec.ts`는 조건부 skip, 200초 전역 timeout, 공유 `e2eWorld`·`idleWorld`, 가짜 초상 route에 기대고 엔진 거절과 manual 실행 시험이 없다. 이 파일을 아래 일곱 시험으로 다시 쓴다(정정 2, Codex 검토). 시험마다 새 계정과 새 월드(F = 0)를 쓰고 메인 30칸 편집기에서 본다. 시간 제한은 Playwright 기본 30초다.

월드는 엔진 월간 fixture(`apps/engine/test/monthlyFixture.ts`, 도시 4·국가 2·NPC 장수 3)를 복사하고 시험 계정이 주인인 사람 장수 하나를 초기 상태에 더한 새 `WorldInit`이다. 사람 장수를 처음부터 둔 월드도 정상 초기 상태다. 소속 월드의 장수는 국가 1의 일반(관직 1)으로 국가 1 도시(농업 200/1000, 보급됨)에 금 1000을 들고 있어 농지 개간이 된다. 재야 월드의 장수는 국가가 없고(관직 0) 내정이 실패한다. 성공과 실패는 다른 월드로 나눈다. backend, 방침 값, 행위자 DTO 서명은 바꾸지 않는다.

거절 시험의 종료 상태는 UI 거절 조건 fixture다. 월드 상태 전환의 제품 증거로 세지 않는다. 공개 API가 방침 입력을 PENDING으로 접수해 `{ status: 'pending' }`을 준 뒤에 이 fixture가 만든 새 월드 ID 하나만 `status = 'ENDED'`로 쓴다. 그러면 진짜 `TurnLoop`의 `processPendingInput`이 `WORLD_CLOSED`를 만든다(`apps/engine/src/inputs.ts:72`). InputEvent의 상태·결과를 써서 거절을 만들지 않는다. 이것이 월드 행 직접 쓰기의 유일한 예외다. ACTOR_INACTIVE·NO_GENERAL·BAD_POLICY와 CONFLICT, 전환 대기 월드의 PRECONDITION_FAILED는 E2E에 없고 단위 시험만 있다.

일곱 시험이 한 worker의 자기 묶음을 쓰는 범위는 이렇다. 새 `e2e/policyFixture.ts`는 공개 지도 fixture의 방식을 읽어 따르되 그 파일은 고치거나 가져다 쓰지 않는다.

- 확인한 것: 실제 Claude CLI `claude-opus-5-5` 기본 모델의 high 설정과 하위 에이전트 0을 원문에서 확인했다. 개인 칸은 AppRouter 출력 타입을 그대로 쓰고 같은 S가 조회·저장 결과·캐시·편집기를 잇는다. 필수 explicit을 optional로 낮추거나 false를 true로 바꾸지 않았다. 기존 select 단언은 대상 타입만 구체화했으며 새 우회 단언은 없다. 저장 입력과 `toTurn`·`toSaveSlots`·편집 규칙은 바꾸지 않았다. 새 4개 단위 시험은 조회·저장 성공·STALE의 false/true·이름·인자 보존과 저장 입력의 null/객체 구분을 확인한다. 국가 칸은 기존 계약을 쓰며 새 1개 시험이 다른 직책 탭과 정보를 지키는지 확인한다. 기준 `141d0a2`의 TS2345를 재현한 뒤 수정된 웹 타입 검사와 관련 단위 41개, 지정 ESLint·Prettier·문구 검사를 통과했다. `24bf17750785137c38158c00320e3d731f2becc2`의 E 드라이브 별도 작업실에도 같은 프론트 patch를 적용해 웹 타입 검사와 같은 단위 41개가 통과했고 기존 homePoll 변경을 보존했다. 증거는 위 구현 기록과 E 작업실의 `test-results/t2-14-compat-receipt.json`에 있다.
- 고칠 것: 이번 타입 연결 범위에는 남은 항목이 없다. 정책 화면의 미접속 안내·임시 계약 교체·실제 API와 브라우저 검증은 미완료로 남긴다. DB 접속·전체 check·브라우저 시험은 실행하지 않았다. 단위의 가짜 응답을 실제 API 증거로 세지 않는다. C 드라이브의 처음 호환 설치 실패는 공간 부족인 환경 문제로 구분했으며 원문과 해시는 E 보존 폴더에 있다.
