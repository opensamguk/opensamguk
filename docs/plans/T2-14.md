# T2-14 기본 방침 설정 화면

> 대기열: T2-14 · AC: AC-M2-17 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-13 (API)

## 계획 (Claude)

### 목표

장수가 기본 방침을 고르고 빈 칸이 실제로 무엇을 할지 예턴 편집에서 미리 본다.

### 범위

`apps/web`: 메인의 지도와 T1-15의 재사용 30칸 편집기 `TurnEditor`(`apps/web/src/turns/TurnEditor.tsx`, 메인 배치는 합쳐진 T1-16의 `apps/web/src/pages/MainPage.tsx:80`, `:99`) 위쪽의 방침 선택, 편집기 안의 빈 칸 표시, 메인 장수 요약의 방침 표시.
별도 페이지나 앞 5칸만으로 기능을 끝내지 않는다 (검토 R63-8).

### 화면

- 예턴 편집 위: `기본 방침: [권농 ▾]  빈 칸은 '농지 개간'을 합니다. 실패하면 휴식합니다.`
- 빈 칸은 흐린 글씨로 "(권농) 농지 개간"이라고 보여 준다. 직접 넣은 휴식은 진한 "휴식"으로 구분.
- 미접속 안내를 한 줄로 둔다. 날 수는 `inactiveAfterDays`를 쓴다. 문장은 T2-13 사용자 결정 U63-1·U63-2가 정해진 뒤 그 내용대로 쓴다.
- 방침 바꾸기는 예턴 저장과 별개로 고르는 즉시 보낸다. 엔진이 처리하기 전에는 고른 방침 옆에 처리 중을 둔다. `applied`를 받거나 다시 읽은 `pending`이 null이 되면 확정으로 보여 준다(T2-13 방침 바꾸기 처리). `lastRejected`가 있으면 이유를 보여 주고 고르기 칸을 `current`로 되돌린다.
- 메인 장수 요약의 앞 5칸 미리보기도 같은 규칙으로 빈 칸을 흐리게 보여 준다. 응답 모양은 [T2-13](./T2-13.md)의 `SlotView`, `PolicyResponse`다.

## 구현 기록 (Claude)

- 바꾼 것:
  - `apps/web/src/policy/`: `PolicyBar`(예턴 편집 위 방침 고르기, 바로 보내기, 처리 중·확정·거절 표시), `usePolicy`(조회와 바꾸기, pending이면 2초마다 다시 읽음), `policyText`(안내 문장과 빈 칸 표시, 조사 고르기).
    `contract.ts`는 T2-13의 `PolicyResponse`·`SetPolicyOutcome`·`SlotView`·`GeneralPolicySummary`를 옮긴 임시 계약이다. Codex API가 main에 들어오면 `AppRouter` 타입으로 바꾸고 지운다.
  - 예턴 어댑터(T2-13 예턴 칸 모양): `draft.ts`의 `Turn`에 `explicit`을 더했다. `toTurn`은 `SlotView.explicit`을 그대로 읽는다. `toSaveSlots`는 T2-13의 `toSlotInput`대로 빈칸을 `null`, 직접 넣은 칸(직접 휴식 포함)을 객체로 보낸다.
    당기기·밀기로 생긴 칸은 빈칸, 반복은 복사한 칸의 구분을 둔다. `turnKey`는 빈칸끼리 같고 빈칸과 직접 휴식을 다르게 본다(`sameSlot`과 같은 규칙).
    `useTurnDraft`는 explicit이 없는 옛 보관 초안을 `toTurn`과 같은 규칙으로 읽는다.
  - `TurnEditor`: 빈 칸을 흐린 `(방침) 명령`으로, 직접 넣은 칸을 굵은 이름으로 보이고 행에 `data-empty`를 단다. [고른 칸 비우기]를 더했다. `CommandPicker`가 넣는 칸은 explicit이다.
  - 메인 명령 칸과 `/w/:worldId/turns`의 편집기 위에 `PolicyBar`, 장수 정보 칸에 기본 방침 이름.
  - 시험: `policy/policy.test.ts`(문장·조사·상태 판정·오류 안내), `policy/PolicyBar.test.tsx`(가짜 tRPC 링크로 applied·pending·거절·CONFLICT 화면), `turns/turns.test.ts`(빈칸과 직접 휴식의 저장·읽기·편집·옛 초안). `e2e/policy.spec.ts`는 써 두었다.
  - 채울 문서: `docs/frontend-ui-guidelines.md` §2 빈 칸과 기본 방침.
- 계획과 달라진 점과 이유:
  - 미접속 안내 한 줄은 넣지 않았다. 계획대로 U63-1·U63-2가 정해진 뒤 그 문장을 쓴다. `inactiveAfterDays`는 계약에만 있다.
  - 메인 장수 요약의 앞 5칸 미리보기는 D-020 뒤로 화면에 없다(`home.get`의 `turnsPreview`를 쓰는 곳이 없다). 메인의 30칸 편집기가 같은 규칙으로 빈 칸을 보여 주므로 따로 만들지 않았다.
  - API가 아직 없을 때(지금 main) `general.policy`가 NOT_FOUND를 주면 방침 줄을 숨기고 빈 칸은 `(빈 칸) 휴식`으로 보인다. 지금 서버는 explicit을 주지 않으므로 휴식을 빈칸으로 읽는다. 지금 서버가 null 저장을 휴식으로 바꾸므로 결과는 이전과 같다.
  - 처리 중에는 고르기 칸을 막는다. 같은 장수의 다른 방침 입력은 서버가 CONFLICT로 거절하기 때문이다.
- 검증 결과:
  - `pnpm vitest run apps/web/src/policy apps/web/src/turns`: 통과. `pnpm --filter web typecheck`, `pnpm lint`, 문구 검사 `--strict` 통과. `pnpm check` 결과는 PR 본문에 적는다.
  - `e2e/policy.spec.ts`는 T2-13 API(`general.setPolicy`)가 main에 없어 건너뛴다. 실행하지 않았고 증거가 아니다. 엔진 거절과 manual 시계 실행 시험은 T2-13 구현의 도우미가 생긴 뒤 쓴다.
