# T1-10 계정 API: 가입·로그인·세션

> 대기열: T1-10 · AC: AC-M1-05 (API) · 구현: Codex · 리뷰: Claude
> 선행: T1-02 · 다음: T1-14 로그인·가입 화면 (Claude)

## 계획 (Claude)

### 목표

이메일과 비밀번호로 가입·로그인·로그아웃이 된다. DB에는 argon2id 해시만 있고 원문 비밀번호는 어디에도 없다 (AC-M1-05).

### 범위

- `packages/db`: `User`, `Session`
- `apps/server/src/auth/`: 해시, 세션, tRPC context의 `user`
- `apps/server/src/routers/auth.ts`: `auth.signup`, `auth.login`, `auth.logout`, `auth.me`

### 하지 않는 것

이메일 인증·비밀번호 재설정·약관·탈퇴(M3 T3-02), 요청 제한·CSRF 전수(M3 T3-04), 소셜 로그인.

### 결정

| 항목 | 결정 |
| ---- | ---- |
| 해시 | `argon2` 패키지, argon2id, 라이브러리 기본 비용 이상 |
| 세션 | 무작위 32바이트 토큰. DB에는 **토큰의 SHA-256만** 저장 (`Session.id`). 만료 30일, 활동하면 연장 |
| 전달 | `HttpOnly; SameSite=Lax; Path=/` 쿠키 `sid`. 운영(HTTPS)에서는 `Secure`. 토큰을 URL·로그에 남기지 않는다 |
| 입력 | zod: 이메일 형식·소문자 정규화, 비밀번호 10~128자 |
| 오류 | 로그인 실패는 "이메일 또는 비밀번호가 맞지 않습니다" 하나 (계정 존재 여부를 드러내지 않음) |
| 행위자 | tRPC `protectedProcedure`가 쿠키 → 세션 → `ctx.user`. 클라이언트가 보낸 user ID는 쓰지 않는다 |
| 비밀값 | `SESSION_SECRET`가 필요하면 `.env`에만. `.env.example`에는 자리만 |

### API 계약 (화면이 쓸 모양)

```ts
auth.signup({ email, password }) → { user: { id, email } }   // 가입 즉시 로그인
auth.login({ email, password })  → { user: { id, email } }
auth.logout()                    → { ok: true }
auth.me()                        → { user: { id, email } | null }
```

- 실패 코드: `CONFLICT`(이미 있는 이메일), `UNAUTHORIZED`(로그인 실패), `BAD_REQUEST`(입력 오류).
- 이 모양을 바꾸면 T1-14 계획 문서의 "상대 영역" 절에 적고 Claude에게 알린다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 흐름 | API 테스트(실제 HTTP, Fastify inject): 가입 → me → 로그아웃 → me null → 로그인 |
| 해시 | DB 조회: `passwordHash`가 `$argon2id$`로 시작, 원문 문자열이 어떤 열에도 없음 |
| 실패 | 중복 가입 `CONFLICT`, 틀린 비밀번호 `UNAUTHORIZED`, 없는 이메일도 같은 메시지 |
| 권한 | 쿠키 없이 `auth.me` → null, 위조 토큰 → null, 만료 세션 → null |
| 로그 | 테스트 중 로그 출력에 비밀번호·토큰 문자열이 없음 |

## 구현 기록 (Codex)

- 바꾼 것: User·Session schema와 새 migration, Argon2id 가입·로그인, SHA-256 토큰 세션, 로그아웃·me·protectedProcedure를 추가했다. 쿠키와 DB 만료를 활동 시 30일로 연장하며 제재·탈퇴 계정은 인증하지 않는다. 요청 로그에서 URL·본문·쿠키·원본 오류를 제외했다.
- 계획과 달라진 점과 이유: 무작위 32바이트 토큰을 DB 해시로 조회하므로 SESSION_SECRET는 필요 없다. Argon2id 비용은 memory 65536 KiB·time 3·parallelism 4로 고정했다. 현재 Mac x64는 사전 빌드가 없어 `pnpm --filter @opensamguk/server rebuild argon2`로 소스 빌드했다.
- 검증 결과: `pnpm test:int` 12개 통과 (인증 실제 HTTP·DB 4개 포함). 가입→me→로그아웃→로그인, 원문 미저장·로그 비노출, 쿠키 속성, 중복·입력 오류, 위조·만료·연장, 다른 사용자 세션 격리·제재 차단을 확인했다. `pnpm lint`, 전체 패키지 타입 검사 통과. AC-M1-05의 화면 검증과 최종 완료는 T1-14 및 Claude 리뷰 뒤 판정한다.
