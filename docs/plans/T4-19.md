## 계획 (Claude)

### 목표

AC-P2-11 가운데 규칙 몫을 만든다. 같은 국가 장수가 부대를 만들고 다른 장수가 가입·탈퇴하는 판정이 순수 함수로 정해진다. 부대장이 집합을 실행하면 같은 국가 부대원이 부대장 도시로 모인다. 다른 국가의 부대에는 가입할 수 없고 국가를 떠난 장수는 부대에서 빠진 것으로 본다. 부대 상태는 확장을 켠 월드에만 생기고 끈 월드의 상태와 해시는 지금과 같다.

AC-P2-11 전체는 T4-20(InputEvent 처리, HTTP 권한, PostgreSQL)과 T4-21(E2E)이 끝나야 닫힌다. 이 작업만으로 AC를 닫지 않는다.

## 2. 계약

### 2.1 상태 조각 `troop`

```ts
// ext/troop/state.ts
export interface TroopRecord {
  leaderId: number; // 부대 번호와 같다
  nationId: number; // 만들 때 부대장의 국가
  name: string;
  members: number[]; // 부대장을 뺀 부대원 장수 번호, 오름차순
}
export interface TroopSlice {
  troops: Record<string, TroopRecord>; // key는 leaderId의 10진 문자열
}
export const troopSlice: ExtSlice<TroopSlice>;
```

- `key`는 `'troop'`이다. `create(context)`는 `{ troops: {} }`를 낸다. 시작 시나리오에 부대가 없으므로 `context`는 읽지 않는다.
- `validate`가 지키는 것. key가 `leaderId`의 10진 문자열과 같다. `leaderId`·`nationId`·`members`는 양의 안전 정수다. `members`는 오름차순이고 중복이 없으며 `leaderId`를 담지 않는다. 한 장수는 모든 부대를 통틀어 한 번만 나온다(부대장이면서 다른 부대원이 될 수 없다). `name`은 2.3 규칙을 통과한다.
- `clone`은 깊은 복제다. 객체 key 순서는 `leaderId` 오름차순으로 다시 만든다. JSONB가 key 순서를 바꾸므로 T4-03 E6의 `hashState` 비교와 맞춘다.
- `validate`는 장수·국가가 실제로 있는지 보지 않는다. 조각 단독 검사이기 때문이다. 있는지는 2.4 정리 함수가 본다.

### 2.2 판정 함수

모두 순수 함수다. 난수와 시각을 받지 않고 입력을 바꾸지 않는다. 성공이면 새 조각, 실패면 이유를 낸다. 게임 상태(장수 위치 등)는 바꾸지 않는다. 실패 코드는 명령 `Failure`가 아니라 부대 판정 전용 합 타입이다. 그래서 `commands/types.ts`(명세 §7 T4-02 → T4-49 → T4-48)를 고치지 않는다. T4-20이 이 코드를 InputEvent `result`의 이유 코드로 그대로 쓴다.

```ts
// ext/troop/actions.ts
export type TroopCode =
  | 'NO_ACTOR' | 'NOT_NATION' | 'IN_TROOP' | 'NOT_IN_TROOP'
  | 'BAD_NAME' | 'BAD_TROOP' | 'NOT_LEADER' | 'NOT_MEMBER' | 'LEADER_TARGET';
export type TroopOutcome = { ok: true; slice: TroopSlice; changed: number[] } | { ok: false; code: TroopCode; message: string };

export function createTroop(view: WorldView, slice: DeepReadonly<TroopSlice>, generalId: number, rawName: string): TroopOutcome;
export function joinTroop(view: WorldView, slice: DeepReadonly<TroopSlice>, generalId: number, troopId: number): TroopOutcome;
export function leaveTroop(view: WorldView, slice: DeepReadonly<TroopSlice>, generalId: number): TroopOutcome;
export function removeTroopMember(view: WorldView, slice: DeepReadonly<TroopSlice>, memberId: number): TroopOutcome; // T4-70과 추방이 함께 쓴다
export function kickTroopMember(view: WorldView, slice: DeepReadonly<TroopSlice>, leaderId: number, memberId: number): TroopOutcome;
export function reconcileTroops(view: WorldView, slice: DeepReadonly<TroopSlice>): TroopSlice;
export function troopOf(view: WorldView, slice: DeepReadonly<TroopSlice>, generalId: number): { troop: TroopRecord; leader: boolean } | null;
```

`changed`는 소속이 바뀐 장수 번호 오름차순이다. T4-20의 결과 기록과 T4-21의 표시가 쓴다.

모든 판정은 먼저 `reconcileTroops`를 거친 조각 위에서 검사한다. 그래서 이미 국가를 떠난 장수의 낡은 소속이 판정을 막지 않는다(반례 X6·X7).

| 판정 | 검사 순서 | 성공 |
| ---- | --------- | ---- |
| `createTroop` | 장수 없음 `NO_ACTOR` → 국가 없음(장수 `nationId` null 또는 국가 행 없음) `NOT_NATION` → 이미 부대장이거나 부대원 `IN_TROOP` → 이름 `BAD_NAME` | `troops[id] = { leaderId: id, nationId, name, members: [] }`, `changed = [id]` |
| `joinTroop` | `NO_ACTOR` → `IN_TROOP` → `NOT_NATION` → 부대 없음 또는 `nationId`가 장수 국가와 다름 `BAD_TROOP` | `members`에 넣고 오름차순, `changed = [id]` |
| `leaveTroop` | `NO_ACTOR` → 소속 없음 `NOT_IN_TROOP` | 부대원이면 그 장수만 뺀다. 부대장이면 부대를 지우고 `changed`는 부대장과 부대원 전부 |
| `removeTroopMember` | `NO_ACTOR` → 소속 없음 `NOT_IN_TROOP` → 대상이 부대장 `LEADER_TARGET` | 그 장수를 뺀다 |
| `kickTroopMember` | 행위 장수 없음 `NO_ACTOR` → 행위 장수가 부대장이 아님 `NOT_LEADER` → 대상이 그 부대원이 아님 `NOT_MEMBER` → 대상이 부대장 자신 `LEADER_TARGET` | 그 장수를 뺀다 |

검사 순서는 원작 처리기(1.2)의 순서를 따랐다. `joinTroop`에서 `IN_TROOP`이 `NOT_NATION`보다 앞인 것도 원작 그대로다(`worldCommandHandler.ts:1288-1306`). 실패 문구는 원작 문구를 [글쓰기 규칙](../writing-style.md)에 맞춰 구현 PR이 정하고 리뷰가 본다. 예: `NOT_LEADER`는 `부대장이 아닙니다.`, `BAD_TROOP`은 `가입할 수 있는 부대가 아닙니다.`.

권한은 장수 자신만 본다. 부대 가입·탈퇴에 직책 조건은 없다(원작도 없다). 계정 제재·세션 같은 처리 시점 재검사는 T4-20(C15)이 엔진에서 한다.

### 2.3 부대 이름

- 입력 문자열을 NFC로 바꾸고 양 끝의 공백·제어 문자(`\p{Z}`, `\p{C}`)를 뺀다(`management.ts:60-67`의 뒤쪽 정규식).
- 폭은 원작처럼 전각 2·반각 1로 세고 1 이상 18 이하다(`management.ts:23-72`). 폭 함수는 원작을 옮기고 파일 머리에 출처를 적는다.
- 원작의 HTML 문자 치환(`&`, `<` 등을 엔티티로)은 하지 않는다. 화면이 React로 글자를 그대로 그리기 때문이다. 이 단순화를 이 문서와 출처 주석에 남긴다.
- 같은 국가 안 이름 중복은 막지 않는다. 원작도 막지 않는다.

### 2.4 정리 `reconcileTroops`

기존 명령은 부대를 모르므로 장수가 국가를 떠나도 조각에는 낡은 소속이 남는다. 정리 함수는 이렇게 고친다.

1. 부대장이 없거나 부대장의 `nationId`가 그 부대의 `nationId`와 다르면 부대를 지운다. 부대원도 함께 빠진다.
2. 남은 부대에서 장수가 없거나 `nationId`가 부대 `nationId`와 다른 부대원을 뺀다.
3. 바뀐 것이 없으면 입력과 깊게 같은 새 값을 낸다.

이 함수를 언제 부르는지가 쟁점 T19-Q1이다. 이 계획의 안은 T4-49가 확장 조각마다 정리 훅을 두고 장수 턴·월간 정산·즉시 행동 처리 끝에서 순수하게 부르는 것이다. 그러면 부대장이 하야한 바로 그 턴 트랜잭션에서 부대가 사라진다(C15의 같은 트랜잭션 범위). 훅이 생기기 전에는 이 문서의 판정과 집합이 시작할 때 정리본 위에서 검사하므로 결과는 맞지만 조각에는 낡은 값이 남는다. 그 사이 부대장이 같은 국가에 다시 들어오면 부대가 되살아나는 반례(X8)가 생긴다. 그래서 훅 없이 T4-20을 병합하지 않는다.

### 2.5 집합 명령 `troop_gather`

| 항목 | 값 |
| ---- | -- |
| key·이름·분류 | `troop_gather`, `집합`, `military`, 대상 `general` |
| 인자 | 없음 (`z.strictObject({})`) |
| 상태 조각 | `troop` (T4-20이 `extCommandBindings`에 `{ commandKey: 'troop_gather', target: 'general', sliceKeys: ['troop'] }`로 등록) |
| 난수 | 쓰지 않는다 |

검사 순서는 원작 제약 순서(`che_집합.ts:48`)를 우리 코드로 옮긴다. 조각은 `reconcileTroops`를 지난 값을 본다.

1. 장수 없음 `NO_ACTOR` (`defineCommand`의 기본 검사).
2. 국가 없음 `NOT_NATION`, 자기 국가 도시 아님 `NOT_OWN_CITY`, 보급 끊김 `NO_SUPPLY`. 기존 `ownCity`(`support.ts:11-19`)를 그대로 쓴다.
3. 조각이 없거나 부대장이 아님 `BAD_STATE` `부대장이 아닙니다.`
4. 부대원이 하나도 없음 `BAD_STATE` `집합할 부대원이 없습니다.`

실행은 `defineCommand`의 `change` 안에서 한다. 명령 파일은 검사 `checkGather(view, actor)`와 이미 복제된 상태를 바꾸는 `applyGather(state, actor)`를 따로 내고 `defineCommand`의 `check`·`change`는 이 둘을 부르기만 한다. 이유는 시험 경로다. `defineCommand.execute`는 운영 등록을 쓰는 `cloneWorld`를 부르므로(`commands/support.ts:53`, `model/clone.ts:6-8`) 운영 `extSlices`에 `troop`이 없는 동안 `ext.troop`이 든 상태에서 예외가 난다. 그래서 이 작업은 `checkGather`(복제 없음)와 `cloneWorldWithRegistry`로 시험용 등록을 넘겨 만든 상태 위의 `applyGather`를 시험한다. `execute`·resolver·`runGeneralTurn` 경로의 성공·대표 실패는 운영 등록과 함께 T4-20이 같은 `troop_gather.test.ts`에 더한다.

- 부대원 가운데 `cityKey`가 부대장 도시와 다른 장수만 부대장 도시로 옮긴다. 순서는 부대원 번호 오름차순이다.
- 부대원에게 따로 보내는 결과(`reports`)는 쓰지 않는다. 지금 `reports`는 엔진이 전투 기록(`BattleLog`)으로 저장하는 칸이다(`apps/engine/src/commandPersistence.ts:87-102`). 부대원 장수 로그는 `GeneralLog`의 `(worldId, generalId, tick)` 유일 제약 때문에 부대장 턴의 tick에 더할 수 없다. 원작은 부대원마다 로그를 남기지만(`che_집합.ts:69-77`) 이 작업은 뺀다(쟁점 T19-Q3).
- 부대장 로그는 성공 한 줄이다. 옮긴 부대원 이름과 수를 함께 적는다. 이미 모두 같은 도시면 0명으로 성공한다(원작도 성공한다).
- 부대장 경험·공헌은 §3 TR-1·TR-2 결정을 따른다. 결정 전 원고 값은 원작 70·100이다.
- 실행 결과의 조각은 정리본이다. 정리로 빠진 낡은 소속도 이때 함께 지워진다.
- 부대원의 예턴, 병력, 훈련, 사기는 바꾸지 않는다. 다른 국가 도시에 있던 부대원도 옮겨진다. 원작도 위치를 가리지 않는다(`che_집합.ts:66`).

## 4. 시험과 증거
