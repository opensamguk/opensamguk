## 계획 (Claude)

### 목표

AC-M1-14의 이 명령 몫이다. 원작 `nation:cr_인구이동`에 대응하는 확장 국가 명령 `nation_migrate`가 켠 월드에서 국가 예턴으로 실행되어 행위자가 있는 자기 국가 도시에서 인접한 자기 국가 보급 도시로 인구를 옮기고 국고에서 비용을 뺀다. 성공 1건과 대표 실패 1건 단위 시험이 있고 같은 입력이면 결과가 같다. HTTP 이후 단계 증거는 T4-50·T4-51 뒤 같은 ID 아래에서 받는다.

### 3. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 3.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `nation_migrate` | 인구이동 | `nation` | `nation` | `z.strictObject({ cityKey: positive, amount: z.number().int().min(AMOUNT_MIN).max(100_000) })` |

도시 인구·국가 금쌀·장수 경험은 모두 `Effect` 필드다(`commands/effects.ts:6-11`). 그래서 `defineCommand`를 쓰지 않고 `investment.ts:82-125`처럼 `CommandDef` 객체를 직접 만들어 필드 효과만 낸다. 국가 명령의 실행 직책 검사는 `defineCommand`가 해 주던 것이므로 `ruler`(`commands/support.ts:20-26`)를 직접 부른다. T2-05 뒤에는 권한 표 함수다. key와 target은 객체에 글자 그대로 적는다(대응표 도구, [T4-02 리뷰](./T4-02.md#리뷰-claude)).

`AMOUNT_MIN`은 §2 M7의 사용자 결정값(0 또는 1)이다. 하한은 허용 행동을 바꾸므로 기술 검토가 정하지 않는다.

#### 3.2 검사 순서와 실패

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | 장수 없음 | `NO_ACTOR` | 장수가 없습니다. |
| 2 | 국가 없음, 실행 직책 아님 | `NOT_NATION`, `NOT_RULER` | `ruler`와 같은 문구 |
| 3 | 행위자 도시가 자기 국가 도시가 아님 | `NOT_OWN_CITY` | 자기 국가 도시에서만 가능합니다. |
| 4 | 행위자 도시 보급 끊김 | `NO_SUPPLY` | 보급이 끊긴 도시입니다. |
| 5 | 대상이 행위자 도시 | `BAD_TARGET` | 다른 도시를 골라야 합니다. |
| 6 | 대상이 없거나 자기 국가 도시가 아님 | `BAD_TARGET` | 자기 국가 도시를 골라야 합니다. |
| 7 | 대상이 행위자 도시와 연결되지 않음 | `NOT_ADJACENT` | 연결된 도시가 아닙니다. (`commands/military.ts:77-78`과 같은 문구) |
| 8 | 대상 보급 끊김 | `NO_SUPPLY` | 대상 도시의 보급이 끊겼습니다. |
| 9 | 행위자 도시 인구 < 30,100 | `NO_POPULATION` | 옮길 인구가 부족합니다. |
| 10 | M4 (가)에서 대상 남은 자리가 0 | `AT_MAX` | 대상 도시 인구가 이미 최대입니다. |
| 11 | 국가 금 < 보유 금 + 비용 | `NO_GOLD` | 국고 금이 부족합니다. |
| 12 | 국가 쌀 < 보유 쌀 + 비용 | `NO_RICE` | 국고 쌀이 부족합니다. |

인자 검사는 resolver가 먼저 한다(`resolve.ts:45-53`). 원작 순서와 다르게 행위자 쪽 검사를 대상 검사 앞에 모았다. 실패 이유가 바뀌는 순서일 뿐 허용 집합은 같다.

#### 3.3 계산

- `available = max(0, 출발 인구 − 30,000)`.
- M4 (가)면 `room = max(0, 대상 인구 최대 − 대상 인구)`, `moved = min(amount, available, room)`. (나)면 `room`을 쓰지 않는다.
- 비용: M2 (나)면 `round(develCost × moved / 10,000)`, (가)면 `amount`로. `develCost`는 M1 결정값.
- 검사 11·12의 비용은 실행과 같은 식으로 계산한다. 같은 상태에서 검사와 실행의 값이 같다.
