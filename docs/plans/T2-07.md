# T2-07 D1 조약서 외교, D16 교역

> 대기열: T2-07 · AC: AC-M2-06, AC-M2-14 · 구현: Codex · 리뷰: Claude
> 선행: M1 전체 · 관련: [차별화 D1](../product/differentiation.md#d1-조약서-외교), [D16](../product/differentiation.md#d16-교역), FR-DIF-01·16

## 계획 (Claude)

### 목표

- 조항을 골라 제안하고 상대가 수락하면 서버가 조항을 자동 집행한다. 종전도 조약으로 맺는다. 파기하면 신의 기록이 남고 다른 국가가 볼 수 있다.
  권한 없는 장수의 제안·수락은 거부된다 (AC-M2-06).
- 교역 허용 조약이 있는 이웃 나라 도시와 교역하면 금·쌀과 내정치가 오른다. 조약이 끝나거나 교전 중이면 실패한다 (AC-M2-14).

### 범위

- `packages/rules/src/diplomacy/treaty.ts`: 조항 타입, 검증, 집행 효과
- `Treaty`, `NationTrust` 테이블 (데이터 모델 차별화 자리)
- 국가 명령 `선전포고`는 그대로, M1의 `종전 제의`·`불가침 제의`·`파기 제의`·`원조`는 **조약 제안으로 대체** (명령 목록에서 뺌)
- 장수 명령 `교역(trade)` 추가
- `apps/server/src/routers/treaty.ts`

### 하지 않는 것

동맹 공동 참전(Phase 2), 조약 문구 자유 입력의 자동 해석, 원작 외교 수치 맞추기.

### 조항 결정 (M2)

| 조항 | 값 | 서버 집행 |
| ---- | -- | --------- |
| `peace` (종전) | — | 수락 즉시 교전 → 중립 |
| `nonAggression` | 기간 1~120개월 | 기간 동안 서로 선포·출병 불가 |
| `passage` | 허용 도시 목록 | 상대 장수가 그 도시로 이동 가능 (출병은 불가) |
| `tribute` | 내는 쪽, 금·쌀 월 금액, 기간 | 월간 정산에서 국고 이체. 국고가 모자라면 그달은 실패 기록 |
| `trade` | 기간 | 교역 명령 허용 (D16) |
| `cityTransfer` | 도시, 주는 쪽 | 수락 즉시 소유 이전 (그 도시 장수는 주는 쪽 수도로) |
| `note` | 자유 문장 (300자) | 집행 없음. 양국에 기록만 |

- 제안·수락·거절·파기는 **즉시 행동** (군주·참모, T2-05 권한 표). 턴을 기다리지 않지만 API가 게임 상태를 바꾸지도 않는다.
  접수와 집행은 아래 [즉시 행동 처리](#즉시-행동-처리-검토-r62-1-2026-10-21-추가)를 따른다. 제안 기한 6개월.
- 비용: 조약 기간 1년당 금 `TREATY_COST_PER_YEAR × 국가 규모`를 **양쪽이** 수락 순간에 낸다 (myosam 유료 계약). 모자라면 수락 실패.
- 파기: 남은 조항 모두 종료, `NationTrust.brokenTreaties += 1`, 파기 국가의 다른 조약 상대에게 알림. 외교 화면에 신의 기록 공개.
- 대치: 선포 뒤 교전이 되었는데 6개월 동안 두 나라 사이 전투가 없으면 **선포국 수입 −50%** (해제는 전투 1회 또는 종전).
- 조약은 여러 개 동시에 가능. 같은 조항이 겹치면 늦게 끝나는 쪽을 따른다.

### 교역 결정 (D16)

- 조건: 내가 있는 도시가 우리 국가 소유, 그 도시와 연결된 도시 중 `trade` 조항이 유효한 상대국 도시가 있음, 교전 아님.
- 효과: 금·쌀 = 두 도시 상업 평균 × 계수 × U(0.9, 1.1), 내 도시 상업·농업 +1% (최대치 안). 장수 경험·공헌 소폭.
- 비용 없음 (myosam "무료 내정").

### API 계약

```ts
treaty.propose({ worldId, toNationId, clauses: Clause[], expiresInMonths }) → InputOutcome
treaty.respond({ worldId, treatyId, accept }) → InputOutcome
treaty.break({ worldId, treatyId }) → InputOutcome
treaty.list({ worldId }) → [{ id, nations, clauses, status, startAt, endAt, brokenBy }]   // 우리 국가 관련만
treaty.trust({ worldId, nationId }) → { brokenTreaties, lastBrokenAt }                    // 모두 공개
```

### 즉시 행동 처리 (검토 R62-1, 2026-10-21 추가)

즉시 행동도 게임 상태는 엔진만 바꾼다 (AGENTS.md §6). 접수와 대기는 장수 생성 `apps/server/src/routers/general.ts:35-95`를 따른다.
엔진 집행은 장수 생성 처리 `apps/engine/src/inputs.ts:11-80`과 같은 자리(리스와 World를 잠근 펜싱 트랜잭션)에서 한다.

| 단계 | 누가 | 하는 일 |
| ---- | ---- | ------- |
| 접수 | API | 행위 장수와 국가를 세션에서 정한다. 입력 모양, 권한(군주·참모), 우리 국가가 당사자인지만 보고 `PENDING` InputEvent 하나를 만든다. kind는 `treaty.propose`·`treaty.respond`·`treaty.break`, payload는 요청 그대로다. 조약·국고·도시·관계는 읽기만 한다 |
| 대기 | API | 같은 요청 안에서 최대 5초 그 입력을 다시 읽는다. `APPLIED`면 `{ status: 'applied', treaty }`, `REJECTED`면 기록된 이유 코드로 오류, 시간이 지나면 `{ status: 'pending', inputId }`를 준다 |
| 집행 | 엔진 | `PENDING` 입력을 id 순으로 꺼내 권한·조약 상태·기한·비용·도시 소유를 다시 검사하고 결과를 한 트랜잭션으로 쓴다 |
| 재조회 | 화면 | `pending`을 받으면 `treaty.list`를 다시 읽는다. 처리 중인 행동은 `pending`에, 끝난 결과는 `myRecent`에 있다 |

엔진 트랜잭션 하나에 함께 들어가는 것은 양국 국고의 비용 차감, 수락 즉시 집행되는 조항(종전의 관계 변경, 도시 이양의 소유 이전과
그 도시 장수의 수도 이동), 조약의 상태·시작·끝, 파기 때 `NationTrust`, 양국 국가 기록과 관련 장수 로그, InputEvent의
`APPLIED`·`sequence`·`result`다. 검사 하나라도 실패하면 게임 상태는 그대로 두고 그 입력만 `REJECTED`와 이유 코드로 바꾼다.

- 판정은 `packages/rules/src/diplomacy/treaty.ts`의 순수 함수 `applyTreatyInput(state, input, tick)` 한 곳에서 한다. 엔진 집행과 재생이 같은 함수를 부른다.
  접수 단계의 검사는 화면 안내용이고 최종 판정이 아니다.
- 화면은 `applied`를 받기 전에는 수락·파기가 됐다고 표시하지 않는다. 접수만으로 성공을 보여 주지 않는다.
- 멱등: 같은 장수가 같은 내용(kind, treatyId, accept, 제안 payload)을 다시 보내고 그 입력이 아직 `PENDING`이면 새로 만들지 않고 그 입력을 기다린다.
  내용이 다르면 `CONFLICT`다(`general.ts:43-55`와 같다). payload 비교는 키 순서를 보지 않는다.
- 경합: 같은 국가의 다른 직책자가 같은 제안에 응답하거나 응답과 파기가 겹치면 둘 다 접수된다. 엔진이 먼저 꺼낸 입력만 집행되고
  뒤 입력은 상태가 맞지 않아 `REJECTED`(`TREATY_NOT_PROPOSED`·`TREATY_NOT_ACTIVE`)가 된다. 엔진이 트랜잭션 안에서 조약 상태를 다시 보므로 차감은 한 번만 일어난다.
- 기준 시점은 엔진의 검사 시점이다. 접수 뒤 국고가 줄었거나, 응답 기한이 지났거나, 이양할 도시를 잃었거나, 행위 장수가 직책을 잃었으면 `REJECTED`다.
  기한 만료와 원조 이체는 월간 정산이 맡는다. 입력과 턴·정산의 순서는 엔진 처리 순서를 따른다.
- 재시작: 엔진이 멈춰도 `PENDING`은 남고 다음 처리에서 한 번 집행된다. `APPLIED`·`REJECTED`는 다시 꺼내지 않는다.
- 재생: `applyRecordedInput`(`packages/rules/src/replay.ts:67-107`)에 세 kind를 더한다. `APPLIED`는 기록된 `result.tick`에서
  `applyTreatyInput`을 다시 불러 같은 결과(조약 ID, 양국 차감액, 상태)가 나오는지 확인한다. 다르면 재생 실패다. `REJECTED`는 지금처럼 건너뛴다.
  조약·신의·관계는 `WorldState`에 들어가 상태 해시에 포함된다. 조약 ID는 입력 sequence에서 만들고 난수나 시각을 쓰지 않는다.
- 위 접수·집행·재생은 모두 T2-07(Codex) 범위다.

### 화면이 기대하는 응답 모양 (T2-08, 2026-10-21 추가)

이름은 바꿔도 되지만 필드는 모두 필요하다. 위 계약에서 달라진 점은 넷이다. `treaty.list`가 상대 후보와 버튼 가능 여부, 처리 중인 즉시 행동을 함께 준다.
`treaty.trust`는 국가 하나 대신 전체 표를 준다. 조약서를 쓰는 동안 쓸 `treaty.quote`와 예턴 편집이 쓸 `treaty.tradeTargets`가 더해진다.
제안·응답·파기는 `InputOutcome`을 돌려준다.
화면 요소와의 대조는 [T2-08 v1 근거](./T2-08.md#v1-근거)에 있다.

```ts
type GameDate = { year: number; month: number };
type NationRef = { id: number; name: string; color: string };
// 버튼을 쓸 수 있는지는 서버가 정한다. 못 쓰면 화면은 DisabledReason으로 reason을 보여 준다.
type Allowed = { ok: true } | { ok: false; reason: string };

type Clause =
  | { kind: 'peace' }
  | { kind: 'nonAggression'; months: number } // 1~120
  | { kind: 'passage'; cityKeys: string[] } // 상대 장수가 지나갈 우리 도시
  | { kind: 'tribute'; payerNationId: number; gold: number; rice: number; months: number }
  | { kind: 'trade'; months: number }
  | { kind: 'cityTransfer'; cityKey: string; giverNationId: number }
  | { kind: 'note'; text: string }; // 300자
// enforced는 note만 false다. 화면이 서버가 집행하는 조항과 기록만 남는 조항을 나눠 보여 준다.
// cityNames는 passage·cityTransfer에만 있다.
type ClauseView = Clause & { enforced: boolean; cityNames?: string[] };

type TreatyStatus = 'PROPOSED' | 'ACTIVE' | 'ENDED' | 'BROKEN' | 'REJECTED' | 'EXPIRED';
type TrustRow = { nation: NationRef; brokenTreaties: number; lastBrokenAt: GameDate | null }; // 파기한 적 없으면 0, null
type TreatyRow = {
  id: string;
  from: NationRef; // 제안한 국가
  to: NationRef; // 받은 국가
  incoming: boolean; // 우리 국가가 받은 제안이면 true
  clauses: ClauseView[];
  status: TreatyStatus;
  proposedAt: GameDate;
  respondBy: GameDate | null; // PROPOSED일 때 응답 기한. 그 밖에는 null
  startAt: GameDate | null; // 수락 전에는 null
  endAt: GameDate | null; // 기간 있는 조항이 없으면(종전·도시 이양·기록만) null
  monthsLeft: number | null; // ACTIVE이고 endAt이 있을 때만
  brokenBy: NationRef | null; // BROKEN일 때만
  cost: { mine: number; theirs: number }; // 수락 순간 양쪽이 낼 금. 실제 차감은 엔진 집행 시점의 값이다
  counterpartTrust: TrustRow; // 받은 제안 카드에 보일 상대 신의 기록
  // 아래 둘은 화면 안내용이다. 최종 판정은 엔진 집행 때 한다. 이 조약에 처리 중인 행동이 있으면 ok: false
  canRespond: Allowed | null; // incoming이고 PROPOSED일 때만. 우리 국고가 모자라면 ok: false와 필요 금액
  canBreak: Allowed | null; // ACTIVE일 때만
};
// 제안·응답·파기의 응답. applied일 때만 결과가 확정된 것이다. 엔진이 거절하면 이유 코드와 문장으로 오류를 준다.
type InputOutcome = { status: 'applied'; treaty: TreatyRow } | { status: 'pending'; inputId: string };
type PendingAction = {
  inputId: string;
  kind: 'propose' | 'respond' | 'break';
  treatyId: string | null; // propose는 집행 전이라 null
  toNation: NationRef | null; // propose일 때만
  accept: boolean | null; // respond일 때만
  requestedBy: { generalId: number; name: string };
};
type RecentAction = {
  inputId: string;
  kind: 'propose' | 'respond' | 'break';
  treatyId: string | null;
  result: 'APPLIED' | 'REJECTED';
  reason: string | null; // REJECTED일 때 이유 문장
};
type TreatyTarget = {
  nation: NationRef;
  relation: 'WAR' | 'DECLARED' | 'NON_AGGRESSION' | 'NONE'; // 우리 국가와의 관계. 종전 조항은 WAR·DECLARED일 때만 고른다
  relationEndAt: GameDate | null; // 불가침·선포의 끝. NONE·WAR는 null
  trust: TrustRow;
};
type TradeTarget = { cityKey: string; cityName: string; nation: NationRef; treatyId: string; tradeEndsAt: GameDate };

// treaty.list → { canPropose: Allowed; targets: TreatyTarget[]; items: TreatyRow[]; pending: PendingAction[]; myRecent: RecentAction[] }
//   items: 우리 국가가 당사자인 조약만. proposedAt 최신순, 같으면 id 순.
//   pending: 우리 국가 장수가 보낸 PENDING 즉시 행동, inputId 순. myRecent: 내 장수가 보낸 즉시 행동 중 끝난 최근 5건, 최신순.
//   화면 탭: 받은 제안·보낸 제안 = PROPOSED, 진행 중 = ACTIVE, 끝남 = ENDED·REJECTED·EXPIRED, 파기됨 = BROKEN.
//   targets: 우리 국가를 뺀 모든 국가, 국가 ID 순. canPropose가 ok: false여도 준다(읽기만 하는 장수도 관계를 본다).
// treaty.quote({ worldId, toNationId, clauses }) → { cost: { mine: number; theirs: number }; problems: { index: number; reason: string }[] }
//   조약서를 쓰는 동안 비용과 조항별 문제(기간 범위, 우리 소유가 아닌 도시 등)를 돌려준다. 저장하지 않는다. 제안 권한자만.
// treaty.trust({ worldId }) → { items: TrustRow[] }
//   국가별 신의 표. 모든 국가, brokenTreaties 많은 순, 같으면 국가 ID 순.
// treaty.tradeTargets({ worldId }) → { fromCityKey: string | null; items: TradeTarget[]; blocked: string | null }
//   예턴 편집의 교역 대상 고르기. 내 장수가 지금 있는 도시와 연결된 도시 중 trade 조항이 유효한 상대국 도시. 도시 키 순.
//   items가 비면 blocked에 이유를 준다(우리 국가 도시가 아님, 교역 조약 없음, 교전 중).
```

공개 범위 (T1-12와 원작 기준):

- 조약 목록과 내용은 당사국 장수만 본다. 쓰기(제안·수락·거절·파기)는 군주·참모만 한다 (T2-05).
  원작도 외교 문서를 자기 국가 안에서만 보여 주고 쓰기는 외교권자에게만 연다. 원작의 소속 기간 제한(오래 소속한 장수만 읽기)은 뺐다.
- 다른 국가가 보는 것은 `TrustRow`(파기 횟수와 마지막 파기 시각)뿐이다.
- `relation`은 우리 국가가 낀 관계만 준다. 원작 중원 정보도 다른 국가끼리의 불가침은 통상으로 가리고 교전·선포만 보여 준다.
  다른 국가끼리의 관계 표는 이번 범위가 아니다.
- `cost.theirs`는 상대가 낼 금액이다. 상대가 낼 수 있는지는 알려 주지 않는다. 상대 국고가 드러나기 때문이다.
- 비용의 국가 규모는 공개값(도시 수·장수 수)으로만 계산한다. 작위(`level`)나 국고를 쓰면 상대 비용으로 비공개 값을 역산할 수 있다.
- `TradeTarget`에 상대 도시의 상업이나 예상 수익을 넣지 않는다. 수익 공식이 상대 도시 상업을 쓰므로 예상 수익만으로도 그 값이 드러난다.
  수익은 실행 뒤 장수 로그로 본다.

| 조항별 | 시나리오: 7개 조항 각각 수락 → 집행 확인 (종전·불가침 출병 거부·통행 이동·월 원조 이체·교역 허용·도시 이전·기록) |
| 비용 | 단위: 국고 부족 시 수락 실패 |
| 파기 | 시나리오: 파기 → 조항 종료, 신의 기록 +1, 다른 국가 조회 가능 |
| 대치 | 시나리오: 6개월 무전투 → 선포국 수입 반감, 전투 1회 → 해제 |
| 교역 | 단위: 성공, 조약 없음·만료·교전 → 실패와 이유 |
| 권한 | API: 수뇌·장수의 제안·수락 거부 |
| 접수와 집행 | 통합: 수락 접수 직후에는 국고·조약이 그대로다. 엔진 처리 뒤 양국 차감·ACTIVE·로그·InputEvent `APPLIED`가 한 번에 바뀐다. 5초 안에 못 끝나면 `pending`을 받고 `treaty.list` 재조회로 결과를 본다 |
| 경합 | 통합: 같은 제안에 두 직책자가 동시에 수락 → 하나만 `APPLIED`, 차감 한 번. 수락과 파기 동시, 접수 뒤 국고 부족·기한 경과 → `REJECTED`와 이유, 게임 상태 변화 없음 |
| 멱등 | API: 같은 장수가 같은 응답을 두 번 → 입력 하나, 다른 응답 → `CONFLICT` |
| 재시작 | 통합: `PENDING`인 채로 엔진 재시작 → 한 번만 집행 |
| 공개 범위 | API: 제3국 장수는 `treaty.list`에서 그 조약을 받지 못하고 `treaty.trust`만 본다. `quote`·`tradeTargets`·`list` 응답에 상대 국고·작위·도시 상업 없음 |
| 결정성 | 재생 테스트에 조약 InputEvent(`APPLIED`·`REJECTED`) 포함, 상태 해시 일치 |
