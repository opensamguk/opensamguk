# T1-22 저장소 전체 프리티어 포맷

> 대기열: T1-22 · AC: AC-M1-01 (저장소 검사) · 구현: Claude · 리뷰: Codex
> 선행: T1-06 (커밋까지), T1-21 (설정)

## 계획 (Claude)

### 목표

T1-21의 설정으로 저장소 전체를 한 번 포맷하고 이후 포맷이 어긋나면 `pnpm check`가 실패하게 한다.

### 순서

1. 착수 전에 **작업 트리가 깨끗한지** 확인한다. 다른 담당의 커밋 안 한 변경이 있으면 멈추고 사용자에게 알린다.
2. `pnpm format` 실행. 포맷만 한 **커밋 하나**로 남긴다 (다른 변경 섞지 않음).
3. 루트 `.git-blame-ignore-revs`에 그 커밋을 적는다 (`git blame`이 포맷 커밋을 건너뛰게).
4. `pnpm check`에 `pnpm format:check`를 넣는다.

### 하지 않는 것

포맷 외의 코드 변경. 포맷 뒤 lint·타입·테스트가 깨지면 고치지 않고 원인을 보고한다 (포맷은 동작을 바꾸면 안 된다).

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 동작 그대로 | 포맷 전후 `pnpm check`·`pnpm test:int`·`pnpm e2e` 결과가 같다 |
| 검사 동작 | 일부러 한 파일의 들여쓰기를 망치면 `pnpm check`가 실패한다 (확인 뒤 되돌림) |
| 범위 | 포맷 커밋의 diff에 T1-21의 무시 대상(`*.md`, `resources/`, migration 등)이 없다 |

### 채울 문서

구현하면서 함께 채운다. 리뷰어는 문서도 확인한다.

- `AGENTS.md §8 (pnpm check가 포맷도 검사함)`

    새 코드에서도 드물게 생길 수 있어 `AGENTS.md §8`에 "check가 포맷으로 실패하면 format을 한 번 더"라고 적었다.
  - 착수 전 단계를 `진행중`으로 바꾸지 않았다. 포맷 커밋에 다른 변경을 섞지 않으려고 깨끗한 트리에서 바로 포맷했고 끝난 뒤 `리뷰`로 바꿨다.
- 검증 결과:
  - 착수 전 작업 트리 깨끗함 (`git status` 0줄).
  - 동작 그대로: 포맷 후 `pnpm check` 단위 15개 파일/106개, `pnpm test:int` 4개 파일/33개, `pnpm e2e` 24개, 웹 운영 빌드 통과. 포맷 전과 같은 숫자.
  - 범위: 포맷 커밋에 `*.md`·`resources/`·migration·`pnpm-lock.yaml`·생성물 0개.
  - 검사 동작: `HomePage.tsx` 들여쓰기를 일부러 망치면 `pnpm check`가 exit 1, 되돌리면 통과.
  - `git blame --ignore-revs-file .git-blame-ignore-revs`가 포맷 커밋을 건너뛴다.
