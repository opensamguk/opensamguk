## 계획 (Claude)

### 목표

장수·국가 순위를 기준별로 정렬해 보고, 내 순위를 바로 찾는다.

### 범위

`apps/web`: `/w/:id/ranking?tab=generals|nations&by=…`, 위쪽 띠 메뉴 "순위".

### 화면

- 탭: 장수 · 국가. 기준은 표 머리글을 눌러 바꾼다 (R4: 머리글 정렬).
- 장수 표: 순위 · 이름 · 소속(NationBadge) · 공헌 · 경험 · 전공. 내 장수 행은 강조하고 100위 밖이면 표 아래에 따로 한 줄.
- 국가 표: 순위 · 국가 · 도시 · 장수 · 국력 (R3: 국가 비교표).
- 숫자는 `StatTable`과 같은 고정폭·오른쪽 정렬. 기준 시각("193년 4월 정산 기준") 표시.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 정렬 | Playwright: 머리글 클릭 → 주소의 `by`와 순서 바뀜, 새로고침 유지 |
| 내 순위 | Playwright: 내 행 강조, 100위 밖 표시 |
| 공개 | Playwright: 국가 표에 국고·군량 열 없음 |

### 채울 문서

- `docs/frontend-ui-guidelines.md` §4 (주소 추가)

## 리뷰 (Codex)

- 결과: 통과. Codex 독립 리뷰 run750, 검토 SHA `89f0082528a64e76834e2d233cb6b482f78e340c` (PR #46). 구현 코드는 고치지 않았다.
- 확인한 것: main `6105638`과 바뀐 13파일을 대조했다. 실제 `AppRouter`에서 타입을 꺼내고 보고 있는 탭의 tRPC만 부른다. 여섯 정렬 기준은 API 시험과 표의 응답 순서 보존으로 확인했다. 내 행 강조·100위 밖 한 줄·정산 전·새 장수·주소와 새로고침·숫자 머리글 오른쪽 정렬은 순위 E2E 6개가 본다. 국가 표는 `row.power`를 그대로 표시하고 국고·군량 열을 두지 않는다. 공유 경로와 메뉴는 main에 순위만 더한 변경이다.
- 실행 증거: GitHub CI `39558493251`의 실제 로그에서 위 SHA의 checkout과 `EXPECTED_SHA` 일치를 확인했다. `pnpm check` 단위 350개(순위 화면 15개 포함), `pnpm test:int` 실제 PostgreSQL 148개(순위 API 17개·엔진 2개 포함), `pnpm e2e --workers=1 --reporter=line` Chromium 32개(순위 6개 포함), 웹 빌드가 모두 통과했다. 별도 run `39558490644`도 같은 SHA의 필수 두 작업과 각 단계가 성공했다. `git diff --check origin/main...HEAD`와 `pnpm next`는 리뷰 환경에서 직접 통과했다.
- 검증 한계: 리뷰 환경의 의존성 설치는 두 번 모두 공유 메모리 예산 때문에 종료 코드 75로 멈췄다. 이를 시험 통과로 세지 않고 정확한 SHA의 CI 실행 증거를 사용했다. 순위 전용 브라우저 시험은 여섯 머리글 전환 전부나 장애 주입 뒤 재시도를 다루지 않는다. 오류 재시도는 화면 단위 시험과 `query.refetch()` 연결을 대조했고 세션 경계는 공통 라우터 가드·인증 캐시 초기화와 API의 만료 세션 거부 시험을 확인했다.
