# T2-06 직책·인사·발령 응답 화면

> 대기열: T2-06 · AC: AC-M2-05, AC-M2-16 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-05 (API)

## 계획 (Claude)

### 목표

군주는 인사부에서 임명·해임을, 직책자는 자기 국가 예턴을, 사람 장수는 발령 제안에 답한다.

### 범위

`apps/web`: `/w/:id/nation/personnel`(인사부), `/w/:id/nation/turns`(국가 예턴), 메인의 발령 알림 상자, 위쪽 띠 메뉴 `국가`.

### 화면

- **인사부:** 소속 장수 표(이름·직책·도시·공헌·사람/NPC). 직책 높은 순으로 놓는다. 군주에게만 직책 바꾸기 칸이 열린다. 다른 사람에게는 `DisabledReason`으로 서버가 준 이유(`군주만 임명할 수 있습니다`)를 보인다.
- **국가 예턴:** T1-15 예턴 편집 부품을 재사용하되 칸 수는 12칸이다. 명령 목록과 인자, 사전 검사는 `nationCommands.list`·`nationCommands.precheck`를 쓴다(개인 칸의 `commands.list`와 섞지 않는다). 직책 탭(군주·참모·수뇌…), 내 칸만 편집 가능, 남의 칸은 읽기 전용. 국가 예턴 권한이 없는 장수와 인사 기능 이전 월드에는 서버가 준 이유를 보인다.
- **국가 예턴 편집기 연결:** 지금 편집기는 30칸과 `turns.*`·`commands.*`에 묶여 있다(`apps/web/src/turns/draft.ts:6`, `TurnEditor.tsx:59-80`). 칸 수와 조회·저장 함수를 바깥에서 받게 나누고 개인 30칸은 지금 연결을 그대로 쓴다.
  국가 칸 저장은 읽은 탭의 `office`(국가·직책·tenure)와 `revision`을 그대로 돌려보낸다. 칸은 `toTurn`·`toSaveSlots`(`draft.ts:22-27,56`)로 표시용 `name`을 빼고 `{ commandKey, args }`만 보낸다.
  초안 저장 키에 계정·월드와 `office`를 함께 넣는다. 직책이나 tenure가 바뀌면 예전 초안을 새 칸에 불러오지 않는다.
  서버가 직책이 바뀌었다고 거부하면 그 문구를 보이고 국가 예턴을 다시 받는다. 예전 초안을 다른 칸에 다시 저장하지 않는다. STALE이면 개인 칸과 같이 최신 스냅샷을 보이고 다시 고르게 한다.
- **발령 제안:** 메인 위쪽에 눈에 띄는 상자를 둔다. 문구는 `공손찬이 북평으로 발령했습니다 · 남은 기한 1개월, 넘기면 수락`이고 [수락] [거절] 버튼이 붙는다. 거절 버튼 옆에 공헌이 얼마나 줄어드는지(−10%와 실제 값) 안내한다.
- 권한은 서버가 준 값(`appoint`, `edit`, `respond`)으로만 판단해 버튼을 그린다. 화면이 권한을 추측하지 않는다.
- 개인 예턴 편집은 지금처럼 지도와 같은 메인에 둔다. 인사부와 국가 예턴이 별도 주소라는 것은 이 배치를 바꾸지 않는다. T1-15 부품 재사용을 앞 5칸 읽기 전용 미리보기로 되돌리는 근거로 쓰지 않는다.

### 접수와 완료 대기 (T2-05 즉시 행동 절)

임명·해임·발령 응답은 서버가 접수만 하고 엔진이 끝낸다. 화면은 아래 순서를 따른다.

1. 누르면 새 `requestId`(UUID)를 만들고 버튼을 막은 채 `처리 중`을 보인다. 같은 버튼을 다시 눌러도 새 요청을 보내지 않는다.
2. 응답을 못 받으면(네트워크 오류, 시간 초과) 같은 `requestId`로 한 번 더 보낸다.
3. `pending`이면 `personnel.request`를 1초마다 묻는다. `applied`이면 결과 안내를 보이고 `offers.mine`·`personnel.officers`·내 장수 조회를 다시 받는다. `rejected`이면 그 `message`를 보이고 버튼을 다시 연다.
4. 새로 고치거나 다시 접속하면 `personnel.recent`를 읽는다. pending인 접수는 3번부터 잇는다. 이미 끝났고 이 브라우저에서 아직 안내하지 않은 접수는 결과 안내를 한 번 보인다. 탭을 닫은 사이 엔진이 끝낸 접수도 여기서 찾는다.
   안내한 `requestId`는 계정·월드별 키로 브라우저 저장소에 남긴다. 저장소를 못 쓰면 같은 안내를 한 번 더 볼 뿐 결과는 같다. 다른 기기에서는 24시간 안의 결과를 다시 볼 수 있다.
5. 대기 중 UNAUTHORIZED면 로그인으로 보낸다(`next`는 지금 주소). 다시 들어오면 4번으로 결과를 찾는다.

- 제안 상자가 목록에서 사라진 것만으로 성공이라 쓰지 않는다. 안내 문구는 `requestId` 결과(`offerStatus`, `city`, `dedicationLost`)로만 만든다.
- 결과를 받은 뒤 다시 받는 조회는 개인 예턴 초안과 지도 선택을 지우지 않는다. 그 조회에 개인 예턴(`turns.get`)과 지도 선택 상태를 넣지 않는다.

## 구현 기록 (Claude)

- 바꾼 것:
  - 편집기 연결 분리: `apps/web/src/turns/source.ts`의 `TurnSource`가 칸 수, 조회·저장 함수, 명령 목록, 사전 검사, 초안 키, 읽기 전용 이유를 넘긴다. 개인 30칸은 `personalSource`로 지금 `turns.*`·`commands.*` 연결을 그대로 쓴다.
    `draft.ts`의 `runs`·`repeatRange`·`quickSelect`와 `readStored`는 칸 수를 인자로 받고 기본값은 30이다.
  - 국가 예턴 `/w/:worldId/nation/turns` (`personnel/NationTurnsPage.tsx`): 직책 탭, 내 칸만 편집, 남의 칸은 서버가 준 이유와 서버 칸 이름으로 읽기 전용. 저장은 읽은 탭의 `office`·`revision`과 `toSaveSlots` 결과만 보낸다.
    초안 키는 계정·월드·국가·직책·tenure다. PRECONDITION_FAILED면 초안을 바로 지우고 서버 문구를 보인 뒤 국가 예턴을 다시 받는다. STALE은 개인 칸과 같은 충돌 안내를 탄다.
  - 인사부 `/w/:worldId/nation/personnel` (`PersonnelPage.tsx`): 직책 바꾸기 표(빈 자리는 직책 없는 장수 중에서 임명, 앉은 자리는 해임), 소속 장수 표(이름·사람/NPC·직책·도시·공헌). 권한은 `appoint`로만 판단하고 아니면 `DisabledReason`으로 서버 이유를 보인다.
  - 메인 발령 제안 상자 (`OfferBox.tsx`): 계획 문구, 기한 연월, 거절 시 공헌 −10%와 실제 값, [수락] [거절]. 제안이 없거나 API가 거부하면 아무것도 그리지 않는다. 편집기와 형제라 결과가 와도 개인 초안과 `?city`는 그대로다.
  - 접수와 완료 대기 (`request.ts`, `usePersonnelAction.ts`): 새 `requestId`, 연결 오류면 같은 `requestId`로 한 번 더, 두 번 다 답이 없으면 `personnel.request`로 접수 여부 확인, pending이면 1초마다 `personnel.request`, UNAUTHORIZED면 `/login?next=지금 주소`.
    다시 접속하면 `personnel.recent`에서 이 화면 종류의 pending을 잇고 안내하지 않은 끝난 접수를 한 번 보인다. 안내한 `requestId`는 localStorage `opensamguk.personnelAnnounced.v1:<계정>:<월드>`에 20개까지 둔다.
  - 위쪽 띠 메뉴 `국가`(인사부로), `CommandPicker`의 `국가` 분류와 대상 장수 이름 고르기(국가 칸만), `describeArgs`의 장수 이름(국가 칸만).
