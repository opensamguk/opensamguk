# T2-05 직책·인사, D11 발령 응답

> 대기열: T2-05 · AC: AC-M2-05, AC-M2-16 · 구현: Codex · 리뷰: Claude
> 선행: M1 전체 · 관련: FR-NAT-03·04, FR-TRN-05, [차별화 D11](../product/differentiation.md#d11-발령-응답)

## 계획 (Claude)

### 목표

- 군주가 수뇌를 임명하고 포상·몰수·발령을 한다. 권한 없는 장수의 같은 요청은 거부된다 (AC-M2-05).
- 발령받은 사람 장수가 턴을 쓰지 않고 수락·거절한다. 기한 안에 답이 없으면 수락이다. NPC 군주는 정해진 주기마다 사람 장수에게
  발령·포상하고 이유를 로그에 남긴다 (AC-M2-16).

### 범위

- `packages/rules/src/personnel/`: 직책 표, 권한 판정, 발령 응답 규칙, NPC 군주 인사 판단
- `NationTurn` 직책별 12칸 (M1은 군주만), `AssignmentOffer` 테이블
- `apps/server/src/routers/personnel.ts`, `nationTurns.ts`

### 하지 않는 것

선양·모반(Phase 2), 관직 주재 효과(D17, M3 T3-09), 인사 화면(T2-06).

### 직책과 권한 결정 (원작 관직 숫자 유지, T1-03)

| officerLevel | 이름 | 국가 예턴 | 임명·해임 | 포상·몰수·발령 | 외교 |
| ------------ | ---- | --------- | --------- | -------------- | ---- |
| 12 | 군주 | ✓ | ✓ | ✓ | ✓ |
| 11 | 참모 | ✓ | | ✓ | ✓ |
| 5~10 | 수뇌 | ✓ | | ✓ | |
| 1 | 장수 | | | | |
| 0 | 재야 | | | | |

- 권한 표는 `personnel/permissions.ts` 한곳에 둔다. server의 권한 검사와 rules의 실행 검사가 같은 표를 쓴다.
- **임명·해임은 즉시 행동**이다 (`InputEvent(kind: 'personnel.appoint')` → 엔진 처리). 포상·몰수·발령은 국가 예턴 명령 그대로.
- 국가 예턴은 직책별 12칸. 군주 턴에 군주 칸, 각 수뇌의 턴에 그 수뇌 칸을 1칸 실행한다.

### 발령 응답 결정 (D11)

```text
발령 실행 ─┬─ 대상이 NPC → 즉시 이동 (M1과 같음)
           └─ 대상이 사람 → AssignmentOffer(PENDING, expiresTick = 지금 + 2개월)
                 ├─ 수락 (즉시 행동, 턴 소비 없음) → 대상 도시로 이동
                 ├─ 거절 → 공헌 −10% (balance.ts), 로그
                 └─ 기한 지남 → 월간 정산에서 수락 처리
```

- 같은 장수에게 PENDING 제안은 하나뿐. 새 발령이 오면 이전 것은 `SUPERSEDED`.
- **NPC 군주 인사** (월간 정산 뒤, 3개월마다): 소속 사람 장수 중 6개월 넘게 같은 후방 도시에 있는 장수를 전선 도시로 발령,
  국고가 기준 이상이면 공헌 상위 사람 장수에게 포상. 각 결정의 이유를 국가 역사에 한 줄로 남긴다.

### API 계약

```ts
personnel.officers({ worldId }) → [{ generalId, name, officerLevel, isHuman, cityKey }]
personnel.appoint({ worldId, generalId, officerLevel })   // 군주만
personnel.dismiss({ worldId, generalId })                 // 군주만
offers.mine({ worldId }) → [{ id, fromNation, targetCity, expiresAt, status }]
offers.respond({ worldId, offerId, accept: boolean })
nationTurns.get/set/edit({ worldId, ... })                // T1-11 turns와 같은 모양, 내 직책 칸만
```

화면(T2-06)이 기대하는 응답 모양 (2026-10-21 추가, 이름은 바꿔도 되지만 필드는 모두 필요):

```ts
type Allowed = { ok: true } | { ok: false; reason: string }; // reason은 화면 문구 그대로 (예: 군주만 임명할 수 있습니다)
type CityRef = { cityKey: number; name: string };
type DisplaySlot = { commandKey: string; args: unknown; name: string }; // T1-11 turns.get의 칸과 같다

// personnel.officers({ worldId }) → PersonnelBoard
type PersonnelBoard = {
  appoint: Allowed; // 임명·해임을 할 수 있는가 (군주만)
  levels: { officerLevel: number; title: string }[]; // 군주가 줄 수 있는 직책, 높은 순
  members: PersonnelMember[]; // 소속 장수 전부. officerLevel 높은 순, 같으면 generalId 순
};
type PersonnelMember = {
  generalId: number;
  name: string;
  officerLevel: number;
  title: string; // permissions.ts 표의 직책 이름
  isHuman: boolean;
  city: CityRef;
  dedication: number;
};

// nationTurns.get({ worldId }) → { tabs: NationTurnTab[] }   직책 높은 순, 군주 칸이 처음
type NationTurnTab = {
  officerLevel: number;
  title: string;
  holder: { generalId: number; name: string } | null; // 빈 자리면 null
  edit: Allowed; // 내 직책 칸만 ok
  revision: number; // nationTurns.set/edit의 충돌 검사용 (T1-11과 같은 STALE 규칙)
  slots: DisplaySlot[]; // 12칸
};

// offers.mine({ worldId }) → AssignmentOfferView[]   PENDING만. 같은 장수의 PENDING은 하나뿐이라 길이는 0이나 1
type AssignmentOfferView = {
  id: string;
  issuer: { generalId: number; name: string }; // 발령 명령을 실행한 군주·참모·수뇌
  targetCity: CityRef;
  expires: { year: number; month: number; monthsLeft: number }; // 기한의 게임 연월과 남은 개월 수
  rejectCost: { dedicationPercent: number; dedication: number }; // 거절하면 줄어드는 공헌 (balance.ts 비율과 실제 값)
  respond: Allowed;
};
// offers.respond({ worldId, offerId, accept }) → { status: 'ACCEPTED' | 'REJECTED'; city: CityRef; dedicationLost: number }
//   city는 응답 뒤 내 장수가 있는 도시. dedicationLost는 거절이면 줄어든 공헌, 수락이면 0
```

- 공개 범위: `personnel.officers`는 같은 국가 장수만 부른다. 재야와 무인증은 거부한다. 공헌은 순위(T2-22)에서도 공개하는 값이다. `nationTurns.get`은 위 권한 표에서 국가 예턴이 ✓인 직책(군주·참모·수뇌)만 부르고 일반 장수는 이유와 함께 거부한다. `offers.mine`과 `offers.respond`는 세션 장수에게 온 제안만 다룬다. 남의 제안 ID는 NOT_FOUND, 이미 처리된 제안은 CONFLICT다.
- 화면 요소와 필드의 대조는 [T2-06](./T2-06.md)의 v1 근거 표 오른쪽 칸에 있다. 권한 판단은 `appoint`·`edit`·`respond`만 쓰고 화면이 `officerLevel`로 권한을 추측하지 않는다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 권한 | API: 직책 5종 × 행동 5종 표 전부 (허용·거부) |
| 공개 범위 | API: 다른 국가의 `personnel.officers`, 일반 장수의 `nationTurns.get`, 남의 제안 `offers.respond` 모두 거부. 응답 키는 화면 응답 모양과 같다 |
| 임명 | 통합: 군주가 수뇌 임명 → 수뇌가 자기 칸 편집 가능, 해임 뒤 거부 |
| 발령 응답 | 시나리오: 수락 → 이동 / 거절 → 공헌 감소 / 2개월 무응답 → 자동 수락 / 새 발령 → 이전 SUPERSEDED |
| NPC 군주 | 시나리오: 후방 6개월 사람 장수 → 3개월 주기에 발령 + 역사 로그 이유 |
