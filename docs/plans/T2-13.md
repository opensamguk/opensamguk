# T2-13 D12 기본 방침

> 대기열: T2-13 · AC: AC-M2-17 · 구현: Codex · 리뷰: Claude
> 선행: M1 전체 · 관련: [차별화 D12](../product/differentiation.md#d12-기본-방침), FR-DIF-12, FR-GEN-04

## 계획 (Claude)

### 목표

기본 방침을 정한 장수의 빈 예턴 칸은 휴식 대신 방침에 맞는 명령으로 실행된다. 그 명령이 실패하면 휴식으로 대신하고 이유가 로그에
남는다. 장기 미접속 장수는 방침 범위 안에서만 AI가 고른다 (AC-M2-17).

### 범위

- `General.defaultPolicy`, `General.lastActiveTick`(판정)·`lastActiveAt`(표시), `GeneralTurn.explicit` (새 migration)
- `packages/rules/src/policy/`: 방침 → 명령 대응, 미접속 판정, 칸 비교 `sameSlot`. `replay.ts`의 칸·방침·활동 재생
- engine: 턴 실행의 빈칸 처리 분기, `general.setPolicy`·`general.active` 집행, 예턴 당김의 `explicit` 보존
- `apps/server`: `general.setPolicy`와 로그인 활동의 접수, 예턴 저장·편집의 `explicit`과 활동 기록

### 하지 않는 것

국가 단위 방침(myosam 국가점수 정책, Phase 2), 장수 삭제·NPC화 정책(지인 테스트 뒤 결정).

### 결정

| 방침 | 빈칸에서 실행 | 실패하면 |
| ---- | ------------- | -------- |
| `farm` 권농 | 농지 개간 | 휴식 + 이유 |
| `commerce` 중상 | 상업 투자 | 〃 |
| `security` 치안 | 치안 강화 | 〃 |
| `defend` 수비 | 수비 강화 → 최대면 성벽 보수 | 〃 |
| `drill` 훈련 | 훈련 → 최대면 사기진작 | 〃 |
| `none` | 휴식 (M1과 같음) | — |

- 빈칸은 사용자가 아무것도 넣지 않은 칸이다. 사용자가 **직접 넣은 휴식은 그대로 휴식**이다 (구분을 위해 저장 형식에 `explicit` 표시, 보존 범위는 아래 [예턴 칸 모양](#예턴-칸-모양-검토-r62-2r63-2-2026-10-21-추가)).
- 미접속: 마지막 활동이 월드가 돌아간 14일보다 오래된 장수는 빈칸뿐 아니라 **모든 칸을** 방침 범위의 NPC AI가 고른다 (출병·이동·임관 같은 큰 결정은 하지 않음).
  판정은 현실 시각이 아니라 기록된 tick으로 한다(아래 [활동 기록](#활동-기록과-재생-결정론-검토-r63-1-2026-10-21-추가)).
  다시 접속하면 즉시 사람 예턴으로 돌아온다.
- 로그: "기본 방침(권농)으로 농지 개간" / "기본 방침 실패: 이미 최대 → 휴식".
- 활동 기록(`lastActiveTick`·`lastActiveAt`)은 로그인과 예턴 저장, 방침 바꾸기에서만 갱신한다. 조회와 SSE 연결은 활동으로 세지 않는다. v1 미접속 위임도 조회와 알림 구독을 활동에서 뺐다(v1 `docs/user/features.md:217`, 판정 `app/game-engine/src/main/kotlin/opensamguk/engine/campaign/OfflineDelegationLease.kt:69-72`).

### API 계약

```ts
general.policy({ worldId }) → PolicyResponse
general.setPolicy({ worldId, policy: PolicyKey }) → SetPolicyOutcome   // 엔진이 집행한다 (아래). 예턴 revision과 무관
turns.get / turns.set / turns.edit                                     // 칸 모양에 explicit 추가 (아래 예턴 칸 모양)
home.get                                                               // 장수 요약에 policy, 예턴 앞 5칸에 explicit 추가
```

`turns.set`에서 칸 값 `null`은 빈칸이고 `{ commandKey: 'rest' }`는 직접 넣은 휴식이다. 지금은 `null`도 휴식으로 바꿔 저장하므로(`apps/server/src/game/slots.ts:7-8`의 `parseSlot`), 빈칸을 따로 저장하도록 고친다.

### 방침 바꾸기 처리 (검토 R63-1, 2026-10-21 추가)

방침은 빈칸의 실행 결과를 바꾸므로 게임 상태로 보고 엔진만 바꾼다 (AGENTS.md §6). 접수와 대기는 장수 생성
`apps/server/src/routers/general.ts:35-95`를, 집행 자리는 `apps/engine/src/inputs.ts:11-80`을 따른다.

| 단계 | 누가 | 하는 일 |
| ---- | ---- | ------- |
| 접수 | API | 행위 장수를 세션에서 정하고 `PolicyKey`를 검사한 뒤 `PENDING` InputEvent `general.setPolicy`(payload `{ policy }`)를 만든다. 같은 장수의 `PENDING` 방침 입력이 있으면 값이 같을 때 그 입력을 기다리고 다르면 `CONFLICT` |
| 대기 | API | 최대 5초 다시 읽는다. `APPLIED`면 `{ status: 'applied', policy }`, `REJECTED`면 이유 코드로 오류, 시간이 지나면 `{ status: 'pending' }` |
| 집행 | 엔진 | 펜싱 트랜잭션 하나에서 `General.defaultPolicy`, `lastActiveTick`·`lastActiveAt`, InputEvent의 `APPLIED`·`sequence`·`result { policy, activeTick }`를 함께 쓴다. 장수가 없거나 계정이 제재됐으면 `REJECTED` |
| 재조회 | 화면 | `pending`이면 `general.policy`를 다시 읽는다. 응답의 `pending`이 null이 될 때까지 고른 방침을 처리 중으로 둔다 |

- 같은 장수의 턴이 방침 입력보다 먼저 실행되면 그 턴은 옛 방침을 따른다. 순서는 엔진이 매긴 sequence이고 재생도 같은 순서를 쓴다.
- 재생: `applyRecordedInput`(`packages/rules/src/replay.ts:67-107`)에 `general.setPolicy`·`general.active`를 더한다.
  방침과 `lastActiveTick`은 `ReplayState`에 `turns`·`revisions`처럼 장수별로 둔다(`replay.ts:13-18`).

### 활동 기록과 재생 결정론 (검토 R63-1, 2026-10-21 추가)

미접속 판정은 턴 결과를 바꾸므로 재생에서 같은 값이 나와야 한다 (AC-M1-13). 엔진과 재생은 벽시계를 읽지 않고 InputEvent에 기록된 tick만 쓴다.

- 판정: `isInactive(lastActiveTick, tick, turnTermMinutes)`는 `tick − lastActiveTick > 14 × 1,440 ÷ turnTermMinutes × 10,000`이면 참이다(`packages/rules/src/policy/`).
  1 tick이 `turnTermMinutes × 60,000 / 10,000` ms이므로(`docs/architecture/game-clock.md:35`) 월드가 돌아간 14일이다. 정지한 시간은 세지 않는다.
- `lastActiveTick`은 아래 활동 입력의 `result.activeTick`에서만 온다. 장수 생성 때는 생성 tick이다. NPC는 판정하지 않는다.
- `lastActiveAt`(현실 시각)은 그 InputEvent의 `createdAt`을 옮겨 적은 표시값이다. 감찰 표(T2-11)와 화면 안내만 쓰고 판정에 쓰지 않는다.

| 활동 | 기록 | activeTick | 쓰는 쪽 |
| ---- | ---- | ---------- | ------- |
| 예턴 저장·편집 | 기존 `turns.set` 입력(`apps/server/src/routers/turns.ts:65-77`)의 `result`에 더한다 | 같은 트랜잭션에서 읽은 `World.clockTick` | API. `turnRevision`처럼 예턴 저장 트랜잭션 안에서 `General.lastActiveTick`·`lastActiveAt`도 쓴다(`turns.ts:60-63`) |
| 방침 바꾸기 | `general.setPolicy` | 엔진이 집행한 tick | 엔진 |
| 로그인 | `general.active`(`PENDING`, payload 없음). 로그인이 성공하면 그 사용자의 RUNNING 월드 장수마다 하나 만든다. 이미 `PENDING`이 있으면 더 만들지 않는다 | 엔진이 집행한 tick | 엔진 |

- `World.clockTick`은 엔진의 체크포인트 값이라 실제보다 최대 5초 늦을 수 있다(`game-clock.md:48`). 판정 단위가 14일이라 무시한다.
- 조회와 SSE 연결은 활동이 아니다(위 결정).

### 화면(T2-14)이 기대하는 응답 모양

```ts
type PolicyKey = 'none' | 'farm' | 'commerce' | 'security' | 'defend' | 'drill';
type CommandRef = { key: string; name: string }; // name은 명령 레지스트리의 화면 이름

type PolicyOption = {
  key: PolicyKey;
  name: string;                  // '권농'·'중상'·'치안'·'수비'·'훈련', none은 '없음'
  emptyCommand: CommandRef;      // 빈칸에서 먼저 하는 명령. none은 휴식
  thenCommand: CommandRef | null; // 먼저 하는 명령이 이미 최대일 때 (수비: 성벽 보수, 훈련: 사기진작). 나머지는 null
};

type PolicyResponse = {
  current: PolicyKey;
  pending: PolicyKey | null; // 엔진이 아직 집행하지 않은 내 방침 입력. 없으면 null
  options: PolicyOption[];  // 위 결정 표의 순서 그대로, none이 마지막
  inactiveAfterDays: 14;    // 안내 문장에 그대로 쓴다. 월드가 돌아간 날 수다
};
type SetPolicyOutcome = { status: 'applied'; policy: PolicyResponse } | { status: 'pending' };

// SlotView는 아래 예턴 칸 모양에 있다. explicit이 false면 사용자가 비워 둔 칸이고,
// 화면은 이때 name 대신 현재 방침의 emptyCommand를 흐리게 보여 준다.

// home.get의 장수 요약에 더한다
type GeneralPolicySummary = { policy: { key: PolicyKey; name: string } };
```

방침 이름과 명령은 `packages/rules/src/policy/` 한곳에서 오고 화면은 이 응답만 보고 문장을 만든다. 화면에 방침 표를 따로 적지 않는다.

| T2-14 화면 요소 | 쓰는 응답 |
| --------------- | --------- |
| 방침 고르기와 바로 보내기, 처리 중 표시 | `PolicyResponse.options`, `pending`, `general.setPolicy`의 `SetPolicyOutcome` |
| "빈 칸은 X를 합니다. 실패하면 휴식합니다." | 현재 방침의 `emptyCommand`, `thenCommand` |
| 빈 칸 흐린 "(권농) 농지 개간"과 직접 넣은 진한 휴식 | `SlotView.explicit` + 현재 방침 |
| 14일 미접속 안내 한 줄 | `inactiveAfterDays` |
| 메인 장수 요약의 방침, 예턴 앞 5칸 | `GeneralPolicySummary`, `SlotView.explicit` |

### 예턴 칸 모양 (검토 R62-2·R63-2, 2026-10-21 추가)

T2-11 작전판도 이 모양을 그대로 쓴다. 칸 모양과 비교 함수는 이곳 하나뿐이다.

```ts
// 규칙·저장·재생·엔진의 칸. 빈칸은 emptyTurn() = { commandKey: 'rest', args: {}, explicit: false } 하나다
interface QueuedTurn { commandKey: string; args: unknown; explicit: boolean }
// 화면으로 나가는 칸. turns.get·turns.set·turns.edit 응답, STALE 응답, home.get 앞 5칸,
// T2-11의 operation.get·operation.suggest·inspection.members가 쓴다. 30칸 모두 객체이고 null이 없다
type SlotView = { commandKey: string; args: unknown; name: string; explicit: boolean };
// 화면에서 들어오는 칸(turns.set). null은 빈칸, 객체는 직접 넣은 칸이다. 직접 넣은 휴식은 { commandKey: 'rest' }
type SlotInput = { commandKey: string; args?: unknown } | null;
// 화면이 받은 SlotView를 다시 저장할 때의 변환. apps/web 한곳에 둔다
const toSlotInput = (v: SlotView): SlotInput => (v.explicit ? { commandKey: v.commandKey, args: v.args } : null);
// 두 칸이 같은지. packages/rules 한곳에 둔다. T2-11의 changed가 쓴다.
// 빈칸끼리는 같다. 빈칸과 직접 넣은 칸은 다르다. 직접 넣은 칸끼리는 commandKey와 args(키 순서 무시)를 비교한다
declare function sameSlot(a: QueuedTurn, b: QueuedTurn): boolean;
```

`explicit`은 아래 경로를 모두 지나도 보존해야 한다. 모두 T2-13(Codex) 범위다.

| 경로 | 지금 | 바꿀 것 |
| ---- | ---- | ------- |
| DB | `GeneralTurn`에 칸 구분이 없다 (`packages/db/prisma/schema.prisma:173-182`) | 새 migration으로 `explicit Boolean @default(false)`를 더한다. 기존 행은 `commandKey <> 'rest'`이면 true다. M1은 빈칸과 직접 넣은 휴식을 나누지 않았으므로 기존 휴식은 모두 빈칸으로 본다 |
| 규칙 타입 | `QueuedTurn`이 commandKey·args만 (`packages/rules/src/replay.ts:9-12`), `emptyTurns`가 휴식 30칸 (`replay.ts:27`) | `explicit`을 더하고 `emptyTurn()`·`emptyTurns()`가 빈칸을 만든다 |
| 입력 해석 | `parseSlot`이 null을 휴식으로 바꾼다 (`apps/server/src/game/slots.ts:7-14`) | null은 빈칸, 객체는 explicit true |
| 읽기 | `readSlots`·`displaySlots` (`slots.ts:15-24`), 메인 앞 5칸 (`apps/server/src/routers/home.ts:47`) | 행의 explicit을 그대로 싣는다. 행이 없으면 빈칸 |
| 편집 | `turns.edit`의 put과 `editArray` 채움 값 (`apps/server/src/routers/turns.ts:98-104`) | put은 explicit true. shift로 생긴 칸은 `emptyTurn()`. repeat는 복사한 칸의 explicit을 그대로 둔다 |
| STALE | 현재 칸을 `displaySlots`로 돌려준다 (`turns.ts:47-48`) | explicit을 담은 SlotView 30칸 |
| 입력 기록 | `turns.set` payload의 turns (`turns.ts:65-77`) | 칸마다 explicit을 싣는다 |
| 재생 | 예턴 기록 검사와 대입 (`replay.ts:70-86`), 당긴 뒤 휴식 채움 (`replay.ts:62`), 생성 장수 (`replay.ts:101`) | explicit을 검사해 대입하고 당긴 뒤 끝 칸은 `emptyTurn()`이다. explicit이 없는 옛 기록은 `commandKey !== 'rest'`로 읽는다(migration과 같은 규칙) |
| 엔진 당김 | `shiftTurns`가 끝 칸을 휴식으로 채운다 (`apps/engine/src/persist.ts:40-55`) | 칸의 explicit을 함께 옮기고 끝 칸은 빈칸 |
| 엔진 실행 | 0번 칸을 읽어 그대로 실행한다 (`apps/engine/src/turnLoop.ts:127-135`) | explicit false면 위 결정 표대로 방침 명령을 고른다. 고르기는 rules의 한 함수이고 재생도 같은 함수를 부른다 |
| 장수 생성 | 휴식 30칸 (`apps/engine/src/inputs.ts:61-69`) | 빈칸 30칸 |

옛 기록을 위 규칙으로 읽으면 방침 기본값이 `none`이라 빈칸도 휴식으로 실행된다. M1 월드의 재생 결과는 바뀌지 않는다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 빈칸 | 단위: 방침 권농 + 빈칸 → 농지 개간 실행 |
| 직접 휴식 | 단위: 사용자가 넣은 휴식 → 휴식 |
| 빈칸 저장 | API: `turns.set`에 `null`과 `{ commandKey: 'rest' }`를 넣고 `turns.get` → `explicit`이 false·true로 돌아옴 |
| 칸 보존 | 통합: 빈칸과 직접 휴식을 섞어 저장 → `turns.edit` shift·repeat → 엔진 당김 → `turns.get`과 재생 결과 모두 explicit 그대로, 끝 칸은 빈칸 |
| STALE | API: revision이 어긋난 저장 → 저장 안 됨, explicit을 담은 현재 30칸 |
| 옛 기록 | 재생: explicit이 없는 M1 `turns.set` 기록 → 지금과 같은 상태 해시 |
| 방침 집행 | 통합: `setPolicy` 접수 직후 `defaultPolicy` 그대로, 엔진 처리 뒤 `APPLIED`·sequence와 함께 바뀜. 5초 안에 못 끝나면 `pending`, `general.policy` 재조회로 확인 |
| 방침 멱등 | API: 같은 값 두 번 → 입력 하나, 다른 값 → `CONFLICT`. 무인증·제재·잘못된 `PolicyKey` 거부 |
| 미접속 판정 | 단위: `isInactive` 경계(14일치 tick과 그보다 1 많은 tick), `turnTermMinutes`가 다른 두 월드 |
| 실패 | 단위: 농업 최대 → 휴식 + 실패 이유 로그 |
| 미접속 | 시나리오: 15일치 tick 동안 활동 기록 없음 → 방침 범위 AI, 출병 없음 / 로그인 → 사람 예턴 |
| 결정성 | 재생 테스트에 방침 변경·로그인 활동·예턴 저장 InputEvent 포함. 벽시계를 바꿔 재생해도 같은 상태 해시 |
