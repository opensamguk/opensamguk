# T2-13 D12 기본 방침

> 대기열: T2-13 · AC: AC-M2-17 · 구현: Codex · 리뷰: Claude
> 선행: M1 전체 · 관련: [차별화 D12](../product/differentiation.md#d12-기본-방침), FR-DIF-12, FR-GEN-04

## 계획 (Claude)

### 목표

기본 방침을 정한 장수의 빈 예턴 칸은 휴식 대신 방침에 맞는 명령으로 실행된다. 그 명령이 실패하면 휴식으로 대신하고 이유가 로그에
남는다. 장기 미접속 장수는 방침 범위 안에서만 AI가 고른다 (AC-M2-17).

### 범위

- `General.defaultPolicy`, `General.lastActiveAt`(이미 있으면 갱신 지점만)
- `packages/rules/src/policy/`: 방침 → 명령 대응, 미접속 판정
- engine 턴 실행에서 빈칸 처리 분기
- `apps/server`: `general.setPolicy`, 로그인·예턴 저장 때 `lastActiveAt` 갱신

### 하지 않는 것

국가 단위 방침(myosam 국가점수 정책, Phase 2), 장수 삭제·NPC화 정책(지인 테스트 뒤 결정).

### 결정

| 방침 | 빈칸에서 실행 | 실패하면 |
| ---- | ------------- | -------- |
| `farm` 권농 | 농지 개간 | 휴식 + 이유 |
| `commerce` 중상 | 상업 투자 | 〃 |
| `security` 치안 | 치안 강화 | 〃 |
| `defend` 수비 | 수비 강화 → 최대면 성벽 보수 | 〃 |
| `drill` 훈련 | 훈련 → 최대면 사기진작 | 〃 |
| `none` | 휴식 (M1과 같음) | — |

- 빈칸은 사용자가 아무것도 넣지 않은 칸이다. 사용자가 **직접 넣은 휴식은 그대로 휴식**이다 (구분을 위해 저장 형식에 `explicit` 표시).
- 미접속: `lastActiveAt`이 14일 넘게 지난 장수는 빈칸뿐 아니라 **모든 칸을** 방침 범위의 NPC AI가 고른다 (출병·이동·임관 같은 큰 결정은 하지 않음).
  다시 접속하면 즉시 사람 예턴으로 돌아온다.
- 로그: "기본 방침(권농)으로 농지 개간" / "기본 방침 실패: 이미 최대 → 휴식".
- `lastActiveAt`은 로그인과 예턴 저장, 방침 바꾸기에서만 갱신한다. 조회와 SSE 연결은 활동으로 세지 않는다. v1 미접속 위임도 조회와 알림 구독을 활동에서 뺐다(v1 `docs/user/features.md:217`, 판정 `app/game-engine/src/main/kotlin/opensamguk/engine/campaign/OfflineDelegationLease.kt:69-72`).

### API 계약

```ts
general.policy({ worldId }) → PolicyResponse
general.setPolicy({ worldId, policy: PolicyKey }) → PolicyResponse   // 바로 저장, 예턴 revision과 무관
turns.get / turns.set                                                // 칸 모양에 explicit 추가 (아래)
home.get                                                             // 장수 요약에 policy, 예턴 앞 5칸에 explicit 추가
```

`turns.set`에서 칸 값 `null`은 빈칸이고 `{ commandKey: 'rest' }`는 직접 넣은 휴식이다. 지금은 `null`도 휴식으로 바꿔 저장하므로(`apps/server/src/game/slots.ts`의 `parseSlot`), 빈칸을 따로 저장하도록 고친다.

### 화면(T2-14)이 기대하는 응답 모양

```ts
type PolicyKey = 'none' | 'farm' | 'commerce' | 'security' | 'defend' | 'drill';
type CommandRef = { key: string; name: string }; // name은 명령 레지스트리의 화면 이름

type PolicyOption = {
  key: PolicyKey;
  name: string;                  // '권농'·'중상'·'치안'·'수비'·'훈련', none은 '없음'
  emptyCommand: CommandRef;      // 빈칸에서 먼저 하는 명령. none은 휴식
  thenCommand: CommandRef | null; // 먼저 하는 명령이 이미 최대일 때 (수비: 성벽 보수, 훈련: 사기진작). 나머지는 null
};

type PolicyResponse = {
  current: PolicyKey;
  options: PolicyOption[];  // 위 결정 표의 순서 그대로, none이 마지막
  inactiveAfterDays: 14;    // 안내 문장에 그대로 쓴다
};

// turns.get·turns.set 응답과 home.get의 예턴 앞 5칸
type SlotView = {
  commandKey: string;
  args: unknown;
  name: string;
  explicit: boolean; // false면 사용자가 비워 둔 칸. 화면은 이때 name 대신 현재 방침의 emptyCommand를 흐리게 보여 준다
};

// home.get의 장수 요약에 더한다
type GeneralPolicySummary = { policy: { key: PolicyKey; name: string } };
```

방침 이름과 명령은 `packages/rules/src/policy/` 한곳에서 오고 화면은 이 응답만 보고 문장을 만든다. 화면에 방침 표를 따로 적지 않는다.

| T2-14 화면 요소 | 쓰는 응답 |
| --------------- | --------- |
| 방침 고르기와 바로 저장 | `PolicyResponse.options`, `general.setPolicy` |
| "빈 칸은 X를 합니다. 실패하면 휴식합니다." | 현재 방침의 `emptyCommand`, `thenCommand` |
| 빈 칸 흐린 "(권농) 농지 개간"과 직접 넣은 진한 휴식 | `SlotView.explicit` + 현재 방침 |
| 14일 미접속 안내 한 줄 | `inactiveAfterDays` |
| 메인 장수 요약의 방침, 예턴 앞 5칸 | `GeneralPolicySummary`, `SlotView.explicit` |

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 빈칸 | 단위: 방침 권농 + 빈칸 → 농지 개간 실행 |
| 직접 휴식 | 단위: 사용자가 넣은 휴식 → 휴식 |
| 빈칸 저장 | API: `turns.set`에 `null`과 `{ commandKey: 'rest' }`를 넣고 `turns.get` → `explicit`이 false·true로 돌아옴 |
| 실패 | 단위: 농업 최대 → 휴식 + 실패 이유 로그 |
| 미접속 | 시나리오: 15일 미접속 → 방침 범위 AI, 출병 없음 / 접속 → 사람 예턴 |
| 결정성 | 재생 테스트에 방침 변경 InputEvent 포함 |
