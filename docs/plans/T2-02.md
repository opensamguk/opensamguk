# T2-02 월드 규칙 프리셋 (D5)

> 대기열: T2-02 · AC: AC-M2-03 · 구현: Codex · 리뷰: Claude
> 선행: T2-01 · 관련: [차별화 D5](../product/differentiation.md#d5-월드-규칙-프리셋-기본-포함), FR-WLD-05, FR-NPC-04

## 계획 (Claude)

### 목표

규칙 프리셋 파일 하나로 턴 간격·시작 조건·명령 세트·NPC 설정이 바뀐다 (AC-M2-03).

### 범위

- `resources/preset/*.json` 4종: `regular`(정규), `speed`(속성), `beginner`(초보), `hardcore`(하드코어)
- `packages/rules/src/world/preset.ts`: zod 스키마와 적용 함수
- `world:create --preset <key>` (기존 `--scenario`·`--turn-term`보다 프리셋이 기본값, 명령줄 값이 우선)
  월드 총정원은 이 작업에 없다. 총정원 결정이 승인되면 T2-03이 같은 `world:create`에 필수 `--max-generals`를 더한다. 이 작업으로 만든 월드는 정원이 비어 있어 운영자가 `world:capacity`로 정한 뒤에 참가할 수 있다 ([T2-03](./T2-03.md) 선행 인계).
- `World.presetKey`, `World.preset`(만들 때의 프리셋 내용 사본)

### 하지 않는 것

프리셋 편집 화면(M3 관리자), 원작 수치 맞추기.

#### K7 상세 (`presetRules`)

이름과 스키마 (`packages/rules/src/world/preset.ts`):

```ts
interface PresetRules {
  protection: { foundUntilMonths: number; peaceMonths: number; maxGeneralsPerNation: number | null };
  npc: { aggression: number };
  boost: {
    smallWorld: { below: number; multiplier: number }[] | null;
    lateJoin: {
      fromYear: number;
      experienceRatio: number;
      percentile: number;
      goldPerYear: number;
      ricePerYear: number;
      maxYears: number;
    } | null;
  };
}
```

- 정수 칸은 0 이상 정수다. `maxGeneralsPerNation`은 1 이상 정수 또는 `null`, `aggression`은 0 초과 3 이하, `multiplier`는 1 초과 3 이하다. `smallWorld`는 1개 이상이며 `below`가 1 이상이고 엄격히 오름차순이다. `experienceRatio`·`percentile`은 0 초과 1 이하다. 이 범위는 잘못된 파일을 막는 기술 경계이며 제품 값이 아니다.
- `npc.fillRatio`, `features.advisor`, `turnTermMinutes`, 리소스 키는 `presetRules`에 넣지 않는다. `fillRatio`는 생성 때 한 번 쓰이고 그 결과가 `initial`에 이미 남는다. `advisor`는 화면용이다.
- 키 위치: `WorldInit.presetRules?`(`packages/rules/src/world/bootstrap.ts`), `WorldState.presetRules?`(`packages/rules/src/model/world.ts`). 프리셋 월드만 키가 있다. 레거시 월드에는 키 자체가 없다. `ext`·`commandMeta`와 같은 조건부 펼침 모양을 쓴다.

경로별 연결 (모두 이 작업 몫):

| 경로 | 파일 | 할 일 |
| ---- | ---- | ----- |
| 생성 | `apps/engine/src/world/persistence.ts` | `initial.presetRules = presetRules(preset)`를 넣은 뒤 `hashState(initial)`과 `replayOrigin.initial`을 만든다. `World.preset`도 같은 트랜잭션에 쓴다 |
| 생성 NPC 비율 | `packages/rules/src/world/bootstrap.ts` `buildInitialWorld` | 1이 아닌 값의 방식은 P-3 답 뒤 확정한다. 아래는 제안이다. `fillRatio`를 받으면 국가 군주는 남긴다. 나머지 시나리오 장수를 id 순으로 놓고 `rngFor(seed, 'preset-fill')`로 `round(n × fillRatio)`명을 고른다. 받지 않으면 지금 코드 경로를 그대로 탄다 |

규칙 적용 (같은 함수가 서버·엔진·NPC를 모두 탄다):

- `defineCommand`는 `precheck`와 `check`에 같은 함수를 쓴다(`commands/support.ts`). 서버 `turns.precheck`는 `def.precheck`를, 엔진 `runCommand`와 NPC `chooser.add`는 `command.check`를 부른다. 그래서 보호 검사는 각 명령의 `check` 안 한 곳에만 둔다.
- 경과 개월은 `Math.floor(actor.tick / TICKS_PER_MONTH)`이다. 서버는 `actor.tick = general.nextTurnTick`을, 엔진은 실행 tick을 넘기므로 사전 검사와 실행이 같은 달을 본다.
- 실패 코드 `PROTECTED`를 `commands/types.ts`의 `Failure.code`에 더한다. 문구는 글쓰기 규칙을 따른다.

| 값 | 적용 위치 | 레거시·`null`·0일 때 |
| -- | --------- | -------------------- |
| `peaceMonths` | `commands/attack.ts` `attack`, `commands/nation.ts` `nation_declare`의 `check` | 0이면 검사를 건너뛴다 |
| `foundUntilMonths` | `commands/personnel.ts`의 `found`·`uprising` `check` | 0이면 건너뛴다 |
| `maxGeneralsPerNation` | `personnel.ts`의 `join`·`join_random`·`accept_invite` `check`. 값이 있을 때의 방식은 P-6 답 뒤 확정한다. 제안은 대상 국가의 사람 장수(`userId !== null`) 수가 상한 이상이면 실패 | `null`이면 건너뛴다 |
| `npc.aggression` | `packages/rules/src/npc/index.ts`. `attack`과 `nation_declare` 후보 점수에 곱한다. 최고 점수 선택 알고리즘, 훈련·사기·군량 기준, RNG 소비 순서는 그대로 둔다 | 키가 없거나 1이면 곱하지 않는다. 레거시와 선택·RNG 소비가 바이트까지 같다 |

`aggression`의 뜻과 한계. 출병·선포 후보의 점수 가중치이며 출병 빈도의 배수가 아니다. 최고 점수 하나를 고르므로 상태에 따라 선택이 바뀌기도 하고 그대로이기도 하다. 0.5배나 1.5배의 출병 횟수를 말하거나 보장하지 않는다.
| `boost.smallWorld` | `commands/domestic/investment.ts`. 사람 장수 수가 `below` 미만인 첫 칸의 배수를 도시·국가 변화량(`cityScore`)에 곱한다. 경험·공헌(`points`)은 그대로 | `null`이면 곱하지 않는다 |
| `boost.lateJoin` | `apps/engine/src/inputs.ts` `processCreation` → `packages/rules/src/general/create.ts` `buildCreatedGeneral`의 새 선택 입력 `bonus` | `null`이면 지금 값(금·쌀 1000, 경험 0) |

`lateJoin` 계산. 상대 연도 `relYear`는 생성 시점 게임 연도에서 시작 연도를 뺀 값이다(`buildCreatedGeneral`의 `birthYear`와 같은 달력 기준). `relYear >= fromYear`이면 국가 소속 장수의 경험을 오름차순(동률은 id)으로 놓는다. 그 가운데 `max(1, round(수 × percentile))`번째 값에 `experienceRatio`를 곱해 반올림한 값을 경험으로 준다. 금·쌀은 `1000 + perYear × min(relYear, maxYears)`이다. 결과는 `general.create` 입력 기록의 `result.general`에 실린다. 순수 재생은 이 기록을 그대로 적용하므로 다시 계산하지 않는다.

#### K8 상세 (재생 기록)

`09604e7`에서 실제로 확인한 사실:

- `persistence.ts`는 `replayOrigin.initial`에 `WorldInit` 전체를 그대로 저장하고 `initialStateHash = hashState(initial)`을 쓴다.
- `apps/engine/src/replay.ts`의 `readArchive`는 엄격한 스키마 파서가 아니다. 모양 검사 뒤 `origin.initialStateHash === hashState(origin.initial)`을 확인한다. 그래서 `initial`의 선택 키는 버려지지 않고 해시에 들어간다. `resourceHash`는 시나리오·지도·병종 키와 `statRules`·`unitSet`만 본다.
- `initialReplayState`는 `toWorldState(origin.initial)`을 부른다. 지금 `toWorldState`는 아는 키만 옮기므로 K7의 상태 변환 수정이 있어야 재생 상태에 `presetRules`가 들어간다.

계약:

- 레거시 월드에는 `presetRules` 키가 없다. 상태 해시, v1 origin, 저장된 `initialStateHash`, 월간 `stateHash`가 바이트까지 같다.
- 프리셋 월드는 같은 v1 origin `initial`에 `presetRules`가 실리고 `initialStateHash`가 그것까지 덮는다. 기록 버전은 v1(origin)과 v2(T1-26 archive, `config`·`end`·`afterEnd`) 그대로다.
- 엔진 적재값과 origin 값이 같아야 한다. `presetRules(parsePreset(World.preset))`과 `origin.initial.presetRules`가 같은지 생성 직후 해시 비교 시험으로 묶는다.
- 이 작업 이전 코드로 프리셋 월드 기록을 읽으면 키가 버려져 첫 월간 해시에서 실패한다. 조용히 다른 결과를 내지 않는다.
- 확장 명령을 켠 월드의 `ext` 기록과 새 형식(예상 v3)은 T4-03이다.

`world:create` 명령줄 계약:

- `--preset <key>`가 있으면 `resources/preset/<key>.json`을 읽는다. key는 기존 `resourceKey` 검사를 그대로 쓴다. 파일이 없거나 스키마가 틀리면 DB에 아무것도 쓰지 않고 실패한다.
- 프리셋의 `scenario`·`map`·`unitSet`은 `loadInitialWorld`가 실제 리소스로 읽어 검사한다. `--scenario`·`--map`·`--turn-term`을 함께 주면 명령줄 값이 이긴다. 턴 간격 범위는 지금 검사(1~2147483647분)를 그대로 쓴다.
- `--seed`, `--end-year`, `--name`은 지금처럼 필수다. 프리셋은 종료 연도 기본값을 주지 않는다.
- `--preset`이 없으면 지금 동작과 같고 `presetKey`·`preset`은 `null`이다. 기존 통합 시험은 고치지 않고 통과해야 한다.

API: T2-02는 tRPC 프로시저를 더하지 않는다. 로비의 `presetName`은 T2-03이다. 구현 중 프로시저를 하나라도 더하면 `apps/server/src/authz/coverage.ts`의 다섯 범주(성공, 무인증, 다른 사용자, 제재, 잘못된 입력) 증거를 함께 넣고 행위자는 세션에서 정한다(`protectedProcedure`).

### AC-M2-03 완료 판정 경계

- 시험용 확장 목록을 주입한 단위 시험은 resolver 기반이 맞는지 보는 순수 검증이다. 실제 프리셋의 명령 세트가 바뀐다는 AC 몫을 대신하지 못한다.
- 운영 확장 목록이 비어 있어 지금 프리셋 4종의 명령 세트는 같다. 실제 확장 명령 등록과, 그것을 켠 월드의 HTTP 저장 → 사전 검사 → 엔진 실행 → 재시작 → 재생은 T4-03이 끝나기 전까지 미완료다. 그때까지 AC-M2-03은 ✅가 될 수 없다. <!-- lint-text-ignore C-5 -->
- T2-02 몫은 턴 간격·시작 조건(보호)·NPC 설정·인원 보정이 실제 HTTP·엔진·재시작·재생에서 동작하는 것이다. 이 몫은 T4-03을 기다리지 않는다.

### 승인 대기 (사용자 제품 결정)

### 실제 PostgreSQL·HTTP·재시작·재생 검증

mock만으로 끝내지 않는다. 아래는 위 검증 표를 대신하지 않고 더한다. 값이 있는 효과는 시험 전용 맞춤 프리셋으로 본다. 맞춤 프리셋은 임시 리소스 폴더에 두며 모든 칸이 0이나 `null`이 아니다.

| 무엇 | 어떻게 |
| ---- | ------ |
| migration | `pnpm db:migrate`가 빈 DB와 기존 월드가 있는 DB 모두에서 성공. 기존 월드의 두 칸은 `null` |
| 생성 | `pnpm test:int`: 실제 PostgreSQL에서 `speed`·`beginner`·맞춤 프리셋으로 월드를 만든 뒤 `presetKey`·`preset`·턴 간격·시나리오 칸과 `replayOrigin.initial.presetRules`를 읽어 비교 |
| 실패 원자성 | 없는 프리셋, 스키마 위반, 기본 key가 든 `commands`, 없는 시나리오 키로 만들면 실패하고 `World` 행 수가 그대로 |
| 레거시 | `--preset` 없이 만든 월드의 `initialStateHash`, v1 origin, 12개월 월간 `stateHash`가 변경 전 골든과 바이트가 같다 |
| 고정 | 생성 뒤 임시 리소스 폴더의 프리셋 파일을 고쳐도 DB의 `preset`과 엔진이 읽는 `presetRules`가 그대로 |
| 보호 HTTP | 맞춤 프리셋 월드에서 `turns.precheck`를 HTTP로 불러 보호 기간 안 `attack`·`nation_declare`·`found`가 `PROTECTED`. 같은 예턴을 엔진이 실행해도 같은 코드로 실패. 시계를 기간 뒤로 옮기면 둘 다 통과 |
| 국가 정원 | P-6 답 뒤. 상한에 찬 국가로 `join`이 사전 검사와 실행 모두 실패 |
| NPC 성향 | 후보 점수가 `aggression`만큼 곱해졌는지 본다. 다른 후보나 동률이 있는 상태에서 선택이 실제로 달라지는지 본다. 예: 1.5배 출병 120이 훈련 100보다 앞섬, 0.5배 선포 50이 국고 1만 이상 50점 후보와 동률. 1.0과 키 없음은 레거시와 선택·RNG 소비가 같다. 출병 횟수가 절반이나 1.5배가 된다는 시험은 두지 않는다 |
| 인원 보정 | 사람 장수 수가 `below` 미만인 월드에서 내정 명령의 도시 변화량이 배수만큼 크다. 경험·공헌은 같다 |
| 늦게 온 장수 | `general.create`를 HTTP로 넣고 엔진이 처리한 장수의 경험·금·쌀이 계산식과 같다 |
| 재시작 | 엔진 재시작 뒤 `loadReplayState` 해시가 재시작 전과 같고 보호·보정이 그대로 걸린다 |
| 재생 | 맞춤 프리셋 월드를 12개월 돌린 뒤 `exportReplay` → `replayArchive(archive, 12)`가 통과. 종료까지 간 월드는 `replayToEnd`도 통과 |
| 턴 간격 | `speed` 월드의 다음 턴 시각이 10분 간격으로 잡힌다 |
| 권한 | 새 프로시저가 없으므로 기존 `turns.precheck`·`general.create` 권한 증거를 쓴다 |
