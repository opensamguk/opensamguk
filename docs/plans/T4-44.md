## 계획 (Claude)

### 1. 목표

AC-P2-22 제안 문장(U-15 1차 범위에 맞춤): 월드가 끝나면 그 월드의 기수 결과(끝난 이유, 통일 국가, 연도, 장수 순위)가 보관되고 종료 뒤에도 로그인한 사용자가 볼 수 있다. 같은 순간 업적 기준에 맞는 사람 장수의 계정에 칭호 3~5종 가운데 해당하는 것이 붙는다. 계정에는 칭호와 받은 기수만 보관한다. 다음 기수의 월드에서는 그 계정 장수의 이름 옆에 칭호가 보일 뿐 능력치, 자원, 명령, 순위 계산에 혜택이 없다. 칭호 계산은 끝난 월드의 상태와 누계에서만 나오며 같은 결과에서 같은 칭호가 나온다.

U-15의 사용자 결정은 아래와 같다.

- 기수 종료 때 통일 군주, 장수 순위 상위, 전공 등 칭호 3~5개.
- 계정에는 칭호와 받은 기수만 보관한다.
- 다음 기수에는 이름 옆 표시만 하고 능력 혜택은 없다.
- 기수 결과 보관(FR-REC-03) 표가 함께 필요하다.

| (가) | 칭호 기준 순수 함수, 기수 결과 보관 표, 종료 트랜잭션에서 보관과 칭호 부여 | Codex → Claude |
| (나) | 기수 결과 조회, 내 칭호 조회, 대표 칭호 고르기, 월드별 칭호 표시 조회 API | Codex → Claude |
| (다) | 기수 결과 화면 확장, 내 칭호 화면, 이름 옆 칭호 표시, 플레이어 가이드 | Claude → Codex |

### 3. 칭호 후보

장수 순위는 종료 순간의 공헌·경험·전공이며 지금 순위 화면과 같은 함수로 센다. 사람 장수(`userId`가 있는 장수)만 받는다. NPC 장수는 순위에는 남지만 칭호를 받지 않는다.

| ID | 칭호 (이름 초안) | 기준 | 받는 수 |
| -- | ---------------- | ---- | ------- |
| TT1 | 천하통일 군주 | `reason = UNIFIED`이고 종료 순간 승자 국가의 군주(`officerLevel = 12`) | 0~1 |
| TT2 | 공헌 으뜸 | 공헌 순위 1위 | 0~1 |
| TT3 | 전공 으뜸 | 전공(승리 + 포로) 순위 1위. 전공이 0이면 주지 않는다 | 0~1 |
| TT4 | 경험 으뜸 | 경험 순위 1위 | 0~1 |
| TT5 | 통일 공신 | `reason = UNIFIED`이고 승자 국가 소속 사람 장수 가운데 TT1이 아닌 장수 | 0~n |

순위 1위가 NPC면 그 칭호는 아무도 받지 않는다. 다음 순위의 사람 장수에게 넘기지 않는다. 한 장수가 여러 칭호를 받을 수 있다. TT5는 받는 사람이 많아질 수 있어 RQ44-1에서 넣을지 정한다.

### 4. 범위와 계약 초안

#### 4.1 (가) 규칙과 보관 (Codex)

| 파일 | 내용 |
| ---- | ---- |

```prisma
model SeasonGeneral {
  worldId     String
  generalId   Int
  userId      String?
  name        String
  nationId    Int?
  nationName  String?
  nationColor String?
  officerLevel Int
  dedication  Int
  experience  Int
  wins        Int
  captures    Int
  world       World @relation(fields: [worldId], references: [id], onDelete: Cascade)

  @@id([worldId, generalId])
}

model AccountTitle {
  id        String   @id @default(uuid())
  userId    String
  worldId   String
  worldName String
  titleKey  String
  awardedAt DateTime
  displayed Boolean  @default(false)
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([userId, worldId, titleKey])
  @@index([userId, awardedAt])
}
```

- `SeasonGeneral`은 FR-REC-03의 장수 순위 몫이다. 종료 순간 등장한 장수 전부를 한 번 쓰고 다시 쓰지 않는다. `RankingSnapshot`은 월간 정산마다 덮어써서 통일로 달 중간에 끝나면 마지막 순간과 다르기 때문에 따로 둔다.
- `AccountTitle`은 U-15대로 칭호와 받은 기수(월드 id와 이름)만 담는다. 장수 이름과 능력은 담지 않는다. 월드가 지워져도 칭호가 남게 `World`와 관계를 걸지 않고 `worldName`을 사본으로 둔다. `displayed`는 RQ44-4 (가)일 때 대표 칭호 표시에 쓴다. 사용자당 `displayed = true`는 많아야 하나이며 바꾸는 트랜잭션이 보장한다.
- 같은 트랜잭션 범위(C5): `persistSeasonArchive`는 `WorldResult`와 같은 트랜잭션에서 쓴다. commit 직전 실패면 결과, 장수 행, 칭호가 모두 없다.
- 결정성: 칭호는 종료 순간 상태와 DB 누계(`battleWins`·`captures`)에서만 나온다. 누계는 상태 해시에 들어가지 않으므로 재생 해시 동등성 대상이 아니다. 대신 `seasonTitles`가 같은 입력에서 같은 출력을 낸다는 단위 시험과 `SeasonGeneral` 행에서 칭호를 다시 계산해 저장값과 같은지 보는 통합 시험으로 증명한다.
- 혜택 없음: 칭호 표는 규칙 패키지의 상태 입력(`WorldState`, `WorldInit`, 프리셋)에 들어가지 않는다. 장수 생성, 명령, 순위 계산은 `AccountTitle`을 읽지 않는다. 정적 시험이 `packages/rules`와 엔진 턴·월간 경로에서 `accountTitle` 참조가 없음을 본다.

### 6. 열린 사용자 결정

| ID | 결정할 것 | 선택지 | 권장 |
| -- | --------- | ------ | ---- |
| RQ44-1 | 칭호 목록 | §3 TT1~TT5 가운데 3~5개 | TT1~TT4 네 개. TT5는 통일 국가 장수 전원이 받아 칭호 값이 흐려진다 |
| RQ44-2 | 칭호 이름 | §3 이름 초안 그대로, 또는 사료 관직·칭호에서 고른 이름 | 초안 그대로. 사료 관직 이름은 실제 관직과 헷갈린다 |
| RQ44-3 | 다음 기수의 뜻 | (가) 칭호를 받은 뒤 만들어진 월드 (나) 받은 월드를 뺀 모든 월드 (다) 모든 월드 | (가). U-15의 다음 기수에 가장 가깝다 |
| RQ44-4 | 표시 방식과 계정 노출 | (가) 대표 칭호 하나를 사용자가 고르고 고르지 않으면 표시하지 않음 (나) 가장 최근 칭호를 자동 표시 (다) 받은 칭호 전부 표시 | (가). 칭호는 다른 월드의 같은 계정을 드러내므로 본인이 켤 때만 보인다 |
| RQ44-5 | `END_YEAR` 종료의 칭호 | (가) TT2~TT4만 준다 (나) 끝까지 남은 국가 가운데 도시가 가장 많은 국가의 군주에게도 칭호 | (가). U-15 예시 밖의 새 기준을 만들지 않는다 |
| RQ44-6 | 이 작업의 기수 결과 보관을 FR-REC-03(M3) 완료 증거로도 셀지 | (가) T4-44 증거로만 (나) M3 FR-REC-03에도 연결(대기열 행 추가 필요) | 조율 세션과 사용자가 정한다. 이 계획은 (가)로 쓴다 |

RQ44-1~RQ44-4가 정해지기 전에는 칭호 표를 계약 준비로 올리지 않는다. 기수 결과 보관(`SeasonGeneral`, `records.season`)은 결정 없이 진행할 수 있다.
