### 2. 증축·감축 공통부

T4-74는 이 절을 그대로 쓴다.

#### 2.1 공통 검사 `capitalScaleCheck(view, actor)`

`defineCommand`의 국가 명령 검사(장수 없음, 인자, 국가 없음, 실행 직책) 뒤에 아래 순서로 본다. 통과하면 수도 도시를 돌려준다.

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | 행위자 도시가 자기 국가 도시가 아님 | `NOT_OWN_CITY` | 자기 국가 도시에서만 가능합니다. |
| 2 | 행위자 도시 보급 끊김 | `NO_SUPPLY` | 보급이 끊긴 도시입니다. |
| 3 | 수도가 국가 소유가 아님 | `BAD_STATE` | 수도가 없는 국가는 할 수 없습니다. |

1·2는 `ownCity`(`commands/support.ts:11-19`)와 같은 문구다. 3은 원작의 수도 없음(방랑) 검사다. 우리 국가는 `capitalCityKey`가 늘 숫자라(`world/bootstrap.ts:43`) 그 도시가 자기 국가 소유인지로 본다. 기존 `return`의 판정(`commands/military.ts:96-99`)과 같다. T4-48이 방랑 표식을 따로 두면 3번은 그 표식도 함께 본다.

#### 2.2 조각 `capital_scale`

| 항목 | 계약 |
| ---- | ---- |
| key | `capital_scale` |
| 값 | `{ origin: { [cityKey: string]: number }, changes: { [nationId: string]: number } }` |
| `create(context)` | `origin`에 `context.cities`의 모든 도시 규모를 적는다. `changes`는 빈 객체 |
| `validate` | 키는 양의 정수 문자열, `origin` 값과 `changes` 값은 0 이상 정수. `origin`에 상한을 두지 않는다. 지도 스키마의 `level`이 0 이상 정수이고 상한이 없으므로(`world/resources.ts:3`, `:26`) 그 범위를 그대로 보존한다. 증축 대상의 3 초과·8 미만 제한은 §4.2 명령 검사에만 둔다 |
| 읽기 | `changes`에 키가 없는 국가는 0으로 읽고 쓸 때 `(changes[국가] ?? 0) + 1`로 시작한다. 빈 객체에 바로 `+= 1`하면 `NaN`이 되어 조각 JSON 검사(`ext/state.ts:30-33`)에서 실패한다. `origin`은 `create`가 모든 도시를 채운다. `validate`는 월드 문맥이 없어 키 집합을 보지 못하므로 키가 빠진 상태는 감축 검사가 거부한다([T4-74 §3.2](./T4-74.md#32-검사-순서)) |
| `clone` | 깊은 복사 |

`origin`은 월드를 만들 때의 규모다. 도시 규모는 지도에서 그대로 오므로(`world/bootstrap.ts:170`) 원작이 읽는 지도 원래 규모와 같다. 감축(T4-74)이 이 값보다 큰 수도만 줄인다. [누락 명령 문서 T4-74](./mvp-command-gaps.md#t4-74-nation_shrink-감축)의 연결 항목(원래 규모를 확장 상태에 남길지 지도 자료를 문맥으로 넘길지)을 이 조각으로 푼다. 명령 문맥 `Actor`(`commands/types.ts:7-12`)를 넓히지 않아도 되고 재생도 상태만으로 같아진다.

`changes`는 원작 `capset`이다. 증축과 감축 모두 1씩 올린다. 원작에서는 준비 턴 연속 판정의 번호로 쓰인다. T4-07이 같은 뜻의 번호를 쓰지 않기로 하면 이 칸을 뺀다(쟁점 R2).

증축과 감축이 같은 조각을 쓰므로 두 명령의 `extCommandBindings` 행 모두 `sliceKeys: ['capital_scale']`다(T4-02 2.4.2). 한쪽만 켠 월드에서도 조각이 생긴다.

### 4. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 4.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `nation_expand` | 증축 | `nation` | `nation` | `noArgs` |

도시 규모와 최대값을 바꾸므로 `Effect`에 맞는 필드가 없다(`commands/effects.ts:7-11`). `defineCommand`로 `{ kind: 'world' }` 효과를 낸다.

#### 4.2 검사 순서

#### 4.3 실행

`change(state, actor)`가 아래를 바꾼다. RNG는 쓰지 않는다.

1. 수도 `level += 1`, `populationMax += POP_STEP`, `agricultureMax`·`commerceMax`·`securityMax += DEVEL_STEP`, `defenceMax`·`wallMax += WALL_STEP`. 현재 값은 바꾸지 않는다.
2. 국가 `gold -= 비용`, `rice -= 비용`.
3. `capital_scale.changes[국가] = (changes[국가] ?? 0) + 1`.
4. C5 (가)면 행위자 `experience += 30`, `dedication += 30`.

월간 정산의 인구 증가(`monthly/index.ts:68`)가 새 최대를 향해 채운다. 별도 처리는 없다.

#### 4.4 준비 턴

U-01 결정(D-027)대로 같은 명령을 연속 칸에 예약해야 실행한다. `PREPARE_TURNS`를 T4-07이 정하는 모양으로 선언한다. 연속 판정, 중단, 재생 복원, 직책별 국가 예턴 칸(T2-05)에서 세는 방법은 T4-07 계약이다. 원작은 `capset`을 연속 판정 번호로 쓴다. 증축이 끝나 번호가 바뀌면 같은 명령을 다시 예약해도 처음부터 센다는 뜻이다. T4-07이 이 뜻을 받는지가 쟁점 R2다.
