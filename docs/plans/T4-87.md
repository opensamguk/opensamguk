## 계획 (Claude)

### 목표

운영자가 관리자 콘솔에서 시나리오, 병종, 기본 능력치 규칙, 초상 대응표의 판을 복제해 표로 고치고 초안으로 저장한 뒤 검증을 통과한 판만 게시한다. 시나리오는 국가, 장수, 도시 소유, 시작 연도, 외교, 함께 쓸 지도 판을 고친다. 게시한 판으로 새 월드를 만들 수 있고 진행 중인 월드는 그대로다.

AC-P2-27의 지도 밖 몫이다. 판 목록·초안 저장·늦은 저장·게시·초안 버리기 흐름은 [T4-81](./T4-81.md) 공통부를 그대로 쓰고 이 작업은 종류별 편집 부품만 만든다. 서버 권한·감사·판 불변은 T4-78, 판을 골라 월드를 만드는 서버 몫은 T4-79, 관리자 월드 생성 양식의 판 고르기는 T4-90이다(조율 결정 R16). 이 작업이 끝나도 T4-81·T4-78·T4-79가 모두 끝나기 전에는 AC-P2-27을 완료로 세지 않는다.

계약의 정본은 T4-78 상세 계획 2.4~2.8절과 T4-76 상세 계획 3.2~3.4절이다. 아래 절이 두 계획과 다르면 두 계획을 따른다.

### 착수 조건

기준 main `3e5b52a`에는 T4-76, T4-78, T3-05, T3-06이 없다. 근거는 [T4-81 착수 조건](./T4-81.md#착수-조건)과 같다. T3-05·T3-06의 이름은 가정이다(조율 결정 R19). 여기에 더해 T4-81이 만든 `apps/web/src/admin/resources/` 공통부가 main에 있어야 한다. 지금 `packages/rules/src/world/`에는 `bootstrap.ts`·`preset.ts`·`resources.ts`만 있고 검증기가 없다.

새 판으로 월드를 만드는 E2E 줄은 T4-79 PR 2(`admin.world.create`가 판 키 다섯을 받음)가 들어와야 돈다. 그 전에는 편집·게시 E2E만 먼저 통과시키고 월드 만들기 줄은 T4-79 병합 뒤 같은 시험에 더한다. 그 사이 AC-P2-27 증거 칸은 채우지 않는다.

### 하지 않는 것

- 서버 API, 권한, 감사, revision 비교, 게시 판 불변 (T4-78)
- 지도 편집 (T4-80·T4-81·T4-88). 시나리오 화면은 지도를 읽기만 한다
- 월드 생성에서 판을 고르는 서버 몫 (T4-79)과 관리자 월드 생성 양식의 판 고르기 칸 (T4-90, 조율 결정 R16)
- 내용의 `id` 고치기. 복제 때 서버가 새 이름으로 바꾼다(조율 결정 R7). 화면은 보이기만 한다
- 스키마 밖 칸의 편집. 지금 내장 JSON에 있지만 `packages/rules/src/world/resources.ts`의 스키마가 읽지 않는 칸(시나리오의 `extends`·`life`·`fiction`·`const`·`general_ex`·`cities`·`history`, 병종의 `requirements`·`info`·`*SkillTrigger`·`iActionList`, 능력치의 `npcTotal`·`npcMax`·`npcMin`·`chiefMin`·`iconPath`, 초상 대응표의 생성기 기록 칸)는 받은 그대로 둔다. 화면에 이 판에서 고치지 않는 칸 목록으로 이름만 적는다
- 행 순서 바꾸기. 국가 번호와 장수 번호가 행 순서라서(아래 시나리오 절) 끌어서 옮기기를 두지 않는다
- 초상 이미지 올리기. 대응표의 ID만 고친다 (이미지 자산 §2)
- 여러 판 비교 화면, 초안 자동 저장, 375px 대응 (T4-81과 같다)

### main 기준 사실 (`3e5b52a`)

- 스키마는 `packages/rules/src/world/resources.ts`에 있다. 초상 대응표 `:6-8`(이름 → 정수 10001~11000), 시나리오 `:38-74`, 병종 `:77-100`, 능력치 규칙 `:102-109`다. zod 기본값이라 모르는 키는 읽을 때 버린다.
- 카탈로그 내용은 내장 JSON을 `JSON.parse`한 값 전체이고 `$comment`와 로더가 쓰지 않는 칸도 남는다(T4-77 상세 계획). `jsonb`라서 읽으면 키 순서가 원래 파일과 다를 수 있다. 저장은 받은 내용 그대로다(T4-76 I-4, T4-78 2.4).
- 시나리오의 국가·장수·외교는 객체가 아니라 튜플이다. 국가는 `[이름, 색, 금, 쌀, 설명, 기술, 성향, 작위 0~7, 소유 도시 이름 목록]`(`resources.ts:42-54`, 읽는 곳 `packages/rules/src/world/bootstrap.ts:141-165`)이다. 장수는 `[친화, 이름, 옛 초상 경로, 국가 번호, 위치 도시 이름 또는 null, 통솔, 무력, 지력, 관직 0~12, 생년, 몰년, 성격, 특기, 선택 칸]`(`resources.ts:55-72`, `bootstrap.ts:195-247`)이다. 외교는 `[국가 A, 국가 B, 0 전쟁·1 선전포고·7 불가침, 남은 개월]`(`resources.ts:73`, `bootstrap.ts:249-260`)이다.
- 국가 ID는 국가 행의 순서 + 1이다(`bootstrap.ts:143`). 장수의 국가 번호와 외교의 국가 번호가 이 순서를 가리킨다. 0은 재야다(`bootstrap.ts:211`). 국가 행 하나를 지우면 뒤 국가의 번호가 모두 당겨진다.
- 국가 소유 도시 목록은 하나 이상이어야 한다(`resources.ts:52`의 `min(1)`). 수도는 그 목록의 첫 도시다(`bootstrap.ts:162`). 한 도시를 두 국가가 가지면 실패한다(`bootstrap.ts:147`).
- 장수 위치가 null이면 생성 때 시드 난수로 소속 국가 도시 가운데 하나를 고른다(`bootstrap.ts:216`). 화면에는 무작위 배치로 적는다.
- 초상은 장수 이름으로 대응표를 찾는다(`bootstrap.ts:222`). 시나리오는 대응표 판을 기록하지 않는다.
- 내장 시나리오 `1030`은 국가 21개, 장수 491명, 외교 8건이다. 초상 대응표는 이름 429개, 병종은 4개다(`resources/` 기준, T4-77이 SQL로 옮김).
- 시나리오 스키마에는 시작 월과 종료 조건이 없다. `startYear` 하나다(`resources.ts:41`). 설계 C-M3a는 시작 연월과 종료 조건 검사를 적었다(Q-87-2).
- 초상 주소는 화면이 ID로 만든다(`apps/web/src/portrait/portraitUrl.ts:1`, 범위 `:6-7`).

### 접근

1. 종류마다 `read(content)`와 `write(view, content)`를 둔다. `read`는 받은 내용에서 편집할 칸을 이름 붙은 값으로 꺼낸다. `write`는 받은 내용을 복사해 그 칸만 바꾼다. 받은 키 순서와 모르는 키, 튜플의 선택 칸을 그대로 둔다. 단위 시험의 첫 줄은 내장 판을 `read` → `write`해 받은 내용과 글자열이 같다는 것이다.
2. 편집 동작을 순수 함수로 만든다. 국가 추가·삭제(번호 당기기 포함), 도시 소유 바꾸기, 수도 바꾸기, 장수 추가·삭제·수정, 외교 추가·삭제, 병종·병과 추가·삭제·수정, 대응 추가·삭제·이름 바꾸기. 동작 하나가 되돌리기 기록 하나다.
3. `history.ts`, `RowTable`, `issueTarget.ts`를 만든다. 표는 찾기 결과를 50행씩 보이고 행을 누르거나 위아래 화살표로 고른다. 고른 행의 양식이 표 오른쪽에 붙는다.
4. 종류별 화면을 T4-81 공통부의 위쪽 띠 아래에 둔다. 검증은 매 편집 뒤 T4-76 검증기를 돌리고 항목을 누르면 그 탭·쪽·행으로 간다.
5. E2E를 쓴다.

### 공통 규칙

- 위쪽 띠, 주소 풀기, 초안 저장, 늦은 저장 안내, 게시 확인(사유 칸 포함), 초안 버리기, 권한 없음, 탭 초안, 이동 막기는 [T4-81](./T4-81.md#초안-저장) 그대로다. 늦은 저장 뒤 내 편집을 살리는 길도 같다. 각 화면에 [JSON 불러오기]를 두고 불러온 내용은 편집 한 번으로 쌓는다.
- 저장하지 않은 편집 수는 저장 기준 내용과 지금 내용을 키를 정렬한 JSON으로 비교해 다를 때의 기록 수다. 같으면 0이다.
- 칸 입력은 Enter나 초점을 옮길 때 내용에 들어간다. 정수 칸에 정수가 아닌 값을 넣으면 칸 아래에 이유를 보이고 내용에는 넣지 않는다(`aria-describedby`). 범위(예: 통솔 0~100)는 막지 않고 넣은 뒤 검증 목록에 보인다. 범위의 기준은 검증기 하나여야 하기 때문이다. 범위 밖 값은 형식 오류(`shape-invalid`)라서 고칠 때까지 다른 검사가 돌지 않는다(아래 검증 목록과 이동).
- 게시한 판은 모든 칸이 꺼진 읽기 전용이다. 표 찾기와 쪽 넘기기는 쓴다.
- 행 삭제는 확인 없이 하고 되돌리기로 살린다. 지울 수 없는 행은 [삭제]가 점선이고 누르면 이유를 보인다.
- 되돌리기·다시 하기는 버튼과 Ctrl+Z·Ctrl+Shift+Z다. 입력 칸에 초점이 있으면 브라우저 기본 동작을 쓴다(T4-80과 같다).

### 시나리오

```text
┌ 기본 · 국가 21 · 도시 소유 · 장수 491 · 외교 8 (탭, 탭 이름에 오류 수) ──────────────────────┐
│ 국가 표                                    │ 고른 국가: 조조                              │
│ 번호 이름 색 금 쌀 기술 성향 작위 수도 도시수│ 이름 [조조] 색 [#000080] 금 [100000] ...      │
│  1  조조 ■  100000 ...          진류  2   │ 수도 [진류 ▾]  [국가 삭제(점선: 장수 12명)]    │
└────────────────────────────────────────────┴──────────────────────────────────────────────┘
```

| 탭 | 칸 | 규칙 |
| -- | -- | ---- |
| 기본 | 내용 `id`(읽기), 제목, 시작 연도, 함께 쓸 지도 판 | 지도 판은 `resourceAdmin.list({ kind: 'MAP', status: 'PUBLISHED' })`에서 고르고 `save`의 `mapKey`로 보낸다(조율 결정 R3). 바꾸면 도시 소유와 장수 위치를 새 지도로 다시 검증한다 |
| 국가 | 번호(읽기), 이름, 색, 금, 쌀, 설명, 기술, 성향, 작위, 수도, 도시 수(읽기) | [국가 추가]는 대화 상자에서 첫 도시 하나를 고르게 한다. 고른 도시가 다른 국가 것이면 그 국가 목록에서 옮긴다. 그래서 도시 없는 국가(형식 오류)가 생기지 않는다. 소속 장수나 외교가 있으면 [국가 삭제]가 점선이고 이유에 장수 수와 외교 수를 적는다. 지우면 뒤 국가를 가리키는 장수·외교 번호를 하나씩 당긴다 |
| 도시 소유 | 도시 이름, 지역, 소유 국가, 수도 표시 | 행은 고른 지도 판의 도시다. 소유 국가를 바꾸면 옛 국가 목록에서 빼고 새 국가 목록 끝에 넣는다. 옛 국가의 수도였으면 목록의 다음 도시가 수도가 된다는 안내를 한 줄 보인다. 옛 국가의 마지막 도시면 바꾸기 전에 그 국가에 도시가 없어진다는 확인을 거친다. 지도에 없는 도시 이름을 가진 국가가 있으면 표 위에 그 이름과 국가를 적는다 |
| 장수 | 번호(읽기), 이름, 소속 국가, 위치 도시, 통솔, 무력, 지력, 관직, 생년, 몰년, 성격, 특기, 친화 | 찾기는 이름·소속 국가·위치 도시로 한다. 위치 도시는 고른 지도의 도시와 무작위 배치 가운데 고른다. 옛 초상 경로와 선택 칸은 양식 아래 읽기 전용으로 둔다. [장수 추가]의 기본값은 아래 |
| 외교 | 국가 A, 국가 B, 관계, 남은 개월 | 관계는 전쟁(0)·선전포고(1)·불가침(7) 셋이다. 같은 국가 쌍이 두 번 있으면 `scenario-diplomacy-duplicate` 경고이고 게시는 막지 않는다(조율 결정 R11). 내장 `1030`에도 이 경고가 하나 있다 |

- 장수 추가 기본값: 친화 0, 이름 `새 장수 <번호>`, 옛 초상 경로 빈 글자, 재야, 무작위 배치, 통솔·무력·지력 50, 관직 0, 생년 시작 연도 − 20, 몰년 시작 연도 + 40, 성격·특기 null. 장수 행은 13칸으로 만들고 선택 칸은 넣지 않는다.
- 국가 삭제 때 번호를 당기는 것은 국가 ID가 행 순서이기 때문이다(`bootstrap.ts:143`). 당긴 결과는 단위 시험으로 본다. 이 방식은 사용자 결정 U-87-2다.
- 장수를 지우면 뒤 장수의 번호가 당겨진다. 시나리오 안에서 장수 번호를 가리키는 스키마 칸은 없다. 스키마 밖 `general_ex`가 번호를 쓰는지는 이 화면이 따라가지 않는다.
- 색은 색 고르기와 `#RRGGBB` 글자 칸을 함께 둔다. 국가 이름표는 `NationBadge`를 쓴다.
- 검증은 T4-76 `validateScenario(content, { map, mapKey })`에 고른 지도 판 내용을 넣는다. 지도 판 내용은 `resourceAdmin.get({ id })`로 받는다. 시작 월과 종료 조건 칸은 T4-76이 스키마에 더하면 기본 탭에 넣는다(Q-87-2).

### 병종

| 표 | 칸 | 규칙 |
| -- | -- | ---- |
| 기본 | 내용 `id`(읽기), 이름, 기본 병종 | 기본 병종은 병종 표의 행 가운데 고른다 |
| 병과 | 번호, 이름 | 번호는 1 이상 정수 글자다(`unitset-arm-key-invalid`). 그 병과를 쓰는 병종이 있으면 [병과 삭제]가 점선이다 |
| 병종 | ID, 병과, 이름, 공격, 방어, 기동, 회피, 계략 계수, 비용, 군량, 공격 상성, 방어 상성 | 상성은 고른 행 양식에서 병과마다 칸 하나다. 빈 칸은 그 병과의 계수가 없다는 뜻이다. 모든 칸이 비면 받은 내용이 `[]`였던 경우 `[]`로 되돌린다(`resources.ts:76`). 기본 병종인 행은 [병종 삭제]가 점선이다 |

- 병종 추가는 고른 행을 복사해 ID를 가장 큰 ID + 100으로 둔다. 내장 판의 ID가 100 간격이라서다(`resources/unitset/basic.json` 1000·1100·…). 겹치면 `unitset-crew-id-duplicate` 오류다.
- 검증은 T4-76 `validateUnitSet`이다. C-M3a의 시나리오가 쓰는 병종 항목은 지금 시나리오 형식에 병종 참조가 없어 `unitset-default-missing`이 그 몫 전부다(T4-76 3.4).

### 능력치 규칙

- 양식 하나다. 합계, 최소, 최대 세 칸이다. 세 칸이 서로 맞지 않으면(`resources.ts:105-108`) `stat-rules-inconsistent` 오류이고 대상은 전체(`root`)다(조율 결정 R11). 목록 항목을 누르면 세 칸 묶음에 초점을 둔다.
- 양식 아래에 지금 값으로 만들 수 있는 능력치 범위를 한 줄로 적는다. 예: 합계 165, 각 능력치 15~80. 계산은 하지 않고 넣은 값을 옮겨 적는다.
- 스키마 밖 키는 이 판에서 고치지 않는 칸 목록에 이름만 적는다.

### 초상 대응표

- 표의 행은 장수 이름 하나다. 칸은 이름, 초상 ID, 미리 보기(작은 그림, `thumb` 48×68)다. 찾기는 이름과 ID로 한다.
- ID가 10001~11000 밖이면 미리 보기 자리에 기본 이미지를 둔다(`portraitUrl.ts:26-28`과 같은 범위). 검증에서는 형식 오류(`shape-invalid`, 대상 `path` `['portraits', 이름]`)라서 고칠 때까지 다른 검사가 돌지 않는다.
- 두 이름이 같은 ID를 쓰면 `portrait-id-duplicate` 경고다. 게시는 막지 않는다.
- 이름 바꾸기는 키 바꾸기다. 같은 이름이 이미 있으면 칸 아래에 이유를 보이고 넣지 않는다. JSON 객체는 키가 겹칠 수 없기 때문이다.
- 대응 추가는 빈 이름을 받지 않는다. 표 끝에 붙고 쓰기는 받은 내용의 키 순서 뒤에 넣는다.
- 미리 보기 그림은 이미지 서버 주소(`imageBaseUrl`)에서 받는다. 한 쪽 50행만 불러오고 `loading="lazy"`를 쓴다.

### 검증 목록과 이동

- 항목은 T4-76의 `{ code, severity, message, target, params, resource? }` 그대로이고 게시 가능 판정은 보고서의 `ok`(심각도 `error`만 센다)다(조율 결정 R11). 목록은 오류와 경고를 글자로 나누고 경고는 게시를 막지 않는다. 탭 이름 뒤에는 그 탭의 오류 수를 붙인다. 색만으로 가르지 않는다.
- 형식 검사가 먼저 돌고 형식 오류(`shape-invalid`)가 하나라도 있으면 그 항목만 오고 뜻 검사 항목은 오지 않는다(T4-76 3.2). 화면은 형식 오류가 있는 동안 목록 머리에 형식 오류를 고치면 나머지 검사가 다시 돈다는 문장을 한 줄 둔다. 그래서 형식 오류 하나를 고치면 그동안 보이지 않던 다른 오류가 새로 나타날 수 있다. 이 동작은 단위 시험과 E2E로 본다.
- `issueTarget.ts`가 `target`을 탭과 행으로 바꾼다.

| 종류 | `target` | 가는 곳 |
| ---- | -------- | ------- |
| 시나리오 | `nation`·`general`·`diplomacy`의 `index` | 그 탭의 그 행 |
| 시나리오 | `path` `['nation', i, …]`·`['general', i, …]`·`['diplomacy', i, …]` | 같은 탭의 `i`번 행. 경로에 칸 번호가 있으면 양식의 그 칸에 초점 |
| 시나리오 | `path` 그 밖(`['title']`, `['startYear']` 등), `root` | 기본 탭 |
| 병종 | `crewType`의 `index`, `path` `['crewTypes', i, …]` | 병종 표 `i`번 행, 칸이 있으면 그 칸 |
| 병종 | `armType`의 `key`, `path` `['armTypes', 키]` | 병과 표 그 행 |
| 병종 | `path` 그 밖, `root` | 기본 표 |
| 능력치 규칙 | `path` `['stat', 칸]` | 그 칸 |
| 능력치 규칙 | `root` | 세 칸 묶음 |
| 초상 대응표 | `portrait`의 `name`, `path` `['portraits', 이름]` | 그 이름의 행 |

- 행으로 갈 때는 찾기를 비우고 행이 있는 쪽을 연 뒤 그 행을 고른다. 행이 없으면(지운 행을 가리키는 오래된 결과) 탭만 연다.
- `resource`가 달린 항목은 다른 자원의 항목이라 이동하지 않고 그 자원의 키를 함께 적는다.
- 게시 때 서버 검증 결과가 오면 목록 머리에 서버 검증 결과라고 적고 그 목록을 쓴다(T4-81 게시 절).

### 상대 영역에 필요한 것

[T4-81 상대 영역](./T4-81.md#t4-78-codex-초안게시-api)대로 T4-78 상세 계획 2.4~2.8이 정본이다(조율 결정 R14). 이 작업이 더 쓰는 것은 시나리오 `save`의 `mapKey`(조율 결정 R3)와 `list({ kind: 'MAP', status: 'PUBLISHED' })`뿐이다. 시나리오 `1030` 내용은 약 136 kB라 T4-78의 900,000바이트 한도 안이다.

- 패키지 경계 예외를 `apps/web/src/admin/resources/**`에도 열어 달라([T4-81](./T4-81.md#t4-76-codex-형식검증기)과 같은 요구).

#### T4-79 (Codex) 월드 생성에서 판 고르기

- E2E가 `admin.world.create`에 다섯 판 키(`scenarioKey`·`mapKey`·`unitSetKey`·`statRulesKey`·`portraitMapKey`)를 넣어 부른다(T4-79 PR 2 모양).

#### T4-90 (Claude) 관리자 월드 생성 양식의 판 고르기
