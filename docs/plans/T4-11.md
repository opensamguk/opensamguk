## 계획 (Claude)

### 목표

AC-P2-07의 규칙 몫이다. 명세 문장은 이렇다. 첩보하면 대상 도시의 그 시점 정보가 자기 국가에만 보이는 기록으로 남고 기록 시각이 함께 보인다. 다른 국가와 무인증의 조회는 거부된다.

이 작업이 끝나면 아래가 순수 규칙으로 성립한다.

- `spy` 명령이 대상 도시의 그 tick 값을 거리에 따라 세 단계로 찍어 실행 장수의 국가 몫 기록으로 남긴다.
- 기록은 확장 상태 조각 `intel`에 국가·도시마다 하나씩 들어가고 같은 도시를 다시 첩보하면 새 기록으로 바뀐다.
- 같은 상태와 시드면 결과가 같고 `view`를 바꾸지 않는다.

조회와 공개 범위(자기 국가에만 보임, 거부)는 T4-12, 안개 표시는 T4-38이다.

### 1.3 열람

원작 첩보의 기록은 국가 `meta.spy`의 남은 달 수다. 달이 바뀌기 전에 1씩 줄고 1 이하가 되면 지운다(`nationTurnMonthlyHandler.ts:44~60, 80`). 그래서 실행한 달과 그 뒤 두 달 동안 열린다. 그 사이 지도는 대상 도시를 첩보 목록에 넣고(`worldMap.ts:131~139, 301`) 도시 정보는 국가 등급이 1 이상이면 대상 도시를 지금 값으로 보여 준다(`router/world/index.ts:153~162`).

### 1.4 우리와 다른 점

원작은 첩보 중인 석 달 동안 대상 도시의 지금 값을 보인다. 우리 차별화 D13(`docs/product/differentiation.md:172~175`)과 AC-P2-07·AC-P2-18은 그 시점 값을 기록으로 남기고 다시 첩보하기 전까지 갱신하지 않는다. 이 문서는 D13을 따른다. 기록을 몇 달까지 보일지는 U-11이고 T4-38이 정한다. 그래서 원작의 남은 달 수 3과 월간 감소는 옮기지 않는다.

```ts
  owner: { id: number; name: string; color: string } | null; // 기록 당시 도시 소유국의 공개 표시값, null은 공백지

  populationMax: number;
  trust: number;
  generals: number;
  crew: number;
  domestic?: {
    agriculture: number; agricultureMax: number;
    commerce: number; commerceMax: number;
    security: number; securityMax: number;
    defence: number; defenceMax: number;
    wall: number; wallMax: number;
  }; // level <= 2
  crewTypes?: { crewType: number; generals: number }[]; // level 1, crewType 오름차순
  tech?: IntelTech; // level 1이고 대상 도시가 국가 소유일 때만
}
// 조각 값: 국가 ID 문자열 → 도시 key 문자열 → 기록
export type IntelSliceValue = Record<string, Record<string, IntelRecord>>;
```

- 최대값은 원작 로그에 없다. 기록 시점의 최대값을 같이 둔 것은 우리 쪽 선택이다. 증축(T4-73)처럼 최대값을 바꾸는 명령이 생겨도 기록과 맞는 막대를 그리게 하기 위해서다. 최대값은 지도 자원에서 온 값이라 숨길 상태가 아니라고 보았으며 G-03 검토 대상이다.
- 소유국은 ID와 함께 그때의 이름·색을 둔다. 셋 다 지금도 공개 값(`visibility.ts:93~94`)이고 그 뒤 멸망하거나 국호를 바꿔도 기록 당시 이름으로 보이게 하기 위해서다.
- 선택 칸은 그 단계가 아니면 키 자체가 없다(`undefined` 칸을 두지 않는다, T4-02 X14). 병종 이름은 기록하지 않는다. 이름은 월드 `unitSet`(`apps/server/src/routers/turns.ts:115`가 이미 읽는 열)에서 T4-12가 붙인다.
- `trust`는 저장 값 그대로다(실수일 수 있다). 소수 자리 표시는 화면 몫이다.
- 기록에 실행 장수를 넣지 않는다. AC가 요구하지 않고 국가를 떠난 장수의 이름을 조회할 이유를 만들지 않는다.

### 4.3 조각 `intelSlice`

| 항목 | 값 |
| ---- | -- |
| `key` | `intel` |
| `create(context)` | `{}`. `context`를 읽지 않는다 |
| `clone(value)` | 깊은 복제 |
| `validate(value)` | `IntelSliceValue` 스키마. 국가 키와 도시 키는 `^[1-9][0-9]{0,9}$`. 기록마다 정수 칸은 0 이상 safe integer(`trust`만 0~100 유한 실수), `level`과 선택 칸의 짝(§4.2 주석)이 맞는지 본다. 남는 칸은 거부한다(strict) |
| 바인딩 `spyBinding` | `{ commandKey: 'spy', target: 'general', sliceKeys: ['intel'] }` |

`record.ts`는 zod와 타입만 import한다. 조각은 `spy`를 켠 월드에만 생기고 끈 월드에는 `ext` 키가 없다(C3, T4-02 X9). 월간 정산에서 조각이 하는 일은 없다. 기록의 나이는 tick으로 계산하므로 달마다 고칠 값이 없다.

### 4.4 검사 순서와 실패

| 순서 | 조건 | code | 장수 로그에 남는 이유 |
| ---- | ---- | ---- | --------------------- |
| 1 | 장수 없음 | `NO_ACTOR` | 장수가 없습니다. |
| 2 | 재야이거나 국가 없음 (I4 (가)) | `NOT_NATION` | 국가에 소속되어야 합니다. |
| 3 | 대상 도시 없음 | `BAD_TARGET` | 없는 도시입니다. |
| 4 | 대상이 자기 국가 도시 | `BAD_TARGET` | 자기 국가 도시는 첩보할 수 없습니다. |
| 5 | 금 < 비용 | `NO_GOLD` | 금이 부족합니다. |
| 6 | 쌀 < 비용 | `NO_RICE` | 쌀이 부족합니다. |

### 4.5 계산

- 비용 `INTEL.COST_GOLD`, `INTEL.COST_RICE`. 값은 I1 결정이다. 결정 전 시험은 상수 이름으로만 쓴다.
- 거리 `intelDistance(view, from, to)`: `from === to`면 0. 아니면 `connections` 너비 우선으로 2칸까지 찾고 못 찾으면 3. 없는 도시 key는 건너뛴다. `stratagem/base.ts:44~60`의 5칸 함수와 같은 꼴이지만 기능 폴더끼리 import하지 않으려고 따로 둔다.
- 단계 `intelLevel(d)`: `d <= 1`이면 1, `d === 2`면 2, 그 밖은 3.
- 현재 연도 `toGameDate(view.startYear, actor.tick ?? 0).year`.
- 대상 장수: `cityKey === 대상`이고 `nationId === 대상 도시 nationId`(둘 다 `null`이면 같다)이며 `activeFromYear <= 현재 연도`인 장수. 마지막 조건은 T4-05 §4.4의 수비 장수 기준(main `attack.ts:70`)과 맞춘 기술 선택이다. 원작에는 없으며 G-03 검토 대상이다.
- `owner`는 대상 도시 `nationId`가 있으면 그 국가의 `{ id, name, color }`, 없으면 `null`이다.
- `generals`는 대상 장수 수, `crew`는 그 `crew` 합이다.
- `crewTypes`는 대상 장수를 `crewType`별로 센 목록이다. 장수가 없으면 빈 배열이다.
- `tech`는 대상 도시가 국가 소유이고 단계 1일 때만. `diff = 대상 국가 tech − 내 국가 tech`이고 `diff >= 1000` 압도, `>= 250` 우위, `>= −250` 대등, `>= −1000` 열위, 그 밖은 미미다(I3 (가)). 둘 다 `Math.floor`한 값을 뺀다.
- 기록은 `ext.intel[String(내 국가)][String(대상 도시)]`에 넣는다. 옛 기록은 단계와 상관없이 새 기록으로 바뀐다(K6).

### 4.6 실행과 효과

`makeSpyCommand(clone: (view: WorldView) => WorldState = cloneWorld)`가 `CommandDef`를 낸다. 운영 정의는 `export const spy = makeSpyCommand()`다.

- `execute`는 `check`를 다시 부르고 실패면 예외다(`defineCommand`, `support.ts:50~56`과 같은 규칙).
- `const state = clone(view)`. `state.ext?.intel`이 없으면 예외다. 바인딩이 조각을 보장하므로 정상 경로에서는 일어나지 않는다.
- `state`에서 장수 금·쌀을 비용만큼 빼고(검사를 지났으므로 0 미만이 되지 않는다) 경험·공헌을 더한 뒤 기록을 넣는다.
- 효과는 `[{ kind: 'world', state }]` 하나다. 조각을 바꾸는 효과 종류가 `effects.ts:6~11`에 없으므로 새 `Effect`를 만들지 않고 기존 `world` 효과를 쓴다. 기본 명령 다수가 같은 효과를 낸다(`defineCommand`).
- 복제 함수를 주입받는 이유: 운영 `cloneWorld`는 운영 `extSlices`(T4-17 전에는 빈 배열)로 `ext`를 검사하므로 `intel` 조각이 든 상태를 모르는 key로 거부한다(`ext/state.ts:115~118`). 단위 시험은 `(v) => cloneWorldWithRegistry(v, { slices: [intelSlice], bindings: [spyBinding] })`(`model/clone.ts:10`)를 넘긴다. 엔진·서버 경로는 주입하지 않는다(T4-03 E1).

### 4.7 RNG 소비 순서

검사를 통과한 실행 한 번이 정확히 두 번 소비한다. `rng.int(1, 100)` 경험, 그다음 `rng.int(1, 70)` 공헌. 원작 `nextInt(1, 101)`, `nextInt(1, 71)`과 같은 범위이고 같은 순서다. 기록 만들기는 난수를 쓰지 않는다. `Math.random()`과 현재 시각은 쓰지 않는다.

### 4.8 로그·보고·국가 기록

문구는 원작을 옮기지 않고 새로 썼다. 조사 처리가 필요 없게 도시 이름 뒤에 쌍점을 둔다.

| 단계 | `logs` (장수) | `history` (대상 국가, I2 (가)) |
| ---- | ------------- | ------------------------------ |
| 1 | `첩보: {도시} 정보를 많이 얻었습니다` | `{도시}: 누군가 이 도시를 살폈습니다` |
| 2 | `첩보: {도시} 정보를 어느 정도 얻었습니다` | 같음 |
| 3 | `첩보: {도시} 소문만 들었습니다` | 같음 |

- 수치는 장수 로그에 쓰지 않는다. 장수 로그는 그 장수가 국가를 떠나도 남으므로 국가 몫 기록과 공개 범위가 다르다. 수치는 T4-12 조회로만 본다.
- 공백지 대상은 `history`를 내지 않는다. I2가 (나)로 정해지면 `history` 칸을 내지 않는다.
- `reports`는 없다.

### 4.9 등록과 연결의 분리

T4-11은 정의, 조각, 바인딩과 단위 시험까지다. 운영 목록 세 곳(`extensionCommands`, `extSlices`, `extCommandBindings`)에 넣는 일은 T4-17이다. 그 전까지 `spy`는 운영 resolver에서 `UNKNOWN_COMMAND`이고 끈 월드와 기본 37개 동작은 그대로다. 시험은 `createCommandResolverWithCommands(enabled, intelCommands)`(`resolve.ts:27`)로 켬·끔을 함께 본다. T4-17은 실제 조각이 든 장수 턴 재생 보존 시험(T4-02 2.4.5)을 이 조각으로 할 수 있다.
