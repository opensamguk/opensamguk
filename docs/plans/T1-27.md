# T1-27 기수 종료 화면과 가속 표시

> 대기열: T1-27 · AC: AC-M1-21 (데모의 종료 화면 부분) · 구현: Claude · 리뷰: Codex
> 선행: T1-26 (병합된 `world.summary` 계약과 시험 도우미) · 후속: T1-18 (독립 에이전트 완주 데모)

## 계획 (Claude)

### 목표

판이 끝난 월드의 메인 화면에 끝난 이유, 승자(없으면 승자 없음), 종료 연월이 나온다. 새로고침하거나 다른 계정으로 열어도 같은 결과가 서버에서 다시 읽힌다.
가속 중인 월드는 위쪽 띠에 가속 중임이 보인다. 열어 둔 화면은 장수가 없어도, 정지 중에 모드가 바뀌었어도 포커스나 새로고침 없이 정해진 주기 안에 모드 전환과 종료를 따라온다.

### 범위

`apps/web`(메인 화면, 게임 레이아웃, 쿼리 갱신), `e2e/`, `docs/user/time-and-turns.md`.
API는 T1-26이 병합한 `AppRouter` 타입만 import한다. 서버·엔진 파일은 고치지 않는다.

| 위치 | 바꿀 내용 |
| ---- | --------- |
| 위쪽 띠 (`GameLayout`) | `ENDED`면 연월 칸에 `result`의 연월, 상태 칸에 종료. `RUNNING`이면서 `clockMode`가 `ACCELERATED`면 상태 칸에 가속 진행 중. 이때는 다음 턴 카운트다운을 쓰지 않는다 |
| 메인 결과 칸 (`MainPage`) | `result`가 있으면 메인 맨 위에 결과 칸을 둔다. 끝난 이유(천하통일 또는 종료 연도 도달), 승자 국가 이름과 국가 색 표식(없으면 승자 없음), 종료 연월, 남은 국가 수 |
| 메인 나머지 | 지도·장수·도시·국가·기록은 그대로 읽는다. 예턴 편집은 저장 버튼을 막고 끝난 판이라 바꿀 수 없다는 안내를 한 줄 둔다(서버도 거부한다) |
| 갱신 | 아래 갱신 규칙대로 `world.summary`를 `home.get`과 따로 주기 조회하고 모드·상태 전환을 감지한다 |
| 오류 | `result`가 없는 `ENDED`면 결과 칸 대신 종료만 표시한다. 조회 실패는 기존 오류 표시를 쓴다 |

#### 갱신 규칙

지금은 카운트다운 0초와 창 포커스 때만 다시 받는다. 장수가 없으면 `home.get`이 `NOT_FOUND`라 `nextTurnAt`이 없고 정지 중에는 카운트다운이 없다. 그래서 이미 받은 `clockMode`에만 기대면 화면을 연 채 가속·재개해도 알 수 없다. 다음 규칙으로 고친다.

- 월드 감시: `world.summary`의 `status`가 `RUNNING`이나 `PAUSED`이면 `home.get` 성공 여부와 상관없이 `world.summary`를 주기적으로 다시 받는다. 주기는 `RUNNING`이고 `ACCELERATED`면 5초, 그 밖(`REALTIME`이거나 `PAUSED`)은 15초다. 카운트다운 0초 갱신은 지금처럼 둔다.
- 전환 감지: 새로 받은 `status`나 `clockMode`가 바로 전 값과 다르면 `home.get`과 기록 쿼리를 한 번 무효화한다. 메인 결과 칸과 위쪽 띠는 같은 쿼리를 읽으므로 함께 바뀐다.
- 가속 중: `RUNNING`이고 `ACCELERATED`인 동안 기록 쿼리와 `home.get`도 5초마다 다시 받는다. 직전 `home.get`이 `NOT_FOUND`였으면 `home.get`은 주기 조회에서 뺀다(전환 감지 때는 한 번 받는다).
- 멈춤: `status`가 `ENDED`가 되면 결과를 그린 뒤 모든 주기 조회를 끈다. `PREOPEN`이거나 `world.summary` 오류가 `NOT_FOUND`·`UNAUTHORIZED`·`FORBIDDEN`이면 켜지 않는다. 일시 오류는 기존 재시도 뒤 다음 주기에 다시 묻는다.
- 숨은 탭: TanStack Query 기본대로 탭이 숨으면 주기 조회가 멈추고 다시 보이면 기존 포커스 갱신이 받는다.
- 요청량: 화면 하나당 `REALTIME`·`PAUSED`는 `world.summary` 분당 4회, 가속 중에는 `world.summary`·`home.get`·기록 각 분당 12회다. `world.summary`는 월드 행 하나와 결과 행 하나를 읽는다. 서버·엔진 파일은 고치지 않는다.

화면 문구는 [글쓰기 규칙](../writing-style.md)을 따른다. 이모지·장식 문구를 쓰지 않는다. 결과 칸도 기존 메인 칸과 같은 디자인 토큰을 쓴다.
국가 색만으로 승자를 구별하지 않게 이름을 항상 함께 쓴다.

### 하지 않는 것

종료 화면 전용 주소, 왕조 일람, 명예의 전당, 다음 기수 안내, 순위 화면 변경은 하지 않는다. 로비의 종료 월드 목록은 M2 T2-04다.
가속을 화면에서 켜는 버튼은 만들지 않는다. 가속은 운영 명령(`pnpm world:accelerate`)이다.

### 접근

1. T1-26 병합 뒤 최신 main에서 시작하고 `world.summary` 타입을 확인한다. 모양이 T1-26 계획과 다르면 구현을 멈추고 T1-26 계획·대기열을 맞춘다.
2. `GameLayout`의 상태·연월 표시와 갱신 규칙(월드 감시·전환 감지·가속 중·멈춤)을 넣는다. 갱신 주기 판단은 순수 함수로 두고 단위 시험으로 상태·모드·오류 조합을 본다.
3. `MainPage` 결과 칸과 예턴 편집 잠금을 넣는다. 단위 시험으로 통일·종료 연도·결과 없음 세 경우를 본다.
4. T1-26 시험 도우미로 실제 엔진 경로의 `ENDED` 월드 두 개와 끝나기 전 월드를 만들고 Chromium 시험을 쓴다.
5. 플레이어 가이드에 기수 종료 단락을 더한다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 표시 | 단위 시험: 통일(승자 이름·색), 종료 연도 도달(승자 없음), 결과 없는 종료, 가속 중 표시 |
| 실제 화면 | `pnpm e2e`(Chromium, 실제 서버·전용 DB): 실제 `TurnLoop`로 끝난 두 월드에서 결과 칸의 이유·승자·연월이 서버 값과 같다. 스크린샷을 증거로 남긴다 |
| 재조회 | 같은 시험에서 새로고침 뒤 같은 결과, 장수가 없는 다른 계정으로 열어도 같은 결과 |
| 입력 잠금 | 끝난 월드에서 예턴 저장 버튼이 막혀 있고 막힌 버튼을 우회한 요청도 서버가 거부한다 |
| 가속 갱신 | 가속 중 월드를 연 화면에서 5초 간격 갱신으로 연월이 바뀌고 그 월드가 끝나면 새로고침 없이도 결과 칸이 나타난다 |
| 모드 전환 감지 | Chromium, 장수가 있는 계정과 없는 계정 두 화면을 같은 월드에 연다. 시험은 포커스·`visibilitychange` 이벤트를 보내지 않고 새로고침하지 않는다(문서 탐색 횟수 1). (가) REALTIME `RUNNING` 월드에 `world:accelerate`: 두 화면 모두 20초 안에 가속 진행 중이 되고 연월이 바뀐다. 이어 엔진이 끝내면 두 화면 모두 결과 칸이 나온다. (나) `PAUSED` 월드에서 `world:accelerate` 뒤 `world:resume`: 두 화면 모두 20초 안에 가속 진행 중이 되고 엔진이 끝내면 결과 칸이 나온다. 두 경우 모두 종료 뒤 20초 동안 `world.summary`·`home.get`·기록 요청이 0건이다. 모드 명령은 T1-26의 운영 명령 코드 경로를 시험 프로세스에서 부르고 엔진은 그 월드를 지정한 `runEngine`으로 따로 돌린다(`pnpm dev`의 엔진은 첫 `RUNNING` 월드만 잡는다) |
| 기존 화면 | 기존 E2E 전부 통과 (skip 0), `pnpm check`, exact head 필수 CI |

자동 Chromium 시험은 T1-18 데모 녹화가 아니다. AC-M1-21의 녹화와 체크리스트는 T1-18에서 구현·증거 작성자와 분리된 독립 참가 에이전트가 실제 브라우저로 15분 이상 플레이하며 만든다.

### 상대 영역에 필요한 것

T1-26의 `world.summary` 새 필드(`clockMode`, `endYear`, `result`)와 시험 도우미(`ENDED` 월드 둘, 가속하면 곧 끝나는 REALTIME `RUNNING` 월드 하나).
