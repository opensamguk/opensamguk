## 계획 (Claude)

### 목표

che 지도(도시 94개, 700×500)에 해안·호수·강·산맥 지형 층 초안을 그린다. 도시, 연결, 도시 수치는 하나도 바꾸지 않는다. 지형 하나하나에 근거를 단다. 근거는 그 지형이 기대는 che 도시와 사료 구절이다. 초안을 che 도시와 합친 v2 지도는 검증을 통과한다. 그 지도에서 내보낸 5색 밑그림(2100×1500)이 [T4-83](./T4-83.md) 바탕 그림 생성의 유일한 입력이 된다.

AC-P2-28 전체가 아니다. 바탕 그림과 출처 기록은 T4-83, 화면에 깔기는 T4-84 몫이다. 이 작업이 끝나도 AC-P2-28을 완료로 세지 않는다.

### 하지 않는 것

- 도시 위치, 연결, 규모, 지역, 수치 바꾸기. 지형이 도시와 맞지 않으면 지형을 고친다.
- 지형을 이동·전투 규칙에 넣기 (map-editor.md C-M2, AGENTS §3).
- 판 게시와 카탈로그 등록 (T4-77·T4-78). 이 작업은 파일 초안까지다.
- 바탕 그림 생성 (T4-83), 화면에 깔기 (T4-84).
- che 말고 다른 지도의 지형.
- 외부 그림을 보고 배치 정하기. 아래 외부 그림 절을 따른다.

### 외부 그림 (D-028, map-editor.md §4)

와룡전 리메이크(`phixteam1/GRZ` v1.1)의 지도 그림은 이용 허락이 없고 원작 그림을 확대한 것으로 보인다. 사용자가 제작자에게 서면 허락을 요청 중이지만 답이 와도 이 작업의 규칙은 바뀌지 않는다. 바꾸려면 결정 기록부터 고친다.

- 해도 되는 것: 화풍, 색 구성, 어떤 종류의 지형을 표시할지 정할 때 보고 참고하기. 이 작업에서는 표시할 지형 종류(해안·호수·강·산맥 네 층)가 이미 C-M2로 정해져 있어 볼 일이 거의 없다.
- 하면 안 되는 것: 따라 그리기, 지형 배치(해안선 모양, 강 굽이, 산맥 위치) 옮기기, 이미지 생성 입력이나 참조 이미지로 넣기, 저장소·이미지 서버에 올리기, 이 저장소의 시험 고정물로 쓰기.
- 그리는 동안 GRZ 그림을 편집기 옆에 띄워 두지 않는다. 배치는 아래 근거 표만으로 정한다. 근거 표에 없는 굽이나 곶을 그려 넣지 않는다.
- core2026의 이미지 저장소 `devsam/image`도 라이선스 표시가 없다([이미지 자산](../image-assets.md) §4). 그 안의 지도 배경도 같은 규칙으로 본다.

### 형식

초안은 지도 하나의 지형 층만 담는다. 도시는 담지 않는다. che 도시 94개를 두 번 들고 있으면 T4-77이 JSON을 SQL로 옮길 때 같은 도시 자료가 두 벌이 되기 때문이다.

```json
{
  "$comment": "Terrain drawn for opensamguk on core2026 df6c926 map_che city coordinates (MIT, see resources/NOTICE.md). Sources: che.sources.json.",
  "version": 2,
  "mapKey": "che",
  "cityHash": "sha256:<도시 층 정규 해시>",
  "canvas": { "width": 700, "height": 500 },
  "terrain": { "coast": [], "lakes": [], "rivers": [], "mountains": [] }
}
```

- `terrain`은 C-M2 모양 그대로다. T4-80 `contract.ts`의 `Terrain` 타입과 같다. 닫힌 다각형은 점 4개 이상이고 마지막 점이 첫 점과 같다. 좌표는 정수로 둔다(편집기에서 찍은 점을 반올림).
- `cityHash`는 초안을 그릴 때 밑에 깔린 도시 층의 해시다. 도시 층은 T4-80 `serializeMap`이 내는 `cities` 배열이다(도시 `meta`는 빠진다). 합칠 때 해시가 다르면 거부한다. che 도시가 바뀐 판에 옛 지형을 얹는 사고를 막는다.
- `mapKey`와 `cityHash`는 C-M2에 없는 초안 전용 칸이다. 판에 들어갈 때는 `terrain`만 들어간다.
- 강 `name`은 한글 이름(`황하`, `장강`)으로 쓴다. 출처 표의 사료 표기는 원문 한자로 따로 둔다.

출처 표 `che.sources.json`:

```json
{
  "features": [
    {
      "layer": "rivers",
      "index": 0,
      "name": "황하",
      "anchors": [{ "cityId": 36, "relation": "near" }],
      "sources": [{ "book": "漢書", "volume": "卷006", "chapter": "武帝紀", "quote": "河水溢于平原", "grade": "正史" }],
      "confidence": "확인"
    }
  ],
  "sketch": { "width": 2100, "height": 1500, "rasterSha256": "…", "pngSha256": "…", "encoder": "Chromium <판> CompressionStream" }
}
```

- `relation`은 다섯 가지다. `coastal`(해안 다각형 경계에서 거리 12 이하), `island`(그 도시만 담는 해안 다각형이 있음), `near`(강·호수 경계에서 거리 15 이하), `between`(산맥 다각형이 두 도시 사이 선분과 겹침, `cityId` 둘), `pass`(산맥 다각형 안에 있어도 되는 관문 도시). 거리는 지도 좌표 단위다. 15는 연결된 che 도시 사이 가장 짧은 거리(약 27)의 절반 남짓으로 정한 출발값이고 그려 보고 구현 기록에 고친 값을 남긴다.
- `grade`는 `正史`와 `演義`를 나눈다. 둘을 섞어 한 근거로 세지 않는다.
- `confidence`는 `확인`(正史 구절이 있음), `약함`(演義나 시대 밖 사료만 있음), `없음`(색인에서 찾지 못함)이다. `없음`인 지형은 그리지 않는다. `약함`은 그리되 사용자 결정 목록에 올린다.
- 사료는 `historical-sources` 색인으로 찾고 권·편명·구절을 그대로 옮긴다. 구절은 15자 안으로 짧게 자른다. 색인에 水經注가 없으므로 강 물길의 세부 굽이는 사료로 정하지 않는다. 사료가 정하는 것은 어느 도시 곁을 어떤 순서로 지나는가뿐이다.

### 접근

1. 근거 표부터 채운다. 위 표의 지형마다 `historical-sources`로 正史를 먼저 찾고 演義는 따로 적는다. 찾지 못하면 `없음`으로 두고 그 지형은 그리지 않는다. 결과를 `che.sources.json`의 `features`에 넣는다. 이 단계에서는 점을 하나도 찍지 않는다.
2. `/dev/map-editor`에서 `resources/map/che.json`을 불러와 해안 → 호수 → 산맥 → 강 순서로 그린다. 해안이 먼저인 것은 섬과 바다를 정해야 나머지가 바다로 빠지지 않아서다. 여러 번에 나눠 그리도록 [지형 층 내려받기]로 초안 파일을 받고 다음에 [지형 층 덮어쓰기]로 이어 그린다. 덮어쓰기는 `cityHash`가 지금 도시 층과 다르면 이유를 보이고 거부한다. 되돌리기 기록은 덮어쓰기 때 비운다(불러오기와 같다).
3. 강은 바다나 다른 강에서 끝나게 한다. 강 끝점이 바다 안 2 이내이거나 다른 강의 선 위에 있어야 한다. 밑그림은 강을 마지막에 칠하므로(`sketch.ts:80`) 호수를 지나는 강은 호수 위에 강 색이 남는다. 호수를 지나는 구간은 강을 끊어 두 선으로 둔다.
4. `terrainDraft.ts`의 `checkAnchors(map, sources)`가 근거 표의 관계를 기계로 본다. 시험이 이 함수를 부르므로 지형을 고칠 때마다 근거가 깨졌는지 바로 안다. 같은 함수가 도시 점 검사도 한다. 모든 도시 중심이 땅이나 산맥 화소 위에 있고(바다·호수·강 화소 위가 아님), `pass`가 아닌 도시는 산맥 다각형 밖이다. 어떤 강도 도시 중심에서 `cityRadius(level) + 1`(`WorldMap.tsx:37`)보다 가까이 지나지 않는다.
5. 밑그림을 내보내고 해시 두 개를 적는다. `pngSha256`은 내려받은 파일 그대로의 해시다. PNG 압축은 브라우저 구현에 따라 바이트가 달라질 수 있어 `rasterSha256`도 둔다. 래스터 해시는 `너비(u32 BE) ‖ 높이(u32 BE) ‖ 팔레트 15바이트 ‖ 화소 번호 배열`의 SHA-256이다. T4-83은 받은 밑그림을 풀어 이 값을 다시 계산하고 같아야 생성을 시작한다(쟁점 MT-3).
6. 사용자 확인용 화면 사진을 남긴다. 편집기에서 che 도시 위에 지형을 띄운 사진 한 장과 밑그림 PNG를 구현 기록에 링크한다. 사진은 저장소에 커밋하지 않고 PR 본문에 붙인다.

### 상대 영역에 필요한 것

- Codex (리뷰): `resources/` 아래 새 파일 두 개는 Codex 소유 경로다. 반영은 Codex 리뷰를 거친다. `resources/NOTICE.md`에 지형 초안이 che 좌표를 바탕으로 했다는 한 줄이 필요한데 이 파일도 Codex 소유라 리뷰 때 Codex가 더하거나 허락한다.
- Codex T4-76: 지형 층 형식이 C-M2와 다르게 정해지면(캔버스 칸 이름, 닫힌 다각형 정의, 좌표 범위, 강 이름 칸) 이 초안을 거기 맞춰 옮긴다. 초안 전용 칸 `mapKey`·`cityHash`는 판 형식에 넣지 말아 달라고 요청한다.
- Codex T4-77: JSON 삭제 정적 검사(map-editor.md §6 남은 파일 행)가 `resources/map-terrain/`을 어떻게 다룰지 정해야 한다(쟁점 MT-1). che 지형을 담은 판을 어떻게 만들지도 정해야 한다(쟁점 MT-2).
- Codex T4-83: 래스터 해시 정의를 같이 쓴다(접근 5, 쟁점 MT-3).

### 사용자 결정이 필요한 것

1. 지형을 담은 che를 새 판으로 낼 때 1판으로 만든 기존 월드에 무엇을 보일지. 새 판의 바탕 그림을 1판에도 쓰거나(도시 층이 같으므로 맞는다), 1판은 바탕 없이 두거나다. 뒤쪽이면 AC-P2-28 문장을 손봐야 한다.
2. 근거가 약한 지형(동정호, 회수)을 그릴지. 이 계획은 그리고 목록에 올리는 쪽이다. 正史 근거가 없으면 빼는 쪽도 있다.
3. 이도(62)와 대(59)를 섬으로 그릴지. 근거를 찾지 못하면 대륙에 붙이는 것이 기본이다.
