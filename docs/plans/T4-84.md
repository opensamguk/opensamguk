# T4-84 메인·공개 지도에 바탕 그림 깔기

> 대기열: T4-84 · AC: AC-P2-28 (화면 몫) · 구현: Claude · 리뷰: Codex
> 설계: [지도 편집기 설계](./map-editor.md) §4 · 결정: [D-028](../product/decisions.md#d-028-운영자-지도-편집기와-도트-바탕-지도를-만든다-2026-10-23), [D-026](../product/decisions.md#d-026-로그인과-로비에-지연-공개-지도를-둔다-2026-10-23) · 선행: [T4-83](./T4-83.md), T2-25 · 앞 단계: [T4-82](./T4-82.md)

## 계획 (Claude)

### 목표

월드의 지도 판에 바탕 그림이 있으면 메인 지도와 공개 지도가 그 그림을 도시 점과 연결선 아래에 깐다. 그림이 없는 판, 그림 주소가 형식에 맞지 않는 판, 그림을 불러오지 못한 경우는 지금처럼 바탕 없이 그린다. 도시를 누르고 고르는 동작, 범례, 접근성 이름은 그대로다.

이 작업과 T4-83의 그림·출처 기록이 함께 있어야 AC-P2-28이 채워진다. T4-82·T4-83 리뷰가 끝나지 않았으면 이 작업이 끝나도 AC-P2-28을 완료로 세지 않는다.

### 하지 않는 것

- 재생 지도(`TimelapseView.tsx`)와 편집 캔버스(`mapEditor/`)에 그림 깔기. AC-P2-28은 메인·공개 지도만 말한다. 재생 지도에도 깔지는 사용자 결정 2다.
- 그림 만들기와 출처 기록 (T4-83).
- 서버 API, DB, 판 카탈로그 (Codex, 아래 상대 영역).
- 도시 점, 연결선, 이름표 모양을 새로 짜기. 그림 위에서 읽히도록 대비만 보강한다.
- 지도 확대·이동. 지금 메인 지도에 없는 기능이다.
- 공개 범위 바꾸기. 바탕 그림은 게임 상태가 아니라 판에 딸린 고정 그림이라 D-026 공개 범위(도시 소유 색과 국가 이름)를 넓히지 않는다.

### 화면 계약

```text
<svg viewBox="0 0 700 500">
  <rect class=ground />                    지금 그대로. 그림을 불러오는 동안과 실패했을 때 보인다
  <image class=background href=… 700×500 aria-hidden />   새로 넣는 한 줄
  <g aria-hidden> 연결선 </g>
  도시 묶음
</svg>
```

- 그림은 같은 SVG 안 `<image>`로 깐다. HTML `<img>`를 SVG 뒤에 겹치면 최대 높이 560px에 걸렸을 때 SVG만 가운데로 맞춰져 그림과 도시 점이 어긋난다. 같은 `viewBox` 안에 두면 어떤 크기에서도 좌표가 맞는다.
- `x=0 y=0 width=700 height=500`, `preserveAspectRatio="none"`이다. 그림은 2100×1500이라 비율이 같다.
- `image-rendering: pixelated`로 도트 경계를 유지하고 `pointer-events: none`으로 도시 누르기를 가리지 않는다. 그림은 꾸밈이라 `aria-hidden`이고 SVG의 `aria-label`(`WorldMap.tsx:66`)은 바꾸지 않는다.
- 불러오기 실패(`onError`)면 그 주소에서는 `<image>`를 빼고 바탕 사각형만 남긴다. 사용자에게 문구를 내지 않는다. 주소가 바뀌면(월드 탭 전환) 다시 시도한다. React는 SVG `<image>`에도 `error` 사건을 붙인다. 단위 시험으로 이를 확인한다.
- 대비: 그림이 있을 때 SVG에 `data-background` 표시를 두고 CSS로 연결선을 진하게, 공백지 점(`NEUTRAL`, `WorldMap.tsx:8`) 테두리를 진하게 한다. 값은 화면 사진을 보고 정한다. 국가색 이름표(`:123-139`)는 이미 불투명 상자라 그대로 둔다. 색만으로 뜻을 전하지 않는다는 기존 규칙(범례 `:152`)은 그대로다.
- 밝은·어두운 테마 모두 같은 그림을 쓴다. 테마별 그림은 만들지 않는다.

### 주소 만들기

- 서버는 판의 그림 경로만 준다(예: `maps/<지도 키>/base.webp`). 화면은 `imageBaseUrl`(`portraitUrl.ts:24`) 뒤에 붙여 주소를 만든다. 초상과 같은 기본 주소, 같은 `VITE_IMAGE_BASE_URL`을 쓴다(D-016).
- `mapBackgroundUrl`은 경로가 `maps/`로 시작하고 `/base.webp`로 끝나며 그 사이 조각이 영문·숫자·밑줄·하이픈·`@`·`/`뿐일 때만 주소를 낸다. `..`, 빈 조각, 다른 이름, 다른 확장자는 `null`이다. 서버가 실수로 엉뚱한 주소를 보내도 화면이 다른 곳의 그림을 부르지 않는다. 조각은 `encodeURIComponent`로 감싼다. `@`를 그대로 둘지 바꿀지는 T4-83 쟁점 MB-1의 확인 결과를 따른다.
- 기본 주소 고정 커밋을 T4-83이 그림을 올린 이미지 저장소 커밋으로 옮긴다. 옮기기 전에 새 커밋에서 초상 3종 주소(id 10002의 portrait·icon·thumb)가 200인지 확인해 구현 기록에 남긴다([이미지 자산](../image-assets.md) §2와 같은 방법). `portrait.test.tsx:46`의 기대값도 같이 바꾼다.

### 접근

1. 착수 조건(머리)을 확인한다. T2-25 `ece57f8`이 main에 없으면 시작하지 않는다. 그 브랜치를 이 작업 브랜치에 병합해 쓰지도 않는다. Codex 그림 칸 계약(아래 상대 영역)이 아직 `AppRouter`에 없으면 화면 부품(`WorldMap`의 `background` 속성, `mapBackground.ts`)과 그 단위 시험만 먼저 만든다. 응답 타입에 임시 칸을 덧대지 않는다. 실제 E2E와 완료 판정은 계약이 들어온 뒤다.
2. `mapBackground.ts`와 시험을 먼저 쓴다.
3. `WorldMap.tsx`에 속성과 `<image>`, 실패 상태를 넣는다. 속성이 없으면 지금 DOM과 같아야 한다(기존 시험 그대로 통과).
4. 메인·지도 화면·공개 지도에서 넘긴다. 공개 응답은 `ece57f8`의 `toPublicMaps`(`publicMaps.ts:41-46`)가 월드 줄에서 그림 칸을 골라 담는다. 타입은 `AppRouter`에서 오지만 경로 검사는 `mapBackgroundUrl`이 따로 한다. 검사에 떨어지면 `null`이다.
5. 화면 사진을 찍어 대비를 정한다. 메인·지도 화면·로그인 공개 지도를 375·768·1280 너비, 밝은·어두운 테마로 찍는다. 사진은 커밋하지 않고 PR 본문에 붙인다.
6. 기본 주소 고정 커밋을 옮기고 초상 응답을 확인한다.

### 상대 영역에 필요한 것

- Codex (`world.map`): 응답에 판의 바탕 그림 칸. 제안 모양은 `background: { path: string; width: number; height: number } | null`이다. 이름과 위치는 Codex 계약이 정한다. 화면은 `path`만 쓰고 `width`·`height`는 2100×1500이 아니면 그림을 깔지 않는 검사에 쓴다.
- Codex (`world.publicMaps`): 월드마다 같은 칸. 지연 사본이 아니라 월드의 판에 딸린 값이다. 무인증 절차에 경로를 더하는 것이므로 공개 범위 시험(T2-24)에 이 칸이 판 경로 말고 다른 값을 내지 않는다는 단언을 더해 달라.
- Codex T4-77·T4-78: 판마다 그림 유무를 저장하는 자리(T4-83 쟁점 MB-2). 그림이 있는 판과 없는 판의 월드를 E2E 준비에서 만들 수 있어야 한다.
- Codex T2-15: 운영 이미지 서버가 `maps/` 경로를 `portraits/`와 같은 방식으로 제공해야 한다.
- Claude T4-83 결과: 이미지 저장소 커밋 SHA, 경로 꼴(MB-1).
