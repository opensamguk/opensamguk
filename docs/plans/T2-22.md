# T2-22 순위 API

> 대기열: T2-22 · AC: AC-M2-19 (API) · 구현: Codex · 리뷰: Claude
> 선행: T1-07, T1-08 ([D-018](../product/decisions.md)) · 담당: Codex · 관련: FR-REC-04, [레퍼런스 R3](../design/references/README.md)

## 계획 (Claude)

### 목표

장수 순위(공헌·경험·전공)와 국가 순위(도시·장수·국력)를 제공한다. 공개 범위 밖 수치는 내보내지 않는다 (AC-M2-19).

### 범위

`apps/server/src/routers/ranking.ts`, 전공(전투 승리 수·점령 수) 집계 필드가 없으면 `General`에 추가 (엔진이 전투 결과에서 갱신).

### 하지 않는 것

역대 기수 기록(M3 FR-REC-03), 명예의 전당.

### 결정

| 순위 | 기준 | 공개 |
| ---- | ---- | ---- |
| 장수 | 공헌, 경험, 전공(승리·점령) | 이름·소속·순위 값 모두 공개 (원작과 같음) |
| 국가 | 도시 수, 장수 수, 국력 | 국력은 공개용 합성값만 ([D-019](../product/decisions.md)). 기술·국고·군량의 원값과 등급은 공개 값으로 역산되지 않아야 함 |

- 국력 공식은 `rules/ranking.ts` 한곳에 둔다. 원작 core2026 `monthlyNationStatsHandler.ts:102-144`처럼 자원/100, 기술, 보급 도시 내정, 장수 능력, (경험+공헌)/100을 더해 10으로 나누고 매달 시드 배율 0.95~1.05를 곱한다(D-019). 장수 능력항은 우리 능력치 3종(통솔·무력·지력)에 맞춘다.
- 회귀 시험: 도시·장수 수가 같고 기술만 다른 두 국가에서 `국력 − 도시 − 장수`가 기술 등급과 같지 않다. 같은 시드로 다시 돌리면 같은 국력이 나온다.
- 장수 순위는 상위 100명 + 내 순위. 국가 순위는 전체.
- 월간 정산 뒤 한 번 계산해 캐시(`RankingSnapshot`)한다. 조회는 캐시를 읽는다.

### API 계약

```ts
ranking.generals({ worldId, by: 'dedication' | 'experience' | 'merit' }) → { top: [...100], me: { rank, value } | null, at }
ranking.nations({ worldId, by: 'cities' | 'generals' | 'power' }) → { items: [...], at }
```

화면(T2-23)이 기대하는 행 모양 (2026-10-21 추가, 이름은 바꿔도 되지만 필드는 모두 필요):

```ts
type RankingAt = { year: number; month: number }; // 마지막 월간 정산의 게임 연월
type RankedGeneral = {
  rank: number; // 1부터, 같은 값이면 ID 순으로 이어 매김
  generalId: number;
  name: string;
  nation: { id: number; name: string; color: string } | null; // 재야는 null
  dedication: number;
  experience: number;
  merit: number; // 전공(승리 + 점령)
};
type RankedNation = { rank: number; nationId: number; name: string; color: string; cities: number; generals: number; power: number };
// ranking.generals → { top: RankedGeneral[], me: RankedGeneral | null, at: RankingAt | null }
//   me: 로그인한 사람의 그 월드 장수. 장수가 없으면 null. top 안에 있어도 함께 준다.
// ranking.nations → { items: RankedNation[], at: RankingAt | null }
//   at이 null이면 아직 월간 정산 전이다.
```

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 정렬 | API: 고정 시드 월드 → 기준별 순서, 같은 값이면 ID 순 |
| 공개 범위 | API: 응답 어디에도 국고·군량 원값 없음 |
| 갱신 | 통합: 월간 정산 뒤 `at` 갱신 |

## 구현 기록 (Codex)

- 착수: 2026-10-21 사용자 승인으로 M1 완료 전에 API만 병행한다. API PR 브랜치는 `codex/t2-22-ranking-api-20261021`이다. 화면은 Claude가 T2-23으로 구현한다. 화면 작업의 공유 폴더는 보존하고 API만 별도 worktree에서 커밋·푸시한다(사용자 승인 2026-10-21).
- 담당: 주 에이전트는 DB·엔진 저장·API·문서, `ranking_rules`는 `packages/rules/src/ranking*`, 전투 결과와 전공 테스트, `ranking_api_tests`는 `apps/server/src/routers/ranking.integration.test.ts`. 공유 export는 추가만 하고 원격 T1-09·T1-11의 코드는 가져오지 않는다.
- 구현 기준: 전공은 장수 간 교전 승리 수 + 도시 점령 수다. 교전 승리는 한쪽 병력 또는 사기가 0이고 상대는 둘 다 남은 경우에만 승자에게 1회 준다. 무승부·동시 소진·성벽 교전은 승리 수에 포함하지 않으며 무주공산 점령도 점령 수에는 포함한다.
- 공개 국력은 `도시 수 + 등장한 소속 장수 수 + min(11, floor(기술 / 1000))`으로 계산한다. 계획에 가중치가 없어 추가 가중치는 두지 않는다. 도시·장수 수와 함께 공개해도 기술 원값을 역산하지 못하도록 기술은 1000단위 구간만 반영하며 최고 구간은 11000~12000을 묶는다. 금·쌀·인구·병력은 입력에 넣지 않는다.
- 월간 정산과 같은 트랜잭션에서 월드별 최신 순위 캐시를 교체한다. 첫 정산 전에는 빈 목록과 `at: null`, 내 장수가 없거나 미등장이면 `me: null`을 반환한다. 동률은 ID 오름차순의 연속 순위다.
- 이미 진행 중인 월드도 migration 이후 다음 정산부터 순위 캐시가 생긴다. 과거 전공·순위는 소급 생성하지 않는다.
- 응답은 위 화면 계약의 필드를 모두 포함한다. 장수 행에는 `wins, captures, value`도 포함하고 `at`에는 `tick`을 함께 준다. 이름·소속도 정산 시점의 값이다.
- 계획과 달라진 점과 이유: 기존 연감의 `power`는 금·쌀·인구·병력의 합이라 공개하지 않는다. 기존 연감과 재생 기록은 보존하고 공개 순위 공식은 별도 순수 함수로 둔다. 전공 누계도 게임 규칙 입력과 재생 해시에서 제외한 조회용 집계다. 규칙이 구조화된 승리·점령 결과를 만들고 엔진이 턴 트랜잭션에서만 누계를 저장한다. 기존 세계의 이전 전투는 문구로 추측해 소급하지 않는다.
- 검증 결과: 최신 main(장수·예턴 API 병합 후) 기반 API worktree에서 `pnpm check` 통과(62개 파일·단위 315개, lint·포맷·타입 포함). 기술 역산 방지 수정 뒤 `pnpm exec vitest run packages/rules/src/ranking.test.ts packages/rules/src/commands/attack.test.ts` 22개, 수정 파일 lint·포맷·문구 검사 통과.
- PostgreSQL 검증은 전용 `opensamguk_ranking_test` DB를 사용했다. 전체 통합 110개 중 105개 통과, 기존 전투 4개와 지도 성능 1개 실패. 관련 4파일 재실행은 57개 중 54개 통과했으며 순위 API 17개·엔진 집계 2개는 두 실행 모두 통과했다. 재실행의 남은 실패는 기존 건국 재생의 30초 제한, 회랑 점령의 리스 만료, 지도 첫 요청 172ms(기준 50ms)였다. 확인 시 호스트 load average가 100을 넘었다.
- 마지막 실패 3개는 `vitest run --config vitest.integration.config.ts apps/engine/src/war.integration.test.ts apps/server/src/routers/reads.integration.test.ts --testNamePattern '건국·등용제안·수락|회랑 점령·단절|94도시 지도의 실제 TCP 요청 시간을'` 분리 실행에서 모두 통과했다(36.62초). 이 실행에서 선택하지 않은 35개는 통과 수에 넣지 않는다. 제한값은 바꾸지 않았으며 전체 통합 명령 자체가 한 번에 통과한 결과는 아직 없다. 개발 DB에는 migration을 적용하지 않았다.
- 상태: 구현을 마치고 Claude 리뷰를 기다린다. AC-M2-19는 화면·반대쪽 리뷰가 남아 있으므로 완료로 바꾸지 않았다.
