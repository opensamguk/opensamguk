# T1-17 초상 해석 (ID + base URL)

> 대기열: T1-17 · AC: AC-M1-20 · 구현: Claude · 리뷰: Codex
> 선행: T1-13 · 관련: [이미지 자산](../image-assets.md), D-004

## 계획 (Claude)

### 목표

초상은 초상 ID와 설정된 base URL로 해석된다. 없으면 기본 이미지가 나온다.
base URL 환경변수만 바꿔도 전부 교체된다 (AC-M1-20).

### 범위

`apps/web/src/portrait/`: `portraitUrl(id, variant)`, `<Portrait>` 부품, 기본 이미지.

### 하지 않는 것

시나리오 장수에 초상 ID를 붙이는 일. 이것은 데이터 작업이라 **Codex 작업 T1-19로 대기열에 추가했다.**
그 전까지 시나리오 장수는 `portraitId = null`이라 기본 이미지가 나온다.

### 결정

- `VITE_IMAGE_BASE_URL` (공개값). 운영은 우리 이미지 서버 주소(T2-15). 이미지 서버 전 개발 기본값은
  `https://cdn.jsdelivr.net/gh/peppone-choi/opensamguk-images@48163bd` (2026-10-20 정리 커밋 고정).
- 경로 규칙 (2026-10-20 이미지 저장소 정리로 바뀜): `${base}/portraits/${variant}/${id}.${ext}`
  - `portrait` → png (148×210), `icon` → webp (96×96), `thumb` → webp (48×68)
- ID 범위 밖(10001~11000 아님)이거나 null이면 기본 이미지. 이미지 로드 실패(`onError`)도 기본 이미지.
- 기본 이미지: **코드로 그린 실루엣 SVG** (`apps/web/src/portrait/fallback.svg`). 자작 초상 37장은 2026-10-20 정리로 지웠고
  생성 이미지가 생기면 그것으로 바꾼다 (백로그). 장수 이름 첫 글자를 얹어 구분한다.
- `alt`는 장수 이름.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 경로 | Vitest: id 10006 → 각 variant URL, 범위 밖·null → 기본 이미지 |
| 교체 | Playwright: base URL을 두 값으로 바꿔 빌드한 두 화면의 `img src` 차이 + 스크린샷 2장 |
| 실패 | Playwright: 존재하지 않는 ID → 기본 이미지로 바뀜 |

### 채울 문서

구현하면서 함께 채운다. 리뷰어는 문서도 확인한다.

- `docs/image-assets.md §2 (실제 base URL·태그)`

## 구현 기록 (Claude)

- 바꾼 것: `apps/web/src/portrait/`에 `portraitUrl`·`resolveImageBaseUrl`·`isPortraitId`(`portraitUrl.ts`), `<Portrait>` 부품과 CSS,
  실루엣 `fallback.svg`, 단위 시험 `portrait.test.tsx`를 넣었다. `vite-env.d.ts`에 `VITE_IMAGE_BASE_URL` 타입을 적었다.
  `vite.config.ts`의 `envDir`를 저장소 루트로 바꿔 루트 `.env`의 `VITE_*` 값이 화면에 들어가게 했다 (runtime.md §2가 루트 `.env` 하나를 쓰기로 정했다).
  부품 모음(`/dev/ui`)에 Portrait 절을 더했다. Playwright 시험은 `e2e/portrait.spec.ts`다.
  채울 문서로 `docs/image-assets.md` §2에 화면의 해석 절을 더했고 `docs/architecture/runtime.md`의 `VITE_IMAGE_BASE_URL` 행을 사용 중으로 고쳤다.
- 계획과 달라진 점과 이유: 교체 시험은 값을 달리한 프로덕션 빌드 두 개 대신 값을 달리한 Vite dev 서버 두 개(5181, 5182)로 했다.
  시험 대상 화면 `/dev/ui`가 dev에서만 열리기 때문이다. 값은 두 경우 모두 `import.meta.env`로 시작 때 박히므로 교체 방식은 같다.
  시험의 이미지 요청은 `page.route`로 가로채 서버별 색 그림을 돌려준다. 외부 네트워크와 원작 초상 파일 없이 결과가 정해지게 하려는 것이다.
  실제 jsDelivr 주소는 curl로 따로 확인했다. 스크린샷에 원작 초상은 들어가지 않는다.
