# T2-21 알림 설정 화면

> 대기열: T2-21 · AC: AC-M2-18 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-20 (API)

## 계획 (Claude)

### 목표

사용자가 디스코드 웹훅을 등록·해제하고 받을 알림 종류를 고른다.

### 범위

`apps/web`: `/settings/notifications` (계정 설정, 월드와 무관), 위쪽 띠 계정 메뉴에서 이동.

### 화면

- 웹훅 주소 입력 → [시험 보내고 저장]. 성공하면 "등록됨 (…ab12)", 실패하면 서버가 준 고정 안내 문장을 그대로 보여 준다(T2-20의 결과 분류별 문장). 디스코드 응답 원문은 받지도 보여 주지도 않는다.
- 알림 종류 체크: 예턴 실패 · 공격받음 · 외교 제안 · 예턴 3칸 이하.
- 웹훅 만드는 법을 3단계로 안내 (디스코드 채널 설정 → 연동 → 웹후크).
- 주소는 저장 뒤 다시 보여 주지 않는다 (끝 4자리만).
- 등록된 대상에는 [해제]가 있고 확인 대화를 거친 뒤 지운다.
- 발송 중 디스코드가 웹훅을 지웠다고 답해 비활성화되면 "웹훅이 더 이상 받지 않습니다. 주소를 다시 등록해 주세요."를 한 줄로 띄운다.
- 체크를 바꾸면 바로 `notification.setEvents`로 저장한다. 주소를 다시 넣지 않는다. 요청은 하나씩 보낸다. 처리 중인 체크는 처리 중으로 표시해 스크린리더도 구분하게 한다. 실패하면 서버 상태로 되돌리고 이유를 보여 준다.
- 모든 변경 요청에 마지막으로 받은 `generation`을 보낸다. `CONFLICT`를 받으면 최신 상태로 다시 그리고 안내 문장을 띄운다.
- 주소 입력 칸은 저장이나 실패 뒤 바로 비운다. 주소를 화면 다른 곳, 브라우저 콘솔 로그, 오류 보고에 남기지 않는다.
- 응답 모양은 [T2-20](./T2-20.md)의 `NotificationResponse`다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 등록 | Playwright(localhost 가짜 웹훅 서버): 저장 → 등록됨 표시 |
| 실패 | Playwright: 디스코드가 아닌 주소 → 고정 안내 문장, 저장 안 됨. 가짜 웹훅이 401·429·500 → 각 고정 문장 |
| 주소 노출 없음 | Playwright: 등록·실패 뒤 DOM, 콘솔 로그, 오류 문장, 스크린샷에 주소 전체와 토큰이 없음 |
| 경합 | Playwright: 체크를 빠르게 여러 번 바꿈 → 마지막 상태로 저장, 순서가 뒤집히지 않음. 다른 탭에서 해제한 뒤 체크 → `CONFLICT` 안내와 최신 상태. 다른 탭에서 해제하고 다시 등록한 뒤 옛 탭에서 체크 → `CONFLICT`, 새 등록 유지 (T2-20 R63-11R) |
| 종류 | Playwright: 체크 해제 → 새로고침 뒤 유지 |
| 해제 | Playwright: 해제 → 확인 → 등록 전 화면으로 돌아감, 새로고침 뒤 유지 |
| 비활성화 | Playwright(가짜 웹훅 서버가 404): 안내 한 줄 표시, 주소를 다시 넣으면 사라짐 |

시험은 모두 T2-20의 시험 전용 전송부와 localhost 가짜 웹훅 서버로 한다. 입력 칸에는 주소 검사를 통과하는 디스코드 모양의 가짜 주소(가짜 ID·토큰)를 넣는다. 실제 디스코드 웹훅은 쓰지 않는다.

## 구현 기록 (Claude)

- 바꾼 것:
  - `apps/web/src/notifications/NotificationSettingsPage.tsx`: `/settings/notifications` 화면. 웹훅 주소 칸과 [시험 보내고 저장], 등록됨 (…끝 4자리), 비활성화 안내 한 줄, 확인을 거치는 [해제], 알림 종류 체크 4개, 웹훅 만드는 법 3단계.
  - 체크는 바꾸는 즉시 `setEvents`로 저장한다. 요청은 하나씩 보내고 앞 요청이 끝났을 때 마지막 상태가 다르면 받은 `generation`으로 한 번 더 보낸다. 처리 중인 체크는 저장 중 글자와 `aria-busy`로 표시한다.
    실패하면 서버 상태로 되돌리고 이유를 보이며 `CONFLICT`면 `notification.get`을 다시 받아 그린다.
  - 주소 칸은 요청을 보내는 순간 비운다. 주소가 query·mutation 캐시에 남지 않도록 `useMutation`을 쓰지 않고 바로 부른다. 오류 객체를 콘솔에 쓰지 않는다.
  - `router.tsx`에 로그인이 필요한 경로 한 줄, 위쪽 띠(`GameLayout`)에 알림 설정 링크 한 줄.
  - API는 아직 main에 없어 T2-20 계약 초안을 `apps/web/src/notifications/contract.ts` 한 파일에 옮겼다.
- 계획과 달라진 점과 이유:
  - 등록 전에도 알림 종류 체크를 고를 수 있게 했다(기본은 넷 다 켬). `setDiscord`가 `events`를 함께 받으므로 그 값으로 저장한다. 등록 뒤의 체크는 계획대로 바로 `setEvents`다.
  - 위쪽 띠에는 아직 계정 메뉴가 없어 로그아웃 옆에 알림 설정 링크 하나를 두었다. 계정 메뉴가 생기면 그 안으로 옮긴다.
  - 로비 위쪽 띠는 T2-04가 만드는 중이라 이 작업에서는 게임 화면 위쪽 띠에만 링크를 두었다.
  - U63-4(결과 모르는 전송)와 U63-5(공격받음 단위)는 고르지 않았다. 둘 다 발송 쪽 결정이라 이 화면의 문구와 동작은 바뀌지 않는다.
- 검증 결과:
  - 단위: `apps/web/src/notifications/notifications.test.tsx`(고른 종류로 등록하고 주소 칸 비움·끝 4자리만 표시·DOM에 토큰 없음, 실패 때 고정 문장만 보이고 DOM·콘솔에 토큰 없음, 비활성화 안내가 다시 등록하면 사라짐,
    해제는 확인 뒤 마지막 generation으로, 빠른 체크 변경이 요청 2번으로 합쳐지고 둘째가 새 generation으로 감, 실패 때 서버 상태로 되돌림, `CONFLICT` 때 최신 상태로 다시 그림). 가짜 주소만 쓰고 실제 디스코드로는 보내지 않았다.
  - `pnpm check` 결과는 PR 본문에 적는다.
  - E2E: `e2e/notifications.spec.ts`. 디스코드가 아닌 주소 거절과 주소 노출 없음, 가짜 수신기로 등록·종류 유지·해제. T2-20 API가 없으면 건너뛰고 등록 시험은 가짜 수신기 설정이 있는 실행(`E2E_FAKE_WEBHOOK=1`)에서만 돈다. 지금 결과는 증거가 아니다.
  - 아직 쓰지 않은 계획 검증 줄: 401·429·500별 고정 문장, 다른 탭 해제·재등록 뒤의 `CONFLICT`, 404 비활성화. 가짜 수신기 응답을 고르는 방법이 T2-20 구현에서 정해지면 더한다.
- Codex에 필요한 것: T2-20 계약대로의 `notification` 라우터. Playwright가 쓸 시험 전용 전송부와 localhost 가짜 수신기를 켜는 환경변수 이름, 그리고 수신기가 돌려줄 상태 코드(401·404·429·500)를 시험에서 고르는 방법.
