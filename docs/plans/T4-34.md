## 계획 (Claude)

### 목표

사용자가 양쪽 병력·병종·훈련·사기·기술과 시드를 직접 넣는다. 진짜 Web Worker가 main `ab6f803`의 `simulateBattle(input, createRng(seed))`를 한 번 실행한다. 화면은 시드, 양쪽 남은 병력과 사기, 그 결과를 낸 입력 가정을 보여 준다. 같은 입력과 시드로 다시 실행하면 결과가 같다. 계산하는 동안에도 입력 칸은 막히지 않는다. 다른 국가의 비공개 값은 조회하지도 자동으로 채우지도 않는다.

### 범위

AC-P2-16 제안 문장 가운데 추출한 함수를 한 번 평가하는 화면만 맡는다. 이 작업이 끝나도 AC-P2-16 전체나 새 명령이 완료된 것으로 세지 않는다. 아래는 남는다.

- 실제 턴의 전투와 결과가 같다는 부분. 실제 출병은 턴 RNG 흐름의 중간에서 계산을 시작하고 교전 전에 군량을 소비하며(`attack.ts:10~13`, `:66~67`) 수비 장수 여럿과 성벽을 이어서 싸운다. 시뮬레이터는 `createRng(seed)`를 새로 만들어 교전 한 번만 계산한다.
- 원작 `battleSimulator/`의 추가 JSON 입력, 승률, 아이템, 특기, 새 명령, 정책 U 항목.
- AC-P2-16 정식 반영. 아래 반영 원고를 원 작성자에게 넘긴다.

### 화면과 진입

- 주소는 `/w/$worldId/simulator`, 제목은 전투 시뮬레이터다. `worldRoute` 아래라 로그인 가드는 기존 그대로다.
- 위쪽 띠 메뉴에 한 줄을 더한다(`layout/GameLayout.tsx`의 `NAV`). 메뉴의 다른 주소처럼 보조 화면이다. 메인 화면, 예턴 편집기, `useTurnDraft`는 고치지 않는다. 메인으로 돌아오면 초안은 `sessionStorage`에서 그대로 다시 읽힌다.
- 이 화면은 tRPC를 부르지 않는다. 위쪽 띠가 원래 부르는 `auth.me`·`home.get`·`world.summary` 말고는 요청이 없다. 내 장수 값도 자동으로 채우지 않는다.

### 입력과 검사

수비 종류는 장수와 성벽 두 가지다. 실제 출병의 두 호출 모양을 그대로 따른다.

| 칸 | 공격 | 수비 (장수) | 수비 (성벽) | 범위 |
| -- | ---- | ----------- | ----------- | ---- |
| 병종 | 선택 | 선택 | 성벽(1000) 고정 표시 | 장수는 `armType > 0`인 병종만 |
| 병력 | 입력 | 입력 | 성벽 값 입력 | 정수. 장수 1~10,000(통솔 상한 100 × `CREW_PER_LEADERSHIP` 100), 성벽 1~12,500 |
| 훈련 | 입력 | 입력 | 100 고정 표시 | 정수 0~100 |
| 사기 | 입력 | 입력 | 100 고정 표시 | 정수 0~100 |
| 기술 | 입력 | 입력 | 입력 | 정수 0~12,000 |
| 수비 값 | 없음 | 0 고정 (보내지 않음) | 입력 | 정수 0~12,500 |
| 시드 | 한 칸 | | | 문자열 1~64자. 다듬지 않고 그대로 `createRng`에 넣는다 |

- 요청 모양은 두 가지만 받는다. 수비 병종이 1000이면 수비 훈련·사기가 100이고 `defence`가 있어야 한다. 수비 병종이 `armType > 0`이면 `defence`가 없어야 한다. 공격 병종은 늘 `armType > 0`이다.
- 성벽 상한 12,500은 `resources/map/che.json`의 도시 `max.wall`·`max.defence` 최댓값이다. 화면 상수로 두고 단위 시험이 같은 파일과 대조한다. `request.ts`는 rules를 import하지 않으므로 기술 상한 12,000과 병력 상한의 `CREW_PER_LEADERSHIP` 100도 상수로 두고 `compute.test.ts`가 `BALANCE`와 대조한다.
- 기본값은 병력 1,000, 병종은 병종표의 `defaultCrewTypeId`, 훈련 50, 사기 50, 기술 0, 수비 값 0, 시드 `1`이다. 게임 상태에서 가져온 값이 아니라 빈칸을 피하려고 둔 값이다.
- 숫자가 아님, `NaN`·`Infinity`, 소수, 음수, 범위 밖, 없는 병종, 장수 쪽 성벽 병종, 빈 시드나 65자 이상 시드는 보내기 전에 칸 아래에 이유를 보이고 실행 버튼을 점선으로 둔다. Worker는 같은 검사 함수(`request.ts`)로 받은 메시지를 다시 검사한다. 화면 검사를 지나친 값도 Worker에서 막힌다.

### Worker 메시지 계약

화면에서 Worker로 가는 메시지는 하나다.

```ts
type BattleRunRequest = {
  type: 'run';
  requestId: number; // 화면 인스턴스 안에서 1부터 하나씩 늘린다
  seed: string;
  attacker: BattleForce; // crew, crewType, train, atmos
  defender: BattleForce;
  attackerTech: number;
  defenderTech: number;
  defence?: number; // 성벽일 때만
};
```

Worker의 답은 둘 중 하나다.

```ts
type BattleRunResult = {
  type: 'result';
  requestId: number;
  seed: string;
  input: Omit<BattleRunRequest, 'type' | 'requestId' | 'seed'>; // 검사를 지난 입력 그대로
  unitSetId: string; // 'basic'
  attacker: BattleForce;
  defender: BattleForce;
};
type BattleRunError = {
  type: 'error';
  requestId: number | null; // 메시지를 읽지 못했으면 null
  code: 'INVALID_INPUT' | 'UNIT_SET_INVALID' | 'FAILED';
  field?: string;
};
```

- Worker는 메시지에 병종표를 받지 않는다. 자기 묶음에 든 공개 병종표만 쓴다.
- 결과의 `attacker`·`defender`는 `simulateBattle`의 반환값 그대로다. 새 수치나 승패 판정을 더하지 않는다.
- 화면 문구는 `code`에서 화면이 만든다. Worker는 한국어 문장을 보내지 않는다.

### 수명

`useBattleWorker` 하나가 Worker와 요청 번호를 맡는다.

- Worker는 첫 실행 때 만든다. 실행할 때마다 `requestId`를 하나 늘리고 그 값만 현재 요청으로 둔다. 다른 `requestId`로 온 답은 버린다. 결과 칸은 가장 최근 요청의 답만 보인다.
- 계산 중에는 입력 칸을 막지 않는다. [취소]를 누르면 Worker를 `terminate()`하고 대기 상태로 돌아간다. 다음 실행 때 새 Worker를 만든다.
- Worker의 `error`·`messageerror` 이벤트나 `type: 'error'` 답을 받으면 Worker를 `terminate()`하고 오류와 [다시 실행]을 보인다. 다시 실행은 마지막으로 보낸 입력과 시드를 새 Worker로 다시 보낸다. 같은 결과가 나와야 한다.
- 화면을 떠나 컴포넌트가 사라지면 Worker를 `terminate()`한다. 사라진 뒤 온 답은 상태를 바꾸지 않는다.
- 시간 제한은 두지 않는다. 계산은 최대 `BALANCE.BATTLE_PHASES` 10페이즈다.

브라우저로 들어가는 것은 아래 두 경로뿐이다. 둘 다 정확한 파일 하나에만 ESLint 예외를 둔다.

| 예외 | 파일 | 허용 | 계속 막는 것 |
| ---- | ---- | ---- | ------------ |
| E1 | `apps/web/src/battleSim/compute.ts`, `compute.test.ts` | `@opensamguk/rules` 값 import. 가능하면 `allowImportNames`로 `simulateBattle`·`unitSetSchema`·`BALANCE`와 타입만 | 다른 `apps/web` 파일의 `@opensamguk/rules` import, `@opensamguk/shared/node`, `@opensamguk/engine`·`db`·`server` 값 import |
| E2 | `apps/web/src/battleSim/publicUnitSet.ts` | `../../../../resources/unitset/basic.json` 하나를 상대 경로로 import (이 파일만 `opensamguk/no-cross-package-relative` 끔) | 다른 `apps/web` 파일의 패키지 밖 상대 경로 |

- `compute.ts`는 Worker 파일만 import한다. 메인 스레드 코드는 `request.ts`(검사)와 `publicUnitSet.ts`(병종 이름과 기본 병종)만 쓴다. 그래서 `simulateBattle` 코드는 Worker 묶음에만 들어간다.
- `packages/rules`는 lint가 Node 내장 모듈, `fetch`, 현재 시각, `@opensamguk/shared/node`를 막는다(`eslint.config.js:68~85`). Node 전용인 `apps/engine/src/world/resources.ts`(`node:fs`)와 `packages/shared/src/node/hashState.ts`(`node:crypto`)는 이 경로에 없다.
- `basic.json`은 저장소에 커밋된 공개 정적 자료다. 사용자 입력이 아니며 네트워크로 받지도 않는다. Worker는 처음 한 번 `unitSetSchema.parse`와 id 중복·기본 병종 존재를 검사한다. 실패하면 모든 요청에 `UNIT_SET_INVALID`를 답하고 결과를 내지 않는다.
- 화면은 이 표를 기본 병종표(basic) 기준이라고 밝힌다. 월드 DB에 저장된 병종표를 조회하지 않으므로 다른 병종표로 만든 월드와 같다고 보장하지 않는다. 지금 엔진 기본값과 유일한 병종표는 basic이다.
- `docs/architecture/package-boundaries.md`의 예외 문단에 E1·E2를 적는다. `apps/web/package.json`에 `"@opensamguk/rules": "workspace:*"`를 더하고 `pnpm-lock.yaml`의 importer 줄만 바뀐다.

### 결과 표시

- 결과 칸은 시드, 병종표 id, 공격·수비 각각의 병종 이름, 병력 시작값과 남은 값(`ValueDelta`), 사기 시작값과 남은 값을 보인다. 숫자는 `.num`이다. 성벽이면 수비 값과 고정된 훈련·사기를 함께 보인다.
- 결과 칸의 입력값은 지금 폼이 아니라 Worker가 돌려준 `input`이다. 실행 뒤 폼을 고치면 결과 위에 지금 입력과 다르다는 한 줄을 보인다.
- 가정 문단을 늘 보인다. 교전 한 번만 계산한다. 출병 전 군량 소비와 굶주림 사기 감소, 수비 장수 여럿과 성벽으로 이어지는 교전, 실제 턴의 난수 흐름은 넣지 않았다는 내용이다.
- 결과 칸은 `aria-live="polite"`다. 계산 중 표시와 [취소]가 있다. 375px 폭에서 이 화면의 본문은 가로로 넘치지 않고 누르는 대상은 44px 이상이다. 위쪽 띠의 좁은 화면 처리는 T3-10 범위다.

### 하지 않는 것

`packages/*`, `apps/server`, `apps/engine`, `resources/`, Prisma schema, API, DB를 고치지 않는다. 새 tRPC 프로시저나 서버 프록시를 만들지 않는다. 월드 상태, 다른 국가 값, 내 장수 값을 조회하거나 채우지 않는다. 전투 수치, 효과, 승률, 승패 판정을 새로 만들지 않는다. 메인 화면과 예턴 편집기, `useTurnDraft`를 고치지 않는다. `deploy/security.caddy`를 고치지 않는다. 결과를 저장하거나 공유하지 않는다.
