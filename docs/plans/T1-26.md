# T1-26 같은 판 가속과 기수 종료 판정·결과 저장·조회

> 대기열: T1-26 · AC: AC-M1-21 (데모의 가속·종료 부분) · 구현: Codex · 리뷰: Claude
> 선행: T1-09 · 후속: T1-27 (종료 화면), T1-18 (독립 에이전트 완주 데모) · 근거: FR-WLD-04, FR-WLD-06, FR-ENG-07, [게임 시계](../architecture/game-clock.md)

## 계획 (Claude)

### 왜 생긴 작업인가

T1-18 사전 점검(main `77723bf`, CI [39741923516](https://github.com/peppone-choi/opensamguk/actions/runs/39741923516))에서 데모 뒷부분을 할 경로가 없다는 것을 확인했다.
실제 PostgreSQL의 1030·94도시·491명 월드를 300년 12월 정산 직전에 두고 `TurnLoop.advanceTo(13200000)`를 돌렸더니 정산은 됐지만 `status`는 `RUNNING`, `endedAt`은 `null`이었다.
`turnLoop.ts`는 시계만 저장하고 종료를 판정하지 않는다. 운영 명령은 `start/pause/resume/status`뿐이다.
`pnpm sim`은 사람 장수가 있으면 거부하므로 사람이 플레이한 판을 이어서 돌릴 수 없다. 조회 API에도 승자·종료 결과가 없다.
그 경계 탐침의 300년은 시뮬레이터 기본값을 빌린 합성 설정이었다. 그 뒤 소유자가 T1-18 시험 월드의 종료 연도를 300년으로 정했다([D-024](../product/decisions.md#d-024-m1-완주-데모의-참가자와-기수-종료-규칙을-정한다-2026-10-22)). 이 값은 그 월드의 생성 인자다.

### 목표

사람이 플레이하던 같은 DB 월드를 운영 명령 하나로 가속하고 그 판이 천하통일이나 월드에 정한 종료 연도에 이르면 엔진이 한 트랜잭션으로 월드를 끝내고 결과를 남긴다.
화면은 `world.summary`에서 승자(없음 포함)와 종료 연월을 읽는다.

### 정한 것

A17은 D-024로 승인됐다. 판정 방식은 A17 문장대로 만든다. 종료 연도는 월드마다 명시하고 코드에 기본값으로 넣지 않는다. T1-18 시험 월드의 300년도 생성 인자로만 준다.

| 항목 | 정한 내용 |
| ---- | --------- |
| 종료 연도 위치 | 월드 설정 `World.endYear Int?`. 시나리오 리소스 1030에는 종료 연도가 없으므로 리소스에 새로 만들지 않는다 |
| 종료 연도 기본값 | 없다. `pnpm world:create`에 `--end-year <연도>`를 필수로 받는다. 시작 연도 이상 10000 이하 정수. 프로그램 API(`saveInitialWorld`)도 명시 인자로 받는다. D-024대로 이 명시 필수 계약을 유지하고 300을 기본값이나 상수로 두지 않는다 |
| 기존 월드 | migration은 `endYear`를 `null`로 둔다. `null`이면 통일로만 끝난다. 저장된 `initialStateHash`·`replayOrigin`·`YearbookSnapshot.stateHash`·`nextTurnTick`은 바꾸지 않는다 |
| 해시와 설정 | 해시 대상 모양은 지금의 `ReplayState` 네 키 `{ state, turns, revisions, monthlyTick }` 그대로 둔다. `endYear`·`clockMode`·`outcomeFromSequence`·결과는 `WorldInit`·`WorldState`·`ReplayState`·`replayOrigin` 어디에도 넣지 않고 판정 함수와 재생 함수에 따로 넘긴다. 상태 모양에 버전을 두는 방식은 쓰지 않는다 (9번) |
| 시뮬레이터 300 | `DEFAULT_SIMULATION_MAX_YEAR = 300`은 AC-M1-17 증거용 시뮬레이터 값으로만 남긴다. 운영 월드 기본값으로 쓰지 않는다. T1-18 시험 월드의 300년도 이 상수를 읽지 않고 `--end-year 300`으로 준다 |
| 통일 | 시뮬레이터 `unifiedNation`과 같다. 국가가 하나만 남고 모든 도시를 그 국가가 가졌을 때다. 중립 도시가 남으면 통일이 아니다 |
| 통일 판정 시점 | 장수 턴 하나(그 턴의 국가 명령 포함)를 실행한 직후와 월간 정산 직후 |
| 종료 연도 판정 시점 | `endYear`년 12월 정산을 마친 직후. 같은 tick의 장수 턴은 정산 뒤에 도는 규칙이므로 종료한 월드에서는 그 턴을 실행하지 않는다 |
| 승자 | 통일이면 그 국가. 종료 연도 도달이면 `null`(승자 없음, D-024). 테스트 정책 §4의 시뮬레이터 결과 형식과 같다 |
| 종료 연월 | 결정한 사건의 게임 연월. 종료 연도 도달은 `endYear`년 12월이다. 12월 정산 tick은 다음 해 1월의 시작 tick이므로 시계에서 연월을 다시 계산하지 않고 결과 행에 저장한다 |
| 가속 방식 | 월드 시계 모드 `World.clockMode`(`REALTIME`·`ACCELERATED`)를 DB에 저장하고 운영 명령으로 바꾼다. 실행권을 가진 엔진(`pnpm dev`나 `engine:run`)이 그 모드를 읽는다. 별도 프로세스나 리스 인계가 필요 없다 |

가속을 별도 CLI 프로세스로 만들지 않은 이유가 있다. `pnpm dev`의 엔진이 실행권을 잡고 있으면 다른 프로세스는 리스를 얻지 못한다.
모드를 월드 행에 두면 지금 도는 엔진이 같은 `TurnLoop.step` 트랜잭션으로 가속한다. 리스·펜싱·정지·재개·월간 정산 순서가 그대로다.

### 범위

`packages/rules`, `packages/db`(schema, 새 migration), `apps/engine`, `apps/server`, `tools/replay.ts`, 루트·엔진 `package.json`의 스크립트 두 줄, 채울 문서.

1. 규칙(`packages/rules`). 순수 함수 `seasonOutcome(state, { endYear, settled? })`를 둔다. `settled`는 방금 정산한 연월이다. 반환은 `null` 또는 `{ reason: 'UNIFIED' | 'END_YEAR', winnerNationId: number | null }`. `unifiedNation`을 이리로 옮기고 시뮬레이터·엔진·재생이 모두 이 함수를 쓴다. DB·시각·파일을 쓰지 않는다.
2. schema와 새 migration. `World.endYear Int?`, `World.clockMode WorldClockMode @default(REALTIME)`, `World.outcomeFromSequence Int @default(0)`, 새 모델 `WorldResult`.
   `WorldResult`는 `worldId`(PK이자 World FK), `reason`, `winnerNationId Int?`, `winnerName String?`, `winnerColor String?`, `endedYear`, `endedMonth`, `endedTick`, `endedSequence`, `remainingNations`, `finalStateHash`, `endedAt`을 둔다. 승자 이름·색은 종료 시점 값을 복사해 둔다. 기존 migration 파일은 고치지 않는다.
   migration은 기존 월드의 `outcomeFromSequence`를 그 월드의 현재 `actionSequence`로 채운다. 새 월드는 0이다. 재생은 이 번호 이후의 사건만 종료 판정을 한다(9번). migration 전에 이미 한 국가만 남은 월드라면 migration 뒤 첫 장수 턴이나 정산에서 끝나고 재생도 같은 사건에서 끝난다.
3. 엔진 종료(`turnLoop.ts`). 장수 턴이나 월간 정산을 저장하는 같은 트랜잭션 안에서 `seasonOutcome`을 부른다. 결과가 있으면 같은 트랜잭션에서 `World.status = ENDED`, `endedAt = DB 시각`, `clockTick = max(저장된 clockTick, 결정 tick)`을 쓰고 `WorldResult`를 만든다. 시계는 뒤로 가지 않는다.
   결정 tick(`endedTick`)은 장수 턴이면 그 턴의 `nextTurnTick`, 정산이면 그 월 경계다. `endedSequence`는 그 사건이 `nextActionSequence`로 받은 번호다.
   `finalStateHash`는 종료 사건의 저장을 모두 마친 같은 트랜잭션에서 `hashState(await loadReplayState(tx, worldId))`로 계산한다. 월간 snapshot과 같은 네 키 모양이다. 장수 턴 종료면 예턴 한 칸 밀기·`turnRevision` 증가·`nextTurnTick` 증가를 저장한 뒤이고 정산 종료면 `monthlyTick` 갱신 뒤다. 그래서 정산 종료의 `finalStateHash`는 같은 트랜잭션의 그 달 `YearbookSnapshot.stateHash`와 같다.
   월드 갱신은 `status = RUNNING`과 `clockRevision` 조건으로 한다. `WorldResult`의 PK가 두 번째 종료를 막는다. commit 직전 리스 확인(`assertLease`)은 지금처럼 한다.
4. 종료 뒤 엔진. `ENDED` 월드에서는 장수 턴·정산·시계 저장을 하지 않는다. `endedSequence` 뒤에는 게임 사건이 없다. 종료를 확인하려고 다음 정산이나 턴을 실행하지 않는다.
   종료 전에 받아 둔 `PENDING` 장수 생성은 상태를 바꾸지 않고 `REJECTED`(`WORLD_CLOSED`)로 닫는다. 이 닫기도 `nextActionSequence`로 번호를 받으므로 sequence가 `endedSequence`보다 크다. 이것은 종료 사건이 아니며 `WorldResult`와 `finalStateHash`를 바꾸지 않는다. 종료 뒤 새 예턴 저장·장수 생성 요청은 서버가 기록 없이 거부한다(지금 코드 그대로).
   `runEngine`은 `ENDED`이고 남은 `PENDING` 생성이 없을 때 실행권을 놓는다. `--world`를 지정했으면 종료 코드 0으로 끝내고 지정하지 않았으면 다음 `RUNNING` 월드를 찾는다.
5. 가속 모드. `ACCELERATED`인 `RUNNING` 월드에서는 `TurnLoop.step`이 벽시계 대신 다음 사건 tick(가장 이른 실행 대상 장수의 `nextTurnTick`과 다음 월 경계 중 작은 값)을 목표로 삼는다. 이 목표는 저장된 `clockTick`보다 작지 않다.
   사건 하나를 한 트랜잭션으로 저장하고 `clockAnchorAt`을 DB 시각으로 둔다. 가속 중에는 다음 사건이 늘 있으므로 지금의 `drain`처럼 진행이 멈출 때까지 돌면 `poll`이 끝나지 않고 실행 결과가 계속 쌓인다. 그래서 `poll`은 배치 하나만 실행하고 돌아온다.
   - 배치 상한: 진행한 step(장수 턴·정산·생성 처리)이 `ENGINE_BATCH_STEPS = 64`개가 되거나 배치 시작부터 `ENGINE_BATCH_MS = 250`ms가 지난 뒤의 첫 step 경계에서 끝난다. 두 값은 운영 루프 상수이고 게임 수치가 아니다. REALTIME에도 같은 상한을 쓴다(오래 멈췄던 엔진의 밀린 턴도 같은 경계로 나눈다).
   - 반환: `poll(signal): Promise<PollBatch>`, `PollBatch = { executions: TurnExecution[]; more: boolean; status: WorldStatus }`. `executions`는 그 배치 것만이고 64개를 넘지 않는다. `more`는 상한 때문에 끝났을 때만 `true`다. 진행이 없어 끝났으면 `false`. `status`는 마지막 step이 잠근 월드 행의 값이다.
   - 보관량: `TurnLoop`은 배치 사이에 실행 결과를 들고 있지 않는다. 남기는 것은 지금처럼 마지막 commit 상태 사본 하나와 `highWaterTick`뿐이다. `runEngine`도 배치 결과를 모으지 않는다.
   - `runEngine`: `more`면 100ms 대기만 생략하고 `setImmediate`로 한 번 양보한 뒤 다음 배치를 부른다. `more`가 `false`면 지금처럼 100ms 쉰다. 배치마다 `session.signal`(종료 신호·리스 갱신 실패)을 확인한다. 각 step은 지금처럼 월드 행을 잠가 상태를 다시 읽고 commit 직전 `assertLease`를 한다. `status`가 `ENDED`이고 `more`가 `false`면 4번대로 실행권을 놓는다. 리스 갱신은 지금처럼 별도 루프가 `LEASE_TTL_MS / 3`마다 한다.
   - `advanceTo(tick)`: 배치 상한을 쓰지 않고 목표 tick까지 실행한 `TurnExecution[]` 전체를 돌려주는 기존 계약 그대로다. 목표가 있어 끝이 있고 시험·도구만 쓴다. 종료 사건에 이르면 거기서 멈춘다.
6. 운영 명령. `pnpm world:accelerate --world <ID>`, `pnpm world:realtime --world <ID>`를 `controlWorld.ts`에 더한다. 기존 시계 명령처럼 월드 행을 잠그고 DB 시각과 `clockRevision` 조건으로 저장한다.
   `RUNNING`·`PAUSED`에서만 받고 `PREOPEN`·`ENDED`나 이미 같은 모드면 거부한다. 가속으로 바꿀 때는 그 순간까지의 realtime tick을 체크포인트한다. realtime으로 돌아갈 때는 저장된 tick을 그대로 두고 기준 시각만 지금으로 옮겨 tick이 튀거나 뒤로 가지 않게 한다.
   정지·재개는 모드를 바꾸지 않는다. `world:status` 출력에 `clockMode`, `endYear`, 종료했으면 결과를 더한다.
7. 시각 계산. `ACCELERATED`이거나 `ENDED`인 월드는 벽시계로 tick을 외삽하지 않는다. `checkpointClock`, 서버 `worldSummary`의 `nowTick`, `nextTurnAt`에 같은 규칙을 쓴다. 가속 중 `home.get.nextTurnAt`은 `null`이다.
8. 조회 계약(`apps/server`). `world.summary` 응답에 아래 필드를 더한다. 다른 필드는 그대로 둔다.

```ts
clockMode: 'REALTIME' | 'ACCELERATED';
endYear: number | null;
result: null | {
  reason: 'UNIFIED' | 'END_YEAR';
  year: number; // 종료 연월. END_YEAR는 endYear년 12월
  month: number;
  winner: null | { nationId: number; name: string; color: string };
  remainingNations: number;
  endedAt: string; // ISO UTC
};
```

`result`는 `status === 'ENDED'`이고 `WorldResult`가 있을 때만 값이 있다. 결과가 있으면 `gameDate`도 결과 연월로 맞춘다. 결과가 없는 `ENDED`(예전 수동 데이터)는 지금처럼 저장 tick으로 계산한다.
결과는 공개 정보다. 로그인한 사용자는 장수가 없어도 읽는다. 비공개 수치(국고·병력 등)는 넣지 않는다. `world.list`는 바꾸지 않는다(참가할 `RUNNING` 월드만).
9. 재생. 재생은 엔진과 같은 사건에서 같은 결과로 멈춘다. 기존 해시는 다시 쓰지 않는다.
   - 해시 대상: 월간 `stateHash`, 순수 재생의 `hashState(replay)`, `finalStateHash`는 모두 지금의 `ReplayState` 네 키를 해시한다. `loadReplayState`·`initialReplayState`의 반환 모양과 `WorldState`·`WorldInit`은 바꾸지 않는다. `endYear`는 `seasonOutcome`에, `{ endYear, outcomeFromSequence }`는 재생 함수에 따로 넘기는 인자다. DB 적재·순수 재생·월간 snapshot·최종 해시가 이 한 규칙을 같이 쓴다.
   - 보관 형식: `exportReplay`는 `version: 2`를 낸다. `origin`은 저장된 v1을 그대로 넣는다.

   ```ts
   interface ReplayArchiveV2 {
     version: 2;
     origin: ReplayOrigin; // version 1, 저장값 그대로
     config: { endYear: number | null; outcomeFromSequence: number };
     inputs: RecordedInput[]; // sequence가 내보내기 끝 번호 이하
     months: ReplayArchive['months']; // 지금과 같음
     end: null | {
       sequence: number; // WorldResult.endedSequence
       tick: number; // WorldResult.endedTick
       reason: 'UNIFIED' | 'END_YEAR';
       winnerNationId: number | null;
       year: number;
       month: number;
       finalStateHash: string;
     };
     afterEnd: RecordedInput[]; // end가 있을 때 종료 뒤 닫힌 생성 요청. 모두 REJECTED
   }
   ```

   - 내보내기 범위: `WorldResult`가 있으면 끝 번호는 `endedSequence`다. 마지막 정산 뒤부터 종료까지의 사람 입력(예턴 저장·장수 생성)이 `inputs`에 들어간다. 첫 정산 전에 끝났으면 `months`는 빈 배열이다. 끝 번호보다 큰 기록은 `afterEnd`로 따로 낸다. `REJECTED`가 아닌 기록이 있으면 내보내기를 거부한다. `WorldResult`가 없으면(진행 중이거나 예전 수동 `ENDED`) 지금처럼 마지막 월간 snapshot의 sequence까지이고 `end`는 `null`이다.
   - 읽기 허용 조합: archive v1 + origin v1은 지금 코드와 같은 월간 대조만 하고 종료 판정을 하지 않는다. archive v2 + origin v1은 아래 규칙을 쓴다. 그 밖은 모두 거부한다. 알 수 없는 archive 버전, origin이 v1이 아님, v1에 `config`·`end`·`afterEnd` 키가 있음, v2에 그 키 중 하나가 없음이 여기에 든다.
   - 종료 재생 `replayToEnd(archive)`(v2, `end` 있음)는 sequence를 1부터 하나씩 진행한다. 그 번호의 입력이 있으면 적용하고 없으면 `nextGameAction` 하나를 실행한다. 월 경계마다 지금처럼 snapshot 해시를 대조한다. `outcomeFromSequence`보다 큰 번호의 장수 턴·정산 뒤마다 `seasonOutcome`을 부르고 `end.sequence` 전에는 `null`이어야 한다.
     `end.sequence`에서 실행한 사건의 tick·종류(통일은 장수 턴 또는 정산, 종료 연도는 정산)·`seasonOutcome` 결과·연월이 `end`와 같고 `hashState(replay) === end.finalStateHash`이면 거기서 멈춘다. 다음 `nextGameAction`은 부르지 않는다. `afterEnd`는 번호가 `end.sequence`보다 크고 오름차순이며 모두 `REJECTED`인지 확인만 하고 상태에 적용하지 않는다.
   - 기존 `replayArchive(value, months)`는 v1·v2 모두 처음 `months`개월을 대조하는 지금 의미 그대로 둔다. v2에서는 대조 구간에도 같은 `seasonOutcome` 검사를 한다. `tools/replay.ts`에 `--to-end`를 더해 `replayToEnd`를 부른다.
10. 시험 도우미. T1-27의 Chromium 시험이 쓸 수 있게, 실제 `TurnLoop` 경로로 `ENDED` 월드를 만드는 도우미를 `apps/engine`에 둔다. 종료 연도 도달(승자 없음) 하나와 통일(승자 있음) 하나다.
    같은 도우미가 끝나기 전 상태도 돌려준다. REALTIME `RUNNING`이고 시작 연도와 종료 연도가 같아 가속하면 몇 초 안에 끝나는 월드다. T1-27이 이 월드로 모드 전환과 종료를 화면에서 본다.
    시험용 월드는 시작 연도와 같은 종료 연도, 통일 직전으로 만든 작은 도시 집합을 써도 된다. 이런 짧은 월드를 데모나 AC-M1-17 증거로 세지 않는다.

### 하지 않는 것

시나리오·전투·정산 수치를 바꾸지 않는다. NPC 수렴 보조를 운영 월드에 켜지 않는다(시뮬레이터 옵션 그대로).
관리자 화면에서 월드를 끝내는 기능, 상태를 직접 `ENDED`로 쓰는 운영 명령(`world:end`), 다음 기수 리셋, 명예의 전당은 만들지 않는다.
운영 중 턴 간격 변경, 가속 배율 선택(최대 속도 하나만), 성능 최적화도 하지 않는다. 성능은 재기만 한다. 5번의 배치 상한은 운영 루프의 메모리 경계이고 최적화가 아니다.
로비(M2 T2-03)와 프리셋(D5, T2-02)의 종료 조건 묶음은 이후 작업에서 이 필드를 쓴다.

### 접근

1. `seasonOutcome`과 단위 시험을 먼저 만든다. 시뮬레이터가 이 함수를 쓰게 바꾸고 `pnpm sim --seed 1 --repeat` 해시가 바뀌지 않는지 본다.
2. schema·migration을 만든 뒤 `world:create --end-year`와 `saveInitialWorld`를 고친다.
3. `TurnLoop.step`에 종료 판정과 종료 뒤 처리, 가속 목표 계산을 넣고 `poll`을 배치 반환으로 바꾼다.
4. `world:accelerate`·`world:realtime`과 시각 계산 규칙을 넣는다.
5. `world.summary`의 새 필드와 권한 시험을 만든다.
6. 재생 호환 fixture를 기본 코드로 먼저 만든 뒤 v2 재생·`replayToEnd`, 시험 도우미, 실제 PostgreSQL 시험, 처리량 측정을 마친다.

## 구현 기록 (Codex)

구현 기준은 main `b8f50740ae0d383013b4323d10c64c1f743b26af`다. 이 작업의 전용 `wt/t_eba6f2a6`에서 구현했다. 재생 어댑터·단위 시험은 별도 하위 에이전트에 맡겨 exact diff를 통합했다. 프론트 담당의 `3fd27e63af0664cf6da5d4c2b852d0c3e06203fb`는 `e2e/rankingSeed.ts` 두 호출에 `endYear: null`을 명시한 호환 변경만 통합했다. 화면은 고치지 않았다.

실제 Chromium에서 기존 CLI 호출의 `--end-year` 누락을 확인한 뒤 프론트 담당의 `cfeed486dca83f3bc438b994d3ed02dbdeca69b2`도 통합했다. `e2e/game.ts`의 시험 월드 생성에 명시 인자 `--end-year 300` 두 줄만 더했다. 첫 실패를 숨기거나 CLI 기본값으로 우회하지 않았다.

`seasonOutcome`을 규칙 패키지에 두고 엔진·재생·시뮬레이터에서 공유한다. 새 migration `20261023000000_world_outcome`은 기존 월드의 종료 연도를 null로 두며 `outcomeFromSequence`만 현재 사건 번호로 채운다. 종료 저장은 결정 사건의 트랜잭션과 펜싱 검사를 그대로 쓴다. 가속은 64step·250ms 폴링 배치이고 결과를 배치 사이에 쌓지 않는다. 감독은 종료한 자식의 정상 종료를 장애로 세지 않으며 종료 뒤 남은 생성 요청도 거부한다.

계획과 달라진 점은 수렴 보조 설명이다. 계획 담당의 t_f596b555 판단대로 하지 않는 것의 120행은 기존 기본 유지로 읽었다. 운영 엔진과 재생은 main과 같이 시작 50년 뒤 보조가 적용되며 이 옵션을 새로 켜거나 바꾸지 않는다. 기존 장기 v1 해시와 v2 계약을 보존한다. 처리량 출력의 잘못된 `convergence:false` 라벨은 `unchanged-engine-default`·`assistanceEligible:false`로 정정했다. 120행의 계획 본문은 바꾸지 않았다.

v1 fixture는 T1-26 전 기준 커밋에서 `apps/engine/test/generateReplayV1.ts`를 실행해 만들었다. 기준 checkout에 그 생성기만 복사한 뒤 `pnpm exec tsx apps/engine/test/generateReplayV1.ts`와 `pnpm exec prettier --write apps/engine/test/fixtures/replay-v1-b8f5074.json`을 실행한다. 생성기가 기준 커밋의 재생 두 파일·월간 fixture 일치를 먼저 검사한다. 기준 `77723bf`와 `b8f5074` 사이에도 이 세 파일의 diff는 없다. 12개월 마지막 골든 해시는 `d60ad5f09185a889fc64926efe4e367e1b909710b227e76e3005698e71d80a0b`이며 새 시험이 그대로 대조한다. 실제 PostgreSQL의 이전 schema 행을 새 migration에 통과시켜 초기·월간 해시·origin·장수 배치와 v2 내보내기를 대조하는 시험도 추가했다.

T1-27 도우미는 `apps/engine/test/seasonFixture.ts`다. `prepareSeasonWorld(db, 'END_YEAR' | 'UNIFIED')`가 REALTIME RUNNING의 `{ worldId, initial }`을 반환한다. 도우미 자체는 엔진을 시작하지 않는다. 이미 dev 감독이 도는 Chromium 환경에서는 선택 인자 `{ beforeStart }`에서 PREOPEN 월드의 리스를 먼저 얻고 관측 동안 갱신해 다른 엔진을 막는다. 두 로그인 계정이 REALTIME·ACCELERATED를 관측한 뒤 예약한 리스의 `TurnLoop`를 시작하거나 리스를 놓고 `runEngine`을 시작한다. 호출자가 `controlClock(..., 'accelerate')` 후 `runEngine`을 시작하면 같은 월드가 실제 경로로 끝난다. 즉시 끝난 fixture가 필요하면 `finishSeasonWorld(db, worldId)`가 전환·리스·TurnLoop·결과 조회까지 한다. 통일 fixture는 마지막 도시 공격 예턴을 사건 번호와 함께 기록하고 종료 연도 fixture는 장수 없이 12개월을 정산한다. 둘 다 짧은 시험 전용이며 데모 증거가 아니다.

실제 DB 처리량은 [테스트 정책의 T1-26 측정](../testing-policy.md#t1-26-실제-db-가속-측정)에 환경·원본 실행 링크·두 달 재생 해시와 함께 기록했다. 장수 턴/초는 14.798, 개월/분은 3.351이다. 300년 말까지 같은 처리율을 선형 환산하면 23637.872초이나 실제 완주 보장은 아니다. 수치·종료 연도·규칙은 바꾸지 않았다.

코드 head `562241952df6ef4b39fd741ce71fd1f4c77ea4cd`의 [PR CI 39843885241](https://github.com/peppone-choi/opensamguk/actions/runs/39843885241)에서 `pnpm check`(단위 563개, 82파일), 실제 PostgreSQL·HTTP 359개(22파일), Chromium 75개, 웹 빌드가 통과했다. 원본 로그의 `EXPECTED_SHA`와 테스트 수를 대조했다. 문구 검사는 209파일에서 S1 0건이다. 통합 실행은 `pnpm test:authz`가 `pnpm test:int` 전체와 AUTHZ 대조(23절차·97실행·18면제·누락0)를 함께 돌린 결과다. skip·flaky는 없다. 로컬 설치는 공유 자원 admission의 exit 75라 우회하지 않았다.

종료 연도·통일 각각의 원자적 저장·beforeCommit 롤백·commit 전후 SIGKILL과 새 펜싱, 종료 뒤 생성 거부·불변, API 입력을 끼운 종료 재생, 이전 DB migration, 가속 배치·리스 갱신·2초 정지·재시작, 실제 잠금 대기 중 API edit의 STALE와 재시도를 검증했다. 첫 정산 전 통일과 정산 뒤 사람 입력 통일, 12월 정산 종료의 최종 해시를 모두 DB 결과와 대조했다. 종료 확인용 다음 사건은 실행하지 않는다.

중간 실패는 수정하고 다시 실행했다. 초기 단위 fixture의 NPC 조기 통일과 기존 전투 12개월 fixture의 조기 종료를 분리했고 조회 응답의 예상 필드를 갱신했다. 이어 Chromium의 CLI 인자 누락은 프론트 담당이 고쳤다. 다중 월드 시험은 두 번째 종료를 늦게 감지해 epoch 시각을 주입한 다른 fixture로 넘어갔으므로 종료 배치 경계에서 중단하고 주입 월드는 PAUSED로 닫았다. 운영 tick 범위 검사는 바꾸지 않았다.

구현 단계를 리뷰로 넘긴다. 이 기록 뒤 문서·대기열만 바꾼 최종 head의 CI는 [PR155의 검사](https://github.com/peppone-choi/opensamguk/pull/155/checks)와 구현 카드의 exact-SHA handoff에서 확인한다. 반대쪽 리뷰·정상 병합은 아직 남았고 AC-M1-21은 T1-27과 독립 15분 같은 판 완주 뒤에 판정한다. 인수조건의 상태·증거 칸은 바꾸지 않았다.
