# T1-26 같은 판 가속과 기수 종료 판정·결과 저장·조회

> 대기열: T1-26 · AC: AC-M1-21 (데모의 가속·종료 부분) · 구현: Codex · 리뷰: Claude
> 선행: T1-09 · 후속: T1-27 (종료 화면), T1-18 (사람 완주 데모) · 근거: FR-WLD-04, FR-WLD-06, FR-ENG-07, [게임 시계](../architecture/game-clock.md)

## 계획 (Claude)

### 왜 생긴 작업인가

T1-18 사전 점검(main `77723bf`, CI [39741923516](https://github.com/peppone-choi/opensamguk/actions/runs/39741923516))에서 데모 뒷부분을 할 경로가 없다는 것을 확인했다.
실제 PostgreSQL의 1030·94도시·491명 월드를 300년 12월 정산 직전에 두고 `TurnLoop.advanceTo(13200000)`를 돌렸더니 정산은 됐지만 `status`는 `RUNNING`, `endedAt`은 `null`이었다.
`turnLoop.ts`는 시계만 저장하고 종료를 판정하지 않는다. 운영 명령은 `start/pause/resume/status`뿐이다.
`pnpm sim`은 사람 장수가 있으면 거부하므로 사람이 플레이한 판을 이어서 돌릴 수 없다. 조회 API에도 승자·종료 결과가 없다.
그 경계 탐침의 300년은 시뮬레이터 기본값을 빌린 합성 설정이다. 승인된 종료 연도가 아니다.

### 목표

사람이 플레이하던 같은 DB 월드를 운영 명령 하나로 가속하고 그 판이 천하통일이나 월드에 정한 종료 연도에 이르면 엔진이 한 트랜잭션으로 월드를 끝내고 결과를 남긴다.
화면은 `world.summary`에서 승자(없음 포함)와 종료 연월을 읽는다.

### 정한 것

A17은 PRD 가정 원장에서 아직 승인 전이다. 그래서 판정 방식은 A17 문장대로 만들되 연도 값은 코드에 넣지 않는다.

| 항목 | 정한 내용 |
| ---- | --------- |
| 종료 연도 위치 | 월드 설정 `World.endYear Int?`. 시나리오 리소스 1030에는 종료 연도가 없으므로 리소스에 새로 만들지 않는다 |
| 종료 연도 기본값 | 없다. `pnpm world:create`에 `--end-year <연도>`를 필수로 받는다. 시작 연도 이상 10000 이하 정수. 프로그램 API(`saveInitialWorld`)도 명시 인자로 받는다 |
| 기존 월드 | migration은 `endYear`를 `null`로 둔다. `null`이면 통일로만 끝난다. 저장된 `initialStateHash`와 `nextTurnTick`은 바꾸지 않는다 |
| 시뮬레이터 300 | `DEFAULT_SIMULATION_MAX_YEAR = 300`은 AC-M1-17 증거용 시뮬레이터 값으로만 남긴다. 운영 월드 기본값으로 쓰지 않는다 |
| 통일 | 시뮬레이터 `unifiedNation`과 같다. 국가가 하나만 남고 모든 도시를 그 국가가 가졌을 때다. 중립 도시가 남으면 통일이 아니다 |
| 통일 판정 시점 | 장수 턴 하나(그 턴의 국가 명령 포함)를 실행한 직후와 월간 정산 직후 |
| 종료 연도 판정 시점 | `endYear`년 12월 정산을 마친 직후. 같은 tick의 장수 턴은 정산 뒤에 도는 규칙이므로 종료한 월드에서는 그 턴을 실행하지 않는다 |
| 승자 | 통일이면 그 국가. 종료 연도 도달이면 `null`(승자 없음). 테스트 정책 §4의 시뮬레이터 결과 형식과 같다 |
| 종료 연월 | 결정한 사건의 게임 연월. 종료 연도 도달은 `endYear`년 12월이다. 12월 정산 tick은 다음 해 1월의 시작 tick이므로 시계에서 연월을 다시 계산하지 않고 결과 행에 저장한다 |
| 가속 방식 | 월드 시계 모드 `World.clockMode`(`REALTIME`·`ACCELERATED`)를 DB에 저장하고 운영 명령으로 바꾼다. 실행권을 가진 엔진(`pnpm dev`나 `engine:run`)이 그 모드를 읽는다. 별도 프로세스나 리스 인계가 필요 없다 |

가속을 별도 CLI 프로세스로 만들지 않은 이유가 있다. `pnpm dev`의 엔진이 실행권을 잡고 있으면 다른 프로세스는 리스를 얻지 못한다.
모드를 월드 행에 두면 지금 도는 엔진이 같은 `TurnLoop.step` 트랜잭션으로 가속한다. 리스·펜싱·정지·재개·월간 정산 순서가 그대로다.

### 범위

`packages/rules`, `packages/db`(schema, 새 migration), `apps/engine`, `apps/server`, 루트·엔진 `package.json`의 스크립트 두 줄, 채울 문서.

1. 규칙(`packages/rules`). 순수 함수 `seasonOutcome(state, { endYear, settled? })`를 둔다. `settled`는 방금 정산한 연월이다. 반환은 `null` 또는 `{ reason: 'UNIFIED' | 'END_YEAR', winnerNationId: number | null }`. `unifiedNation`을 이리로 옮기고 시뮬레이터·엔진·재생이 모두 이 함수를 쓴다. DB·시각·파일을 쓰지 않는다.
2. schema와 새 migration. `World.endYear Int?`, `World.clockMode WorldClockMode @default(REALTIME)`, 새 모델 `WorldResult`.
   `WorldResult`는 `worldId`(PK이자 World FK), `reason`, `winnerNationId Int?`, `winnerName String?`, `winnerColor String?`, `endedYear`, `endedMonth`, `endedTick`, `remainingNations`, `finalStateHash`, `endedAt`을 둔다. 승자 이름·색은 종료 시점 값을 복사해 둔다. 기존 migration 파일은 고치지 않는다.
3. 엔진 종료(`turnLoop.ts`). 장수 턴이나 월간 정산을 저장하는 같은 트랜잭션 안에서 `seasonOutcome`을 부른다. 결과가 있으면 같은 트랜잭션에서 `World.status = ENDED`, `endedAt = DB 시각`, `clockTick = 결정 tick`을 쓰고 `WorldResult`를 만든다.
   월드 갱신은 `status = RUNNING`과 `clockRevision` 조건으로 한다. `WorldResult`의 PK가 두 번째 종료를 막는다. commit 직전 리스 확인(`assertLease`)은 지금처럼 한다.
4. 종료 뒤 엔진. `ENDED` 월드에서는 장수 턴·정산·시계 저장을 하지 않는다. 종료 전에 받아 둔 `PENDING` 장수 생성은 상태를 바꾸지 않고 `REJECTED`로 닫는다.
   `runEngine`은 `ENDED`를 보면 실행권을 놓는다. `--world`를 지정했으면 종료 코드 0으로 끝내고 지정하지 않았으면 다음 `RUNNING` 월드를 찾는다.
5. 가속 모드. `ACCELERATED`인 `RUNNING` 월드에서는 `TurnLoop.step`이 벽시계 대신 다음 사건 tick(가장 이른 실행 대상 장수의 `nextTurnTick`과 다음 월 경계 중 작은 값)을 목표로 삼는다. 이 목표는 저장된 `clockTick`보다 작지 않다.
   사건 하나를 한 트랜잭션으로 저장하고 `clockAnchorAt`을 DB 시각으로 둔다. `poll`은 진행이 있는 동안 쉬지 않고 이어 가므로 100ms 대기 없이 최대 속도가 된다. `advanceTo`의 기존 동작은 바꾸지 않는다.
6. 운영 명령. `pnpm world:accelerate --world <ID>`, `pnpm world:realtime --world <ID>`를 `controlWorld.ts`에 더한다. 기존 시계 명령처럼 월드 행을 잠그고 DB 시각과 `clockRevision` 조건으로 저장한다.
   `RUNNING`·`PAUSED`에서만 받고 `PREOPEN`·`ENDED`나 이미 같은 모드면 거부한다. 가속으로 바꿀 때는 그 순간까지의 realtime tick을 체크포인트한다. realtime으로 돌아갈 때는 저장된 tick을 그대로 두고 기준 시각만 지금으로 옮겨 tick이 튀거나 뒤로 가지 않게 한다.
   정지·재개는 모드를 바꾸지 않는다. `world:status` 출력에 `clockMode`, `endYear`, 종료했으면 결과를 더한다.
7. 시각 계산. `ACCELERATED`이거나 `ENDED`인 월드는 벽시계로 tick을 외삽하지 않는다. `checkpointClock`, 서버 `worldSummary`의 `nowTick`, `nextTurnAt`에 같은 규칙을 쓴다. 가속 중 `home.get.nextTurnAt`은 `null`이다.
8. 조회 계약(`apps/server`). `world.summary` 응답에 아래 필드를 더한다. 다른 필드는 그대로 둔다.

```ts
clockMode: 'REALTIME' | 'ACCELERATED';
endYear: number | null;
result: null | {
  reason: 'UNIFIED' | 'END_YEAR';
  year: number; // 종료 연월. END_YEAR는 endYear년 12월
  month: number;
  winner: null | { nationId: number; name: string; color: string };
  remainingNations: number;
  endedAt: string; // ISO UTC
};
```

`result`는 `status === 'ENDED'`이고 `WorldResult`가 있을 때만 값이 있다. 결과가 있으면 `gameDate`도 결과 연월로 맞춘다. 결과가 없는 `ENDED`(예전 수동 데이터)는 지금처럼 저장 tick으로 계산한다.
결과는 공개 정보다. 로그인한 사용자는 장수가 없어도 읽는다. 비공개 수치(국고·병력 등)는 넣지 않는다. `world.list`는 바꾸지 않는다(참가할 `RUNNING` 월드만).
9. 재생. `ReplayState`와 재생 보관 형식이 종료 연도를 알게 한다. 재생은 같은 사건에서 같은 결과로 멈춘다. 저장된 `replayOrigin`·`initialStateHash`를 다시 쓰지 않도록, 종료 연도는 월드 행에서 읽어 보관 파일에 따로 넣는다(형식 버전을 올려도 된다).
10. 시험 도우미. T1-27의 Chromium 시험이 쓸 수 있게, 실제 `TurnLoop` 경로로 `ENDED` 월드를 만드는 도우미를 `apps/engine`에 둔다. 종료 연도 도달(승자 없음) 하나와 통일(승자 있음) 하나다.
    시험용 월드는 시작 연도와 같은 종료 연도, 통일 직전으로 만든 작은 도시 집합을 써도 된다. 이런 짧은 월드를 데모나 AC-M1-17 증거로 세지 않는다.

### 하지 않는 것

시나리오·전투·정산 수치를 바꾸지 않는다. NPC 수렴 보조를 운영 월드에 켜지 않는다(시뮬레이터 옵션 그대로).
관리자 화면에서 월드를 끝내는 기능, 상태를 직접 `ENDED`로 쓰는 운영 명령(`world:end`), 다음 기수 리셋, 명예의 전당은 만들지 않는다.
운영 중 턴 간격 변경, 가속 배율 선택(최대 속도 하나만), 성능 최적화도 하지 않는다. 성능은 재기만 한다.
로비(M2 T2-03)와 프리셋(D5, T2-02)의 종료 조건 묶음은 이후 작업에서 이 필드를 쓴다.

### 접근

1. `seasonOutcome`과 단위 시험을 먼저 만든다. 시뮬레이터가 이 함수를 쓰게 바꾸고 `pnpm sim --seed 1 --repeat` 해시가 바뀌지 않는지 본다.
2. schema·migration을 만든 뒤 `world:create --end-year`와 `saveInitialWorld`를 고친다.
3. `TurnLoop.step`에 종료 판정과 종료 뒤 처리, 가속 목표 계산을 넣는다.
4. `world:accelerate`·`world:realtime`과 시각 계산 규칙을 넣는다.
5. `world.summary`의 새 필드와 권한 시험을 만든다.
6. 재생과 시험 도우미, 실제 PostgreSQL 시험, 처리량 측정을 마친다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 규칙 | 단위 시험: 통일, 중립 도시가 남은 단일 국가, 종료 연도 12월 직전·직후, `endYear = null`이면 연도로 끝나지 않음 |
| 시뮬레이터 불변 | `pnpm sim --seed 1 --repeat`와 `--convergence off` 해시가 [T1-09 측정](../testing-policy.md#t1-09-측정)과 같다 |
| 종료 연도 단일 종료 | 실제 PostgreSQL: 종료 연도 12월 정산 한 트랜잭션에 정산·`ENDED`·`endedAt`·`WorldResult`가 함께 저장된다. 같은 tick 장수 턴은 실행하지 않는다 |
| 통일 단일 종료 | 실제 PostgreSQL: 마지막 도시를 얻는 장수 턴 한 트랜잭션에 턴 결과와 종료·결과가 함께 저장된다. 그 뒤 턴·정산이 없다 |
| 원자성 | `beforeCommit` 훅으로 종료 트랜잭션에서 오류를 내면 턴·정산·종료·결과가 모두 없다. 다시 돌리면 한 번만 끝난다 |
| SIGKILL | 엔진 자식 프로세스를 종료 commit 전·후에 `SIGKILL`하고 새 프로세스로 다시 띄운다. 결과 행 1개, 같은 턴 중복 0, 리스는 만료 뒤 더 큰 펜싱 토큰으로 다시 얻는다 |
| 같은 판 가속 | 실제 PostgreSQL: API로 예턴을 넣은 사람 장수가 있는 월드를 realtime으로 몇 턴 돌린 뒤 `world:accelerate`. 사람 예턴이 순서대로 실행되고 빈 칸은 휴식이 된다. 가속 중 `world:pause`면 tick이 멈추고 `world:resume` 뒤 이어 간다. `world:realtime` 뒤 tick이 뒤로 가거나 튀지 않는다 |
| 가속 중 편집 | 가속 중 `turns.set`·`turns.edit`가 revision 규칙대로 성공하거나 충돌을 돌려준다. 엔진의 턴 저장과 겹쳐도 잃는 편집이 없다 |
| 결정적 재생 | 같은 사람 입력으로 끝까지 간 월드의 `exportReplay`를 재생하면 최종 상태 해시와 결과(사유·승자·연월)가 `WorldResult.finalStateHash`와 같다 |
| 운영 명령 | 통합 시험: `PREOPEN`·`ENDED`·같은 모드 거부, 동시 명령의 `clockRevision` 충돌, 출력에 비밀값 없음 |
| HTTP 권한 | 실제 서버 시험: 무인증 `UNAUTHORIZED`, 잘못된 `worldId` `BAD_REQUEST`, 없는 월드 `NOT_FOUND`, 장수 없는 다른 사용자도 같은 결과를 읽고 비공개 수치는 없음, 정지된 계정은 기존 세션 규칙대로 거부 |
| 종료 뒤 입력 | 실제 서버 시험: 실제 엔진으로 끝난 월드에서 `turns.set`·`turns.edit`·`general.create`가 거부되고 DB가 바뀌지 않는다 |
| 처리량 | GitHub 표준 실행기의 실제 PostgreSQL에서 1030·94도시·491명 월드를 가속으로 일정 개월 돌려 장수 턴/초와 개월/분을 잰다. 정한 종료 연도까지의 예상 시간을 구현 기록에 적는다. 이 수치로 규칙이나 종료 연도를 바꾸지 않는다 |
| 전체 | `pnpm check`, `pnpm test:int`, exact head 필수 CI 통과 |

### 상대 영역에 필요한 것

T1-27이 위 `world.summary` 모양과 시험 도우미를 쓴다. 필드 이름을 바꾸면 이 계획과 T1-27 계획을 같이 고친다. 프론트는 `AppRouter` 타입만 import한다.

### 다른 작업과 겹치는 곳

`apps/engine/src/main.ts`와 Prisma schema는 T2-01(PR #66, 다중 월드 감독)도 고친다. 이 작업은 `main.ts`에서 종료 처리 몇 줄만 바꾸고 먼저 병합된 쪽 위로 다시 맞춘다. migration은 최신 main 위에 새 파일 하나로 만든다.
`packages/rules`의 명령 쪽은 PR #67 계열(전체 명령)이 고치지만 이 작업은 명령 파일을 건드리지 않는다.
