# T1-24 글쓰기 규칙 적용: 게임·서버 문구와 Codex 담당 문서

> 대기열: T1-24 · AC: AC-M1-22 · 구현: Codex · 리뷰: Claude
> 선행: T1-25 · 근거: [D-017](../product/decisions.md), [글쓰기 규칙](../writing-style.md)

## 계획 (Claude)

### 목표

플레이어가 읽는 게임 문구와 서버 오류 메시지, Codex 담당 문서를 [글쓰기 규칙](../writing-style.md)에 맞게 고친다.

### 범위

- 게임 문구: `packages/rules/src`의 명령 결과·실패 이유·로그 문구, 월간 정산 기록 문구
- 서버 문구: `apps/server/src`, `apps/engine/src`의 사용자에게 가는 오류 메시지와 CLI 출력
- 문서: `docs/architecture/`, `docs/developer/`, `docs/design/`, `docs/admin-console.md`, `docs/release-operations.md`, `docs/testing-policy.md`, `docs/numeric-state-policy.md`, `docs/image-assets.md`
- 앞으로 새 문구를 만드는 작업(T1-07~T1-09, T1-11, T1-12, T1-20)도 이 규칙을 따른다.

### 하지 않는 것

명령 이름·관직 이름 같은 고유명사, 로그에 들어가는 수치와 인물 이름. 골든 테스트의 기대 문자열은 문구만 바뀐 것이 확인될 때만 함께 고친다.

### 결정

- 로그 문구는 한 곳(문구 표)에 모아 두는 쪽이 고치기 쉽다. 이미 흩어져 있으면 이 작업에서 모으지 않고 제자리에서 고친다(범위 동결).
- 오류 메시지는 "무엇이 안 됐고, 무엇을 하면 되는지"를 한 문장으로 쓴다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| S1 0건 | `pnpm lint:text --strict` (Codex 담당 경로) |
| 동작 그대로 | `pnpm check`, `pnpm test:int` 통과 |
| 뜻 보존 | 리뷰어가 diff에서 수치·조건·고유명사가 바뀌지 않았는지 본다 |

### 채울 문서

구현하면서 함께 채운다. 리뷰어는 문서도 확인한다.

- 없음 (대상 문서 자체를 고친다)

## 구현 기록 (Codex)

- 바꾼 것: main `c1377a1`(T1-09·T1-11·T1-12·T2-22 반영)을 기준으로 담당 문서 12개의 연결어미 뒤 쉼표와 장식을 정리했다. 가정 ID와 확인·통과 여부는 글자로 남겼다. 이미지 라이선스의 위험 경고와 공개 전 관문은 유지했다. 수치·조건·서법·고유명사와 코드·URL·명령어는 바꾸지 않았다.
- 계획과 달라진 점과 이유: 게임·서버 문자열은 기존 S1이 0건이라 그대로 두었다. 로그 표를 만들거나 골든 문자열·API·계산·비용·확률·RNG·게임 상태 해시를 바꾸지 않았다. 도구의 `classify()`가 `apps/engine/src`를 대상에서 제외하므로 엔진 17파일은 같은 `lintSource()`에 `kind: code`, `koreanOnly: true`를 넘겨 따로 검사했다. 도구와 root `package.json`은 수정하지 않았다. 계획·리뷰 원문은 보존했고 예외 주석은 추가하지 않았다. phases와 AC 상태는 공유 문서 담당 및 독립 리뷰에 남겼다.
- 검증 결과:
  - 담당 경로의 `pnpm lint:text --strict`는 66파일에서 36건(C-5 12, C-11 24)이던 결과가 0건이 됐다. `docs/architecture`, `docs/developer`, `docs/design`과 지정 단일 문서 5개, `packages/rules/src`, `apps/server/src`를 검사했다. 이 명령에 엔진 경로도 주었으나 도구는 위 분류 때문에 엔진을 세지 않는다.
  - 엔진 직접 검사를 포함한 TypeScript 66파일(검사 도우미 `contracts.ts` 포함)의 한글 문자열·템플릿 조각 294개를 확인했다. rules 27파일·227개, server 22파일·21개, engine 17파일·46개이며 S1은 모두 0건이다. 66파일의 내용이 기준 main과 바이트 단위로 같아 명령 이름·실패 이유·로그·NPC 이유와 신규 순위 코드도 그대로다. 월간 정산 기록은 기존 수치 JSON 구조를 유지한다.
  - 수정 문서 12개에서 숫자열·인라인 코드·URL·펜스 코드 블록의 순서와 내용이 기존과 같았다. 변경 문자 비율은 SequenceMatcher 기준 최대 0.565%이며 `git diff --check`가 통과했다. 문구의 뜻 보존은 Claude가 별도로 리뷰한다.
  - 로컬 `pnpm install --frozen-lockfile`은 공용 메모리 예산 때문에 종료 코드 75로 중단됐다. 기존 의존성을 읽어 가벼운 문구 검사를 실행했으며 무거운 `pnpm check`와 실제 PostgreSQL 통합·월간 재생·SIGKILL 회귀는 GitHub 표준 실행기의 exact-head CI로 검증한다. skip이나 mock 결과를 통과로 세지 않는다.
