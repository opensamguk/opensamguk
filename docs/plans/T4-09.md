## 계획 (Claude)

### 목표

AC-P2-06: 특수 병종 연구 9종 가운데 승인된 병종은 연구를 마친 국가만 모병·징병한다. 기술·도시 조건이 맞지 않으면 사전 검사가 이유를 보인다. 연구 전 국가와 확장을 끈 월드는 기존 병종만 쓴다. 이 작업은 9종 가운데 보병·궁병·기병 계열 6종의 연구 명령, 병종 조건 검사, 모병·징병 연결, 그 병종을 담은 병종 판 몫이다. 귀병·차병 계열 3종은 [T4-10](./T4-10.md), 등록과 엔진 시험은 [T4-53](./T4-53.md)이다.

### 원작 동작

연구 명령 공통(`eventResearch.ts`):

| 순서 | 제약 | 문구 |
| ---- | ---- | ---- |
| 1 | 실행 장수 도시가 자기 국가 도시 | 아국이 아닙니다. |
| 2 | 관직 4 초과(수뇌 이상) | 수뇌가 아닙니다. |
| 3 | 연구 표식이 미완료 | `{이름}가 이미 완료되었습니다.` |
| 4 | 국고 금 ≥ 비용 | 자금이 모자랍니다. |
| 5 | 국고 쌀 ≥ 비용 | 군량이 모자랍니다. |

### 기술 계약 초안 (Codex 계획 기술 검토 전)

#### A. 조각 `research`

```ts
// ext/research/slice.ts
export type ResearchState = Record<string, string[]>; // 국가 id 문자열 → 마친 연구 이름(오름차순, 중복 없음)
export const RESEARCH_SLICE_KEY = 'research';
export const researchSlice: ExtSlice<ResearchState>;
```

- 연구 이름은 `greatsword`, `halberd`, `fire_arrow`, `repeater`, `mountain`, `elephant`(T4-10이 `ghost`, `dancer`, `fire_wheel`을 더한다)다. 명령 key의 `nation_research_` 뒤와 같다.
- `create`는 `{}`다. `validate`는 key가 양의 정수 문자열, 값이 알려진 연구 이름의 오름차순 중복 없는 배열인지 본다. T4-03 E7 저장 가능 검사를 rules 안에서 같은 규칙으로 한다.
- 원작은 연구 표식을 국가 메타에 숫자로 둔다. 우리는 마친 연구 이름 목록으로 둔다. 미완료는 목록에 없음이다.
- `slice.ts`는 명령 정의, `model/clone`, `commands/effects`를 import하지 않는다.

#### B. 병종 조건

`packages/rules/src/world/resources.ts`의 병종 항목에 선택 칸 하나를 더한다.

```ts
requirements: z.array(z.discriminatedUnion('kind', [
  z.strictObject({ kind: z.literal('research'), name: researchName }),
  z.strictObject({ kind: z.literal('tech'), min: natural }),
  z.strictObject({ kind: z.literal('city'), name, level: positive }),
  z.strictObject({ kind: z.literal('chief') }),
])).optional()
```

- `chief`는 T4-10의 화륜차가 쓴다. 이 작업은 스키마에만 둔다.
- 칸이 없으면 지금처럼 늘 고를 수 있다. 기본 판 `basic.json`에는 칸이 없으므로 모든 기존 월드의 모병·징병 결과가 같다.
- `ext/research/requirements.ts`의 `crewTypeFailure(view, general, unit): Failure | null`이 배열 순서대로 평가해 첫 실패를 낸다(원작 `isCrewTypeAvailable`과 같은 순서 규칙).

| 조건 | 통과 | 실패 code·문구 |
| ---- | ---- | -------------- |
| `research` | 장수 국가가 `view.ext?.research`에 그 연구를 가짐. 조각이 없으면 실패 | `BAD_STATE` `{병종 이름}은 연구를 마친 국가만 모집할 수 있습니다.` |
| `tech` | 장수 국가 `tech` ≥ `min` | `BAD_STATE` `기술이 부족합니다. (필요 {min})` |
| `city` | 장수 국가가 이름이 `name`인 도시를 가지고 그 도시 `level` ≥ `level` | `BAD_STATE` `{도시}을 규모 {level} 이상으로 가진 국가만 모집할 수 있습니다.` |
| `chief` | 장수 officerLevel ≥ 5 | `BAD_STATE` `수뇌만 모집할 수 있는 병종입니다.` |

- 문구의 조사는 구현 PR이 [글쓰기 규칙](../writing-style.md)에 맞춰 처리한다. 병종·도시 이름 뒤 조사를 피하는 쌍점 꼴도 된다.
- 재야 장수는 국가가 없으므로 `research`·`tech`·`city`가 모두 실패다. 지금 모병·징병은 `ownCity`가 먼저 재야를 거부하므로(`military.ts:12-13`) 이 함수까지 오지 않는다.

#### C. 모병·징병 연결

`commands/military.ts:16-17` 다음에 한 줄을 더한다.

```ts
const requirement = crewTypeFailure(view, general, unit);
if (requirement) return requirement;
```

- 검사 위치는 병종 확인 바로 뒤, 병종 교체·통솔·인구·금 검사보다 앞이다. 원작도 병종 선택 가능 여부를 먼저 본다.
- `defineCommand`가 `check`를 `precheck`로도 쓰므로(`support.ts:42-49`) 서버 사전 검사가 같은 이유를 보인다. 실행 때도 같은 검사를 다시 한다(원작 `che_징병.ts:427-430`과 같다).
- `military.ts`가 `ext/research/requirements.ts`를 import한다. `requirements.ts`는 `model/world` 타입과 조각 타입만 쓰고 명령 정의를 import하지 않으므로 순환이 없다.
- NPC 모병 판단(`npc/index.ts:118`)은 고치지 않는다. NPC가 조건 있는 병종을 고르면 같은 검사에서 실패한다(C11).

#### D. 연구 명령

```ts
// ext/research/makeResearch.ts
export function makeResearch(spec: {
  key: string;
  name: string;
  research: ResearchName;
  preReqTurn: 11 | 23;
  cost: number; // 금·쌀 각각
}): CommandDef;
```

- 안쪽 정의는 T4-06의 `defineStrategy`를 쓰지 않는다. 연구는 전략 기한·재사용 대기가 없다. 직책·자기 도시 검사는 같은 규칙을 이 파일에 둔다. T4-06 `base.ts`의 직책 검사 함수를 import해 쓸 수 있으면 그것을 쓴다(G-03에서 정한다).
- `check` = `precheck` 순서: 장수 없음 `NO_ACTOR` → 국가 없음 `NOT_NATION` → 현재 도시가 자기 국가 도시 아님 `NOT_OWN_CITY`(보급은 보지 않는다) → 직책 부족 `NOT_RULER` `수뇌만 실행할 수 있습니다.` → 이미 마침 `BAD_STATE` `{이름}는 이미 끝났습니다.` → 국고 금 < 비용 `NO_GOLD` `국고 금이 부족합니다.` → 국고 쌀 < 비용 `NO_RICE` `국고 쌀이 부족합니다.`
- `execute`: 국고 금·쌀 −비용, 실행 장수 경험·공헌 + 5 × (준비 턴 + 1), 조각에 연구 이름 추가(오름차순 유지). `cloneWorld` 뒤 `{ kind: 'world' }` 효과 하나다. 난수를 쓰지 않는다.
- 바깥은 T4-07 `withPrepare(def, { preReqTurn })`로 감싼다. 준비 칸마다 위 검사가 모두 돈다. 준비 중 국고가 비용 아래로 내려가면 그 칸은 실패하고 진행은 남는다(T4-07 P8).
- 문구는 원작을 옮기지 않고 새로 썼다. 로그 `{이름} 완료`, 국가 기록 `{이름} 완료: {장수}`.

#### E. 병종 판 `event` (PR 2)

- 기본 판 `basic`의 네 병종을 그대로 두고 여섯 병종을 원작 id(91100, 91102, 91201, 91202, 91301, 91302) 그대로 더한다. `id`·`name`은 `event`·`이벤트 병종`이다. `defaultCrewTypeId`는 기본 판과 같다.
- 각 병종의 `requirements`는 원작 JSON 순서를 따른다. 원작은 기술 → 도시 → 연구 순이다.
- `magicCoef`는 원작 값(여섯 모두 0)을 둔다.
- 원작 JSON을 옮기므로 파일 머리 주석을 둘 수 없는 JSON이면 `resources/NOTICE.md`에 출처 한 줄을 적는다.
- 연구 명령을 켠 프리셋과 이 판의 짝 맞춤은 [T4-53](./T4-53.md)이 확인한다(쟁점 Z5).
