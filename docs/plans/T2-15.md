# T2-15 배포·백업·오류 알림

> 대기열: T2-15 · AC: AC-M2-08, AC-M2-09, AC-M2-10 · 구현: Codex · 리뷰: Claude
> 선행: T2-01, **T2-19 (사용자: 배포 서버·도메인·디스코드 웹훅)** · 관련: [릴리스 운영](../release-operations.md), A13, NFR-09·10·14, FR-ADM-06

## 계획 (Claude)

### 목표

- 서버 1대에 명령 하나로 배포되고 이전 버전으로 되돌리기를 한 번 연습해 성공한다 (AC-M2-08).
- 매일 DB를 백업하고 백업으로 새 DB를 복구해 월드가 이어서 진행되는 것을 한 번 확인한다 (AC-M2-09).
- 서버·엔진 오류가 기록되고 엔진이 5분 넘게 멈추면 디스코드로 알림이 온다 (AC-M2-10).

### 범위

- `deploy/`: 운영 `compose.yml`(postgres, server, engine-supervisor, caddy), `Caddyfile`(게임 + 이미지 서버), `.env.production.example`
- Docker 이미지 2개: `server`(API + 빌드된 web 정적 파일), `engine` (감독 + 엔진)
- `tools/deploy.sh`, `tools/rollback.sh`, `tools/backup.sh`, `tools/restore.sh`
- 감시: `EngineHeartbeat`(T2-01)을 보는 server의 감시 작업 → 디스코드 웹훅
- 구조화 로그(pino) JSON, Docker 로그 회전

### 하지 않는 것

무중단 배포, 여러 서버, 외부 모니터링 서비스(M3 T3-11), 이미지 레지스트리 자동 빌드(CI).

### 결정

| 항목 | 결정 |
| ---- | ---- |
| 배포 | `tools/deploy.sh <git-ref>`: 로컬에서 이미지 빌드 → 태그 `<날짜>-<커밋 7자리>` → 서버로 전송(`docker save | ssh docker load`) → `prisma migrate deploy` → compose 재시작 → `/healthz` 확인 |
| 되돌리기 | `tools/rollback.sh <태그>`: 이전 태그로 compose 재시작. **migration이 있는 배포는 되돌리기 전에 백업 복구가 필요**함을 스크립트가 경고 |
| 백업 | 매일 04:00 `pg_dump -Fc` → 서버 볼륨 + 외부 복사본 1곳(사용자가 T2-19에서 정함). 7일 보관 (NFR-14, 가정) |
| 복구 리허설 | `tools/restore.sh <파일>`이 새 DB에 복구 → 엔진을 그 DB로 띄워 1개월 진행 → 해시 확인. 결과를 [릴리스 운영](../release-operations.md)에 기록 |
| 알림 | 엔진 지연 5분 초과, 엔진 반복 크래시, server 5xx 비율 급증 → 디스코드 웹훅. 같은 알림은 30분에 한 번 |
| 비밀값 | `.env.production`은 서버에만. 웹훅 주소·DB 비밀번호를 저장소·로그에 남기지 않는다 |
| HTTPS | Caddy 자동 인증서. Cloudflare는 DNS(+선택적 프록시) (A13) |

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 배포 | 실제 서버: `deploy.sh` → `/healthz` 200, 로비 열림 |
| 되돌리기 | 실제 서버: 다음 버전 배포 → `rollback.sh` → 이전 버전 동작 (리허설 기록) |
| 백업·복구 | 실제 서버: 백업 파일로 새 DB 복구 → 월드 1개월 진행 성공 (리허설 기록) |
| 알림 | 실제 서버: 엔진 컨테이너 정지 → 5분 뒤 디스코드 알림 1건, 재시작 뒤 회복 알림 |
| 비밀값 | 저장소 grep: 웹훅·비밀번호 없음 |

### 이미지 서버 (D-016, 2026-10-20 추가)

- 이미지 저장소 `peppone-choi/opensamguk-images`를 서버에 받아 두고 Caddy가 `img.<도메인>` 아래에서 **읽기 전용**으로 제공한다.
  저장소 루트·`.git`·목록 보기는 노출하지 않는다 (core2026 `devsam/image`와 같은 원칙).
- 갱신: `tools/deploy.sh`가 `.env.production`의 `IMAGE_REPO_COMMIT`에 고정된 커밋으로 맞춘다 (fast-forward만). 웹훅 자동 갱신은 하지 않는다.
- 캐시: 초상 경로는 바뀌지 않으므로 `Cache-Control: public, max-age=31536000, immutable`. Cloudflare 앞단.
- 화면 빌드의 `VITE_IMAGE_BASE_URL`을 이 주소로 둔다.
- 검증 추가: 이미지 서버에서 초상 3종 200, `/.git/` 404, 목록 보기 404, 캐시 헤더 확인.
