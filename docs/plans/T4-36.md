## 계획 (Claude)

### 목표

로그인한 사용자가 기록 화면의 영토 재생 탭에서 월드의 달별 도시 소유를 오래된 달부터 차례로 본다. 재생·정지·이전·다음으로 달을 옮긴다. 각 달의 국가는 그 달에 저장된 이름과 색으로 그린다. 그 뒤 멸망해 국가 행이 지워졌거나 이름·색이 바뀐 국가도 마찬가지다. 저장되지 않은 값은 지어내지 않는다. 두 달의 소유 차이로 건국·멸망·전투 같은 사건을 만들지 않는다.

## 2. 화면 계약

### 2.1 진입

- 주소는 `/w/$worldId/records?tab=timelapse`, 탭 이름과 패널 제목은 영토 재생이다. 위쪽 메뉴의 기록에서 탭으로 간다. 메뉴 줄은 늘리지 않는다.
- `worldRoute`의 로그인 가드를 그대로 쓴다. 장수 없는 계정도 본다(T4-35 2.7).
- `RecordsPage`는 `tab === 'timelapse'`이면 `<Panel title="영토 재생">` 안에 `RecordList` 대신 `<TimelapsePanel key={worldId} worldId={worldId} />`를 낸다. `key`로 월드가 바뀌면 상태를 모두 버린다. 머리글은 탭 항목 이름으로 `기록 · 영토 재생`이 된다.

### 2.2 불러오기

- `TimelapsePanel.tsx`는 두 부품이다. `TimelapsePanel({ worldId })`는 연결만 한다. `fetchPage = (input, { signal }) => trpcClient.timelapse.frames.query(input, { signal })`, 키 `[...trpc.timelapse.frames.queryKey({ worldId }), 'pages']`, `useWorldMap(worldId)`를 `TimelapseScreen`에 넘긴다. `TimelapseScreen({ worldId, fetchPage, queryKey, map, retry })`이 상태를 고르고 그린다. 단위 시험은 `TimelapseScreen`에 주입한 `fetchPage`와 지도 결과를 넣는다(U14).
- 받는 것은 기존 `useTimelapsePages`다. 첫 요청은 `{ worldId }`, 다음은 `{ worldId, cursor: nextCursor }`이고 strict 입력이라 다른 칸을 넣지 않는다. 첫 페이지가 오면 `nextCursor`가 `null`이 될 때까지 한 번에 한 요청씩 이어 받는다. 받은 만큼 바로 재생할 수 있고 상태 줄에 `N개월 불러옴`을 보인다.
- 응답 타입은 `inferRouterOutputs<AppRouter>['timelapse']['frames']`다. `useTimelapsePages`와 `joinPages`를 페이지 타입 인자 `P extends TimelapsePage`로 일반화해 이은 프레임에 `nations`가 남게 한다. `TimelapseScreen`은 그 타입 인자에 `items[number]`가 2.3의 `SavedFrame`이어야 한다는 제약을 건다. 서버 응답 모양이 바뀌면 웹 typecheck가 깨진다.
- 캐시 정책은 이 쿼리에만 건다. 1차의 `TIMELAPSE_CACHE`(`staleTime: Infinity`, `gcTime: 0`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`)와 `signal` 소비에 `enabled: (query) => query.state.data === undefined`를 더한다. 다른 지도·기록 캐시와 공유 훅은 건드리지 않는다.
  - `enabled`는 SSE `ready` 때문에 더한다. `ready`는 연결·재연결 때마다 `invalidateQueries()`로 화면의 모든 쿼리를 무효화한다(1절). TanStack Query 5.104.5에서 이 호출의 기본 `refetchType: 'active'`는 관찰자의 `enabled`가 false가 아닌 쿼리만 다시 받는다. 첫 페이지가 온 뒤 이 쿼리는 비활성이라 무효 표시만 되고 다시 받지 않는다. 이어 받기는 `fetchNextPage`라 `enabled`와 관계없이 돈다. 첫 페이지를 기다리는 동안의 무효화는 진행 중 요청에 합쳐진다. 첫 페이지 오류 뒤 다시 시도는 `refetch()`라 역시 돈다. 이 동작은 실제 `QueryClient`로 U13이 확인한다. U13이 실패하면 이 방식을 버리고 부모에게 알린다.
  - 보는 동안: 창 포커스·네트워크 재연결·SSE `ready`·`GameLayout`의 0초 무효화(`records` 키만)·`monthly.done`(`world.map`만) 어느 것도 이 쿼리를 다시 받게 하지 않는다. 지도 좌표는 다시 받을 수 있으나 도시 이름·좌표·연결만 쓰므로 재생 위치는 그대로다.
  - 패널이 사라질 때(다른 탭, 다른 화면, 월드 전환): 관찰자가 0이 된다. `signal`을 소비한 진행 중 요청은 취소되고 데이터는 되돌려진다(`@tanstack/query-core` `Query.removeObserver`). `enabled`와 관계없다. `gcTime: 0`이라 캐시 항목도 바로 지운다.
  - 다시 열 때: 캐시가 없어 `enabled`가 참이고 첫 페이지부터 새로 받는다. 그래서 탭을 다시 열면 그 사이 정산된 달이 나오고 E10에서 돌아온 월드도 다시 받는다(U10, E13).
- 재시도는 기록 조회와 같은 `retryUnlessClientError`다. 클라이언트 오류는 다시 묻지 않고 그 밖은 한 번 더 묻는다. 시험만 `false`를 넘긴다.
- 계약 위반을 숨기지 않는다. 페이지를 이은 프레임의 tick이 엄격히 오름차순이 아니거나 `nextCursor`가 그 페이지 마지막 tick과 다르면 이어 받기를 멈추고 오류 줄을 보인다. 정렬해서 덮지 않는다(1차 그대로).

### 2.3 국가 표시값의 출처

화면은 프레임의 도시 소유 `nationId`마다 표시값을 1차의 `NationDisplaySource`(`frames.ts:21-28`)로만 묻는다. 그리는 부품은 값이 어디서 왔는지 모른다. 구현은 새 `displaySource.ts`의 하나뿐이고 응답의 `items[].nations`에 묶는다.

```ts
// apps/web/src/timelapse/displaySource.ts
export interface SavedFrame {
  tick: number;
  nations: readonly StoredNation[]; // 응답 items[].nations. StoredNation은 frames.ts의 { id, name, color }
}
// 이은 프레임만 받는다. currentNations와 지도의 nations는 인자로 들어갈 자리가 없다.
export function savedNationSource(frames: readonly SavedFrame[]): NationDisplaySource;
```

| `resolve(frameTick, nationId)`의 입력 | 결과 |
| ------------------------------------- | ---- |
| `nationId === null` | `empty` |
| tick이 `frameTick`인 프레임의 `nations`에 그 id가 한 번 있다 | `stored`. 그 항목의 `name`·`color`를 고치지 않고 쓴다 |
| 그 프레임의 `nations`에 그 id가 없다 | `missing`. 다른 프레임, `currentNations`, 지도 `nations`, `RemovedNation`에서 찾지 않는다 |
| 같은 프레임의 `nations`에 같은 id가 둘 이상이다 | `missing`. 서버 계약 위반이라 하나를 고르지 않는다 |
| 받은 프레임에 그 tick이 없다 | `missing` |

- 열쇠는 그 프레임의 tick이다. 같은 국가가 프레임마다 다른 이름·색이면 프레임마다 자기 값이다. 멸망해 지금 행이 없는 국가도 그 프레임에 저장된 값으로 그린다.
- 이름과 색을 만들지 않는다. 기본값, `국가 N` 같은 대체 이름, 회색 등 대체 색을 두지 않는다.
- `currentNations`는 `TimelapsePanel`·`TimelapseScreen`이 읽지 않는다. 화면이 지금 이름을 따로 보여 줄 필요가 이 작업에 없다.
- `missing`은 제품 표시 정책이 아니라 자료 오류로 다룬다(부모 기술 수용, D-027, T4-56 7절 Q1). 소유 국가 가운데 하나라도 `missing`이면 기존 `frameView`가 그 프레임 전체를 그리지 않는다. 가짜 이름·색, 회색 지도, 일부만 그린 지도를 내지 않는다. 지도 자리에 1차의 기록 없음 표시(`이 시점의 국가 기록이 없습니다.`, `다른 달을 골라 주세요.`, 날짜 줄의 `국가 기록 없음`)를 그대로 쓴다. 다른 정상 프레임은 그대로 재생·탐색된다. 사용자가 철회한 회색안을 다시 쓰거나 다시 묻지 않는다.

### 2.4 그리기

- 도시 점의 채움은 `stored`면 그 색, `empty`면 `#d6d0c4`(지도와 같음)다. `missing`이 있는 프레임은 지도를 그리지 않는다(2.3).
- 도시 점의 크기는 하나로 고정한다. 지금 `level`과 보급으로 그리면 과거 상태처럼 보인다.
- `world.map`에 있으나 프레임에 없는 도시는 점선 빈 원과 `기록 없음`으로, 프레임에 있으나 지도에 없는 도시는 그리지 않고 상태 줄에 `지도에 없는 도시 N곳`을 적는다. 지금 엔진(`buildYearbook`)은 모든 도시를 담으므로 두 경우 모두 자료 이상이다.
- 지도 아래 범례는 이 달의 국가별 도시 수다. 많은 순, 같으면 id 순. 공백지도 글자로 센다. 기록 없는 프레임에는 범례도 없다.
- 지도 위 안내 한 줄: `국가 이름과 색은 그 달에 기록된 값입니다.`
- 국력·국고·군량·장수 수는 그리지 않는다. 응답에도 없다.

### 2.5 재생

- 처음 상태는 가장 오래된 달, 정지.
- 버튼은 처음, 이전, 재생(누르면 정지로 바뀜), 다음. 그리고 `input type="range"` 재생 위치. 처음·이전은 첫 달에서, 다음은 받은 마지막 달에서 막는다.
- 재생은 1초에 한 달 앞으로 간다. 받은 마지막 달에 닿았을 때 더 받을 페이지가 있으면 그 자리에서 기다리고 `다음 기록을 불러오는 중`을 보인다. 더 없으면 정지한다. 마지막 달에서 재생을 누르면 첫 달부터 다시 한다.
- 이전·다음·위치 조작은 재생을 멈춘다.
- 타이머는 `setInterval` 하나이며 정지·언마운트·월드 전환 때 지운다. 게임 시드 RNG와 관계없다.

### 2.6 월드 전환과 취소

`worldId`가 바뀌면 `key`로 패널이 다시 만들어져 재생 위치·타이머·불러온 프레임이 모두 사라진다. 이전 월드 쿼리는 관찰자가 0이 되므로 `signal`을 소비한 진행 중 요청이 취소되고(`@tanstack/query-core` 5.104.5 `query.js` `removeObserver`의 `cancel({ revert: true })`) `gcTime: 0`으로 캐시도 지워진다. 키에 `worldId`가 있어 새 월드 화면에 섞이지 않는다. 월드가 바뀌면 SSE가 새로 이어져 `ready`가 오지만 2.2의 `enabled` 정책 때문에 새 월드의 재생 쿼리는 첫 페이지 뒤 다시 받지 않는다.

### 2.7 상태

| 상황 | 화면 |
| ---- | ---- |
| 첫 페이지 대기, 지도 대기 | `LoadingState` (`role="status"`) |
| 프레임 0개 | `EmptyState` `영토 기록이 아직 없습니다. 월간 정산 뒤에 쌓입니다` |
| 첫 페이지 `NOT_FOUND`·`BAD_REQUEST` | `QueryError`의 `월드를 찾을 수 없습니다`. 재시도 없음 |
| 첫 페이지 그 밖의 오류 | `QueryError`의 `ErrorState` `불러오지 못했습니다`와 다시 시도. 누르면 `refetch()`로 `{ worldId }`부터 다시 받는다 |
| 이어 받기 오류 | 받은 달은 그대로 재생하고 아래에 `다음 기록을 불러오지 못했습니다.`와 다시 시도 |
| 지도 조회 오류 | `QueryError`. 좌표 없이 프레임만 그리지 않는다 |
| 이 프레임의 국가 기록 없음 | 지도와 범례 대신 `이 시점의 국가 기록이 없습니다. 다른 달을 골라 주세요.` 조작은 그대로이고 재생도 다음 달로 넘어간다. 날짜 줄에도 같은 사실을 붙인다 |
| 세션 만료 | 다음 화면 이동 때 기존 가드가 로그인으로 보낸다. 패널 안에서는 오류 줄이다 |

### 2.8 접근성

- 지도 `svg`는 `role="img"`, `aria-label`은 `190년 3월 영토 지도, 도시 94개`. 도시 점은 포커스를 받지 않고 `<title>`에 `도시 이름, 국가 이름`을 둔다.
- 범례가 글자 대체물이다. 색만으로 뜻을 전하지 않는다.
- 날짜 줄 `190년 3월 (12/35)`은 정지 상태에서 `aria-live="polite"`, 재생 중에는 `aria-live="off"`. 1초마다 읽어 주지 않는다.
- 재생 버튼의 이름은 상태에 따라 재생·정지로 바뀐다. 모든 조작은 기본 `button`·`range`라 키보드로 된다. 재생 중에도 포커스를 옮기지 않는다.

| U13 | 전체 무효화 (실제 `QueryClient`, 주입한 `fetchPage`) | 첫 페이지를 받은 뒤 `invalidateQueries()`를 불러도 `fetchPage` 호출 수가 같다. 둘째 페이지를 받는 중에 부르면 그 요청의 `signal`이 abort되지 않고 첫 페이지 요청이 다시 가지 않으며 끝나면 35개다. 첫 페이지를 기다리는 중에 부르면 요청은 하나뿐이다. 그 뒤에도 떼고 다시 붙이면 첫 페이지부터 받는다(U10 그대로) |
| U14 | `TimelapseScreen` 상태 (실제 `QueryClient`, 주입한 `fetchPage`·지도 결과, `retry: false`) | 첫 페이지 대기와 지도 대기는 `role="status"`. 첫 페이지 `NOT_FOUND`(서버 오류 모양의 `TRPCClientError`)는 `월드를 찾을 수 없습니다`이고 다시 시도가 없다. 그 밖의 첫 페이지 오류는 `불러오지 못했습니다`와 다시 시도이고 누르면 같은 입력 `{ worldId }`로 한 번 더 불러 첫 달 지도가 나온다. 빈 응답은 빈 상태 문구다. 35개 두 페이지는 입력이 `{ worldId }`, `{ worldId, cursor: '300000' }` 순서로 정확히 두 번이고 `35개월 불러옴`이다. 둘째 페이지 오류는 30개월이 재생되고 `다음 기록을 불러오지 못했습니다.`가 보이며 다시 시도 뒤 35개월이다. 지도 오류는 `QueryError`이고 `svg`가 없다. 국가 2가 프레임 `nations`에 없고 `currentNations`에만 있으면 그 프레임은 기록 없음이고 그 이름이 화면 어디에도 없다. 국가 1의 프레임 저장 이름·색과 다른 `currentNations` 값이 있으면 도시 `title`·범례·점 채움은 저장 값이다. 둘째 페이지 중 언마운트하면 그 `signal`이 abort된다 |

단위 시험은 실제 HTTP와 Chromium 증거를 대신하지 않는다. U14는 `TimelapsePanel.tsx`를 import하므로 `../trpc`도 함께 읽힌다. 네트워크는 열지 않고 `fetchPage`만 부른다.

### 4.2 Chromium 통합 E2E (`e2e/timelapse.spec.ts`, 이번에는 준비만)

이번 구현은 두 E2E 파일을 쓰고 정적 검사(4.3)만 한다. PostgreSQL, 브라우저, `pnpm e2e`, `pnpm check` 전체, 설치, 외부 요청은 허가되지 않았다. 실행은 사용자 허가나 CI에서 하며 그 전에는 E1~E13 어느 것도 증거가 아니다.

실제 웹·API·PostgreSQL을 쓴다. `page.route`로 응답을 지어내거나 실제 경로를 응답 mock으로 바꾸지 않는다. 지연이 필요한 E9·E10만 실제 요청을 잡아 둔다. E9는 그대로 흘려보내고(`route.continue`) E10은 화면이 그 요청을 끊는지 본다.

실행 환경은 `timelapseSeed.ts`의 worker fixture다. `publicMapFixture.ts`와 같은 틀을 이 파일에 새로 쓰고 기존 fixture는 고치지 않는다.

- `e2eDatabaseUrl()`로 원래 주소가 `_test` DB인지 확인하고 같은 서버에 `e2e_timelapse_<randomUUID의 하이픈을 뺀 32자>_test`를 만든다. 이름은 `/^e2e_timelapse_[0-9a-f]{32}_test$/`로 다시 검사한다. 있는 DB는 지우거나 비우지 않는다.
- migration은 `packages/db`의 prisma CLI 진입 파일을 `execFile(...nodeCli(prismaEntry, ['migrate', 'deploy']), { cwd, env })`로 실행한다. `tools/node-cli.ts`의 `nodeCli`라 셸과 `pnpm.cmd`를 띄우지 않는다. 다른 자식 프로세스가 필요하면 같은 `nodeCli`·`pnpmCli`를 쓴다.
- worker 안에서만 `DATABASE_URL`·`TEST_DATABASE_URL`을 자기 DB로 바꾸고 끝에 되돌린다. 파일은 `test.describe.configure({ mode: 'serial' })`이고 다른 파일과 worker를 나누지 않는다.
- API는 `buildServer({ db, logging: false, publicOrigin: webOrigin, realtime: { connectionString } })`를 포트 0으로 띄운다. 웹은 apps/web의 vite를 빈 포트와 `strictPort`, `/trpc`·`/sse` 프록시로 띄우고 의존성 캐시는 `mkdtemp(tmpdir(), 't4-36-vite-')`에 둔다. `baseURL` fixture를 자기 웹 출처로 바꾼다. 3001·5173 서버와 공용 DB 행은 쓰지 않는다.
- 감독 엔진은 띄우지 않는다. 월드를 움직이는 것은 준비 단계의 `TurnLoop`뿐이다. 준비가 끝나면 시계를 멈추고 리스를 놓아 시험 중 상태가 바뀌지 않는다.
- 계정은 `createAccount`로 자기 DB에 만들고 그 쿠키를 지운 뒤 자기 웹 출처의 로그인 화면으로 들어간다(`publicMap.spec.ts`와 같음). 실제 인증 경로를 탄다.
- 서버의 `/sse`는 월드 상태를 보지 않지만 그 월드에 로그인한 계정의 `General`이 없으면 404로 닫는다(`apps/server/src/realtime/index.ts:247-251`). PREOPEN이어도 장수가 있으면 열린다. 그래서 SSE가 필요한 E2는 시험 중에 A의 주인 없는 준비 장수 하나를 그 계정에 맡기고 끝에 되돌린다. 서버와 훅은 고치지 않는다.
- 정리 순서는 고정이다. Vite 닫기, API 닫기, DB 연결 끊기, 환경 변수 되돌리기, 자기 Vite 캐시 폴더 지우기(임시 폴더 바로 아래이고 접두사가 맞을 때만), 자기 DB 연결이 0이 될 때까지 짧게 기다린 뒤 0일 때만 `DROP DATABASE`, 관리 연결 끊기 순이다. 단계마다 성공 여부를 `test-results/t4-36-fixture-cleanup.json`에 남기고 연결 문자열은 남기지 않는다. 본 실패를 먼저 던지고 없으면 정리 실패를 던진다. 시험이 바꾼 행은 그 시험의 `finally`에서 되돌린다. 자기 DB만 지우므로 공용 자원에 닿는 정리는 없다.

월드 준비는 fixture가 시험 전에 한 번 한다. 모든 월드는 `apps/engine/test/warFixture.ts`의 두 국가·네 도시 장면에 `nationArchive.integration.test.ts:33-40`과 같은 경계 도시를 더해 `saveInitialWorld`로 저장한다. A·B·C·M은 PREOPEN이고 프레임은 DB 준비로 넣는다. `YearbookSnapshot`은 tick `10000 × (k + 1)`, `data`는 그 월드 실제 `City` 키의 `{ cities }`, `sequence`·`stateHash`는 준비용 값이다. 같은 tick의 `YearbookNation`에는 그 프레임 소유 국가의 행을 넣는다. 스냅샷과 저장 행은 DB 준비이며 응답 mock이 아니다. P만 실제 엔진으로 저장한다.

### 4.3 증거로 인정되는 것

지금 돌릴 수 있는 검사다. DB, 브라우저, 네트워크가 필요 없다. 구현 뒤 Claude가 돌리고 Codex가 같은 명령으로 다시 확인한다.
