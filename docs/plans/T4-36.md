## 계획 (Claude)

### 목표

로그인한 사용자가 기록 화면의 영토 재생 탭에서 월드의 달별 도시 소유를 오래된 달부터 차례로 본다. 재생·정지·이전·다음으로 달을 옮긴다. 각 달의 국가는 그 달에 저장된 이름과 색으로 그린다. 그 뒤 멸망해 국가 행이 지워졌거나 이름·색이 바뀐 국가도 마찬가지다. 저장되지 않은 값은 지어내지 않는다. 두 달의 소유 차이로 건국·멸망·전투 같은 사건을 만들지 않는다.

## 2. 화면 계약

### 2.1 진입

- 주소는 `/w/$worldId/records?tab=timelapse`, 탭 이름과 패널 제목은 영토 재생이다. 위쪽 메뉴의 기록에서 탭으로 간다. 메뉴 줄은 늘리지 않는다.
- `worldRoute`의 로그인 가드를 그대로 쓴다. 장수 없는 계정도 본다(T4-35 2.7).
- `RecordsPage`는 `tab === 'timelapse'`이면 `RecordList` 대신 `<TimelapsePanel key={worldId} worldId={worldId} />`를 낸다. `key`로 월드가 바뀌면 상태를 모두 버린다.

### 2.2 불러오기

- `pages.ts`의 `useTimelapsePages(worldId, fetchPage, queryKey)`가 `useInfiniteQuery`로 받는다. `fetchPage(input, { signal })`와 키는 주입받는다. 구현 준비 뒤에 `trpcClient.timelapse.frames.query`와 `[...trpc.timelapse.frames.queryKey({ worldId }), 'pages']`를 넘긴다. 첫 요청은 `{ worldId }`, 다음은 `{ worldId, cursor: nextCursor }`.
- 첫 페이지가 오면 `nextCursor`가 `null`이 될 때까지 한 번에 한 요청씩 이어 받는다. 받은 만큼 바로 재생할 수 있고 상태 줄에 `N개월 불러옴`을 보인다.
- 캐시 정책은 이 쿼리에만 건다. `staleTime: Infinity`, `gcTime: 0`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`, `queryFn`은 `signal`을 소비한다. 다른 지도·기록 캐시는 건드리지 않는다.
  - 보는 동안: 쿼리가 stale이 되지 않아 창 포커스·재연결·다른 무효화가 없으면 페이지를 다시 받지 않는다. `GameLayout`의 0초 무효화는 `records` 키만 건다.
  - 패널이 사라질 때(다른 탭, 다른 화면, 월드 전환): 관찰자가 0이 된다. TanStack Query v5는 `signal`을 소비한 진행 중 요청을 취소하고 데이터를 되돌린다. `gcTime: 0`이라 캐시 항목도 바로 지운다.
  - 다시 열 때: 캐시가 없어 첫 페이지부터 새로 받는다. 그래서 탭을 다시 열면 그 사이 정산된 달이 나오고 E10에서 돌아온 월드도 다시 받는다(U10, E13).
- 계약 위반을 숨기지 않는다. 페이지를 이은 프레임의 tick이 엄격히 오름차순이 아니거나 `nextCursor`가 그 페이지 마지막 tick과 다르면 이어 받기를 멈추고 오류 줄을 보인다. 정렬해서 덮지 않는다.
- 보존 조회가 T4-35 응답에 필드를 더하든 다른 절차로 오든 페이지 단위가 같으면 이 훅 하나에서 받는다. 다른 절차라면 같은 tick 범위를 같은 페이지 흐름으로 받는다. 어느 쪽인지는 보존 계약이 정한다.

### 2.3 국가 표시값의 출처

화면은 프레임의 도시 소유 `nationId`마다 표시값을 아래 인터페이스로만 묻는다. 그리는 부품은 값이 어디서 왔는지 모른다.

```ts
// apps/web/src/timelapse/frames.ts (지역 타입, 서버 계약이 아님)
type FrameNation =
  | { kind: 'empty' } // nationId === null, 공백지
  | { kind: 'stored'; id: number; name: string; color: string } // 그 프레임에 저장된 값
  | { kind: 'missing'; id: number }; // 그 프레임에 저장된 값이 없음
interface NationDisplaySource {
  resolve(frameTick: number, nationId: number | null): FrameNation;
}
```

- `stored`는 보존 계약이 그 프레임에 대해 낸 이름·색뿐이다. T4-56 원고는 프레임별 국가 목록을 응답에 더하는 안을 쓰고 있으나 기술 검토 전이라 이 문서는 필드 이름과 모양을 고정하지 않는다. 계약이 정해지면 `NationDisplaySource` 구현 하나를 그 필드에 묶는다.
- `currentNations`로 `stored`를 만들지 않는다. 지금 행 값은 과거 값이 아니다. 화면이 지금 이름을 따로 보여 줄 필요는 1차에 없으므로 `currentNations`는 그리기에 쓰지 않는다.
- `missing`은 제품 표시 정책이 아니라 자료 오류로 다룬다(부모 기술 검토 수용). 프레임의 도시 소유 `nationId` 가운데 하나라도 `missing`이면 그 프레임 전체를 그리지 않는다. 가짜 이름·색, 회색 지도, 일부만 그린 지도를 내지 않는다. 지도 자리에 `이 시점의 국가 기록이 없습니다.`와 다른 달을 고르라는 안내를 보인다. 다른 정상 프레임은 그대로 재생·탐색된다. 사용자가 철회한 회색안을 다시 쓰거나 다시 묻지 않는다.

### 2.4 그리기

- 도시 점의 채움은 `stored`면 그 색, `empty`면 `#d6d0c4`(지도와 같음)다. `missing`이 있는 프레임은 지도를 그리지 않는다(2.3).
- 도시 점의 크기는 하나로 고정한다. 지금 `level`과 보급으로 그리면 과거 상태처럼 보인다.
- `world.map`에 있으나 프레임에 없는 도시는 점선 빈 원과 `기록 없음`으로, 프레임에 있으나 지도에 없는 도시는 그리지 않고 상태 줄에 `지도에 없는 도시 N곳`을 적는다. 지금 엔진(`buildYearbook`)은 모든 도시를 담으므로 두 경우 모두 자료 이상이다.
- 지도 아래 범례는 이 달의 국가별 도시 수다. 많은 순, 같으면 id 순. 공백지도 글자로 센다. 기록 없는 프레임에는 범례도 없다.
- 지도 위 안내 한 줄: `국가 이름과 색은 그 달에 기록된 값입니다.`
- 국력·국고·군량·장수 수는 그리지 않는다. 응답에도 없다.

### 2.5 재생

- 처음 상태는 가장 오래된 달, 정지.
- 버튼은 처음, 이전, 재생(누르면 정지로 바뀜), 다음. 그리고 `input type="range"` 재생 위치. 처음·이전은 첫 달에서, 다음은 받은 마지막 달에서 막는다.
- 재생은 1초에 한 달 앞으로 간다. 받은 마지막 달에 닿았을 때 더 받을 페이지가 있으면 그 자리에서 기다리고 `다음 기록을 불러오는 중`을 보인다. 더 없으면 정지한다. 마지막 달에서 재생을 누르면 첫 달부터 다시 한다.
- 이전·다음·위치 조작은 재생을 멈춘다.
- 타이머는 `setInterval` 하나이며 정지·언마운트·월드 전환 때 지운다. 게임 시드 RNG와 관계없다.

### 2.6 월드 전환과 취소

`worldId`가 바뀌면 `key`로 패널이 다시 만들어져 재생 위치·타이머·불러온 프레임이 모두 사라진다. 이전 월드 쿼리는 관찰자가 0이 되므로 `signal`을 소비한 진행 중 요청이 취소되고(`@tanstack/query-core` 5.104.5 `query.js` `removeObserver`의 `cancel({ revert: true })`) `gcTime: 0`으로 캐시도 지워진다. 키에 `worldId`가 있어 새 월드 화면에 섞이지 않는다.

### 2.8 접근성

- 지도 `svg`는 `role="img"`, `aria-label`은 `190년 3월 영토 지도, 도시 94개`. 도시 점은 포커스를 받지 않고 `<title>`에 `도시 이름, 국가 이름`을 둔다.
- 범례가 글자 대체물이다. 색만으로 뜻을 전하지 않는다.
- 날짜 줄 `190년 3월 (12/35)`은 정지 상태에서 `aria-live="polite"`, 재생 중에는 `aria-live="off"`. 1초마다 읽어 주지 않는다.
- 재생 버튼의 이름은 상태에 따라 재생·정지로 바뀐다. 모든 조작은 기본 `button`·`range`라 키보드로 된다. 재생 중에도 포커스를 옮기지 않는다.

### 4.2 Chromium 통합 E2E (`e2e/timelapse.spec.ts`, `pnpm e2e`)

실제 `pnpm dev`(web·server·engine)와 `_test` PostgreSQL을 쓴다. `page.route`로 응답을 지어내지 않는다. 지연이 필요한 시험만 실제 요청을 잡아 두었다가 그대로 흘려보낸다(`route.continue`). E2E는 보존 저장·조회가 main에 병합된 뒤에만 증거가 된다. T4-35 병합 뒤 보존과 무관한 E1~E3, E7~E12를 미리 돌려 볼 수 있으나 증거로 세지 않는다.

준비(`timelapseSeed.ts create`): `saveInitialWorld`로 PREOPEN 월드를 만든다. PREOPEN이라 엔진 감독이 가져가지 않고 첫 RUNNING 월드를 쓰는 다른 시험에 닿지 않는다. 도시 소유 프레임은 각 월드의 실제 `City` 행으로 `YearbookSnapshot`을 넣는다(tick `10000 × (k + 1)`, `data`는 rules의 `Yearbook` 타입). 스냅샷 행은 DB 준비이며 응답 mock이 아니다.

과거 표시값의 준비 방법은 보존 계약에 따른다. 멸망 국가는 최소 하나가 실제 엔진 경로를 끝까지 거쳐야 한다. `rankingSeed.ts settled`처럼 `TurnLoop`를 직접 돌려 월간 정산이 프레임과 보존값을 저장하게 한다. 그 뒤 미리 예약한 출병 턴을 엔진이 실행해 마지막 도시를 잃은 국가가 `removeNation`(`packages/rules/src/commands/attack.ts:122`)과 행 삭제(`commandPersistence.ts:74`)로 실제 멸망하게 한다. 준비 모양은 백엔드 T4-56 S3(`warFixture`)과 같은 장면을 쓰고 그 시험과 함께 기능 전체를 증명한다. DB에서 행만 지우는 경우는 보조 시험(E4b)이며 이것만으로는 증거가 아니다. 보존 표에 손으로 넣은 행도 같다.

## 5. 반례와 처리

| 반례 | 처리 |
| ---- | ---- |
| 국가가 멸망해 지금 행이 없음 | 그 프레임에 저장된 값으로 그린다 (U2, E4) |
| 국가 이름·색이 나중에 바뀜(T4-16 뒤) | 옛 프레임은 저장된 옛 값이다. 지금 값으로 덮지 않는다 (U2, E5) |
| 프레임에 저장값이 없는 국가 | 자료 오류로 그 프레임만 막는다. 값을 만들지 않는다 (U3, E6) |
| 멸망한 국가 id를 새 국가가 다시 받음 | 생기지 않는다. `removeNation`이 `nextNationId`를 먼저 확정한다(T4-35 1절). 저장값도 프레임별이라 섞이지 않는다 |
| 페이지 순서·cursor가 계약과 다름 | 이어 받기를 멈추고 오류 줄. 정렬로 덮지 않는다 (U1) |
| 재생 중 마지막 받은 달에 닿음 | 더 받을 것이 있으면 기다리고 없으면 정지 (U6) |
| 보는 중 새 달 정산 | 다시 받지 않는다. 탭을 다시 열면 캐시가 없어 첫 페이지부터 받는다 (U10, E13) |
| 월드 전환 중 늦은 응답 | 취소되고 키가 달라 섞이지 않는다 (U10, E10) |
| 수백 개월 월드 | 한 번에 한 페이지씩 받고 받은 만큼 재생한다. 지금 계약에 페이지 크기 선택이 없어 30개월씩이다 |
| 도시 소유 차이로 사건처럼 보이는 표시 | 1차 화면에는 변화 표시가 없다 (U8) |
