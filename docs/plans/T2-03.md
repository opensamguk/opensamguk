# T2-03 로비 API

## 계획 (Claude)

### 목표

로그인 뒤 로비에서 월드 목록을 보고 참가할 수 있게 하는 API (AC-M2-02).

### 범위

- `apps/server/src/routers/lobby.ts`: `lobby.worlds`, `lobby.notices`
- 월드 총정원 (D-020): 새 migration으로 `World.maxHumanGenerals Int?`를 더한다. `world:create --max-generals <n>`을 필수로 받고 운영자 명령 `world:capacity --world <ID> --max-generals <n>`을 더한다
- 장수 생성 판정 (D-020): `packages/rules`에 순수 함수 `creationBlock`을 두고 로비·`general.create` 접수·엔진 처리가 같이 쓴다. `general.ts:37`과 `inputs.ts:35`의 RUNNING 전용 판정을 이 함수로 바꾼다

### 하지 않는 것

월드 개설 화면(M3 관리자), 참가 신청·승인 절차(참가 = 장수 생성, T1-11), 로비 공지 저장 모델과 작성 명령(T2-09), 국가별 정원(T2-02).

### 선행 인계

- `presetName`은 T2-02가 월드에 저장하는 프리셋 사본(`World.preset`)의 `name`이다 ([T2-02](./T2-02.md) 프리셋 항목 표). T2-02 전에 만든 월드는 `World.preset`이 없으므로 `presetName`이 null이다. 화면은 null이면 프리셋 칸을 비운다.
- 로비 공지는 T2-09가 만드는 `Notice` 모델의 로비 범위 행을 읽는다. API 이름은 `lobby.notices` 하나이고 `notice.lobby.list`는 두지 않는다. 로비 공지 행에는 `title`, `body`, `publishedAt`이 있어야 한다. T2-09 계획(PR #63)에 이 세 필드가 없으면 그 리뷰에서 맞춘다.
- 대기열 표(`docs/product/phases.md`)의 T2-03 선행 칸은 지금 `T2-01`뿐이다. PR #46이 같은 파일을 고치고 있어 이 PR에서는 바꾸지 않는다. #46이 합쳐진 뒤 `T2-01, T2-02, T2-09`로 맞춘다.

### API 계약

이 타입 하나가 계약이다. 예전 요약(`presetKey`, `createdAt`이 있던 짧은 목록)은 지웠다. 구현 뒤에는 `AppRouter` 타입이 이 모양을 그대로 낸다.

```ts
type GameDate = { year: number; month: number };
type LobbyWorld = {
  id: string;
  name: string;
  status: 'PREOPEN' | 'RUNNING' | 'PAUSED' | 'ENDED'; // ENDED는 includeEnded일 때만 온다
  presetName: string | null; // 정규, 속성 등 (T2-02). T2-02 전에 만든 월드는 null
  scenarioTitle: string;
  startYear: number;
  gameDate: GameDate; // 지금 게임 연월. PREOPEN이면 시작 연월
  turnTermMinutes: number;
  startedAt: string | null; // ISO 시각. 아직 시작하지 않은 PREOPEN만 null
  humanGenerals: number; // 아래 집계 정의
  maxHumanGenerals: number | null; // 월드 총정원 (D-020). null이면 아직 정하지 않은 월드이고 생성을 막는다
  myGeneral: { id: number; name: string; nationName: string | null } | null; // 무인증이면 null, 재야면 nationName이 null
  createBlockedReason: string | null; // 아래 판정 표. 화면 문구 그대로
};
// lobby.worlds({ includeEnded?: boolean }) → LobbyWorld[]
//   정렬: RUNNING → PREOPEN → PAUSED → ENDED. 같은 상태면 startedAt 최신 순(null이면 createdAt), 그다음 id 순
type LobbyNotice = { id: string; title: string; body: string; publishedAt: string }; // publishedAt은 ISO 시각
// lobby.notices() → LobbyNotice[]   publishedAt 최신 순, 같으면 id 내림차순, 많아야 20개
```

- 공개 범위: 무인증도 두 API를 부른다. 응답 키는 위 타입과 같고 시드·`statRules`·`initialStateHash` 같은 월드 내부 값은 내보내지 않는다. `myGeneral`은 세션 사용자의 장수만이다.
- 무인증과 로그인한 미참가자는 둘 다 `myGeneral`이 null이다. 화면은 `auth.me`로 둘을 가른다 (T2-04). 로비 API에 사용자 필드를 따로 두지 않는다.
- 화면 요소와 필드의 대조는 [T2-04](./T2-04.md)의 v1 근거 표 오른쪽 칸에 있다. `id`는 `들어가기`·`장수 만들기` 주소에 쓴다. 나머지 필드도 모두 화면 요소 하나 이상에 쓰인다.

### 총정원과 집계 (D-020)

- 출처는 `World.maxHumanGenerals`다. 운영자가 `world:create --max-generals <n>`(필수, 1 이상)으로 정하고 `world:capacity`로 바꾼다. 값은 계획에서 정하지 않는다.
- 이 migration 전에 만든 월드는 null로 남는다. 운영자가 `world:capacity`로 정하기 전까지 그 월드에서는 장수를 만들 수 없다. 국가별 정원(T2-02 `protection.maxGeneralsPerNation`)으로 대신하지 않는다.
- `world:capacity`는 `World` 행을 `FOR UPDATE`로 잠그고 바꾼다. 지금 `humanGenerals`보다 작은 값도 받는다. 이미 있는 장수는 그대로이고 새 생성만 막힌다.
- 집계 `humanGenerals`는 그 월드에서 `General.userId`가 null이 아닌 행의 수다. NPC는 세지 않는다. 접수만 되고 엔진이 아직 처리하지 않은 생성(InputEvent PENDING)도 세지 않는다. 마지막 자리는 엔진이 정한다.

### 장수 생성 판정 `createBlockedReason`

위에서부터 처음 맞는 줄을 쓴다. 로비(`lobby.worlds`), 접수(`general.create`), 엔진(`processCreation`)이 같은 `creationBlock` 함수를 부른다.

| 순서 | 조건 | `createBlockedReason` | 접수·엔진 거부 코드 |
| ---- | ---- | --------------------- | ------------------- |
| 1 | 내 장수가 있다 | null (화면은 `들어가기`) | `ALREADY_EXISTS` |
| 2 | 상태가 PAUSED | `멈춘 월드입니다` | `WORLD_CLOSED` |
| 3 | 상태가 ENDED | `끝난 월드입니다` | `WORLD_CLOSED` |
| 4 | 내 생성 요청이 PENDING | `장수를 만드는 중입니다` | 없음. 접수는 같은 요청이면 그 요청을 돌려준다 (`general.ts:43-55`) |
| 5 | `maxHumanGenerals`가 null | `정원이 정해지지 않은 월드입니다` | `WORLD_FULL` |
| 6 | `humanGenerals` ≥ `maxHumanGenerals` | `인원이 찼습니다` | `WORLD_FULL` |
| 7 | 그 밖 (PREOPEN·RUNNING, 자리 있음) | null (화면은 `장수 만들기`) | 통과 |

- 무인증이면 1번과 4번 줄을 건너뛴다. 화면은 null이면 `로그인하고 참가`, 아니면 그 이유를 보인다.
- 멈춤 월드의 조회와 생성은 다르다. 내 장수가 있는 멈춤 월드는 1번 줄에서 끝나고 화면은 `들어가기`를 연다. 장수가 없으면 2번 줄로 막는다.
- 새 거부 코드 `WORLD_FULL`(`인원이 찼습니다`)을 `CREATION_ERRORS`에 더하고 서버 응답 코드는 `PRECONDITION_FAILED`로 둔다. 5번 줄도 같은 코드를 쓰고 문구만 다르다.
- 마지막 자리: 접수는 `requireWorld(tx, worldId, true)`의 World 잠금 안에서 판정해 뻔한 거절을 빨리 돌려준다. 엔진은 리스와 World를 잠근 같은 펜싱 트랜잭션(`turnLoop.ts:81-88`)에서 `humanGenerals`를 다시 세어 판정한다. 둘이 다르면 엔진 판정을 따른다.
- 가오픈 생성 (D-020): `processCreation`은 PREOPEN에서 tick을 `world.clockTick`으로 쓴다(`turnLoop.ts:86-87`). 엔진이 가오픈 월드도 맡도록 `main.ts:33`의 RUNNING 전용 선택을 T2-01 월드별 엔진에서 넓힌다.
  만든 장수는 기존 `general.create` 입력 기록으로 재생되고 `world:start` 뒤 첫 월간 정산부터 다른 장수와 같이 정산된다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 목록 | API: 월드 4개(상태 다름) → 정렬·ENDED 숨김, 같은 상태 동률이면 id 순 |
| 내 장수 | API: 월드 A에만 장수가 있는 사용자 → A만 `myGeneral` |
| 무인증 | API: 쿠키 없이 목록 OK, `myGeneral` 전부 null, 1번과 4번 줄 없이 판정 |
| 판정 표 | 단위: `creationBlock` 7줄 전부. API: 상태 4종 × 내 장수 있음·없음·생성 대기 × 정원 미설정·남음·참의 `createBlockedReason` |
| 같은 판정 | 통합: 판정 표의 각 줄에서 로비 이유, `general.create` 거부 코드, 엔진 REJECTED 코드가 표와 같다 |
| 가오픈 생성 | 통합: PREOPEN 월드에서 생성 → APPLIED → `world:start` → 12개월 재생 해시가 실제 기록과 같다 |
| 마지막 자리 | 통합: 남은 자리 1개에 두 사용자가 동시에 접수 → 하나는 APPLIED, 하나는 REJECTED `WORLD_FULL`. 사람 장수 수가 정원을 넘지 않는다 |
| 대기 중 변경 | 통합: PENDING 뒤 `world:pause` → REJECTED `WORLD_CLOSED`. PENDING 뒤 `world:capacity`로 정원을 줄임 → REJECTED `WORLD_FULL` |
| 총정원 설정 | 통합: `world:create`에 `--max-generals` 없음 → 실패. 0 이하 → 실패. migration 전 월드 → null, 생성 거부 |
| 공개 범위 | API: 응답 키가 위 타입과 정확히 같다, 월드 내부 값이 없다 |
| 공지 | API: 로비 공지 21개(같은 시각 2개 포함) → 20개, 최신 순, 동률은 id 내림차순 |
| 성능 | 월드 10개·장수 600명에서 50ms 미만 |
