# T2-03 로비 API

> 대기열: T2-03 · AC: AC-M2-02 (API) · 구현: Codex · 리뷰: Claude
> 선행: T2-01 · 다음: T2-04 로비 화면 (Claude)

## 계획 (Claude)

### 목표

로그인 뒤 로비에서 월드 목록을 보고 참가할 수 있게 하는 API (AC-M2-02).

### 범위

`apps/server/src/routers/lobby.ts`, `notice` 일부(로비 공지 읽기)

### 하지 않는 것

월드 개설 화면(M3 관리자), 참가 신청·승인 절차(참가 = 장수 생성, T1-11).

### API 계약

```ts
lobby.worlds() → [{
  id, name, status,                 // PREOPEN | RUNNING | PAUSED | ENDED
  presetKey, presetName,            // '정규', '속성' …
  scenarioTitle, startYear, gameDate: { year, month },
  turnTermMinutes, startedAt | null,
  humanGenerals, maxHumanGenerals | null,
  myGeneral: { id, name, nationName | null } | null,   // 로그인 사용자 기준
}]
lobby.notices() → [{ id, title, body, createdAt }]     // 운영자 로비 공지 (T2-09)
```

- 무인증으로도 `lobby.worlds`를 부를 수 있다 (가입 전 구경). 그때 `myGeneral`은 null.
- ENDED 월드는 기본 숨김, `includeEnded: true`일 때만.
- 정렬: RUNNING → PREOPEN → PAUSED, 같은 상태면 시작일 최신 순.

화면(T2-04)이 기대하는 응답 모양 (2026-10-21 추가, 이름은 바꿔도 되지만 필드는 모두 필요):

```ts
type GameDate = { year: number; month: number };
type LobbyWorld = {
  id: string;
  name: string;
  status: 'PREOPEN' | 'RUNNING' | 'PAUSED' | 'ENDED'; // ENDED는 includeEnded일 때만 온다
  presetName: string; // 화면에 그대로 쓰는 이름 (정규, 속성 등, T2-02). presetKey는 화면이 쓰지 않는다
  scenarioTitle: string;
  startYear: number;
  gameDate: GameDate; // 지금 게임 연월. PREOPEN이면 시작 연월
  turnTermMinutes: number;
  startedAt: string | null; // ISO 시각. PREOPEN이면 null
  humanGenerals: number; // 사람이 맡은 살아 있는 장수 수
  maxHumanGenerals: number | null; // null이면 정원 없음
  myGeneral: { id: number; name: string; nationName: string | null } | null; // 무인증이면 null, 재야면 nationName이 null
  createBlockedReason: string | null; // 장수를 만들 수 없는 이유 (화면 문구 그대로). 만들 수 있거나 myGeneral이 있으면 null
};
// lobby.worlds({ includeEnded?: boolean }) → LobbyWorld[]
//   정렬: RUNNING → PREOPEN → PAUSED → ENDED. 같은 상태면 startedAt 최신 순(null이면 createdAt), 그다음 id 순
type LobbyNotice = { id: string; title: string; body: string; createdAt: string }; // createdAt은 ISO 시각
// lobby.notices() → LobbyNotice[]   최신 순, 많아야 20개
```

- 공개 범위: 무인증도 두 API를 부른다. 응답 키는 위 타입과 같고 시드·`statRules`·`initialStateHash` 같은 월드 내부 값은 내보내지 않는다. `myGeneral`은 세션 사용자의 장수만이다.
- 장수 만들기 가능 여부는 서버가 정한다. 정원이 차면 `인원이 찼습니다`를 준다. 지금 `general.create`는 RUNNING 월드만 받는다(`apps/server/src/routers/general.ts:37`). 가오픈 월드에서 미리 만들게 할지는 구현 때 이 규칙과 함께 정하고 `createBlockedReason`에 맞춘다.
- `lobby.notices`는 T2-09의 `notice.lobby.list`와 같은 자료다. 하나만 두고 이름은 Codex가 정한다. 화면은 위 모양만 기대한다.
- 화면 요소와 필드의 대조는 [T2-04](./T2-04.md)의 v1 근거 표 오른쪽 칸에 있다. `id`는 `들어가기`·`장수 만들기` 주소에 쓴다. 나머지 필드도 모두 화면 요소 하나 이상에 쓰인다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 목록 | API: 월드 3개(상태 다름) → 정렬·숨김 규칙 |
| 내 장수 | API: 월드 A에만 장수가 있는 사용자 → A만 `myGeneral` |
| 무인증 | API: 쿠키 없이 목록 OK, `myGeneral` 전부 null |
| 공개 범위 | API: 응답 키가 화면 응답 모양과 정확히 같다, 정원 찬 월드는 `createBlockedReason`이 있다 |
| 성능 | 월드 10개·장수 600명에서 50ms 미만 |
