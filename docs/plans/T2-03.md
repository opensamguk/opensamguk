## 계획 (Claude)

### 목표

로그인 뒤 로비에서 월드 목록을 보고 참가할 수 있게 하는 API (AC-M2-02).

### 범위

기본 범위 (D-022와 무관하게 한다):

- `apps/server/src/routers/lobby.ts`: `lobby.worlds`, `lobby.notices`
- 장수 생성 판정: `packages/rules`에 순수 함수 `creationBlock`을 두고 로비·`general.create` 접수·엔진 처리가 같이 쓴다. `general.ts:37`과 `inputs.ts:35`의 상태 판정을 이 함수로 바꾼다. 승인 전에는 받는 상태가 지금처럼 RUNNING 하나다

D-022 승인 뒤에만 하는 범위 (승인 전에는 착수하지 않는다):

- 판정에 PREOPEN 허용과 정원 줄을 켠다 (아래 판정 표의 D-022 칸)
- 월드 총정원: 새 migration으로 `World.maxHumanGenerals Int?`를 더한다. `world:create --max-generals <n>`을 필수로 받고 운영자 명령 `world:capacity --world <ID> --max-generals <n>`을 더한다
- 감독 프로세스(T2-01 `apps/engine/src/supervisor.ts`)가 PREOPEN 월드에도 자식 엔진을 띄우게 한다 (아래 T2-01 인계)

### 하지 않는 것

월드 개설 화면(M3 관리자), 참가 신청·승인 절차(참가 = 장수 생성, T1-11), 로비 공지 저장 모델과 작성 명령(T2-09), 국가별 정원(T2-02).

### 선행 인계

- T2-02: `presetName`은 T2-02가 월드에 저장하는 프리셋 사본(`World.preset`)의 `name`이다 ([T2-02](./T2-02.md) 프리셋 항목 표). T2-02 전에 만든 월드는 `World.preset`이 없으므로 `presetName`이 null이다. 화면은 null이면 프리셋 칸을 비운다.
  D-022가 승인되면 `--max-generals`는 T2-02가 `--preset`을 더한 같은 `world:create`에 붙는다. T2-03 migration 전에 만든 월드(T2-02로 만든 프리셋 월드 포함)는 `maxHumanGenerals`가 null이고 운영자가 `world:capacity`로 정해야 참가할 수 있다.
- T2-09: 로비 공지는 T2-09가 만드는 `Notice` 모델의 로비 행을 읽는다. API 이름은 `lobby.notices` 하나이고 `notice.lobby.list`는 두지 않는다.
  받는 계약은 PR #63 head `d50c590`의 T2-09 공지 저장 모델 표다. 로비 행은 `scope = LOBBY`, `worldId = null`이고 `title`·`body`·`publishedAt`이 필수다. 작성은 `pnpm notice:publish --scope lobby`가 하고 `pinned`는 쓰지 않는다.
  `lobby.notices`는 `publishedAt` 최신 순, 같으면 id 내림차순, 많아야 20개를 낸다. 월드 공지(`scope = WORLD`)와 고정 우선 순서는 로비에 섞지 않는다.
  지금 main의 T2-09 계획(`docs/plans/T2-09.md:56`)은 아직 `notice.lobby.list`를 적고 있다. PR #63이 합쳐지고 T2-09가 완료되기 전에는 T2-03을 착수하지 않는다.
- T2-01: T2-01 감독 프로세스는 RUNNING·PAUSED 월드만 맡는다 (`docs/plans/T2-01.md:27`). T2-01 계획과 인계는 바꾸지 않는다.
  D-022가 승인되면 PREOPEN 선택은 T2-03이 T2-01이 합쳐진 `supervisor.ts` 위에서 더한다. 자식 엔진의 리스는 T2-01과 같은 `EngineLease`다.
  PREOPEN 월드의 엔진은 생성 접수만 처리하고 tick·개인 턴·월간 정산은 돌리지 않는다. 이 동작은 지금 코드에 있다(`apps/engine/src/turnLoop.ts:86-91`, RUNNING이 아니면 `processCreation`만 부른다). `world:start` 뒤 처음 RUNNING 분기에 들어간다.
- 대기열 표(`docs/product/phases.md`)의 T2-03 선행 칸은 이 PR에서 `T2-01, T2-02, T2-09`로 맞췄다.

### API 계약

이 타입 하나가 계약이다. 예전 요약(`presetKey`, `createdAt`이 있던 짧은 목록)은 지웠다. 구현 뒤에는 `AppRouter` 타입이 이 모양을 그대로 낸다.

```ts
type GameDate = { year: number; month: number };
type LobbyWorld = {
  id: string;
  name: string;
  status: 'PREOPEN' | 'RUNNING' | 'PAUSED' | 'ENDED'; // ENDED는 includeEnded일 때만 온다
  presetName: string | null; // 정규, 속성 등 (T2-02). T2-02 전에 만든 월드는 null
  scenarioTitle: string;
  startYear: number;
  gameDate: GameDate; // 지금 게임 연월. PREOPEN이면 시작 연월
  turnTermMinutes: number;
  startedAt: string | null; // ISO 시각. 아직 시작하지 않은 PREOPEN만 null
  humanGenerals: number; // 아래 집계 정의
  maxHumanGenerals?: number | null; // D-022 승인 뒤에만 있는 키. null이면 아직 정하지 않은 월드이고 생성을 막는다
  myGeneral: { id: number; name: string; nationName: string | null } | null; // 무인증이면 null, 재야면 nationName이 null
  createBlockedReason: string | null; // 아래 판정 표. 화면 문구 그대로
};
// lobby.worlds({ includeEnded?: boolean }) → LobbyWorld[]
//   정렬: RUNNING → PREOPEN → PAUSED → ENDED. 같은 상태면 startedAt 최신 순(null이면 createdAt), 그다음 id 순
type LobbyNotice = { id: string; title: string; body: string; publishedAt: string }; // publishedAt은 ISO 시각
// lobby.notices() → LobbyNotice[]   publishedAt 최신 순, 같으면 id 내림차순, 많아야 20개
```

- 공개 범위: 무인증도 두 API를 부른다. 응답 키는 위 타입과 같고 시드·`statRules`·`initialStateHash` 같은 월드 내부 값은 내보내지 않는다. `myGeneral`은 세션 사용자의 장수만이다.
- 무인증과 로그인한 미참가자는 둘 다 `myGeneral`이 null이다. 화면은 `auth.me`로 둘을 가른다 (T2-04). 로비 API에 사용자 필드를 따로 두지 않는다.
- 화면 요소와 필드의 대조는 [T2-04](./T2-04.md)의 v1 근거 표 오른쪽 칸에 있다. `id`는 `들어가기`·`장수 만들기` 주소에 쓴다. 나머지 필드도 모두 화면 요소 하나 이상에 쓰인다.

### 집계 정의

- `humanGenerals`는 그 월드에서 `General.userId`가 null이 아닌 행의 수다. NPC는 세지 않는다. 접수만 되고 엔진이 아직 처리하지 않은 생성(InputEvent PENDING)도 세지 않는다.

### 총정원 (D-022 승인 뒤에만)

- 출처는 `World.maxHumanGenerals`다. 운영자가 `world:create --max-generals <n>`(필수, 1 이상)으로 정하고 `world:capacity`로 바꾼다. 값은 계획에서 정하지 않는다.
- 이 migration 전에 만든 월드는 null로 남는다. 운영자가 `world:capacity`로 정하기 전까지 그 월드에서는 장수를 만들 수 없다. 국가별 정원으로 대신하지 않는다.
- `world:capacity`는 `World` 행을 `FOR UPDATE`로 잠그고 바꾼다. 지금 `humanGenerals`보다 작은 값도 받는다. 이미 있는 장수는 그대로이고 새 생성만 막힌다.
- 마지막 자리는 엔진이 정한다 (아래 판정의 마지막 자리 줄).

### 장수 생성 판정 `createBlockedReason`

위에서부터 처음 맞는 줄을 쓴다. 로비(`lobby.worlds`), 접수(`general.create`), 엔진(`processCreation`)이 같은 `creationBlock` 함수를 부르되 단계마다 넣는 값이 다르다.
D-022 칸이 `승인 뒤`인 줄은 승인 전에 없다. `승인 전`인 줄은 승인 뒤에 없다.

| 순서 | 조건 | D-022 | `createBlockedReason` (로비) | 접수 `general.create` | 엔진 `processCreation` |
| ---- | ---- | ----- | ---------------------------- | --------------------- | ---------------------- |
| 1 | 내 장수가 있다 | 항상 | null (화면은 `들어가기`) | `ALREADY_EXISTS` | `ALREADY_EXISTS` |
| 2 | 상태가 PAUSED | 항상 | `멈춘 월드입니다` | `WORLD_CLOSED` | `WORLD_CLOSED` |
| 3 | 상태가 ENDED | 항상 | `끝난 월드입니다` | `WORLD_CLOSED` | `WORLD_CLOSED` |
| 3a | 상태가 PREOPEN | 승인 전 | `아직 열리지 않은 월드입니다` | `WORLD_CLOSED` | `WORLD_CLOSED` |
| 4 | 내 생성 요청이 PENDING | 항상 | `장수를 만드는 중입니다` | 같은 내용이면 그 접수를 돌려주고 다른 내용이면 CONFLICT (`general.ts:43-55`) | 해당 없음. 엔진은 지금 처리하는 그 접수를 이 줄에 넣지 않는다 |
| 5 | `maxHumanGenerals`가 null | 승인 뒤 | `정원이 정해지지 않은 월드입니다` | `WORLD_FULL` | `WORLD_FULL` |
| 6 | `humanGenerals` ≥ `maxHumanGenerals` | 승인 뒤 | `인원이 찼습니다` | `WORLD_FULL` | `WORLD_FULL` |
| 7 | 그 밖 (승인 전 RUNNING, 승인 뒤 PREOPEN·RUNNING) | 항상 | null (화면은 `장수 만들기`) | 접수 PENDING | APPLIED |

- 함수 입력은 상태, 내 장수 유무, 내 PENDING 생성 접수 유무, `humanGenerals`, 정원 값(승인 전에는 없음)이다. 로비와 접수는 DB에서 읽은 내 PENDING 유무를 넣는다.
  엔진은 가장 오래된 PENDING 접수 하나를 집어 처리하므로(`inputs.ts:16-19`) 그 접수의 PENDING 유무를 거짓으로 넣는다. 그래서 정상 PENDING 하나는 4번 줄에서 멈추지 않고 정원 재검사와 생성까지 간다.
- 무인증이면 1번과 4번 줄을 건너뛴다. 화면은 null이면 `로그인하고 참가`, 아니면 그 이유를 보인다.
- 멈춤 월드의 조회와 생성은 다르다. 내 장수가 있는 멈춤 월드는 1번 줄에서 끝나고 화면은 `들어가기`를 연다. 장수가 없으면 2번 줄로 막는다.
- 이미 만든 장수의 결과를 다시 받는 일과 두 번째 생성은 다르다. APPLIED 뒤 같은 사용자가 `general.create`를 다시 부르면 1번 줄의 `ALREADY_EXISTS`다. 결과는 지금처럼 `general.mine`(`general.ts:97-104`)이 돌려준다.
- 3a번 줄 문구 `아직 열리지 않은 월드입니다`는 `WORLD_CLOSED`의 화면 문구만 다르다. 승인 뒤 쓰는 새 거부 코드 `WORLD_FULL`(`인원이 찼습니다`)은 `CREATION_ERRORS`에 더하고 서버 응답 코드는 `PRECONDITION_FAILED`로 둔다. 5번 줄도 같은 코드를 쓰고 문구만 다르다.
- 마지막 자리 (승인 뒤): 접수는 `requireWorld(tx, worldId, true)`의 World 잠금 안에서 판정해 뻔한 거절을 빨리 돌려준다. 엔진은 리스와 World를 잠근 같은 펜싱 트랜잭션(`turnLoop.ts:81-88`)에서 `humanGenerals`를 다시 세어 판정한다. 둘이 다르면 엔진 판정을 따른다.
- 직렬화 (승인 뒤): 엔진의 생성 처리(`turnLoop.ts:84`), `world:start`(`apps/engine/src/world/clock.ts:8`), `world:capacity`가 모두 같은 World 행을 `FOR UPDATE`로 잠근다. 시작·생성·정원 변경이 겹쳐도 하나씩 차례로 확정된다.
- 가오픈 생성 (승인 뒤): `processCreation`은 PREOPEN에서 tick을 `world.clockTick`으로 쓴다(`turnLoop.ts:86-87`). 만든 장수는 기존 `general.create` 입력 기록으로 재생되고 `world:start` 뒤 첫 월간 정산부터 다른 장수와 같이 정산된다.
- 가오픈 월드의 메인과 개인 예턴: 지금 서버는 조회에서 상태를 막지 않고(`apps/server/src/queries.ts:28-40`) 개인 예턴 저장은 ENDED만 막는다(`apps/server/src/routers/turns.ts:39`). 다음 턴 시각은 RUNNING이 아니면 null이다(`queries.ts:64-65`).
  그래서 승인 뒤 가오픈 월드에 만든 장수는 시작 전에도 메인을 보고 개인 30칸을 저장한다. T1-15·T1-16 화면이 다음 턴 시각 null을 시작 전으로 그리는지 T2-04 리뷰에서 함께 확인한다.

### 검증

| 무엇 | 어떻게 |
| ---- | ------ |
| 목록 | API: 월드 4개(상태 다름) → 정렬·ENDED 숨김, 같은 상태 동률이면 id 순 |
| 내 장수 | API: 월드 A에만 장수가 있는 사용자 → A만 `myGeneral` |
| 무인증 | API: 쿠키 없이 목록 OK, `myGeneral` 전부 null, 1번과 4번 줄 없이 판정 |
| 판정 표 | 단위: `creationBlock`의 승인 전 줄(1, 2, 3, 3a, 4, 7)과 승인 뒤 줄(1, 2, 3, 4, 5, 6, 7) 전부. API: 상태 4종 × 내 장수 있음·없음·생성 대기, 승인 뒤에는 정원 미설정·남음·참도 곱한다 |
| 단계별 판정 | 통합: 판정 표의 각 줄에서 로비 이유, 접수 결과, 엔진 결과가 그 줄의 칸과 같다. 4번 줄은 로비와 접수만 본다 |
| 자기 접수 | 통합: 정상 PENDING 하나 → 반드시 APPLIED. 같은 내용으로 다시 접수 → 원래 접수 id를 돌려받고 InputEvent는 1행. APPLIED 뒤 `general.mine` → 그 장수. APPLIED 뒤 새 생성 → `ALREADY_EXISTS` |
| RUNNING 경계 (승인 전) | 통합: PREOPEN 월드 생성 접수 → `WORLD_CLOSED`, 엔진에 PREOPEN 접수가 남아 있으면 REJECTED `WORLD_CLOSED` |
| 가오픈 감독 (승인 뒤) | 통합: 실제 감독 프로세스를 띄움 → PREOPEN 월드의 생성 접수가 APPLIED. 시작 전에는 `clockTick`·`monthlyTick`이 그대로이고 개인 턴 로그와 월간 기록이 0행. `processCreation` 직접 호출로 대신하지 않는다 |
| 시작 전 예턴 (승인 뒤) | 통합: 가오픈 월드에서 생성 → 개인 30칸 저장 → `world:start` → 첫 턴이 저장한 0번 칸을 실행 → 12개월 재생 해시가 실제 기록과 같다 |
| 시작과 생성 경합 (승인 뒤) | 통합: 생성 접수 처리와 `world:start`를 동시에 → 둘 다 한 번씩 확정되고 재생 해시가 기록과 같다 |
| 마지막 자리 (승인 뒤) | 통합: 남은 자리 1개에 두 사용자가 동시에 접수 → 하나는 APPLIED, 하나는 엔진에서 REJECTED `WORLD_FULL`. 사람 장수 수가 정원을 넘지 않는다 |
| 대기 중 변경 | 통합: PENDING 뒤 `world:pause` → REJECTED `WORLD_CLOSED`. 승인 뒤: PENDING 뒤 `world:capacity`로 정원을 줄임 → REJECTED `WORLD_FULL` |
| 총정원 설정 (승인 뒤) | 통합: `world:create`에 `--max-generals` 없음 → 실패. 0 이하 → 실패. migration 전 월드와 T2-02 프리셋 월드 → null, 생성 거부 → `world:capacity`로 정함 → 생성 APPLIED |
| 공개 범위 | API: 응답 키가 위 타입과 정확히 같다, 월드 내부 값이 없다 |
| 공지 | API: 로비 공지 21개(같은 시각 2개 포함) → 20개, 최신 순, 동률은 id 내림차순. 월드 공지는 섞이지 않는다 |
| 성능 | 월드 10개·장수 600명에서 50ms 미만 |
