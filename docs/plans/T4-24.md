## 계획 (Claude)

### 목표

장비매매를 켠 월드에서 장수가 장비 화면을 열어 내 장비 네 칸, 금과 지금 도시의 치안, 살 수 있는 장비의 값·치안 요구·효과를 본다. 사거나 팔 장비를 고르면 고른 예턴 칸에 장비매매가 들어가고 편집기에서 저장한다. 엔진이 그 턴을 실행하면 장착 상태와 금이 바뀐 것을 같은 화면에서 본다. 끈 월드에는 메뉴가 없다.

### 범위

| 구분 | 파일 | 담당 → 리뷰 |
| ---- | ---- | ----------- |

| E2E | 새 `e2e/equipment.spec.ts`, `e2e/equipmentSeed.ts` | Claude → Codex |

- 메인 장수 정보 칸에 장비 넣기(쟁점 T24-Q2).
- 다른 장수의 장비 보기, 경매(T4-29), 전투 시뮬레이터에 장비 넣기.
- 즉시 매매. 매매는 예턴으로만 한다.

## 2. 화면 계약

### 2.1 진입

- 주소 `/w/:worldId/equipment`. 직접 열기·새로 고침이 된다.
- 메뉴 `장비`는 `commands.list`에 `equipment_trade`가 있을 때만 그린다. 끈 월드에서 주소로 오면 서버의 꺼진 기능 응답을 빈 상태 `이 월드에서는 장비를 쓰지 않습니다.`로 보인다.

### 2.2 배치

```text
┌ 내 장비 ───────────────┬ 장비 목록 ───────────────────────────────────────┐
│ 명마  노기             │ 칸   이름     효과                값     치안  지금 │
│ 무기  (비어 있음)       │ 명마 노기     (EQ-2 결과 문구)    1,000  1,000  가능 │
│ 서적  (비어 있음)       │ 명마 조랑     …                   3,000  2,000  금 부족│
│ 도구  (비어 있음)       │ …                         [예턴에 넣기]          │
│ 금 1,200 · 치안 1,000   │                                                  │
│ [판매 예턴에 넣기]       │                                                  │
├────────────────────────┴──────────────────────────────────────────────────┤
│ 30칸 예턴 편집기 (renderTop: 넣을 매매 · 고른 칸 · [고른 칸에 넣기])        │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 목록은 `DataTable`이다. 칸·이름·효과·값·치안 요구·지금 가능 여부. 값과 치안은 고정폭 숫자, 오른쪽 정렬. 기본 정렬은 칸, 그다음 값.
- 지금 가능 여부는 `canBuy`다. 가능하면 `가능`, 아니면 서버 이유(`Tag` 경고 색과 글자). 판매 버튼은 `canSell`을 같은 방식으로 보인다.
- `예턴에 넣기`를 누르면 그 매매가 아래 매매 칸에 고른 값으로 올라간다. 지금 실패할 이유가 있어도 넣을 수 있다. 예턴은 나중에 실행되고 엔진이 그때 다시 검사하기 때문이다(UI 지침 §2 사전 검사 규칙과 같다). 이유는 매매 칸에 함께 보인다.
- 매매 칸의 [고른 칸에 넣기]는 편집기에서 고른 칸마다 `edit({ put })`를 부른다. 고른 칸이 없으면 점선 버튼과 `예턴 칸을 먼저 고르세요.` 저장하지 않은 편집이 있는 칸을 덮을 때는 한 번 묻는다(작전 화면과 같다).
- 비매품은 목록 아래 따로 접힌 묶음에 둔다. 얻는 경로 문구는 T4-22 EQ-7 결과를 따른다.
- 장수가 없으면 장수 만들기 안내.

### 2.3 효과 문구

`effects.ts`가 T4-23의 `EquipmentEffectView`를 고정 문구로 바꾼다. 단계마다 문구가 하나다.

| 단계·연산 | 문구 예 |
| --------- | ------- |
| `domestic.score` mul | `내정 점수 ×1.05` (`commandKeys`가 있으면 그 명령 이름을 괄호로) |
| `battle.dealt` mul | `주는 피해 ×1.05` |
| `battle.taken` mul | `받는 피해 ×0.95` |
| `general.stat` | `통솔 +3` |
| add 연산 | `+N`으로 같은 꼴 |

모르는 단계가 오면 문구를 짓지 않고 `효과 설명 없음`으로 둔다. 서버가 단계를 늘리면 이 표를 같이 늘린다.

### 2.4 갱신

- `equipment.mine`은 화면을 열 때, 편집기 저장 뒤, 위쪽 띠의 0초 재조회 때 받는다. 0초 재조회는 `GameLayout.tsx`의 무효화 묶음에 넣지 않고 이 화면 안에서 `home.get` 갱신과 같은 시점에 다시 받는다.
- `equipment.catalog`는 월드마다 한 번 받는다(바뀌지 않는다).

### 2.5 접근성

- 표 머리글 `scope`, 버튼 이름에 장비 이름(`노기 예턴에 넣기`).
- 지금 가능 여부는 색과 글자를 함께 쓴다.
- 키보드만으로 장비 고르기 → 칸 고르기 → 넣기 → 저장.

### 3.2 Chromium E2E (`e2e/equipment.spec.ts`, `pnpm e2e`)

실제 `pnpm dev`와 `_test` PostgreSQL. `page.route`로 응답을 짓지 않는다. 준비(`equipmentSeed.ts`)는 T4-03 켠 월드 생성으로 `equipment_trade`를 켠 월드 K와 끈 월드 F를 만들고 K에 사람 장수 A(금 충분, 치안 높은 도시)와 B(치안 낮은 도시)를 둔다. 턴 실행은 `rankingSeed.ts`처럼 `TurnLoop`를 직접 돌린다.

| ID | 시험 | 기대 |
| -- | ---- | ---- |
| E1 | 진입 | K에서 메뉴 `장비`, F에서는 없음. F 주소 직접 열기는 빈 상태 |
| E2 | 목록 | 결정된 매매 장비 수만큼 행, 값·치안이 서버 값과 같다 |
| E3 | 구매 예약과 실행 | A가 노기를 0칸에 넣고 저장. 엔진이 A의 턴을 실행한 뒤 내 장비 명마 칸이 노기, 금이 값만큼 줄었다. 개인 기록에 매매 한 줄 |
| E4 | 효과 반영 | 장비 효과가 걸리는 명령(EQ-2 결과)을 다음 칸에 넣고 실행한다. 개인 기록의 결과 수치가 같은 상태를 순수 함수로 돌린 값(준비 스크립트가 계산해 둔 값)과 같다 |
| E5 | 판매 | 판매 예약 실행 뒤 칸이 비고 금이 절반 값만큼 늘었다 |
| E6 | 실패 이유 | B의 목록에서 치안 요구를 못 넘는 장비에 이유. 넣고 실행하면 개인 기록에 실패 이유 |
| E7 | 새로 고침 | 넣고 저장하지 않은 매매 초안이 새로 고침 뒤에도 남는다(편집기 기존 동작) |
| E8 | 무인증 | 쿠키 없이 주소를 열면 `/login?next=` |
| E9 | 키보드 | Tab·Enter·Space만으로 E3의 넣기와 저장 |

## 4. 반례와 처리

| 반례 | 처리 |
| ---- | ---- |
| 넣은 뒤 실행 전에 금이 줄어듦 | 엔진이 실패로 기록한다. 화면은 실행 결과를 개인 기록으로 보인다 |
| 같은 칸 장비를 사는 매매가 두 칸에 들어감 | 막지 않는다. 두 번째 칸이 `이미 가지고 있습니다.`로 실패한다. 매매 칸에 같은 장비가 이미 초안에 있다는 안내를 한 줄 둔다 |
