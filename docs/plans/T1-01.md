## 계획 (Claude)

- 목표: 새로 클론한 저장소에서 `pnpm install` 다음 `pnpm check`가 통과한다 (AC-M1-01).
- 범위: 루트 설정, `apps/{web,server,engine}`, `packages/{shared,rules,db}`, `tools/`
- 하지 않는 것: 게임 규칙, 실제 로그인, DB 테이블 설계
- 검증: 깨끗한 폴더에 Git 추적 파일만 복사해 설치와 검사

## 구현 기록 (Claude)

- pnpm workspace, TypeScript 6.0 strict, ESLint 10 flat config, Vitest 5, Prisma 7(`prisma-client` + `@prisma/adapter-pg`)
- `eslint.config.js`: 패키지 의존 방향, 상대 경로 교차 import 금지, rules의 `Math.random`·`Date.now`·`new Date()`·node 내장·`fetch` 금지,
  shared·engine의 `Math.random` 금지, web은 server에서 타입만 import
- `tools/lint-boundaries.test.ts`가 위 규칙이 실제로 막는지 확인
- 검증: 2026-10-20 빈 폴더에서 `pnpm install --frozen-lockfile` → `pnpm check` 통과 (lint 0건, 타입 6개 패키지, 테스트 10개)

### 리뷰 반영 1차 (2026-10-20)

- [P2] 형제 패키지 상대 경로: 문자열 패턴 대신 로컬 lint 규칙 `opensamguk/no-cross-package-relative`
  (`tools/eslint/no-cross-package-relative.js`)를 추가했다. 파일 위치에서 실제로 풀린 경로가 자기 패키지(`apps/*`, `packages/*`) 밖이면 막는다.
  import·export from·동적 import 모두 검사한다. 이전 문자열 패턴(`**/apps/**`, `**/packages/**`)은 지웠다.
- [P2] Node 내장 모듈: 손으로 쓴 목록 대신 `node:module`의 `builtinModules` 전체와 하위 경로, `node:*`를 막는다.
- 회귀 테스트 (`tools/lint-boundaries.test.ts`): 리뷰 재현 경로 `../../db/src/index`(rules), `../../server/src/router`(web),
  깊은 경로의 형제 패키지, 같은 패키지 안 상대 경로 허용, 내장 모듈 8종(`fs`, `node:fs`, `crypto`, `node:crypto`, `dns/promises`,
  `node:dns/promises`, `fs/promises`, `timers/promises`).
- 검증: 작업 폴더와 Git 추적 파일만 복사한 빈 폴더 모두 `pnpm install --frozen-lockfile` → `pnpm check` 통과 (테스트 17개).

## 리뷰 (Codex)

- 결과: 수정 필요 (2026-10-20). 대기열을 `구현`으로 되돌림.
- 확인한 것: 커밋 `4122b70`의 Git 추적 파일만 빈 임시 폴더에 풀어 `pnpm install --frozen-lockfile` → `pnpm check` 통과. Prisma 생성, lint, 6개 패키지 타입 검사, 16개 테스트 통과 (Node 26.5.1, pnpm 10.33.0).
- 고칠 것:
  - [P2] `eslint.config.js:25`: 상대 import 문자열에 `apps` 또는 `packages`가 있어야 차단돼 형제 패키지 경로는 놓친다. ESLint `lintText`로 rules의 `import { createDb } from '../../db/src/index'`와 web의 `import { appRouter } from '../../server/src/router'` 모두 오류 0건을 재현했다. 실제 파일 위치를 기준으로 패키지 밖 상대 import를 차단하고 두 경로의 회귀 검증을 추가해야 한다. 현재 검사는 rules→DB 금지와 web→server 값 import 금지를 보장하지 못한다.
  - [P2] `eslint.config.js:18`: Node 내장 모듈 차단 목록에 접두사 없는 `crypto`, `dns/promises` 등이 빠져 있다. rules에서 `randomBytes`를 `crypto`로 import하거나 `lookup`을 `dns/promises`로 import해도 ESLint 오류가 0건이다. 내장 모듈과 하위 경로를 빠짐없이 차단하고 `node:` 유무를 모두 검증해야 한다. 현재는 비결정적 난수·네트워크 사용이 lint를 통과한다.
