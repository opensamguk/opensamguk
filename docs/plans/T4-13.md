## 계획 (Claude)

### 목표

AC-P2-07의 화면 몫이다. 명세 문장은 이렇다. 첩보하면 대상 도시의 그 시점 정보가 자기 국가에만 보이는 기록으로 남고 기록 시각이 함께 보인다. 다른 국가와 무인증의 조회는 거부된다.

이 작업이 끝나면 로그인한 장수가 기록 화면의 첩보 기록 탭에서 자기 국가가 남긴 첩보 기록을 도시마다 한 줄로 본다. 줄마다 기록 연월과 몇 개월 전, 정보 단계, 기록 당시 소유국, 기록된 값이 있다. 기록되지 않은 칸은 지어내지 않고 —와 이유로 둔다. 다른 국가 장수는 그 줄을 보지 못한다(서버가 보내지 않는다).

## 1. 화면 계약

### 1.1 진입

- 주소는 `/w/$worldId/records?tab=intel`, 탭 이름과 패널 제목은 첩보 기록이다. 탭 순서는 내 장수, 국가 역사, 월드 정세, (T4-36의) 영토 재생, 첩보 기록이다.
- `worldRoute`의 로그인 가드를 그대로 쓴다. 무인증은 지금처럼 `/login?next=`로 간다.
- `RecordsPage`는 `tab === 'intel'`이면 `RecordList` 대신 `<IntelRecords key={worldId} worldId={worldId} nations={...} cities={...} />`를 낸다. 도시 이름과 지금 국가 목록은 이미 받는 `useWorldMap` 결과를 넘긴다.

### 1.2 불러오기

- `useQuery({ ...trpc.intel.records.queryOptions({ worldId }), retry: retryUnlessClientError, refetchOnMount: 'always' })`. 탭을 열 때마다 새로 받는다.
- 이 작업은 0초 재조회와 SSE 무효화 목록을 고치지 않는다. 탭 위에 [다시 불러오기] 단추를 둔다. T4-39가 `turn.result`·`monthly.done`·0초 재조회에 `intel.records` 키를 더하면(T4-39 1.5) 이 탭도 같은 쿼리라 함께 갱신된다. 그 전에는 탭을 다시 열거나 단추를 누르거나 창 포커스 때 바뀐다.

### 1.3 상태별 화면

| 상태 | 판정 | 화면 |
| ---- | ---- | ---- |
| 불러오는 중 | `isPending` | `LoadingState` |
| 장수 없음 | 오류 코드 `NOT_FOUND`이고 지도는 받았음 | `EmptyState` 장수가 없습니다, 장수 만들기 링크(`/w/:worldId/create`) |
| 꺼진 월드 | `enabled === false` | `EmptyState` 이 월드에서는 첩보를 쓰지 않습니다 |
| 재야 | `enabled`이고 `items`가 비었고 `home.get`의 `nation === null` | `EmptyState` 국가에 소속되면 나라의 첩보 기록을 봅니다 |
| 기록 없음 | `enabled`이고 `items`가 빔 | `EmptyState` 아직 첩보 기록이 없습니다, 예턴에 첩보를 넣으면 그 도시의 그때 값이 기록됩니다 |
| 불러오기 실패 | 그 밖의 오류 | `QueryError`와 다시 시도. 빈 목록과 다르게 보인다(UI 지침 §1) |
| 기록 있음 | 그 밖 | 1.4 표 |

### 1.4 기록 표

`DataTable` 하나. 기본 정렬은 기록 연월 최신순(서버 순서와 같다). 머리글을 누르면 정렬한다.

| 열 | 값 | 기록에 없을 때 |
| -- | -- | -------------- |
| 도시 | `world.map`의 이름. 누르면 `/w/:worldId?city=<key>`로 메인 지도에서 그 도시를 고른다 | (늘 있다. 지도에 없는 key면 key 숫자) |
| 기록 | `191년 2월 · 3개월 전`, 같은 달이면 `이번 달` | — |
| 정보 | 많이 / 어느 정도 / 소문. 글자로만 쓰고 색은 보조 | — |
| 당시 주인 | 기록의 `owner` 이름표(`NationBadge`, 기록 당시 이름·색). `null`이면 공백지 | — |
| 주민 | `12,345 / 30,000` | — |
| 민심 | 소수 한 자리 | — |
| 장수 | 정수 | — |
| 병력 | `min === max`면 한 값, 아니면 `5,000~9,999`, `max === null`이면 `50,000 이상` | — |
| 농업·상업·치안·수비·성벽 | 값과 최대치 | — , 마우스를 올리면 `정보를 어느 정도 이상 얻었을 때만 기록됩니다` |
| 병종 | `창병 2 · 궁병 1`처럼 이름과 장수 수 | — , `정보를 많이 얻었을 때만 기록됩니다` |
| 기술 | 압도 / 우위 / 대등 / 열위 / 미미 (내 나라와 비교) | — , `정보를 많이 얻었을 때만 기록됩니다`. 공백지는 `공백지라 비교하지 않습니다` |

- 숫자 열은 `.num`(고정폭·오른쪽 정렬, UI 지침 §1·§3).
- 당시 주인이 지금 주인과 다르면 이름표 옆에 `지금은 다른 나라 도시`를 `Tag`로 붙인다. 지금 주인은 `world.map`에서 본다. 지금 주인을 기록 값처럼 쓰지 않는다.
- 표 위 캡션 `첩보 기록 N곳`. 그 아래 안내 한 줄: 기록은 첩보한 때의 값이며 다시 첩보하기 전까지 바뀌지 않는다.
- 색만으로 뜻을 전하지 않는다(NFR-08). 정보 단계와 기술 비교는 글자가 본체다.

### 1.5 표시 함수 (`view.ts`, 순수)

| 함수 | 입력 → 출력 |
| ---- | ----------- |
| `ageLabel(ageMonths)` | 0 → `이번 달`, n → `n개월 전` |

### 2.2 Chromium E2E (`e2e/intel.spec.ts`)

준비 스크립트 `e2e/intelSeed.ts`는 `rankingSeed.ts`와 같은 틀이다. `spy`를 켠 고정 프리셋으로 월드를 만들고 계정 셋(국가 A 장수, 국가 B 장수, 재야)과 끈 월드 하나를 둔다. A 장수의 예턴에 이웃 B 도시와 두 칸 거리 B 도시, 먼 B 도시의 `spy`를 넣고 엔진 `TurnLoop`로 실제 실행한다.

| ID | 내용 |
| -- | ---- |
| E1 | A 장수로 로그인해 기록 → 첩보 기록 탭에서 세 줄을 본다. 정보 단계가 많이·어느 정도·소문이고 기록 연월과 몇 개월 전이 보인다. 값은 준비 스크립트가 실행 tick에 읽은 도시 값과 같다 |
| E2 | B 장수로 같은 탭을 열면 A의 기록이 없다(빈 상태). 화면 요청의 응답 본문에도 A 기록이 없다(네트워크 응답 확인) |
| E3 | 재야 계정은 재야 안내가 보인다 |
| E4 | 로그아웃 상태로 `/w/:worldId/records?tab=intel`에 가면 로그인 화면으로 가고 돌아오면 같은 탭이다 |
| E5 | 끈 월드에서는 첩보를 쓰지 않는다는 안내가 보인다 |
| E6 | 한 달을 더 진행시킨 뒤 탭을 다시 열면 몇 개월 전이 1 늘어나고 값은 그대로다 |
| E7 | 도시 이름을 누르면 메인에서 그 도시가 골라져 있다 |
| E8 | `e2e/routes.spec.ts` 방식으로 주소 직접 접근·새로고침이 된다 |
