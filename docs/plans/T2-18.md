# T2-18 독립 에이전트 참가 시험 1기와 버그 정리

> 대기열: T2-18 · AC: AC-M2-12, AC-M2-13 · 구현: 사용자 (대기열 칸 유지) · 판정 리뷰: 참가자를 운영하지 않은 쪽
> 선행: T2-01~T2-17, T2-19~T2-23 · 결정: [D-021](../product/decisions.md#d-021-지인-참가-시험을-독립-에이전트-참가-시험으로-바꾸고-공개를-승인한다-2026-10-21) · 기록 형식: [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험)

## 계획 (Claude)

### 목표

- 계정·세션이 서로 다른 독립 에이전트 참가자 5명 이상이 실제 화면이나 HTTP로 월드 2개에 참가해 한 기수(합의한 기간)를 진행한다. 오류 때문에 상태를 되돌린 일이 0번이고 참가자별 행동·결과·피드백이 목록으로 정리된다 (AC-M2-12).
- 시험이 끝날 때 치명(P0) 버그가 0건이고 중대(P1) 버그는 전부 담당 AC나 백로그에 연결된다 (AC-M2-13).

### 범위

이 계획은 시험 방법과 증거 형식만 정한다. 제품 코드, 시험 실행, 인수 판정, 배포는 이 문서가 하지 않는다. 참가 에이전트 배정과 실행 일정은 총괄(opensamguk-lead)이 정한다.

### 하지 않는 것

NPC나 같은 에이전트의 병렬 요청으로 참가자 수 채우기, 진행 중 기간 줄이기, 관리자 권한이나 DB 수정으로 참가자를 진행시키기, 운영 데이터 초기화, 새 유료 서비스 사용.

### 참가자 기준

| 항목 | 기준 |
| ---- | ---- |
| 인원 | 5명 이상. 두 월드 모두에 참가자가 있다. 월드별 인원은 시작 전에 적는다 |
| 독립 | 계정, 로그인 세션, 에이전트 세션이 모두 참가자마다 다르다. 한 에이전트 세션이 여러 계정을 돌리면 한 명으로 센다 |
| 경로 | 실제 웹 화면이나 플레이어용 HTTP API. 관리자 API와 DB 직접 수정은 참가 행동이 아니다 |
| 개인정보 | 실제 이메일·비밀번호·토큰·쿠키·IP를 기록에 넣지 않는다. 계정은 `accountRef`로만 적는다 |

### 진행 순서

1. 시작 전에 아래 구현 기록에 `sourceSHA`(필수 CI를 통과한 정확한 커밋), 두 월드의 `worldId`·시나리오·턴 간격·프리셋, 기수의 끝 조건(천하통일 또는 종료 연도, A17)과 기간, 참가자 목록을 적는다. 시작한 뒤 기간과 끝 조건을 바꾸면 완주로 세지 않는다.
2. 참가자마다 가입·로그인 → 로비에서 월드 참가 → 장수 생성 → 예턴 입력을 한다. 그 뒤 기수가 끝날 때까지 각자 판단해 플레이한다. 행동과 결과를 [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험)의 필드로 남긴다.
3. 오류로 DB 복구, 상태 수정, 재생 초기화를 했다면 한 번으로 센다. 1번 이상이면 AC-M2-12는 통과하지 않는다.
4. 월드마다 기수 끝 증거(종료 화면의 승자와 연도, 최종 상태 해시)를 남긴다.
5. 결함을 P0·P1·P2로 나눠 이슈 목록을 만든다. P0은 고쳐서 0건으로 만든다. P1은 담당 AC나 [백로그](../product/backlog.md)에 연결한다.
6. 참가자별 피드백을 한 목록으로 묶어 회고로 정리한다.

### 검증

- AC-M2-12: 테스트 회고 문서. 아래 구현 기록의 참가자 표, 월드 표, 되돌림 횟수, 피드백 목록과 원본 기록 SHA-256.
- AC-M2-13: 이슈 목록. 결함마다 등급, 보고 참가자, `worldId`, `sourceSHA`, 연결한 AC나 백로그 항목.
- 참가자를 운영하지 않은 쪽이 원본 기록과 요약을 대조한다. 그 리뷰가 끝나야 AC를 통과로 표시한다. 하지 않았거나 일부만 한 시험은 미착수나 진행 중으로 둔다.

### 상대 영역에 필요한 것

참가자가 쓸 기능(가입, 로비, 장수 생성, 예턴, 메시지, 알림)은 선행 작업이 만든다. 참가자 계정을 만들 때 시험용 메일함이나 별칭을 써서 실제 개인정보가 기록에 남지 않게 한다.

## 구현 기록 (진행 담당)

### 증거 도구 (Codex, t_6e9433da)

구현 범위는 `tools/participation/`의 버전 1 JSONL·manifest 검사와 읽기 전용 HTTP 탐침이다. 참가 에이전트를 실행하거나 게임 상태를 쓰지 않는다. `package.json`, AppRouter, DB schema, 화면과 e2e는 바꾸지 않는다. 실제 참가 시험과 AC 판정은 아래 별도 기록으로 남긴다.

실행 명령은 저장소 루트에서 쓴다. 원본 묶음과 출력은 저장소 밖에 둔다.

```sh
pnpm exec tsx tools/participation/cli.ts validate --manifest /외부경로/manifest.json --source-sha <40자리SHA>
pnpm exec tsx tools/participation/cli.ts probe --base-url http://127.0.0.1:3001 --source-sha <40자리SHA>
```

`validate`는 파일을 읽고 SHA-256, 참조 연결, 참가자 독립성, 고정 기간·끝 조건, 월드별 종료, 참가자별 가입·턴·메시지·협업·종료 관측, 피드백과 결함을 검사한다. M3 모드는 이메일 인증·약관과 첫 턴까지의 순서도 검사한다. 형식 정본은 `tools/participation/schema.ts`다. 모든 필드는 필수이며 해당 없음은 허용된 필드의 `null`로 적는다. 알 수 없는 필드는 거부한다.

| 파일·필드 | 버전 1 형식 |
| --------- | ----------- |
| manifest | `version: 1`, `kind: actual/synthetic/probe`, `mode: m2/m3`, `sourceSHA`, `registeredAt`, `startsAt`, `endsAt`, `planRef`, `participants`, `worlds`, `events`, `artifacts`, `prerequisites`, `outcomes`, `feedback`, `defects` |
| 참가자 | `participantId`는 P1·P01 형식. `agent.provider/model`, native 실행의 `sessionRef`, `loginSessionRef`, `accountRef`, `nativeRef`. 계정 참조는 `account-<SHA256>`, 로그인 세션 참조는 `login-<SHA256>`. 토큰을 해시하지 말고 내부 비밀 아닌 행 ID에 시험별 소금을 붙여 해시한다 |
| 월드·계획 | `worldId`, `scenario`, `turnTermMinutes`, `preset`, 시작·종료 시각, `endCondition.type`(year/unification)와 `year`. `planRef`는 시작 전 등록한 계획 파일을 가리킨다. 참가자·월드·SHA·기간이 manifest와 같아야 한다. 원래 등록 시각과 원본 해시는 독립 리뷰어가 외부 시스템에서 대조한다 |
| 파일 참조 | `events`는 JSONL 파일명과 SHA-256. `artifacts`는 `ref`, `file`, `sha256`, `kind` 목록. 종류는 plan/native/result/completion/feedback/gate. 파일은 같은 디렉터리의 JSON·JSONL만 읽으며 상위 경로와 밖으로 나가는 심볼릭 링크를 거부한다 |
| 행동 JSONL | 한 줄에 `version`, `participantId`, `worldId`, `sourceSHA`, `at`, `transport`(http/screen), `path`, `step`, `requestRef`, `resultRef`, `decisionRef`. 시각은 UTC ISO 문자열이며 밀리초까지 적는다. 요청 본문·응답 본문·헤더를 복사하지 않는다 |
| native | `runtime`(hermes/codex/claude-code), 고유한 `runRef`, `sessionRef`, 제공자·모델, 참가자·SHA, 시작·종료 시각, 원래 실행을 찾을 `nativeSourceRef`, `decisions`. 판단마다 `decisionRef`, `at`, 직전 응답의 `observationRef`, `requestRef`를 잇는다. JSON 파일만으로 실행 출처를 인증하지 않는다 |
| 결과·종료 | result는 요청·참가자·월드·SHA·시각·`status`(ok/blocked)·`observationRef`. completion은 월드·SHA·시각·`status: ENDED`·승자·연도·최종 상태 해시·끝 조건·`evidenceSourceRef`. M2는 참가자마다 자기 월드 종료 뒤 `season_end` 관측이 있어야 한다 |
| 피드백·결함 | 피드백은 참가자·월드·SHA·시각과 외부 회고의 `feedbackRef`·재현 `reproductionRef`. 결함은 ID·등급·상태·보고 참가자·월드·SHA·담당 `trackingRef`·`evidenceRef`. P0 잔존, P1 담당 연결 누락과 되돌림 1회 이상은 실패다 |
| 선행 | M2는 M1과 T2-01~17/19~23, M3는 M2와 T3-01~14 및 release-build. 두 모드 모두 exact-sha-ci/cross-review/resource-admission 근거가 필요하다. gate 파일의 `evidenceSourceRef`는 원래 CI·리뷰·자원 예약 기록을 가리킨다 |

검사기는 자기신고 JSON을 실제 참가 근거로 인증하지 않는다. `toolStatus: VALID`와 `evidenceStatus: COMPLETE_FOR_REVIEW`는 파일 구조가 검토 가능하다는 뜻이다. `productStatus`는 `NOT_READY`, `acStatus`는 `NOT_ASSESSED`로 두고 실제 자료도 native 실행 원본을 참가자를 운영하지 않은 리뷰어가 확인하기 전에는 종료 코드 1을 낸다. `nativeSourceRef`, `evidenceSourceRef`, 피드백 참조가 실제 기록을 가리키는지와 내용·권한·독립성을 그 리뷰에서 확인한다. 원본 기록은 비밀값을 복사하지 않고 원래 시스템에서 열람한다.

단위 시험의 합성 묶음은 `--fixture`를 붙였을 때만 도구 성공(종료 코드 0)을 낸다. 그때도 제품은 `NOT_READY`이며 합성을 actual로 바꿔도 제품 통과로 올라가지 않는다. 빠진 자료·선행 미충족은 1, 인자 오류·HTTP 실패는 2다. `probe` 성공의 0은 현재 서버의 health DB 조회와 무인증 world.list 거부만 뜻한다. health 응답에 배포 SHA가 없으므로 `claimedSourceSHA`는 운영자 주장으로 표시하고 실제 빌드 일치는 별도 배포 근거로 확인한다.

원시 비밀번호·토큰·쿠키·개인정보는 입력부터 넣지 않는다. 알려진 필드만 받는 파서와 이메일·IPv4·인증 헤더 패턴 검사도 두지만 임의 문자열의 모든 개인정보를 자동 식별한다고 보장하지 않는다. 오류 출력은 원문과 경로를 되풀이하지 않는다. JSONL이나 외부 회고 원문은 커밋하지 않는다.

검증 경로는 `pnpm check`의 단위 시험과 `pnpm test:authz`가 실행하는 `tools/participation.integration.test.ts`다. 통합 시험은 현재 `buildServer`를 loopback 임시 포트에 올리고 실제 전용 PostgreSQL로 CLI를 실행한다. 게임 월드·계정·세션을 만들거나 초기화하지 않으며 전후 테이블 건수도 대조한다. 도구 시험 성공은 실제 5명 기수의 성공 증거가 아니다.
