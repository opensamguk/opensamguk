# T2-18 독립 에이전트 참가 시험 1기와 버그 정리

> 대기열: T2-18 · AC: AC-M2-12, AC-M2-13 · 구현: 사용자 (대기열 칸 유지) · 판정 리뷰: 참가자를 운영하지 않은 쪽
> 선행: T2-01~T2-17, T2-19~T2-23 · 결정: [D-021](../product/decisions.md#d-021-지인-참가-시험을-독립-에이전트-참가-시험으로-바꾸고-공개를-승인한다-2026-10-21) · 기록 형식: [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험)

## 계획 (Claude)

### 목표

- 계정·세션이 서로 다른 독립 에이전트 참가자 5명 이상이 실제 화면이나 HTTP로 월드 2개에 참가해 한 기수(합의한 기간)를 진행한다. 오류 때문에 상태를 되돌린 일이 0번이고 참가자별 행동·결과·피드백이 목록으로 정리된다 (AC-M2-12).
- 시험이 끝날 때 치명(P0) 버그가 0건이고 중대(P1) 버그는 전부 담당 AC나 백로그에 연결된다 (AC-M2-13).

### 범위

이 계획은 시험 방법과 증거 형식만 정한다. 제품 코드, 시험 실행, 인수 판정, 배포는 이 문서가 하지 않는다. 참가 에이전트 배정과 실행 일정은 총괄(opensamguk-lead)이 정한다.

### 하지 않는 것

NPC나 같은 에이전트의 병렬 요청으로 참가자 수 채우기, 진행 중 기간 줄이기, 관리자 권한이나 DB 수정으로 참가자를 진행시키기, 운영 데이터 초기화, 새 유료 서비스 사용.

### 참가자 기준

| 항목 | 기준 |
| ---- | ---- |
| 인원 | 5명 이상. 두 월드 모두에 참가자가 있다. 월드별 인원은 시작 전에 적는다 |
| 독립 | 계정, 로그인 세션, 에이전트 세션이 모두 참가자마다 다르다. 한 에이전트 세션이 여러 계정을 돌리면 한 명으로 센다 |
| 경로 | 실제 웹 화면이나 플레이어용 HTTP API. 관리자 API와 DB 직접 수정은 참가 행동이 아니다 |
| 개인정보 | 실제 이메일·비밀번호·토큰·쿠키·IP를 기록에 넣지 않는다. 계정은 `accountRef`로만 적는다 |

### 진행 순서

1. 시작 전에 아래 구현 기록에 `sourceSHA`(필수 CI를 통과한 정확한 커밋), 두 월드의 `worldId`·시나리오·턴 간격·프리셋, 기수의 끝 조건(천하통일 또는 종료 연도, A17)과 기간, 참가자 목록을 적는다. 시작한 뒤 기간과 끝 조건을 바꾸면 완주로 세지 않는다.
2. 참가자마다 가입·로그인 → 로비에서 월드 참가 → 장수 생성 → 예턴 입력을 한다. 그 뒤 기수가 끝날 때까지 각자 판단해 플레이한다. 행동과 결과를 [테스트 정책 §6](../testing-policy.md#6-독립-에이전트-참가-시험)의 필드로 남긴다.
3. 오류로 DB 복구, 상태 수정, 재생 초기화를 했다면 한 번으로 센다. 1번 이상이면 AC-M2-12는 통과하지 않는다.
4. 월드마다 기수 끝 증거(종료 화면의 승자와 연도, 최종 상태 해시)를 남긴다.
5. 결함을 P0·P1·P2로 나눠 이슈 목록을 만든다. P0은 고쳐서 0건으로 만든다. P1은 담당 AC나 [백로그](../product/backlog.md)에 연결한다.
6. 참가자별 피드백을 한 목록으로 묶어 회고로 정리한다.

### 검증

- AC-M2-12: 테스트 회고 문서. 아래 구현 기록의 참가자 표, 월드 표, 되돌림 횟수, 피드백 목록과 원본 기록 SHA-256.
- AC-M2-13: 이슈 목록. 결함마다 등급, 보고 참가자, `worldId`, `sourceSHA`, 연결한 AC나 백로그 항목.
- 참가자를 운영하지 않은 쪽이 원본 기록과 요약을 대조한다. 그 리뷰가 끝나야 AC를 통과로 표시한다. 하지 않았거나 일부만 한 시험은 미착수나 진행 중으로 둔다.

### 상대 영역에 필요한 것

참가자가 쓸 기능(가입, 로비, 장수 생성, 예턴, 메시지, 알림)은 선행 작업이 만든다. 참가자 계정을 만들 때 시험용 메일함이나 별칭을 써서 실제 개인정보가 기록에 남지 않게 한다.
