# T2-04 로비 화면

> 대기열: T2-04 · AC: AC-M2-02 (화면) · 구현: Claude · 리뷰: Codex
> 선행: T2-03 (API) · 결정 제안: [D-025](../product/decisions.md#d-025-가오픈-월드의-장수-생성과-월드-총정원-2026-10-21) (사용자 승인 대기)

## 계획 (Claude)

### 목표

로그인 뒤 로비에서 월드 목록(상태·시나리오·턴 간격·인원·시작일)을 보고 참가한다 (AC-M2-02).

### 범위

- `apps/web`: `/lobby` 주소, 위쪽 띠에 `로비` 링크.
- 로그인 뒤 이동: 안전한 `next`가 있으면 그 주소가 먼저다. 없을 때만 `/lobby`로 간다 (T1-14의 첫 RUNNING 월드로 보내기를 대신함).
  `AuthForm.tsx:33`의 `safeNext(next) ?? '/'`에서 기본값만 `/lobby`로 바꾼다. `credentials.ts:39-44`의 열린 리다이렉트 차단과 `router.tsx:77-82`의 직접 주소 복귀는 그대로 둔다.

### 하지 않는 것

월드 만들기(M3), 월드 상세 페이지(카드 안 요약으로 충분).

### 화면

```text
┌ 공지 (lobby.notices, 최신 1개 펼침) ─────────────────────────┐
├ 월드 카드 ────────────────────────────────────────────────────┤
│ [진행 중] 정규 1월드 · 군웅할거(191) · 193년 4월               │
│ 턴 60분 · 장수 34/— · 시작 10/18                               │
│ 내 장수: 조운 (공손찬)                     [들어가기]          │
├────────────────────────────────────────────────────────────────┤
│ [가오픈] 속성 2월드 · 공백지(180) · 턴 10분 · 장수 3/10 · 시작 전│
│                                            [장수 만들기]       │
└────────────────────────────────────────────────────────────────┘
```

- 공지는 서버 순서(`publishedAt` 최신 순, 같으면 id 내림차순, T2-03)대로 놓고 첫 줄만 펼친다. 화면이 다시 정렬하지 않는다.
- 상태는 글자와 색을 함께 쓴다 (색만으로 구분하지 않음). 글자는 `진행 중`, `가오픈`, `멈춤`, `끝남`이다. M2 화면은 `includeEnded`를 부르지 않으므로 `끝남`은 응답에 ENDED가 올 때를 위해서만 정해 둔다.
- 시작일: `startedAt`이 있으면 `시작 10/18`처럼 월/일로 쓴다. null(아직 시작하지 않은 가오픈)이면 `시작 전`이라고 쓴다.
- 프리셋 이름: `presetName`이 null(T2-02 전에 만든 월드)이면 그 칸을 그리지 않는다.
- 정원: D-025 승인 전에는 응답에 `maxHumanGenerals` 키가 없고 `장수 34`처럼 인원만 쓴다. 승인 뒤 키가 있으면 `장수 3/10`, 값이 null이면 `장수 34/—`처럼 쓴다. null일 때 생성은 서버가 이유와 함께 막는다.
- 위 그림의 가오픈 카드는 D-025 승인 뒤 모습이다. 승인 전 가오픈 카드는 막힌 `장수 만들기`와 `아직 열리지 않은 월드입니다`를 보인다 (T2-03 판정 표 3a번 줄).
- 버튼은 `auth.me`와 `myGeneral`, `createBlockedReason`만 보고 고른다. 상태로 버튼을 추측하지 않는다.

| `auth.me` | `myGeneral` | `createBlockedReason` | 버튼 |
| --------- | ----------- | --------------------- | ---- |
| 로그인 | 있음 | null | `들어가기` (`/w/:id`). 멈춤 월드도 연다 |
| 로그인 | null | null | `장수 만들기` (`/w/:id/create`). D-025 승인 뒤에는 가오픈 월드도 여기에 온다 |
| 로그인 | null | 이유 | 막힌 `장수 만들기`와 그 이유의 `DisabledReason` (예: `인원이 찼습니다`, `장수를 만드는 중입니다`) |
| 무인증 | null | null | `로그인하고 참가` (`/login?next=/lobby`) |
| 무인증 | null | 이유 | 막힌 `로그인하고 참가`와 그 이유 |

- 로그인 안 한 사람도 목록을 본다. 무인증과 로그인한 미참가자는 `myGeneral`이 둘 다 null이라 `auth.me`로 가른다.
- D-025 승인 뒤 가오픈 월드에 장수를 만들고 들어가면 메인과 개인 예턴 편집이 열린다. 턴은 `world:start` 뒤부터 돈다. 서버 쪽 근거와 다음 턴 시각 null 처리는 T2-03 판정 절의 가오픈 월드 메인 줄에 있다. T1-15 편집기와 T1-16 메인이 다음 턴 시각 null을 `시작 전`으로 그리는지 이 작업에서 확인한다.
- 월드가 0개면 `EmptyState`, 목록을 못 받으면 `ErrorState`와 다시 시도. 둘을 섞지 않는다.

v1과 다르게 정한 것:

- v1은 월드 상태와 내 참가 여부를 칩 하나로 합쳤다 (참가 중·마감·모집 중, `lobbyEntry.ts:50-64`). 새 화면은 상태 칩에 월드 상태만 쓰고 내 참가 여부는 버튼이 맡는다.
- v1은 준비 중이거나 점검 중이면 입장을 막았다 (`ServerCard.tsx:74-80`). 새 화면은 `myGeneral`과 `createBlockedReason`만 보고 버튼을 그린다. 멈춤 월드도 내 장수가 있으면 `들어가기`가 열린다.
- 가오픈 월드의 사전 생성은 D-025 제안이고 아직 승인되지 않았다. 지금 `general.create`는 RUNNING 월드만 받는다(`apps/server/src/routers/general.ts:37`). 화면은 승인 여부와 관계없이 서버가 준 `createBlockedReason`만 따른다.

v1에는 있으나 범위 밖:

- 서버 거르기 칩 (`LobbyScreen.tsx:46-58`). ENDED는 기본 숨김으로만 다룬다.
- 기수 칩, 통일 칩, 따라잡기 배속 칩 (`ServerCard.tsx:101-104`)
- 세력 수와 NPC 수 (`ServerCard.tsx:111`)
- 내 장수 초상 (`ServerCard.tsx:117-124`)
- 현황 펼치기의 지도 미리보기·세력 현황·천하 정세 (`ServerCard.tsx:129-145`)
- 공지 고정 표시와 더 보기 (`NoticeBoard.tsx:61,71`)
- 로비 각주 두 줄 (`LobbyScreen.tsx:12-15,72-76`)

## 구현 기록 (Claude)

- 바꾼 것:
  - `apps/web/src/lobby/`: `LobbyPage.tsx`(공지판, 월드 카드, 버튼), `lobbyView.ts`(상태 글자와 색, 시작일, 인원, 버튼 고르기 `lobbyAction`), `contract.ts`(T2-03 응답 타입과 조회), `lobby.test.tsx`.
  - `router.tsx`: `/lobby` 주소를 더했다. 로그인한 `/`는 첫 RUNNING 월드 대신 `/lobby`로 보낸다. 로그인 안 한 `/`는 지금처럼 `/login`이다. 쓰지 않게 된 `pages/HomePage.tsx`는 지웠다.
  - `AuthForm.tsx`: `safeNext(next) ?? '/lobby'`. `safeNext`와 직접 주소 복귀는 그대로다.
  - `GameLayout.tsx`: 위쪽 띠 맨 앞에 `로비` 링크 한 줄.
  - `e2e/lobby.spec.ts`를 새로 쓰고 `/`가 첫 월드로 간다고 본 `e2e/main.spec.ts` 1건과 `e2e/auth.spec.ts` 1건을 로비 기준으로 바꿨다.
  - 채울 문서: `docs/frontend-ui-guidelines.md` §4 주소 표, 로그인 가드, 로비 절. `docs/user/index.md`의 첫 접속 단계는 계획대로 T2-17에서 쓴다.
- 계획과 달라진 점과 이유:
  - T2-03 API가 main에 없다. main의 `world.list`(T1-20)는 로그인해야 부르고 RUNNING 월드의 id·이름·상태만 준다. 시나리오·인원·시작일·생성 판정·공지가 없어 카드를 채울 수 없다. 그래서 응답 타입은 `contract.ts` 한 파일에 두고 `lobby.worlds`·`lobby.notices`를 이름으로 부른다. `AppRouter`에 들어오면 `trpc.lobby.*.queryOptions()`로 바꾸고 이 파일을 지운다. `auth.me`, `/w/:id`, `/w/:id/create`, `/login`은 실제 타입을 쓴다.
  - D-025는 승인 전이라 구현하지 않았다. 화면은 `maxHumanGenerals` 키가 오면 그리는 자리만 있고 버튼은 서버가 준 `createBlockedReason`만 따른다.
  - 공지가 0개면 공지 칸을 그리지 않는다. 계획에 빈 공지 모습이 없고 빈 상자를 두면 월드 목록이 밀린다.
  - 다음 턴 시각 null 확인: 위쪽 띠는 PREOPEN에서 `개시 전`, 장수 정보 칸의 다음 턴은 `—`를 쓴다. 계획의 `시작 전`과 다르다. 가오픈 장수가 생기는 D-025 승인 뒤의 일이라 이 작업에서는 고치지 않았다.
- 검증 결과:
  - `pnpm vitest run apps/web/src/lobby`: 15개 통과. 버튼 표 5줄, 상태 4종 글자와 색(`끝남` 포함), 시작일과 `시작 전`, 정원 키 없음·있음·null, 내 장수와 재야, 카드 링크 주소, 공지 첫 줄 펼침과 하나만 열기.
  - `pnpm check` (2026-10-23): generate·lint·`lint:text --strict`·format·typecheck 통과. 단위 시험은 이 Mac에 다른 세션이 몰려 부하 평균이 800까지 오른 동안 손대지 않은 `tools/`·`apps/engine` 시험 몇 개가 5초 제한에 걸렸다 (돌릴 때마다 다른 시험). `pnpm vitest run --testTimeout 60000`으로 83개 파일 581개 전부 통과.
  - E2E (2026-10-23, 전용 DB `opensamguk_t204_test`, `CI=1 pnpm e2e` 30개 골라 실행): 28개 통과, 2개 실패.
    - 통과: 로그인 뒤 이동 3건(`next=/w/1/turns` → 그 주소, `next` 없음 → `/lobby`, `next=//evil.example` → `/lobby`), 로그인한 `/` → `/lobby`, `auth.spec.ts` 11건, `routes.spec.ts` 12건, `smoke.spec.ts`.
    - 실패: 로비 흐름과 무인증 목록 2건. 둘 다 `lobby.worlds`가 HTTP 404 NOT_FOUND다 (T2-03 미구현). 가오픈·상태 시험 2건은 같은 이유로 돌리지 않았다. 로비 카드를 그리는 E2E는 T2-03이 main에 들어온 뒤 다시 돌려야 증거가 된다.
