## 계획 (Claude)

### 목표

AC-M1-14의 이 명령 몫이다. 원작 `nation:che_무작위수도이전`에 대응하는 확장 국가 명령 `nation_random_capital`이 켠 월드에서 사용권이 남은 국가의 군주가 연속 예약으로 실행해 규모 5·6 빈 도시 하나로 수도를 옮긴다. 옛 수도는 빈 도시가 되고 국가 장수 전원이 새 수도로 간다. 성공 1건과 대표 실패 1건 단위 시험이 있고 같은 시드면 결과가 같다. HTTP 이후 단계 증거는 T4-50·T4-51 뒤 같은 ID 아래에서 받는다.

### 하지 않는 것

- 사용권을 주는 명령. 원작에서는 `general:che_무작위건국`만 준다(`general/che_무작위건국.ts:166-171`). 그 명령은 미해결 원본 UQ-3이며 새 작업 ID는 총괄이 정한다.
- 준비 턴 기제(연속 칸 판정, 중단, 재생). T4-07이 맡는다. 이 명령은 준비 턴 수 1을 T4-07 계약 모양으로 선언만 한다.
- 국가 예턴 직책 칸과 권한 표(T2-05), 화면(T4-51, 인자가 없어 목록 표시만), NPC 판단(C11).
- 도시 관직 해제. 원작은 옛 수도의 관직 설정(`officer_set`)을 지운다(`:134-145`). 우리 도시 관직 상태는 T3-09·T3-16 몫이며 그 상태가 main에 있으면 쟁점 R5로 맞춘다.

### 3. MQ-4 제안 묶음 (결정 아님)

MQ-4는 [누락 명령 문서 7절](./mvp-command-gaps.md#7-소유자-질문-묶음)의 질문이다. UQ-3과 U-04(국기 변경권)를 같은 묶음으로 묻는다. 권장 열은 계획 쪽 의견이다.

| ID | 선택지 | 권장 | 이유 |
| -- | ------ | ---- | ---- |
| MQ-4 사용권 | (가) UQ-3 (가)로 무작위 건국을 확장 명령으로 만들고 그 명령이 1을 준다 (나) 켠 월드의 모든 국가가 시작할 때 1을 받는다 (다) 초반 기간에 건국·거병한 국가가 1을 받는다 (라) T4-71과 UQ-3을 함께 MVP 범위에서 뺀다(D-022 정정, 결정 기록 먼저) | (다) | 원작의 뜻은 초반에 막 세운 국가가 자리를 한 번 바꾸는 것이다. 우리 `found`·`uprising`이 같은 자리를 차지한다. (가)는 새 명령 하나가 더 필요하다 |
| Q2 초반 기간 | (가) 원작처럼 시작 뒤 2년 (나) 프리셋 `protection.foundUntilMonths`와 같게 (다) 프리셋에 새 칸 | (가) | 프리셋의 건국 보호는 반대 뜻(초반에 건국을 막음)이라 같은 값을 쓰면 겹친다 |
| Q4 | (가) +10·+10을 그대로 (나) 주지 않는다 | (가) | 원작 값이 작고 우리 내정 경험과 같은 자리다. U-19에서 다른 값이 정해지면 따른다 |

MQ-4 (다)를 고르면 사용권을 주는 곳이 `found`·`uprising` 실행 결과다. 기본 37개를 고치지 않으려면 조각의 `create`가 아니라 실행 뒤 처리가 필요하다. 그 방식은 쟁점 R1이다.

### 4. 기술 계약 초안 (Codex 계획 기술 검토 전)

#### 4.1 정의

| key | name | category | target | args |
| --- | ---- | -------- | ------ | ---- |
| `nation_random_capital` | 무작위 수도 이전 | `nation` | `nation` | `noArgs` |

국가·도시·장수 위치를 바꾸므로 `defineCommand`로 `{ kind: 'world' }` 효과를 낸다. `defineCommand`의 국가 명령은 지금 군주 검사(`commands/support.ts:20-26`, `:40`)를 거치며 원작 `beLord`와 같다. T2-05가 권한 표를 들이면 이 명령의 행은 군주만이다.

#### 4.2 사용권 조각

| 항목 | 계약 |
| ---- | ---- |
| key | `nation_random_capital` |
| 값 | `{ uses: { [nationId: string]: number } }`. 값은 0 이상 정수. 없는 국가는 0이다 |
| `create(context)` | MQ-4 (나)면 `context.nations`마다 1. 그 밖에는 `{ uses: {} }` |
| `validate` | 키가 양의 정수 문자열이고 값이 0 이상 정수 |
| `clone` | 깊은 복사 |

국가가 멸망하면 그 키는 남아도 읽히지 않는다. 지울지는 T4-02 조각 계약과 같이 쟁점 R4다.

#### 4.3 검사 순서와 실패

| 순서 | 조건 | code | 이유 |
| ---- | ---- | ---- | ---- |
| 1 | 장수 없음, 인자 형식, 국가 없음, 군주 아님 | `NO_ACTOR`, `BAD_ARGS`, `NOT_NATION`, `NOT_RULER` | `defineCommand`와 `ruler` |
| 2 | 행위자 도시가 자기 국가 도시가 아님 | `NOT_OWN_CITY` | 자기 국가 도시에서만 가능합니다. |
| 3 | 행위자 도시 보급 끊김 | `NO_SUPPLY` | 보급이 끊긴 도시입니다. |
| 4 | 초반 기간이 지남 (Q2) | `BAD_STATE` | 초반에만 쓸 수 있습니다. |
| 5 | 사용권 0 | `BAD_STATE` | 수도를 옮길 권리가 남지 않았습니다. |
| 6 | 후보 없음 | `BAD_TARGET` | 옮길 수 있는 빈 도시가 없습니다. |

2·3은 `ownCity`(`support.ts:11-19`)와 같은 문구다. 6번은 원작에서 실행 단계 결과다. 후보는 상태만 읽는 계산이라 검사로 옮긴다(쟁점 R2). 원작 4번 실패 문구는 뜻이 반대로 적혀 있어(`misc.ts:43`, 초반이 지났는데 `초반 제한 중`) 옮기지 않는다.

#### 4.4 준비 턴

U-01 결정(D-027)대로 같은 명령을 연속 칸에 예약해야 실행한다. 준비 턴 수는 Q3 결정 전에는 원작 값 1을 상수 `PREPARE_TURNS = 1`로 둔다. 몇 번째 칸인지 세는 방법, 중간에 다른 명령이 끼면 다시 세는 규칙, 국가 예턴이 직책별 12칸(T2-05)일 때 어느 칸을 세는지는 T4-07의 계약이다. 이 명령은 T4-07이 정한 모양으로 준비 칸 수만 낸다(쟁점 R3).

#### 4.5 실행

`change(state, actor)`가 아래 순서로 바꾼다.

1. `candidates = randomCapitalCandidates(state)`: `nationId === null`이고 `level`이 5 또는 6인 도시 `cityKey` 오름차순.
2. `dest = rng.pick(candidates)` 한 번.
3. `old = nation.capitalCityKey`. `nation.capitalCityKey = dest`, `cities[dest].nationId = 국가`, `cities[old].nationId = null`.
4. `generals` 가운데 `nationId === 국가`인 장수 전원의 `cityKey = dest`.
5. 사용권 `uses[국가] = (uses[국가] ?? 0) - 1`. 검사 5번이 1 이상을 보장하므로 결과는 0 이상이다.
6. Q4 (가)면 행위자 `experience += 10`, `dedication += 10`.
7. `refreshSupply(state)`(`supply.ts:4-20`). 옛 영토가 새 수도와 이어지지 않으면 보급이 끊긴다. 원작과 같다.

옛 수도의 인구·내정·성벽은 그대로다. 옛 수도에 남아 있던 다른 국가 장수는 움직이지 않는다.

#### 4.6 로그와 기록

| 출력 | 문구 |
| ---- | ---- |
| `logs` | `{새 도시}로 수도 이전` |
| `history` (자기 국가) | `{행위자} {새 도시}로 무작위 수도 이전` |
| `reports` (4번에서 실제로 옮긴 같은 국가 장수 가운데 행위자 밖의 각 장수) | `국가 수도가 {새 도시}로 옮겨 그곳으로 이동했습니다.` |

보고는 엔진이 수신 장수 기록으로 저장한다(`apps/engine/src/commandPersistence.ts:100`). 움직이지 않은 다른 국가 장수에게는 보내지 않는다.
