## 0. 이 문서의 위치

명세 C17은 방랑 국가 표식, 수도 표현, 소속 장수 위치, 보급과 월간 수입, 점령·멸망 처리, 통일 판정, 도시 재획득·해산 조건, DB 저장과 `worldLoader` 복원을 이 계획이 정하라고 했다. 이 문서는 그 가운데 기술 계약을 정하고 규칙 선택은 U-21 세부 질문으로 남긴다.

방랑 표식은 다른 작업의 계약 선행이기도 하다. T4-62 전투태세, T4-63 맹훈련, T4-67 물자조달, T4-69 접경귀환은 원작이 방랑 국가를 거절하는 명령이다([누락 명령 문서](./mvp-command-gaps.md) 4절 [방랑]). T4-15의 해산도 원작에서는 방랑 국가만 할 수 있다(아래 1절). 그래서 표식과 그것을 읽는 함수(W1·W2)는 U-21 답과 상관없이 먼저 계약할 수 있게 나눴다.

### 기술 계약

#### W1 표식

```ts
// packages/rules/src/commands/ext/wander/state.ts
// 조각 key 'wander'. 방랑 중인 국가만 담는다. 방랑 국가가 없으면 빈 객체다.
type WanderSlice = { nations: Record<string, { sinceTick: number }> }; // 키는 국가 id 문자열
```

- 조각은 방랑 명령을 켠 월드에만 생긴다(T4-02 `extCommandBindings`). 끈 월드에는 `ext.wander`가 없고 `ext` 키도 없다(C3).
- `create`는 `{ nations: {} }`다. 시나리오 시작 때 방랑 국가는 없다.
- `validate`는 키가 `state.nations`의 국가 id인지까지 보지 않는다. 조각 검사는 조각 값만 본다(T4-02 2.4). 국가와의 대조는 W5의 불변식 시험이 한다.
- 저장 가능 값 검사(T4-03 E7)를 `validate`에 넣는다. `sinceTick`은 0 이상 안전 정수다.

#### W2 방랑 판정 함수

```ts
// packages/rules/src/commands/ext/wander/query.ts
export function isWandering(view: WorldView, nationId: number | null): boolean;
```

- `view.ext?.wander`가 없으면 늘 false다. 끈 월드와 방랑 명령을 켜지 않은 월드의 모든 명령은 지금 결과와 같다.
- 국가 규모(`level`)를 읽지 않는다. 지금 `found`가 규모 0 국가를 만들기 때문이다(`personnel.ts:34`).
- T4-62·T4-63·T4-67·T4-69·T4-15는 이 함수만 import한다. 조각 모양을 직접 읽지 않는다.

#### W3 수도 표현

방랑 국가는 `state.nations`에 남고 `capitalCityKey`는 방랑 직전 수도 값을 그대로 둔다. 방랑 국가는 그 도시를 갖지 않는다.

- 이유: 모델과 DB 형식을 바꾸지 않는다. 수도를 읽는 곳 대부분이 이미 수도 소유를 확인한다(2절). 보급(`supply.ts:7-8`), 귀환(`military.ts:98-99`), 무작위 임관·등용 수락(`personnel.ts:62-75`, `:129-137`)이 방랑 국가를 자연히 걸러 낸다.
- 남는 곳: 천도(`nation.ts:144-147`)는 대상 도시가 자기 도시여야 하므로 방랑 국가에서 실패한다. 출병의 수도 함락(`attack.ts:154-157`)은 방랑 국가가 방어 측이 될 수 없어 닿지 않는다. NPC(`npc/index.ts:150`)는 NPC 군주 국가의 방랑을 만들지 않으므로(C11) 닿지 않는다. 구현 PR은 이 셋을 시험으로 고정한다.
- 대안 W3-2: `capitalCityKey: number | null`로 모델을 바꾼다. 읽는 곳 열 군데와 `worldLoader.ts:27`을 고쳐야 하고 명세 §7 모델 파일 순서(T4-02 → T4-49 → T4-48)를 탄다. Codex가 G-03에서 W3를 받지 않으면 이 대안으로 바꾸고 범위 표를 다시 쓴다.

#### W4 방랑 명령

장수 명령, 인자 없음. 확장 명령으로 등록하고 조각 `wander`에 결합한다.

| 검사 | 원작 근거 | 우리 판정 |
| ---- | --------- | --------- |
| 군주 | `che_방랑.ts:42-52` | `officerLevel === 12`. 실패 코드 `NOT_RULER` |
| 이미 방랑이 아님 | `notWanderingNation` | `!isWandering`. 실패 `BAD_STATE` |
| 초반 기간이 아님 | `notOpeningPart` | 원작의 초반 기간에 해당하는 우리 값이 없다. `presetRules.protection`의 기간을 쓸지는 U-21a |
| 외교 | `allowDiplomacyStatus([2, 7])` | 자기 국가와 `WAR`·`DECLARED` 관계가 하나도 없다. 실패 `BAD_STATE` |

실행 효과(원작 L98-193의 순서):

1. 소유 도시를 모두 공백지로 한다(`nationId = null`). 도시 수치는 바꾸지 않는다.
2. 자기 국가가 낀 외교 행을 지운다. 우리 모델에서 평시는 행이 없는 상태다(`world/bootstrap.ts:80`).
3. 군주 밖 소속 장수의 `officerLevel`을 1로 내린다. 장수 위치는 그대로다. 인사 기능을 켠 월드는 T2-05의 `syncOffices`를 불러 직책 칸을 비운다([T4-52](./T4-52.md) 쟁점 X4).
4. `ext.wander.nations[id] = { sinceTick: tick }`.
5. 국가 이름·색·기술을 바꿀지는 U-21d다. 답 전에는 바꾸지 않는다.
6. `refreshSupply(state)`를 부른다.
7. 국가 역사에 방랑 한 줄, 장수 로그에 성공 한 줄. 문구는 구현 PR이 글쓰기 규칙으로 쓴다.

- 국가를 지우지 않으므로 T4-56의 멸망 국가 보존(`apps/engine/src/nationArchive.ts`)은 불리지 않는다.
- 원작에서 방랑은 사용자 입력에 노출하지 않는 내부 명령이다(1절). AC-P2-08은 국가가 방랑을 고른다고 적었다. 사람 장수가 예턴으로 고를 수 있게 할지는 U-21a다. 답이 나기 전 규칙 PR은 명령 정의와 단위 시험까지만 하고 대응표 단계의 ui 증거를 받지 않는다.

#### W5 방랑 중 불변식

- 방랑 국가는 도시를 하나도 갖지 않는다. 방랑 국가가 도시를 얻는 길은 W6의 정착 하나다. 공백지 점령인 출병은 자기 국가 도시에서 떠나야 하므로(`attack.ts:37`) 방랑 국가 장수는 하지 못한다.
- 다른 국가가 공백지가 된 옛 도시를 출병으로 얻어도 방어 국가가 없으므로 방랑 국가는 바뀌지 않는다(`attack.ts:146` 갈래가 `defendingNation === null`).
- 소속 장수는 다른 국가 도시나 공백지에 남는다. 내정·징병·출병은 자기 국가 도시 검사(`support.ts:11-19`)에서 실패하고 이유가 장수 로그에 남는다. 기본 명령은 고치지 않는다.
- 월간: 도시가 없으므로 수입·봉급이 0이다(`monthly/index.ts:31-58`). 인구·보급·외교 단계도 도시와 외교 행이 없어 바꿀 것이 없다. 국고 금·쌀은 그대로 남는다.
- 엔진 시작 대조나 조각 쓰기 전에 `ext.wander.nations`의 키가 모두 `state.nations`에 있고 그 국가가 도시를 하나도 갖지 않는지 순수 함수 `assertWanderInvariant(state)`로 본다. 어기면 규칙 버그이므로 예외다. 이 함수는 W4·W6 실행 뒤 시험과 T4-03 엔진 턴 저장 직전에 부른다(쟁점 X4).

#### W6 재획득 (정착)

장수 명령, 인자는 기존 `found`와 같은 모양(`{ name, color }`, `personnel.ts:12`)이다. 조각 `wander`에 결합한다.

| 검사 | 원작 근거 | 우리 판정 |
| ---- | --------- | --------- |
| 방랑 국가의 군주 | `che_건국.ts:70-71` | `isWandering`이고 `officerLevel === 12` |
| 장수 수 | `reqNationGeneralCount(2)` | 소속 장수 2명 이상. 원작 값을 그대로 쓴다(C10 표) |
| 도시 | `constructableCity`(공백지이면서 규모 5·6) 또는 `cr_건국`의 `neutralCity` | 지금 장수가 있는 도시가 공백지. 도시 규모 조건을 둘지는 U-21b |
| 초반 기간 | `beOpeningPart` | U-21b |
| 이름 | `checkNationNameDuplicate` | 기존 `found`와 같은 이름 검사(`personnel.ts:19-20`) |

실행 효과: 그 도시를 자기 국가 도시로 하고 수도로 정한다. `ext.wander.nations[id]`를 지운다. 이름·색을 인자대로 바꾼다. `refreshSupply`. 국가 역사 한 줄. 국가 규모는 지금 `found`처럼 0으로 둔다(정상 국가의 규모 규칙은 바꾸지 않는다).

#### W7 해산과 자동 해산

- 수동 해산은 T4-15 몫이다. 원작은 방랑 국가의 군주만 해산한다(`che_해산.ts:51-53`). T4-15가 그 조건을 쓰면 `isWandering`을 읽고 실행 효과의 마지막에 조각에서 그 국가를 지운다. 국가 삭제는 `removeNation`(`support.ts:70-88`)을 쓴다. 그래서 T4-56 보존이 그대로 불린다.
- 자동 해산(원작 `monthlyWanderHandler.ts`)을 넣을지와 그 시점은 U-21c다. 넣으면 월간 정산에 확장 자리가 필요하다(쟁점 X3). 답 전에는 만들지 않는다.

#### W8 통일 판정

- 끈 월드와 방랑 국가가 없는 월드의 `unifiedNation` 결과는 지금과 같다. 방랑 국가가 하나라도 있으면 U-21 답의 식을 쓴다.
- 후보 (가): 방랑 국가는 판정에서 빼고 남은 국가가 하나이며 모든 도시가 그 국가 것이면 통일이다.
- 후보 (나): 방랑 국가가 남아 있는 동안은 통일이 아니다(지금 식 그대로). 이 경우 자동 해산(U-21c)이 없으면 방랑 국가 하나가 시즌 끝까지 통일을 막을 수 있다.
- 어느 쪽이든 `season.ts` 한 곳만 바꾸고 엔진 턴·재생·시뮬레이터가 같은 함수를 지난다.

#### W9 저장·재시작·재생

- 조각은 T4-03의 `WorldExtSlice` 한 행이다. 턴 저장(T4-03 E6)이 바뀐 조각만 쓰고 엔진 `loadWorld`와 서버 `readView`가 `restoreExtState`로 되살린다(T4-03 E5).
- 도시 소유·외교·관직 변화는 기존 `persistEffects` 경로로 저장된다. 방랑 국가 행은 지워지지 않으므로 `Nation.capitalCityKey`도 숫자로 남아 `worldLoader.ts:27`의 예외에 닿지 않는다.
- 재생은 T4-03 E9대로 `createCommandResolver(featureData.ext.commands)`로 방랑·정착을 실행한다. 이 작업이 재생 기록 형식을 바꾸지 않는다.
