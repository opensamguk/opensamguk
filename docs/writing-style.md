# 글쓰기 규칙

> 기준: [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai/tree/b37e0206d31fffd9149bf57168d4d62eb2086bee) (MIT), 커밋 `b37e020`의
> `skills/humanize-korean/references/quick-rules.md`. 결정은 [D-017](./product/decisions.md#d-017-모든-한국어-글은-im-not-ai-규칙을-따른다-2026-10-20).
> 이 문서는 우리 글에서 자주 걸리는 것만 줄여 옮겼다. 애매하면 원본 규칙을 따른다.

한국어로 쓰는 모든 글은 사람이 쓴 글처럼 읽혀야 한다. 번역투, 기계적인 대구, 꾸밈 장식이 AI 티를 낸다.

## 1. 적용 범위

- 문서: `docs/`, `AGENTS.md`, `README.md`, 작업 계획·구현 기록·리뷰
- 화면 문구: 버튼, 안내, 오류, 빈 상태, 툴팁, 도움말, 플레이어 가이드
- 게임 문구: 장수 로그, 국가·월드 기록, 사건 본문, 월단평 한 줄 평, NPC 말, 명령 결과, 서버 오류 메시지
- 커밋 메시지와 PR 본문
- 화면 장식 (§4)
- 사용자와의 대화, 코드 주석, 디자인·게임 요소와 생성 프롬프트 (§7)

## 2. 건드리지 않는 것

고유명사(인물·지명·관직·명령 이름), 수치·날짜·단위, 코드 식별자와 명령어, 사료 원문 인용, 표준 기술 용어(API, SSE, tRPC 등)는 고치지 않는다.

## 4. 화면과 문서의 장식

- 이모지를 쓰지 않는다 (C-5).
- 굵게는 경고나 꼭 봐야 하는 수치 한 곳에만 쓴다. 문장마다 굵게 하지 않는다 (J-1).
- 따옴표로 강조하지 않는다. 실제 인용과 화면 이름에만 쓴다 (J-2).
- 대시(—)로 부연하지 않는다. 쉼표, 괄호, 별도 문장으로 나눈다 (J-3).
- "X: Y" 콜론 부제를 반복하지 않는다 (C-10).
- 문서에서 산문으로 쓸 내용을 글머리표로 쪼개지 않는다 (C-2). 데이터 목록과 표는 그대로 둔다.
- "1) 2) 3)" 번호 나열보다 문장 안에서 잇는다 (C-9).

## 5. 고칠 때 지킬 것

- 서법을 바꾸지 않는다. "~해야 한다"를 "~한다"로, "~일 수 있다"를 단정으로 올리지 않는다. <!-- lint-text-ignore J-2 -->
- 내용 명사를 지우거나 동의어로 바꾸지 않는다. 덜어내는 것은 꾸밈말과 형식명사다.
- 원문에 없던 비유와 상투구를 새로 넣지 않는다.
- 격식 등급을 유지한다. 합니다체 문서는 합니다체, 해라체 문서는 해라체.
- 한 번에 고친 양이 원문의 30%를 넘으면 다시 본다.

## 6. 확인

- 쓴 사람이 §3·§4로 직접 본다. 리뷰어는 문구도 본다. §3의 원본 S1 패턴(A-7, A-8, C-5, C-10, C-11, D-1~D-3, J-2)이 남아 있으면 통과시키지 않는다.
- 자동 검사는 `pnpm lint:text`다. 위 S1 패턴 9개를 찾아 `파일:줄 [ID] 걸린 표현`으로 출력한다. 기본은 경고만 내고 성공하며 `pnpm lint:text --strict`는 1건이라도 있으면 실패한다(종료 코드 1, 사용 오류는 2). 경로를 주면 그 아래만 본다. 예: `pnpm lint:text docs/plans`
  - 대상은 `docs/**/*.md`, `AGENTS.md`, `README.md`와 `apps/web/src`의 문자열·JSX 텍스트, `packages/rules/src`와 `apps/server/src`의 한글 문자열이다. 테스트 파일과 코드 주석, `private/`는 보지 않는다.
  - 코드 블록, 인라인 코드, URL, 링크 주소, 표에서 경로만 든 칸은 건너뛴다. 코드 블록은 펜스 블록과 들여쓴 블록(4칸 이상)이며 인용(`>`)과 목록 안의 것도 포함한다. 코드 문자열·템플릿·JSX 속성 안의 URL도 그 부분만 건너뛴다.
  - D-1은 문서당 3회까지, J-2는 4회까지, C-10은 1회까지 허용한다. 번호 절(`1.`, `Ⅱ.`, `(3)`, `제2장`)과 콜론 앞이 ID뿐인 헤딩(`D-017: …`)은 C-10에서 뺀다. 발화 표지(말했다·밝혔다·따르면)가 붙은 따옴표는 J-2에서 뺀다.
  - 기계는 화면 이름 인용과 강조를 가리지 못한다. 규칙을 지킨 글이 걸리면 그 줄 끝에 예외를 적는다. 문서는 `<!-- lint-text-ignore ID -->`, 코드는 `// lint-text-ignore ID`(JSX 안에서는 `{/* lint-text-ignore ID */}`)이다. ID는 여러 개를 공백이나 쉼표로 이어 쓴다. 코드의 예외는 실제 주석에 적은 것만 인정하고 문자열이나 JSX 텍스트에 적은 것은 무시한다. 예외를 둔 곳은 문서당 횟수에서도 빠진다.
  - `pnpm check` 연결은 T1-23·T1-24가 기존 글을 고친 뒤 한다.
- Claude Code에서는 원본 스킬로 윤문할 수 있다: `/plugin marketplace add epoko77-ai/im-not-ai`, `/plugin install humanize-korean@im-not-ai`, 그 뒤 `/humanize`.
- Codex에는 같은 커밋의 `humanize-korean` 스킬을 설치했다. 다음 턴부터 `$humanize-korean`으로 사용할 수 있다. 별도 환경에서는 [Codex 설치 안내](https://github.com/epoko77-ai/im-not-ai/blob/b37e0206d31fffd9149bf57168d4d62eb2086bee/INSTALL.md#codex-cli)를 따른다.
- 기존 글을 스킬로 윤문할 때 변경률은 스킬의 검증 스크립트로 측정한다. Codex 스킬 기준 30% 이상이면 경고하고 50% 이상이면 결과를 채택하지 않고 되돌려 한 번 재실행한다. 수치·조건·부정·추측·의무의 의미가 달라졌으면 변경률과 관계없이 되돌린다.
- 패턴은 장르·빈도·문맥을 함께 본다. 예를 들어 A-1의 "~에 대해"는 기본 보존이며 한 문단 3회 이상 밀집할 때만 검토한다. 특정 단어가 있다는 이유만으로 일괄 치환하거나 리뷰를 반려하지 않는다. <!-- lint-text-ignore J-2 -->

## 7. 디자인과 게임

원본 스킬은 한글 윤문 도구다. 아래는 사용자가 요청한 적용 범위에 맞춰 이 프로젝트에서 확장한 기준이다. 새 요소와 수정하는 요소를 기획·구현·리뷰할 때 적용한다.

화면 구성, 타이포그래피, 색, 이미지, 아이콘, 애니메이션과 소리는 플레이어가 상태를 읽고 행동을 고르는 데 어떤 역할을 하는지 설명할 수 있어야 한다. 삼국지의 인물·시대·상황과 기존 화면의 표현을 참고한다. 범용 템플릿을 그대로 붙이거나 의미 없는 장식을 보태지 않는다. 일관된 조작, 가독성, 접근성, 필수 경고는 유지한다.

게임의 이름, 인물의 말투, 사건, 보상, 규칙과 콘텐츠는 누가 어떤 상황에서 무엇을 선택하고 어떤 결과를 겪는지 구체적으로 쓴다. 인물의 대사와 시스템 안내는 각각의 쓰임에 맞춘다. 개성을 만들려고 근거 없는 설정·수치·기능을 덧붙이거나 일부러 오류·불규칙함을 넣지 않는다. 표현을 다듬는 과정에서 밸런스, 확률, 비용, 조건, API 계약을 바꾸지 않는다. 규칙 변경은 기존 AC·계획·승인 절차를 따른다.

생성 프롬프트에도 대상, 맥락, 실제 용도, 보존할 조건을 명시한다. 결과물은 위 기준과 원본 의미를 대조해 검토한다. 문맥에 맞는 반복·문체·양식은 보존한다.
