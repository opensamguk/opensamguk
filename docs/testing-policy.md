# 테스트 정책

> 상태: 뼈대 · 필요 시점: M1 · 참고: core2026 `docs/testing-policy.md`, `integration-tests.md`, `architecture/npc-unification-timing-benchmark.md`

## 1. 원칙

- 테스트는 AC의 증거입니다. AC마다 어떤 테스트가 증거인지 [인수조건](./product/acceptance-criteria.md)에 적습니다.
- 시계, 시드, fixture를 고정합니다. 테스트에서 현재 시각과 `Math.random()`을 쓰지 않습니다.
- skip된 테스트, 환경이 없어 건너뛴 통합 테스트, mock만으로 한 검증은 통과로 세지 않습니다.
- 원작과 1:1 비교는 하지 않습니다 (D-001). 대신 **우리 자신과의** 재생 일치를 검사합니다.

## 2. 테스트 종류

| 종류         | 대상                              | 도구        | 실행 |
| ------------ | --------------------------------- | ----------- | ---- |
| 단위         | `packages/rules`, `packages/shared` | Vitest    | `pnpm check` |
| 골든         | 월간 정산 등 순서가 중요한 계산   | Vitest + 스냅샷 | `pnpm check` |
| 재생         | 시드 + 입력 기록 → 같은 상태 해시 | Vitest      | `pnpm check` |
| 통합         | 실제 PostgreSQL 트랜잭션, 리스, 재적재, 권한 | Vitest + Docker DB | `pnpm test:int` |
| 시뮬레이션   | NPC만으로 한 판                   | 헤드리스 시뮬레이터 | `pnpm sim` |
| E2E          | 화면 흐름                         | Playwright  | `pnpm e2e` |
| 부하         | 서비스 성능 (M3)                  | 미정        | 별도 |

## 3. 권한 테스트

API마다 다섯 가지를 확인합니다 (NFR-05).

- [ ] 성공
- [ ] 로그인 안 함
- [ ] 다른 사용자의 장수·국가
- [ ] 제재된 계정
- [ ] 잘못된 입력과 경계값

M3 전에 API 목록과 권한 테스트 목록을 자동으로 대조합니다 (AC-M3-03).

## 4. 시뮬레이션 기준

core2026 측정값을 참고합니다. 장수 880명·도시 94개를 NPC만으로 무보정 진행하면 747개월(약 62년)에
통일했고 메모리 안 계산으로 약 470초가 걸렸습니다 (2026-08-15, Ryzen 7 9800X3D).

우리 기준(AC-M1-17·18, 가정 A18)은 10개 시드 전부 오류 없이 완주, 1판 15분 이내입니다.

`pnpm sim --seeds 10`은 시드 문자열 `1`부터 `10`까지 차례로 실행합니다.
기본 리소스는 시나리오 `1030`, 지도 `che`의 94도시입니다. 종료 연도는 절대 연도 300이며
그해 12월 정산까지 진행합니다. 국가가 하나여도 중립 도시가 남으면 통일로 세지 않습니다.
모든 도시를 한 국가가 소유하면 그 장수 턴에서 멈춥니다. 종료 연도 도달과 통일은 별도로 표시합니다.

```sh
pnpm sim --seeds 10 --output simulation.jsonl
pnpm sim --seed 1 --repeat
pnpm sim --seed 1 --repeat --convergence off
pnpm sim --seeds 10 --scenario 1030 --max-year 300
```

표준 출력은 시드당 JSON 한 줄입니다. 시드·시나리오·도시 수·초기 장수 수, 수렴 보조 여부,
종료 연도 설정, 결과, 마지막 연월, 승자 ID와 이름(종료 연도 도달이면 `null`), 남은 국가 수,
장수 턴 수, 소요 초, 최종 규칙 상태 해시, 실행한 장수 명령별 횟수를 담습니다.
하드웨어와 Node 버전은 표준 오류로 출력합니다. `--output`은 결과를 JSONL 파일에 덧붙입니다.
기존 파일을 다시 쓰면 결과가 누적되므로 시드 수를 셀 때 반복 실행과 이전 실행을 구별합니다.

`--repeat`는 각 시드를 두 번 실행해 최종 상태 해시와 장수 턴 수를 대조합니다.
각 판이 900초를 넘거나 명령 실행·반복 해시 검사가 실패하면 종료 코드 1을 반환합니다.
시드 선택과 `--seeds`는 함께 쓸 수 없습니다. `--max-year`는 진단용으로 바꿀 수 있으나
AC-M1-17·18 증거는 기본 종료 연도 300과 전체 리소스를 사용합니다.
단위 시험의 짧은 실행이나 작은 장수 집합은 10시드 완주 증거에 넣지 않습니다.

수렴 보조는 기본 ON입니다. 게임 시작 50년 뒤부터 소유 도시 수만큼 출병 후보 점수를 더합니다.
`--convergence off`는 이 점수 보정만 끕니다. 명령 비용·피해식·월간 정산·RNG 스트림은 바꾸지 않습니다.
후보에는 실제 명령의 인자 검사와 `check`를 통과한 명령만 들어갑니다.
NPC 장수와 NPC 국가의 빈 슬롯(`rest`, `nation_rest`)만 판단으로 채웁니다.
사람 장수와 사람 군주, NPC가 따로 지정한 비휴식 명령은 대신 두지 않습니다.

메모리 실행기는 `apps/engine/src/simulation.ts`에 있습니다. DB 턴 실행·입력 재생과 같은
`runGeneralTurn`, `runMonthly`를 사용하며 월 경계보다 앞선 장수 턴을 tick·ID 순으로 실행합니다.
파일 읽기·시간 측정·상태 해시는 규칙 패키지 밖에서 처리합니다. DB 저장과 로그 쓰기 비용은
이 시간에 포함하지 않습니다. 실제 PostgreSQL의 NPC 저장·사람 휴식·12개월 재생·롤백·펜싱은
`apps/engine/src/npc.integration.test.ts`에서 별도로 검증합니다.

## 5. 통합 테스트 준비

```sh
pnpm db:up
pnpm test:int
```

`tools/run-integration.ts`가 전용 DB를 만들고 migration을 적용한 뒤 테스트를 실행합니다.
기본 대상은 같은 PostgreSQL의 `opensamguk_test`입니다. 다른 대상은 `.env`의 `TEST_DATABASE_URL`로 지정합니다.
DB 생성 권한이 없으면 해당 계정의 전용 테스트 DB를 먼저 준비해야 합니다.

테스트 DB 이름은 소문자·숫자·밑줄로 구성하고 `_test`로 끝나야 합니다.
개발 `DATABASE_URL`과 호스트·포트·DB 이름이 같으면 시작 전에 거부합니다.
테스트는 이 전용 DB의 월드 데이터를 시작·종료 시 지웁니다. 개발 DB는 비우지 않습니다.

통합 파일은 `*.integration.test.ts`이며 `pnpm check`의 단위 테스트에서 제외합니다.
DB가 없거나 migration·테스트가 실패하면 명령이 실패하고 skip으로 통과시키지 않습니다.
