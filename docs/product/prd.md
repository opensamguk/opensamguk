## 한 줄 요약

여러 사람이 장수 한 명씩을 맡아 나라를 키우고 천하를 다투는 **턴 예약형 삼국지 웹 전략 게임**이다.
원작 「삼국지 모의전투」의 검증된 핵심 루프를 새 코드로 단순하게 다시 만든다. 그리고 원작이 사람 손에
맡겨 둔 **협업·외교·입문의 불편**을 게임 기능으로 풀어 차별화한다.

## 1. 배경

### 1.1 원작

devsam의 [core2026](https://gitea.hided.net/devsam/core2026)은 PHP 원작 sam을 TypeScript로 옮긴
모노레포다(MIT, © 2025 devsam). TS·Vue 파일 1,617개, 약 37.5만 줄이다. 장수 명령 55개, 국가 명령 35개,
시나리오 60여 개, 문서 53개를 가진다. 상당 부분은 원작과 동작을 1:1로 맞추는 차등 검증에 쓰인다.

### 1.2 이전 시도 회고 (opensamguk v1, 2026-05 ~ 2026-10)

| 지표      | 값                                                     |
| --------- | ------------------------------------------------------ |
| 기간      | 약 5개월, 커밋 5,654개                                 |
| 코드      | Kotlin 43만 줄 + TS 13만 줄 + Python 16만 줄           |
| 문서      | 1,200개 이상 (에이전트 운영 문서 포함)                 |
| 진척      | 로드맵 10단계 중 3단계, 1개 주(예주)만 동작            |
| 방향 전환 | 9/17 명령 체계를 카드 체계로 교체, 지도·UI 여러 번 재작업 |

사용자 회고: "개발이 늘어졌다. 내가 뭘 하고 있는지도 몰랐고 어떻게 해야 끝났는지도 몰랐다."

### 1.3 이번 계획이 다르게 하는 것

1. **끝을 먼저 정한다.** 모든 기능은 인수조건(AC) ID를 가지며 AC가 통과해야 완료다.
2. **진행이 보이게 한다.** 진행률의 유일한 기준은 [인수조건](./acceptance-criteria.md)의 상태다.
   README 첫 화면에도 표시한다.
3. **범위를 얼린다.** 현재 관문에 없는 아이디어는 [백로그](./backlog.md)로 간다. 규칙 체계를
   갈아엎는 방향 전환은 [결정 기록](./decisions.md)과 사용자 승인 없이는 하지 않는다.
4. **원작 1:1 일치를 목표로 하지 않는다.** 재미가 검증된 뼈대만 가져오고 규칙은 단순하게 새로 쓴다.

## 2. 문제 정의

### 2.1 플레이어의 문제

원작 문서와 커뮤니티 용어에서 확인한 불편이다.

- **입문:** 신규 유저는 첫 접속에서 무엇을 할지 모른다. 원작 안내서도 첫 할 일로 "국가 메시지로
  물어보기"를 권한다.
- **협업:** 점사·턴 정렬 같은 협동 공격을 메시지로 손수 맞춰야 한다.
- **외교:** "최후 2국" 같은 외교 약속이 말로만 존재해 모호하고 서버가 집행하지 못한다.
- **부재:** 로그아웃한 동안 예턴이 실패해도 다음 접속 때까지 모른다.
- **기억:** 한 기수가 끝나면 그 판의 이야기가 흩어진다.

### 2.2 개발의 문제

진행 상황이 보이지 않았고 완료 기준이 없었다. 1.3의 원칙과 [AGENTS.md](../../AGENTS.md)의 작업
규칙으로 대응한다.

## 3. 목표와 비목표

### 목표 (MVP = M3 공개 오픈)

- **G1.** 누구나 가입해서 여러 월드 중 하나에 참가하고 한 기수를 끝까지 플레이할 수 있다.
- **G2.** 원작 경험자가 "삼모 맞네"라고 느낄 핵심 루프가 있다. 장수·예턴·내정·전쟁·국가·외교·월간
  정산이다.
- **G3.** 원작에 없는 차별화 기능 9개가 있다 (D-010). 늦어지면 정해 둔 순서대로 미루되, 핵심 4개(D1·D2·D3·D12)는 지킨다.
- **G4.** 1인 개발 + AI로 유지할 수 있는 규모다. MVP 시점 코드 5만 줄 이하를 목표로 한다. (가정 A2)

### 비목표 (MVP에서 하지 않음)

- 원작과 동작·수치·난수의 1:1 일치
- 원작 서버 데이터 이관
- 명령 90개 전체 (MVP는 37개, [6.3](#63-mvp-명령-세트))
- 아이템·특기·계략·경매·토너먼트·부대·전투 시뮬레이터 (Phase 2)
- 모바일 앱 (반응형 웹으로 대응)
- 무중단 배포

## 5. 핵심 게임 루프

```text
[가입] → [월드 선택] → [장수 생성] → [임관 또는 건국]
                                          │
      ┌───────────────────────────────────┘
      ▼
 [예턴 입력 (최대 30칸)] ──▶ [내 턴 시각에 1칸 실행] ──▶ [결과 로그]
      ▲                                                       │
      └────────────── [접속해서 확인·수정] ◀──────────────────┘

 달이 바뀔 때: 세금·봉급 → 인구·민심 → 보급 판정 → 외교 기한 → 연감 기록
 기수 종료: 천하통일 또는 종료 연도 → 결과 보관 → 다음 기수
```

- 1턴은 게임 1개월이다. 장수마다 그 달 안에서 자기 턴 시각이 다르다.
- 턴 간격은 월드마다 정한다. 예를 들어 정규 월드는 60분, 속성 월드는 10분이다. (가정 A3)
- 예턴은 장수 30칸, 국가(직책별) 12칸이다. (가정 A15)
- 기수는 천하통일이나 시나리오 종료 연도에 끝난다. (가정 A17)

## 9. 디자인 방향

**키워드: 원작 정보량 + 모던 정리**

1. 한 화면에 내 장수·도시·국가·다음 턴 시각이 다 보인다. 원작 메인 화면의 정보 밀도를 지킨다.
2. 숫자는 오른쪽 정렬과 고정폭 숫자를 쓴다. 변화량은 색과 부호로 함께 보여 준다.
3. 색의 의미를 고정한다. 국가색은 지도와 이름표에만, 상태색(성공·실패·경고)은 따로 쓴다.
4. 표는 촘촘하되 행 간격·구분선·고정 머리글로 읽기 쉽게 만든다.
5. 데스크톱이 우선이고 375px 폭에서도 핵심 화면을 쓸 수 있다.

레퍼런스는 [화면 레퍼런스](../design/references/README.md)의 5개다 (원작 화면 2, 외부 3). 2026-10-20 사용자 확인 (A10 확인 완료).
레퍼런스는 방향을 합의하는 용도이며 이미지를 저장하거나 산출물에 다시 싣지 않는다.

## 10. 기술 방향

| 영역     | 선택                                                  |
| -------- | ----------------------------------------------------- |
| 언어     | TypeScript 하나 (Node.js 24)                          |
| 서버     | Fastify + tRPC + zod                                  |
| 화면     | React + Vite + TanStack Query                         |
| 저장     | PostgreSQL + Prisma (가정 A12). Redis 없이 시작 (가정 A11)    |
| 테스트   | Vitest, Playwright                                    |
| 배포     | 서버 1대 + Docker Compose + Caddy (가정 A13)              |

구성은 `apps/web`, `apps/server`(계정·로비·게임 API), `apps/engine`(월드별 턴 엔진),
`packages/rules`(순수 게임 규칙), `packages/shared`, `packages/db`, `resources/`다.
자세한 내용은 [아키텍처 개요](../architecture/overview.md)에 있다.
