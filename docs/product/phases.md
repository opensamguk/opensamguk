> 상태: 확정 v0.2 (2026-10-20, D-011) · 완료 판정: [인수조건](./acceptance-criteria.md)

Phase 1(MVP)은 관문 세 개로 나눕니다. 관문마다 **데모 한 장면**으로 끝을 정의합니다.
각 관문의 작업 대기열은 순서·담당·선행·단계를 가지며 `pnpm next`가 이 표로 다음 작업을 알려 줍니다.

```text
Phase 1 (MVP) ─┬─ M1 혼자+NPC 완주 ─┬─ M2 지인 테스트 ─┬─ M3 공개 오픈 ══▶ MVP 완료
               │   (내부, 월드 1개)  │  (월드 2개)      │  (누구나 가입)
Phase 2 (확장) ─┴────────────────────┴──────────────────┴─▶ 명령 확장, 부대·장비·계략, D7~D9
Phase 3 (고도화) ─────────────────────────────────────────▶ PWA, LLM 조언, 시즌 메타
```

소유자 마감 지시(2026-10-22)에 따라 MVP 전체(M1·M2·M3)와 Phase 2 확장의 목표 시각은 2026-10-22 23:59:59 KST입니다. 앞선 2026-10-21 목표는 지난 목표로 남기며 달성했다는 뜻이 아닙니다. Phase 3 목표 2026-10-25는 그대로입니다. 목표일 뿐 완료 보장이나 인수조건 면제가 아닙니다. M2·M3에서 지인이 참가하던 시험은 같은 수의 독립 에이전트 참가 시험으로 바뀌었습니다 ([D-021](./decisions.md#d-021-지인-참가-시험을-독립-에이전트-참가-시험으로-바꾸고-공개를-승인한다-2026-10-21)). 관문 이름은 그대로 둡니다.

## 작업 흐름

2026-10-20부터 담당을 나눕니다 (D-012).

```text
계획 (Claude) ──▶ 구현 (담당: Codex 또는 Claude) ──▶ 리뷰 (구현하지 않은 쪽) ──▶ 완료
                        ▲                                   │
                        └────────── 고칠 것이 있으면 ────────┘
```

| 영역   | 구현 담당 | 리뷰 담당 |
| ------ | --------- | --------- |
| 백엔드: `apps/server`, `apps/engine`, `packages/*`, `resources/`, 운영 | **Codex** | Claude |
| 프론트: `apps/web`, `e2e/`, 플레이어 가이드 | **Claude** | Codex |
| 결정·데모·테스트 진행 | 사용자 | — |

- **계획**은 항상 Claude가 [작업 계획](../plans/README.md)에 씁니다. 선행 작업과 상관없이 미리 쓸 수 있습니다.
- **구현**은 선행 작업이 모두 `완료`이고 계획 문서(`docs/plans/<ID>.md`)가 있을 때만 시작합니다. 끝나면 단계를 `리뷰`로 바꿉니다.
  계획 문서가 없으면 `pnpm next`가 단계와 상관없이 Claude의 계획 작업으로 보여 줍니다.
- `pnpm next`의 `[계획]` 절은 구현 전에 계획이 필요한 작업을 관문별로 보여 줍니다. 다음 관문 것도 미리 쓸 수 있습니다.
- 계획에는 **채울 문서**를 적습니다. 구현 담당은 코드와 함께 그 문서를 채우고 리뷰는 문서도 확인합니다. 문서가 비어 있으면 리뷰를 통과하지 않습니다.
- **리뷰**는 반대쪽이 합니다. 통과하면 `완료`로 바꾸고 인수조건을 ✅로 바꿉니다. 고칠 것이 있으면 `구현`으로 되돌립니다. <!-- lint-text-ignore C-5 -->
- 구현하는 쪽은 자기 단계를 `완료`로 바꾸지 않습니다.
- 작업이 끝나면 `pnpm next`를 실행해 다음 작업과 담당을 보고합니다.

### 대기열 형식

`| ID | 작업 | AC | 구현 | 선행 | 단계 |`

- 구현: `Codex`, `Claude`, `사용자`
- 선행: `—`, 작업 ID 목록(`T1-05, T1-10`), 범위(`T2-01~T2-17`), 관문 전체(`M1`)
- 단계: `계획`, `구현`(대기), `진행중`(실제 착수), `리뷰`, `완료` (사용자 작업은 `구현`·`진행중`·`완료`)
- 담당마다 여러 작업을 동시에 `진행중`으로 둘 수 있습니다. 각 작업의 선행 완료·계획 준비를 확인하고 착수 시 `구현` → `진행중`, 검증 후 `진행중` → `리뷰`로 바꿉니다.
- 병렬 작업은 작업별 실제 담당 에이전트와 수정 범위를 계획에 기록하고 공유 파일 수정을 조율합니다. `pnpm next`는 진행 중인 작업을 모두 먼저 표시하고 나머지 대기 작업을 요약합니다.
- `tools/next-task.mjs`가 이 표를 읽습니다. 형식을 바꾸면 그 스크립트도 고칩니다.
